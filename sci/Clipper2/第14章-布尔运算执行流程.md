# 第14章：布尔运算执行流程

## 14.1 概述

本章将详细分析 Clipper2 执行布尔运算的完整流程，从输入多边形到输出结果的每个步骤。理解这个流程对于调试问题和优化性能至关重要。

## 14.2 执行流程总览

调用者看到的只是一次 Execute：传入主体路径、裁剪路径、裁剪类型和填充规则，拿回结果路径。内部却不是「两两求交再拼回去」这种直观思路，而是扫描线算法：用一条水平线从一端推向另一端，维护一组与扫描线相交的边（AEL），在边进入、离开、相交的位置更新每条边两侧的缠绕数，缠绕数变化决定该段是否属于结果。理解这一点，后面的所有函数名才有意义：局部极值决定边何时进入，交点决定边何时换序，顶点事件决定边何时离开。

```
┌─────────────────────────────────────────────────────┐
│                    Execute()                         │
├─────────────────────────────────────────────────────┤
│ 1. 预处理阶段                                        │
│    ├── 构建顶点列表                                  │
│    ├── 识别局部极值                                  │
│    └── 排序局部极小值                                │
├─────────────────────────────────────────────────────┤
│ 2. 扫描线处理阶段                                    │
│    ├── 插入局部极小值到 AEL                          │
│    ├── 处理水平边                                    │
│    ├── 计算并处理交点                                │
│    └── 处理扫描带顶部                                │
├─────────────────────────────────────────────────────┤
│ 3. 后处理阶段                                        │
│    ├── 处理连接                                      │
│    ├── 清理共线点                                    │
│    └── 构建输出路径                                  │
└─────────────────────────────────────────────────────┘
```

总览图把流程分成三段，对应三类工作：预处理把用户给的路径整理成算法能消费的结构；扫描线阶段产生输出轮廓的顶点序列；后处理把轮廓整理成干净的路径。三个阶段之间靠几个核心对象传递状态：顶点链表（Vertex）、扫描线列表（_scanlineList）、活动边表（_actives，即 AEL）、交点列表（_intersectList）、输出轮廓列表（_outrecList）。调试时按这五个对象打印状态，基本能定位到出问题的阶段。

## 14.3 预处理阶段

预处理的目标只有一个：为扫描线算法准备一份「带极值标记的边链表」。用户的路径可能是折线、可能是闭合环、可能带重复点，扫描线算法不能直接处理这些原始输入。

### 14.3.1 AddPath 处理

```csharp
public void AddPaths(Paths64 paths, PathType pathtype, bool isOpen = false)
{
    // 标记是否有开放路径
    if (isOpen) _hasOpenPaths = true;
    
    // 标记需要重新排序
    _isSortedMinimaList = false;
    
    foreach (Path64 path in paths)
    {
        // 跳过无效路径
        if (path.Count < 2) continue;
        if (!isOpen && path.Count < 3) continue;
        
        // 构建顶点链表
        AddPathToVertexList(path, pathtype, isOpen);
    }
}
```

AddPaths 是入口，两个参数值得注意。PathType 标记这批路径属于主体（Subject）还是裁剪（Clip），后面的缠绕计数和贡献判断都依赖它；isOpen 标记开放路径，开放路径不参与布尔运算的闭合轮廓，只用于特定的裁剪与描边场景。两个跳过条件对应几何上无意义的输入：少于两个点的路径连一条边都构不成，闭合路径少于三个点围不出面积。_isSortedMinimaList 置为 false 是一个惰性标记，表示极值列表已经过期，下次执行前必须重新排序；这样连续调用 AddPaths 时不必每次排序，只有真正执行时才付出代价。

### 14.3.2 构建顶点链表

```csharp
private void AddPathToVertexList(Path64 path, PathType pathtype, bool isOpen)
{
    // 创建顶点
    Vertex? firstVert = null;
    Vertex? prevVert = null;
    
    foreach (Point64 pt in path)
    {
        // 跳过重复点
        if (prevVert != null && pt == prevVert.pt) continue;
        
        Vertex v = new Vertex { pt = pt };
        
        if (firstVert == null)
            firstVert = v;
        else
        {
            prevVert!.next = v;
            v.prev = prevVert;
        }
        prevVert = v;
    }
    
    // 闭合路径
    if (!isOpen && firstVert != null && prevVert != null)
    {
        prevVert.next = firstVert;
        firstVert.prev = prevVert;
    }
    
    // 标记并添加局部极值
    if (firstVert != null)
        FindAndMarkLocalMinMax(firstVert, pathtype, isOpen);
}
```

顶点用双向链表串起来，prev 和 next 各指一侧，闭合路径最后把尾节点的 next 指回首节点、首节点的 prev 指回尾节点，形成一个环。跳过相邻重复点是必须的：重复点会让「相邻两点 Y 相同」的判断失效，还会让斜率计算出现零除，后面求交点和排序都可能出错。每个顶点在链表里是独立对象，一次裁剪结束后整条链会被复用或释放，这是扫描线算法频繁申请释放内存的地方，也是性能分析时最先要看的部分。

### 14.3.3 识别局部极值

```csharp
private void FindAndMarkLocalMinMax(Vertex firstVertex, 
    PathType pathtype, bool isOpen)
{
    Vertex v = firstVertex;
    
    do
    {
        // 跳过水平段
        if (v.pt.Y == v.next!.pt.Y) 
        {
            v = v.next;
            continue;
        }
        
        // 检查局部极小值
        if (IsLocalMin(v))
        {
            v.flags |= VertexFlags.LocalMin;
            AddLocMin(v, pathtype, isOpen);
        }
        // 检查局部最大值
        else if (IsLocalMax(v))
        {
            v.flags |= VertexFlags.LocalMax;
        }
        
        v = v.next;
    } while (v != firstVertex);
}

private bool IsLocalMin(Vertex v)
{
    Vertex prev = v.prev!;
    Vertex next = v.next!;
    
    // 向上找第一个非水平点
    while (prev.pt.Y == v.pt.Y) prev = prev.prev!;
    while (next.pt.Y == v.pt.Y) next = next.next!;
    
    return prev.pt.Y > v.pt.Y && next.pt.Y >= v.pt.Y;
}
```

扫描线算法只在边「开始进入 AEL」的位置需要事件，这类位置就是局部极值。判断方法很直接：一个顶点的两侧邻居都比它高，它就是局部极小；都比它低，就是局部极大。水平段要跳过——连续多个点 Y 相同，谁是极值取决于再往前找到的第一个非水平点，所以代码里用两个 while 循环分别向前、向后跳过水平点，再拿得到的邻居比较。注意两个比较用的符号不完全对称（一个是严格大于，一个是大于等于），这是为了处理平台段只标记一次，避免同一个极值被重复加入。开放路径的首尾顶点只有一侧邻居，极值判断需要单独处理，否则链表的环形遍历会在端点处越界。

### 14.3.4 排序局部极小值

```csharp
private void SortMinimaList()
{
    if (!_isSortedMinimaList)
    {
        // 按 Y 坐标降序排序（从大到小）
        _minimaList.Sort((a, b) => b.vertex.pt.Y.CompareTo(a.vertex.pt.Y));
        
        _isSortedMinimaList = true;
        
        // 初始化扫描线列表
        _scanlineList.Clear();
        foreach (var lm in _minimaList)
            _scanlineList.Add(lm.vertex.pt.Y);
    }
}
```

极性列表最终要按扫描推进的顺序排好。代码按 Y 坐标降序排序，注释写的是从大到小，同时把每个极值的 Y 值复制进 _scanlineList，作为扫描线的候选位置。_isSortedMinimaList 这个标记避免重复排序：只要没有新增路径，排好的列表就可以一直用。排序本身不复杂，但顺序错了后果很隐蔽——扫描线会跳过某些事件，结果是少画一段轮廓或者多出一个洞，而输入几何完全合法，排查时很难想到是排序问题。

## 14.4 扫描线处理主循环

主循环是整个算法的骨架，六个步骤的顺序不能随意调整。AEL 里始终保存当前扫描线穿过的所有非水平边，并按 X 坐标有序；扫描带是两条相邻扫描线之间的区域，交点只可能发生在带内。理解这两条不变量，就能看懂每个步骤在维护什么。

逐行看这个循环。进入前先 Reset 清理上一次执行留下的状态，NoClip 直接返回，说明这不是一个单纯的几何运算容器。PopScanline 取出当前 Y 值，如果连一条扫描线都没有，说明输入为空，直接结束。循环体里，步骤一把 Y 值等于当前扫描线的局部极值插入 AEL；步骤二把这一层积压的水平边处理完；然后推进到下一个扫描线，若没有下一个就退出；步骤三四处理两条扫描线之间形成的扫描带里的交点；步骤五处理扫描带顶部（也就是下一条扫描线位置）的顶点事件；步骤六再清一次水平边。水平边之所以要处理两次，是因为插入极值和顶点事件都可能产生新的水平边，必须在本层结束前消化掉。

### 14.4.1 ExecuteInternal 主循环

```csharp
private void ExecuteInternal(ClipType ct, FillRule fillrule)
{
    if (ct == ClipType.NoClip) return;
    
    _fillrule = fillrule;
    _cliptype = ct;
    
    Reset();
    
    if (!PopScanline(out long y)) return;
    
    while (true)
    {
        // 步骤1：插入当前 Y 的局部极小值
        InsertLocalMinimaIntoAEL(y);
        
        // 步骤2：处理所有水平边
        while (PopHorz(out Active? horz))
        {
            DoHorizontal(horz!);
        }
        
        // 步骤3：获取下一个扫描线
        if (!PopScanline(out long topY)) break;
        
        // 步骤4：处理当前扫描带的交点
        DoIntersections(y, topY);
        
        // 步骤5：处理扫描带顶部事件
        DoTopOfScanbeam(topY);
        
        // 步骤6：更新水平边
        while (PopHorz(out Active? horz))
        {
            DoHorizontal(horz!);
        }
        
        y = topY;
    }
}
```

扫描带是理解交点处理的关键。扫描线从当前 Y 推进到 topY 的过程中，边的 X 坐标按各自的斜率线性变化，两条边如果在带内交叉，它们的前后顺序就变了。算法把这类顺序反转视为交点事件：先算出交点，再在交点处交换两条边在 AEL 中的位置，同时更新缠绕计数。注意这里处理的是「相邻两条边」的顺序，因为 AEL 始终有序，一对边如果相交，它们之间不会夹着第三条与扫描线相交的边。这也是扫描线算法比朴素两两求交高效的原因：每个扫描带只需要检查相邻对。

### 14.4.2 扫描带概念

```
Y = 100  ───────────────────  扫描线 (当前 y)
          ╲                ╱
           ╲   扫描带     ╱
            ╲            ╱
Y = 80   ───────────────────  扫描线 (topY)
              ╲        ╱
               ╲      ╱
                ╲    ╱
Y = 60   ───────────────────  下一个扫描线
```

扫描带的高度不是固定的，PopScanline 返回的是下一个存在事件的 Y 值，两条扫描线之间可能跨越很长的空白区域。空白区域里没有顶点也没有交点，边的相对顺序不会改变，所以可以整段跳过。这个特性让扫描线算法的复杂度与事件数量相关，而不是与坐标范围相关；坐标值本身可以是很大的整数，只要事件不多，速度就不受影响。

## 14.5 步骤1：插入局部极小值

局部极小值是一个闭合轮廓「开始」的位置：从这一点出发，轮廓分成左、右两条边向两侧展开，随后进入 AEL，一直上升到某个局部极大值处重新汇合。插入这一步要做的就是把一个极值拆成两条活动边，并判断它们是否位于结果区域内。

### 14.5.1 InsertLocalMinimaIntoAEL

```csharp
private void InsertLocalMinimaIntoAEL(long botY)
{
    while (PopLocalMinima(botY, out LocalMinima locMin))
    {
        Vertex vert = locMin.vertex;
        
        // 创建左边（向 next 方向）
        Active leftBound = new Active
        {
            bot = vert.pt,
            top = vert.next!.pt,
            curX = vert.pt.X,
            dx = GetDx(vert.pt, vert.next.pt),
            windDx = 1,
            vertexTop = vert.next,
            localMin = locMin,
            isLeftBound = true
        };
        
        // 创建右边（向 prev 方向）
        Active rightBound = new Active
        {
            bot = vert.pt,
            top = vert.prev!.pt,
            curX = vert.pt.X,
            dx = GetDx(vert.pt, vert.prev.pt),
            windDx = -1,
            vertexTop = vert.prev,
            localMin = locMin,
            isLeftBound = false
        };
        
        // 插入到 AEL
        InsertLeftEdge(leftBound);
        
        // 设置缠绕计数
        SetWindCountForClosedPathEdge(leftBound);
        
        // 检查是否贡献输出
        if (IsContributingClosed(leftBound))
        {
            Active ae2 = rightBound;
            SetOutRecReference(leftBound, ae2);
        }
        
        InsertRightEdge(rightBound, leftBound);
        SetWindCountForClosedPathEdge(rightBound);
        
        // 添加局部最小值输出点
        if (leftBound.outrec != null)
        {
            AddLocalMinPoly(leftBound, rightBound, leftBound.bot);
        }
        
        // 添加下一个扫描线
        if (leftBound.top.Y < botY)
            AddScanline(leftBound.top.Y);
        if (rightBound.top.Y < botY)
            AddScanline(rightBound.top.Y);
    }
}
```

InsertLocalMinimaIntoAEL 从极值列表里弹出所有 Y 值等于当前扫描线的项，为每一项建立两条 Active 边。左边沿 next 方向走，windDx 记为 1；右边沿 prev 方向走，windDx 记为 -1，正负号在后面更新缠绕计数时用来判断方向。bot 存下端点，top 存上端点，curX 是当前扫描线处的 X，dx 是斜率相关的增量，vertexTop 记录这条边的上端顶点，扫描到该顶点时触发顶点事件。
两条边分别插入 AEL，然后各自计算缠绕计数：SetWindCountForClosedPathEdge 根据路径类型与边的方向初始化 windCnt，IsContributingClosed 结合填充规则判断这条边是否落在结果内部，落在内部才会建立输出轮廓引用（outrec）。最后把两个上端点的 Y 值加入扫描线列表，保证后面能推进到这些位置。

### 14.5.2 AEL 排序插入

```csharp
private void InsertLeftEdge(Active ae)
{
    if (_actives == null)
    {
        ae.prevInAEL = null;
        ae.nextInAEL = null;
        _actives = ae;
    }
    else if (!IsValidAelOrder(_actives, ae))
    {
        ae.prevInAEL = null;
        ae.nextInAEL = _actives;
        _actives.prevInAEL = ae;
        _actives = ae;
    }
    else
    {
        Active ae2 = _actives;
        while (ae2.nextInAEL != null && IsValidAelOrder(ae2.nextInAEL, ae))
            ae2 = ae2.nextInAEL;
        
        ae.nextInAEL = ae2.nextInAEL;
        if (ae2.nextInAEL != null)
            ae2.nextInAEL.prevInAEL = ae;
        ae.prevInAEL = ae2;
        ae2.nextInAEL = ae;
    }
}
```

AEL 是一个按 X 坐标升序排列的双向链表。插入分三种情况：表为空时直接成为头节点；新边的 X 小于头节点时插到表头；否则从头节点开始向后找，直到找到第一个顺序正确的后继。IsValidAelOrder 封装了比较逻辑，比较的是两条边的 curX；curX 在扫描线推进时统一更新，所以 AEL 的顺序始终对应当前扫描线位置，而不是边各自端点的坐标。链表结构让插入和交换都是常数时间，代价是查找是线性的；真实工程里如果边数很多，热点就落在这个线性插入上。

## 14.6 步骤2：处理水平边

水平边是扫描线算法的特殊情形：它与扫描线平行，无法用「当前 X」排序，也无法用斜率推算交点。代码的处理办法是把它们放进单独的队列，等扫描线推进到该 Y 值后再统一处理。DoHorizontal 先比较两个端点的 X 确定方向与左右边界，然后从水平边在 AEL 中的邻居开始，沿一个方向扫描所有 curX 落在水平边范围内的边，逐个求交、更新状态、交换位置，最后调用 UpdateEdgeIntoAEL 把这条边推进到它的上端点或从 AEL 删除。方向判断很重要：从头节点向另一个方向扫会漏掉交点，因为排序假设只在一个方向上成立。

### 14.6.1 DoHorizontal

```csharp
private void DoHorizontal(Active horz)
{
    // 确定水平边方向
    bool leftToRight;
    long horzLeft, horzRight;
    
    if (horz.bot.X < horz.top.X)
    {
        leftToRight = true;
        horzLeft = horz.bot.X;
        horzRight = horz.top.X;
    }
    else
    {
        leftToRight = false;
        horzLeft = horz.top.X;
        horzRight = horz.bot.X;
    }
    
    // 处理与其他边的交点
    Active? ae = leftToRight ? horz.nextInAEL : horz.prevInAEL;
    
    while (ae != null)
    {
        // 检查是否在水平边范围内
        if ((leftToRight && ae.curX > horzRight) ||
            (!leftToRight && ae.curX < horzLeft))
            break;
        
        // 计算交点
        Point64 pt = new Point64(ae.curX, horz.bot.Y);
        
        // 处理交点
        if (ae.curX >= horzLeft && ae.curX <= horzRight)
        {
            IntersectEdges(horz, ae, pt);
            SwapPositionsInAEL(horz, ae);
        }
        
        ae = leftToRight ? ae.nextInAEL : ae.prevInAEL;
    }
    
    // 更新或删除水平边
    UpdateEdgeIntoAEL(ref horz);
}
```

水平边的处理顺序和普通边不同，容易在阅读时产生困惑。普通边的交点是在两个扫描带之间统一检测的，而水平边与扫描线重合，它的交点发生在同一 Y 值上，没法等扫描带结束再处理，只能当场逐个算。把水平边延后到本层是个折中：插入时只登记，等到所有垂直边都就位、AEL 顺序稳定之后，再统一处理，避免边还没插全就开始求交。

## 14.7 步骤3-4：处理交点

求交这一步先建立交点清单，再统一处理，而不是边算边改。BuildIntersectList 遍历 AEL 中每一对相邻边，用 TopX 算出它们在 topY 处的 X 坐标：如果前一条的 X 反而大于后一条，说明这两条边在扫描带内交叉了。GetIntersection 计算精确交点，然后把它限制在扫描带范围内——浮点误差或极短边可能算出带外的交点，不裁剪会让后续排序和缠绕计数错乱。所有交点收集完统一排序，先按 Y 降序，Y 相同时按 X 升序，保证处理顺序与扫描推进方向一致。两个相邻边都检查、不重复检查同一对，依赖的正是 AEL 的有序性。

### 14.7.1 BuildIntersectList

```csharp
private bool BuildIntersectList(long topY)
{
    if (_actives == null || _actives.nextInAEL == null) 
        return false;
    
    // 使用简单冒泡找出需要交换的边对
    bool result = false;
    
    Active? ae = _actives;
    while (ae.nextInAEL != null)
    {
        Active ae2 = ae.nextInAEL;
        
        // 计算两边在 topY 的 X 坐标
        long x1 = TopX(ae, topY);
        long x2 = TopX(ae2, topY);
        
        // 检查是否需要交换（X 顺序改变）
        if (x1 > x2)
        {
            // 计算交点
            if (GetIntersection(ae, ae2, out Point64 pt))
            {
                // 限制在扫描带内
                if (pt.Y > _currentBotY) pt.Y = _currentBotY;
                if (pt.Y < topY) pt.Y = topY;
                
                AddIntersectNode(ae, ae2, pt);
                result = true;
            }
        }
        
        ae = ae2;
    }
    
    // 排序交点（按 Y 降序，Y 相同时按 X 升序）
    if (_intersectList.Count > 1)
    {
        _intersectList.Sort((a, b) => {
            if (a.pt.Y != b.pt.Y)
                return b.pt.Y.CompareTo(a.pt.Y);
            return a.pt.X.CompareTo(b.pt.X);
        });
    }
    
    return result;
}
```

ProcessIntersectList 按排好的顺序逐个处理交点，每个交点做两件事：调用 IntersectEdges 更新边的状态和输出，然后交换两条边在 AEL 中的位置。第二件事是维持不变量——交点之后，两条边的左右关系反转，AEL 必须仍然按 X 有序，否则后续的相邻比较会失效。顺序也不能反：先交换再更新，或者先更新再交换但用了交换后的顺序，都会让缠绕计数错位，表现为结果里凭空多出一条边或者少一条边。

### 14.7.2 ProcessIntersectList

```csharp
private void ProcessIntersectList()
{
    foreach (IntersectNode node in _intersectList)
    {
        // 处理交点
        IntersectEdges(node.edge1, node.edge2, node.pt);
        
        // 交换边在 AEL 中的位置
        SwapPositionsInAEL(node.edge1, node.edge2);
    }
    
    _intersectList.Clear();
}
```

### 14.7.3 IntersectEdges

```csharp
private void IntersectEdges(Active ae1, Active ae2, Point64 pt)
{
    // 保存当前状态
    bool ae1Contributing = ae1.outrec != null;
    bool ae2Contributing = ae2.outrec != null;
    
    // 更新缠绕计数
    if (GetPolyType(ae1) == GetPolyType(ae2))
    {
        // 同类型
        if (_fillrule == FillRule.EvenOdd)
        {
            int tmp = ae1.windCnt;
            ae1.windCnt = ae2.windCnt;
            ae2.windCnt = tmp;
        }
        else
        {
            ae1.windCnt += ae2.windDx;
            ae2.windCnt -= ae1.windDx;
        }
    }
    else
    {
        // 不同类型
        ae1.windCnt2 += ae2.windDx;
        ae2.windCnt2 -= ae1.windDx;
    }
    
    // 检查新的贡献状态
    bool ae1ContributingNew = IsContributing(ae1);
    bool ae2ContributingNew = IsContributing(ae2);
    
    // 根据状态变化处理
    if (ae1Contributing && ae2Contributing)
    {
        if (ae1ContributingNew && ae2ContributingNew)
        {
            // 两边继续贡献
            AddOutPt(ae1, pt);
            AddOutPt(ae2, pt);
            SwapOutrecs(ae1, ae2);
        }
        else if (ae1ContributingNew)
        {
            // 只有 ae1 继续
            AddOutPt(ae1, pt);
            SwapOutrecs(ae1, ae2);
        }
        else if (ae2ContributingNew)
        {
            // 只有 ae2 继续
            AddOutPt(ae2, pt);
            SwapOutrecs(ae1, ae2);
        }
        else
        {
            // 两边都停止 -> 局部最大值
            AddLocalMaxPoly(ae1, ae2, pt);
        }
    }
    else if (ae1Contributing)
    {
        AddOutPt(ae1, pt);
        SwapOutrecs(ae1, ae2);
    }
    else if (ae2Contributing)
    {
        AddOutPt(ae2, pt);
        SwapOutrecs(ae1, ae2);
    }
    else if (!ae1ContributingNew && !ae2ContributingNew)
    {
        // 开始新的局部最小值
        AddLocalMinPoly(ae1, ae2, pt, true);
    }
}
```

IntersectEdges 是整个流程里分支最多的函数，理解它要抓住一个前提：每条边两侧的缠绕数决定了这段区间属于结果内部还是外部，交点意味着两侧的归属可能同时改变。函数先记录两条边当前的贡献状态，再更新缠绕计数。两条边属于同一组多边形时，按填充规则处理：偶奇规则下两条边的缠绕数直接互换；非零、正负规则下，各自加上对方的 windDx。两条边分属主体与裁剪时，更新的是第二个计数 windCnt2，它记录另一组多边形在这一侧的覆盖情况。
计数更新完，用 IsContributing 重新判断贡献状态，然后按新旧状态的组合分支：两边都继续贡献，各自加输出点并交换轮廓归属；只有一边继续，给仍然贡献的那条加输出点；两边都停止，说明到了一个局部极大值，调用 AddLocalMaxPoly 把轮廓闭合；两边原本都不贡献而新状态也不贡献，可能是新的局部极小值，建立新的输出轮廓。这些分支合起来覆盖了交汇点上的所有拓扑变化，漏掉任何一种，结果都会出现轮廓断裂或自交。

## 14.8 步骤5：处理扫描带顶部

扫描带顶部是下一条扫描线的位置，也是顶点事件集中发生的地方。DoTopOfScanbeam 遍历 AEL，先把每条边的 curX 更新到当前 Y 值，再判断该边是否已经到达上端顶点。到达顶点分两种处理：如果这是一个局部极大值，就调用 DoMaxima 让左右两条边在这里汇合；否则说明这条边还要继续向上延伸，只是跨越了一个中间顶点，同时如果上端顶点是水平边的起点，把这条边压入水平边队列，等本层末尾统一处理。这里的 _sel 是内部临时状态的重置，读代码时不必深究它的业务含义。

### 14.8.1 DoTopOfScanbeam

```csharp
private void DoTopOfScanbeam(long y)
{
    _sel = null;
    Active? ae = _actives;
    
    while (ae != null)
    {
        // 更新当前 X 坐标
        ae.curX = TopX(ae, y);
        
        // 检查是否到达顶点
        if (ae.top.Y == y)
        {
            // 到达顶点
            ae = DoMaxima(ae, y);
        }
        else
        {
            // 继续向上
            // 检查是否有新的水平边
            if (IsHorizontal(ae.vertexTop!))
            {
                PushHorz(ae);
            }
            ae = ae.nextInAEL;
        }
    }
}
```

### 14.8.2 DoMaxima

```csharp
private Active? DoMaxima(Active ae, long y)
{
    Active? prevE = ae.prevInAEL;
    Active? nextE = ae.nextInAEL;
    
    // 检查是否是局部最大值
    if (IsLocalMaxima(ae))
    {
        // 查找配对边
        Active? maxPair = GetMaximaPair(ae);
        
        if (maxPair == null)
        {
            // 开放路径端点
            if (ae.outrec != null)
                AddOutPt(ae, ae.top);
            DeleteFromAEL(ae);
            return nextE;
        }
        
        // 添加局部最大值
        if (ae.outrec != null || maxPair.outrec != null)
            AddLocalMaxPoly(ae, maxPair, ae.top);
        
        DeleteFromAEL(ae);
        DeleteFromAEL(maxPair);
        
        return prevE != null ? prevE.nextInAEL : _actives;
    }
    
    // 更新到下一段边
    UpdateEdgeIntoAEL(ref ae);
    return ae.nextInAEL;
}
```

DoMaxima 处理轮廓的收口。先判断这个顶点是否真的是局部极大：如果是，找它的配对边；配对边不存在，说明这是开放路径的端点，直接把端点写入输出并删除该边即可。配对成功且两侧都有输出轮廓时，调用 AddLocalMaxPoly 把左右两条轮廓在这里连接起来，形成闭合环的起点与终点。之后两条边都从 AEL 删除，函数返回被删除位置前一条边的后继，从那里继续遍历。
注意返回值取的是 prevE.nextInAEL 而不是 nextE，因为 nextE 可能就是被删掉的配对边，直接返回它会让遍历读到已删除节点。如果不是局部极大，说明边只是路过一个顶点，调用 UpdateEdgeIntoAEL 把边推进到下一段，继续留在 AEL 里。

## 14.9 后处理阶段

扫描线阶段结束时，_outrecList 里保存的是若干条输出轮廓，每条轮廓是一串输出点。这些点还不能直接交给调用者：可能有共线点、可能有重复点、方向也可能与配置不符。后处理负责把轮廓整理成合法路径，并按闭合/开放分类输出。

BuildPaths 遍历所有输出轮廓，先清理共线点，再构建路径。构建时有两个条件决定顶点顺序：ReverseSolution 配置与轮廓本身的有向面积符号，两者异或决定是否需要反转；IsPositive 用于判断面积方向，外轮廓与内孔的方向约定相反，这样才能让下游正确识别洞。输出按开放与闭合分开存放：开放路径只要有 2 个点就有效，闭合路径少于 3 个点围不出面积，直接丢弃。BuildPath 可能返回空，通常意味着轮廓退化成一个点或一条线段，属于正常情况。

### 14.9.1 BuildPaths

```csharp
private void BuildPaths(Paths64 closedPaths, Paths64 openPaths)
{
    foreach (OutRec outrec in _outrecList)
    {
        if (outrec.pts == null) continue;
        
        // 清理共线点
        CleanCollinear(outrec);
        
        if (outrec.pts == null) continue;
        
        // 构建路径
        Path64? path = BuildPath(outrec.pts, 
            ReverseSolution != IsPositive(outrec),
            outrec.isOpen);
        
        if (path == null || path.Count < 2) continue;
        
        if (outrec.isOpen)
            openPaths.Add(path);
        else if (path.Count > 2)
            closedPaths.Add(path);
    }
}
```

共线点清理只在 PreserveCollinear 为 false 时执行。清理的逻辑是沿着输出点链表走一圈，检查当前点与前后两点是否共线，共线就删掉当前点并回退一步，避免连续共线时跳着删。循环里有几个变量需要盯着：op 是当前节点，op.prev 和 op.next 是邻居，startOp 是这一轮遍历的起点，outrec.pts 是轮廓的头指针。删除头节点时，头指针必须更新到前一个节点，否则 outrec.pts 会指向已释放的对象；删除之后 op 会回退一步，如果这个节点正好是轮廓头，startOp 也要同步更新，否则遍历终点与当前头指针脱节，循环可能在错误的节点上结束。这段代码短，但手工修改时最容易在这里引入 bug。

### 14.9.2 CleanCollinear

```csharp
private void CleanCollinear(OutRec outrec)
{
    if (!PreserveCollinear)
    {
        OutPt? op = outrec.pts;
        if (op == null) return;
        
        OutPt startOp = op;
        
        do
        {
            // 检查是否共线
            if (InternalClipper.IsCollinear(op.prev!.pt, op.pt, op.next!.pt))
            {
                if (op == outrec.pts)
                    outrec.pts = op.prev;
                
                DisposeOutPt(op);
                op = op.prev!;
                
                if (op == outrec.pts)
                    startOp = op;
            }
            else
            {
                op = op.next;
            }
        } while (op != startOp && outrec.pts != null);
    }
}
```

流程讲完，回到调用者视角看结果。一次 Execute 的输入是两组路径加参数，输出是两组路径（闭合与开放）和一次成功/失败标记。同样的输入，填充规则不同结果可能完全不同：两条重叠的矩形，偶奇规则下重叠区是空的，非零规则下重叠区被合并；裁剪类型选交集、并集、差集、异或，输出的拓扑也随之变化。判断结果是否正确，除了看几何形状，还要看路径方向与洞的归属，这两点在导出到下游（比如 GIS 或 CAD）时比形状本身更容易出问题。

### 14.10.1 两个正方形求交

```csharp
// 输入
Path64 subject = new Path64 { 
    (0,0), (100,0), (100,100), (0,100) 
};
Path64 clip = new Path64 { 
    (50,50), (150,50), (150,150), (50,150) 
};

// 1. 预处理
// Subject: 局部极小值在 Y=100 (顶点 (0,100) 和 (100,100))
// Clip: 局部极小值在 Y=150 (顶点 (50,150) 和 (150,150))

// 2. 扫描开始 Y=150
// 插入 Clip 的两条边

// 3. Y=100
// 插入 Subject 的两条边
// 检测交点

// 4. 交点处理
// (50,100), (100,50) 处产生交点

// 5. 构建输出
// 结果: (50,50), (100,50), (100,100), (50,100)
```

用两个正方形走一遍，可以把前面所有步骤串起来。输入是主体正方形 (0,0)-(100,100) 与裁剪正方形 (50,50)-(150,150)，交集应当是 (50,50)-(100,100) 的 50×50 正方形。跟踪时关注三件事：每条边在什么时候进入 AEL，AEL 的顺序在哪个扫描带发生变化，输出轮廓在哪一步被建立和闭合。
示例注释里列的是事件顺序的简化版，没有给出每个顶点是局部极值还是普通顶点，也没有给出环绕计的中间值；真正调试时建议在 InsertLocalMinimaIntoAEL、ProcessIntersectList、DoMaxima 三处各加一行日志，打印扫描线 Y、边的 curX 和 windCnt，再对照几何图看是否符合预期。

## 14.11 本章小结

布尔运算执行流程包含三个主要阶段：

1. **预处理阶段**：
   - 构建顶点链表
   - 识别局部极值
   - 排序局部极小值

2. **扫描线处理**：
   - 插入局部极小值
   - 处理水平边
   - 计算交点
   - 处理扫描带顶部

3. **后处理阶段**：
   - 清理共线点
   - 构建输出路径

理解这个流程有助于调试和优化 Clipper2 的使用。

排查布尔运算问题可以按阶段缩小范围。结果完全为空，先查输入是否有效、填充规则是否把重叠区判成了外部；结果多出或缺少一段轮廓，重点看交点处理和缠绕计数，尤其是水平边与退化边附近；结果里出现自交或重复点，去看后处理的共线清理和方向判断。坐标精度也是常见来源：整数路径不存在舍入问题，浮点路径要按需要设置小数位数，位数太少会让本应相交的边擦肩而过，位数太多又会让本应合并的点被判成不同点。
