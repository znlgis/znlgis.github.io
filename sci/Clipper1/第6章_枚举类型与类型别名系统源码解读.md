# 第6章：枚举类型与类型别名系统源码解读

## 6.1 引言

在前面的五个章节中，我们已经详细分析了 Clipper1 库的项目结构、基础数据结构（`IntPoint`、`IntRect`、`DoublePoint`）、128 位整数运算（`Int128`）、多边形树结构（`PolyNode` 与 `PolyTree`）以及边结构与辅助数据结构（`TEdge`、`LocalMinima`、`OutRec` 等）。这些内容构成了 Clipper 库的"骨架"。

然而，一个优秀的算法库不仅需要精心设计的数据结构，还需要一套**清晰、完备的"词汇系统"**来描述算法的行为模式、操作类型和数据表示。在 Clipper1 中，这套词汇系统由**枚举类型（Enums）**和**类型别名（Type Aliases）**共同组成。

枚举类型定义了 Clipper 库能够"理解"的所有行为指令：

| 类别 | 枚举类型 | 核心问题 |
|:---:|:---|:---|
| 布尔运算 | `ClipType` | "执行什么运算？交集、并集、差集还是异或？" |
| 多边形角色 | `PolyType` | "这个多边形是主体还是裁剪工具？" |
| 填充规则 | `PolyFillType` | "怎样判断一个点是否在多边形内部？" |
| 连接类型 | `JoinType` | "偏移时拐角如何连接？方形、圆弧还是尖角？" |
| 端点类型 | `EndType` | "开放路径的端点如何处理？" |
| 内部边侧 | `EdgeSide` | "这条边是在左侧还是右侧？" |
| 内部方向 | `Direction` | "扫描线沿什么方向遍历？" |

类型别名则定义了数据的"语言"：

| 类型别名 | 实际类型 | 含义 |
|:---:|:---|:---|
| `cInt` | `System.Int64`（默认）或 `System.Int32` | 坐标整数类型 |
| `Path` | `List<IntPoint>` | 单个多边形轮廓 |
| `Paths` | `List<List<IntPoint>>` | 多边形集合 |

本章将对 Clipper1 源码中的**每一个枚举类型和类型别名**进行深入解读。我们不仅会分析它们的定义和语义，还会追踪它们在核心算法中的使用路径，揭示这些看似简单的类型定义如何驱动整个裁剪算法的运行。

## 6.2 类型别名系统（Type Alias System）

C# 语言的 `using` 指令除了引入命名空间外，还可以定义**类型别名**（Type Alias）。Clipper1 大量使用了这一特性来增强代码的可读性和灵活性。

在 `clipper.cs` 文件的最顶部（命名空间声明之前），我们可以看到一系列 `using` 指令：

```csharp
/*******************************************************************************
*                                                                              *
* Author    :  Angus Johnson                                                   *
* Version   :  6.4.2                                                           *
* Date      :  27 February 2017                                                *
* Website   :  http://www.angusj.com                                           *
* Copyright :  Angus Johnson 2010-2017                                         *
*                                                                              *
*******************************************************************************/

// 条件编译控制的坐标类型
#if use_int32
  using cInt = System.Int32;
#else
  using cInt = System.Int64;
#endif

// 路径类型别名
using Path = System.Collections.Generic.List<ClipperLib.IntPoint>;
using Paths = System.Collections.Generic.List<System.Collections.Generic.List<ClipperLib.IntPoint>>;
```

这些类型别名定义在文件级别，作用域覆盖整个文件。让我们逐一深入分析。

### 6.2.1 cInt 类型别名 — 坐标整数类型

#### 源码定义

```csharp
#if use_int32
  using cInt = System.Int32;   // 32 位有符号整数，范围：-2,147,483,648 ~ 2,147,483,647
#else
  using cInt = System.Int64;   // 64 位有符号整数，范围：-9,223,372,036,854,775,808 ~ 9,223,372,036,854,775,807
#endif
```

`cInt` 是 Clipper 库中最基础的类型别名，代表**坐标整数类型**（Coordinate Integer）。它的定义通过 C# 的条件编译（`#if`）实现了编译时可切换：

| 编译条件 | 实际类型 | 位宽 | 最大值 | 近似范围 |
|:---:|:---:|:---:|:---:|:---:|
| 定义了 `use_int32` | `System.Int32` | 32 位 | 2,147,483,647 | ±2.1 × 10⁹ |
| 未定义（**默认**） | `System.Int64` | 64 位 | 9,223,372,036,854,775,807 | ±9.2 × 10¹⁸ |

#### 为什么使用整数坐标而非浮点数？

这是 Clipper 库最重要的设计决策之一。Angus Johnson 选择整数坐标的原因可以从以下几个维度理解：

**（1）精度问题**

浮点运算存在固有的精度问题。考虑以下经典的浮点陷阱：

```
在 IEEE 754 双精度浮点数中：
  0.1 + 0.2 = 0.30000000000000004  （而非精确的 0.3）
```

在计算几何中，这种误差是致命的。判断"三点共线"或"两线段是否相交"等基础操作高度依赖精确比较。浮点误差可能导致：

```
点 P 在线段 AB 的"左侧"——根据一个计算
点 P 在线段 AB 的"右侧"——根据另一个等价计算

→ 算法产生自相矛盾的结果 → 崩溃或产生无效输出
```

**（2）确定性（Determinism）**

整数运算是**完全确定的**——同样的输入永远产生同样的输出，与运行平台无关。浮点运算则可能因编译器优化、FPU 模式设置、操作顺序等因素产生不同结果。对于裁剪算法这种需要大量拓扑判断的算法，确定性至关重要。

**（3）无舍入错误**

整数的加减法运算是精确的（不溢出的前提下）。两个整数坐标点的差值是精确的，两个坐标的比较也是精确的。这消除了浮点运算中"几乎相等"的歧义。

**（4）性能优势**

整数运算在大多数 CPU 上比浮点运算更快，尤其是比较操作。这对于扫描线算法中频繁的排序和比较尤为重要。

#### cInt 与范围常量的关系

在 `ClipperBase` 类中，定义了两个关键的范围常量：

```csharp
internal const cInt loRange = 0x3FFFFFFF;           // = 1,073,741,823（约 10.7 亿）
internal const cInt hiRange = 0x3FFFFFFFFFFFFFFFL;  // = 4,611,686,018,427,387,903（约 4.6 × 10^18）
```

这两个常量的含义如下：

```
┌─────────────────────────────────────────────────────────────────────┐
│                     cInt 取值范围与安全范围                          │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│  Int64 完整范围: -9.2×10^18 ─────────────── 0 ─────────────── 9.2×10^18  │
│                                                                     │
│  hiRange 安全范围: -4.6×10^18 ────────── 0 ────────── 4.6×10^18    │
│  （约 Int64 最大值的一半，确保两坐标相减不溢出）                     │
│                                                                     │
│  loRange 安全范围:    -10.7亿 ────── 0 ────── 10.7亿               │
│  （约 Int32 最大值的一半，在此范围内不需要 Int128 中间计算）         │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

**loRange 的意义**：当所有坐标都在 `[-loRange, loRange]` 范围内时，两个坐标值的乘积不会超过 `Int64` 的表示范围，因此**不需要 `Int128`** 进行中间计算。这是一个性能优化的临界值。

**hiRange 的意义**：这是坐标值的绝对上限。即使在此范围内，中间计算（如叉积）可能需要 `Int128`。超过此范围的坐标将被 Clipper 直接拒绝。

在 `ClipperBase.AddPath()` 方法中，有如下检查逻辑：

```csharp
private bool RangeTest(IntPoint Pt, ref bool useFullRange)
{
    if (Pt.X > loRange || Pt.Y > loRange || -Pt.X > loRange || -Pt.Y > loRange)
    {
        // 坐标超出 loRange，需要启用 Int128 模式
        useFullRange = true;
        if (Pt.X > hiRange || Pt.Y > hiRange || -Pt.X > hiRange || -Pt.Y > hiRange)
            // 坐标超出 hiRange，完全不可接受
            throw new ClipperException("Coordinate outside allowed range");
    }
    return true;
}
```

这段代码揭示了 `cInt` 类型与范围检查之间的精密关系：

```
坐标输入
   │
   ▼
┌─────────────────┐      ┌─────────────────────────────┐
│ |coord| ≤ loRange │──是──▶│ 使用普通 Int64 乘法（快速）    │
└────────┬────────┘      └─────────────────────────────┘
         │ 否
         ▼
┌─────────────────┐      ┌─────────────────────────────┐
│ |coord| ≤ hiRange │──是──▶│ 使用 Int128 乘法（精确但慢）   │
└────────┬────────┘      └─────────────────────────────┘
         │ 否
         ▼
┌─────────────────┐
│ 抛出异常，拒绝输入  │
└─────────────────┘
```

#### 如何启用 Int32 模式

在 Visual Studio 项目中，可以通过以下方式定义 `use_int32`：

1. **项目属性** → **生成** → **条件编译符号** → 添加 `use_int32`
2. 或在 `.csproj` 文件中：
   ```xml
   <DefineConstants>use_int32</DefineConstants>
   ```
3. 或在代码文件顶部（不推荐，因为只影响当前文件）：
   ```csharp
   #define use_int32
   ```

**何时使用 Int32 模式**：

- 坐标值确保在 ±1,073,741,823 范围内
- 对内存占用敏感（每个坐标点节省 8 字节）
- 在嵌入式设备或 32 位系统上运行
- 处理的多边形数量极大，需要最大化缓存效率

**注意**：在 Int32 模式下，`IntPoint` 的每个坐标占 4 字节，一个二维点占 8 字节；而在 Int64 模式下，每个坐标占 8 字节，一个二维点占 16 字节。对于包含数百万点的多边形操作，这个差异可能很显著。

#### cInt 在 IntPoint 中的使用

`cInt` 类型直接用于定义 `IntPoint` 结构体的坐标字段：

```csharp
public struct IntPoint
{
    public cInt X;    // X 坐标，类型为 cInt（Int64 或 Int32）
    public cInt Y;    // Y 坐标，类型为 cInt（Int64 或 Int32）
#if use_xyz
    public cInt Z;    // Z 坐标（可选），类型同为 cInt
#endif
    // ... 构造函数和其他方法
}
```

这意味着编译时选择的整数宽度会直接影响所有坐标运算的精度和性能。

### 6.2.2 use_xyz 条件编译标志

#### 源码定义

`use_xyz` 并非类型别名，而是一个**条件编译标志**（Conditional Compilation Symbol），它控制 `IntPoint` 结构体是否包含第三维坐标 `Z`：

```csharp
public struct IntPoint
{
    public cInt X;
    public cInt Y;
#if use_xyz
    public cInt Z;    // 仅在定义了 use_xyz 时存在

    public IntPoint(cInt x, cInt y, cInt z = 0)
    {
        this.X = x; this.Y = y; this.Z = z;
    }
#endif

    public IntPoint(cInt x, cInt y)
    {
        this.X = x; this.Y = y;
#if use_xyz
        this.Z = 0;
#endif
    }
    // ...
}
```

#### Z 坐标的设计意图

Clipper 是一个**二维**裁剪库，所有的布尔运算和偏移操作都只使用 X 和 Y 坐标。那么 Z 坐标的意义何在？

Z 坐标的核心用途是**自定义数据标记**（Custom Data Tagging）。由于裁剪运算会产生新的交点（这些交点不在原始多边形的顶点上），用户可能需要知道这些新交点的"来源"。Z 坐标为此提供了一种传递机制：

```
原始多边形 A 的顶点：Z = 点的原始 ID 或标签
原始多边形 B 的顶点：Z = 点的原始 ID 或标签

裁剪产生的新交点：Z = ？（需要用户自定义逻辑来决定）
```

#### ZFillFunction 回调委托

当 `use_xyz` 启用时，Clipper 类会暴露一个回调委托：

```csharp
// 委托类型定义
public delegate void ZFillCallback(IntPoint bot1, IntPoint top1,
                                    IntPoint bot2, IntPoint top2,
                                    ref IntPoint pt);

// Clipper 类中的属性
public ZFillCallback ZFillFunction { get; set; }
```

当两条边产生交点时，Clipper 会调用这个回调，传入两条边的端点，让用户决定新交点的 Z 值。典型应用场景：

| 应用场景 | Z 值含义 | ZFillFunction 逻辑 |
|:---|:---|:---|
| GIS 高程数据 | 海拔高度 | 根据交点在两条边上的位置进行线性插值 |
| 点 ID 追踪 | 原始顶点 ID | 记录产生此交点的两条源边的 ID |
| 颜色映射 | 颜色编码 | 混合两条边端点的颜色值 |
| 层级标记 | 图层编号 | 选择优先级更高的图层编号 |

#### 示例：Z 值线性插值

```csharp
// 启用 use_xyz 后的典型 ZFillFunction 实现
clipper.ZFillFunction = (IntPoint bot1, IntPoint top1,
                         IntPoint bot2, IntPoint top2,
                         ref IntPoint pt) =>
{
    // 对两条边的 Z 值进行简单平均
    // 实际应用中可能需要根据交点位置进行加权插值
    pt.Z = (bot1.Z + top1.Z + bot2.Z + top2.Z) / 4;
};
```

#### 内存影响

| 配置 | IntPoint 大小 | 100 万点占用 |
|:---:|:---:|:---:|
| Int64，无 Z | 16 字节 | ~15.3 MB |
| Int64，有 Z | 24 字节 | ~22.9 MB |
| Int32，无 Z | 8 字节 | ~7.6 MB |
| Int32，有 Z | 12 字节 | ~11.4 MB |

### 6.2.3 Path 和 Paths 类型别名

#### 源码定义

```csharp
using Path = System.Collections.Generic.List<ClipperLib.IntPoint>;
using Paths = System.Collections.Generic.List<System.Collections.Generic.List<ClipperLib.IntPoint>>;
```

简化来看：

```csharp
Path  ≡ List<IntPoint>     // 单个多边形轮廓（有序顶点列表）
Paths ≡ List<List<IntPoint>> // 多边形集合（多个轮廓的列表）
```

#### Path — 单个多边形轮廓

一个 `Path` 表示一个**有序的顶点序列**，定义了一个多边形的边界或一条折线。

```
Path 的两种语义：

1. 闭合路径（Closed Path）→ 多边形轮廓
   顶点: [P0, P1, P2, P3]
   隐含的边: P0→P1, P1→P2, P2→P3, P3→P0（自动闭合）

   P0 ─────── P1
   │           │
   │           │
   P3 ─────── P2

2. 开放路径（Open Path）→ 折线
   顶点: [P0, P1, P2, P3]
   边: P0→P1, P1→P2, P2→P3（不闭合）

   P0 ─── P1
              \
               P2 ─── P3
```

#### 环绕方向（Winding Order）

对于闭合路径，顶点的排列顺序决定了**环绕方向**（Winding Direction），这对于区分外边界和孔洞至关重要：

```
标准数学坐标系（Y 轴向上）：
  逆时针（CCW）= 正方向 → 外边界
  顺时针（CW） = 负方向 → 孔洞

屏幕坐标系（Y 轴向下，Clipper 默认）：
  顺时针（CW） = 正方向 → 外边界
  逆时针（CCW）= 负方向 → 孔洞
```

在 Clipper 中，`ReverseSolution` 属性可以反转输出的环绕方向。

可以使用 `Clipper.Orientation()` 静态方法检查路径的方向：

```csharp
public static bool Orientation(Path poly)
{
    return Area(poly) >= 0;
    // 返回 true  → 在默认坐标系中为正方向（外边界）
    // 返回 false → 负方向（孔洞）
}
```

#### Paths — 多边形集合

一个 `Paths` 对象可以表示：

```
┌────────────────────────────────────────────────────────────┐
│  Paths = [Path0, Path1, Path2, ...]                        │
│                                                            │
│  场景1：多个独立的多边形                                     │
│  ┌────┐   ┌────┐   ┌────┐                                  │
│  │Path0│   │Path1│   │Path2│                                │
│  └────┘   └────┘   └────┘                                  │
│                                                            │
│  场景2：一个带孔洞的多边形                                   │
│  ┌─────────────────────┐                                   │
│  │ Path0（外边界，CW）   │                                   │
│  │   ┌──────────┐       │                                   │
│  │   │Path1（孔洞，CCW）│                                   │
│  │   └──────────┘       │                                   │
│  └─────────────────────┘                                   │
│                                                            │
│  场景3：混合                                                │
│  多个多边形，部分带有孔洞                                    │
└────────────────────────────────────────────────────────────┘
```

#### 为什么使用类型别名而非自定义类？

Angus Johnson 选择使用 `List<IntPoint>` 的类型别名而非自定义的 `Polygon` 类，这是一个深思熟虑的设计决策：

1. **简洁性**：用户可以直接使用 `List<T>` 的所有方法（`Add`、`Insert`、`RemoveAt`、`Count`、LINQ 操作等），无需学习新 API
2. **互操作性**：与其他使用 `List<T>` 的库无缝集成
3. **序列化友好**：标准集合类型可以直接使用 JSON/XML 序列化
4. **避免过度封装**：多边形本质上就是一个点的列表，过度封装反而增加复杂度

#### 在代码库中的使用示例

```csharp
// 创建一个矩形路径
Path rect = new Path(4);
rect.Add(new IntPoint(0, 0));
rect.Add(new IntPoint(100, 0));
rect.Add(new IntPoint(100, 100));
rect.Add(new IntPoint(0, 100));

// 创建路径集合
Paths subject = new Paths();
subject.Add(rect);

// 添加到 Clipper
Clipper c = new Clipper();
c.AddPaths(subject, PolyType.ptSubject, true);  // true = 闭合路径

// 执行裁剪
Paths solution = new Paths();
c.Execute(ClipType.ctUnion, solution);
```

### 6.2.4 use_lines 条件编译标志

#### 源码定义

```csharp
#if use_lines
  // 在多个位置启用开放路径（折线）支持代码
#endif
```

`use_lines` 控制 Clipper 库是否支持**开放路径**（Open Paths / Polylines）处理。

#### 开放路径 vs 闭合路径

```
闭合路径（Closed Path）：
  ┌────────┐
  │        │    所有边首尾相连，形成封闭区域
  │        │    用于表示多边形（面积区域）
  └────────┘

开放路径（Open Path）：
  ○────────●────────○    有起点和终点，不闭合
                         用于表示折线（线段序列）
```

#### 对代码的影响

当 `use_lines` 被定义时，以下行为被启用：

1. **`AddPath()` 方法接受开放路径**：

```csharp
public bool AddPath(Path pg, PolyType polyType, bool Closed)
{
#if use_lines
    if (!Closed && polyType == PolyType.ptClip)
        throw new ClipperException("AddPath: Open paths must be subject.");
#else
    if (!Closed)
        throw new ClipperException("AddPath: Open paths have been disabled.");
#endif
    // ...
}
```

2. **裁剪算法中的特殊处理**：开放路径不参与面积计算，但会被裁剪多边形"切割"
3. **`TEdge` 结构中的标记**：开放路径的边会被标记，以便在构建输出时进行特殊处理

#### 默认状态

在 Clipper 6.4.2 中，`use_lines` **默认是启用的**。这意味着出厂即支持开放路径的裁剪操作。

#### 使用限制

开放路径的使用有一些限制：

| 限制 | 原因 |
|:---|:---|
| 开放路径只能作为 `ptSubject` | 裁剪操作的"工具"必须是闭合的面积区域 |
| 开放路径不参与填充规则计算 | 线段没有"内部"和"外部"的概念 |
| 开放路径不能用于 `ClipperOffset`（直接） | 偏移操作有专门的 `EndType` 来处理端点 |

## 6.3 ClipType 枚举 — 布尔运算类型

`ClipType` 是 Clipper 库最核心的枚举类型，它定义了四种基本的**多边形布尔运算**。

#### 源码定义

```csharp
public enum ClipType { ctIntersection, ctUnion, ctDifference, ctXor };
```

这四个枚举值分别对应集合论中的四种基本运算：

| 枚举值 | 中文名 | 集合论符号 | 数学定义 |
|:---:|:---:|:---:|:---|
| `ctIntersection` | 交集 | A ∩ B | 同时属于 A 和 B 的区域 |
| `ctUnion` | 并集 | A ∪ B | 属于 A 或 B（或两者）的区域 |
| `ctDifference` | 差集 | A \ B | 属于 A 但不属于 B 的区域 |
| `ctXor` | 异或 | A △ B | 属于 A 或 B 但不同时属于两者的区域 |

### 6.3.1 ctIntersection（交集）

#### 数学定义

```
A ∩ B = { x | x ∈ A 且 x ∈ B }
```

交集运算的结果**仅包含同时属于主体（Subject）和裁剪体（Clip）的区域**。

#### ASCII 图示

```
    Subject (A)         Clip (B)          A ∩ B (交集)
  ┌──────────┐      ┌──────────┐
  │          │      │          │
  │    ┌─────┼──────┼─────┐    │      ┌─────┐
  │    │/////│//////│/////│    │      │/////│
  │    │/////│//////│/////│    │  →   │/////│
  │    └─────┼──────┼─────┘    │      └─────┘
  │          │      │          │
  └──────────┘      └──────────┘

  图例：///// = 重叠区域（交集结果）
```

#### 常见用例

- **碰撞检测**：计算两个物体的重叠区域
- **可见区域计算**：视锥体与场景的交集
- **地图叠加分析**：两个行政区域的交叉部分
- **遮罩裁剪**：将图像限制在特定形状内

#### 特性

- **交换律**：A ∩ B = B ∩ A（Subject 和 Clip 互换结果不变）
- **结合律**：(A ∩ B) ∩ C = A ∩ (B ∩ C)
- **空集性质**：如果 A 和 B 不重叠，结果为空

### 6.3.2 ctUnion（并集）

#### 数学定义

```
A ∪ B = { x | x ∈ A 或 x ∈ B }
```

并集运算的结果包含**属于任何一个输入多边形的区域**。

#### ASCII 图示

```
    Subject (A)         Clip (B)          A ∪ B (并集)
  ┌──────────┐      ┌──────────┐    ┌──────────────────┐
  │//////////│      │//////////│    │//////////////////│
  │////┌─────┼──────┼─────┐////│    │//////////////////│
  │////│/////│//////│/////│////│    │//////////////////│
  │////│/////│//////│/////│////│ →  │//////////////////│
  │////└─────┼──────┼─────┘////│    │//////////////////│
  │//////////│      │//////////│    │//////////////////│
  └──────────┘      └──────────┘    └──────────────────┘

  图例：///// = 并集结果（覆盖所有原始区域）
```

#### 常见用例

- **合并相邻多边形**：将碎片化的区域合并为一个整体
- **Dissolve 操作**：GIS 中的融合操作，消除多边形之间的边界
- **缓冲区合并**：多个缓冲区的联合
- **简化重叠区域**：去除多边形之间的重叠

#### 特殊用法：自身并集

对同一组多边形执行并集操作（不指定 Clip），可以实现**自我清理**：

```csharp
Clipper c = new Clipper();
c.AddPaths(polygons, PolyType.ptSubject, true);
Paths cleaned = new Paths();
c.Execute(ClipType.ctUnion, cleaned, PolyFillType.pftNonZero);
// cleaned 中的多边形已去除自交叉和重叠
```

#### 特性

- **交换律**：A ∪ B = B ∪ A
- **结合律**：(A ∪ B) ∪ C = A ∪ (B ∪ C)
- **恒等性**：A ∪ ∅ = A

### 6.3.3 ctDifference（差集）

#### 数学定义

```
A \ B = { x | x ∈ A 且 x ∉ B }
```

差集运算的结果包含**属于主体（Subject）但不属于裁剪体（Clip）的区域**。

#### ASCII 图示

```
    Subject (A)         Clip (B)          A \ B (差集)
  ┌──────────┐      ┌──────────┐    ┌─────┐
  │//////////│      │          │    │/////│
  │////┌─────┼──────┼─────┐    │    │/////│
  │////│     │      │     │    │    │/////│
  │////│     │      │     │    │ →  │/////│
  │////└─────┼──────┼─────┘    │    │/////│
  │//////////│      │          │    │/////│
  └──────────┘      └──────────┘    └─────┘

  图例：///// = 差集结果（A 中去掉与 B 重叠的部分）
```

#### **关键特性：差集不满足交换律**

```
A \ B ≠ B \ A  （一般情况下）
```

这是 `ClipType.ctDifference` 中**Subject 和 Clip 角色区分**至关重要的原因。如果交换了 Subject 和 Clip 的角色，差集结果将完全不同：

```
A \ B = A 中去掉 B 的部分
B \ A = B 中去掉 A 的部分

这两个结果通常完全不同！
```

#### 常见用例

- **开孔操作**：在大多边形中挖去小多边形形成的孔
- **裁剪**：保留地图中某个区域内的部分
- **擦除**：从绘图中移除特定区域
- **边界修剪**：去除多边形超出边界的部分

### 6.3.4 ctXor（异或）

#### 数学定义

```
A △ B = (A ∪ B) \ (A ∩ B) = (A \ B) ∪ (B \ A)
```

异或运算的结果包含**属于任何一个输入多边形但不同时属于两者的区域**。

#### ASCII 图示

```
    Subject (A)         Clip (B)          A △ B (异或)
  ┌──────────┐      ┌──────────┐    ┌─────┐     ┌─────┐
  │//////////│      │//////////│    │/////│     │/////│
  │////┌─────┼──────┼─────┐////│    │/////│     │/////│
  │////│     │      │     │////│    │/////│     │/////│
  │////│     │      │     │////│ →  │/////│     │/////│
  │////└─────┼──────┼─────┘////│    │/////│     │/////│
  │//////////│      │//////////│    │/////│     │/////│
  └──────────┘      └──────────┘    └─────┘     └─────┘

  图例：///// = 异或结果（重叠区域被移除）
```

#### 等价表达

异或可以用其他三种运算表示：

```
A △ B = (A ∪ B) \ (A ∩ B)    （并集减去交集）
      = (A \ B) ∪ (B \ A)    （两个差集的并集）
```

#### 特性

- **交换律**：A △ B = B △ A
- **结合律**：(A △ B) △ C = A △ (B △ C)
- **自逆性**：A △ A = ∅（与自身异或结果为空）

#### 常见用例

- **对称差异检测**：找出两个版本的地图之间的变化区域
- **切割效果**：创建"镂空"或"排除"效果
- **拼图生成**：将两个区域的独有部分分离出来

### 6.3.5 ClipType 在代码中的使用

`ClipType` 在 Clipper 库中的核心使用位置是 `IsContributing()` 方法。这个方法决定了扫描线处理过程中，一条边**是否对最终输出有贡献**——这是整个布尔运算的"灵魂"。

```csharp
private bool IsContributing(TEdge edge)
{
    PolyFillType pft, pft2;
    if (edge.PolyTyp == PolyType.ptSubject)
    {
        pft = m_SubjFillType;
        pft2 = m_ClipFillType;
    }
    else
    {
        pft = m_ClipFillType;
        pft2 = m_SubjFillType;
    }

    // 首先根据填充规则判断当前边是否"处于填充状态"
    switch (pft)
    {
        case PolyFillType.pftEvenOdd:
            if (edge.WindDelta == 0 && edge.WindCnt != 1) return false;
            break;
        case PolyFillType.pftNonZero:
            if (Math.Abs(edge.WindCnt) != 1) return false;
            break;
        case PolyFillType.pftPositive:
            if (edge.WindCnt != 1) return false;
            break;
        case PolyFillType.pftNegative:
            if (edge.WindCnt != -1) return false;
            break;
    }

    // 然后根据 ClipType 和另一组多边形的状态决定贡献性
    switch (m_ClipType)
    {
        case ClipType.ctIntersection:
            switch (pft2)
            {
                case PolyFillType.pftEvenOdd:
                case PolyFillType.pftNonZero:
                    return (edge.WindCnt2 != 0);        // 另一组有填充 → 贡献
                case PolyFillType.pftPositive:
                    return (edge.WindCnt2 > 0);
                case PolyFillType.pftNegative:
                    return (edge.WindCnt2 < 0);
            }
            break;

        case ClipType.ctUnion:
            switch (pft2)
            {
                case PolyFillType.pftEvenOdd:
                case PolyFillType.pftNonZero:
                    return (edge.WindCnt2 == 0);        // 另一组无填充 → 贡献
                case PolyFillType.pftPositive:
                    return (edge.WindCnt2 <= 0);
                case PolyFillType.pftNegative:
                    return (edge.WindCnt2 >= 0);
            }
            break;

        case ClipType.ctDifference:
            if (edge.PolyTyp == PolyType.ptSubject)
                switch (pft2)
                {
                    case PolyFillType.pftEvenOdd:
                    case PolyFillType.pftNonZero:
                        return (edge.WindCnt2 == 0);    // Subject 边：Clip 区域无填充 → 贡献
                    case PolyFillType.pftPositive:
                        return (edge.WindCnt2 <= 0);
                    case PolyFillType.pftNegative:
                        return (edge.WindCnt2 >= 0);
                }
            else
                switch (pft2)
                {
                    case PolyFillType.pftEvenOdd:
                    case PolyFillType.pftNonZero:
                        return (edge.WindCnt2 != 0);    // Clip 边：Subject 区域有填充 → 贡献
                    case PolyFillType.pftPositive:
                        return (edge.WindCnt2 > 0);
                    case PolyFillType.pftNegative:
                        return (edge.WindCnt2 < 0);
                }
            break;

        case ClipType.ctXor:
            return true;                                 // 异或：始终贡献
    }
    return true;
}
```

上面这段代码完整展示了 `ClipType` 如何驱动裁剪逻辑。核心思想是：

```
每条边是否"贡献"到输出，取决于：
  1. 该边自身的环绕计数（WindCnt）和当前多边形组的填充规则
  2. 另一组多边形在该边位置的环绕计数（WindCnt2）
  3. ClipType 指定的布尔运算规则

三者结合，精确决定每条边的输出行为。
```

`ClipType` 在 `Execute()` 方法中被传入并存储：

```csharp
public bool Execute(ClipType clipType, Paths solution,
    PolyFillType subjFillType, PolyFillType clipFillType)
{
    // ...
    m_ClipType = clipType;           // 存储布尔运算类型
    m_SubjFillType = subjFillType;   // 存储 Subject 的填充规则
    m_ClipFillType = clipFillType;   // 存储 Clip 的填充规则
    // ... 执行算法
}
```

## 6.4 PolyType 枚举 — 多边形角色类型

#### 源码定义

```csharp
public enum PolyType { ptSubject, ptClip };
```

`PolyType` 定义了多边形在布尔运算中的**角色**——是"被操作的主体"还是"操作的工具"。

| 枚举值 | 中文名 | 角色定位 |
|:---:|:---:|:---|
| `ptSubject` | 主体 | 被操作的主要多边形 |
| `ptClip` | 裁剪体 | 作为"工具"的多边形 |

### 6.4.1 Subject 与 Clip 的角色区分

在布尔运算中，Subject 和 Clip 的区分在以下两种情况下至关重要：

**（1）差集运算的非交换性**

```
ctDifference: 结果 = Subject \ Clip

Subject = 大矩形, Clip = 小圆形 → 结果是大矩形中挖了一个圆形的孔
Subject = 小圆形, Clip = 大矩形 → 结果可能是空的（圆形完全被矩形包含）
```

**（2）不同的填充规则**

Subject 和 Clip 可以使用**不同的填充规则**（PolyFillType）：

```csharp
clipper.Execute(ClipType.ctIntersection, solution,
    PolyFillType.pftEvenOdd,    // Subject 使用奇偶规则
    PolyFillType.pftNonZero);   // Clip 使用非零规则
```

这在处理来自不同来源（如不同 CAD 软件）的多边形数据时非常有用，因为不同来源可能使用不同的环绕约定。

### 6.4.2 在 TEdge 中的存储

每条边（`TEdge`）都携带了其 `PolyType` 信息：

```csharp
internal class TEdge
{
    // ... 其他字段
    internal PolyType PolyTyp;   // 这条边属于 Subject 还是 Clip
    // ...
}
```

在扫描线处理过程中，算法需要区分 Subject 边和 Clip 边来：

1. **计算环绕数**：Subject 边只受 Subject 边影响的部分计入 `WindCnt`，受 Clip 边影响的部分计入 `WindCnt2`
2. **判断贡献性**：如 `IsContributing()` 方法所示，不同 `PolyType` 的边在不同 `ClipType` 下的贡献规则不同
3. **构建输出**：在差集运算中，Subject 边和 Clip 边的输出侧不同

环绕数计算的相关代码：

```csharp
private void SetWindingCount(TEdge edge)
{
    TEdge e = edge.PrevInAEL;
    // 找到同类型的前一条边
    while (e != null && ((e.PolyTyp != edge.PolyTyp) || (e.WindDelta == 0)))
        e = e.PrevInAEL;

    if (e == null)
    {
        // 没有同类型的前边 → 环绕数初始化
        edge.WindCnt = (edge.WindDelta == 0 ? 1 : edge.WindDelta);
        edge.WindCnt2 = 0;
        e = m_ActiveEdges; // 从 AEL 头部开始计算 WindCnt2
    }
    else if (edge.WindDelta == 0 && m_ClipType != ClipType.ctUnion)
    {
        edge.WindCnt = 1;
        edge.WindCnt2 = e.WindCnt2;
        e = e.NextInAEL;
    }
    // ... 更多逻辑
}
```

### 6.4.3 在 AddPath 中的赋值

`PolyType` 在用户调用 `AddPath()` 或 `AddPaths()` 时被指定，并在构建边结构时赋值到每条 `TEdge`：

```csharp
// 用户代码
Clipper c = new Clipper();
c.AddPath(subjectPoly, PolyType.ptSubject, true);  // 标记为 Subject
c.AddPath(clipPoly, PolyType.ptClip, true);         // 标记为 Clip

// ClipperBase.AddPath() 内部
public bool AddPath(Path pg, PolyType polyType, bool Closed)
{
    // ... 验证和预处理
    TEdge[] edges = new TEdge[pg.Count];
    // 创建边并设置 PolyType
    for (int i = 0; i < pg.Count; i++)
    {
        edges[i] = new TEdge();
        edges[i].PolyTyp = polyType;  // ← 赋值 PolyType
        // ... 其他初始化
    }
    // ...
}
```

一旦赋值，`PolyType` 在整个算法执行过程中保持不变——每条边始终"知道"自己是 Subject 还是 Clip。

## 6.5 PolyFillType 枚举 — 填充规则

`PolyFillType` 是 Clipper 库中**最精巧**的枚举类型。它定义了如何判断一个点是否在多边形的"内部"——这个看似简单的问题在处理复杂多边形（特别是自交叉多边形）时变得非常微妙。

#### 源码定义

```csharp
public enum PolyFillType { pftEvenOdd, pftNonZero, pftPositive, pftNegative };
```

### 6.5.1 填充规则的数学基础 — 环绕数（Winding Number）

#### 什么是环绕数？

**环绕数**（Winding Number）是拓扑学中的一个概念，它描述了一条闭合曲线绕某个点旋转的总次数。

对于一个多边形边界和一个测试点 P：

1. 从点 P 向任意方向发出一条射线（通常向右）
2. 计算射线与多边形边的交叉：
   - 边从下向上穿越射线：环绕数 **+1**
   - 边从上向下穿越射线：环绕数 **-1**
3. 所有交叉的代数和即为点 P 的环绕数

```
射线法计算环绕数示例：

        ┌───────┐
        │       │ ↑ 从下向上穿越 (+1)
  P ────┼───────┼────────→ 射线
        │       │ ↓ 从上向下穿越 (-1)
        └───────┘

环绕数 = (+1) + (-1) = 0 → P 在多边形外部

        ┌───────┐
        │       │ ↑ (+1)
        │ P ────┼────────→ 射线
        │       │ ↓ (-1)  （射线不再穿越左边）
        └───────┘

环绕数 = (+1) + 0 = 不为零 → 但实际上...

正确理解：对于简单（非自交叉）多边形，射线穿越奇数次边就在内部，偶数次就在外部。
但对于复杂多边形，不同的填充规则会给出不同答案。
```

在 Clipper 中，环绕数的计算通过 `WindCnt`（Wind Count）字段实现：

```csharp
internal class TEdge
{
    internal int WindDelta;  // 这条边对环绕数的贡献（+1 或 -1）
    internal int WindCnt;    // 当前边的同类型环绕计数
    internal int WindCnt2;   // 当前边的异类型环绕计数
}
```

#### WindDelta 的赋值

```csharp
// 在边初始化时
if (/* 边的方向是从下到上 */)
    edge.WindDelta = 1;    // 正方向
else
    edge.WindDelta = -1;   // 反方向

// 对于开放路径的端边
if (/* 开放路径 */)
    edge.WindDelta = 0;    // 不贡献环绕数
```

### 6.5.2 pftEvenOdd（奇偶规则）

#### 规则定义

```
点 P 在多边形内部 ⟺ P 的环绕数为奇数
等价于：从 P 发射线，穿越边的次数为奇数
```

**奇偶规则完全忽略边的方向**——它只关心穿越次数的奇偶性。每穿越一条边，就在"内部/外部"之间切换一次。

#### 自交叉多边形示例

```
五角星多边形（自交叉）：

         A
        /|\
       / | \
      /  |  \
     /   |   \
    E────┼────B
     \   |   /
      \  |  /
       \ | /
        \|/
    D────┼────C

奇偶规则下的填充状态：

         A
        /|\
       /1|1\          1 = 填充（穿越 1 次边）
      /  |  \
     / 2 | 2 \        2 = 不填充（穿越 2 次边）→ 中心五边形为空
    E────┼────B
     \ 1 | 1 /        1 = 填充
      \  |  /
       \ | /
        \|/
    D────┼────C

在奇偶规则下，五角星的中心五边形是空的！
因为到达中心需要穿越 2 条边（偶数）→ 外部
```

#### 特点

- **简单直观**：每次穿越就切换状态
- **方向无关**：不需要关心多边形的环绕方向
- **SVG 默认规则**：SVG 标准中 `fill-rule="evenodd"` 即此规则
- **对简单多边形**：与非零规则给出相同结果
- **对自交叉多边形**：产生"交替填充"效果

#### 在 Clipper 中的实现

```csharp
// IsContributing() 中 pftEvenOdd 的判断
case PolyFillType.pftEvenOdd:
    if (edge.WindDelta == 0 && edge.WindCnt != 1) return false;
    break;
// 奇偶规则只关心环绕计数是否为 1（即处于"内部"状态的边界上）
// 对于 WindDelta == 0 的边（开放路径），也同样判断
```

### 6.5.3 pftNonZero（非零规则）

#### 规则定义

```
点 P 在多边形内部 ⟺ P 的环绕数 ≠ 0
```

非零规则**考虑边的方向**——从下向上的边贡献 +1，从上向下的边贡献 -1。只有当所有贡献的代数和不为零时，点才被认为在内部。

#### 自交叉多边形示例

```
五角星多边形（自交叉）：

         A
        /|\
       / | \
      /  |  \
     / w=2|   \
    E────┼────B    w = 环绕数
     \ w=2|   /
      \  |  /
       \ | /
        \|/
    D────┼────C

非零规则下的填充状态：

         A
        /|\
       /1|1\          1 = 填充（环绕数 = 1 ≠ 0）
      /  |  \
     / 2 | 2 \        2 = 填充（环绕数 = 2 ≠ 0）→ 中心五边形也是填充的！
    E────┼────B
     \ 1 | 1 /        1 = 填充
      \  |  /
       \ | /
        \|/
    D────┼────C

在非零规则下，五角星完全填充！
因为中心区域的环绕数为 2（≠ 0）→ 内部
```

#### 特点

- **方向相关**：考虑边的穿越方向
- **CAD 常用规则**：许多 CAD 应用程序的默认规则
- **全填充效果**：对于同向环绕的重叠区域，总是填充
- **PDF 默认规则**：PDF 标准中的默认填充规则

#### 在 Clipper 中的实现

```csharp
// IsContributing() 中 pftNonZero 的判断
case PolyFillType.pftNonZero:
    if (Math.Abs(edge.WindCnt) != 1) return false;
    break;
// 非零规则下，只有当 |WindCnt| == 1 时边才贡献
// 即这条边处于"内部/外部"的分界线上
// |WindCnt| > 1 意味着这条边在多个重叠区域内部，不是有效边界
```

### 6.5.4 pftPositive（正值规则）

#### 规则定义

```
点 P 在多边形内部 ⟺ P 的环绕数 > 0
```

正值规则只认为**正方向环绕**的区域为内部。

#### 应用场景

```
两个重叠的多边形，一个顺时针一个逆时针：

  顺时针（环绕数 +1）     逆时针（环绕数 -1）
  ┌──────────┐           ┌──────────┐
  │  w = +1  │           │  w = -1  │
  │    ┌─────┼───────────┼─────┐    │
  │    │ w=0 │           │ w=0 │    │
  │    └─────┼───────────┼─────┘    │
  │          │           │          │
  └──────────┘           └──────────┘

在正值规则下：
  w = +1 的区域 → 填充 ✓
  w = -1 的区域 → 不填充 ✗
  w = 0 的重叠区域 → 不填充 ✗（+1 和 -1 抵消）
```

#### 在 Clipper 中的实现

```csharp
// IsContributing() 中 pftPositive 的判断
case PolyFillType.pftPositive:
    if (edge.WindCnt != 1) return false;
    break;
// 正值规则下，只有当 WindCnt 恰好等于 1 时边才贡献
// WindCnt == 1 表示这条边是从"外部"进入"正环绕区域"的边界
```

### 6.5.5 pftNegative（负值规则）

#### 规则定义

```
点 P 在多边形内部 ⟺ P 的环绕数 < 0
```

负值规则是正值规则的**镜像**——只认为**负方向环绕**的区域为内部。

#### 在 Clipper 中的实现

```csharp
// IsContributing() 中 pftNegative 的判断
case PolyFillType.pftNegative:
    if (edge.WindCnt != -1) return false;
    break;
// 负值规则下，只有当 WindCnt 恰好等于 -1 时边才贡献
// WindCnt == -1 表示这条边是从"外部"进入"负环绕区域"的边界
```

#### 正值 vs 负值规则的选择

| 坐标系 | 外边界方向 | 适用规则 |
|:---:|:---:|:---:|
| 数学坐标（Y 向上） | 逆时针 | `pftPositive`（CCW 产生正环绕数） |
| 屏幕坐标（Y 向下） | 顺时针 | `pftPositive`（CW 在 Y 翻转坐标系中产生正环绕数） |
| 需要仅提取反向环绕区域 | — | `pftNegative` |

### 6.5.6 四种填充规则的对比表

下表总结了四种填充规则在不同环绕数下的行为：

| 环绕数 | pftEvenOdd | pftNonZero | pftPositive | pftNegative |
|:---:|:---:|:---:|:---:|:---:|
| -3 | 内部（奇数） | 内部（≠0） | 外部（<0不满足>0） | 内部（<0） |
| -2 | 外部（偶数） | 内部（≠0） | 外部 | 内部 |
| -1 | 内部（奇数） | 内部（≠0） | 外部 | 内部 |
| 0 | 外部（偶数） | 外部（=0） | 外部 | 外部 |
| 1 | 内部（奇数） | 内部（≠0） | 内部（>0） | 外部（>0不满足<0） |
| 2 | 外部（偶数） | 内部（≠0） | 内部 | 外部 |
| 3 | 内部（奇数） | 内部（≠0） | 内部 | 外部 |

可视化对比：

```
环绕数:   -3    -2    -1     0     1     2     3
          ─────┼─────┼─────┼─────┼─────┼─────┼─────

EvenOdd:  ████       ████        ████        ████
NonZero:  ████  ████  ████        ████  ████  ████
Positive:                         ████  ████  ████
Negative: ████  ████  ████

图例: ████ = 内部（填充）, 空白 = 外部
```

#### 填充规则选择指南

| 场景 | 推荐规则 | 原因 |
|:---|:---:|:---|
| 简单多边形（无自交叉） | 任意 | 四种规则结果相同 |
| SVG 渲染兼容 | `pftEvenOdd` | SVG 默认规则 |
| CAD 数据处理 | `pftNonZero` | CAD 软件通常使用非零规则 |
| 自交叉多边形全填充 | `pftNonZero` | 不会产生"空洞" |
| 自交叉多边形交替填充 | `pftEvenOdd` | 产生棋盘格效果 |
| 仅正向环绕区域 | `pftPositive` | 过滤方向 |
| 混合来源数据 | 分别指定 | Subject 和 Clip 可使用不同规则 |

在核心环绕数计算中，填充规则决定了边的计数方式：

```csharp
private void SetWindingCount(TEdge edge)
{
    TEdge e = edge.PrevInAEL;
    // 查找同类型的前一条边，获取基准环绕数
    while (e != null && ((e.PolyTyp != edge.PolyTyp) || (e.WindDelta == 0)))
        e = e.PrevInAEL;

    if (e == null)
    {
        // 没有同类型的前边
        PolyFillType pft = (edge.PolyTyp == PolyType.ptSubject)
            ? m_SubjFillType : m_ClipFillType;
        edge.WindCnt = (edge.WindDelta == 0 ? 1 : edge.WindDelta);
        edge.WindCnt2 = 0;
        e = m_ActiveEdges;
    }
    else if (edge.WindDelta == 0 && m_ClipType != ClipType.ctUnion)
    {
        edge.WindCnt = 1;
        edge.WindCnt2 = e.WindCnt2;
        e = e.NextInAEL;
    }
    else if (IsEvenOddFillType(edge))
    {
        // ★ 奇偶规则：环绕计数在 0 和 1 之间切换
        if (edge.WindDelta == 0)
        {
            bool Inside = true;
            TEdge e2 = e.PrevInAEL;
            while (e2 != null)
            {
                if (e2.PolyTyp == edge.PolyTyp && e2.WindDelta != 0)
                    Inside = !Inside;
                e2 = e2.PrevInAEL;
            }
            edge.WindCnt = (Inside ? 0 : 1);
        }
        else
        {
            edge.WindCnt = edge.WindDelta;
        }
        edge.WindCnt2 = e.WindCnt2;
        e = e.NextInAEL;
    }
    else
    {
        // ★ 非奇偶规则（NonZero/Positive/Negative）：累加环绕数
        if (e.WindCnt * e.WindDelta < 0)
        {
            // 前边和当前边方向相反
            if (Math.Abs(e.WindCnt) > 1)
            {
                if (e.WindDelta * edge.WindDelta < 0)
                    edge.WindCnt = e.WindCnt;
                else
                    edge.WindCnt = e.WindCnt + edge.WindDelta;
            }
            else
                edge.WindCnt = (edge.WindDelta == 0 ? 1 : edge.WindDelta);
        }
        else
        {
            // 前边和当前边方向相同
            if (edge.WindDelta == 0)
                edge.WindCnt = (e.WindCnt < 0 ? e.WindCnt - 1 : e.WindCnt + 1);
            else if (e.WindDelta * edge.WindDelta < 0)
                edge.WindCnt = e.WindCnt;
            else
                edge.WindCnt = e.WindCnt + edge.WindDelta;
        }
        edge.WindCnt2 = e.WindCnt2;
        e = e.NextInAEL;
    }

    // 计算 WindCnt2（另一类型的环绕数）
    if (IsEvenOddAltFillType(edge))
    {
        while (e != edge)
        {
            if (e.WindDelta != 0)
                edge.WindCnt2 = (edge.WindCnt2 == 0 ? 1 : 0);
            e = e.NextInAEL;
        }
    }
    else
    {
        while (e != edge)
        {
            edge.WindCnt2 += e.WindDelta;
            e = e.NextInAEL;
        }
    }
}
```

辅助方法判断是否使用奇偶规则：

```csharp
private bool IsEvenOddFillType(TEdge edge)
{
    if (edge.PolyTyp == PolyType.ptSubject)
        return m_SubjFillType == PolyFillType.pftEvenOdd;
    else
        return m_ClipFillType == PolyFillType.pftEvenOdd;
}

private bool IsEvenOddAltFillType(TEdge edge)
{
    if (edge.PolyTyp == PolyType.ptSubject)
        return m_ClipFillType == PolyFillType.pftEvenOdd;
    else
        return m_SubjFillType == PolyFillType.pftEvenOdd;
}
```

## 6.6 JoinType 枚举 — 连接类型

`JoinType` 用于 `ClipperOffset` 类，控制多边形偏移时**拐角处的连接方式**。

#### 源码定义

```csharp
public enum JoinType { jtSquare, jtRound, jtMiter };
```

| 枚举值 | 中文名 | 描述 |
|:---:|:---:|:---|
| `jtSquare` | 方形连接 | 拐角处截断为平面 |
| `jtRound` | 圆弧连接 | 拐角处生成圆弧 |
| `jtMiter` | 尖角连接 | 拐角处延伸为尖角 |

### 6.6.1 jtSquare（方形连接）

方形连接在多边形的每个顶点处生成一个**平截面**（bevel），将原来的尖角"削平"：

```
原始顶点:              jtSquare 偏移后:

      /\                    ╱──╲
     /  \                  ╱    ╲
    /    \                ╱      ╲
   /      \              ╱   /\   ╲
──/        \──        ──╱   /  \   ╲──
                              ↑ 原始顶点

削平后的角 = 垂直于两边的等距线的交点连线
```

#### 特点

- **可预测性强**：偏移后的宽度始终可控
- **无尖角溢出**：不会产生极长的尖角
- **适合制造加工**：在 CNC 加工和 PCB 布线中常用

#### 在 ClipperOffset 中的使用

```csharp
// 使用 jtSquare 进行偏移
ClipperOffset co = new ClipperOffset();
co.AddPath(path, JoinType.jtSquare, EndType.etClosedPolygon);
Paths result = new Paths();
co.Execute(ref result, 10.0);  // 向外偏移 10 个单位
```

### 6.6.2 jtRound（圆弧连接）

圆弧连接在每个顶点处生成一段**圆弧**，使偏移后的拐角呈圆滑过渡：

```
原始顶点:              jtRound 偏移后:

      /\                    ╭──╮
     /  \                  ╱    ╲
    /    \                ╱      ╲
   /      \              ╱   /\   ╲
──/        \──        ──╱   /  \   ╲──
                              ↑ 原始顶点

圆弧是以原始顶点为圆心、偏移距离为半径的弧
```

#### ArcTolerance 参数

圆弧连接的精度由 `ArcTolerance` 参数控制：

```csharp
ClipperOffset co = new ClipperOffset();
co.ArcTolerance = 0.25;  // 默认值
// ArcTolerance 定义了圆弧与真实圆之间的最大偏差（以坐标单位计）
```

`ArcTolerance` 越小，生成的弧线越平滑，但点数越多：

```
ArcTolerance 大（粗糙）:     ArcTolerance 小（精细）:

     ╱╲                          ╭╮
    ╱  ╲                        ╱  ╲
   ╱    ╲                      ╱    ╲
  ╱      ╲                    ╱      ╲

  点数少，性能好               点数多，更圆滑
```

`ArcTolerance` 与弧段数量的关系：

```csharp
// ClipperOffset 内部计算弧段角度步长
double steps = Math.PI / Math.Acos(1 - arcTolerance / Math.Abs(delta));
// delta = 偏移距离
// steps = 完整圆所需的段数
// 实际每个拐角只使用其中一部分段
```

### 6.6.3 jtMiter（尖角连接）

尖角连接将两条偏移边线**延伸直至相交**，形成尖锐的角：

```
原始顶点:              jtMiter 偏移后:

      /\                       /\
     /  \                     /  \    ← 尖角延伸
    /    \                   /    \
   /      \                 / /  \ \
──/        \──          ───/ /    \ \───
                              ↑ 原始顶点

当原始角度很小时，尖角会延伸得很长
```

#### MiterLimit 参数

由于小角度会导致尖角无限延伸，`MiterLimit` 参数用于限制延伸长度：

```csharp
ClipperOffset co = new ClipperOffset(MiterLimit: 2.0);
// MiterLimit = 尖角长度与偏移距离的最大比值
// 默认值 = 2.0

// 当实际的 miter 比超过 MiterLimit 时，自动退化为 Square 连接
```

MiterLimit 与角度的关系：

```
MiterLimit = 1 / sin(θ/2)    其中 θ = 两边的夹角

MiterLimit = 2.0 → θ_min ≈ 60°（小于 60° 的角退化为 Square）
MiterLimit = 3.0 → θ_min ≈ 38.9°
MiterLimit = 4.0 → θ_min ≈ 28.9°
MiterLimit = 10.0 → θ_min ≈ 11.5°
```

```csharp
// ClipperOffset 内部的 MiterLimit 检查
private void DoMiter(int j, int k, double r)
{
    double q = m_delta / r;
    if (q > m_miterLim)
    {
        // 超过 MiterLimit，退化为 Square
        DoSquare(j, k);
        return;
    }
    // ... 正常的 miter 处理
}
```

## 6.7 EndType 枚举 — 端点类型

`EndType` 用于 `ClipperOffset` 类，控制路径**端点的处理方式**。

#### 源码定义

```csharp
public enum EndType {
    etClosedPolygon,   // 闭合多边形
    etClosedLine,      // 闭合线
    etOpenButt,        // 开放路径 - 平头
    etOpenSquare,      // 开放路径 - 方头
    etOpenRound        // 开放路径 - 圆头
};
```

五种端点类型可以分为两大类：

```
EndType
├── 闭合类型（路径首尾相连）
│   ├── etClosedPolygon  → 偏移为封闭区域
│   └── etClosedLine     → 偏移为"管状"轮廓
│
└── 开放类型（路径有起点和终点）
    ├── etOpenButt       → 平头端点
    ├── etOpenSquare     → 方头端点
    └── etOpenRound      → 圆头端点
```

### 6.7.1 etClosedPolygon — 闭合多边形

这是最常用的端点类型，用于**封闭的面积多边形**的偏移。

```
原始多边形:              偏移后:

  ┌────────┐          ┌──────────────┐
  │        │          │  ┌────────┐  │
  │        │    →     │  │ (原始) │  │
  │        │          │  └────────┘  │
  └────────┘          └──────────────┘

路径的两侧都被偏移，形成一个更大（或更小）的多边形
```

特点：
- 路径自动闭合（最后一点与第一点相连）
- 偏移在路径的**两侧**进行
- 正偏移量 → 扩大，负偏移量 → 收缩
- 结果始终是闭合的多边形

### 6.7.2 etClosedLine — 闭合线

用于闭合的**线条**偏移。与 `etClosedPolygon` 的区别在于：偏移结果形成一个围绕原始路径的"管道"。

```
原始闭合线:             偏移后:

  ┌────────┐          ┌──────────────┐
  │        │          │  ┌────────┐  │
  │        │    →     │  │        │  │
  │        │          │  │  ┌──┐  │  │
  └────────┘          │  │  │  │  │  │
                      │  └──┘  └──┘  │
                      └──────────────┘

结果是一个"环形"区域，内外两侧各偏移 delta 距离
```

特点：
- 路径自动闭合
- 但不作为面积区域处理——而是作为"线条"
- 结果包含外轮廓和内轮廓，形成"管道"效果
- 偏移量始终为正（负值无意义）

#### etClosedPolygon vs etClosedLine 的区别

```
输入: 一个正方形路径 [A, B, C, D]

etClosedPolygon, delta = +5:
  结果 = 一个更大的正方形（外扩 5 单位）

etClosedPolygon, delta = -5:
  结果 = 一个更小的正方形（内缩 5 单位）

etClosedLine, delta = 5:
  结果 = 一个"方环"（外圈 = 外扩 5，内圈 = 内缩 5）
  等价于 etClosedPolygon(+5) 减去 etClosedPolygon(-5)
```

### 6.7.3 etOpenButt — 平头端点

用于**开放路径**的偏移，端点处不延伸——精确到端点位置处就截断。

```
原始开放路径:

  A──────────────B

etOpenButt 偏移后:

  ┌──────────────┐
  │ A──────────B │
  └──────────────┘

端点 A 和 B 处的结束线与路径方向垂直
偏移"管道"精确在端点处截断
```

"Butt" 一词来自英语中"对接"的含义，表示端点处的平齐截面。

### 6.7.4 etOpenSquare — 方头端点

用于开放路径的偏移，端点处**向外延伸**偏移距离的长度，形成方形端帽。

```
原始开放路径:

  A──────────────B

etOpenSquare 偏移后:

┌────────────────────┐
│    A──────────B    │
└────────────────────┘
  ↑                ↑
  延伸 delta       延伸 delta

端点 A 和 B 处各向外延伸 delta 距离
```

#### etOpenButt vs etOpenSquare 的区别

```
                        etOpenButt:         etOpenSquare:
原始路径长度 L:          │←── L ──→│         │←── L + 2δ ──→│
                        ┌──────────┐        ┌────────────────┐
                        │          │        │                │
端点位置:               └──────────┘        └────────────────┘
                        ↑          ↑      ↑                    ↑
                     端点处截断          端点外延伸 δ

δ = 偏移距离
```

### 6.7.5 etOpenRound — 圆头端点

用于开放路径的偏移，端点处生成**半圆形端帽**。

```
原始开放路径:

  A──────────────B

etOpenRound 偏移后:

╭────────────────────╮
│    A──────────B    │
╰────────────────────╯
  ↑                ↑
  半圆形端帽       半圆形端帽

半径 = 偏移距离 delta
```

圆形端帽的精度同样受 `ArcTolerance` 参数控制。

#### 在 ClipperOffset.AddPath() 中的使用

```csharp
public void AddPath(Path path, JoinType joinType, EndType endType)
{
    int highI = path.Count - 1;
    if (highI < 0) return;

    PolyNode newNode = new PolyNode();
    newNode.m_jointype = joinType;
    newNode.m_endtype = endType;

    // 闭合类型的验证
    if (endType == EndType.etClosedLine || endType == EndType.etClosedPolygon)
    {
        // 闭合路径至少需要 3 个点
        while (highI > 0 && path[highI] == path[0]) highI--;
        if (highI < 2) return;
    }
    else
    {
        // 开放路径至少需要 2 个点
        if (highI < 1) return;
    }
    // ... 继续处理
}
```

## 6.8 内部枚举 — EdgeSide 和 Direction

除了面向用户的公开枚举外，Clipper 还定义了两个**内部枚举**（`internal`），仅在算法内部使用。

#### 源码定义

```csharp
internal enum EdgeSide { esLeft, esRight };
internal enum Direction { dRightToLeft, dLeftToRight };
```

这两个枚举被标记为 `internal`，意味着它们**不对库的使用者可见**——它们是算法实现的内部细节。

### 6.8.1 EdgeSide — 边侧

#### 含义

`EdgeSide` 用于标记一条边在**局部最小值对**（Local Minimum Pair）中的位置——是左边界还是右边界。

```
局部最小值（Local Minimum）：

         左边界           右边界
          (esLeft)       (esRight)
            ╱               ╲
           ╱                 ╲
          ╱                   ╲
         ╱                     ╲
        ╱                       ╲
       ○─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─○
                   ↑
            局部最小点（Y 最低点）

两条边从同一个最低点"向上分叉"
左边向左上方延伸 → esLeft
右边向右上方延伸 → esRight
```

#### 在输出多边形构建中的作用

`EdgeSide` 决定了新生成的输出点应该添加到输出多边形的**哪一侧**：

```csharp
private void AddOutPt(TEdge e, IntPoint pt)
{
    if (e.Side == EdgeSide.esLeft)
    {
        // 左侧边：点添加到输出多边形链表的头部
        op = new OutPt();
        op.Pt = pt;
        op.Next = outRec.Pts;
        // ...
    }
    else
    {
        // 右侧边：点添加到输出多边形链表的尾部
        op = new OutPt();
        op.Pt = pt;
        op.Prev = outRec.Pts;
        // ...
    }
}
```

这种设计确保了输出多边形的顶点能够按照正确的顺序（环绕方向）排列。

#### 在边交换操作中的使用

当两条边在扫描线上交叉时（交点事件），它们的 `EdgeSide` 需要交换：

```csharp
private void SwapSides(TEdge edge1, TEdge edge2)
{
    EdgeSide side = edge1.Side;
    edge1.Side = edge2.Side;
    edge2.Side = side;
}
```

### 6.8.2 Direction — 扫描方向

#### 含义

`Direction` 用于指示对**活跃边列表**（Active Edge List, AEL）的遍历方向，特别是在处理水平边（Horizontal Edges）时。

```
活跃边列表（AEL）中的边按 X 坐标排序：

  ← dRightToLeft（从右向左遍历）
  X: 10    30    50    70    90
      │     │     │     │     │
      e1    e2    e3    e4    e5
  → dLeftToRight（从左向右遍历）
```

#### 在水平边处理中的使用

水平边的处理是 Clipper 算法中最复杂的部分之一。`Direction` 决定了处理水平边时的遍历方向：

```csharp
private void ProcessHorizontal(TEdge horzEdge)
{
    Direction dir;
    cInt horzLeft, horzRight;

    if (horzEdge.Bot.X < horzEdge.Top.X)
    {
        horzLeft = horzEdge.Bot.X;
        horzRight = horzEdge.Top.X;
        dir = Direction.dLeftToRight;  // 水平边从左到右
    }
    else
    {
        horzLeft = horzEdge.Top.X;
        horzRight = horzEdge.Bot.X;
        dir = Direction.dRightToLeft;  // 水平边从右到左
    }

    // 根据方向决定遍历 AEL 的起点和终点
    TEdge eStart;
    if (dir == Direction.dLeftToRight)
    {
        eStart = horzEdge.NextInAEL;  // 从水平边的右邻居开始
        // 向右遍历，处理与水平边交叉的边
    }
    else
    {
        eStart = horzEdge.PrevInAEL;  // 从水平边的左邻居开始
        // 向左遍历
    }
    // ...
}
```

#### 为什么水平边需要特殊方向处理？

普通的非水平边在扫描线推进时自然会产生交点，但水平边**横跨一个 Y 值**，需要在同一个 Y 值上处理所有与之交叉的边。遍历方向确保了正确的交点处理顺序：

```
水平边 H 从左到右（dLeftToRight）：
                                    遍历方向 →
     e1      e2    H────────────    e3      e4
     │       │     ────────────     │       │
     │       │                      │       │
     
处理顺序：先处理 e3，再处理 e4
（从水平边的右端开始向右查找交叉边）

水平边 H 从右到左（dRightToLeft）：
                  ← 遍历方向
     e1      e2    ────────────H    e3      e4
     │       │     ────────────     │       │
     │       │                      │       │
     
处理顺序：先处理 e2，再处理 e1
（从水平边的左端开始向左查找交叉边）
```

## 6.9 枚举系统的整体设计分析

### 6.9.1 命名惯例

Clipper 库的枚举值遵循一种独特的**Pascal/Delphi 风格命名惯例**——使用小写前缀 + CamelCase 后缀。这是因为 Clipper 最初是用 Delphi 编写的，后来移植到 C#、C++、Java 等语言。

| 前缀 | 来源枚举类型 | 含义 | 示例 |
|:---:|:---:|:---|:---|
| `ct` | `ClipType` | Clip Type | `ctIntersection`, `ctUnion` |
| `pt` | `PolyType` | Poly Type | `ptSubject`, `ptClip` |
| `pft` | `PolyFillType` | Poly Fill Type | `pftEvenOdd`, `pftNonZero` |
| `jt` | `JoinType` | Join Type | `jtSquare`, `jtRound` |
| `et` | `EndType` | End Type | `etClosedPolygon`, `etOpenButt` |
| `es` | `EdgeSide` | Edge Side | `esLeft`, `esRight` |
| `d` | `Direction` | Direction | `dLeftToRight`, `dRightToLeft` |

这种命名惯例的优点：

1. **避免冲突**：不同枚举中的值可以有相似的名称而不冲突
2. **快速识别**：看到前缀就知道属于哪个枚举
3. **Delphi 传统**：Delphi 不支持枚举值的限定访问（`EnumType.Value`），因此需要前缀来区分
4. **跨语言一致**：C#、C++、Java 版本的 Clipper 都使用相同的命名

在现代 C# 中，通常推荐使用 PascalCase 不带前缀（如 `Intersection` 而非 `ctIntersection`），因为 C# 支持 `ClipType.Intersection` 这种限定访问。但 Clipper 保留了 Delphi 风格以保持跨版本一致性。

### 6.9.2 公开枚举 vs 内部枚举

Clipper 的枚举类型可以按可见性分为两层：

```
┌─────────────────────────────────────────────────────────────┐
│                     公开 API 层（public）                      │
│                                                             │
│  ┌──────────┐ ┌────────┐ ┌─────────────┐                   │
│  │ ClipType │ │PolyType│ │PolyFillType │                   │
│  └──────────┘ └────────┘ └─────────────┘                   │
│                                                             │
│  ┌──────────┐ ┌─────────┐                                  │
│  │ JoinType │ │ EndType │                                   │
│  └──────────┘ └─────────┘                                  │
│                                                             │
│  用户直接使用这些枚举来配置 Clipper 的行为                     │
├─────────────────────────────────────────────────────────────┤
│                     内部实现层（internal）                     │
│                                                             │
│  ┌──────────┐ ┌───────────┐                                │
│  │ EdgeSide │ │ Direction │                                 │
│  └──────────┘ └───────────┘                                │
│                                                             │
│  算法内部使用，对用户不可见                                    │
└─────────────────────────────────────────────────────────────┘
```

这种分层设计遵循了良好的**信息隐藏**原则：

- **公开层**：5 个枚举，定义了用户需要做出的所有选择
- **内部层**：2 个枚举，封装了算法实现细节

用户只需关心"做什么运算"（ClipType）、"谁是主体谁是工具"（PolyType）、"如何定义内部"（PolyFillType）、"拐角如何连接"（JoinType）、"端点如何处理"（EndType），而不需要知道算法内部如何遍历活跃边列表。
