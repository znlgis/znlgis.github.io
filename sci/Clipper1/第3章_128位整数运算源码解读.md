# 第3章：128位整数运算（Int128）源码解读

## 3.1 引言

在前一章中，我们分析了 Clipper1 的基础数据结构 `IntPoint`、`IntRect` 和 `DoublePoint`。我们知道，Clipper1 使用 **64位整数**（`Int64` / `cInt`）作为所有多边形顶点的坐标类型。这个设计决策赋予了库极高的精度，但同时也引入了一个严峻的数学问题：

> **当两个 64 位整数相乘时，结果可能需要 128 位才能精确表示。**

在几何裁剪算法中，**斜率比较**（slope comparison）和**叉积计算**（cross product）是最核心的基础运算。这些运算本质上涉及两个 64 位整数的乘积，而 C# 的原生类型最大只支持 64 位整数运算。如果简单地使用浮点数（`double`）来完成这些运算，将不可避免地引入浮点误差，从而导致拓扑错误——多边形的交点可能算错、边的交叉判断可能出错，最终产出错误的裁剪结果。

为了彻底解决这个问题，Angus Johnson 在 Clipper1 中手工实现了一个 **128 位有符号整数**结构体 `Int128`，通过纯整数运算来确保几何计算的精确性。

本章将 **逐行、逐方法** 地深入解析 `Int128` 的完整源代码。

---

## 3.2 为什么需要 128 位整数运算

### 3.2.1 问题的根源：64 位乘法溢出

C# 中 `Int64`（即 `long`）的取值范围是：

$$-2^{63} \leq x \leq 2^{63} - 1$$

即大约 $-9.2 \times 10^{18}$ 到 $+9.2 \times 10^{18}$。

当我们计算两个 `Int64` 值的乘积时，理论上结果的范围是：

$$(-2^{63}) \times (-2^{63}) = 2^{126}$$

这远远超出了 `Int64` 所能表示的最大值 $2^{63} - 1$。事实上，两个 64 位整数的乘积最多需要 **127 位**（无符号）或 **128 位**（有符号，含符号位）才能精确表示。

| 运算 | 操作数位宽 | 结果所需位宽 | 结果最大值 |
|------|-----------|-------------|-----------|
| `Int32 × Int32` | 32 位 | 64 位 | 约 $4.6 \times 10^{18}$ |
| `Int64 × Int64` | 64 位 | 128 位 | 约 $8.5 \times 10^{37}$ |

### 3.2.2 数学证明：叉积需要 128 位

在 Clipper1 中，判断三个点是否共线（或两条边的斜率是否相等）使用的是**叉积**（cross product）比较。对于两条线段 $(x_1, y_1) \to (x_2, y_2)$ 和 $(x_3, y_3) \to (x_4, y_4)$，斜率相等的条件是：

$$\frac{y_2 - y_1}{x_2 - x_1} = \frac{y_4 - y_3}{x_4 - x_3}$$

为了避免除法（除法会引入浮点误差，且需要处理除以零的情况），将其转化为等价的叉积形式：

$$(y_2 - y_1) \times (x_4 - x_3) = (y_4 - y_3) \times (x_2 - x_1)$$

这里每个差值本身就可能是一个完整的 `Int64` 值（接近 $2^{63}$），而两个这样的差值相乘就需要 128 位。

### 3.2.3 在 Clipper1 中的使用场景：SlopesEqual

`Int128` 在 Clipper1 中主要被 `SlopesEqual` 方法的多个重载使用。以下是这些方法的签名：

```csharp
// 三点共线判断（两条共享端点的线段斜率是否相等）
internal static bool SlopesEqual(IntPoint pt1, IntPoint pt2, IntPoint pt3, 
    bool UseFullRange)
{
    if (UseFullRange)
        return Int128.Int128Mul(pt1.Y - pt2.Y, pt2.X - pt3.X) ==
            Int128.Int128Mul(pt1.X - pt2.X, pt2.Y - pt3.Y);
    else
        return (pt1.Y - pt2.Y) * (pt2.X - pt3.X) -
            (pt1.X - pt2.X) * (pt2.Y - pt3.Y) == 0;
}

// 四点斜率比较（两条独立线段斜率是否相等）
internal static bool SlopesEqual(IntPoint pt1, IntPoint pt2,
    IntPoint pt3, IntPoint pt4, bool UseFullRange)
{
    if (UseFullRange)
        return Int128.Int128Mul(pt1.Y - pt2.Y, pt3.X - pt4.X) ==
            Int128.Int128Mul(pt1.X - pt2.X, pt3.Y - pt4.Y);
    else
        return (pt1.Y - pt2.Y) * (pt3.X - pt4.X) -
            (pt1.X - pt2.X) * (pt3.Y - pt4.Y) == 0;
}
```

可以看到：

- 当 `UseFullRange` 为 `false` 时，直接使用 64 位整数运算（适用于坐标值较小的情况）
- 当 `UseFullRange` 为 `true` 时，使用 `Int128.Int128Mul` 进行 128 位精确乘法

`UseFullRange` 标志在初始化阶段根据多边形顶点的实际坐标范围来决定：如果所有坐标的绝对值都在一定阈值以内（确保乘积不会溢出 64 位），就使用快速的原生运算；否则就切换到 128 位运算。

### 3.2.4 为什么不用 `decimal` 或 `BigInteger`

读者可能会问：C# 有 `decimal`（128 位十进制浮点）和 `BigInteger`（任意精度整数），为什么不直接使用它们？

| 方案 | 精度 | 性能 | 适用性 |
|------|------|------|--------|
| `double` | 53 位有效位，不够 | 最快 | ❌ 精度不足 |
| `decimal` | 96 位有效位 | 慢约 10-30 倍 | ❌ 精度仍可能不足，且为十进制 |
| `BigInteger` | 任意精度 | 慢约 50-100 倍，有堆分配 | ❌ 性能不可接受 |
| 手写 `Int128` | 精确 128 位 | 接近原生 | ✅ 完美匹配需求 |

`Int128` 是一个 **值类型（struct）**，在栈上分配，没有 GC 压力；它的每个操作都是几条机器指令级别的操作，非常高效。这正是在性能关键路径上所需要的。

## 3.3 Int128 完整源代码

以下是 `Int128` 结构体的完整源代码（来自 Clipper1 / ClipperLib 6.4.2）：

```csharp
  internal struct Int128
  {
    private Int64 hi;
    private UInt64 lo;

    public Int128(Int64 _hi, UInt64 _lo)
    {
      lo = _lo;
      hi = _hi;
    }

    public Int128(Int64 val)
    {
      lo = (UInt64)val;
      if (val < 0) hi = -1;
      else hi = 0;
    }

    public bool IsNegative()
    {
      return hi < 0;
    }

    public static bool operator ==(Int128 val1, Int128 val2)
    {
      if ((object)val1 == (object)val2) return true;
      else if ((object)val1 == null || (object)val2 == null) return false;
      return (val1.hi == val2.hi && val1.lo == val2.lo);
    }

    public static bool operator !=(Int128 val1, Int128 val2)
    {
      return !(val1 == val2);
    }

    public override bool Equals(object obj)
    {
      if (obj == null || !(obj is Int128))
        return false;
      Int128 i128 = (Int128)obj;
      return (i128.hi == hi && i128.lo == lo);
    }

    public override int GetHashCode()
    {
      return hi.GetHashCode() ^ lo.GetHashCode();
    }

    public static bool operator >(Int128 val1, Int128 val2)
    {
      if (val1.hi != val2.hi)
        return val1.hi > val2.hi;
      else
        return val1.lo > val2.lo;
    }

    public static bool operator <(Int128 val1, Int128 val2)
    {
      if (val1.hi != val2.hi)
        return val1.hi < val2.hi;
      else
        return val1.lo < val2.lo;
    }

    public static Int128 operator +(Int128 lhs, Int128 rhs)
    {
      lhs.hi += rhs.hi;
      lhs.lo += rhs.lo;
      if (lhs.lo < rhs.lo) lhs.hi++;
      return lhs;
    }

    public static Int128 operator -(Int128 lhs, Int128 rhs)
    {
      return lhs + (-rhs);
    }

    public static Int128 operator -(Int128 val)
    {
      if (val.lo == 0)
        return new Int128(-val.hi, 0);
      else
        return new Int128(~val.hi, ~val.lo + 1);
    }

    public static explicit operator double(Int128 val)
    {
      const double shift64 = 18446744073709551616.0; //2^64
      if (val.hi < 0)
      {
        if (val.lo == 0)
          return (double)val.hi * shift64;
        else
          return -(double)(~val.lo + ~(UInt64)val.hi * shift64);
      }
      else
        return (double)(val.lo + (UInt64)val.hi * shift64);
    }

    public static Int128 Int128Mul(Int64 lhs, Int64 rhs)
    {
      bool negate = (lhs < 0) != (rhs < 0);
      if (lhs < 0) lhs = -lhs;
      if (rhs < 0) rhs = -rhs;
      UInt64 int1Hi = (UInt64)lhs >> 32;
      UInt64 int1Lo = (UInt64)lhs & 0xFFFFFFFF;
      UInt64 int2Hi = (UInt64)rhs >> 32;
      UInt64 int2Lo = (UInt64)rhs & 0xFFFFFFFF;

      UInt64 a = int1Hi * int2Hi;
      UInt64 b = int1Lo * int2Lo;
      UInt64 c = int1Hi * int2Lo + int1Lo * int2Hi;

      UInt64 lo;
      Int64 hi;
      hi = (Int64)(a + (c >> 32));

      unchecked { lo = (c << 32) + b; }
      if (lo < b) hi++;
      Int128 result = new Int128(hi, lo);
      return negate ? -result : result;
    }

  };
```

## 3.4 字段定义与数据表示

```csharp
private Int64 hi;
private UInt64 lo;
```

### 3.4.1 高位与低位的类型选择

`Int128` 由两个 64 位字段组成：

| 字段 | 类型 | 位宽 | 含义 |
|------|------|------|------|
| `hi` | `Int64`（有符号） | 64 位 | 128 位数的高 64 位 |
| `lo` | `UInt64`（无符号） | 64 位 | 128 位数的低 64 位 |

这两个字段共同表示一个 128 位有符号整数。其数值等于：

$$\text{value} = \text{hi} \times 2^{64} + \text{lo}$$

### 3.4.2 为什么 hi 是有符号而 lo 是无符号

这是 128 位整数表示的标准做法：

- **`hi` 是有符号的**：因为它负责承载整个 128 位数的**符号信息**。如果 `hi < 0`，则整个 128 位数为负。
- **`lo` 是无符号的**：因为低 64 位永远是一个正的"偏移量"。在二进制补码表示中，低位部分始终被解释为无符号值。

### 3.4.3 二进制位布局图示

```
128 位有符号整数 (Int128) 的二进制布局：

         hi (Int64, 有符号)                    lo (UInt64, 无符号)
┌──────────────────────────────────┬──────────────────────────────────┐
│ S │         高 63 位             │            低 64 位              │
│   │                              │                                  │
│bit│ bit126 ... bit64             │ bit63 ... bit1  bit0             │
│127│                              │                                  │
└──────────────────────────────────┴──────────────────────────────────┘
 ↑
 符号位 (S)：0 = 正数或零，1 = 负数
```

### 3.4.4 表示范围

| 属性 | 值 |
|------|-----|
| 最大正值 | $2^{127} - 1 \approx 1.70 \times 10^{38}$ |
| 最小负值 | $-2^{127} \approx -1.70 \times 10^{38}$ |
| 零 | `hi = 0, lo = 0` |
| +1 | `hi = 0, lo = 1` |
| -1 | `hi = -1, lo = 0xFFFFFFFFFFFFFFFF` |

### 3.4.5 一些示例值

| 十进制值 | hi | lo | 说明 |
|---------|----|----|------|
| 0 | `0` | `0` | 零 |
| 1 | `0` | `1` | 最简单的正数 |
| -1 | `-1` (`0xFFFFFFFFFFFFFFFF`) | `0xFFFFFFFFFFFFFFFF` | 全 1 的补码表示 |
| $2^{64}$ | `1` | `0` | 刚好超过 lo 能表示的最大值 |
| $-2^{64}$ | `-1` | `0` | 负的 $2^{64}$ |
| `Int64.MaxValue` ($2^{63}-1$) | `0` | `0x7FFFFFFFFFFFFFFF` | 64 位正数最大值 |
| `Int64.MinValue` ($-2^{63}$) | `-1` | `0x8000000000000000` | 64 位负数最小值 |

## 3.5 构造函数解析

### 3.5.1 双参数构造函数

```csharp
public Int128(Int64 _hi, UInt64 _lo)
{
    lo = _lo;
    hi = _hi;
}
```

这是最基础的构造函数，直接将 `hi` 和 `lo` 赋值。调用者必须自己确保传入的值组合是有意义的。

**典型调用场景**：在 `Int128Mul` 方法中构造计算结果时使用。

### 3.5.2 从 Int64 构造（符号扩展）

```csharp
public Int128(Int64 val)
{
    lo = (UInt64)val;
    if (val < 0) hi = -1;
    else hi = 0;
}
```

这个构造函数将一个普通的 `Int64` 值"提升"为 `Int128`。关键在于**符号扩展**（sign extension）。

#### 什么是符号扩展

在二进制补码中，要将一个较窄的有符号数扩展为更宽的位数，需要用原来的符号位来填充新增的高位：

- **正数或零**：高位全部填 `0`，即 `hi = 0`
- **负数**：高位全部填 `1`，即 `hi = -1`（在二进制中 `-1` 就是 `0xFFFFFFFFFFFFFFFF`，即全 1）

#### 为什么 hi = -1 就是正确的符号扩展

在二进制补码中，`-1` 的 64 位表示是全 1（`0xFFFF_FFFF_FFFF_FFFF`）。这正是我们需要填充到高 64 位的值。

#### 详细示例

**示例 1**：`val = 42`

```
val (Int64)  = 0x000000000000002A
              = 0000...0000 0010 1010 （64位）

符号扩展到 128 位：
hi = 0x0000000000000000  （正数，高位填 0）
lo = 0x000000000000002A  （直接复制）

Int128 = 0x0000000000000000_000000000000002A
       = 42 ✓
```

**示例 2**：`val = -1`

```
val (Int64)  = 0xFFFFFFFFFFFFFFFF  （-1 的二进制补码）

符号扩展到 128 位：
hi = 0xFFFFFFFFFFFFFFFF  （即 -1，负数高位填 1）
lo = 0xFFFFFFFFFFFFFFFF  （直接复制 val 的位模式）

Int128 = 0xFFFFFFFFFFFFFFFF_FFFFFFFFFFFFFFFF
       = -1 ✓ （128位全1就是 -1 的补码表示）
```

**示例 3**：`val = -100`

```
val (Int64)  = 0xFFFFFFFFFFFFFF9C  （-100 的二进制补码）

符号扩展到 128 位：
hi = 0xFFFFFFFFFFFFFFFF  （即 -1，负数高位填 1）
lo = 0xFFFFFFFFFFFFFF9C  （直接复制）

Int128 = 0xFFFFFFFFFFFFFFFF_FFFFFFFFFFFFFF9C
       = -100 ✓
```

**关键点**：`(UInt64)val` 这个强制转换不会改变 `val` 的**位模式**，只是改变了**类型解释**。例如，`(UInt64)(-1)` 在二进制中仍然是全 1，但被解释为 `18446744073709551615`（`UInt64.MaxValue`）而非 `-1`。

## 3.6 IsNegative 方法

```csharp
public bool IsNegative()
{
    return hi < 0;
}
```

### 3.6.1 解析

这个方法非常简洁：只需检查 `hi` 是否为负。

在二进制补码表示中，一个 128 位有符号整数的**符号位**是最高位（第 127 位），而这一位恰好在 `hi` 的最高位（`hi` 的第 63 位）。因此：

- 如果 `hi < 0`，说明 `hi` 的最高位为 1，即整个 128 位数的符号位为 1，数值为负。
- 如果 `hi >= 0`，说明数值为正或零。

### 3.6.2 为什么不用字段直接访问

虽然可以直接检查 `val.hi < 0`，但封装为方法有更好的可读性，且 `internal` 访问级别限制了外部访问字段的能力。

## 3.7 相等性运算符与方法

### 3.7.1 operator ==

```csharp
public static bool operator ==(Int128 val1, Int128 val2)
{
    if ((object)val1 == (object)val2) return true;
    else if ((object)val1 == null || (object)val2 == null) return false;
    return (val1.hi == val2.hi && val1.lo == val2.lo);
}
```

#### 逐行分析

**第 1 行：引用相等检查**

```csharp
if ((object)val1 == (object)val2) return true;
```

将两个 `Int128` 强制转换为 `object` 后进行引用比较。对于**值类型**来说，这会触发**装箱**（boxing），即在堆上分配一个对象来包装这个结构体。

> **注意**：这段代码对于结构体来说是**不太常规**的写法。对于值类型，`(object)val1 == (object)val2` 几乎永远返回 `false`，因为每次装箱都会创建一个新的堆对象，两个不同的堆对象的引用不可能相等。这段代码可能是从一个引用类型（class）版本迁移过来时遗留的。

**第 2 行：空值检查**

```csharp
else if ((object)val1 == null || (object)val2 == null) return false;
```

同样，对于值类型来说，装箱后的结果**永远不为 null**。这行代码在结构体上下文中实际上永远不会返回 `true`，但它不会造成错误——只是冗余代码。

**第 3 行：实际的值比较**

```csharp
return (val1.hi == val2.hi && val1.lo == val2.lo);
```

这才是真正有意义的比较逻辑：高 64 位和低 64 位都必须相等，两个 128 位数才相等。

#### 设计讨论

这个 `==` 运算符的实现展示了一个常见的"防御性编程"（defensive programming）模式，尽管对于结构体来说前两个检查是多余的。在实际运行中，真正起作用的只有最后一行。这不影响正确性，只是稍微影响性能（装箱操作）。

### 3.7.2 operator !=

```csharp
public static bool operator !=(Int128 val1, Int128 val2)
{
    return !(val1 == val2);
}
```

这是标准写法：`!=` 直接委托给 `==` 再取反。这样可以保证 `==` 和 `!=` 的一致性——修改相等逻辑时只需修改一处。

### 3.7.3 Equals 方法

```csharp
public override bool Equals(object obj)
{
    if (obj == null || !(obj is Int128))
        return false;
    Int128 i128 = (Int128)obj;
    return (i128.hi == hi && i128.lo == lo);
}
```

#### 逐行分析

```csharp
if (obj == null || !(obj is Int128))
    return false;
```

首先检查参数是否为 `null` 或者不是 `Int128` 类型。对于值类型，传入的 `obj` 实际上是一个装箱的 `Int128`，所以 `obj is Int128` 会正确返回 `true`。

```csharp
Int128 i128 = (Int128)obj;
return (i128.hi == hi && i128.lo == lo);
```

拆箱（unboxing）后比较两个字段。逻辑与 `==` 运算符一致。

**为什么需要同时实现 `==` 和 `Equals`**：

- `==` 是编译时静态分发的运算符，用于已知类型的比较
- `Equals` 是运行时虚方法调用，用于泛型集合（如 `Dictionary`）和反射场景
- C# 编译器会在重载 `==` 时要求同时重写 `Equals` 和 `GetHashCode`

### 3.7.4 GetHashCode 方法

```csharp
public override int GetHashCode()
{
    return hi.GetHashCode() ^ lo.GetHashCode();
}
```

使用**异或（XOR）**将 `hi` 和 `lo` 的哈希码组合起来。

- `Int64.GetHashCode()` 返回该 `Int64` 值的哈希码
- `UInt64.GetHashCode()` 返回该 `UInt64` 值的哈希码
- XOR 是组合哈希码的经典方式——简单且分布均匀

> **注意**：在实际使用中，`Int128` 并不会被用作字典的键，所以这个哈希函数主要是为了满足 C# 编译器的要求（重写 `Equals` 时必须重写 `GetHashCode`）。

## 3.8 比较运算符

### 3.8.1 operator > （大于）

```csharp
public static bool operator >(Int128 val1, Int128 val2)
{
    if (val1.hi != val2.hi)
        return val1.hi > val2.hi;
    else
        return val1.lo > val2.lo;
}
```

#### 算法解析

128 位有符号数的比较分为两步：

1. **首先比较高 64 位（`hi`）**：如果 `hi` 不同，那么 `hi` 更大的数就更大。注意 `hi` 是**有符号**的 `Int64`，所以这里的 `>` 是有符号比较，能正确处理正负数。

2. **如果 `hi` 相同，则比较低 64 位（`lo`）**：`lo` 是**无符号**的 `UInt64`，所以这里的 `>` 是无符号比较。

#### 为什么这样做是正确的

考虑 `Int128` 的值公式：$\text{value} = \text{hi} \times 2^{64} + \text{lo}$

- 由于 $2^{64}$ 是一个极大的数，`hi` 的权重远大于 `lo`。
- 如果 $\text{hi}_1 > \text{hi}_2$，那么无论 `lo` 值如何，$\text{val}_1 > \text{val}_2$。
- 只有当 `hi` 相同时，比较才取决于 `lo`。

#### 示例

| val1 (hi, lo) | val2 (hi, lo) | 结果 | 原因 |
|---------------|---------------|------|------|
| (5, 100) | (3, 999) | `true` | hi: 5 > 3 |
| (-1, 100) | (0, 1) | `false` | hi: -1 < 0，负数小于正数 |
| (2, 500) | (2, 300) | `true` | hi 相等，lo: 500 > 300 |
| (2, 300) | (2, 500) | `false` | hi 相等，lo: 300 < 500 |

### 3.8.2 operator < （小于）

```csharp
public static bool operator <(Int128 val1, Int128 val2)
{
    if (val1.hi != val2.hi)
        return val1.hi < val2.hi;
    else
        return val1.lo < val2.lo;
}
```

这与 `>` 运算符完全对称，逻辑一致，只是方向相反。

## 3.9 加法运算符

```csharp
public static Int128 operator +(Int128 lhs, Int128 rhs)
{
    lhs.hi += rhs.hi;
    lhs.lo += rhs.lo;
    if (lhs.lo < rhs.lo) lhs.hi++;
    return lhs;
}
```

### 3.9.1 算法：带进位的 128 位加法

128 位加法的核心思想与小学学的竖式加法完全相同，只不过"每一位"变成了 64 位：

```
        hi₁         lo₁
  +     hi₂         lo₂
  ──────────────────────────
    hi₁+hi₂+C    lo₁+lo₂
```

其中 `C` 是从低 64 位向高 64 位的**进位**（carry），取值为 0 或 1。

### 3.9.2 逐行分析

**第 1 行**：先把高位相加

```csharp
lhs.hi += rhs.hi;
```

**第 2 行**：再把低位相加

```csharp
lhs.lo += rhs.lo;
```

**第 3 行**：检测进位

```csharp
if (lhs.lo < rhs.lo) lhs.hi++;
```

这一行是整个加法运算的精髓。它利用了一个巧妙的数学性质：

> **对于无符号加法 `a + b`，当且仅当 `(a + b) < b` 时（其中比较也是无符号的），发生了溢出（进位）。**

为什么？因为无符号加法溢出时，结果会"回绕"（wrap around），变成一个比两个操作数都小的值。具体来说：

- 如果 `lo₁ + lo₂` 没有溢出：结果 ≥ `lo₂`（因为 `lo₁ ≥ 0`）
- 如果 `lo₁ + lo₂` 溢出：结果 = `lo₁ + lo₂ - 2^64`，由于 `lo₁ < 2^64`，所以结果 < `lo₂`

检测到溢出后，`lhs.hi++` 将进位加到高位。

### 3.9.3 数值示例

**示例 1**：`100 + 200 = 300`（无进位）

```
  lhs = (hi=0, lo=100)
  rhs = (hi=0, lo=200)

  步骤 1: lhs.hi = 0 + 0 = 0
  步骤 2: lhs.lo = 100 + 200 = 300
  步骤 3: 300 < 200？ 否 → 无进位

  结果: (hi=0, lo=300) = 300 ✓
```

**示例 2**：`(2^64 - 1) + 1 = 2^64`（有进位）

```
  lhs = (hi=0, lo=0xFFFFFFFFFFFFFFFF)   // 即 2^64 - 1
  rhs = (hi=0, lo=1)

  步骤 1: lhs.hi = 0 + 0 = 0
  步骤 2: lhs.lo = 0xFFFFFFFFFFFFFFFF + 1 = 0（溢出回绕！）
  步骤 3: 0 < 1？ 是 → lhs.hi = 0 + 1 = 1

  结果: (hi=1, lo=0) = 1 × 2^64 + 0 = 2^64 ✓
```

**示例 3**：`(3 × 2^64 + 5) + (2 × 2^64 + 10) = 5 × 2^64 + 15`

```
  lhs = (hi=3, lo=5)
  rhs = (hi=2, lo=10)

  步骤 1: lhs.hi = 3 + 2 = 5
  步骤 2: lhs.lo = 5 + 10 = 15
  步骤 3: 15 < 10？ 否 → 无进位

  结果: (hi=5, lo=15) ✓
```

### 3.9.4 关于值类型参数的修改

注意这段代码直接修改了 `lhs` 参数。这是可行的，因为 `Int128` 是**值类型**——方法接收到的是调用者值的**副本**。修改副本不会影响调用者的原始值。这种写法避免了创建新的临时变量，虽然对于结构体来说差别微小。

## 3.10 取反运算符（一元负号）

```csharp
public static Int128 operator -(Int128 val)
{
    if (val.lo == 0)
        return new Int128(-val.hi, 0);
    else
        return new Int128(~val.hi, ~val.lo + 1);
}
```

### 3.10.1 二进制补码取反原理

在二进制补码中，对一个数取反（求相反数）的公式是：

$$-x = \sim x + 1$$

即**按位取反**（bitwise NOT）**再加 1**。

对于 128 位数 `(hi, lo)`，按位取反得到 `(~hi, ~lo)`，然后加 1。但"加 1"需要考虑进位！

### 3.10.2 为什么需要 lo == 0 的特殊处理

当 `lo == 0` 时，`~lo + 1` 的计算过程如下：

```
~lo = ~0 = 0xFFFFFFFFFFFFFFFF
~lo + 1 = 0xFFFFFFFFFFFFFFFF + 1 = 0x0000000000000000 （溢出回绕！）
```

也就是说 `~lo + 1 = 0`。这意味着加 1 产生了进位，需要传播到 `hi` 部分。

完整的取反应该是：
- `~lo + 1 = 0`（低位回绕为 0，产生进位 1）
- `~hi + 1`（高位取反再加上进位 1）
- 但 `~hi + 1 = -hi`（这正是 `Int64` 取反的结果）

所以当 `lo == 0` 时，结果就是 `(-hi, 0)`。

### 3.10.3 当 lo != 0 时

当 `lo != 0` 时，`~lo + 1` 不会溢出（因为 `~lo < 0xFFFFFFFFFFFFFFFF`，加 1 不会回绕），所以没有进位需要传播到 `hi`。

此时取反结果就是 `(~hi, ~lo + 1)`。

### 3.10.4 逐步示例

**示例 1**：取反 `+1` → 得到 `-1`

```
输入: val = (hi=0, lo=1)

lo != 0，走 else 分支：
  ~hi = ~0 = 0xFFFFFFFFFFFFFFFF = -1（作为 Int64）
  ~lo + 1 = ~1 + 1 = 0xFFFFFFFFFFFFFFFE + 1 = 0xFFFFFFFFFFFFFFFF

结果: (hi=-1, lo=0xFFFFFFFFFFFFFFFF) = -1 ✓
```

**示例 2**：取反 `2^64`（即 `(hi=1, lo=0)`）→ 得到 `-2^64`

```
输入: val = (hi=1, lo=0)

lo == 0，走 if 分支：
  -hi = -1

结果: (hi=-1, lo=0)

验证: -1 × 2^64 + 0 = -2^64 ✓
```

**示例 3**：取反 `(hi=0, lo=0x8000000000000000)` → 得到 `-2^63`

```
输入: val = (hi=0, lo=0x8000000000000000)    // 即 2^63

lo != 0，走 else 分支：
  ~hi = ~0 = -1
  ~lo + 1 = ~0x8000000000000000 + 1
           = 0x7FFFFFFFFFFFFFFF + 1
           = 0x8000000000000000

结果: (hi=-1, lo=0x8000000000000000)

验证: -1 × 2^64 + 0x8000000000000000
     = -2^64 + 2^63
     = -2^63 ✓
```

## 3.11 减法运算符

```csharp
public static Int128 operator -(Int128 lhs, Int128 rhs)
{
    return lhs + (-rhs);
}
```

### 3.11.1 解析

减法直接实现为"加上对方的相反数"：

$$a - b = a + (-b)$$

这种实现方式非常简洁优雅，复用了已有的加法运算符和取反运算符，避免了重复实现带借位的减法逻辑。

### 3.11.2 性能考量

这种实现会创建一个临时的 `Int128`（`-rhs` 的结果），然后再进行一次加法。但由于 `Int128` 是值类型（仅 16 字节），临时值在栈上分配，代价极低。在 JIT 编译器优化后，这些操作很可能被内联为寄存器运算。

## 3.12 显式转换为 double

```csharp
public static explicit operator double(Int128 val)
{
    const double shift64 = 18446744073709551616.0; //2^64
    if (val.hi < 0)
    {
        if (val.lo == 0)
            return (double)val.hi * shift64;
        else
            return -(double)(~val.lo + ~(UInt64)val.hi * shift64);
    }
    else
        return (double)(val.lo + (UInt64)val.hi * shift64);
}
```

### 3.12.1 shift64 常量

```csharp
const double shift64 = 18446744073709551616.0; //2^64
```

这个常量等于 $2^{64} = 18{,}446{,}744{,}073{,}709{,}551{,}616$。它用于将 `hi` 的值"左移"64 位（乘以 $2^{64}$）后与 `lo` 相加。

> 注意：虽然 `double` 只有 53 位有效位，不能精确表示所有的 128 位整数，但在 Clipper1 中这个转换主要用于近似计算，精确的比较始终使用整数运算。

### 3.12.2 正数的处理（hi >= 0）

```csharp
return (double)(val.lo + (UInt64)val.hi * shift64);
```

当 128 位数为正或零时，直接计算：

$$\text{result} = \text{lo} + \text{hi} \times 2^{64}$$

这里 `(UInt64)val.hi` 的强制转换是安全的，因为我们已知 `hi >= 0`。

### 3.12.3 负数的处理（hi < 0）

负数的处理更复杂，分两种情况：

**情况 1：lo == 0**

```csharp
return (double)val.hi * shift64;
```

当 `lo == 0` 时，值就等于 `hi × 2^64`。由于 `hi` 是负的，结果也是负的。

**情况 2：lo != 0**

```csharp
return -(double)(~val.lo + ~(UInt64)val.hi * shift64);
```

这里的思路是先计算绝对值，再取负：

1. 对整个 128 位数取反得到绝对值（近似）
2. `~val.lo` 是低位取反
3. `~(UInt64)val.hi` 是高位取反
4. 组合得到绝对值后加负号

> **注意**：这个公式实际上是 $-(\sim\text{lo} + \sim\text{hi} \times 2^{64})$，它等价于 $-(|val| - 1)$，因为取反但没有 +1。在浮点精度范围内，这个误差（最多差 1）是可以忽略的。

### 3.12.4 使用 explicit 而非 implicit 的原因

这个转换被声明为 `explicit`（显式），意味着必须写明强制转换 `(double)myInt128`。这是正确的设计，因为：

1. **精度损失**：128 位整数最多有 128 位有效位，而 `double` 只有 53 位有效位，转换必然导致精度损失
2. **程序员意图**：强制显式转换确保程序员意识到这种精度损失

## 3.13 核心方法：Int128Mul（128 位乘法）

这是 `Int128` 中最重要也是最复杂的方法。它将两个 `Int64` 相乘，返回精确的 `Int128` 结果。

```csharp
public static Int128 Int128Mul(Int64 lhs, Int64 rhs)
{
    bool negate = (lhs < 0) != (rhs < 0);
    if (lhs < 0) lhs = -lhs;
    if (rhs < 0) rhs = -rhs;
    UInt64 int1Hi = (UInt64)lhs >> 32;
    UInt64 int1Lo = (UInt64)lhs & 0xFFFFFFFF;
    UInt64 int2Hi = (UInt64)rhs >> 32;
    UInt64 int2Lo = (UInt64)rhs & 0xFFFFFFFF;

    UInt64 a = int1Hi * int2Hi;
    UInt64 b = int1Lo * int2Lo;
    UInt64 c = int1Hi * int2Lo + int1Lo * int2Hi;

    UInt64 lo;
    Int64 hi;
    hi = (Int64)(a + (c >> 32));

    unchecked { lo = (c << 32) + b; }
    if (lo < b) hi++;
    Int128 result = new Int128(hi, lo);
    return negate ? -result : result;
}
```

### 3.13.1 为什么是静态方法而非 operator*

`Int128Mul` 被实现为静态方法而非 `operator*`，这是一个刻意的设计选择：

1. **输入类型不同**：它接受两个 `Int64`，而非两个 `Int128`。C# 的 `operator*` 重载通常要求至少一个操作数是所在类型。
2. **语义清晰**：方法名 `Int128Mul` 清楚地表达了"执行一次产生 128 位结果的乘法"这一意图。
3. **性能**：调用者可以直接传入 `Int64` 值，无需先转换为 `Int128`。

### 3.13.2 第一步：确定结果的符号

```csharp
bool negate = (lhs < 0) != (rhs < 0);
if (lhs < 0) lhs = -lhs;
if (rhs < 0) rhs = -rhs;
```

乘法的符号规则：

| lhs | rhs | 结果 | `negate` |
|-----|-----|------|----------|
| + | + | + | `false` |
| + | - | - | `true` |
| - | + | - | `true` |
| - | - | + | `false` |

`(lhs < 0) != (rhs < 0)` 优雅地实现了"异或"逻辑：两个操作数符号不同时，结果为负。

然后取绝对值，将问题简化为**无符号乘法**，最后再根据 `negate` 决定是否取反。

### 3.13.3 第二步：将每个 64 位数拆分为两个 32 位半部分

```csharp
UInt64 int1Hi = (UInt64)lhs >> 32;
UInt64 int1Lo = (UInt64)lhs & 0xFFFFFFFF;
UInt64 int2Hi = (UInt64)rhs >> 32;
UInt64 int2Lo = (UInt64)rhs & 0xFFFFFFFF;
```

将每个 64 位操作数拆为高 32 位和低 32 位：

```
lhs（64位，已取绝对值）:
┌──────────────────┬──────────────────┐
│    int1Hi (32位)  │    int1Lo (32位)  │
│   高32位          │    低32位         │
└──────────────────┴──────────────────┘

rhs（64位，已取绝对值）:
┌──────────────────┬──────────────────┐
│    int2Hi (32位)  │    int2Lo (32位)  │
│   高32位          │    低32位         │
└──────────────────┴──────────────────┘
```

- `>> 32`：右移 32 位，提取高 32 位
- `& 0xFFFFFFFF`：与掩码进行按位与，提取低 32 位

> 为什么这些变量类型是 `UInt64` 而非 `UInt32`？因为后续的乘法 `int1Hi * int2Hi` 等运算的结果可能需要 64 位来存储（两个 32 位数的乘积最大为 $2^{64} - 2^{33} + 1$）。使用 `UInt64` 可以避免在乘法前进行类型提升。

### 3.13.4 第三步：计算部分积（schoolbook multiplication）

```csharp
UInt64 a = int1Hi * int2Hi;
UInt64 b = int1Lo * int2Lo;
UInt64 c = int1Hi * int2Lo + int1Lo * int2Hi;
```

这是经典的**竖式乘法**（schoolbook multiplication）算法，类似于我们在小学学的多位数乘法。

让我们将 `lhs` 写为 $H_1 \times 2^{32} + L_1$，`rhs` 写为 $H_2 \times 2^{32} + L_2$。那么：

$$\text{lhs} \times \text{rhs} = (H_1 \times 2^{32} + L_1)(H_2 \times 2^{32} + L_2)$$

展开得到四个部分积：

$$= H_1 H_2 \times 2^{64} + H_1 L_2 \times 2^{32} + L_1 H_2 \times 2^{32} + L_1 L_2$$

$$= H_1 H_2 \times 2^{64} + (H_1 L_2 + L_1 H_2) \times 2^{32} + L_1 L_2$$

$$= a \times 2^{64} + c \times 2^{32} + b$$

其中：
- **a** = $H_1 \times H_2$：贡献到 bit 64 ~ bit 127 的区域
- **b** = $L_1 \times L_2$：贡献到 bit 0 ~ bit 63 的区域
- **c** = $H_1 \times L_2 + L_1 \times H_2$：贡献到 bit 32 ~ bit 95 的区域（**跨越 64 位边界**！）

### 3.13.5 部分积的位范围图示

下图展示了三个部分积在 128 位结果中的位置：

```
位位置:  127    96 95    64 63    32 31     0
         ├───────┼───────┼───────┼───────┤
    a:   │███████│███████│       │       │   a × 2^64 (bit 64~127)
    c:   │       │███████│███████│       │   c × 2^32 (bit 32~95)
    b:   │       │       │███████│███████│   b × 2^0  (bit 0~63)
         ├───────┼───────┼───────┼───────┤
  结果:  │  hi 高64位     │  lo 低64位     │
```

可以看到，`c` 部分积**跨越了高低 64 位的边界**，它的高 32 位会贡献到 `hi`，低 32 位会贡献到 `lo`。

### 3.13.6 第四步：组装 128 位结果

```csharp
hi = (Int64)(a + (c >> 32));
```

高 64 位 = `a`（整个 `a` 都在高位区域）+ `c` 的高 32 位（`c >> 32`）。

```csharp
unchecked { lo = (c << 32) + b; }
```

低 64 位 = `c` 的低 32 位左移 32 位（`c << 32`）+ `b`（整个 `b` 都在低位区域）。

**为什么需要 `unchecked`**？

C# 默认情况下，整数运算溢出不会抛出异常（`unchecked` 是默认行为）。但如果项目启用了全局 `checked` 编译选项，`(c << 32) + b` 可能会因为溢出而抛出 `OverflowException`。使用 `unchecked` 块确保溢出时会安静地回绕（wrap around），这正是我们需要的行为——溢出的部分会通过下一行的进位检测传播到 `hi`。

```csharp
if (lo < b) hi++;
```

与加法运算符中的进位检测完全相同：如果 `lo < b`，说明 `(c << 32) + b` 溢出了，需要向 `hi` 进位。

### 3.13.7 第五步：应用符号

```csharp
Int128 result = new Int128(hi, lo);
return negate ? -result : result;
```

如果原始操作数的符号不同，需要对结果取反。这里复用了之前定义的取反运算符 `-`。

### 3.13.8 完整数值示例

让我们用具体数字来走一遍完整的 `Int128Mul` 流程。

**示例**：计算 `1000000007 × 2000000011`

```
lhs = 1000000007  (约 10^9)
rhs = 2000000011  (约 2×10^9)

预期结果 = 1000000007 × 2000000011 = 2000000018000000077 (约 2×10^18)
```

**步骤 1：符号处理**

两个操作数都是正数，`negate = false`。

**步骤 2：拆分为 32 位半部分**

```
lhs = 1000000007 = 0x3B9ACA07
  int1Hi = 0x3B9ACA07 >> 32 = 0x00000000 = 0
  int1Lo = 0x3B9ACA07 & 0xFFFFFFFF = 0x3B9ACA07 = 1000000007

rhs = 2000000011 = 0x7735940B
  int2Hi = 0x7735940B >> 32 = 0x00000000 = 0
  int2Lo = 0x7735940B & 0xFFFFFFFF = 0x7735940B = 2000000011
```

（注意：这两个数都小于 $2^{32}$，所以高 32 位为 0）

**步骤 3：计算部分积**

```
a = 0 × 0 = 0
b = 1000000007 × 2000000011 = 2000000018000000077
c = 0 × 2000000011 + 1000000007 × 0 = 0
```

**步骤 4：组装结果**

```
hi = (Int64)(0 + (0 >> 32)) = 0
lo = (0 << 32) + 2000000018000000077
```

等等！这里 `b = 2000000018000000077`，这已经超出了 `UInt64.MaxValue` ($= 18446744073709551615$) 了吗？

```
2000000018000000077 < 18446744073709551615  ✓
```

实际上 $2 \times 10^{18} \ll 1.8 \times 10^{19}$，所以 `b` 可以用 `UInt64` 存储。

```
hi = 0
lo = 0 + 2000000018000000077 = 2000000018000000077
lo < b？ 2000000018000000077 < 2000000018000000077？ 否 → 无进位
```

**结果**：`(hi=0, lo=2000000018000000077)` = `2000000018000000077` ✓

**示例 2**：计算 `(-3) × 5 = -15`（涉及符号处理）

```
lhs = -3, rhs = 5

步骤 1：negate = (true) != (false) = true
        lhs = 3, rhs = 5

步骤 2：
  int1Hi = 0, int1Lo = 3
  int2Hi = 0, int2Lo = 5

步骤 3：
  a = 0, b = 15, c = 0

步骤 4：

步骤 5：result = (0, 15) = 15

取反过程（lo != 0）：
  ~hi = ~0 = -1 (0xFFFFFFFFFFFFFFFF)
  ~lo + 1 = ~15 + 1 = 0xFFFFFFFFFFFFFFF0 + 1 = 0xFFFFFFFFFFFFFFF1

最终结果：(hi=-1, lo=0xFFFFFFFFFFFFFFF1)

验证：-1 × 2^64 + 0xFFFFFFFFFFFFFFF1
     = -18446744073709551616 + 18446744073709551601
     = -15 ✓
```

**示例 3**：大数乘法（高位非零的情况）

计算 `(2^33) × (2^33) = 2^66`

```
lhs = 2^33 = 8589934592
rhs = 2^33 = 8589934592

步骤 1：两个正数，negate = false

步骤 2：
  lhs = 8589934592 = 0x0000000200000000
  int1Hi = 0x0000000200000000 >> 32 = 2
  int1Lo = 0x0000000200000000 & 0xFFFFFFFF = 0

  rhs = 8589934592 = 0x0000000200000000

步骤 4：
  hi = (Int64)(4 + (0 >> 32)) = 4
  lo = (0 << 32) + 0 = 0
  进位？ 0 < 0？ 否

结果：(hi=4, lo=0) = 4 × 2^64 = 2^66 ✓
```

### 3.13.9 关于 c 的溢出风险

细心的读者可能会注意到：

```csharp
UInt64 c = int1Hi * int2Lo + int1Lo * int2Hi;
```

`int1Hi * int2Lo` 和 `int1Lo * int2Hi` 各自最大为 $(2^{32}-1) \times (2^{32}-1) \approx 2^{64} - 2^{33}$，两者之和最大约为 $2^{65} - 2^{34}$，这超出了 `UInt64` 的范围（$2^{64} - 1$）！

这意味着 `c` 的计算本身可能会溢出。在原始 Clipper1 代码中，这确实是一个已知的边界情况。但在实际使用中，由于 Clipper1 限制了坐标的最大范围（通常远小于 `Int64.MaxValue`），这种极端溢出在实践中不会发生。

如果需要处理完全范围的 64 位乘法，`c` 需要被拆分为两个独立的加法来处理可能的进位。但 Clipper1 选择了在实用性和简洁性之间做出权衡——对于实际的几何计算场景，这已经足够了。

## 3.15 Int128 在 Clipper1 中的调用路径

为了更完整地理解 `Int128` 的角色，让我们梳理它在 Clipper1 整体架构中的调用路径：

```
用户输入多边形数据（IntPoint 顶点列表）
        │
        ▼
   AddPath / AddPaths
        │
        ▼
   检查坐标范围 → 设置 UseFullRange 标志
        │
        ▼
   Execute（裁剪执行）
        │
        ├──► ProcessIntersections
        │         │
        │         ▼
        │    SlopesEqual(pt1, pt2, pt3, UseFullRange)
        │         │
        │         ▼ (当 UseFullRange == true)
        │    Int128.Int128Mul(dy1, dx2) == Int128.Int128Mul(dx1, dy2)
        │
        ├──► ProcessEdgesAtTopOfScanbeam
        │         │
        │         ▼
        │    SlopesEqual(pt1, pt2, pt3, pt4, UseFullRange)
        │         │
        │         ▼ (当 UseFullRange == true)
        │    Int128.Int128Mul(dy1, dx2) == Int128.Int128Mul(dx1, dy2)
        │
        └──► ... 其他使用斜率比较的位置
```

### 3.15.1 数学等价关系

`SlopesEqual` 使用 `Int128Mul` 实现的数学原理：

要比较两条线段的斜率是否相等：

$$\frac{\Delta y_1}{\Delta x_1} \stackrel{?}{=} \frac{\Delta y_2}{\Delta x_2}$$

等价于（交叉相乘，避免除法）：

$$\Delta y_1 \times \Delta x_2 \stackrel{?}{=} \Delta y_2 \times \Delta x_1$$

在代码中：

```csharp
Int128.Int128Mul(pt1.Y - pt2.Y, pt2.X - pt3.X) ==
    Int128.Int128Mul(pt1.X - pt2.X, pt2.Y - pt3.Y)
```

这里：
- `pt1.Y - pt2.Y` 对应 $\Delta y_1$
- `pt2.X - pt3.X` 对应 $\Delta x_2$
- `pt1.X - pt2.X` 对应 $\Delta x_1$
- `pt2.Y - pt3.Y` 对应 $\Delta y_2$

两个 `Int128Mul` 的结果用 `==` 比较，这调用的是我们之前分析的 `Int128` 的相等运算符，比较两个 128 位整数是否**完全相等**。

### 3.15.2 为什么精确性如此重要

在多边形裁剪算法中，如果斜率比较出现一个比特的误差，可能导致：

1. **边交叉的漏检或误检**：算法认为两条边不相交但实际相交，或反过来
2. **拓扑结构错误**：导致生成自交多边形、缺失面、重复面
3. **无限循环**：在处理交点列表时进入死循环
4. **崩溃**：空指针或数组越界

使用 128 位精确整数运算完全消除了这类浮点误差，确保了算法的**鲁棒性**（robustness）。这是 Clipper1 以稳定可靠著称的重要原因之一。

## 3.17 深入理解：二进制补码与 128 位运算

### 3.17.1 二进制补码回顾

**二进制补码**（two's complement）是现代计算机表示有符号整数的标准方式。对于 $n$ 位的二进制补码表示：

- **正数和零**：最高位为 0，其余位表示数值
- **负数**：最高位为 1，数值等于 $-2^{n-1} + \text{剩余位的无符号值}$
- **取反公式**：$-x = \sim x + 1$

### 3.17.2 为什么二进制补码是最佳选择

二进制补码有一个极为优雅的特性：**加法和减法不需要关心操作数的符号**。无论两个操作数是正是负，使用同样的硬件加法器就能得到正确结果。

这就是为什么 `Int128` 的加法运算符不需要任何符号判断——它直接把两个 128 位补码数相加，进位处理就是唯一需要的额外操作。

### 3.17.3 128 位取反的完整推导

对于 128 位数 $(hi, lo)$，其按位取反为 $(\sim hi, \sim lo)$。取反后加 1：

$$-x = (\sim hi, \sim lo) + (0, 1)$$

如果 $\sim lo + 1$ 没有溢出（即 $lo \neq 0$），那么 $\sim lo + 1$ 就是新的低 64 位，$\sim hi$ 就是新的高 64 位。

如果 $\sim lo + 1$ 溢出了（即 $lo = 0$，此时 $\sim lo = \text{0xFFFF...FFFF}$，$\sim lo + 1 = 0$），那么需要向高位进位：$\sim hi + 1 = -hi$。

这正是代码中 `if (val.lo == 0)` 分支的由来。

## 3.18 潜在的改进与注意事项

### 3.18.1 == 运算符中的装箱问题

如前所述，`operator ==` 中的 `(object)val1 == (object)val2` 和 `(object)val1 == null` 检查对于值类型是冗余的，且会导致不必要的装箱操作。在性能关键路径上，这些额外的堆分配可能影响 GC 性能。

改进后的实现可以是：

```csharp
public static bool operator ==(Int128 val1, Int128 val2)
{
    return (val1.hi == val2.hi && val1.lo == val2.lo);
}
```

### 3.18.2 Int128Mul 中 c 的潜在溢出

如 3.13.9 节所述，当两个操作数都接近 `Int64.MaxValue` 时，中间变量 `c` 可能溢出。Clipper1 通过限制输入坐标的范围来规避此问题（`hiRange` 常量），但这意味着 `Int128Mul` 不是一个通用的 128 位乘法函数。

### 3.18.3 缺少 operator >=、<= 和其他运算

`Int128` 只实现了 `>` 和 `<`，没有 `>=` 和 `<=`。这是因为 Clipper1 中只需要这些比较操作。如果需要 `>=`，可以组合 `>` 和 `==`。

## 3.19 本章小结

本章深入解析了 Clipper1 中 `Int128` 结构体的完整源代码。关键要点如下：

1. **存在的意义**：两个 64 位整数的乘积可能超过 64 位，`Int128` 提供了精确的 128 位运算能力，确保斜率比较和叉积计算的正确性。

2. **数据表示**：使用有符号的 `hi`（Int64）和无符号的 `lo`（UInt64）两个字段，以二进制补码方式表示一个 128 位有符号整数。

3. **核心算法**：
   - **加法**：分别相加高位和低位，通过"结果 < 操作数"检测进位
   - **取反**：按位取反再加 1，需特殊处理 `lo == 0` 的进位情况
   - **乘法（Int128Mul）**：将 64 位操作数拆为两个 32 位半部分，通过竖式乘法计算四个部分积，再组装为 128 位结果

4. **设计哲学**：最小化实现，只提供算法实际需要的操作，不求通用，但求高效可靠。

5. **在 Clipper1 中的角色**：主要服务于 `SlopesEqual` 方法，实现无浮点误差的斜率比较，是整个裁剪算法鲁棒性的数学基础。

在下一章中，我们将分析 Clipper1 的边（Edge）数据结构和扫描线算法的核心逻辑。
