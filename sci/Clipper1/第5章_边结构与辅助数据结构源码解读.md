# 第5章：边结构与辅助数据结构源码解读

## 5.1 引言

在前面的章节中，我们分析了 Clipper1 的基础数据类型（`IntPoint`、`IntRect`、`DoublePoint`）、128 位整数运算（`Int128`）以及多边形树结构（`PolyNode` 与 `PolyTree`）。这些内容为理解 Clipper 的核心裁剪算法奠定了基础。然而，当我们真正进入 Clipper 最核心的 **Vatti 扫描线裁剪算法** 时，我们会发现：算法的复杂性并不仅仅在于数学计算，更在于它所依赖的**一系列精心设计的数据结构**。

本章是整个 Clipper 源码解读系列中**最关键**的一章。我们将深入剖析以下 10 个核心数据结构：

| 序号 | 数据结构 | 用途概述 |
|:---:|:---|:---|
| 1 | `TEdge` | **最核心的数据结构**——代表多边形的一条边，同时参与多个链表 |
| 2 | `LocalMinima` | 局部最小值——多边形中两条边"向上分叉"的最低点 |
| 3 | `Scanbeam` | 扫描束——驱动整个算法循环的 Y 坐标事件列表 |
| 4 | `Maxima` | 局部最大值——边达到最高点的 X 坐标列表 |
| 5 | `OutRec` | 输出记录——代表结果中的一个多边形 |
| 6 | `OutPt` | 输出点——输出多边形的顶点，环形双向链表结构 |
| 7 | `Join` | 连接记录——用于合并共享公共边的输出多边形 |
| 8 | `IntersectNode` | 交点节点——记录两条活动边的交点 |
| 9 | `MyIntersectNodeSort` | 交点排序器——按 Y 坐标降序排列交点 |
| 10 | **综合分析** | 所有数据结构的协作关系与数据流图 |

这些数据结构共同构成了 Vatti 扫描线算法的"骨架"。理解它们之间的关系，就等于理解了整个算法的一半。

## 5.2 前置知识：Vatti 扫描线算法概览

在深入分析每个数据结构之前，我们需要先建立一个对 **Vatti 扫描线裁剪算法（Vatti Scanline Clipping Algorithm）** 的宏观理解。该算法由 Bala R. Vatti 于 1992 年提出，是目前已知的最通用的多边形裁剪算法之一。

### 5.2.1 算法的基本思想

Vatti 算法的核心思想是：用一条**水平扫描线**从下往上（Y 值从小到大）扫过整个平面。在扫描过程中，扫描线会与多边形的各条边相交。算法通过维护一个**活动边列表（Active Edge List, AEL）**来跟踪当前扫描线与哪些边相交，并根据**填充规则（Fill Rule）**判断哪些区域位于多边形"内部"。

整个算法可以概括为以下几个阶段：

```
输入多边形
    │
    ▼
构建 TEdge 环形链表（每个多边形的边首尾相连）
    │
    ▼
识别 LocalMinima（局部最小值）
    │
    ▼
创建 Scanbeam 列表（所有需要处理的 Y 坐标）
    │
    ▼
主循环：对每个 scanbeam Y 值
    │
    ├── 1. 将新的 LocalMinima 的边插入 AEL
    ├── 2. 处理水平边
    ├── 3. 处理交点（Intersections）
    ├── 4. 处理到达顶部的边（删除或替换）
    ├── 5. 更新 OutRec/OutPt（输出多边形）
    └── 6. 处理 Join（合并共享公共边的输出多边形）
    │
    ▼
输出结果（Paths 或 PolyTree）
```

### 5.2.2 坐标系约定

**这是一个极其重要的概念，很多初学者会在这里产生混淆。**

在 Clipper 库中，坐标系的约定如下：

- **X 轴**：向右为正方向
- **Y 轴**：**向上为正方向**（数学坐标系，而非屏幕坐标系）

这意味着：
- Y 值较小的点在下方
- Y 值较大的点在上方
- 扫描线**从下往上**扫描，即 Y 值从小到大

但是，在屏幕坐标系（例如 Windows GDI、HTML Canvas）中：
- Y 轴**向下为正方向**
- Y 值较小的点在上方
- Y 值较大的点在下方

Clipper 在内部使用数学坐标系进行计算，但当用户使用屏幕坐标系的数据时，Clipper 通过 `ReverseSolution` 属性和方向判断来正确处理。

```
数学坐标系（Clipper 内部）      屏幕坐标系（显示用）

      Y ↑                              ┌──────→ X
        │                              │
        │    ·P2(3,5)                  │    ·P2(3,2)
        │   / \                        │   / \
        │  /   \                       │  /   \
        │ /     \                      │ /     \
        ·P1(1,2) ·P3(5,2)             ·P1(1,5) ·P3(5,5)
        │                             │
        └──────→ X                     ▼ Y

    扫描线从 Y=2 向上扫到 Y=5      扫描线从 Y=2 向下扫到 Y=5
```

## 5.3 TEdge 类：最核心的数据结构

### 5.3.1 完整源码

`TEdge` 是 Clipper 库中**最重要、最复杂**的数据结构。它代表多边形的一条**有向边（directed edge）**，并且**同时参与多个链表**。以下是其完整源码：

```csharp
  internal class TEdge {
    internal IntPoint Bot;
    internal IntPoint Curr; //current (updated for every new scanbeam)
    internal IntPoint Top;
    internal IntPoint Delta;
    internal double Dx;
    internal PolyType PolyTyp;
    internal EdgeSide Side; //side only refers to current side of solution poly
    internal int WindDelta; //1 or -1 depending on winding direction
    internal int WindCnt;
    internal int WindCnt2; //winding count of the opposite polytype
    internal int OutIdx;
    internal TEdge Next;
    internal TEdge Prev;
    internal TEdge NextInLML; //next in Local Minima List
    internal TEdge NextInAEL; //next in Active Edge List
    internal TEdge PrevInAEL; //prev in Active Edge List
    internal TEdge NextInSEL; //next in Sorted Edge List
    internal TEdge PrevInSEL; //prev in Sorted Edge List
  };
```

让我们注意几个关键设计决策：

1. **`internal` 访问修饰符**：所有字段都是 `internal`，意味着它们只在同一个程序集（assembly）内可见。这是因为 `TEdge` 是算法的内部实现细节，不应该暴露给外部使用者。
2. **`class`（引用类型）**而非 `struct`（值类型）：因为 `TEdge` 需要被多个链表指针引用，使用引用类型是正确的选择。如果使用 `struct`，每次赋值都会产生副本，链表指针将无法正常工作。
3. **没有构造函数或方法**：`TEdge` 是一个纯数据容器（Plain Old Data），所有初始化逻辑在外部方法中完成。

### 5.3.2 几何字段详解

#### 5.3.2.1 Bot（底部端点）

```csharp
internal IntPoint Bot;
```

**含义**：边的底部端点（Bottom point），即 Y 值**较小**的那个端点。

在 Clipper 的数学坐标系中，Y 值较小意味着位置偏下。因此 `Bot` 是这条边的"起始点"——在扫描线从下往上扫描时，扫描线首先到达的端点。

**关键细节**：

- `Bot.Y` 始终小于等于 `Top.Y`（`Bot.Y <= Top.Y`）
- 对于水平边（horizontal edge），`Bot.Y == Top.Y`
- `Bot` 在边初始化时确定，之后不再改变
- `Bot` 通常对应多边形的一个局部最小值（Local Minimum）的顶点

**注意屏幕坐标系的差异**：如果用户使用屏幕坐标系（Y 轴向下），则 `Bot` 实际上是屏幕上方的点。但 Clipper 在内部统一使用数学坐标系处理，这一细节对用户来说是透明的。

```
数学坐标系:                屏幕坐标系:
                            
   Top ·                      Bot · (在屏幕上方)
       |                          |
       |  ← 边                   |  ← 同一条边
       |                          |
   Bot ·                      Top · (在屏幕下方)
                            
  Bot.Y < Top.Y              Bot.Y < Top.Y（数值上）
  Bot 在下方                  但 Bot 在屏幕上方
```

#### 5.3.2.2 Curr（当前位置）

```csharp
internal IntPoint Curr; //current (updated for every new scanbeam)
```

**含义**：边与当前扫描线的交点位置（Current position）。每当扫描线移动到一个新的扫描束（scanbeam）Y 值时，`Curr` 会被更新。

**关键细节**：

- `Curr.Y` 等于当前扫描线的 Y 坐标
- `Curr.X` 是边与扫描线在该 Y 值处的交点 X 坐标
- `Curr` 用于确定活动边列表（AEL）中边的左右顺序
- 初始值为 `Bot`（当边刚被插入 AEL 时）

**更新公式**：当扫描线从 Y₁ 移动到 Y₂ 时，`Curr.X` 的更新使用以下逻辑：

```csharp
// 简化的更新逻辑（实际代码在 Clipper.UpdateEdgeIntoAEL 等方法中）
Curr.X = Bot.X + Round(Dx * (Y₂ - Bot.Y));
Curr.Y = Y₂;
```

其中 `Dx` 是逆斜率（inverse slope），我们将在 5.3.2.5 节详细讨论。

#### 5.3.2.3 Top（顶部端点）

```csharp
internal IntPoint Top;
```

**含义**：边的顶部端点（Top point），即 Y 值**较大**的那个端点。

**关键细节**：

- `Top.Y` 始终大于等于 `Bot.Y`（`Top.Y >= Bot.Y`）
- 当扫描线到达 `Top.Y` 时，这条边就到达了它的顶部，需要在 `ProcessEdgesAtTopOfScanbeam` 中进行处理
- 处理方式取决于该边是否还有后续边（`NextInLML` 是否为 null）：
  - 有后续边：用后续边替换当前边
  - 无后续边：这是一个局部最大值（local maximum），删除该边

#### 5.3.2.4 Delta（预计算的向量差）

```csharp
internal IntPoint Delta;
```

**含义**：预计算的向量差 `Delta = Top - Bot`，即从底部端点到顶部端点的方向向量。

**计算方式**：

```csharp
Delta.X = Top.X - Bot.X;
Delta.Y = Top.Y - Bot.Y;
```

**用途**：

1. **计算 Dx**（逆斜率）：`Dx = Delta.X / Delta.Y`
2. **判断边的方向**：`Delta.X > 0` 表示边从左向右上升，`Delta.X < 0` 表示边从右向左上升
3. **交点计算**：在 `IntersectPoint` 方法中用于计算两条边的交点

**为什么要预计算？** 因为 `Delta` 在算法过程中会被频繁使用（每次计算交点、每次更新 `Curr` 都可能用到），预计算可以避免重复运算。

#### 5.3.2.5 Dx（逆斜率）⭐ 最关键的几何属性

```csharp
internal double Dx;
```

**含义**：边的**逆斜率（inverse slope）**，定义为 `Delta.X / Delta.Y`，即 **X 方向的变化量除以 Y 方向的变化量**。

**这是一个非常重要的设计决策，需要仔细理解。**

在传统数学中，直线的斜率（slope）定义为：

```
slope = ΔY / ΔX = (Y₂ - Y₁) / (X₂ - X₁)
```

但是在 Clipper 中，使用的是**逆斜率**：

```
Dx = ΔX / ΔY = (X₂ - X₁) / (Y₂ - Y₁) = Delta.X / Delta.Y
```

**为什么使用逆斜率而不是斜率？**

因为 Vatti 算法的扫描线是**水平的**，沿 **Y 轴方向**扫描。在每一步中，我们需要回答的核心问题是：

> "当 Y 增加 1 时，这条边的 X 坐标变化了多少？"

这恰恰就是逆斜率 `Dx` 的定义！如果我们使用传统斜率 `slope = ΔY/ΔX`，则每次计算都需要执行一次除法（`ΔX_change = ΔY_step / slope`），而使用逆斜率只需要一次乘法（`ΔX_change = Dx * ΔY_step`），计算效率更高。

**初始化 Dx 的代码**：

以下是 `InitEdge2` 方法中计算 `Dx` 的关键代码：

```csharp
internal static void InitEdge2(TEdge e, PolyType polyType)
{
    if (e.Curr.Y >= e.Next.Curr.Y)
    {
        e.Bot = e.Curr;
        e.Top = e.Next.Curr;
    }
    else
    {
        e.Top = e.Curr;
        e.Bot = e.Next.Curr;
    }
    SetDx(e);
    e.PolyTyp = polyType;
}
```

以及 `SetDx` 方法的实现：

```csharp
internal static void SetDx(TEdge e)
{
    e.Delta.X = (e.Top.X - e.Bot.X);
    e.Delta.Y = (e.Top.Y - e.Bot.Y);
    if (e.Delta.Y == 0)
        e.Dx = horizontal; // horizontal = -3.4E+38
    else
        e.Dx = (double)(e.Delta.X) / (e.Delta.Y);
}
```

让我们逐行分析 `SetDx`：

| 行 | 代码 | 含义 |
|:---|:---|:---|
| 1 | `e.Delta.X = (e.Top.X - e.Bot.X)` | 计算 X 方向的变化量 |
| 2 | `e.Delta.Y = (e.Top.Y - e.Bot.Y)` | 计算 Y 方向的变化量 |
| 3 | `if (e.Delta.Y == 0)` | 判断是否为水平边 |
| 4 | `e.Dx = horizontal` | 水平边使用哨兵值 `-3.4E+38` |
| 5 | `else e.Dx = (double)(e.Delta.X) / (e.Delta.Y)` | 正常计算逆斜率 |

**水平边的特殊处理**：

对于水平边（`Delta.Y == 0`），逆斜率 `Dx` 在数学上是无穷大（除以零）。Clipper 使用一个特殊的哨兵值来表示水平边：

```csharp
internal const double horizontal = -3.4E+38;
```

这个值是一个极大的负数（接近 `double.MinValue`），选择负值的原因是：在活动边列表中，边是按 `Curr.X` 从左到右排序的，如果两条边的 `Curr.X` 相同，则按 `Dx` 排序。使用一个极大的负值可以确保水平边在排序时有确定的行为。

**Dx 的取值范围与几何含义**：

| Dx 的值 | 几何含义 | 边的方向 |
|:---|:---|:---|
| `Dx = 0` | 垂直边 | 边完全垂直，X 坐标不变 |
| `Dx > 0` | 边向右上方倾斜 | X 随 Y 增加而增加 |
| `Dx < 0` | 边向左上方倾斜 | X 随 Y 增加而减少 |
| `Dx = 1` | 45° 边 | X 和 Y 以相同速率变化 |
| `Dx = -1` | 135° 边 | X 减少速率等于 Y 增加速率 |
| `Dx = horizontal` | 水平边 | 特殊情况，单独处理 |

```
Dx < 0        Dx = 0        Dx > 0        水平边
                                          
  · Top        · Top            · Top     · ─────── ·
 /             |                 \        Bot       Top
/              |                  \       (Dx = -3.4E+38)
· Bot          · Bot          · Bot
```

### 5.3.3 分类字段详解

#### 5.3.3.1 PolyTyp（多边形类型）

```csharp
internal PolyType PolyTyp;
```

**含义**：标识这条边属于哪种类型的输入多边形。

`PolyType` 是一个枚举类型：

```csharp
public enum PolyType { ptSubject, ptClip };
```

| 值 | 含义 | 说明 |
|:---|:---|:---|
| `ptSubject` | 主多边形（Subject） | 被裁剪的多边形 |
| `ptClip` | 裁剪多边形（Clip） | 用来裁剪的多边形 |

**用途**：在布尔运算过程中，算法需要分别统计 Subject 和 Clip 多边形的缠绕数（winding count），以确定哪些区域位于结果多边形的"内部"。`PolyTyp` 字段使得算法能够区分一条边属于哪种多边形。

**举例**：在计算 `A ∩ B`（A 与 B 的交集）时：
- A 的所有边：`PolyTyp = ptSubject`
- B 的所有边：`PolyTyp = ptClip`

#### 5.3.3.2 Side（边侧）

```csharp
internal EdgeSide Side; //side only refers to current side of solution poly
```

**含义**：这条边当前位于输出多边形（solution polygon）的哪一侧。

`EdgeSide` 是一个枚举类型：

```csharp
public enum EdgeSide { esLeft, esRight };
```

| 值 | 含义 |
|:---|:---|
| `esLeft` | 边位于输出多边形的左侧 |
| `esRight` | 边位于输出多边形的右侧 |

**重要说明**：`Side` 仅指在**输出多边形**中的位置，而非在输入多边形中的位置。当两条活动边相遇形成输出多边形时：
- 左边的那条边的 `Side = esLeft`
- 右边的那条边的 `Side = esRight`

当扫描线扫过一个输出多边形的左边界时，点被添加到输出多边形的左侧链表；扫过右边界时，点被添加到右侧链表。这种区分确保了输出多边形的点按照正确的顺序排列。

#### 5.3.3.3 WindDelta（缠绕增量）

```csharp
internal int WindDelta; //1 or -1 depending on winding direction
```

**含义**：当扫描线从左往右穿过这条边时，缠绕数（winding number）的变化量。

| 值 | 含义 | 对应的边方向 |
|:---|:---|:---|
| `+1` | 缠绕数增加 | 边从下往上走（Bot → Top，Y 增加），在多边形中对应逆时针方向经过时左侧为内部 |
| `-1` | 缠绕数减少 | 边从上往下走（Top → Bot，Y 减少），在多边形中对应顺时针方向经过时右侧为内部 |
| `0` | 不影响缠绕数 | 开放路径（Open Path）的边 |

**缠绕方向的判断**：

在 `InitEdge2` 中，`WindDelta` 的值取决于边的原始方向（在多边形顶点序列中，这条边是从较小的 Y 到较大的 Y，还是反过来）。

```
缠绕方向示例（逆时针多边形）:

         · P2
        / \
       /   \        扫描线从左往右穿过:
      /     \       - 穿过左边(P1→P2): 缠绕数 +1
     /       \      - 穿过右边(P2→P3): 缠绕数 -1
    ·─────────·
   P1         P3

左边 WindDelta = +1     右边 WindDelta = -1
```

#### 5.3.3.4 WindCnt（缠绕计数）

```csharp
internal int WindCnt;
```

**含义**：这条边的缠绕计数（Winding Count）。缠绕计数表示从扫描线的最左端到这条边的位置，同类型（Subject 或 Clip）边的 `WindDelta` 累积和。

**如何计算**：在 `SetWindingCount` 方法中，从活动边列表（AEL）的左端开始，累加所有同类型边的 `WindDelta`，直到到达当前边。

**与填充规则的关系**：

缠绕计数与填充规则（Fill Rule）共同决定了一条边是否是"有效的"——即是否对输出多边形有贡献：

| 填充规则 | 边有效的条件 |
|:---|:---|
| `pftEvenOdd`（奇偶规则） | `WindCnt` 为奇数（`WindCnt % 2 != 0`） |
| `pftNonZero`（非零规则） | `WindCnt != 0` |
| `pftPositive`（正向规则） | `WindCnt > 0` |
| `pftNegative`（负向规则） | `WindCnt < 0` |

#### 5.3.3.5 WindCnt2（对侧缠绕计数）

```csharp
internal int WindCnt2; //winding count of the opposite polytype
```

**含义**：**另一种类型**多边形对这条边位置的缠绕计数。如果当前边属于 Subject 多边形（`PolyTyp = ptSubject`），则 `WindCnt2` 是 Clip 多边形在此位置的缠绕数；反之亦然。

**用途**：在布尔运算中，仅靠一种多边形的缠绕数是不够的。例如，计算交集（Intersection）时，一条 Subject 边只有在 Clip 多边形的"内部"时才应该出现在结果中。`WindCnt2` 正是用来判断这一点的。

**布尔运算判定表**：

| 运算类型 | Subject 边有效的条件 | Clip 边有效的条件 |
|:---|:---|:---|
| 交集（Intersection） | `WindCnt2 != 0`（在 Clip 内部） | `WindCnt2 != 0`（在 Subject 内部） |
| 并集（Union） | `WindCnt2 == 0`（在 Clip 外部） | `WindCnt2 == 0`（在 Subject 外部） |
| 差集（Difference） | `WindCnt2 == 0`（在 Clip 外部） | `WindCnt2 != 0`（在 Subject 内部） |
| 异或（Xor） | 总是有效 | 总是有效 |

> **注**：以上是简化的判定表，实际代码中还需要考虑填充规则的影响。

#### 5.3.3.6 OutIdx（输出索引）

```csharp
internal int OutIdx;
```

**含义**：这条边当前关联的输出记录（`OutRec`）在 `m_PolyOuts` 列表中的索引。

| 值 | 含义 |
|:---|:---|
| `-1`（`Unassigned`） | 这条边尚未分配给任何输出多边形 |
| `>= 0` | 这条边属于索引为 `OutIdx` 的输出多边形 |

**生命周期**：

1. **初始化**：当边刚被插入 AEL 时，`OutIdx = Unassigned (-1)`
2. **赋值**：当两条活动边相遇（形成一个新的输出多边形或向现有输出多边形添加点）时，`OutIdx` 被设置为对应 `OutRec` 的索引
3. **可能改变**：在处理过程中，如果两个输出多边形被合并，`OutIdx` 可能被更新为新的索引
4. **清除**：当边离开 AEL 时，不再需要 `OutIdx`

### 5.3.4 链表指针字段详解

这是 `TEdge` 最独特的设计——一个 `TEdge` 对象**同时参与最多 4 个不同的链表**。这在大多数数据结构教科书中是不常见的，但它是 Vatti 算法高效实现的关键。

#### 5.3.4.1 Next / Prev（多边形环链表）

```csharp
internal TEdge Next;
internal TEdge Prev;
```

**含义**：构成**多边形边环**的循环双向链表指针。

每个输入多边形被转换为一个 `TEdge` 对象的**环形双向链表**。例如，一个三角形有 3 条边，这 3 个 `TEdge` 对象通过 `Next` 和 `Prev` 首尾相连：

```
        TEdge A
       ┌──────┐
       │Bot   │
       │Top   │
       │Next ─┼──────────────────┐
       │Prev ─┼──────┐           │
       └──────┘      │           │
          ▲          │           ▼
          │       ┌──┴───┐   ┌──────┐
          │       │TEdge C│  │TEdge B│
          │       │Bot   │   │Bot   │
          │       │Top   │   │Top   │
          │       │Next ─┼───┘Next ─┼──┐
          └───────┤Prev  │   │Prev ─┼──┤
                  └──────┘   └──────┘  │
                      ▲                │
                      └────────────────┘
              
              A.Next = B, B.Next = C, C.Next = A  (循环)
              A.Prev = C, C.Prev = B, B.Prev = A  (反向循环)
```

**关键特性**：

- **循环**（circular）：最后一条边的 `Next` 指向第一条边，第一条边的 `Prev` 指向最后一条边
- **双向**（doubly-linked）：可以从任意边出发，沿任意方向遍历整个多边形
- **在整个算法生命周期中保持不变**：这个环链表在初始化阶段建立后，不会被修改（不同于 AEL 等动态链表）

#### 5.3.4.2 NextInLML（局部最小值链表）

```csharp
internal TEdge NextInLML; //next in Local Minima List
```

**含义**：在**局部最小值链表（Local Minima List）**中，指向当前边的**后续边**。

**背景**：当一条边到达其 `Top` 点时，如果它不是一个局部最大值（local maximum），那么多边形的轮廓会在 `Top` 点处"转弯"，继续沿另一条边延伸。`NextInLML` 指向的就是这条"接续边"。

```
            · P3
           / \
     e2   /   \   e3
         /     \
        · P2    · P4
        |       |
   e1   |       |   e4
        |       |
        · P1    · P5
         \     /
     e6   \   /   e5
           \ /
            · P6(局部最小值)

在 P6 这个局部最小值处:
- e6 和 e5 向上分叉
- e6.NextInLML = e1 (到达 P1 后转弯继续沿 e1 向上)
- e5.NextInLML = e4 (到达 P5 后转弯继续沿 e4 向上)
- e1.NextInLML = e2 (到达 P2 后转弯继续沿 e2 向上)
- e4.NextInLML = e3 (到达 P4 后转弯继续沿 e3 向上)
- e2.NextInLML = null (P3 是局部最大值, e2 到达终点)
- e3.NextInLML = null (P3 是局部最大值, e3 到达终点)
```

**当 `NextInLML == null` 时**：表示当前边到达的顶点是一个**局部最大值（local maximum）**。在处理时，这条边会被从 AEL 中删除。

#### 5.3.4.3 NextInAEL / PrevInAEL（活动边列表）

```csharp
internal TEdge NextInAEL; //next in Active Edge List
internal TEdge PrevInAEL; //prev in Active Edge List
```

**含义**：**活动边列表（Active Edge List, AEL）**的双向链表指针。

AEL 是 Vatti 算法中最重要的运行时数据结构。它包含当前扫描线与之相交的所有边，按照**当前 X 坐标（`Curr.X`）从左到右**排序。

```
扫描线 Y = 5:

    AEL (从左到右):
    
    null ← PrevInAEL ┌───────┐ NextInAEL → ┌───────┐ NextInAEL → ┌───────┐ NextInAEL → null
                      │Edge A │              │Edge B │              │Edge C │
                      │Curr.X │              │Curr.X │              │Curr.X │
                      │ = 2   │              │ = 5   │              │ = 8   │
                      └───────┘ ← PrevInAEL  └───────┘ ← PrevInAEL └───────┘
    
    Edge A.Curr.X < Edge B.Curr.X < Edge C.Curr.X
```

**AEL 的动态性**：

- **插入**：当扫描线到达一个局部最小值的 Y 坐标时，该最小值的两条边（LeftBound 和 RightBound）被插入 AEL
- **删除**：当一条边到达其 `Top` 点且没有后续边（`NextInLML == null`）时，从 AEL 中删除
- **替换**：当一条边到达其 `Top` 点且有后续边时，用后续边替换当前边
- **重新排序**：当两条边交叉时（交点事件），需要交换它们在 AEL 中的位置

#### 5.3.4.4 NextInSEL / PrevInSEL（排序边列表）

```csharp
internal TEdge NextInSEL; //next in Sorted Edge List
internal TEdge PrevInSEL; //prev in Sorted Edge List
```

**含义**：**排序边列表（Sorted Edge List, SEL）**的双向链表指针。SEL 是一个**临时性**的链表，仅在 `ProcessIntersections` 阶段使用。

**用途**：在处理交点时，算法需要找出当前扫描束中所有可能的边交叉。SEL 是 AEL 的一个"快照"，算法在这个快照上进行冒泡排序（bubble sort），每次交换就产生一个交点事件。

**生命周期**：

1. 在 `ProcessIntersections` 开始时，AEL 中的边被复制到 SEL 中（通过设置 `NextInSEL`/`PrevInSEL` 指针）
2. 对 SEL 进行排序，找出所有交叉
3. 处理完所有交点后，SEL 不再使用

### 5.3.5 TEdge 多链表参与图

下面这张图展示了一个 `TEdge` 对象是如何**同时参与多个链表**的：

```
                    ┌──────────────────────────────┐
                    │          TEdge 对象            │
                    │                              │
                    │  Bot, Curr, Top, Delta, Dx   │ ← 几何数据
                    │  PolyTyp, Side, WindDelta     │ ← 分类数据
                    │  WindCnt, WindCnt2, OutIdx    │ ← 运行时状态
                    │                              │
    ┌───────────────┤  Next ──────────────────────┐│──→ 多边形环链表
    │  ←────────────┤  Prev                       ││    (循环双向)
    │               │                              │
    │  ←────────────┤  NextInLML ─────────────────┐│──→ 局部最小值链
    │               │                              │    (单向)
    │               │                              │
    │  ┌────────────┤  NextInAEL ─────────────────┐│──→ 活动边列表
    │  │  ←─────────┤  PrevInAEL                  ││    (双向)
    │  │            │                              │
    │  │  ┌─────────┤  NextInSEL ─────────────────┐│──→ 排序边列表
    │  │  │  ←──────┤  PrevInSEL                  ││    (双向, 临时)
    │  │  │         │                              │
    │  │  │         └──────────────────────────────┘
    │  │  │
    │  │  │     同一个 TEdge 对象同时存在于:
    │  │  │     1. 多边形环链表 (永久, 循环双向)
    │  │  │     2. 局部最小值链  (永久, 单向)
    │  │  │     3. 活动边列表   (动态, 双向)
    │  │  │     4. 排序边列表   (临时, 双向)
    ▼  ▼  ▼
```

**为什么这样设计？**

使用多个指针使同一对象参与多个链表，而不是维护多个独立的数据结构（如多个数组或字典），有以下优势：

1. **O(1) 的跨链表导航**：知道一个 `TEdge` 在 AEL 中的位置，可以立即访问它在多边形环链表中的邻居，无需查找
2. **零内存开销**：不需要额外的容器对象（如 `LinkedListNode<T>`）
3. **避免重复存储**：同一个对象只存在一份，不同链表共享引用
4. **缓存友好**：虽然是链表，但由于 `TEdge` 对象包含所有必要信息，一次内存访问就能获取所有字段

## 5.4 LocalMinima 类：局部最小值

### 5.4.1 完整源码

```csharp
  internal class LocalMinima
  {
    internal cInt Y;
    internal TEdge LeftBound;
    internal TEdge RightBound;
    internal LocalMinima Next;
  };
```

### 5.4.2 什么是局部最小值？

**局部最小值（Local Minimum）** 是多边形轮廓上的一个顶点，在该顶点处，多边形的两条相邻边都**向上延伸**。换句话说，它是轮廓上的一个"V 形谷底"。

```
一个六边形的局部最小值示例:

            · P3 (局部最大值)
           / \
          /   \
    P2 ·       · P4
        |       |
        |       |
    P1 ·       · P5
         \     /
          \   /
           · P6 (局部最小值: 两条边都向上延伸)
```

在上面的例子中：
- `P6` 是一个**局部最小值**：边 P6→P1 向上延伸，边 P6→P5 也向上延伸
- `P3` 是一个**局部最大值**：边 P2→P3 到达顶部，边 P3→P4 开始下降

**一个多边形可以有多个局部最小值**：

```
复杂多边形（W 形）:

    ·           ·           ·
   / \         / \         / \
  /   \       /   \       /   \
 /     \     /     \     /     \
·       \   /       \   /       ·
         \ /         \ /
          · LM1       · LM2

这个多边形有 2 个局部最小值 (LM1 和 LM2)
```

### 5.4.3 字段详解

#### 5.4.3.1 Y（局部最小值的 Y 坐标）

```csharp
internal cInt Y;
```

**含义**：这个局部最小值所在的 Y 坐标。`cInt` 是 `long` 的别名（在 `use_int32` 未定义时），提供 64 位整数精度。

**用途**：
- 确定扫描线何时到达这个局部最小值
- 用于将所有局部最小值按 Y 坐标排序

#### 5.4.3.2 LeftBound（左边界）

```csharp
internal TEdge LeftBound;
```

**含义**：从局部最小值向上延伸的**左侧边**。

"左侧"的定义：如果两条边从最小值点分叉向上，X 坐标较小（或 `Dx` 值使其偏左）的那条边是 `LeftBound`。

#### 5.4.3.3 RightBound（右边界）

```csharp
internal TEdge RightBound;
```

**含义**：从局部最小值向上延伸的**右侧边**。

**LeftBound 和 RightBound 的关系**：

```
              LeftBound          RightBound
                  \                /
                   \              /
                    \            /
                     \          /
                      · ──────── Y = LocalMinima.Y
                  局部最小值点
                  
LeftBound.Bot == RightBound.Bot == (最小值点的坐标)
LeftBound.Bot.Y == RightBound.Bot.Y == LocalMinima.Y
```

**特殊情况**：当一条边是水平边时，`LeftBound` 或 `RightBound` 可能为 `null`。这是因为水平边需要特殊处理，Clipper 在某些情况下会将水平边放在右侧边界。

#### 5.4.3.4 Next（下一个局部最小值）

```csharp
internal LocalMinima Next;
```

**含义**：指向下一个局部最小值的指针，形成一个**按 Y 坐标从小到大排序**的单向链表。

```
局部最小值链表（从底部到顶部）:

┌──────────┐     ┌──────────┐     ┌──────────┐
│ LM1      │     │ LM2      │     │ LM3      │
│ Y = 2    │────→│ Y = 5    │────→│ Y = 8    │────→ null
│LeftBound │     │LeftBound │     │LeftBound │
│RightBound│     │RightBound│     │RightBound│
└──────────┘     └──────────┘     └──────────┘
```

### 5.4.4 ClipperBase 如何构建局部最小值链表

Clipper 通过以下步骤从输入多边形构建局部最小值链表：

**第一步：创建 TEdge 环形链表**

对于每个输入多边形，创建一个 `TEdge` 对象的环形双向链表。每个多边形顶点对应一条边（从该顶点到下一个顶点）。

**第二步：识别局部最小值**

遍历 `TEdge` 环形链表，寻找满足以下条件的顶点：

```csharp
// 简化的局部最小值识别逻辑
// 一个顶点是局部最小值，当且仅当：
// 它的 Y 坐标小于等于它的前驱和后继的 Y 坐标
```

**第三步：构建链表**

将所有识别出的局部最小值按 Y 坐标插入排序链表中。对于 Y 坐标相同的局部最小值，保持它们被发现的顺序。

**第四步：设置 NextInLML**

从每个局部最小值出发，沿着边的链路设置 `NextInLML` 指针，直到遇到下一个局部最大值或局部最小值。

## 5.5 Scanbeam 类：扫描束

### 5.5.1 完整源码

```csharp
  internal class Scanbeam
  {
    internal cInt Y;
    internal Scanbeam Next;
  };
```

### 5.5.2 什么是扫描束？

**扫描束（Scanbeam）** 是 Y 坐标值的集合，代表扫描线在算法执行过程中需要**停下来处理事件**的位置。

扫描线并不是以 1 为步长逐步扫描整个 Y 轴范围的——那样效率太低。相反，扫描线只在**有意义的 Y 坐标**处停留。这些"有意义的 Y 坐标"包括：

| 事件类型 | 说明 |
|:---|:---|
| 边的底部（`Bot.Y`） | 新的边需要被插入 AEL |
| 边的顶部（`Top.Y`） | 边到达终点，需要被删除或替换 |
| 交点的 Y 坐标 | 两条边交叉，需要交换它们在 AEL 中的顺序 |

```
示例: 一个三角形的扫描束

    · P2 (Y=10)          扫描束列表: Y=2, Y=10
   / \
  /   \
 /     \
·───────· P1(Y=2), P3(Y=2)

扫描线在 Y=2 处: 插入两条边到 AEL
扫描线在 Y=10 处: 两条边到达顶部, 处理局部最大值
```

### 5.5.3 字段详解

#### 5.5.3.1 Y（扫描束 Y 坐标）

```csharp
internal cInt Y;
```

**含义**：需要处理事件的 Y 坐标值。

#### 5.5.3.2 Next（下一个扫描束）

```csharp
internal Scanbeam Next;
```

**含义**：指向下一个扫描束的指针，形成**按 Y 坐标从小到大排序**的单向链表。

```
扫描束链表:

┌──────────┐     ┌──────────┐     ┌──────────┐     ┌──────────┐
│ SB1      │     │ SB2      │     │ SB3      │     │ SB4      │
│ Y = 2    │────→│ Y = 5    │────→│ Y = 8    │────→│ Y = 12   │────→ null
└──────────┘     └──────────┘     └──────────┘     └──────────┘
```

### 5.5.4 扫描束如何驱动主算法循环

扫描束是整个 Vatti 算法的"时钟"。主循环的伪代码如下：

```csharp
// Clipper.ExecuteInternal 的简化逻辑
while (PopScanbeam(out cInt Y))  // 取出下一个扫描束 Y 值
{
    InsertLocalMinimaIntoAEL(Y);     // 插入新的局部最小值到 AEL
    ProcessHorizontals();             // 处理水平边
    ProcessIntersections(topY);       // 处理交点
    ProcessEdgesAtTopOfScanbeam(topY);// 处理到达顶部的边
}
```

每次循环处理一个扫描束，从链表的头部取出 Y 值最小的扫描束。当链表为空时（所有事件都已处理），算法终止。

### 5.5.5 为什么使用链表而非优先队列？

理论上，扫描束可以使用优先队列（如最小堆）实现，这样插入和取出最小值都是 O(log n) 复杂度。然而，Clipper 选择使用**排序链表**，原因可能包括：

1. **实际规模较小**：扫描束的数量通常不会特别大（与多边形顶点数量线性相关），排序链表的常数因子更小
2. **去重方便**：链表在插入时可以方便地跳过重复的 Y 值
3. **实现简单**：链表的代码更简洁，更容易调试和维护
4. **内存分配模式**：链表节点可以逐个分配，适合 C# 的垃圾回收器

## 5.6 Maxima 类：局部最大值

### 5.6.1 完整源码

```csharp
  internal class Maxima
  {
    internal cInt X;
    internal Maxima Next;
    internal Maxima Prev;
  };
```

### 5.6.2 什么是局部最大值？

在 Vatti 算法的上下文中，**Maxima** 记录的不是 Y 坐标的最大值，而是**边到达其最高点时的 X 坐标**。当一条边到达其 `Top` 点且 `NextInLML == null`（即该顶点是一个局部最大值点，两条边在此处汇合而不再继续向上）时，这个 `Top` 点的 X 坐标被记录为一个 `Maxima`。

```
      · P_max (局部最大值)
     / \
    /   \
   /     \
  ·       ·
  
P_max.X 被记录在 Maxima 链表中
```

### 5.6.3 字段详解

#### 5.6.3.1 X（最大值点的 X 坐标）

```csharp
internal cInt X;
```

**含义**：局部最大值点的 X 坐标。

**为什么只记录 X 而不记录 Y？** 因为局部最大值总是在当前扫描束的 Y 坐标处被处理，此时 Y 值是已知的。算法需要的是 X 坐标，用于在处理活动边时进行比较。

#### 5.6.3.2 Next / Prev（双向链表指针）

```csharp
internal Maxima Next;
internal Maxima Prev;
```

**含义**：构成**按 X 坐标排序**的双向链表。

**为什么使用双向链表？** 与 `Scanbeam` 的单向链表不同，`Maxima` 使用双向链表是因为在 `ProcessEdgesAtTopOfScanbeam` 阶段，算法需要在链表中进行高效的插入和删除操作。双向链表允许 O(1) 的删除操作（只需更新前后节点的指针），而单向链表的删除需要 O(n) 来找到前驱节点。

```
Maxima 双向链表（按 X 排序）:

null ← Prev ┌─────────┐ Next → ┌─────────┐ Next → ┌─────────┐ Next → null
             │ M1      │        │ M2      │        │ M3      │
             │ X = 3   │        │ X = 7   │        │ X = 12  │
             └─────────┘ ← Prev └─────────┘ ← Prev └─────────┘
```

### 5.6.4 Maxima 在算法中的作用

在 `ProcessEdgesAtTopOfScanbeam` 中，当扫描线到达一条边的顶部时，如果该边到达的是一个局部最大值点，算法需要检查是否有其他边也到达相同的 X 坐标。`Maxima` 链表提供了一种快速查找的机制：

1. 在处理到达顶部的边时，将局部最大值点的 X 坐标插入 `Maxima` 链表
2. 当处理其他边经过这些 X 坐标时，检查是否需要添加额外的输出点
3. 处理完当前扫描束后，清空 `Maxima` 链表

这种机制确保了在局部最大值处，输出多边形的点被正确地连接起来。

## 5.7 OutRec 类：输出记录

### 5.7.1 完整源码

```csharp
  internal class OutRec
  {
    internal int Idx;
    internal bool IsHole;
    internal bool IsOpen;
    internal OutRec FirstLeft; //see comments inerta
    internal OutPt Pts;
    internal OutPt BottomPt;
    internal PolyNode PolyNode;
  };
```

### 5.7.2 概述

`OutRec`（Output Record，输出记录）代表布尔运算结果中的**一个输出多边形**。当 Clipper 算法确定某条边对输出有贡献时，它会创建或更新一个 `OutRec` 对象。

### 5.7.3 字段详解

#### 5.7.3.1 Idx（唯一标识符）

```csharp
internal int Idx;
```

**含义**：这个输出记录在 `Clipper.m_PolyOuts`（一个 `List<OutRec>`）中的索引。

**用途**：
- 用于快速查找：通过索引在 O(1) 时间内访问对应的 `OutRec`
- 用于关联：`TEdge.OutIdx` 字段存储的就是这个值
- 用于去重：如果两条边指向相同的 `Idx`，说明它们属于同一个输出多边形

#### 5.7.3.2 IsHole（是否为孔洞）

```csharp
internal bool IsHole;
```

**含义**：标识这个输出多边形是否是一个**孔洞（hole）**。

**判断规则**：

- `IsHole = true`：这个多边形是其父多边形内部的一个空洞区域
- `IsHole = false`：这个多边形是一个实心的外轮廓

**如何确定**：在算法的后处理阶段（`FixupOutPolyline`、`BuildResult2` 等方法），Clipper 通过分析多边形的方向（顺时针或逆时针）以及与其他多边形的包含关系来确定 `IsHole` 的值。

在默认设置下（`ReverseSolution = false`）：
- 外轮廓的方向为 `true`（面积为正，即逆时针方向）
- 孔洞的方向为 `false`（面积为负，即顺时针方向）

#### 5.7.3.3 IsOpen（是否为开放路径）

```csharp
internal bool IsOpen;
```

**含义**：标识这个输出记录是否代表一条**开放路径（open path）**。

**开放路径 vs 闭合多边形**：

| 特征 | 闭合多边形 | 开放路径 |
|:---|:---|:---|
| `IsOpen` | `false` | `true` |
| 首尾相连 | 是 | 否 |
| 有面积 | 是 | 否（线条） |
| 可作为 Subject | 是 | 是 |
| 可作为 Clip | 是 | **否**（开放路径不能作为裁剪多边形） |

#### 5.7.3.4 FirstLeft（首个左侧外轮廓）⭐ 关键字段

```csharp
internal OutRec FirstLeft;
```

**含义**：指向**包含当前多边形的最内层外轮廓**。这是构建 `PolyTree` 层次结构的关键字段。

**作用说明**：

```
一个嵌套结构的示例:

┌────────────────────────────────────────────┐
│  OutRec A (外轮廓)                          │
│  FirstLeft = null                           │
│                                             │
│  ┌──────────────────────────────────────┐   │
│  │  OutRec B (孔洞)                      │   │
│  │  FirstLeft → OutRec A                 │   │
│  │                                       │   │
│  │  ┌────────────────────────────────┐   │   │
│  │  │  OutRec C (岛屿/外轮廓)         │   │   │
│  │  │  FirstLeft → OutRec B           │   │   │
│  │  └────────────────────────────────┘   │   │
│  │                                       │   │
│  └──────────────────────────────────────┘   │
│                                             │
└────────────────────────────────────────────┘

A.FirstLeft = null (最外层, 没有包围它的多边形)
B.FirstLeft = A    (B 被 A 包含)
C.FirstLeft = B    (C 被 B 包含)
```

在构建 `PolyTree` 时，`FirstLeft` 用于确定每个多边形节点的父节点。如果 `FirstLeft` 为 `null`，则该多边形是 `PolyTree` 的直接子节点（最外层多边形）。

#### 5.7.3.5 Pts（输出点链表头指针）

```csharp
internal OutPt Pts;
```

**含义**：指向这个输出多边形的**第一个输出点（`OutPt`）**。所有输出点构成一个**环形双向链表**。

**结构示意**：

```
Pts ──→ OutPt1 ⟷ OutPt2 ⟷ OutPt3 ⟷ OutPt4
           ↑                              │
           └──────────────────────────────┘
                    (环形链表)
```

#### 5.7.3.6 BottomPt（底部点指针）

```csharp
internal OutPt BottomPt;
```

**含义**：指向这个输出多边形中 Y 坐标**最小**的点（即几何上最低的点）。

**用途**：
- 用于计算多边形的方向（`Orientation`）：通过分析 `BottomPt` 附近点的走向来确定多边形是顺时针还是逆时针
- 用于排序：当需要比较两个输出多边形的位置关系时

#### 5.7.3.7 PolyNode（多边形树节点引用）

```csharp
internal PolyNode PolyNode;
```

**含义**：在构建 `PolyTree` 输出时，指向与这个 `OutRec` 对应的 `PolyNode` 对象。

**用途**：在 `BuildResult2` 方法中，Clipper 遍历所有 `OutRec`，为每个有效的输出多边形创建一个 `PolyNode`，并根据 `FirstLeft` 指针建立父子关系。`PolyNode` 字段使得从 `OutRec` 到 `PolyNode` 的映射是直接的。

## 5.8 OutPt 类：输出点

### 5.8.1 完整源码

```csharp
  internal class OutPt
  {
    internal int Idx;
    internal IntPoint Pt;
    internal OutPt Next;
    internal OutPt Prev;
  };
```

### 5.8.2 概述

`OutPt`（Output Point，输出点）代表输出多边形的**一个顶点**。多个 `OutPt` 通过 `Next` 和 `Prev` 指针形成一个**环形双向链表**，表示一个完整的多边形轮廓。

### 5.8.3 字段详解

#### 5.8.3.1 Idx（所属输出记录索引）

```csharp
internal int Idx;
```

**含义**：这个输出点所属的 `OutRec` 的索引值。即 `Idx` 等于对应 `OutRec.Idx` 的值。

**用途**：当算法需要知道一个输出点属于哪个输出多边形时，可以通过 `Idx` 在 `m_PolyOuts` 列表中直接查找对应的 `OutRec`，时间复杂度为 O(1)。

#### 5.8.3.2 Pt（坐标点）

```csharp
internal IntPoint Pt;
```

**含义**：这个输出点的实际坐标值。`IntPoint` 包含 `X` 和 `Y` 两个 `cInt` 类型的字段。

#### 5.8.3.3 Next / Prev（环形双向链表指针）

```csharp
internal OutPt Next;
internal OutPt Prev;
```

**含义**：构成**环形双向链表**的指针。

**关键特性**：

- **环形**：最后一个点的 `Next` 指向第一个点，第一个点的 `Prev` 指向最后一个点
- **双向**：可以从任意点出发，向任意方向遍历整个多边形
- **不存在 null 指针**：由于是环形结构，`Next` 和 `Prev` 永远不为 `null`

```
OutPt 环形双向链表示意图:

    ┌──────┐      ┌──────┐      ┌──────┐      ┌──────┐
    │OutPt1│ Next→│OutPt2│ Next→│OutPt3│ Next→│OutPt4│
    │(1,2) │←Prev │(3,5) │←Prev │(5,3) │←Prev │(4,1) │
    └──────┘      └──────┘      └──────┘      └──────┘
       ▲   ↑                                      │   │
       │   └──────────────────────────────────────┘   │
       └──────────────────────────────────────────────┘
    
    OutPt1.Next = OutPt2       OutPt4.Next = OutPt1 (环形)
    OutPt1.Prev = OutPt4 (环形) OutPt4.Prev = OutPt3
    
    遍历方法:
    OutPt op = startPt;
    do {
        // 处理 op
        op = op.Next;
    } while (op != startPt);
```

### 5.8.4 OutPt 的添加方式

在算法运行过程中，新的 `OutPt` 被添加到环形链表中的方式取决于当前边的 `Side`：

```csharp
// 简化的添加逻辑 (AddOutPt 方法)
if (edge.Side == EdgeSide.esLeft)
{
    // 在 Pts 之前插入 (链表头部)
    newOp.Next = outRec.Pts;
    newOp.Prev = outRec.Pts.Prev;
    outRec.Pts.Prev.Next = newOp;
    outRec.Pts.Prev = newOp;
    outRec.Pts = newOp;  // 更新头指针
}
else
{
    // 在 Pts 之后插入 (链表尾部, 但由于是环形, 效果等同于在头部的 Prev 方向)
    newOp.Prev = outRec.Pts;
    newOp.Next = outRec.Pts.Next;
    outRec.Pts.Next.Prev = newOp;
    outRec.Pts.Next = newOp;
}
```

这种左右分别添加的机制确保了输出多边形的点按照**正确的环绕方向**排列。

## 5.9 Join 类：连接记录

### 5.9.1 完整源码

```csharp
  internal class Join
  {
    internal OutPt OutPt1;
    internal OutPt OutPt2;
    internal IntPoint OffPt;
  };
```

### 5.9.2 概述

`Join` 代表两个输出多边形之间的一个**潜在连接点**。当两个多边形共享一条公共边（common edge）时，它们可以被合并为一个多边形。`Join` 记录了这种合并的信息。

### 5.9.3 为什么需要 Join？

在布尔运算过程中，可能会出现以下情况：

```
两个输出多边形共享一条公共边:

    ┌───────┬───────┐
    │       │       │
    │ Poly1 │ Poly2 │
    │       │       │
    └───────┴───────┘
         ↑
    公共边 (shared edge)

合并后:
    ┌───────────────┐
    │               │
    │   Merged Poly │
    │               │
    └───────────────┘
```

这种情况在自交多边形（self-intersecting polygon）或重叠多边形中尤为常见。如果不进行合并，结果中会出现不必要的退化边（零面积的突出部分）。

### 5.9.4 字段详解

#### 5.9.4.1 OutPt1 / OutPt2（连接点对）

```csharp
internal OutPt OutPt1;
internal OutPt OutPt2;
```

**含义**：公共边两端的输出点。`OutPt1` 属于一个输出多边形，`OutPt2` 属于另一个（或同一个）输出多边形。

**如果 OutPt1 和 OutPt2 属于同一个 OutRec**：合并操作会将该多边形一分为二（split），这种情况对应的是多边形的自接触（self-touching）。

**如果 OutPt1 和 OutPt2 属于不同的 OutRec**：合并操作会将两个多边形合并为一个。

#### 5.9.4.2 OffPt（偏移点）

```csharp
internal IntPoint OffPt;
```

**含义**：偏移点（Offset Point），与公共边的中间位置相关。

**用途**：在 `JoinCommonEdges` 方法中，`OffPt` 用于验证连接的有效性——确认两个输出点确实位于同一条公共边上。`OffPt` 是公共边上的一个参考点，通过比较 `OutPt1.Pt`、`OutPt2.Pt` 和 `OffPt` 的位置关系来判断连接是否合法。

### 5.9.5 Join 的处理流程

```
1. 在 AddLocalMinPoly / AddLocalMaxPoly 中:
   检测是否存在公共边, 如果存在则创建 Join 记录
   
2. 将 Join 记录添加到 m_Joins 列表

3. 在所有扫描束处理完成后:
   调用 JoinCommonEdges() 方法
   遍历 m_Joins 列表
   对每个 Join, 执行合并操作
```

## 5.10 IntersectNode 类：交点节点

### 5.10.1 完整源码

```csharp
  public class IntersectNode
  {
    internal TEdge Edge1;
    internal TEdge Edge2;
    internal IntPoint Pt;
  };
```

### 5.10.2 概述

`IntersectNode` 代表两条活动边的一个**交点事件**。在 Vatti 算法中，当扫描线向上移动时，两条边可能会交叉——这意味着它们在 AEL 中的左右顺序需要交换。

### 5.10.3 字段详解

#### 5.10.3.1 Edge1 / Edge2（相交的两条边）

```csharp
internal TEdge Edge1;
internal TEdge Edge2;
```

**含义**：发生交叉的两条活动边的引用。在交点处理时，这两条边在 AEL 中的位置将被交换。

**约定**：`Edge1` 在交换前位于 `Edge2` 的左边（`Edge1.Curr.X <= Edge2.Curr.X`）。

#### 5.10.3.2 Pt（交点坐标）

```csharp
internal IntPoint Pt;
```

**含义**：两条边的交点坐标，通过 `IntersectPoint` 方法计算得出。

**精度说明**：由于 Clipper 使用整数坐标，交点坐标会被四舍五入到最近的整数。这可能导致微小的精度误差，但 Clipper 的整数运算保证了结果的确定性和可重现性。

### 5.10.4 交点的计算

`IntersectPoint` 方法使用以下数学原理来计算两条直线的交点：

给定两条边 e1 和 e2，各有其底部端点和 `Dx` 值：

```
e1 的参数方程: X = e1.Bot.X + e1.Dx * (Y - e1.Bot.Y)
e2 的参数方程: X = e2.Bot.X + e2.Dx * (Y - e2.Bot.Y)

令两式相等:
e1.Bot.X + e1.Dx * (Y - e1.Bot.Y) = e2.Bot.X + e2.Dx * (Y - e2.Bot.Y)

解出 Y:
Y = (e2.Bot.X - e1.Bot.X + e1.Dx*e1.Bot.Y - e2.Dx*e2.Bot.Y) / (e1.Dx - e2.Dx)

然后将 Y 代回任一等式求出 X。
```

**特殊情况处理**：
- 如果 e1 或 e2 是垂直边（`Dx = 0`），交点的 X 坐标直接等于垂直边的 X 坐标
- 如果 e1 或 e2 是水平边（`Dx = horizontal`），需要特殊处理

### 5.10.5 交点在算法中的处理流程

```
ProcessIntersections 的流程:

1. 构建 SEL (Sorted Edge List):
   将 AEL 中的边复制到 SEL

2. 对 SEL 按当前扫描束顶部的 X 坐标排序:
   使用冒泡排序, 每次交换记录一个 IntersectNode

3. 收集所有 IntersectNode 到 m_IntersectList

4. 使用 MyIntersectNodeSort 对 m_IntersectList 排序

5. 验证交点列表的一致性 (FixupIntersectionOrder)

6. 对每个 IntersectNode:
   a. 在 AEL 中交换 Edge1 和 Edge2 的位置
   b. 根据布尔运算规则, 决定是否在交点处添加输出点
   c. 更新受影响边的 WindCnt 和 WindCnt2
```

## 5.11 MyIntersectNodeSort 类：交点排序器

### 5.11.1 完整源码

```csharp
  public class MyIntersectNodeSort : IComparer<IntersectNode>
  {
    public int Compare(IntersectNode node1, IntersectNode node2)
    {
      cInt i = node2.Pt.Y - node1.Pt.Y;
      if (i > 0) return 1;
      else if (i < 0) return -1;
      else return 0;
    }
  }
```

### 5.11.2 逐行分析

| 行号 | 代码 | 详细说明 |
|:---|:---|:---|
| 1 | `public class MyIntersectNodeSort : IComparer<IntersectNode>` | 实现 `IComparer<T>` 接口，使其可以被 `List<T>.Sort()` 使用 |
| 2 | `public int Compare(IntersectNode node1, IntersectNode node2)` | 比较两个交点节点的方法。返回正数表示 node1 排在后面，负数表示 node1 排在前面，0 表示相等 |
| 3 | `cInt i = node2.Pt.Y - node1.Pt.Y;` | **注意顺序**：是 `node2 - node1`，不是 `node1 - node2`！这决定了排序方向 |
| 4 | `if (i > 0) return 1;` | 如果 `node2.Y > node1.Y`，返回正数 → node1 排在 node2 前面 |
| 5 | `else if (i < 0) return -1;` | 如果 `node2.Y < node1.Y`，返回负数 → node1 排在 node2 后面 |
| 6 | `else return 0;` | Y 坐标相同，顺序不变 |

### 5.11.3 排序方向分析

这个比较器产生的排序结果是**按 Y 坐标降序排列**（从大到小）。

**证明**：

假设 `node1.Pt.Y = 3`，`node2.Pt.Y = 7`：
```
i = node2.Pt.Y - node1.Pt.Y = 7 - 3 = 4 > 0
返回 1 (正数)
```
`Compare` 返回正数意味着 node1 "大于" node2（在排序中 node1 排在 node2 后面），因此排序结果是 `node2(Y=7)` 在前，`node1(Y=3)` 在后——即**降序**。

### 5.11.4 为什么要降序排列？

**降序排列意味着交点按 Y 坐标从大到小的顺序处理**，即先处理 Y 值大的交点（上方的交点），后处理 Y 值小的交点（下方的交点）。

这看起来与"扫描线从下往上"的直觉相矛盾。然而，在 `ProcessIntersections` 的上下文中，降序是正确的。原因如下：

在当前扫描束内（Y 值范围 `[botY, topY]`），交点的 Y 坐标可能分布在这个范围内的任意位置。排序后的处理顺序需要保证**一致性**——即处理某个交点时，不会与后续交点产生矛盾。

具体来说，降序处理确保了：
1. 上方的交叉先处理，下方的交叉后处理
2. 在 AEL 中的交换操作按正确的顺序执行
3. 输出多边形的点按正确的顺序添加

**排序效果示例**：

```
交点列表（排序前）:
  IntersectNode1: Y = 5
  IntersectNode2: Y = 8
  IntersectNode3: Y = 3

排序后（降序）:
  IntersectNode2: Y = 8  ← 先处理
  IntersectNode1: Y = 5
  IntersectNode3: Y = 3  ← 后处理
```

### 5.12.2 TEdge 多链表参与总结

下面的表格总结了 `TEdge` 同时参与的所有链表：

| 链表名称 | 指针字段 | 链表类型 | 生命周期 | 排序依据 | 用途 |
|:---|:---|:---|:---|:---|:---|
| 多边形环 | `Next`, `Prev` | 循环双向 | 永久（整个算法生命周期） | 多边形顶点顺序 | 表示原始多边形结构 |
| LML 链 | `NextInLML` | 单向 | 永久 | 边的连接顺序 | 跟踪边到达 Top 后的后续边 |
| AEL | `NextInAEL`, `PrevInAEL` | 双向 | 动态（插入/删除） | `Curr.X` 从小到大 | 跟踪当前扫描线相交的边 |
| SEL | `NextInSEL`, `PrevInSEL` | 双向 | 临时（仅在交点处理阶段） | 按 Top 的 X 排序 | 辅助交点检测 |

### 5.12.3 所有数据结构的角色对比

| 数据结构 | 类比 | 创建时机 | 销毁时机 | 核心作用 |
|:---|:---|:---|:---|:---|
| `TEdge` | 演员 | 输入阶段 | 算法结束后由 GC 回收 | 多边形的一条边，算法的基本操作单元 |
| `LocalMinima` | 入场通知 | 输入阶段 | 用完即弃 | 告知算法何时将新边插入舞台（AEL） |
| `Scanbeam` | 时间表 | 输入+执行阶段 | 每次 Pop 后丢弃 | 驱动算法前进的"时钟" |
| `Maxima` | 退场标记 | 执行阶段 | 每个扫描束后清空 | 标记边到达最高点的位置 |
| `OutRec` | 剧本 | 执行阶段 | 输出后由 GC 回收 | 记录输出多边形的元信息 |
| `OutPt` | 台词 | 执行阶段 | 输出后由 GC 回收 | 记录输出多边形的每个顶点 |
| `Join` | 合并指令 | 执行阶段 | 处理后丢弃 | 合并共享公共边的多边形 |
| `IntersectNode` | 冲突报告 | 执行阶段 | 处理后丢弃 | 记录两条边的交叉事件 |
| `MyIntersectNodeSort` | 优先级规则 | 无状态工具 | 无需销毁 | 决定交点的处理顺序 |

### 5.12.4 为什么链表优于数组？

在 Clipper 的实现中，核心数据结构几乎全部使用**链表**而非**数组**（`List<T>` 或数组）。这是经过深思熟虑的设计决策。以下是原因分析：

| 操作 | 链表复杂度 | 数组复杂度 | 在算法中的频率 |
|:---|:---|:---|:---|
| 在已知位置插入 | O(1) | O(n)（需要移动元素） | **极高**（每次插入新边到 AEL） |
| 在已知位置删除 | O(1) | O(n)（需要移动元素） | **极高**（每次删除到达顶部的边） |
| 交换相邻元素 | O(1)（修改指针） | O(1)（交换数组元素） | **高**（处理交点时） |
| 顺序遍历 | O(n) | O(n) | **高**（遍历 AEL 计算 WindCnt） |
| 随机访问 | O(n) | O(1) | **极低**（算法几乎不需要随机访问） |

可以看到，算法中最频繁的操作（插入、删除）在链表中是 O(1) 的，而在数组中是 O(n) 的。唯一劣势——随机访问——在算法中几乎用不到。因此，链表是明确的最优选择。

此外，链表还有以下优势：
1. **一个对象参与多个链表**：这在数组中是不可能实现的（或需要额外的索引映射）
2. **无需预分配内存**：链表可以按需分配节点
3. **迭代器不会失效**：在修改链表时（插入/删除），其他位置的引用仍然有效

## 5.13 本章小结

本章是 Clipper1 源码解读系列中内容最密集的一章。我们详细分析了 Vatti 扫描线裁剪算法所依赖的 **9 个核心数据结构**，以及它们之间的协作关系。

### 5.13.1 关键要点回顾

1. **TEdge 是核心中的核心**：它不仅存储几何信息（Bot、Curr、Top、Delta、Dx），还存储分类信息（PolyTyp、Side、WindDelta）和运行时状态（WindCnt、WindCnt2、OutIdx），更重要的是它**同时参与 4 个不同的链表**（多边形环、LML 链、AEL、SEL）。

2. **逆斜率 Dx 是关键的性能优化**：使用 `ΔX/ΔY` 而非 `ΔY/ΔX`，使得在垂直扫描线方向上的 X 坐标更新仅需一次乘法。水平边使用哨兵值 `-3.4E+38` 处理。

3. **LocalMinima 是算法的"入口"**：它告诉算法何时、在哪里将新的边插入活动边列表。

4. **Scanbeam 是算法的"引擎"**：它驱动主循环，确保所有重要的 Y 坐标都被处理到。

5. **OutRec 和 OutPt 是算法的"输出"**：它们以环形双向链表的形式记录输出多边形的顶点，并通过 FirstLeft 建立嵌套层次。

6. **IntersectNode 和 MyIntersectNodeSort 处理最复杂的情况**：边的交叉检测和正确排序是算法正确性的关键。

7. **Join 是后处理步骤**：它在主循环结束后合并共享公共边的输出多边形，清理不必要的退化几何。

### 5.13.2 为下一章做准备

在下一章中，我们将进入 Clipper 算法的**核心执行逻辑**——`ClipperBase` 类和 `Clipper` 类。这些类包含了构建 TEdge 链表、识别 LocalMinima、驱动扫描线循环、处理交点等所有关键方法。本章分析的数据结构将是理解那些方法的基础。
