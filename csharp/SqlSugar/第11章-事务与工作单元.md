## 1. 事务基础概念

### 1.1 什么是事务

事务（Transaction）是数据库操作的逻辑单元，它保证一组数据库操作要么全部成功执行，要么全部回滚到操作前的状态。事务是保证数据一致性的核心机制。

### 1.2 ACID特性

事务必须满足四个基本特性，简称 ACID：

| 特性 | 英文 | 说明 |
|------|------|------|
| 原子性 | Atomicity | 事务中的操作要么全部完成，要么全部不完成 |
| 一致性 | Consistency | 事务完成后，数据必须处于一致状态 |
| 隔离性 | Isolation | 多个事务并发执行时，彼此互不干扰 |
| 持久性 | Durability | 事务完成后，其结果永久保存 |

### 1.3 事务的典型场景

```
场景1：银行转账
  步骤1：从A账户扣款1000元
  步骤2：向B账户存入1000元
  → 两步必须同时成功或同时失败

场景2：下单操作
  步骤1：创建订单记录
  步骤2：扣减商品库存
  步骤3：创建支付记录
  → 三步必须在同一事务中
```

### 1.4 SqlSugar中的事务支持

SqlSugar 提供了多种事务使用方式：

| 方式 | 特点 | 推荐场景 |
|------|------|---------|
| `BeginTran/CommitTran/RollbackTran` | 手动控制，灵活 | 复杂业务流程 |
| `UseTran` | 自动提交/回滚 | 简单事务场景 |
| `AsTran()` | 基于 `using` 语法 | 中等复杂度 |
| `UnitOfWork` | 工作单元模式 | 分层架构 |

## 2. 本地事务BeginTran

### 2.1 基本用法

`BeginTran/CommitTran/RollbackTran` 是最基础的事务控制方式，完全由开发者手动管理事务的生命周期：

```csharp
try
{
    db.Ado.BeginTran(); // 开启事务

    // 操作1：创建订单
    var order = new Order
    {
        OrderNo = "ORD20240101001",
        TotalAmount = 200m,
        Status = "待支付",
        CreateTime = DateTime.Now
    };
    var orderId = db.Insertable(order).ExecuteReturnIdentity();

    // 操作2：创建订单明细
    var detail = new OrderDetail
    {
        OrderId = orderId,
        ProductName = "商品A",
        Quantity = 2,
        Price = 100m
    };
    db.Insertable(detail).ExecuteCommand();

    // 操作3：扣减库存
    db.Updateable<Product>()
      .SetColumns(p => p.Stock == p.Stock - 2)
      .Where(p => p.Name == "商品A" && p.Stock >= 2)
      .ExecuteCommand();

    db.Ado.CommitTran(); // 提交事务
    Console.WriteLine("订单创建成功");
}
catch (Exception ex)
{
    db.Ado.RollbackTran(); // 回滚事务
    Console.WriteLine($"订单创建失败：{ex.Message}");
    throw;
}
```

### 2.2 事务中的查询

```csharp
try
{
    db.Ado.BeginTran();

    // 在事务中查询（读取的是事务内的数据状态）
    var product = db.Queryable<Product>()
                    .Where(p => p.Id == 1)
                    .First();

    if (product.Stock < 2)
    {
        throw new Exception("库存不足");
    }

    // 扣减库存
    db.Updateable<Product>()
      .SetColumns(p => p.Stock == p.Stock - 2)
      .Where(p => p.Id == 1)
      .ExecuteCommand();

    db.Ado.CommitTran();
}
catch (Exception ex)
{
    db.Ado.RollbackTran();
    throw;
}
```

### 2.3 事务中的多表操作

```csharp
try
{
    db.Ado.BeginTran();

    // 转账操作
    decimal amount = 1000m;

    // 1. 检查余额
    var fromAccount = db.Queryable<Account>()
                        .Where(a => a.Id == 1)
                        .First();
    if (fromAccount.Balance < amount)
    {
        throw new Exception("余额不足");
    }

    // 2. 扣款
    db.Updateable<Account>()
      .SetColumns(a => a.Balance == a.Balance - amount)
      .Where(a => a.Id == 1)
      .ExecuteCommand();

    // 3. 存款
    db.Updateable<Account>()
      .SetColumns(a => a.Balance == a.Balance + amount)
      .Where(a => a.Id == 2)
      .ExecuteCommand();

    // 4. 记录流水
    db.Insertable(new TransactionLog
    {
        FromAccountId = 1,
        ToAccountId = 2,
        Amount = amount,
        CreateTime = DateTime.Now,
        Remark = "转账"
    }).ExecuteCommand();

    db.Ado.CommitTran();
    Console.WriteLine($"转账 {amount} 元成功");
}
catch (Exception ex)
{
    db.Ado.RollbackTran();
    Console.WriteLine($"转账失败：{ex.Message}");
    throw;
}
```

## 3. UseTran方法

### 3.1 基本用法

`UseTran` 是 SqlSugar 提供的简化事务方法，它自动处理提交和回滚，减少了 try-catch 的样板代码：

```csharp
var result = db.UseTran(() =>
{
    // 事务中的操作
    db.Insertable(new Student { Name = "张三", Age = 20 }).ExecuteCommand();
    db.Insertable(new Student { Name = "李四", Age = 22 }).ExecuteCommand();
    db.Updateable<Class>()
      .SetColumns(c => c.StudentCount == c.StudentCount + 2)
      .Where(c => c.Id == 1)
      .ExecuteCommand();
});

if (result.IsSuccess)
{
    Console.WriteLine("事务执行成功");
}
else
{
    Console.WriteLine($"事务执行失败：{result.ErrorMessage}");
}
```

### 3.2 带返回值的UseTran

```csharp
// 返回事务执行的结果
var result = db.UseTran<int>(() =>
{
    var orderId = db.Insertable(new Order
    {
        OrderNo = "ORD001",
        TotalAmount = 100m,
        CreateTime = DateTime.Now
    }).ExecuteReturnIdentity();

    db.Insertable(new OrderDetail
    {
        OrderId = orderId,
        ProductName = "商品A",
        Quantity = 1,
        Price = 100m
    }).ExecuteCommand();

    return orderId; // 返回订单ID
});

if (result.IsSuccess)
{
    Console.WriteLine($"订单创建成功，ID: {result.Data}");
}
else
{
    Console.WriteLine($"订单创建失败：{result.ErrorMessage}");
}
```

### 3.3 异步UseTran

```csharp
// 异步事务
var result = await db.UseTranAsync(async () =>
{
    await db.Insertable(new Student { Name = "王五", Age = 21 })
            .ExecuteCommandAsync();

    await db.Updateable<Class>()
            .SetColumns(c => c.StudentCount == c.StudentCount + 1)
            .Where(c => c.Id == 1)
            .ExecuteCommandAsync();
});

if (result.IsSuccess)
{
    Console.WriteLine("异步事务执行成功");
}
```

### 3.4 UseTran与BeginTran的对比

| 特性 | BeginTran | UseTran |
|------|-----------|---------|
| 代码量 | 较多（需要try-catch） | 较少（自动处理） |
| 灵活性 | 高（完全手动控制） | 中等（自动提交/回滚） |
| 错误处理 | 手动 catch | 自动捕获，通过 IsSuccess 判断 |
| 返回值 | 需要自行处理 | 支持泛型返回值 |
| 推荐场景 | 复杂业务、需要条件判断 | 简单的事务操作 |

## 4. Using事务

### 4.1 基本用法

SqlSugar 还支持通过 `using` 语法管理事务，事务在 `using` 块结束时自动处理：

```csharp
using (var tran = db.UseTranScope())
{
    db.Insertable(new Student { Name = "张三", Age = 20 }).ExecuteCommand();
    db.Insertable(new Student { Name = "李四", Age = 22 }).ExecuteCommand();

    tran.Complete(); // 标记为完成（提交事务）
}
// 如果没有调用Complete()，事务会自动回滚
```

### 4.2 TransactionScope方式

```csharp
// 使用.NET原生的TransactionScope
using (var scope = new TransactionScope())
{
    db.Insertable(new Student { Name = "测试1", Age = 20 }).ExecuteCommand();
    db.Insertable(new Student { Name = "测试2", Age = 22 }).ExecuteCommand();

    scope.Complete();
}
```

### 4.3 异步TransactionScope

```csharp
// 异步TransactionScope需要指定AsyncFlowOption
using (var scope = new TransactionScope(TransactionScopeAsyncFlowOption.Enabled))
{
    await db.Insertable(new Student { Name = "异步测试", Age = 25 })
            .ExecuteCommandAsync();

    scope.Complete();
}
```

### 4.4 Using事务的优势

- **自动清理**：离开 `using` 块自动回滚未提交的事务
- **异常安全**：即使发生异常也能正确回滚
- **代码简洁**：不需要显式的 try-catch-finally

## 5. 事务隔离级别

### 5.1 隔离级别概述

事务隔离级别决定了一个事务能看到其他事务修改的数据程度。SQL 标准定义了四种隔离级别：

| 隔离级别 | 脏读 | 不可重复读 | 幻读 | 说明 |
|---------|------|-----------|------|------|
| ReadUncommitted | 可能 | 可能 | 可能 | 最低隔离，性能最高 |
| ReadCommitted | 不会 | 可能 | 可能 | 大多数数据库默认级别 |
| RepeatableRead | 不会 | 不会 | 可能 | MySQL默认级别 |
| Serializable | 不会 | 不会 | 不会 | 最高隔离，性能最低 |

### 5.2 并发问题解释

```
脏读（Dirty Read）：
  事务A修改了数据但未提交 → 事务B读取到了未提交的数据 → 事务A回滚 → 事务B读到的是无效数据

不可重复读（Non-Repeatable Read）：
  事务A第一次读取数据为X → 事务B修改数据为Y并提交 → 事务A第二次读取数据为Y → 同一事务内两次读取不一致

幻读（Phantom Read）：
  事务A查询得到10条记录 → 事务B插入1条新记录并提交 → 事务A再次查询得到11条记录 → 凭空多出一条记录
```

### 5.3 设置隔离级别

```csharp
// 使用BeginTran指定隔离级别
db.Ado.BeginTran(IsolationLevel.ReadCommitted);

try
{
    // 事务操作...
    db.Ado.CommitTran();
}
catch
{
    db.Ado.RollbackTran();
    throw;
}
```

### 5.4 不同场景的隔离级别选择

```csharp
// 场景1：报表查询（允许脏读，提高性能）
db.Ado.BeginTran(IsolationLevel.ReadUncommitted);
try
{
    var report = db.Queryable<Order>()
                   .GroupBy(o => o.Status)
                   .Select(o => new
                   {
                       Status = o.Status,
                       Count = SqlFunc.AggregateCount(o.Id),
                       TotalAmount = SqlFunc.AggregateSum(o.TotalAmount)
                   })
                   .ToList();
    db.Ado.CommitTran();
}
catch
{
    db.Ado.RollbackTran();
    throw;
}

// 场景2：金融交易（需要最高隔离级别）
db.Ado.BeginTran(IsolationLevel.Serializable);
try
{
    // 转账操作...
    db.Ado.CommitTran();
}
catch
{
    db.Ado.RollbackTran();
    throw;
}
```

### 5.5 隔离级别的性能影响

> **建议**：在大多数业务场景中使用默认的 `ReadCommitted` 隔离级别即可。只有在确实需要更高隔离性（如金融系统）或更高性能（如报表查询）时，才需要调整隔离级别。

## 6. 分布式事务

### 6.1 什么是分布式事务

当操作涉及多个数据库时，单机事务无法保证所有数据库的一致性，此时需要使用分布式事务。

```
单机事务：一个数据库内的多个操作
分布式事务：跨多个数据库的操作需要保证一致性
```

### 6.2 SqlSugar跨库事务

SqlSugar 通过 `TransactionScope` 支持跨库事务：

```csharp
// 创建多个数据库连接
var db1 = new SqlSugarClient(new ConnectionConfig
{
    ConnectionString = "Server=.;Database=DB1;...",
    DbType = DbType.SqlServer,
    IsAutoCloseConnection = true
});

var db2 = new SqlSugarClient(new ConnectionConfig
{
    ConnectionString = "Server=.;Database=DB2;...",
    DbType = DbType.SqlServer,
    IsAutoCloseConnection = true
});

// 跨库事务
using (var scope = new TransactionScope())
{
    // 操作数据库1
    db1.Insertable(new Order { OrderNo = "ORD001" }).ExecuteCommand();

    // 操作数据库2
    db2.Updateable<Inventory>()
       .SetColumns(i => i.Stock == i.Stock - 1)
       .Where(i => i.ProductId == 1)
       .ExecuteCommand();

    scope.Complete(); // 两个数据库操作要么同时成功，要么同时失败
}
```

### 6.3 多租户跨库事务

```csharp
// SqlSugarScope多租户模式的跨库事务
var db = new SqlSugarScope(new List<ConnectionConfig>
{
    new ConnectionConfig
    {
        ConfigId = "db1",
        ConnectionString = "Server=.;Database=DB1;...",
        DbType = DbType.SqlServer,
        IsAutoCloseConnection = true
    },
    new ConnectionConfig
    {
        ConfigId = "db2",
        ConnectionString = "Server=.;Database=DB2;...",
        DbType = DbType.SqlServer,
        IsAutoCloseConnection = true
    }
});

// 跨库事务
using (var scope = new TransactionScope())
{
    // 操作数据库1
    db.GetConnection("db1").Insertable(new Order { OrderNo = "ORD001" }).ExecuteCommand();

    // 操作数据库2
    db.GetConnection("db2").Insertable(new LogRecord { Message = "创建订单" }).ExecuteCommand();

    scope.Complete();
}
```

### 6.4 CAP模式（最终一致性）

在微服务架构中，强一致性的分布式事务代价很高，通常使用最终一致性方案：

```csharp
// 基于消息队列的最终一致性方案（伪代码）
public async Task CreateOrderAsync(OrderDto dto)
{
    // 本地事务
    var result = await db.UseTranAsync(async () =>
    {
        // 1. 创建订单
        var orderId = await db.Insertable(new Order
        {
            OrderNo = dto.OrderNo,
            TotalAmount = dto.TotalAmount,
            Status = "待处理"
        }).ExecuteReturnIdentityAsync();

        // 2. 记录消息（在同一事务中）
        await db.Insertable(new OutboxMessage
        {
            EventType = "OrderCreated",
            Payload = JsonSerializer.Serialize(new { OrderId = orderId }),
            Status = "待发送",
            CreateTime = DateTime.Now
        }).ExecuteCommandAsync();
    });

    // 事务提交后，后台任务发送消息到消息队列
    // 库存服务消费消息并扣减库存
}
```

### 6.5 分布式事务注意事项

> **重要提示**：
>
> 1. `TransactionScope` 需要 MSDTC（Microsoft Distributed Transaction Coordinator）服务
> 2. 不是所有数据库都支持分布式事务
> 3. 分布式事务性能开销较大，应尽量避免
> 4. 推荐在微服务架构中使用最终一致性方案代替强一致性事务

## 7. 工作单元UnitOfWork

### 7.1 什么是工作单元

工作单元（Unit of Work）是一种设计模式，它维护一组在事务中需要更改的对象列表，协调这些更改的持久化以及并发问题的处理。

```
工作单元模式的核心思想：
  → 将一次业务操作中的所有数据库操作收集起来
  → 在同一个事务中统一提交
  → 如果任何操作失败，统一回滚
```

### 7.2 SqlSugar的UnitOfWork

SqlSugar 内置了 `UnitOfWork` 支持：

```csharp
// 创建工作单元
var uow = db.CreateContext<UnitOfWork>();

try
{
    // 在工作单元中操作
    var studentRepository = uow.GetRepository<Student>();
    var classRepository = uow.GetRepository<Class>();

    studentRepository.Insert(new Student { Name = "张三", Age = 20, ClassId = 1 });
    classRepository.Update(c => c.StudentCount == c.StudentCount + 1, c => c.Id == 1);

    // 统一提交
    uow.Commit();
}
catch
{
    uow.Rollback();
    throw;
}
```

### 7.3 基础的UnitOfWork实现

```csharp
// 自定义UnitOfWork接口
public interface IUnitOfWork
{
    ISqlSugarClient GetDbClient();
    void BeginTran();
    void CommitTran();
    void RollbackTran();
}

// UnitOfWork实现
public class UnitOfWork : IUnitOfWork
{
    private readonly ISqlSugarClient _db;

    public UnitOfWork(ISqlSugarClient db)
    {
        _db = db;
    }

    public ISqlSugarClient GetDbClient()
    {
        return _db;
    }

    public void BeginTran()
    {
        _db.Ado.BeginTran();
    }

    public void CommitTran()
    {
        try
        {
            _db.Ado.CommitTran();
        }
        catch (Exception)
        {
            _db.Ado.RollbackTran();
            throw;
        }
    }

    public void RollbackTran()
    {
        _db.Ado.RollbackTran();
    }
}
```

### 7.4 Repository模式与UnitOfWork

```csharp
// 泛型仓储接口
public interface IRepository<T> where T : class, new()
{
    ISqlSugarClient DbContext { get; }
    int Insert(T entity);
    int Update(T entity);
    int Delete(int id);
    T GetById(int id);
    List<T> GetList();
}

// 泛型仓储实现
public class Repository<T> : IRepository<T> where T : class, new()
{
    private readonly IUnitOfWork _unitOfWork;

    public Repository(IUnitOfWork unitOfWork)
    {
        _unitOfWork = unitOfWork;
    }

    public ISqlSugarClient DbContext => _unitOfWork.GetDbClient();

    public int Insert(T entity)
    {
        return DbContext.Insertable(entity).ExecuteCommand();
    }

    public int Update(T entity)
    {
        return DbContext.Updateable(entity).ExecuteCommand();
    }

    public int Delete(int id)
    {
        return DbContext.Deleteable<T>().In(id).ExecuteCommand();
    }

    public T GetById(int id)
    {
        return DbContext.Queryable<T>().InSingle(id);
    }

    public List<T> GetList()
    {
        return DbContext.Queryable<T>().ToList();
    }
}
```

## 8. 依赖注入中的UnitOfWork

### 8.1 ASP.NET Core服务注册

```csharp
// Program.cs 或 Startup.cs
public static void ConfigureServices(IServiceCollection services)
{
    // 注册SqlSugarScope（单例，线程安全）
    services.AddSingleton<ISqlSugarClient>(provider =>
    {
        return new SqlSugarScope(new ConnectionConfig
        {
            ConnectionString = "Server=.;Database=TestDB;...",
            DbType = DbType.SqlServer,
            IsAutoCloseConnection = true
        });
    });

    // 注册UnitOfWork（Scoped，每个请求一个实例）
    services.AddScoped<IUnitOfWork, UnitOfWork>();

    // 注册泛型仓储
    services.AddScoped(typeof(IRepository<>), typeof(Repository<>));

    // 注册业务服务
    services.AddScoped<IOrderService, OrderService>();
}
```

### 8.2 服务层使用UnitOfWork

```csharp
public interface IOrderService
{
    Task<int> CreateOrderAsync(OrderDto dto);
}

public class OrderService : IOrderService
{
    private readonly IUnitOfWork _unitOfWork;
    private readonly IRepository<Order> _orderRepo;
    private readonly IRepository<OrderDetail> _detailRepo;
    private readonly IRepository<Product> _productRepo;

    public OrderService(
        IUnitOfWork unitOfWork,
        IRepository<Order> orderRepo,
        IRepository<OrderDetail> detailRepo,
        IRepository<Product> productRepo)
    {
        _unitOfWork = unitOfWork;
        _orderRepo = orderRepo;
        _detailRepo = detailRepo;
        _productRepo = productRepo;
    }

    public async Task<int> CreateOrderAsync(OrderDto dto)
    {
        try
        {
            _unitOfWork.BeginTran();

            // 1. 检查库存
            var product = _productRepo.GetById(dto.ProductId);
            if (product.Stock < dto.Quantity)
            {
                throw new Exception("库存不足");
            }

            // 2. 创建订单
            var order = new Order
            {
                OrderNo = $"ORD{DateTime.Now:yyyyMMddHHmmss}",
                TotalAmount = product.Price * dto.Quantity,
                Status = "待支付",
                CreateTime = DateTime.Now
            };
            var orderId = _orderRepo.Insert(order);

            // 3. 创建订单明细
            _detailRepo.Insert(new OrderDetail
            {
                OrderId = orderId,
                ProductName = product.Name,
                Quantity = dto.Quantity,
                Price = product.Price
            });

            // 4. 扣减库存
            _unitOfWork.GetDbClient().Updateable<Product>()
                .SetColumns(p => p.Stock == p.Stock - dto.Quantity)
                .Where(p => p.Id == dto.ProductId)
                .ExecuteCommand();

            _unitOfWork.CommitTran();
            return orderId;
        }
        catch
        {
            _unitOfWork.RollbackTran();
            throw;
        }
    }
}
```

### 8.3 Controller层调用

```csharp
[ApiController]
[Route("api/[controller]")]
public class OrderController : ControllerBase
{
    private readonly IOrderService _orderService;

    public OrderController(IOrderService orderService)
    {
        _orderService = orderService;
    }

    [HttpPost]
    public async Task<IActionResult> CreateOrder([FromBody] OrderDto dto)
    {
        try
        {
            var orderId = await _orderService.CreateOrderAsync(dto);
            return Ok(new { OrderId = orderId, Message = "订单创建成功" });
        }
        catch (Exception ex)
        {
            return BadRequest(new { Message = ex.Message });
        }
    }
}
```

### 8.4 使用AOP自动管理事务

```csharp
// 定义事务特性
[AttributeUsage(AttributeTargets.Method)]
public class TransactionalAttribute : Attribute
{
    public IsolationLevel IsolationLevel { get; set; } = IsolationLevel.ReadCommitted;
}

// AOP拦截器（使用Autofac或其他IoC框架）
public class TransactionInterceptor : IInterceptor
{
    private readonly IUnitOfWork _unitOfWork;

    public TransactionInterceptor(IUnitOfWork unitOfWork)
    {
        _unitOfWork = unitOfWork;
    }

    public void Intercept(IInvocation invocation)
    {
        var attribute = invocation.Method.GetCustomAttribute<TransactionalAttribute>();
        if (attribute == null)
        {
            invocation.Proceed();
            return;
        }

        _unitOfWork.BeginTran();
        try
        {
            invocation.Proceed();
            _unitOfWork.CommitTran();
        }
        catch
        {
            _unitOfWork.RollbackTran();
            throw;
        }
    }
}

// 使用事务特性标注方法
public class OrderService : IOrderService
{
    [Transactional]
    public virtual async Task<int> CreateOrderAsync(OrderDto dto)
    {
        // 不再需要手动管理事务
        // 方法执行成功自动提交，异常自动回滚
        // ...
    }
}
```

## 9. 多租户事务

### 9.1 多租户架构概述

在多租户系统中，不同租户可能使用不同的数据库。SqlSugar 通过 `SqlSugarScope` 支持多租户，并提供了跨租户的事务管理。

```csharp
    {
        ConfigId = "tenant2",
        ConnectionString = "Server=.;Database=Tenant2DB;...",
        DbType = DbType.SqlServer,

```

### 9.3 同一租户内事务

```csharp

try
{
    tenantDb.Ado.BeginTran();
```

### 9.5 多租户事务注意事项

> **注意**：
>
> - 跨租户事务依赖 `TransactionScope`，需要确保 MSDTC 服务可用
> - 尽量减少跨租户事务的使用，优先考虑最终一致性方案
> - 不同类型的数据库（如 MySQL 和 SQL Server 混合）可能不支持跨库事务

## 10. 嵌套事务

### 10.1 嵌套事务的概念

嵌套事务指的是在一个事务内部再开启另一个事务。SqlSugar 支持嵌套事务，但需要注意其行为特点。

### 10.2 SqlSugar的嵌套事务行为

```csharp
// SqlSugar嵌套事务使用SavePoint实现
db.Ado.BeginTran(); // 外层事务

try
{
    db.Insertable(new Student { Name = "外层数据" }).ExecuteCommand();

    // 内层事务
    db.Ado.BeginTran(); // 创建SavePoint
    try
    {
        db.Insertable(new Student { Name = "内层数据" }).ExecuteCommand();
        db.Ado.CommitTran(); // 释放SavePoint
    }
    catch
    {
        db.Ado.RollbackTran(); // 回滚到SavePoint
    }

    db.Ado.CommitTran(); // 提交外层事务
}
catch
{
    db.Ado.RollbackTran(); // 回滚整个事务
}
```

### 10.3 在服务层中的嵌套事务

```csharp
public class OrderService
{
    private readonly ISqlSugarClient _db;
    private readonly InventoryService _inventoryService;

    public void CreateOrder(OrderDto dto)
    {
        try
        {
            _db.Ado.BeginTran(); // 外层事务

            // 创建订单
            _db.Insertable(new Order { OrderNo = dto.OrderNo }).ExecuteCommand();

            // 调用库存服务（内部也可能有事务）
            _inventoryService.DeductStock(dto.ProductId, dto.Quantity);

            _db.Ado.CommitTran();
        }
        catch
        {
            _db.Ado.RollbackTran();
            throw;
        }
    }
}

public class InventoryService
{
    private readonly ISqlSugarClient _db;

    public void DeductStock(int productId, int quantity)
    {
        // 这里不再开启新事务，复用外层事务
        // 因为SqlSugarScope在同一线程/请求中共享连接
        _db.Updateable<Product>()
           .SetColumns(p => p.Stock == p.Stock - quantity)
           .Where(p => p.Id == productId && p.Stock >= quantity)
           .ExecuteCommand();
    }
}
```

### 10.4 嵌套事务最佳实践

> **建议**：
>
> 1. 避免过深的嵌套事务，通常不超过2层
> 2. 在分层架构中，事务管理应放在服务层的最外层
> 3. 使用 `UnitOfWork` 模式统一管理事务，避免各服务层各自管理事务
> 4. 如果使用 `SqlSugarScope`，同一请求中的操作自动共享数据库连接

## 11. 事务中的错误处理

### 11.1 异常类型

在事务操作中，可能遇到多种类型的异常：

| 异常类型 | 说明 | 处理方式 |
|---------|------|---------|
| 数据库连接异常 | 连接断开、超时 | 重试或报错 |
| 死锁异常 | 多事务互相等待 | 重试 |
| 数据约束异常 | 唯一键冲突、外键约束 | 业务提示 |
| 业务逻辑异常 | 库存不足、余额不够 | 回滚+业务提示 |
| 超时异常 | 事务执行时间过长 | 优化SQL或分步执行 |

### 11.2 完善的错误处理

```csharp
public async Task<Result<int>> CreateOrderWithRetryAsync(OrderDto dto, int maxRetries = 3)
{
    int retryCount = 0;

    while (retryCount < maxRetries)
    {
        try
        {
            var result = await db.UseTranAsync(async () =>
            {
                // 检查库存
                var product = await db.Queryable<Product>()
                                     .Where(p => p.Id == dto.ProductId)
                                     .FirstAsync();

                if (product == null)
                    throw new BusinessException("商品不存在");

                if (product.Stock < dto.Quantity)
                    throw new BusinessException("库存不足");

                // 创建订单
                var orderId = await db.Insertable(new Order
                {
                    OrderNo = $"ORD{DateTime.Now:yyyyMMddHHmmss}",
                    TotalAmount = product.Price * dto.Quantity,
                    CreateTime = DateTime.Now
                }).ExecuteReturnIdentityAsync();

                // 扣减库存
                var affectedRows = await db.Updateable<Product>()
                    .SetColumns(p => p.Stock == p.Stock - dto.Quantity)
                    .Where(p => p.Id == dto.ProductId && p.Stock >= dto.Quantity)
                    .ExecuteCommandAsync();

                if (affectedRows == 0)
                    throw new BusinessException("库存扣减失败，可能已被其他订单占用");

                return orderId;
            });

            if (result.IsSuccess)
            {
                return Result<int>.Success(result.Data);
            }
            else
            {
                throw result.ErrorException;
            }
        }
        catch (BusinessException)
        {
            throw; // 业务异常不重试
        }
        catch (Exception ex) when (IsDeadlockException(ex))
        {
            retryCount++;
            if (retryCount >= maxRetries)
                throw;

            // 死锁异常等待后重试
            await Task.Delay(100 * retryCount);
        }
    }

    throw new Exception("操作失败，已达到最大重试次数");
}

private bool IsDeadlockException(Exception ex)
{
    return ex.Message.Contains("deadlock") ||
           ex.Message.Contains("死锁");
}
```

## 12. 最佳实践

### 12.1 事务使用原则

| 原则 | 说明 |
|------|------|
| 保持事务简短 | 事务持续时间越长，锁定资源越多 |
| 减少事务中的操作 | 只将必须原子化的操作放在事务中 |
| 避免用户交互 | 不要在事务中等待用户输入 |
| 正确处理异常 | 确保任何异常都能正确回滚 |
| 避免嵌套过深 | 嵌套不超过2层 |
| 选择合适的隔离级别 | 默认使用ReadCommitted即可 |

### 12.2 事务方式选择指南

```
简单的CRUD操作 → UseTran（自动管理）
复杂的业务逻辑 → BeginTran/CommitTran/RollbackTran（手动控制）
分层架构        → UnitOfWork（统一管理）
跨库操作        → TransactionScope（分布式事务）
微服务架构      → 最终一致性方案（消息队列）
```

### 12.3 常见的事务错误

```csharp
// ❌ 错误1：事务中做耗时操作
db.Ado.BeginTran();
Thread.Sleep(10000); // 长时间占用事务
db.Ado.CommitTran();

// ❌ 错误2：忘记回滚
try
{
    db.Ado.BeginTran();
    // ... 操作 ...
    db.Ado.CommitTran();
}
catch
{
    // 忘记了 RollbackTran()！事务会一直挂着
    throw;
}

// ❌ 错误3：事务中调用外部API
db.Ado.BeginTran();
var result = await httpClient.PostAsync("...", content); // 外部调用可能超时
db.Ado.CommitTran();

// ✅ 正确做法：先调用外部API，再在事务中操作数据库
var apiResult = await httpClient.PostAsync("...", content);
if (apiResult.IsSuccessStatusCode)
{
    db.Ado.BeginTran();
    try
    {
        // 数据库操作
        db.Ado.CommitTran();
    }
    catch
    {
        db.Ado.RollbackTran();
        throw;
    }
}
```

### 12.4 事务监控

```csharp
// 监控事务执行时间
var stopwatch = new Stopwatch();

db.Aop.OnLogExecuting = (sql, pars) =>
{
    if (sql.Contains("BEGIN TRAN") || sql.Contains("BEGIN TRANSACTION"))
    {
        stopwatch.Restart();
        Console.WriteLine("[事务开始]");

        if (elapsed > 5000)

            Console.WriteLine($"[警告] 事务执行时间过长: {elapsed}ms");
        }
    }
};
```
