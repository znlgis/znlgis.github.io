# 第十四章：事件处理与交互

前面各章的功能都是「代码主动调用」，这一章反过来：用户在表格上点击、输入、选择、按键，控件把动作变成事件抛出来，程序在事件里做响应。事件是做交互逻辑的入口，也是限制用户行为的关口。

ReoGrid 的事件分几层。单元格层的事件关心单个格子的数据与编辑状态，选择层的事件关心焦点和区域，工作表层的事件关心结构变化，输入层的事件关心鼠标键盘。层的划分对应事件的触发时机，选对层才能在对的时机拿到需要的数据。

订阅事件时注意生命周期：窗体或页面关闭时要取消订阅，否则事件处理器持有对象引用，可能造成内存泄漏，或者在对象已销毁后仍被回调。

## 14.1 单元格事件

单元格事件有三个常用成员。CellDataChanged 在数据变化后触发，处理器里能拿到发生变化的单元格，适合做联动计算、日志记录、脏数据标记。

BeforeCellEdit 在进入编辑状态之前触发，事件参数带一个取消标志，把它设为 true 就能阻止这次编辑。示例用它禁止编辑第一行，做法是判断行号后取消。这条路径适合做只读区、锁定表头、按权限控制可编辑范围。

CellEdit 在编辑过程中触发，用来感知「用户正在改哪个格子」。三个事件的时机不同，不要混用：要在写入前拦截用 BeforeCellEdit，要在写入后处理用 CellDataChanged。

```csharp
using unvell.ReoGrid.Events;

public class CellEvents
{
    public void RegisterCellEvents(Worksheet sheet)
    {
        // 单元格数据变化
        sheet.CellDataChanged += (s, e) =>
        {
            Console.WriteLine($"单元格 {e.Cell.Address} 数据已更改为: {e.Cell.Data}");
        };
        
        // 单元格编辑前
        sheet.BeforeCellEdit += (s, e) =>
        {
            // 可以阻止编辑
            if (e.Cell.Row == 0)
            {
                e.IsCancelled = true;  // 禁止编辑第一行
            }
        };
        
        // 单元格编辑中
        sheet.CellEdit += (s, e) =>
        {
            Console.WriteLine("正在编辑单元格: " + e.Cell.Address);
        };
    }
}
```

CellDataChanged 在批量导入时会触发很多次。处理器里如果做数据库写入、界面刷新这类重活，导入会慢到无法接受。处理办法是：批量操作期间只记录变化的范围，操作结束后处理一次；或者用一个标志位表明「正在导入」，处理器直接返回。

事件里的单元格对象不保证长期有效。行列插入删除之后，原来的 Cell 引用可能指向别的位置，需要在处理器里先用地址重新取单元格，不要缓存 Cell 实例。

取消编辑之后，用户看到的可能是输入框一闪而过。体验上不如直接把单元格设成只读，或者在进入编辑前给出提示。

## 14.2 选择事件

SelectionRangeChanged 在选区变化时触发，事件参数里带新的区域。适合做「选中某块区域后显示统计」「选区变化刷新工具栏状态」这类联动。

FocusPosChanged 在焦点单元格移动时触发。焦点单元格是当前可以输入的那一格，与选区可以不同：选区是一块区域，焦点是其中的活动格。编辑相关的逻辑通常关心焦点，批量操作关心选区。

键盘导航时这两个事件会连续触发。按住方向键移动选区，事件按格触发，处理器里不要做重计算，否则移动会明显卡顿。

```csharp
public class SelectionEvents
{
    public void RegisterSelectionEvents(Worksheet sheet)
    {
        // 选择区域变化
        sheet.SelectionRangeChanged += (s, e) =>
        {
            Console.WriteLine($"选择区域: {e.Range}");
        };
        
        // 焦点单元格变化
        sheet.FocusPosChanged += (s, e) =>
        {
            Console.WriteLine($"焦点移至: {e.Position}");
        };
    }
}
```

选区变化时重新计算统计值，要限制范围。用户全选整表时区域可能覆盖上百万个空单元格，遍历求和会卡住界面。先判断区域的行列数，超过阈值就跳过或只统计有数据的部分。

选择事件和编辑事件可能嵌套触发。例如在 SelectionRangeChanged 里设置单元格的值，会引发 CellDataChanged，处理器里再改选区又会回到选择事件。写联动逻辑时加一个「处理中」标志，避免无限递归。

保存当前焦点位置，用于「离开再回来」的场景。切走页面时记下焦点格，回来时恢复，用户不会丢失正在编辑的位置。

## 14.3 工作表事件

结构事件在插入、删除行列时触发，事件参数里有起始位置和数量。示例订阅了行插入、行删除、列插入三个事件，用来记录表格结构的变化。

这类事件适合维护依赖行号的辅助数据：序号列、汇总公式、外部索引表。行插入后序号要重排，行删除后汇总范围要收缩，放在结构事件里统一处理，比在每个调用点手工维护更可靠。

结构事件是「动作完成之后」的通知，不是「即将发生」的拦截点。需要在删除前做校验（例如「这行有数据，确定删除吗」），应在调用删除的代码里判断，事件里已经来不及阻止。

```csharp
public class WorksheetEvents
{
    public void RegisterWorksheetEvents(Worksheet sheet)
    {
        // 行插入
        sheet.RowsInserted += (s, e) =>
        {
            Console.WriteLine($"插入了 {e.Count} 行，起始行: {e.Index}");
        };
        
        // 行删除
        sheet.RowsDeleted += (s, e) =>
        {
            Console.WriteLine($"删除了 {e.Count} 行");
        };
        
        // 列插入
        sheet.ColumnsInserted += (s, e) =>
        {
            Console.WriteLine($"插入了 {e.Count} 列");
        };
    }
}
```

结构事件与撤销重做会一起触发。用户按 Ctrl+Z 撤销一次插入，事件同样会抛出来，处理器如果只按「插入」处理，数据会被重复调整。判断事件来源是否可靠，取决于版本是否提供相关标志；没有标志时，把维护逻辑做成幂等的（重复执行结果一致）更稳妥。

批量插入行会产生大量结构事件。处理器里做重活同样会拖慢操作，必要时用标志位合并处理。

事件订阅数量要控制。每个订阅都是一个委托，同一处理器重复订阅会执行多次，界面上的表现是「一次操作触发两遍」。订阅前先取消一次，或者用带命名的方法订阅，便于排查。

## 14.4 鼠标和键盘事件

鼠标与键盘事件挂在控件层，而不是工作表。CellMouseDown 在单元格上按下鼠标时触发，事件参数里带单元格位置，适合做自定义菜单、双击进入特殊编辑、点击图标列执行动作。

CellKeyDown 在单元格获得焦点时接收按键。示例判断是否为 Delete 键，可以在这里拦下删除、替换成自定义行为，或者做快捷键。是否能在控件层拦下按键，取决于事件参数是否提供取消入口。

鼠标键盘事件触发频繁，处理器要短。鼠标移动、按键连发这类事件每秒可能几十次，做重活会直接表现为卡顿。需要基于这些事件做耗时操作时，加节流或改为异步。

```csharp
public class InputEvents
{
    public void RegisterInputEvents(ReoGridControl grid)
    {
        // 鼠标点击
        grid.CellMouseDown += (s, e) =>
        {
            Console.WriteLine($"鼠标点击: {e.CellPosition}");
        };
        
        // 键盘按下
        grid.CellKeyDown += (s, e) =>
        {
            if (e.KeyCode == Keys.Delete)
            {
                Console.WriteLine("按下删除键");
            }
        };
    }
}
```

自定义交互的边界要清楚。点击表头排序、点击图标列执行动作，这类需求和单元格编辑冲突：鼠标落在单元格上会先进入编辑。想避开默认行为，需要在按下事件里拦截，或者把可点击元素做成单元格类型（第十五章的内容），由类型自己处理点击。

键盘事件里处理快捷键时，注意不要和控件内建的编辑键冲突。方向键、回车、Tab 在编辑状态下有自己的语义，拦截之前先确认当前是否处于编辑模式。

## 14.5 本章小结

本章介绍了ReoGrid的事件处理机制。

四层事件按关注点划分：

- 单元格层：数据变化、编辑前、编辑中，处理值与编辑权限；
- 选择层：选区与焦点，处理联动展示；
- 工作表层：插入删除等结构变化，处理依赖行号的数据；
- 输入层：鼠标与键盘，处理自定义交互。

事件代码有三条纪律：处理器要短、处理要幂等、订阅要成对。前者保证界面流畅，中者避免撤销重做带来的重复执行，后者防止内存泄漏和重复回调。

调试事件时，最有效的手段是打日志而不是打断点。事件触发频繁，断点会不断停下，日志能看清触发顺序和参数，反而更快定位问题。
