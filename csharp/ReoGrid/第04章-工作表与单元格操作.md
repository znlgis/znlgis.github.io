# 第四章：工作表与单元格操作

工作表（Worksheet）是 ReoGrid 里所有读写操作的落点。控件负责窗口、滚动条与输入法，真正保存数据、样式、合并信息与公式的是一个个 Worksheet 对象，因此本章的示例统一切到工作表这一层来写，控件只作为获取工作表的入口。

示例里的 Worksheet 从构造函数注入，这和实际项目的做法一致：把 sheets 引用保存在窗体或服务类里，比每次操作都重新读取 grid.CurrentWorksheet 更可靠。CurrentWorksheet 表示用户当前激活的那张表，切换标签页时会变，在长流程里反复读取它，容易把数据写到别的表上。

ReoGrid 提供两套单元格地址：A1 这种字母加数字的地址，以及以 0 开始的行列索引。两套地址可以互转（CellPosition 与 RangePosition 都同时保存行列号），但混用时要注意行列顺序，本章第一节会专门说明这一点。

## 4.1 单元格数据读写

### 4.1.1 基本读写操作

单元格读写有三套入口：索引器、SetCellData / GetCellData，以及先取 Cell 对象再访问成员。三套入口操作的是同一份存储，区别在参数形态：字符串地址适合写死在配置和示例里，行列索引适合循环，CellPosition 与 RangePosition 适合在方法之间传递位置。

写数据时最容易出错的是索引顺序。sheet[0, 1] 的两个参数是「行号, 列号」，且都从 0 开始，所以它指向 B1，而不是 A2。如果把它当成 A2，后续每一个单元格都会错开一行，而且代码不会报错，只是数据落在错误的位置。初学阶段建议先在一个空表上写入几行数据，用地址读回来核对一遍，确认自己的理解再继续。

索引器和 SetCellData 都会按值的实际装箱类型存储数据，传字符串 "123.45" 进去，单元格里就是文本，不会自动变成数字；方式 5 显式带上 CellDataFormatFlag.Number，才能让后面按数字格式显示。

```csharp
using unvell.ReoGrid;

public class CellBasicOperations
{
    private Worksheet sheet;
    
    public CellBasicOperations(ReoGridControl grid)
    {
        sheet = grid.CurrentWorksheet;
    }
    
    /// <summary>
    /// 写入数据的多种方式
    /// </summary>
    public void WriteDataExamples()
    {
        // 方式1：使用字符串地址
        sheet["A1"] = "Hello ReoGrid";
        
        // 方式2：使用数字索引 [row, col]
        sheet[0, 1] = 12345;
        
        // 方式3：使用CellPosition
        sheet.SetCellData(new CellPosition("C1"), DateTime.Now);
        
        // 方式4：使用行列索引
        sheet.SetCellData(0, 3, true);
        
        // 方式5：指定数据格式
        sheet.SetCellData(0, 4, "123.45", CellDataFormatFlag.Number);
    }
    
    /// <summary>
    /// 读取数据的多种方式
    /// </summary>
    public void ReadDataExamples()
    {
        // 方式1：使用字符串地址
        object value1 = sheet["A1"];
        
        // 方式2：使用数字索引
        object value2 = sheet[0, 1];
        
        // 方式3：使用GetCellData
        object value3 = sheet.GetCellData(0, 2);
        
        // 方式4：获取Cell对象
        var cell = sheet.GetCell(0, 3);
        if (cell != null)
        {
            object data = cell.Data;
            string text = cell.DisplayText;
        }
    }
}
```

读取部分演示了两条路径。索引器和 GetCellData 返回 object，拿到的就是写入时的对象，可能为 null；GetCell 返回 Cell 对象，可以通过 Cell.Data 取原始值，通过 Cell.DisplayText 取按当前格式渲染后的文本。这两个成员的区别在数据显示上：Data 是 double 就是 double，DisplayText 是给用户看的字符串，可能带千分位、货币符号或日期格式。要参与计算用 Data，要导出成文本或写进日志用 DisplayText。

访问 cell 之前要先判空。没有被编辑过的单元格可能返回 null，也可能返回一个 Data 为 null 的实例，直接取 cell.Data 会抛空引用异常，加一层判空最省事。

另外注意，索引器的返回值类型是 object，做数值运算前需要显式转换。写成 sheet["A1"] + 1 是编译不过的，必须先转成 double 或 int，转换失败时用 TryParse 做保护。

### 4.1.2 类型转换与处理

单元格内部按 object 保存数据，写进去是什么类型，读出来就是什么类型。GetStringValue 用 ?. 和 ?? 兜底，避免空单元格导致异常；GetNumericValue 先用 ToString 再 TryParse，好处是兼容文本型和数值型两种来源，代价是每次都要分配一个字符串。

GetDateTimeValue 和 GetBooleanValue 用 is 做类型判断，比按文本解析可靠：DateTime 和 bool 在装箱后类型信息是完整的，直接判断即可，不需要再猜格式。需要区分的是，如果单元格里是字符串 "2024-01-01"，is DateTime 会返回 false，这时应先用 DateTime.TryParse 转换，并按业务决定是否接受这种宽松写法。

```csharp
using System;
using unvell.ReoGrid;

public class CellDataTypeOperations
{
    private Worksheet sheet;
    
    public CellDataTypeOperations(Worksheet worksheet)
    {
        sheet = worksheet;
    }
    
    /// <summary>
    /// 获取字符串类型数据
    /// </summary>
    public string GetStringValue(string address)
    {
        var cell = sheet.GetCell(new CellPosition(address));
        return cell?.Data?.ToString() ?? string.Empty;
    }
    
    /// <summary>
    /// 获取数值类型数据
    /// </summary>
    public double? GetNumericValue(string address)
    {
        var cell = sheet.GetCell(new CellPosition(address));
        if (cell != null && cell.Data != null)
        {
            if (double.TryParse(cell.Data.ToString(), out double result))
            {
                return result;
            }
        }
        return null;
    }
    
    /// <summary>
    /// 获取日期类型数据
    /// </summary>
    public DateTime? GetDateTimeValue(string address)
    {
        var cell = sheet.GetCell(new CellPosition(address));
        if (cell != null && cell.Data is DateTime dt)
        {
            return dt;
        }
        return null;
    }
    
    /// <summary>
    /// 获取布尔类型数据
    /// </summary>
    public bool? GetBooleanValue(string address)
    {
        var cell = sheet.GetCell(new CellPosition(address));
        if (cell != null && cell.Data is bool b)
        {
            return b;
        }
        return null;
    }
}
```

数值解析要留意区域设置。double.TryParse 不带参数时使用当前线程的区域文化，在中文系统上小数点解析通常没问题，但数据来自其他机器或文本文件时，千分位和小数点可能按不同规则解释。对外部数据统一用 CultureInfo.InvariantCulture 解析，可以避免同一份文件在两种环境上算出不同结果。

直接强转也是常见错误：写成 (double)cell.Data，而存储的其实是 int，装箱拆箱会抛 InvalidCastException。统一走 Convert.ToDouble 或先 is 判断再转换，能把这类问题挡在业务代码之外。返回值用可空类型（double?、DateTime?）表达"单元格里没有可用值"，调用方可以据此决定是报错、跳过还是填默认值。

### 4.1.3 批量数据操作

逐格写入在演示里最直观，但数据量大时性能会成问题，原因在重绘与布局计算：每次赋值都可能触发一次单元格失效与区域重算。示例代码为了突出读写本身没有加批量包裹，实际项目里应把整个循环放进 BeginUpdate / EndUpdate 之间，具体做法见第十七章。

WriteBatch2DArray 接收 object[,]，注意二维数组的维度顺序是 [行, 列]，与工作表的索引顺序一致。数组的起点由 startRow 与 startCol 决定，这样一个方法就能把数据写到表格的任意位置，常用于把 DataTable 或查询结果贴到指定区域。

```csharp
using System.Collections.Generic;
using unvell.ReoGrid;

public class BatchDataOperations
{
    private Worksheet sheet;
    
    public BatchDataOperations(Worksheet worksheet)
    {
        sheet = worksheet;
    }
    
    /// <summary>
    /// 批量写入二维数组数据
    /// </summary>
    public void WriteBatch2DArray(int startRow, int startCol, object[,] data)
    {
        int rows = data.GetLength(0);
        int cols = data.GetLength(1);
        
        for (int r = 0; r < rows; r++)
        {
            for (int c = 0; c < cols; c++)
            {
                sheet[startRow + r, startCol + c] = data[r, c];
            }
        }
    }
    
    /// <summary>
    /// 批量写入列表数据
    /// </summary>
    public void WriteListData<T>(int startRow, int startCol, List<T> dataList)
    {
        var properties = typeof(T).GetProperties();
        
        // 写入表头
        for (int i = 0; i < properties.Length; i++)
        {
            sheet[startRow, startCol + i] = properties[i].Name;
        }
        
        // 写入数据
        for (int row = 0; row < dataList.Count; row++)
        {
            var item = dataList[row];
            for (int col = 0; col < properties.Length; col++)
            {
                var value = properties[col].GetValue(item);
                sheet[startRow + row + 1, startCol + col] = value;
            }
        }
    }
    
    /// <summary>
    /// 批量读取区域数据
    /// </summary>
    public object[,] ReadRangeData(string range)
    {
        var rangePos = new RangePosition(range);
        object[,] data = new object[rangePos.Rows, rangePos.Cols];
        
        for (int r = 0; r < rangePos.Rows; r++)
        {
            for (int c = 0; c < rangePos.Cols; c++)
            {
                data[r, c] = sheet[rangePos.Row + r, rangePos.Col + c];
            }
        }
        
        return data;
    }
    
    /// <summary>
    /// 从对象列表读取数据
    /// </summary>
    public List<T> ReadToList<T>(int startRow, int startCol, int rowCount) where T : new()
    {
        var list = new List<T>();
        var properties = typeof(T).GetProperties();
        
        for (int r = 0; r < rowCount; r++)
        {
            var item = new T();
            for (int c = 0; c < properties.Length; c++)
            {
                var cell = sheet.GetCell(startRow + r, startCol + c);
                if (cell != null)
                {
                    var prop = properties[c];
                    object value = Convert.ChangeType(cell.Data, prop.PropertyType);
                    prop.SetValue(item, value);
                }
            }
            list.Add(item);
        }
        
        return list;
    }
}
```

WriteListData 是反射写入的典型写法：先用属性名做表头，再从第二行开始逐行填值。它省去了手写列映射，代价是反射调用本身有开销，属性很多时建议缓存 PropertyInfo 数组，或者干脆改成显式的列映射。另外 typeof(T).GetProperties() 返回顺序在运行时不保证与源码声明顺序一致，依赖表头顺序的场景应显式指定属性名数组，不要依赖反射顺序。

ReadToList 用 Convert.ChangeType 做类型转换，遇到 null 或 DBNull 会抛异常。读取前要判断 cell 与 cell.Data，空值要么跳过，要么按属性类型给默认值，不要直接交给 ChangeType。读区域时用 RangePosition 的 Rows、Cols 计算尺寸，Row、Col 是起点坐标，两个概念不要混用。

## 4.2 数据格式化

### 4.2.1 内置格式

数据格式化改的是显示方式，不是存储的数据。单元格里存 0.25，设成百分比格式后显示 25%，Data 读出来仍是 0.25；把这一格参与计算，用的也是 0.25。理解这一点，可以避免「设了格式为什么公式算错」这类问题。

SetRangeDataFormat 的第二个参数是格式类别。Number 是通用数值，可以带千分位和小数位；Currency 会加货币符号；Percent 把小数按百分比显示；DateTime 按日期时间显示；Text 按文本处理，不做数值解释。不同类别对应不同的格式参数对象，示例中时间格式就是给 DateTime 类别传了 DateTimeFormatArgs，并把 Format 指定为 HH:mm:ss（24 小时制，带秒）。

```csharp
using unvell.ReoGrid;
using unvell.ReoGrid.Data;

public class DataFormatting
{
    private Worksheet sheet;
    
    public DataFormatting(Worksheet worksheet)
    {
        sheet = worksheet;
    }
    
    /// <summary>
    /// 设置数字格式
    /// </summary>
    public void SetNumberFormat(string range)
    {
        sheet.SetRangeDataFormat(range, CellDataFormatFlag.Number);
    }
    
    /// <summary>
    /// 设置货币格式
    /// </summary>
    public void SetCurrencyFormat(string range)
    {
        sheet.SetRangeDataFormat(range, CellDataFormatFlag.Currency);
    }
    
    /// <summary>
    /// 设置百分比格式
    /// </summary>
    public void SetPercentFormat(string range)
    {
        sheet.SetRangeDataFormat(range, CellDataFormatFlag.Percent);
    }
    
    /// <summary>
    /// 设置日期格式
    /// </summary>
    public void SetDateFormat(string range)
    {
        sheet.SetRangeDataFormat(range, CellDataFormatFlag.DateTime);
    }
    
    /// <summary>
    /// 设置时间格式
    /// </summary>
    public void SetTimeFormat(string range)
    {
        sheet.SetRangeDataFormat(range, CellDataFormatFlag.DateTime, 
            new DateTimeDataFormatter.DateTimeFormatArgs
            {
                Format = "HH:mm:ss"
            });
    }
}
```

格式参数只影响该类别的显示细节，不会改变数据类型。设置日期格式前，单元格里最好已经是 DateTime 或能被识别为日期的值；如果是普通字符串，多数情况下会原样显示，日期格式不生效。

百分比有一处容易踩坑：值本身应当是小数。把 25 存进单元格再设百分比格式，界面显示的是 2500%，因为 25 被当成 2500%。要么存 0.25，要么在存之前除以 100，两件事只能做一次。

### 4.2.2 自定义格式

内置类别够用的时候不必自定义。需要固定小数位、固定分隔风格或统一日期写法时，才用自定义格式串。示例中的 "#,##0.00" 可以逐段拆开看：井号表示这一位有值就显示、没有就留空，0 表示没有值也补 0，逗号是千分位分隔，点号后的小数位固定两位。

电话号码那一段用 Text 类别加 Pattern，作用是把输入的数字按模板排版成 (000) 000-0000 的样子。它只负责显示，不阻止用户输入字母；输入校验是第八章数据验证的职责，两者解决的不是同一个问题。

```csharp
using unvell.ReoGrid;
using unvell.ReoGrid.Data;

public class CustomFormatting
{
    private Worksheet sheet;
    
    public CustomFormatting(Worksheet worksheet)
    {
        sheet = worksheet;
    }
    
    /// <summary>
    /// 自定义数字格式
    /// </summary>
    public void SetCustomNumberFormat(string range, string pattern)
    {
        // 例如: "#,##0.00" 表示千位分隔符和两位小数
        sheet.SetRangeDataFormat(range, CellDataFormatFlag.Number,
            new NumberDataFormatter.NumberFormatArgs
            {
                Pattern = pattern
            });
    }
    
    /// <summary>
    /// 自定义日期格式
    /// </summary>
    public void SetCustomDateFormat(string range, string format)
    {
        // 例如: "yyyy-MM-dd HH:mm:ss"
        sheet.SetRangeDataFormat(range, CellDataFormatFlag.DateTime,
            new DateTimeDataFormatter.DateTimeFormatArgs
            {
                Format = format
            });
    }
    
    /// <summary>
    /// 电话号码格式
    /// </summary>
    public void SetPhoneFormat(string range)
    {
        sheet.SetRangeDataFormat(range, CellDataFormatFlag.Text,
            new TextDataFormatter.FormatArgs
            {
                Pattern = "(000) 000-0000"
            });
    }
}
```

自定义格式串的支持范围与版本有关。示例里的 Pattern 参数在部分版本中用于数字格式化器，部分版本要求改用 DecimalPlaces、UseSeparator 这类分项参数；如果设置了没有效果，先确认当前版本支持哪种写法，再决定是否改成分项配置。

日期格式串用的是 .NET 的自定义格式：yyyy 是四位年，MM 是两位月，dd 是两位日，HH 是 24 小时制的小时，mm 是分钟。月和分的写法都写作 m，大小写不能写错，写反了显示结果会差几个小时。

格式设置本身很轻，但作用在大区域上会触发一次区域重绘。批量设置时把它放进 BeginUpdate 块里，最后统一刷新一次即可。

## 4.3 单元格样式

### 4.3.1 字体样式

ReoGrid 的样式对象由两部分组成：Flag 位掩码和属性值。Flag 用按位或组合出「这次要改哪些属性」，只有出现在 Flag 里的属性才会被写入，其余属性保持原样。这是控件样式 API 的核心约定，也是设置不生效最常见的原因——比如只写了 Bold = true 却没把 PlainStyleFlag.FontBold 加进 Flag，粗体不会出现，代码也不报错。

字体颜色使用 System.Drawing.Color，不是 WPF 的 Color；字号以磅为单位。字体名写成系统中不存在的名称时，通常会回退到默认字体，字形与设计稿对不上，跨机器部署时要提前确认目标机装了哪些字体。

```csharp
using System.Drawing;
using unvell.ReoGrid.Data;

public class FontStyling
{
    private Worksheet sheet;
    
    public FontStyling(Worksheet worksheet)
    {
        sheet = worksheet;
    }
    
    /// <summary>
    /// 设置字体基本属性
    /// </summary>
    public void SetFontStyle(string range)
    {
        sheet.SetRangeStyles(range, new WorksheetRangeStyle
        {
            Flag = PlainStyleFlag.FontName | 
                   PlainStyleFlag.FontSize | 
                   PlainStyleFlag.FontColor,
            FontName = "微软雅黑",
            FontSize = 12,
            FontColor = Color.Blue
        });
    }
    
    /// <summary>
    /// 设置粗体
    /// </summary>
    public void SetBold(string range, bool bold = true)
    {
        sheet.SetRangeStyles(range, new WorksheetRangeStyle
        {
            Flag = PlainStyleFlag.FontBold,
            Bold = bold
        });
    }
    
    /// <summary>
    /// 设置斜体
    /// </summary>
    public void SetItalic(string range, bool italic = true)
    {
        sheet.SetRangeStyles(range, new WorksheetRangeStyle
        {
            Flag = PlainStyleFlag.FontItalic,
            Italic = italic
        });
    }
    
    /// <summary>
    /// 设置下划线
    /// </summary>
    public void SetUnderline(string range, bool underline = true)
    {
        sheet.SetRangeStyles(range, new WorksheetRangeStyle
        {
            Flag = PlainStyleFlag.FontUnderline,
            Underline = underline
        });
    }
    
    /// <summary>
    /// 设置删除线
    /// </summary>
    public void SetStrikethrough(string range, bool strikethrough = true)
    {
        sheet.SetRangeStyles(range, new WorksheetRangeStyle
        {
            Flag = PlainStyleFlag.FontStrikethrough,
            Strikethrough = strikethrough
        });
    }
}
```

SetRangeStyles 是合并式更新：只改 Flag 中指定的属性，未指定的属性保留原值。所以可以分两步，先给 A1:A10 设粗体，再给同一区域设字号，两步互不覆盖。反过来说，想清除某项样式也要显式写进去，例如 Bold = false 并带上 FontBold 标志，不能靠「不设置」来实现。

重复设置同一属性会覆盖前一次的值，顺序在后的生效。设置顺序没有依赖时，合并成一次调用，可以减少区域失效的次数。

### 4.3.2 对齐方式

水平对齐与垂直对齐分别对应两个枚举，都要通过样式 Flag 才生效。没有显式设置对齐时，控件按数据类型推断：文本靠左、数值靠右，这是表格软件的通行习惯。一旦显式设置，推断规则就不再生效，所以给表头设了居中，数据行仍要单独处理。

TextWrap 有两个常用取值：NoWrap 表示不换行，内容超出列宽时溢出到右侧空白单元格；WordBreak 表示按列宽折行。折行需要在垂直方向有足够空间，行高不够时看到的只是被截断的文本，因此通常还要配合自动行高或手动调整行高。

```csharp
using unvell.ReoGrid.Data;

public class AlignmentStyling
{
    private Worksheet sheet;
    
    public AlignmentStyling(Worksheet worksheet)
    {
        sheet = worksheet;
    }
    
    /// <summary>
    /// 设置水平对齐
    /// </summary>
    public void SetHorizontalAlign(string range, ReoGridHorAlign align)
    {
        sheet.SetRangeStyles(range, new WorksheetRangeStyle
        {
            Flag = PlainStyleFlag.HorizontalAlign,
            HAlign = align
        });
    }
    
    /// <summary>
    /// 设置垂直对齐
    /// </summary>
    public void SetVerticalAlign(string range, ReoGridVerAlign align)
    {
        sheet.SetRangeStyles(range, new WorksheetRangeStyle
        {
            Flag = PlainStyleFlag.VerticalAlign,
            VAlign = align
        });
    }
    
    /// <summary>
    /// 设置文本换行
    /// </summary>
    public void SetTextWrap(string range, bool wrap = true)
    {
        sheet.SetRangeStyles(range, new WorksheetRangeStyle
        {
            Flag = PlainStyleFlag.TextWrap,
            TextWrap = wrap ? TextWrapMode.WordBreak : TextWrapMode.NoWrap
        });
    }
}
```

文本换行设置之后，如果列宽变化，已经计算过的行高不会自动跟着变。需要重新执行自动行高，或者把行高设成一个够用的固定值，界面展示才稳定。

分散对齐（DistributedIndent）适合表头文字较短的场景，它把文字均匀分布到整个列宽里，视觉上比普通居中更像正式报表，但列宽变化时文字间距会随之变化，窄列上容易出现字挤在一起的情况，用之前先看重置后的效果。

### 4.3.3 背景和边框

背景色和边框是两组独立的样式属性，可以单独设置，也可以放进同一次 SetRangeStyles。背景色用 BackColor，边框用 Border 加一个 RangeBorderStyle，后者把左、上、右、下四条边分别描述，每条边由颜色和线型组成。

整块区域的边框有两种写法：给每个单元格设四条边（示例中的 SetBorder），或者用 SetRangeBorders 指定位置。前者写起来直接，但相邻单元格之间会出现两条边重叠；后者把「外框」和「内部线」分开处理，外框只加在区域边缘，内部线加在行列之间，报表里更常用。

```csharp
using System.Drawing;
using unvell.ReoGrid.Data;
using unvell.ReoGrid.Graphics;

public class BackgroundAndBorderStyling
{
    private Worksheet sheet;
    
    public BackgroundAndBorderStyling(Worksheet worksheet)
    {
        sheet = worksheet;
    }
    
    /// <summary>
    /// 设置背景色
    /// </summary>
    public void SetBackgroundColor(string range, Color color)
    {
        sheet.SetRangeStyles(range, new WorksheetRangeStyle
        {
            Flag = PlainStyleFlag.BackColor,
            BackColor = color
        });
    }
    
    /// <summary>
    /// 设置全边框
    /// </summary>
    public void SetBorder(string range, Color color, BorderLineStyle style)
    {
        sheet.SetRangeStyles(range, new WorksheetRangeStyle
        {
            Flag = PlainStyleFlag.Border,
            Border = new RangeBorderStyle
            {
                Left = new BorderStyle { Color = color, Style = style },
                Top = new BorderStyle { Color = color, Style = style },
                Right = new BorderStyle { Color = color, Style = style },
                Bottom = new BorderStyle { Color = color, Style = style }
            }
        });
    }
    
    /// <summary>
    /// 设置外边框
    /// </summary>
    public void SetOutsideBorder(string range, Color color, BorderLineStyle style)
    {
        sheet.SetRangeBorders(new RangePosition(range), BorderPositions.Outside,
            new BorderStyle { Color = color, Style = style });
    }
    
    /// <summary>
    /// 设置内边框
    /// </summary>
    public void SetInsideBorder(string range, Color color, BorderLineStyle style)
    {
        sheet.SetRangeBorders(new RangePosition(range), BorderPositions.Inside,
            new BorderStyle { Color = color, Style = style });
    }
}
```

边框有先后覆盖关系：同一位置的边线，后设置的样式会覆盖先设置的。做报表时通常先铺底色和内部细线，最后再给表头加粗外框，顺序反了外框容易被后面的细线覆盖掉。

粗线和双线占用的像素比普通实线多，行高很小时显示会不完整，看起来像缺了一段。设置这类边框前先把行高留够，或者只在表头使用，避免整表变拥挤。

另一个常见问题是给每个单元格都设置四边全框，结果相邻单元格的边线叠在一起，视觉上线宽变成两倍。若只是想画出网格，用 SetRangeBorders 的 Inside，一次调用就能覆盖整块区域。

## 4.4 单元格合并

### 4.4.1 合并操作

合并单元格用于表头跨列、标题跨行这类排版。MergeRange 接收一个区域，区域里除左上角以外的单元格都变成从属单元格，界面上只显示左上角的内容。取消合并用 UnmergeRange，参数要传同一块区域，传单格地址不会报错但没有效果。

合并会影响数据：从属单元格里原有内容不再显示，也从正常读取路径里消失。因此合并前应确认从属单元格是空的，或者先把需要保留的数据移到左上角。取消合并不会自动把内容还原回去，这一点在动态排版场景里要提前设计好。

```csharp
using unvell.ReoGrid;

public class CellMerging
{
    private Worksheet sheet;
    
    public CellMerging(Worksheet worksheet)
    {
        sheet = worksheet;
    }
    
    /// <summary>
    /// 合并单元格
    /// </summary>
    public void MergeCells(string range)
    {
        sheet.MergeRange(range);
    }
    
    /// <summary>
    /// 取消合并
    /// </summary>
    public void UnmergeCells(string range)
    {
        sheet.UnmergeRange(range);
    }
    
    /// <summary>
    /// 检查是否已合并
    /// </summary>
    public bool IsMerged(string address)
    {
        var pos = new CellPosition(address);
        var cell = sheet.GetCell(pos);
        return cell != null && cell.IsMergedCell;
    }
    
    /// <summary>
    /// 获取合并区域
    /// </summary>
    public RangePosition GetMergedRange(string address)
    {
        var pos = new CellPosition(address);
        var cell = sheet.GetCell(pos);
        
        if (cell != null && cell.IsMergedCell)
        {
            return cell.MergeRange;
        }
        
        return RangePosition.Empty;
    }
}
```

代码用 Cell.IsMergedCell 判断单元格是否属于某次合并，再用 MergeRange 属性取回整块区域，适合在点击、编辑前做拦截：合并区域只有左上角可编辑，其他从属单元格应当跳过。

合并区域与行列增删会互相影响。删除的行列如果落在合并区域内，区域会相应收缩；插入行列会把区域撑开。批量操作后又需要合并时，建议先完成增删，再做合并，顺序反了容易得到形状不符合预期的区域。

对已经合并的区域再调用一次 MergeRange，通常不会报错但也不会产生新的效果；对没有合并的区域调用 UnmergeRange 则可能抛出异常，调用前用 IsMergedCell 判断一下更稳妥。

## 4.5 行列操作

### 4.5.1 插入和删除

插入和删除行列会移动后续的数据，这个动作不只是显示变化，表格里保存的行列下标都会跟着调整：在第 3 行插入一行，原来的第 3 行数据变成第 4 行，后续所有行号加一。代码里的 row 参数是插入点，count 是一次插入多少行，插入内容为空，原有单元格不受影响。

公式对行列的引用会随插入删除一起调整。插入行时，跨过插入点的引用区间会自动扩展；删除被引用的行时，引用会变成无效地址，公式计算结果是 #REF!。这是表格软件的标准行为，但在业务代码里批量删除前，最好先确认哪些列上有公式，避免导出时满屏错误值。

这些操作会进入撤销栈，控件的 Action 系统会记录它们，因此用户可以用快捷键撤销。代价是一次批量插入会产生对应的动作记录，行数很多时合并成一次调用比逐行插入更省资源。

```csharp
using unvell.ReoGrid;

public class RowColumnOperations
{
    private Worksheet sheet;
    
    public RowColumnOperations(Worksheet worksheet)
    {
        sheet = worksheet;
    }
    
    /// <summary>
    /// 插入行
    /// </summary>
    public void InsertRow(int row, int count = 1)
    {
        sheet.InsertRows(row, count);
    }
    
    /// <summary>
    /// 删除行
    /// </summary>
    public void DeleteRow(int row, int count = 1)
    {
        sheet.DeleteRows(row, count);
    }
    
    /// <summary>
    /// 插入列
    /// </summary>
    public void InsertColumn(int col, int count = 1)
    {
        sheet.InsertColumns(col, count);
    }
    
    /// <summary>
    /// 删除列
    /// </summary>
    public void DeleteColumn(int col, int count = 1)
    {
        sheet.DeleteColumns(col, count);
    }
}
```

插入与删除的位置由当前工作表尺寸决定。行号超过 RowCount 时插入可能失败，删除超出范围的行列也一样，调用前用 RowCount、ColumnCount 校验一下参数，比让控件抛异常更容易定位问题。

循环删除时有个经典错误：正序删除会让后面的下标整体前移，结果每删一行就跳过下一行。正确做法是从后往前删，或者一次删除一个连续区间。插入时相反，正序插入并同步调整计数才不会漏插。

### 4.5.2 隐藏和显示

隐藏行和隐藏列属于视图层操作：数据还在，公式照常参与计算，屏幕上看不到而已。这和删除完全不同——删除会把数据连同单元格一起移走，被引用的公式会失效。需要「暂时不看」时用隐藏，需要「确实不要」时才用删除。

隐藏之后，行号列号会跳过那一段，用户仍然可以通过行标题的选中来显示整段。代码里成对提供 HideRows / ShowRows 与 HideColumns / ShowColumns，参数是起始下标和数量，恢复显示时要传同一段范围，否则只会恢复其中一部分。

```csharp
using unvell.ReoGrid;

public class RowColumnVisibility
{
    private Worksheet sheet;
    
    public RowColumnVisibility(Worksheet worksheet)
    {
        sheet = worksheet;
    }
    
    /// <summary>
    /// 隐藏行
    /// </summary>
    public void HideRows(int row, int count = 1)
    {
        sheet.HideRows(row, count);
    }
    
    /// <summary>
    /// 显示行
    /// </summary>
    public void ShowRows(int row, int count = 1)
    {
        sheet.ShowRows(row, count);
    }
    
    /// <summary>
    /// 隐藏列
    /// </summary>
    public void HideColumns(int col, int count = 1)
    {
        sheet.HideColumns(col, count);
    }
    
    /// <summary>
    /// 显示列
    /// </summary>
    public void ShowColumns(int col, int count = 1)
    {
        sheet.ShowColumns(col, count);
    }
}
```

隐藏行列不影响导出：写 Excel 时是否输出隐藏行列取决于导出选项和版本，默认通常保留数据但带上隐藏标记。如果报表要求「隐藏即不导出」，导出前要用 DeleteRows 真正删掉，不能只是 HideRows。

列宽设置为 0 在界面上等价于隐藏，但语义不同：前者是尺寸为 0，后者是显式的隐藏状态。用户用「显示所有列」之类的操作时，两种状态的处理也不一样，业务代码里不要混用。

### 4.5.3 尺寸调整

行高和列宽都以像素为单位，参数类型是 ushort，意味着上限约六万五千，实际值通常在一百上下。SetRowsHeight 与 SetColumnsWidth 的参数顺序是「起点、数量、尺寸」，三个参数都是整数，写反了不会报错，只会得到奇怪的行高。

自动调整尺寸按单元格内容计算：设了字体、字号和换行之后，AutoFitRowHeight 才能算出合适高度。数据还没填完就调用自动调整，得到的只是当前内容的尺寸，后续再写入长文本仍会被截断。

```csharp
using unvell.ReoGrid;

public class RowColumnSizing
{
    private Worksheet sheet;
    
    public RowColumnSizing(Worksheet worksheet)
    {
        sheet = worksheet;
    }
    
    /// <summary>
    /// 设置行高
    /// </summary>
    public void SetRowHeight(int row, ushort height, int count = 1)
    {
        sheet.SetRowsHeight(row, count, height);
    }
    
    /// <summary>
    /// 设置列宽
    /// </summary>
    public void SetColumnWidth(int col, ushort width, int count = 1)
    {
        sheet.SetColumnsWidth(col, count, width);
    }
    
    /// <summary>
    /// 自动调整行高
    /// </summary>
    public void AutoFitRow(int row)
    {
        sheet.AutoFitRowHeight(row);
    }
    
    /// <summary>
    /// 自动调整列宽
    /// </summary>
    public void AutoFitColumn(int col)
    {
        sheet.AutoFitColumnWidth(col);
    }
    
    /// <summary>
    /// 自动调整所有列宽
    /// </summary>
    public void AutoFitAllColumns()
    {
        for (int col = 0; col < sheet.ColumnCount; col++)
        {
            sheet.AutoFitColumnWidth(col);
        }
    }
}
```

## 4.6 本章小结

本章详细介绍了ReoGrid中工作表和单元格的各种操作，包括数据读写、格式化、样式设置、单元格合并以及行列操作等核心功能。

把这一章的内容按"读到哪一层"来记会更清楚：

- 数据层：索引器、SetCellData / GetCellData、Cell.Data，处理的是单元格里存的值；
- 显示层：DisplayText、SetRangeDataFormat、样式与对齐，处理的是值怎么呈现；
- 结构层：合并、行列增删、隐藏与尺寸，处理的是表格的形状。

三层之间互相独立，改动一层不影响另一层，这是排查问题时最有用的判断依据。数值算错先看数据层，显示不对先看格式层，位置错乱先看结构层。

实践中还有两点值得固定成习惯。第一，循环读写放进 BeginUpdate 块，避免逐格触发重绘；第二，访问单元格前判空，尤其是用户可能清空过的区域。这两条不能解决所有问题，但能挡掉这类代码里最常见的异常与卡顿。

自动调整行高列宽属于开销较大的操作，放在数据与样式都设置完之后执行一次，不要放在循环里。大表上重复调用自动调整，是界面长时间无响应的常见原因。

本章的示例以单元格为主，下一章会把数据类型单独拆开讲，重点在格式化器怎么影响显示与导出。
