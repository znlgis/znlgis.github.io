# 第十六章：脚本与宏功能

有些操作更适合写成脚本而不是编译进程序：一次性的批量排版、给客户的自定义计算规则、临时的数据清洗。ReoGrid 在带脚本支持构建时集成了 ReoScript 引擎，可以在运行时执行一段脚本，脚本里直接读写工作表的单元格。

先说明前提：脚本功能由 EX_SCRIPT 编译开关控制，官方 NuGet 包默认不带。看本章之前先确认手上的程序集是否包含脚本引擎，没有的话示例代码编译不过，这不是写法问题。

脚本在同一个进程里执行，能访问工作表，也能调用宿主注册进来的 C# 函数。它带来灵活性的同时也带来风险，脚本内容来自外部时，要在受控环境里执行，不要当成安全的沙箱。

## 16.1 ReoScript简介

ReoGrid集成了ReoScript脚本引擎，支持在电子表格中执行脚本。

> **注意**：脚本功能由 `EX_SCRIPT` 条件编译开关控制，官方 NuGet 正式包（3.3.1）未包含该功能；如需脚本支持，需从源码以带脚本的配置自行构建。

脚本运行时对象从控件上取：grid.Srm，注释里写明它是 Script Runtime Machine。调用它的 Run 方法执行一段脚本字符串，脚本里的全局对象包括 workbook 与 sheet，分别对应当前工作簿和当前工作表。

示例脚本改了三格：A1 写文本，A2 写数字，A3 写 A2 加 50 的结果。注意脚本里的字符串用单引号，属性访问用点号，写法接近 JavaScript。脚本执行完，改动立刻反映到工作表上。

```csharp
using unvell.ReoScript;

public class ScriptBasics
{
    private ReoGridControl grid;
    
    public void ExecuteScript(string script)
    {
        var srm = grid.Srm;  // Script Runtime Machine
        srm.Run(script);
    }
    
    public void SimpleScript()
    {
        var script = @"
            // 设置单元格值
            sheet.cells['A1'].data = 'Hello from script';
            sheet.cells['A2'].data = 100;
            
            // 计算
            var sum = sheet.cells['A2'].data + 50;
            sheet.cells['A3'].data = sum;
        ";
        
        ExecuteScript(script);
    }
}
```

脚本报错的处理方式与 C# 不同：错误发生在 Run 内部，可能以异常形式抛到 C# 调用点，也可能被记录为脚本错误。调用 Run 时用 try/catch 包住，至少能看到出错行号，否则用户只会看到「没反应」。

脚本里的 sheet 指向当前工作表。切换工作表后再执行同一段脚本，操作对象就变了，脚本中显式取 workbook.currentWorksheet 更稳，避免依赖调用时的上下文。

脚本执行是同步的。脚本里循环几十万次会有明显停顿，与 C# 循环的耗时相当；需要长时间运行时把脚本拆成小段，或者放到后台执行并处理线程问题。

## 16.2 脚本访问工作表

脚本访问工作表有两种写法：通过 workbook.currentWorksheet 取当前表，或者直接使用全局的 sheet。示例用后者，并用 cells 索引器读写单元格，行列下标从 0 开始。

cells[i, 0] 用的是行列下标，A1 这种地址写法同样支持。循环里用下标更自然，配置类操作用地址更可读，两者可以混用，不必统一。

样式通过 setRangeStyle 设置，第二个参数是一个对象字面量，字段名用脚本侧的命名（backColor、textColor、bold），颜色写成井号加六位十六进制。字段名与 C# 属性名不完全一致，写错不会报错，只是不生效，设置后要看一眼效果。

```csharp
public class ScriptWorksheetAccess
{
    public void AccessWorksheetFromScript(ReoGridControl grid)
    {
        var script = @"
            // 获取当前工作表
            var sheet = workbook.currentWorksheet;
            
            // 设置数据
            for (var i = 0; i < 10; i++) {
                sheet.cells[i, 0].data = i + 1;
                sheet.cells[i, 1].data = (i + 1) * 10;
            }
            
            // 设置样式
            sheet.setRangeStyle('A1:B1', {
                backColor: '#4472C4',
                textColor: '#FFFFFF',
                bold: true
            });
        ";
        
        grid.Srm.Run(script);
    }
}
```

脚本适合做「一次性」的事：批量填数、按规则改格式、生成演示数据。它的优势是不用重新编译，改一段文本就能调整行为；代价是没有编译期检查，拼写错误要到运行时才暴露。

脚本与公式不是一回事。公式由计算引擎解析，参与依赖计算；脚本是命令式的，执行完就结束，不会随单元格变化自动重跑。需要自动响应的逻辑仍然用公式或事件。

脚本改动的数据同样会进入撤销栈（如果版本支持），用户按 Ctrl+Z 可以回退。脚本里做大批量修改时，注意撤销记录会占内存。

## 16.3 注册C#函数到脚本

脚本能做的事有限，复杂逻辑还是 C# 更合适。把 C# 方法注册成脚本函数，脚本里就能像调用普通函数一样调用它，实现「脚本编排、C# 执行」的分工。

注册方式是把一个函数对象挂到运行时对象的索引器上，示例用 NativeFunctionObject 包装一个委托，第一个参数是脚本里使用的函数名，委托里从参数数组取值并返回结果。

参数从脚本传进来是 object，类型转换要自己做。示例用 Convert.ToInt32 转整型，转换失败会抛异常并冒泡到脚本调用点，所以在函数内部判断参数类型和个数更稳妥。

```csharp
public class RegisterFunctionsToScript
{
    public void RegisterFunctions(ReoGridControl grid)
    {
        var srm = grid.Srm;
        
        // 注册C#函数到脚本
        srm["myFunction"] = new NativeFunctionObject("myFunction", (args) =>
        {
            var param = Convert.ToInt32(args[0]);
            return param * 2;
        });
        
        // 在脚本中调用
        var script = @"
            var result = myFunction(10);
            sheet.cells['A1'].data = result;  // 输出20
        ";
        
        srm.Run(script);
    }
}
```

注册的函数名要全局唯一。与内置函数重名时，哪个生效取决于查找顺序，出现问题时很难发现；加一个业务前缀（例如公司缩写）可以避免大部分冲突。

注册时机在脚本执行之前。每次运行脚本前都重新注册一次不影响结果，反而能保证函数对象是当前实例，避免持有已释放对象的旧委托。

被注册的 C# 函数能做脚本做不到的事，也意味着它能突破权限边界。脚本来源不可信时，不要在注册函数里暴露文件写入、进程启动这类能力。

## 16.4 宏录制与回放

示例的宏不是内建功能，而是一个最小的录制器：开着录制标志时，把用户的操作包装成委托存进列表，回放时依次执行。它演示的是思路，不是 ReoGrid 的 API。

录制一份操作列表，回放时重新执行，本质上就是把界面动作参数化。适合的场景是重复排版：同样的表头样式、同样的列宽、同样的汇总公式，录一次，后面一键套用。

委托的形式有局限。它捕获的是执行时的对象引用，回放时如果工作表已更换，委托操作的可能还是旧表。真正做宏功能时，录制的是「动作描述」（操作类型加参数），回放时再解释执行。

```csharp
public class MacroRecording
{
    private List<Action> recordedActions = new List<Action>();
    private bool isRecording = false;
    
    public void StartRecording()
    {
        isRecording = true;
        recordedActions.Clear();
    }
    
    public void StopRecording()
    {
        isRecording = false;
    }
    
    public void RecordAction(Action action)
    {
        if (isRecording)
        {
            recordedActions.Add(action);
        }
    }
    
    public void PlaybackMacro()
    {
        foreach (var action in recordedActions)
        {
            action.Invoke();
        }
    }
}
```

回放要注意顺序与数量。插入行之后再按原行号删除，删掉的可能是别的行；宏里的操作应当尽量少依赖绝对行号，改用「当前选区」「当前单元格」这类相对描述。

宏回放失败要能停下并报告第几步出错。静默执行到一半失败，用户看到的是半成品表格，很难判断哪里不对。

宏的持久化不在本章范围内。把动作描述序列化成 JSON 存进文件或数据库，是更实际的做法，回放时反序列化执行，跨会话也能用。

## 16.5 本章小结

本章介绍了ReoScript脚本引擎和宏功能。

脚本部分要记住的前提和用法：

- 前提：脚本引擎由 EX_SCRIPT 开关控制，官方 NuGet 包默认不含；
- 入口：grid.Srm.Run 执行脚本，脚本里可访问 workbook 与 sheet；
- 样式：setRangeStyle 用对象字面量，字段名是脚本侧命名；
- 扩展：把 C# 委托包装成 NativeFunctionObject 注册，脚本即可调用。

宏部分的关键是认识到示例只是思路演示。生产中要录制动作而不是委托，要处理对象变化、执行顺序和失败回滚，才能让回放结果可预期。

脚本功能最大的价值是「不重新编译就能调整行为」，代价是失去类型检查和调试手段。它适合辅助工具、内部脚本，不适合承载核心业务规则。核心规则写成 C# 代码，才能被测试和审查覆盖。
