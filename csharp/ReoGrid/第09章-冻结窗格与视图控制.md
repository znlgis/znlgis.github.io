# 第九章：冻结窗格与视图控制

数据量大到需要滚动时，表头会先滚出视野，用户看到一排数字却不知道哪列是什么。冻结窗格解决的就是这个问题：把指定的行或列钉在窗口顶部和左侧，滚动时它们不跟着动。这一章讲冻结、缩放和滚动定位这三类视图控制，它们都不改数据，只影响用户看到的部分。

三个功能的共同点是操作对象都是「视图」而不是「内容」。冻结改变的是绘制时的分区，缩放改变的是渲染倍率，滚动定位改变的是视口位置。因此它们的设置不会写进单元格数据，保存文件时通常也不带走，需要每次打开时由代码重新设置。

## 9.1 冻结窗格

FreezeToCell 的参数是「第一个可以滚动的单元格」的行列下标，不是要冻结的行数。冻结首行传 (1, 0)，表示从第 2 行开始可以滚动，第 1 行被钉住；冻结首列传 (0, 1)，同理。传 (2, 3) 会冻结上面两行和左边三列，形成一个 L 形的固定区域。

冻结区间与左上角单元格之间有一条分隔线，用户拖动滚动条时，冻结区保持不动，其余部分滚动。分隔线位置由参数决定，写错一个数字就会多冻一行或少冻一行，设置后滚动一下确认边界。

取消冻结调用 Unfreeze，恢复成整表滚动。切换工作表、重新加载数据后，冻结状态通常需要重新设置，不要假设控件会记住上一次的设置。

```csharp
public class FreezePanes
{
    private Worksheet sheet;
    
    // 冻结首行
    public void FreezeTopRow()
    {
        sheet.FreezeToCell(1, 0);
    }
    
    // 冻结首列
    public void FreezeFirstColumn()
    {
        sheet.FreezeToCell(0, 1);
    }
    
    // 冻结行列
    public void FreezeRowsAndColumns(int row, int col)
    {
        sheet.FreezeToCell(row, col);
    }
    
    // 取消冻结
    public void Unfreeze()
    {
        sheet.Unfreeze();
    }
}
```

冻结用在有表头的长表上，效果最明显。冻结首行之后，向下滚动到第 500 行，列标题仍然在顶部，用户不用滚回去确认列含义。冻结行列组合适合宽表：首列是编号或名称，冻住后横向滚动不会丢失行标识。

冻结区域不参与滚动，但参与绘制，因此冻结的行列越多，每次重绘要处理的内容越多。只冻结必要的一两行、一两列即可，不要把大块区域冻起来。

合并单元格跨越冻结边界时，显示可能不完整。表头如果有跨列合并，冻结位置应避开合并区域的中部，让整块合并单元格落在同一边。

## 9.2 缩放控制

SetScale 接收一个浮点比例，1.0 是原始大小，0.5 是一半，2.0 是两倍。示例注释给出了这三个常用值，实际范围通常限制在 0.1 到 4 之间，超出范围可能被截断或直接忽略。

缩放只改渲染倍率，不改行高列宽的存储值，也不改字体大小。放大到 150% 时，一屏能看到的行列变少，但单元格里的字号在数据上仍是原来的磅值；导出、打印拿到的是原始尺寸。

缩放与冻结可以同时使用。冻结区按缩放后的尺寸绘制，分隔线位置随之变化，不需要额外计算。

```csharp
public class ZoomControl
{
    public void SetZoom(Worksheet sheet, float scale)
    {
        // 设置缩放比例 (0.5 = 50%, 1.0 = 100%, 2.0 = 200%)
        sheet.SetScale(scale);
    }
}
```

缩放接口挂在哪个对象上，各版本可能不同：有的版本提供工作表级的缩放，有的放在控件上。示例调用的是工作表的 SetScale，编译不通过时把调用对象换成控件试一次，两者语义一致。

缩放比例要给出可恢复的入口。界面上放一个「100%」按钮或下拉框，用户放大查看细节后能一键回到原始比例；只提供放大不提供复位，用户容易卡在异常比例里。

缩放会改变鼠标坐标到单元格的映射，控件内部按当前倍率换算，不需要业务代码自己算。自定义绘制或命中测试时，坐标要用缩放后的值，混用原始坐标会点错位置。

## 9.3 视图导航

ScrollToCell 把指定单元格滚到可见区域。参数是 CellPosition，可以传地址字符串构造，也可以传行列下标。常用于「搜索定位」：用户输入编号，程序找到对应行，滚动过去并选中。

滚动只移动视口，不改变当前选择与焦点。定位到目标后如果希望用户直接编辑，还要显式设置当前单元格或选择区域，两件事要分别做。

VisibleRange 返回当前视口覆盖的区域，可用于按需加载：滚动事件里判断即将进入视口的行，动态把数据填进去，避免一次性加载几十万行。

```csharp
public class ViewNavigation
{
    public void ScrollToCell(Worksheet sheet, string address)
    {
        sheet.ScrollToCell(new CellPosition(address));
    }
    
    public void GetVisibleRange(Worksheet sheet)
    {
        var visibleRange = sheet.VisibleRange;
        Console.WriteLine($"可见区域: {visibleRange}");
    }
}
```

滚动定位有两个边界情况。目标单元格已经在可见区域内时，多数实现不做任何移动，界面看起来「没反应」，需要高亮或选中来提示用户；目标位置超出工作表当前尺寸时，滚动可能被限制在有效范围内。

滚动与冻结配合时，滚动目标如果落在冻结区内，视口不会移动，因为那块区域本来就不参与滚动。定位逻辑里要先判断目标行是否大于冻结边界，再决定是否调用。

## 9.4 本章小结

本章介绍了冻结窗格、缩放和视图导航功能。

三个功能都属于视图控制，记住三条对应关系就不容易用错：

- 冻结：FreezeToCell 的参数是滚动起点，不是冻结数量；
- 缩放：SetScale 的 1.0 是原始比例，只影响渲染，不影响数据与打印尺寸；
- 导航：ScrollToCell 只移动视口，选中与焦点要另外设置。

这些设置通常不随文件保存，重新打开页面时要在初始化代码里重新应用。把它们和「工作表初始化」写在一起，比散落在各处的事件里更容易维护。

视图控制做得好不好，用户不一定说得出来，但会直接影响操作效率。表头常驻、比例可复位、定位后能立刻编辑，这三点做到位，大表的可用性会明显不同。
