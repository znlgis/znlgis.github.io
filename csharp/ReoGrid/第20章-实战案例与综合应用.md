# 第二十章：实战案例与综合应用

前面十九章拆开讲了一个个功能点，这一章把它们拼成完整应用。四个案例覆盖报表分析、进销存、考勤、预算四类常见业务，结构都是「建表、灌数据、写公式、加样式、导文件」，差别在业务规则与数据流。

案例代码是骨架，不是可直接上线的产品。它们省略了数据校验、异常处理、权限控制这些工程细节，也不考虑界面布局。看的时候关注三件事：工作表怎么组织、公式怎么引用、数据变化怎么驱动汇总。把这三条抓住，换成自己的业务就能改写。

代码里有几处已知的写法问题，正文里会逐个指出来。保留原样是为了让读者看到「常见的坑长什么样」，遇到同样的代码时能认出来。

## 20.1 案例一：数据分析报表系统

### 20.1.1 需求分析

创建一个数据分析报表系统，支持：
- 数据导入（Excel、CSV、数据库）
- 数据统计分析
- 图表可视化
- 报表导出

这四条对应一套典型流程：原始数据表存明细，分析表存汇总，图表挂在分析表上，最后整本导出。需求本身不复杂，难点在两块表的联动——分析表的公式要引用明细表，明细表换了数据，分析结果和图表都要跟着变。

设计上把「原始数据」和「数据分析」拆成两张工作表，而不是在同一张表里上下排布。拆开后职责清楚：明细表只放数据，分析表只放结论，导出时两张表分别对应「数据附件」和「分析报告」，接收方各取所需。

### 20.1.2 实现代码

示例的类持有控件与两张工作表的引用，构造时创建工作表并切到明细表。ImportData 先调 Load 导入文件，再调 AnalyzeData 写汇总。

这里有一个需要留意的地方：grid.Load 是工作簿级加载，导入后会重建工作表集合，构造函数里保存的 dataSheet 与 summarySheet 引用可能失效。示例紧接着用 summarySheet 写公式，此时它指向的可能是已被替换的旧对象。稳妥做法是导入后重新从控件取工作表，或者改用工作表级的 LoadExcel 只填数据。

AnalyzeData 用 BeginUpdate 包住整段写操作，减少重绘；try/finally 保证 EndUpdate 一定执行。这个结构值得照抄，是批量写表的标准写法。

```csharp
public class DataAnalysisSystem
{
    private ReoGridControl grid;
    private Worksheet dataSheet;
    private Worksheet summarySheet;
    
    public DataAnalysisSystem(ReoGridControl gridControl)
    {
        grid = gridControl;
        Initialize();
    }
    
    private void Initialize()
    {
        // 创建数据表和汇总表
        dataSheet = grid.CreateWorksheet("原始数据");
        summarySheet = grid.CreateWorksheet("数据分析");
        
        grid.CurrentWorksheet = dataSheet;
    }
    
    public void ImportData(string filePath)
    {
        grid.Load(filePath);
        AnalyzeData();
    }
    
    private void AnalyzeData()
    {
        summarySheet.BeginUpdate();
        try
        {
            // 统计分析
            summarySheet["A1"] = "统计项";
            summarySheet["B1"] = "结果";
            
            summarySheet["A2"] = "总记录数";
            summarySheet["B2"] = $"=COUNTA(原始数据.A:A)";
            
            summarySheet["A3"] = "数值总和";
            summarySheet["B3"] = $"=SUM(原始数据.B:B)";
            
            summarySheet["A4"] = "平均值";
            summarySheet["B4"] = $"=AVERAGE(原始数据.B:B)";
            
            summarySheet["A5"] = "最大值";
            summarySheet["B5"] = $"=MAX(原始数据.B:B)";
            
            summarySheet["A6"] = "最小值";
            summarySheet["B6"] = $"=MIN(原始数据.B:B)";
            
            // 设置样式
            summarySheet.SetRangeStyles("A1:B1", new WorksheetRangeStyle
            {
                Flag = PlainStyleFlag.FontBold | PlainStyleFlag.BackColor,
                Bold = true,
                BackColor = Color.LightBlue
            });
            
            // 创建图表
            CreateChart();
        }
        finally
        {
            summarySheet.EndUpdate();
        }
    }
    
    private void CreateChart()
    {
        var chart = new unvell.ReoGrid.Chart.ColumnChart
        {
            Location = new unvell.ReoGrid.Graphics.Point(500, 20),
            Size = new unvell.ReoGrid.Graphics.Size(420, 260),
            Title = "数据分析图表",
            DataSource = new unvell.ReoGrid.Chart.WorksheetChartDataSource(
                summarySheet, summarySheet.Ranges["A3:A6"], summarySheet.Ranges["B3:B6"])
            {
                CategoryNameRange = summarySheet.Ranges["B2:B2"],
            },
        };
        summarySheet.FloatingObjects.Add(chart);
    }
    
    public void ExportReport(string filePath)
    {
        grid.Save(filePath, IO.FileFormat.Excel2007);
    }
}
```

汇总区的六行公式是两个模块的核心：COUNTA 统计非空行数，SUM、AVERAGE、MAX、MIN 对数值列做统计，全部引用「原始数据」表。跨表引用在不同版本里支持的语法不同，Excel 通用的写法是「工作表名加感叹号」，工作表名含空格或中文时用单引号包起来，例如 =SUM('原始数据'!B:B)。示例用的是点号形式，若计算结果出现 #NAME? 或 #REF!，先换成感叹号写法试一次。

统计列用整列引用（B:B）写起来省事，但会把标题行也算进去。标题是文本，SUM 与 AVERAGE 会忽略文本不影响结果，COUNTA 却会把它计入，总记录数会多 1。要精确计数时把范围写成 B2:B1000 这类明确区间。

图表的数据源引用分析表 A3:B6，分类名取 B2:B2。分类范围只给一个单元格，图表会把这一格的值当成整个分类名，实际显示可能只剩一个标签。数据行有 4 条、分类名却只有 1 个时，图例与横轴会对不上，改成 A3:A6 更合理。

最后导出用 grid.Save 加 FileFormat.Excel2007，整本工作簿存成一个文件，明细表与分析表都带出去。这里没有配置选项对象，公式与样式按默认行为导出。

## 20.2 案例二：进销存管理系统

进销存的核心是两张表：库存表存当前状态，出入库记录表存流水。示例的 Initialize 创建工作表后分别初始化，库存表设列头、公式与格式，记录表设列头与数据验证。

库存表的第五列是「库存金额」，公式 =C*D 用数量乘单价。示例给第 1 到 100 行都预置了公式，即使这些行暂时没有数据，公式也在。数量或单价为空时，公式按 0 计算，金额列显示 0 而不是空白，界面看起来会有一片 0。介意的话把公式改成条件写法，或者等数据填入后再写公式。

表头样式用深蓝底白字加粗居中，和第十五章、第六章的模板思路一致。货币格式设在 D2:E101，单价与金额都按人民币两位小数显示，范围比公式范围多一行，是为了留出合计行的位置。

```csharp
public class InventoryManagementSystem
{
    private Worksheet inventorySheet;
    private Worksheet transactionSheet;
    
    public void Initialize(ReoGridControl grid)
    {
        inventorySheet = grid.CreateWorksheet("库存");
        transactionSheet = grid.CreateWorksheet("出入库记录");
        
        SetupInventorySheet();
        SetupTransactionSheet();
    }
    
    private void SetupInventorySheet()
    {
        // 设置列头
        var headers = new[] { "商品编号", "商品名称", "库存数量", "单价", "库存金额" };
        for (int i = 0; i < headers.Length; i++)
        {
            inventorySheet[0, i] = headers[i];
        }
        
        // 设置公式（库存金额 = 数量 × 单价）
        for (int row = 1; row <= 100; row++)
        {
            inventorySheet[row, 4] = $"=C{row+1}*D{row+1}";
        }
        
        // 设置样式
        inventorySheet.SetRangeStyles("A1:E1", new WorksheetRangeStyle
        {
            Flag = PlainStyleFlag.FontBold | PlainStyleFlag.BackColor | PlainStyleFlag.HorizontalAlign,
            Bold = true,
            BackColor = Color.FromArgb(68, 114, 196),
            HAlign = ReoGridHorAlign.Center
        });
        
        // 设置货币格式
        inventorySheet.SetRangeDataFormat("D2:E101", CellDataFormatFlag.Currency,
            new CurrencyDataFormatter.CurrencyFormatArgs
            {
                Symbol = "¥",
                DecimalPlaces = 2
            });
    }
    
    private void SetupTransactionSheet()
    {
        var headers = new[] { "日期", "商品编号", "类型", "数量", "备注" };
        for (int i = 0; i < headers.Length; i++)
        {
            transactionSheet[0, i] = headers[i];
        }
        
        // 数据验证
        transactionSheet.SetRangeDataValidation("C2:C1000", DataValidationType.List,
            new ListValidationRule
            {
                Items = new[] { "入库", "出库" }
            });
    }
    
    public void AddTransaction(DateTime date, string productId, string type, int quantity, string notes)
    {
        int nextRow = FindNextEmptyRow(transactionSheet);
        
        transactionSheet[nextRow, 0] = date;
        transactionSheet[nextRow, 1] = productId;
        transactionSheet[nextRow, 2] = type;
        transactionSheet[nextRow, 3] = quantity;
        transactionSheet[nextRow, 4] = notes;
        
        UpdateInventory(productId, type, quantity);
    }
    
    private void UpdateInventory(string productId, string type, int quantity)
    {
        // 查找商品并更新库存
        for (int row = 1; row < inventorySheet.RowCount; row++)
        {
            var id = inventorySheet[row, 0]?.ToString();
            if (id == productId)
            {
                var currentQty = Convert.ToInt32(inventorySheet[row, 2] ?? 0);
                if (type == "入库")
                {
                    inventorySheet[row, 2] = currentQty + quantity;
                }
                else if (type == "出库")
                {
                    inventorySheet[row, 2] = currentQty - quantity;
                }
                break;
            }
        }
    }
    
    private int FindNextEmptyRow(Worksheet sheet)
    {
        for (int row = 1; row < 10000; row++)
        {
            if (sheet[row, 0] == null)
            {
                return row;
            }
        }
        return 1;
    }
}
```

## 20.3 案例三：考勤管理系统

考勤表按「人一行、日期一列」排布，日期列从 1 到 31，后面接出勤天数、缺勤天数、出勤率三列汇总。这种横表适合月度视图，人一眼能看出谁哪天缺勤。

汇总列用 COUNTIF 统计区域里指定符号的个数。方括号里的「√」和「×」是条件参数，本身是文本，写进 C# 字符串时必须转义引号，否则编译不过。示例写成连续双引号的形式，实际代码里需要写成反斜杠转义或改用逐字字符串。

出勤率 = 出勤天数 /（出勤天数 + 缺勤天数）。分母为 0（一天都没记录）时公式会得到除零错误，界面上显示 #DIV/0!。用 IF 判断分母，或者外层套 IFERROR 返回 0，都能让报表干净一些。

```csharp
public class AttendanceSystem
{
    private Worksheet attendanceSheet;
    
    public void Initialize(ReoGridControl grid)
    {
        attendanceSheet = grid.CreateWorksheet("考勤记录");
        SetupAttendanceSheet();
    }
    
    private void SetupAttendanceSheet()
    {
        // 月度考勤表头
        attendanceSheet["A1"] = "员工姓名";
        attendanceSheet["B1"] = "部门";
        
        // 日期列（1-31日）
        for (int day = 1; day <= 31; day++)
        {
            attendanceSheet[0, day + 1] = day.ToString();
        }
        
        attendanceSheet[0, 33] = "出勤天数";
        attendanceSheet[0, 34] = "缺勤天数";
        attendanceSheet[0, 35] = "出勤率";
        
        // 出勤天数公式
        for (int row = 1; row <= 100; row++)
        {
            attendanceSheet[row, 33] = $"=COUNTIF(C{row+1}:AG{row+1},"√")";
            attendanceSheet[row, 34] = $"=COUNTIF(C{row+1}:AG{row+1},"×")";
            attendanceSheet[row, 35] = $"=AH{row+1}/(AH{row+1}+AI{row+1})";
        }
        
        // 设置百分比格式
        attendanceSheet.SetRangeDataFormat("AJ2:AJ101", CellDataFormatFlag.Percent,
            new NumberDataFormatter.NumberFormatArgs { DecimalPlaces = 1 });
        
        // 条件格式（低出勤率标红）
        SetupConditionalFormatting();
    }
    
    private void SetupConditionalFormatting()
    {
        // 当出勤率低于80%时，设置为红色背景
        for (int row = 1; row <= 100; row++)
        {
            var cell = attendanceSheet.GetCell(row, 35);
            if (cell != null)
            {
                // 可以通过事件处理动态设置样式
                attendanceSheet.CellDataChanged += (s, e) =>
                {
                    if (e.Cell.Position.Col == 35)
                    {
                        var value = Convert.ToDouble(e.Cell.Data ?? 0);
                        if (value < 0.8)
                        {
                            attendanceSheet.SetCellStyle(e.Cell.Position, new WorksheetRangeStyle
                            {
                                Flag = PlainStyleFlag.BackColor | PlainStyleFlag.FontColor,
                                BackColor = Color.FromArgb(255, 199, 206),
                                FontColor = Color.FromArgb(156, 0, 6)
                            });
                        }
                    }
                };
            }
        }
    }
    
    public void MarkAttendance(int employeeRow, int day, bool present)
    {
        attendanceSheet[employeeRow, day + 1] = present ? "√" : "×";
    }
}
```

## 20.4 案例四：财务预算表

预算表是标准的「类别行 × 月份列」矩阵，最后一行是月度合计，最后一列是类别合计。结构对称，公式好写：行内求和得到类别合计，列内求和得到月度合计，右下角再求一次总和。

示例先写列头与行头，再给每一行写行合计公式，最后给合计行写列合计公式。公式用 SUM 加明确区域，不用整行整列，避免把标题也计入。

行合计写在第 14 列（N 列），因为表头占了一列，月份 12 列加合计 1 列，正好到 N。列索引从 0 开始，写代码时很容易差一位，示例用 13 作为合计列的下标，对应第 14 列。

```csharp
public class BudgetSheet
{
    public void CreateBudgetSheet(ReoGridControl grid)
    {
        var sheet = grid.CurrentWorksheet;
        
        // 创建预算表结构
        var categories = new[] { "工资", "租金", "水电", "办公用品", "差旅费", "其他" };
        var months = new[] { "1月", "2月", "3月", "4月", "5月", "6月", 
                            "7月", "8月", "9月", "10月", "11月", "12月", "合计" };
        
        // 设置列头
        sheet["A1"] = "费用类别";
        for (int i = 0; i < months.Length; i++)
        {
            sheet[0, i + 1] = months[i];
        }
        
        // 设置行头
        for (int i = 0; i < categories.Length; i++)
        {
            sheet[i + 1, 0] = categories[i];
        }
        
        // 设置合计公式
        for (int row = 1; row <= categories.Length; row++)
        {
            sheet[row, 13] = $"=SUM(B{row+1}:M{row+1})";
        }
        
        // 设置月度合计
        sheet[categories.Length + 1, 0] = "月度合计";
        for (int col = 1; col <= 13; col++)
        {
            char colLetter = (char)('A' + col);
            sheet[categories.Length + 1, col] = $"=SUM({colLetter}2:{colLetter}{categories.Length + 1})";
        }
        
        // 设置样式
        sheet.SetRangeStyles("A1:N1", new WorksheetRangeStyle
        {
            Flag = PlainStyleFlag.FontBold | PlainStyleFlag.BackColor,
            Bold = true,
            BackColor = Color.FromArgb(79, 129, 189)
        });
        
        sheet.SetRangeStyles("N2:N8", new WorksheetRangeStyle
        {
            Flag = PlainStyleFlag.FontBold,
            Bold = true
        });
        
        // 设置货币格式
        sheet.SetRangeDataFormat("B2:N8", CellDataFormatFlag.Currency,
            new CurrencyDataFormatter.CurrencyFormatArgs
            {
                Symbol = "¥",
                DecimalPlaces = 2
            });
    }
}
```

## 20.5 本章小结

本章通过实际案例展示了ReoGrid在各种业务场景中的应用，包括：
- 数据分析报表系统
- 进销存管理
- 考勤管理
- 财务预算表

这些案例展示了ReoGrid的强大功能和实用价值。

四个案例的共性结构比代码本身更值得记：

- 工作表按职责拆分，明细与汇总分开，导出时各取所需；
- 汇总尽量用公式而不是循环算好再写值，数据一变结果自动更新；
- 样式与格式集中设置，区域化调用，不逐格散写；
- 数据验证与条件格式负责约束与提示，业务代码只处理正常路径。

案例里的问题也值得记住：工作簿级加载会让旧的工作表引用失效，跨表引用语法随版本不同，靠字符串拼列号在宽表上会出错，循环里订阅事件会造成重复处理。这些问题在真实项目里都会遇到，识别得出来就能省下排查时间。

写业务表格还有一个顺序问题：先定数据结构，再定公式，最后做样式。反过来做，样式改一次就要重排一次，返工量很大。

## 20.6 系列教程总结

通过本系列20章的学习，您应该已经掌握：
1. ReoGrid的基础概念和架构
2. 环境配置和项目创建
3. 数据操作和格式化
4. 样式和外观定制
5. 公式计算和图表
6. 文件导入导出
7. 事件处理和交互
8. 性能优化和最佳实践
9. 高级功能和扩展开发
10. 实战案例应用

这二十章可以分成四组来回顾。第一组是基础：控件是什么、怎么装、有哪些核心对象，对应第一到第三章。第二组是数据与样式：读写、格式化、样式、公式、验证与条件格式，对应第四到第八章，这一组决定了表格「能不能用」。第三组是显示与输出：视图、分组、图表、文件、打印，对应第九到第十三章，决定了「好不好用、能不能交付」。第四组是进阶：事件、单元格类型、脚本、性能、WPF、扩展与案例，对应第十四到第二十章，决定了「能不能接进真实系统」。

如果要给学习路径一个建议：先把第一组和第二组吃透，能独立做出一个带公式和格式的表格；再去碰事件与自定义类型，那些是需要具体需求驱动的；性能与多线程放到最后，没有真实数据量做参照，优化容易变成空谈。

ReoGrid 的文档不算齐全，很多细节要靠读源码和试。遇到 API 行为不确定时，写一个最小的测试窗口，放两个单元格试一下，比在项目里反复调试快得多。这个习惯比记住任何一个 API 都有价值。
