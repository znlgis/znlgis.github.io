# 第七章：公式与计算引擎

公式让表格从静态数据变成会计算的文档。ReoGrid 的计算引擎在单元格数据变化时重新求值，把结果写回单元格供显示，同时保留公式文本本身，用户点开单元格看到的是等号开头的表达式，而不是结果。

这一章从最基础的单元格引用讲起，覆盖内置函数、自定义函数、自动计算的开关和错误值。示例都以字符串形式把公式赋给单元格，写法是 sheet["A3"] = "=A1+A2"。等号是必须的，没有等号的字符串会被当成普通文本。

先给一个预期管理：ReoGrid 的函数库覆盖常用类别，但不是 Excel 函数全集。遇到新函数先在当前版本里试算一次，确认返回的不是 #NAME?；不要照着 Excel 文档直接抄不认识的函数名。

## 7.1 公式基础

### 7.1.1 公式概述

ReoGrid支持类似Excel的公式计算功能，可以使用内置函数和自定义函数。

公式的载体是字符串。赋值时以等号开头，引擎就按公式解析；否则按普通文本或数字处理。示例三行分别演示算术表达式、求和与平均值、最大值，结果写在注释里，便于对照。

公式求值是自动的：A1 或 A2 的值变化后，A3 会重新计算。这个联动由依赖关系驱动，引擎记录每个公式引用了哪些单元格，被引用的单元格变化时把依赖它的公式标记为待计算，再按顺序求值。

公式单元格里保存两份信息：公式文本和计算结果。读取 Cell.Data 拿到的是结果，读取 Cell.Formula 才是公式本身。数据绑定或导出时搞清楚要哪一个，否则会拿到一列数值而不是一列公式。

```csharp
using unvell.ReoGrid;

public class FormulaBasics
{
    private Worksheet sheet;
    
    /// <summary>
    /// 基本公式使用
    /// </summary>
    public void BasicFormulas()
    {
        // 简单算术
        sheet["A1"] = 10;
        sheet["A2"] = 20;
        sheet["A3"] = "=A1+A2";  // 结果: 30
        
        // 使用函数
        sheet["B1"] = "=SUM(A1:A2)";  // 结果: 30
        sheet["B2"] = "=AVERAGE(A1:A2)";  // 结果: 15
        sheet["B3"] = "=MAX(A1:A2)";  // 结果: 20
    }
}
```

示例里的公式直接写字符串，C# 中双引号要转义，或者用前面加 @ 的逐字字符串。公式里包含中文文本时，注意文件编码与引号配对，写成 "及格" 而不是漏掉一侧引号，否则解析会失败并显示错误值。

公式字符串没有编译期检查。函数名拼错、括号不配对、引用写错，都只能在运行时以 #NAME?、#VALUE! 这类错误值的形式暴露。可以在保存或提交前遍历一遍公式单元格，检查 FormulaStatus 或错误值，把问题挡在用户看到之前。

### 7.1.2 公式语法

引用分四类：相对引用 A1、绝对引用 $A$1、混合引用 $A1 与 A$1。相对引用在复制公式时会随位置偏移，绝对引用不会。$ 加在列号前表示列固定，加在行号前表示行固定，两个都加就是完全固定。

区域引用用冒号连接起止单元格，A1:A10 表示同一列连续十行，B:B 表示整列，1:1 表示整行。整列整行引用写起来短，但计算范围大，参与运算的单元格越多，求值开销越高，几十万行的表上尤其明显。

多区域引用用逗号分隔，一个函数可以接收多个不连续区域。示例中 SUM(A1:A5,B1:B5) 会把两块区域的值一起求和，适合汇总分布在表格不同位置的数据。

```csharp
public class FormulaSyntax
{
    public void DemonstrateSyntax(Worksheet sheet)
    {
        // 单元格引用
        sheet["C1"] = "=A1";  // 相对引用
        sheet["C2"] = "=$A$1";  // 绝对引用
        sheet["C3"] = "=$A1";  // 混合引用（列绝对）
        sheet["C4"] = "=A$1";  // 混合引用（行绝对）
        
        // 区域引用
        sheet["D1"] = "=SUM(A1:A10)";  // 区域求和
        sheet["D2"] = "=AVERAGE(B:B)";  // 整列平均
        sheet["D3"] = "=MAX(1:1)";  // 整行最大值
        
        // 多区域
        sheet["E1"] = "=SUM(A1:A5,B1:B5)";  // 多个区域
    }
}
```

相对引用与绝对引用的差别，在单个格子上看不出来，复制公式后才显现。把 =A1 从 B1 复制到 B2，公式会变成 =A2；把 =$A$1 复制到 B2，公式仍是 =$A$1。写模板时用绝对引用锁定参数格，用相对引用跟随数据行，是最常用的组合。

引用还支持跨工作表。写法通常是「工作表名 + 感叹号 + 单元格」，工作表名含空格或中文时用单引号包起来，例如 =SUM('1月'!B2:B10)。是否能解析成功取决于版本对跨表语法的支持程度，写完先试算一次确认结果。

## 7.2 内置函数

### 7.2.1 数学函数

数学函数是使用频率最高的一类。SUM 把区域或若干个参数相加，AVERAGE 求算术平均，MIN 与 MAX 取极值，COUNT 统计数值个数。示例把它们放在同一列的第 10 行，对上面九行做汇总，这是报表里最常见的「明细加合计」结构。

单参数函数演示了标量运算：ABS 取绝对值，ROUND 四舍五入到指定位数，POWER 求幂，SQRT 求平方根。ROUND 的第二个参数是小数位数，0 表示取整，写负数表示对整数位四舍五入，例如 ROUND(1234.5, -2) 得到 1200。

函数名不区分大小写，SUM 与 sum 等价。参数之间用逗号分隔，区域参数与单个单元格参数可以混用，例如 SUM(A1:A5, C1, 100)。

```csharp
public class MathFunctions
{
    public void UseMathFunctions(Worksheet sheet)
    {
        // SUM - 求和
        sheet["A10"] = "=SUM(A1:A9)";
        
        // AVERAGE - 平均值
        sheet["B10"] = "=AVERAGE(B1:B9)";
        
        // MIN - 最小值
        sheet["C10"] = "=MIN(C1:C9)";
        
        // MAX - 最大值
        sheet["D10"] = "=MAX(D1:D9)";
        
        // COUNT - 计数
        sheet["E10"] = "=COUNT(E1:E9)";
        
        // ABS - 绝对值
        sheet["F1"] = "=ABS(-10)";  // 结果: 10
        
        // ROUND - 四舍五入
        sheet["G1"] = "=ROUND(3.14159, 2)";  // 结果: 3.14
        
        // POWER - 幂运算
        sheet["H1"] = "=POWER(2, 3)";  // 结果: 8
        
        // SQRT - 平方根
        sheet["I1"] = "=SQRT(16)";  // 结果: 4
    }
}
```

COUNT 只统计数值单元格，文本与空格不计入；如果需要统计非空单元格，应当用 COUNTA。两者名字接近，用错会让合计数偏小，排查时容易被忽略。

数学函数遇到无法计算的情况会返回错误值。SQRT 传负数得到 #NUM!，除零得到 #DIV/0!，文本参与算术运算得到 #VALUE!。这些错误会沿引用链传播，一个单元格出错，引用它的公式一起错。

浮点误差在这类计算里无法回避。0.1 加 0.2 的结果不一定是 0.3，做金额汇总时建议在最后一步统一四舍五入，而不是中间每一步都舍入。

### 7.2.2 逻辑函数

逻辑函数把判断交给公式，省去在界面层写条件分支。IF 接收三个参数：条件、条件成立时的值、条件不成立时的值。条件是一个返回 true 或 false 的表达式，例如 B1>60。

AND 与 OR 接收多个条件，分别表示全部成立和任意成立；NOT 对单个条件取反。它们常作为 IF 的条件参数使用，也可以单独放在单元格里返回 true/false 文本。

嵌套 IF 可以表达多段分级，示例把成绩分成优秀、良好、及格、不及格四档。嵌套层数多了以后可读性急剧下降，判断超过三层时考虑换查表方式：把分级规则写在一小块区域里，用查找函数匹配。

```csharp
public class LogicalFunctions
{
    public void UseLogicalFunctions(Worksheet sheet)
    {
        // IF - 条件判断
        sheet["A1"] = "=IF(B1>60, \"及格\", \"不及格\")";
        
        // AND - 与运算
        sheet["A2"] = "=AND(B2>0, B2<100)";
        
        // OR - 或运算
        sheet["A3"] = "=OR(B3<0, B3>100)";
        
        // NOT - 非运算
        sheet["A4"] = "=NOT(B4=0)";
        
        // 嵌套IF
        sheet["A5"] = "=IF(B5>=90, \"优秀\", IF(B5>=80, \"良好\", IF(B5>=60, \"及格\", \"不及格\")))";
    }
}
```

IF 的两个分支可以返回不同类型：一段文本、一个数字、甚至是另一个公式。这给了公式很大的灵活性，代价是结果类型不固定，下游对它做数值运算时可能出错，设计时尽量让分支返回同一类型。

逻辑值参与算术运算时，true 按 1 处理，false 按 0 处理。这个规则让 SUM(B1>0) 这类写法在某些场景下可用，但可读性差，建议仍用 IF 明确写出结果。

条件里比较文本要加引号，中文文本也一样。写成 IF(B1="是",...) 而漏掉引号，解析器会把它当成单元格引用或名称，得到 #NAME? 或错误的比较结果。

### 7.2.3 文本函数

文本函数用于拼接、截取和大小写转换。CONCATENATE 把多个参数按顺序连成一串，经常用来把姓和名、省和市拼在一起；LEFT、RIGHT、MID 按位置截取，LEN 返回字符数，UPPER 与 LOWER 做大小写转换。

MID 的三个参数依次是文本、起始位置、截取长度，起始位置从 1 开始，不是 0。这一点与大多数编程语言的字符串下标不同，写惯了代码的人第一次用容易截错一位。

LEN 统计的是字符数，中英文都算一个字符。需要按字节统计时要找对应的字节函数，直接用 LEN 处理编码长度相关的逻辑会算错。

```csharp
public class TextFunctions
{
    public void UseTextFunctions(Worksheet sheet)
    {
        // CONCATENATE - 连接文本
        sheet["A1"] = "=CONCATENATE(B1, \" \", C1)";
        
        // LEFT - 左侧字符
        sheet["A2"] = "=LEFT(B2, 3)";
        
        // RIGHT - 右侧字符
        sheet["A3"] = "=RIGHT(B3, 3)";
        
        // MID - 中间字符
        sheet["A4"] = "=MID(B4, 2, 5)";
        
        // LEN - 长度
        sheet["A5"] = "=LEN(B5)";
        
        // UPPER - 大写
        sheet["A6"] = "=UPPER(B6)";
        
        // LOWER - 小写
        sheet["A7"] = "=LOWER(B7)";
    }
}
```

文本拼接的结果仍然是文本，不是数字。把两个数字用 CONCATENATE 拼起来，得到的是 "1234" 这样的字符串，参与求和时可能被当成 0 或报错。需要数值结果时用算术运算，不要用文本函数绕一圈。

截取超出长度的部分时，LEFT 与 RIGHT 会返回能取到的全部内容，不会报错；MID 的起始位置超过文本长度则返回空串。写死长度的公式在数据变长后会截断，给足余量或先判断 LEN 更稳妥。

### 7.2.4 日期时间函数

日期函数以序列值参与计算。单元格里的日期在内部是一个数值，加 1 表示加一天，两个日期相减得到相差的天数。示例里的 NOW 与 TODAY 分别返回当前时刻与当天零点。

YEAR、MONTH、DAY 从日期里取出年月日分量，DATE 用三个数字构造日期。DATE(2024, 12, 31) 得到 2024 年最后一天；月份写 13 会自动进位到次年 1 月，这类宽松处理在算月末日期时很有用。

DATEDIF 计算两个日期之间的差值，第三个参数决定单位，d 是天数，m 是整月数，y 是整年数。单位字母要加引号，写错单位会得到错误值。

```csharp
public class DateTimeFunctions
{
    public void UseDateTimeFunctions(Worksheet sheet)
    {
        // NOW - 当前日期时间
        sheet["A1"] = "=NOW()";
        
        // TODAY - 今天日期
        sheet["A2"] = "=TODAY()";
        
        // YEAR - 年份
        sheet["A3"] = "=YEAR(B3)";
        
        // MONTH - 月份
        sheet["A4"] = "=MONTH(B4)";
        
        // DAY - 日
        sheet["A5"] = "=DAY(B5)";
        
        // DATE - 构造日期
        sheet["A6"] = "=DATE(2024, 12, 31)";
        
        // DATEDIF - 日期差
        sheet["A7"] = "=DATEDIF(B7, C7, \"d\")";  // 天数差
    }
}
```

NOW 与 TODAY 是易失函数，每次重算都会取当前时间，因此频繁重算会让表格看起来一直在变。需要固定时间戳时，把时间写入单元格当普通值，不要在报表里到处放 NOW。

日期显示格式与日期值要分开设置。单元格里是日期值，显示成什么写法由数据格式决定；只改显示格式不会改值，两个日期相减仍然按天数算。

时区与区域设置在日期计算里影响很小，日期序列值本身不带时区，NOW 取的是本机时间。跨时区协作的报表要注明基准时区，避免接收方按自己的时间理解。

## 7.3 自定义函数

### 7.3.1 创建自定义函数

内置函数覆盖不到的业务计算，可以写成自定义函数。示例定义一个 MYCALC，接收两个参数，返回 a * b + 10。类继承 NamedFunction，重写 Name 与 Invoke：Name 是公式里调用的名字，Invoke 拿到参数数组并返回计算结果，参数个数与类型都要在方法内部自己校验。

注册发生在控件层，调用 grid.RegisterFunction 传入实例，之后所有工作表都能用这个函数名。注册要在加载含该函数的文件之前完成，否则公式初次求值时找不到函数，会留下 #NAME?，需要重算才能恢复。

Invoke 的返回值类型决定公式结果的类型。返回 double，单元格就是数值；返回 string，就是文本。参数从公式里传进来时是 object，可能是数字、文本或引用求值后的结果，Convert.ToDouble 之前先判断空值和类型，避免抛异常。

```csharp
using unvell.ReoGrid.Formula;

[CustomFunction]
public class MyCustomFunction : NamedFunction
{
    public override string Name => "MYCALC";
    
    public override object Invoke(object[] args)
    {
        if (args.Length < 2) return 0;
        
        double a = Convert.ToDouble(args[0]);
        double b = Convert.ToDouble(args[1]);
        
        return a * b + 10;
    }
}

// 注册使用
public class RegisterCustomFunction
{
    public void Register(ReoGridControl grid)
    {
        // 注册自定义函数
        grid.RegisterFunction(new MyCustomFunction());
        
        // 使用自定义函数
        var sheet = grid.CurrentWorksheet;
        sheet["A1"] = 5;
        sheet["A2"] = 3;
        sheet["A3"] = "=MYCALC(A1, A2)";  // 结果: 25
    }
}
```

[CustomFunction] 特性用于标记可被公式引擎识别的类，是否必须取决于版本：有些版本靠特性扫描，有些版本只认显式注册。两种都做不会有坏处，可以保证换版本后依然可用。

自定义函数出错时不要让异常直接抛出，异常会中断整次重算，用户看到的是整片单元格停更。捕获异常并返回一个错误值或 0，至少能让其余公式继续算。

函数名建议加业务前缀，避免与将来内置函数重名。重名时哪个生效取决于注册顺序，出现问题时很难排查。

### 7.3.2 多参数自定义函数

WAVG 演示了成对参数的处理：值、权重、值、权重这样排列，参数个数必须是偶数。函数内部把参数两两配对，算出加权和与权重和，再做除法，权重总和为 0 时返回 0，避免除零。

这种「参数个数不固定、按约定成对传入」的写法，在 Excel 里也有对应例子。使用时调用方要保证参数个数正确，参数缺失或奇数个都不会报错，只会算出错误结果，因此在函数开头做一次奇偶校验很有必要。

自定义函数的执行频率比想象中高。单元格值一变，所有依赖它的公式重算，函数就被调用一次。函数体里做数据库查询、网络请求这类耗时操作，会让整张表卡住，重计算逻辑必须保持纯内存。

```csharp
[CustomFunction]
public class WeightedAverage : NamedFunction
{
    public override string Name => "WAVG";
    
    public override object Invoke(object[] args)
    {
        if (args.Length % 2 != 0) return 0;
        
        double sum = 0;
        double weightSum = 0;
        
        for (int i = 0; i < args.Length; i += 2)
        {
            double value = Convert.ToDouble(args[i]);
            double weight = Convert.ToDouble(args[i + 1]);
            
            sum += value * weight;
            weightSum += weight;
        }
        
        return weightSum == 0 ? 0 : sum / weightSum;
    }
}
```

注册自定义函数之后建议写一个自检：在工作表里放一个调用该函数的单元格，重新计算后检查结果是否为预期值。自检放在程序启动阶段，能在用户打开正式数据前发现版本不匹配、函数名冲突这类问题。

函数的签名与公式里的调用必须一致。参数个数、引号、逗号都按公式语法写，例如 =WAVG(A1,B1,A2,B2)。写成 WAVG(A1:B2) 会传入一个区域引用，函数内部拿到的是区域对象而非单个值，结果往往不对。

## 7.4 公式计算控制

### 7.4.1 自动计算设置

自动计算是默认行为，改一个单元格，相关公式立刻重算，适合交互式编辑。导入大量数据或批量生成公式时，每次赋值都触发重算，总耗时会成倍放大，这时应当临时关掉自动计算，数据写完再手动算一次。

SetSettings 的第一个参数是设置项名称，Formula_AutoCalculate 控制是否自动计算，第二个参数是布尔值。设置作用于工作簿层，对其中所有工作表生效。

关掉自动计算后，公式单元格显示的是上一次的结果，数据可能已经过期。手动调用 RecalculateAll 才会更新全部公式；只更新某一块区域时找对应区域级的重算方法，能省下不少时间。

```csharp
public class FormulaCalculation
{
    public void ConfigureCalculation(ReoGridControl grid)
    {
        // 启用自动计算
        grid.SetSettings(WorkbookSettings.Formula_AutoCalculate, true);
        
        // 禁用自动计算
        grid.SetSettings(WorkbookSettings.Formula_AutoCalculate, false);
    }
    
    /// <summary>
    /// 手动触发计算
    /// </summary>
    public void ManualCalculate(Worksheet sheet)
    {
        sheet.RecalculateAll();
    }
}
```

自动计算的开关是全局设置，忘了恢复会让后续所有操作都失去实时反馈。用 try/finally 包住批量操作，在 finally 里恢复设置，比在正常路径末尾写一行更可靠。

重算的代价与公式数量和依赖链长度成正比。整表重算在几十万单元格上可能耗时数秒，界面会明显卡顿。批量导入场景可以把重算安排在加载完成、界面回到空闲之后，或者分块重算并处理进度。

保存文件时是否需要先重算，取决于接收方是否会用计算结果。只存公式不存结果，接收方打开时会自己算；既要公式又要缓存结果的格式，建议在保存前显式重算一次。

### 7.4.2 循环引用处理

循环引用是公式指向了自己：A1 的公式引用 A2，A2 的公式又引用 A1。引擎在依赖图里检测到环，无法确定求值顺序，于是把参与循环的单元格标记为循环引用错误，结果是 #REF! 或对应的错误状态。

示例先检查单元格有没有公式（HasFormula），再看 FormulaStatus 是否为循环引用。两个判断缺一不可：没有公式的单元格没有状态可查，直接访问可能拿到默认值。

FormulaStatus 这个成员的名称与可用值随版本略有差异，写代码时以当前引用的程序集为准。查不到状态时可以用结果值兜底：结果等于 #REF! 且公式里引用了自身所在单元格，基本就能判定是循环引用。

```csharp
public class CircularReference
{
    public void HandleCircular(Worksheet sheet)
    {
        // ReoGrid会自动检测循环引用
        // 循环引用会导致 #REF! 错误
        
        // 检查单元格是否有错误
        var cell = sheet.GetCell("A1");
        if (cell != null && cell.HasFormula)
        {
            // 检查计算错误
            if (cell.FormulaStatus == FormulaStatus.CircularReference)
            {
                Console.WriteLine("检测到循环引用");
            }
        }
    }
}
```

循环引用不一定是错误，有些业务场景需要迭代计算（例如按比例分摊的成本表）。ReoGrid 没有提供迭代计算选项时，把公式改成一次性计算，或者用代码循环算到收敛，比在表格里留一个环更可控。

排查循环引用时从结果反推：找到显示错误的单元格，逐个展开它的引用，看哪条引用链又指回起点。公式多时先在副本里删掉可疑区域，能更快定位。

## 7.5 公式错误处理

### 7.5.1 常见公式错误

错误值按原因分类，见下表。识别错误类型是排查的第一步，不同类型的修法完全不同：类型错误改数据或转换，引用错误改地址，除零加保护。

| 错误值 | 含义 | 常见原因 |
| --- | --- | --- |
| #DIV/0! | 除数为零 | 分母单元格为空或为 0，示例里直接写 10/0 |
| #NAME? | 名称无法识别 | 函数名拼错，或自定义函数未注册 |
| #REF! | 引用无效 | 引用的行列被删除，或地址超出范围 |
| #VALUE! | 值类型不匹配 | 文本参与算术运算，示例里 SUM 收到文本 |
| #NUM! | 数值无法计算 | 对负数开平方、参数超出定义域 |

示例第二段演示 IFERROR：第一个参数是待检查的表达式，第二个参数是出错时返回的替代值。它把错误值换成 0 或一段提示文本，报表里不会出现刺眼的红色错误码。

```csharp
public class FormulaErrors
{
    public void HandleErrors(Worksheet sheet)
    {
        // #DIV/0! - 除以零
        sheet["A1"] = "=10/0";
        
        // #NAME? - 未识别的函数名
        sheet["A2"] = "=UNKNOWNFUNC()";
        
        // #REF! - 无效引用
        sheet["A3"] = "=A100000";
        
        // #VALUE! - 值错误
        sheet["A4"] = "=SUM(\"text\")";
        
        // #NUM! - 数字错误
        sheet["A5"] = "=SQRT(-1)";
    }
    
    /// <summary>
    /// 使用IFERROR处理错误
    /// </summary>
    public void UseIFERROR(Worksheet sheet)
    {
        sheet["B1"] = "=IFERROR(A1/B1, 0)";  // 如果出错返回0
        sheet["B2"] = "=IFERROR(A2, \"错误\")";  // 如果出错返回文本
    }
}
```

IFERROR 会掩盖问题，用之前想清楚是真错了还是数据尚未填。分母为空是「还没填」，返回 0 会让人以为结果是零；这种情况更适合返回空串或提示文本，让读者知道数据缺失。

另一个常见做法是用 ISERROR 或 ISNA 判断错误后再分支处理，比 IFERROR 更细。函数是否可用同样以当前版本为准，试算一次最直接。

## 7.6 本章小结

本章介绍了ReoGrid的公式与计算引擎，包括内置函数的使用和自定义函数的创建。

公式的使用可以归成三条主线：

- 写法：等号开头、引用用 A1 或 $A$1 形式、区域用冒号、多区域用逗号；
- 能力：内置函数覆盖数学、逻辑、文本、日期几类，业务特有计算写成自定义函数注册到控件；
- 控制：自动计算可以临时关闭，循环引用要主动检测，错误值用 IFERROR 之类的手段兜底。

实际项目里最容易出问题的是计算时机，而不是公式本身。批量导入时忘了关自动计算，界面会卡；关掉之后忘了恢复，用户改数据看不到变化。这两个坑都能用一个 try/finally 结构解决。

自定义函数要当成业务代码来维护：加前缀、做参数校验、捕获异常、处理空值。函数体里不要有 IO，也不要依赖可变的外部状态，否则同样的公式在不同时刻会算出不同结果，问题极难复现。

下一章讨论数据验证与条件格式，两者都依赖单元格的值变化，和本章的自动计算机制会一起工作。
