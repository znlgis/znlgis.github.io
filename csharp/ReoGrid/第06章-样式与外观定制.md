# 第六章：样式与外观定制

上一章把数据写进了单元格，这一章解决「写进去的东西怎么好看、怎么可读」。表格的外观由三层组成：单元格样式（字体、颜色、边框、对齐）、区域级排版（行高列宽、合并），以及整体配色（主题）。本章集中在样式层，示例都是对 Range 调用 SetRangeStyles，参数是一个 WorksheetRangeStyle 对象。

ReoGrid 的样式 API 有一条贯穿全章的规则：Flag 决定改什么，属性决定改成什么。漏掉 Flag，属性写了也不生效；Flag 写全了，没赋值的属性会取默认值，反而可能把已有样式覆盖回默认。这套机制初看啰嗦，好处是可以只改一个属性而不动其他属性，做局部高亮时很省事。

实际项目里不要把这些样式散落在各处。推荐先定义一组模板（本章 6.5 节），再按业务语义套用，这样换配色时只改模板，不用翻遍界面代码。

## 6.1 字体样式

### 6.1.1 基本字体设置

字体样式拆成六个属性：字体名、字号、颜色、粗体、斜体、下划线，另外还有删除线。每个属性对应 PlainStyleFlag 里的一个标志位，示例把它们分别写成独立方法，是为了演示单个属性的开关，实际使用时应按需要合并成一次调用。

字号单位是磅（point），12 磅约等于 Word 里的小四，表格正文常用 9 到 11 磅，表头 11 到 12 磅。字号调大会撑高行高，行高不够时文字会被裁掉，改完字号记得看一下行高。

颜色是 System.Drawing.Color，不是字符串，也不是 WPF 的颜色类型。常用颜色可以直接写 Color.Red、Color.LightGray，需要精确色值时用 Color.FromArgb(r, g, b)，三个分量都是 0 到 255。

```csharp
using System.Drawing;
using unvell.ReoGrid.Data;

public class FontStyling
{
    private Worksheet sheet;
    
    public FontStyling(Worksheet worksheet)
    {
        sheet = worksheet;
    }
    
    /// <summary>
    /// 设置字体名称和大小
    /// </summary>
    public void SetFontBasics(string range)
    {
        sheet.SetRangeStyles(range, new WorksheetRangeStyle
        {
            Flag = PlainStyleFlag.FontName | PlainStyleFlag.FontSize,
            FontName = "微软雅黑",
            FontSize = 12
        });
    }
    
    /// <summary>
    /// 设置字体颜色
    /// </summary>
    public void SetFontColor(string range, Color color)
    {
        sheet.SetRangeStyles(range, new WorksheetRangeStyle
        {
            Flag = PlainStyleFlag.FontColor,
            FontColor = color
        });
    }
    
    /// <summary>
    /// 设置粗体
    /// </summary>
    public void SetBold(string range, bool bold = true)
    {
        sheet.SetRangeStyles(range, new WorksheetRangeStyle
        {
            Flag = PlainStyleFlag.FontBold,
            Bold = bold
        });
    }
    
    /// <summary>
    /// 设置斜体
    /// </summary>
    public void SetItalic(string range, bool italic = true)
    {
        sheet.SetRangeStyles(range, new WorksheetRangeStyle
        {
            Flag = PlainStyleFlag.FontItalic,
            Italic = italic
        });
    }
    
    /// <summary>
    /// 设置下划线
    /// </summary>
    public void SetUnderline(string range, bool underline = true)
    {
        sheet.SetRangeStyles(range, new WorksheetRangeStyle
        {
            Flag = PlainStyleFlag.FontUnderline,
            Underline = underline
        });
    }
    
    /// <summary>
    /// 设置删除线
    /// </summary>
    public void SetStrikethrough(string range, bool strikethrough = true)
    {
        sheet.SetRangeStyles(range, new WorksheetRangeStyle
        {
            Flag = PlainStyleFlag.FontStrikethrough,
            Strikethrough = strikethrough
        });
    }
}
```

删除线和下划线这类修饰在报表里有明确语义：删除线表示作废、下划线表示强调或链接。把它们和颜色搭配使用比单纯改颜色更清晰，红色加删除线表示「这笔已经取消」，比只标红少一层歧义。

字体的可用性由运行环境决定。代码里写「微软雅黑」，在 Windows 上一般没问题，换到没有该字体的机器上会回退到默认字体，行高、宽度都可能变。对字体有硬性要求的场景，发布时把字体随程序分发，或改用系统一定存在的字体。

大量单元格逐个设置字体是最慢的做法。同一列的字体通常一致，按列或按区域设置一次即可；需要遍历时放进 BeginUpdate 块，避免每次都触发重绘。

### 6.1.2 组合字体样式

组合样式的意义在于减少调用次数。一次 SetRangeStyles 里把字体名、字号、颜色、粗体一起写进 Flag，控件只做一次区域失效，比连续调四次单属性方法更快，也更容易保证几个属性同时生效。

示例把标题样式和强调样式封装成方法，参数是 Worksheet 和区域。这种写法比在界面代码里直接拼样式对象好维护：标题的字号和颜色只在一处定义，改版式时不用逐个找。

注意这里用到了 Color.DarkBlue，说明该文件已经引用了 System.Drawing。把这段代码复制到新文件时，如果编译报找不到 Color，补一行 using System.Drawing 即可。

```csharp
public class CombinedFontStyles
{
    /// <summary>
    /// 设置标题样式
    /// </summary>
    public void SetTitleStyle(Worksheet sheet, string range)
    {
        sheet.SetRangeStyles(range, new WorksheetRangeStyle
        {
            Flag = PlainStyleFlag.FontName | 
                   PlainStyleFlag.FontSize | 
                   PlainStyleFlag.FontColor | 
                   PlainStyleFlag.FontBold,
            FontName = "微软雅黑",
            FontSize = 16,
            FontColor = Color.DarkBlue,
            Bold = true
        });
    }
    
    /// <summary>
    /// 设置强调文本样式
    /// </summary>
    public void SetEmphasisStyle(Worksheet sheet, string range)
    {
        sheet.SetRangeStyles(range, new WorksheetRangeStyle
        {
            Flag = PlainStyleFlag.FontColor | 
                   PlainStyleFlag.FontItalic | 
                   PlainStyleFlag.FontBold,
            FontColor = Color.Red,
            Italic = true,
            Bold = true
        });
    }
}
```

组合样式里最容易出错的是 Flag 与属性不匹配：Flag 写了 FontBold 却忘了给 Bold 赋值，粗体标志被写入但值为 false，反而把原本的粗体清掉了。样式对象是按 Flag 全量覆盖，不是只改有值的项，赋值时把 Flag 和属性当成一对来写。

标题样式通常还要配合合并与居中。字号放大后，行高和列宽都要跟着调，否则标题会挤在单元格里。样式设置和尺寸设置放在一起调试，比分开试错省时间。

## 6.2 单元格背景

### 6.2.1 背景颜色

背景色用于分区：表头一行深色、数据区交替浅色、只读区灰色，用户扫一眼就知道哪里能改。示例给了三种最常见的用法，分别对应高亮、表头和只读区域。

透明是背景色的一个特例。不设置 BackColor 时单元格背景透明，会露出工作表的底色；显式设置成白色则是一块实色。两者在视觉上接近，但导出到 Excel 时语义不同，报表模板里统一用实色更稳妥。

交替行颜色用代码循环设置，以行号奇偶判断颜色。表格很大时这个循环会执行几百上千次，记得包在 BeginUpdate 里；另一种做法是只对可见区域设置，滚动时再补，适合几十万行的数据表。

```csharp
public class BackgroundStyling
{
    private Worksheet sheet;
    
    /// <summary>
    /// 设置单色背景
    /// </summary>
    public void SetBackgroundColor(string range, Color color)
    {
        sheet.SetRangeStyles(range, new WorksheetRangeStyle
        {
            Flag = PlainStyleFlag.BackColor,
            BackColor = color
        });
    }
    
    /// <summary>
    /// 常用背景色设置
    /// </summary>
    public void SetCommonBackgrounds()
    {
        // 浅黄色背景（突出显示）
        sheet.SetRangeStyles("A1:A10", new WorksheetRangeStyle
        {
            Flag = PlainStyleFlag.BackColor,
            BackColor = Color.LightYellow
        });
        
        // 浅蓝色背景（表头）
        sheet.SetRangeStyles("A1:Z1", new WorksheetRangeStyle
        {
            Flag = PlainStyleFlag.BackColor,
            BackColor = Color.LightBlue
        });
        
        // 浅灰色背景（只读区域）
        sheet.SetRangeStyles("A1:A5", new WorksheetRangeStyle
        {
            Flag = PlainStyleFlag.BackColor,
            BackColor = Color.LightGray
        });
    }
    
    /// <summary>
    /// 交替行颜色
    /// </summary>
    public void SetAlternateRowColors(int startRow, int endRow, int startCol, int endCol)
    {
        for (int row = startRow; row <= endRow; row++)
        {
            Color bgColor = row % 2 == 0 
                ? Color.White 
                : Color.FromArgb(242, 242, 242);
            
            sheet.SetRangeStyles(
                new RangePosition(row, startCol, 1, endCol - startCol + 1),
                new WorksheetRangeStyle
                {
                    Flag = PlainStyleFlag.BackColor,
                    BackColor = bgColor
                });
        }
    }
}
```

SetCommonBackgrounds 里三个区域的设置方式是一样的，区别只在颜色和范围。实际项目里把颜色抽成常量或配置项，不要在业务代码里散落 Color.FromArgb(242, 242, 242) 这样的魔法值，改配色时才知道要改哪里。

背景色和条件格式会互相影响。第八章的条件格式规则如果也设置了 BackColor，最终显示哪个取决于规则优先级与样式应用顺序，调试时先确认是谁覆盖了谁，不要只看单元格当前的样式属性。

## 6.3 边框样式

### 6.3.1 基本边框设置

边框有两种设置路径。一种是把四条边写进 RangeBorderStyle，随 SetRangeStyles 一起生效；另一种是调用 SetRangeBorders，用 BorderPositions 指定要给区域的哪一部分加边框。前者适合给单元格四边统一描边，后者适合画整块表格的外框和内部网格。

BorderPositions 的常用取值有三个：All 给每个单元格四边都加，Outside 只加区域外沿，Inside 只加区域内部的分隔线。做报表时典型组合是先 Inside 画细网格，再 Outside 画粗外框，两次调用就能得到常见的三线表效果。

线型用 BorderLineStyle 枚举，除了实线还有虚线、点线、粗实线和双线。粗线的实际宽度由渲染器决定，不同显示缩放比例下看起来会略有差异，打印前用预览确认。

```csharp
using unvell.ReoGrid.Graphics;

public class BorderStyling
{
    private Worksheet sheet;
    
    /// <summary>
    /// 设置全边框
    /// </summary>
    public void SetAllBorders(string range, Color color, BorderLineStyle style)
    {
        sheet.SetRangeStyles(range, new WorksheetRangeStyle
        {
            Flag = PlainStyleFlag.Border,
            Border = new RangeBorderStyle
            {
                Left = new BorderStyle { Color = color, Style = style },
                Top = new BorderStyle { Color = color, Style = style },
                Right = new BorderStyle { Color = color, Style = style },
                Bottom = new BorderStyle { Color = color, Style = style }
            }
        });
    }
    
    /// <summary>
    /// 设置外边框
    /// </summary>
    public void SetOutsideBorder(string range, Color color, BorderLineStyle style)
    {
        sheet.SetRangeBorders(
            new RangePosition(range), 
            BorderPositions.Outside,
            new BorderStyle { Color = color, Style = style });
    }
    
    /// <summary>
    /// 设置内边框
    /// </summary>
    public void SetInsideBorder(string range, Color color, BorderLineStyle style)
    {
        sheet.SetRangeBorders(
            new RangePosition(range), 
            BorderPositions.Inside,
            new BorderStyle { Color = color, Style = style });
    }
    
    /// <summary>
    /// 设置特定边
    /// </summary>
    public void SetSpecificBorders(string range)
    {
        sheet.SetRangeStyles(range, new WorksheetRangeStyle
        {
            Flag = PlainStyleFlag.Border,
            Border = new RangeBorderStyle
            {
                Top = new BorderStyle 
                { 
                    Color = Color.Black, 
                    Style = BorderLineStyle.Solid 
                },
                Bottom = new BorderStyle 
                { 
                    Color = Color.Black, 
                    Style = BorderLineStyle.Solid 
                }
            }
        });
    }
}
```

设置边框时要注意单元格的共享边。相邻两个单元格之间的那条线，对左边单元格来说是右边框，对右边单元格来说是左边框，分别设置会互相覆盖。给整块区域设置 Inside 能避免这种手工对齐，渲染时也只画一条线。

边框的覆盖顺序是后设优先。先给区域设外框再逐个单元格设内线，外框边缘可能被内线盖掉；反过来先细后粗，粗线才会留在最外层。写模板时把顺序固定下来，比每次调试更可靠。

合并单元格的边框要单独处理。合并区域内部的线不显示，只有外沿有效，给合并后的区域设置 Inside 通常没有意义。

### 6.3.2 边框样式类型

五种线型在同一行里演示，方便横向对比。实际排版不必追求线型丰富，一张表里通常只用两种：数据区用细实线，表头或合计行用粗实线。线型太多反而分散注意力。

双线边框由两条平行线组成，占用宽度比单线大，窄行里容易糊成一条。只在合计行的上下边使用双线，比给整张表加双线更清楚。

边框设置对空单元格同样生效。先画表格再填数据、或者先填数据再画表格都可以，但合并与插入行列之后边框会跟着单元格移动，批量改结构后要重新检查一遍边框是否还对得上。

```csharp
public class BorderStyleTypes
{
    public void DemonstrateBorderStyles(Worksheet sheet)
    {
        // 实线边框
        sheet.SetRangeBorders("A1:A1", BorderPositions.All,
            new BorderStyle { Color = Color.Black, Style = BorderLineStyle.Solid });
        
        // 虚线边框
        sheet.SetRangeBorders("B1:B1", BorderPositions.All,
            new BorderStyle { Color = Color.Black, Style = BorderLineStyle.Dashed });
        
        // 点线边框
        sheet.SetRangeBorders("C1:C1", BorderPositions.All,
            new BorderStyle { Color = Color.Black, Style = BorderLineStyle.Dotted });
        
        // 粗线边框
        sheet.SetRangeBorders("D1:D1", BorderPositions.All,
            new BorderStyle { Color = Color.Black, Style = BorderLineStyle.BoldSolid });
        
        // 双线边框
        sheet.SetRangeBorders("E1:E1", BorderPositions.All,
            new BorderStyle { Color = Color.Black, Style = BorderLineStyle.DoubleLine });
    }
}
```

线型之间的差异在渲染时会随缩放比例变化，设计稿上看着合适的虚线，缩放到 75% 可能糊成实线。对线型有要求的场景，按实际打印比例检查一遍，别只看 100% 缩放下的效果。

边框和背景色的组合也有讲究：深色背景配深色边框会看不出边，浅色边框配白背景同样不明显。常见做法是背景浅、边框深一个色阶，或者干脆只用细边框加浅底色，靠色块区分区域。

## 6.4 对齐方式

### 6.4.1 水平对齐

水平对齐决定文字在单元格宽度内的位置。ReoGrid 提供左、中、右、分散几种取值，除了示例里的三种，DistributedIndent 会把文字均匀分布到整列宽度，效果接近两端对齐。

默认对齐跟数据类型走：文本靠左、数值靠右、日期靠右或居中，取决于版本与区域设置。这个默认值在大多数报表里已经够用，只有表头、标题这类需要居中的区域才需要显式设置。

对齐只影响显示。单元格宽度不够时，靠左的文字会溢出到右侧空单元格，靠右的会溢出到左侧，居中的会两边都溢出。想避免溢出，要么加宽列，要么开启换行，后者还需要足够行高。

```csharp
public class HorizontalAlignment
{
    private Worksheet sheet;
    
    /// <summary>
    /// 设置左对齐
    /// </summary>
    public void SetLeftAlign(string range)
    {
        sheet.SetRangeStyles(range, new WorksheetRangeStyle
        {
            Flag = PlainStyleFlag.HorizontalAlign,
            HAlign = ReoGridHorAlign.Left
        });
    }
    
    /// <summary>
    /// 设置居中对齐
    /// </summary>
    public void SetCenterAlign(string range)
    {
        sheet.SetRangeStyles(range, new WorksheetRangeStyle
        {
            Flag = PlainStyleFlag.HorizontalAlign,
            HAlign = ReoGridHorAlign.Center
        });
    }
    
    /// <summary>
    /// 设置右对齐
    /// </summary>
    public void SetRightAlign(string range)
    {
        sheet.SetRangeStyles(range, new WorksheetRangeStyle
        {
            Flag = PlainStyleFlag.HorizontalAlign,
            HAlign = ReoGridHorAlign.Right
        });
    }
    
    /// <summary>
    /// 设置分散对齐
    /// </summary>
    public void SetDistributedAlign(string range)
    {
        sheet.SetRangeStyles(range, new WorksheetRangeStyle
        {
            Flag = PlainStyleFlag.HorizontalAlign,
            HAlign = ReoGridHorAlign.DistributedIndent
        });
    }
}
```

给整片区域设置水平对齐时，容易连带把数据行的默认对齐也改掉。数据行里的数字如果被设成居中，列与列之间不再对齐小数点，看起来反而乱。表头单独设，数据区保持默认，是更稳的做法。

对齐和数字格式会一起影响观感。货币列通常右对齐，百分比列也右对齐，这样小数点能自然对齐；如果给这些列设置了居中，视觉上就看不出数值大小关系了。

### 6.4.2 垂直对齐

垂直对齐有三个取值：顶、中、底。行高等于文字高度时三者没有区别，行高明显大于文字高度时才有意义。表头行通常偏高，设成居中视觉上最平衡。

开启文本换行后，行高往往需要放大，此时垂直对齐的作用就体现出来了：内容顶部对齐适合长文本，中部对齐适合短标签。报表里同一行混排两种内容时，把所有单元格统一设成中部对齐，观感更整齐。

```csharp
public class VerticalAlignment
{
    private Worksheet sheet;
    
    /// <summary>
    /// 设置顶部对齐
    /// </summary>
    public void SetTopAlign(string range)
    {
        sheet.SetRangeStyles(range, new WorksheetRangeStyle
        {
            Flag = PlainStyleFlag.VerticalAlign,
            VAlign = ReoGridVerAlign.Top
        });
    }
    
    /// <summary>
    /// 设置中部对齐
    /// </summary>
    public void SetMiddleAlign(string range)
    {
        sheet.SetRangeStyles(range, new WorksheetRangeStyle
        {
            Flag = PlainStyleFlag.VerticalAlign,
            VAlign = ReoGridVerAlign.Middle
        });
    }
    
    /// <summary>
    /// 设置底部对齐
    /// </summary>
    public void SetBottomAlign(string range)
    {
        sheet.SetRangeStyles(range, new WorksheetRangeStyle
        {
            Flag = PlainStyleFlag.VerticalAlign,
            VAlign = ReoGridVerAlign.Bottom
        });
    }
}
```

垂直对齐的枚举值和水平对齐一样，通过 Flag 单独生效。只设 VAlign 不设行高，多数情况下看不出效果，因为默认行高刚好容纳一行文字。

行高由用户或代码控制，不随内容自动增长。设了居中之后如果内容被裁切，先检查行高，而不是反复调整对齐方式。

### 6.4.3 文本换行

换行有两个模式：WordBreak 按列宽折行，NoWrap 不折行、内容溢出到相邻单元格。示例用两个方法分别打开和关闭，切换时只需要改 TextWrap 一个属性。

折行生效的前提是行高足够。ReoGrid 不会因为内容变多就自动加高行高，需要另外调用自动行高，或手动把行高设成能容纳两行、三行的值。只开换行不加行高，看到的是被裁掉一半的文字。

```csharp
public class TextWrapping
{
    private Worksheet sheet;
    
    /// <summary>
    /// 启用文本换行
    /// </summary>
    public void EnableTextWrap(string range)
    {
        sheet.SetRangeStyles(range, new WorksheetRangeStyle
        {
            Flag = PlainStyleFlag.TextWrap,
            TextWrap = TextWrapMode.WordBreak
        });
    }
    
    /// <summary>
    /// 禁用文本换行
    /// </summary>
    public void DisableTextWrap(string range)
    {
        sheet.SetRangeStyles(range, new WorksheetRangeStyle
        {
            Flag = PlainStyleFlag.TextWrap,
            TextWrap = TextWrapMode.NoWrap
        });
    }
}
```

换行与列宽的配合值得单独说一句：列宽很窄又开了换行，一行字会被拆成很多行，行高再高也放不下，正确的做法是先保证列宽合理，再用换行处理超长内容。

关闭换行后，内容会溢出到右侧单元格，但只在这个单元格为空时可见；右侧一旦有内容，溢出部分就被遮住。所以靠溢出显示长文本并不可靠，需要完整显示时还是用换行或加宽列。

## 6.5 样式模板

### 6.5.1 预定义样式模板

样式模板把视觉规则集中到一处。示例用静态属性返回 WorksheetRangeStyle，每个属性都是一次新的构造，调用方拿到的是独立对象，修改它不会影响模板本身。如果改成静态字段只构造一次，所有调用方共享同一个实例，任何一处修改都会影响全局，这种共享可变状态是样式错乱的常见来源。

模板里的颜色用的是 RGB 值，不是命名颜色。这样便于把设计稿上的色值直接抄进来，也便于整体替换。表头、强调、错误、警告、成功这五类语义覆盖了大多数报表场景，业务代码按语义取用，不要各自 new 样式。

```csharp
public static class StyleTemplates
{
    /// <summary>
    /// 表头样式
    /// </summary>
    public static WorksheetRangeStyle HeaderStyle => new WorksheetRangeStyle
    {
        Flag = PlainStyleFlag.BackColor | 
               PlainStyleFlag.FontBold | 
               PlainStyleFlag.FontColor | 
               PlainStyleFlag.HorizontalAlign | 
               PlainStyleFlag.VerticalAlign,
        BackColor = Color.FromArgb(68, 114, 196),
        FontColor = Color.White,
        Bold = true,
        HAlign = ReoGridHorAlign.Center,
        VAlign = ReoGridVerAlign.Middle
    };
    
    /// <summary>
    /// 数据行样式
    /// </summary>
    public static WorksheetRangeStyle DataRowStyle => new WorksheetRangeStyle
    {
        Flag = PlainStyleFlag.FontName | PlainStyleFlag.FontSize,
        FontName = "微软雅黑",
        FontSize = 10
    };
    
    /// <summary>
    /// 强调样式
    /// </summary>
    public static WorksheetRangeStyle EmphasisStyle => new WorksheetRangeStyle
    {
        Flag = PlainStyleFlag.BackColor | PlainStyleFlag.FontBold,
        BackColor = Color.Yellow,
        Bold = true
    };
    
    /// <summary>
    /// 错误样式
    /// </summary>
    public static WorksheetRangeStyle ErrorStyle => new WorksheetRangeStyle
    {
        Flag = PlainStyleFlag.BackColor | PlainStyleFlag.FontColor,
        BackColor = Color.FromArgb(255, 199, 206),
        FontColor = Color.FromArgb(156, 0, 6)
    };
    
    /// <summary>
    /// 警告样式
    /// </summary>
    public static WorksheetRangeStyle WarningStyle => new WorksheetRangeStyle
    {
        Flag = PlainStyleFlag.BackColor | PlainStyleFlag.FontColor,
        BackColor = Color.FromArgb(255, 235, 156),
        FontColor = Color.FromArgb(156, 101, 0)
    };
    
    /// <summary>
    /// 成功样式
    /// </summary>
    public static WorksheetRangeStyle SuccessStyle => new WorksheetRangeStyle
    {
        Flag = PlainStyleFlag.BackColor | PlainStyleFlag.FontColor,
        BackColor = Color.FromArgb(198, 239, 206),
        FontColor = Color.FromArgb(0, 97, 0)
    };
}
```

模板定义成属性而不是字段，还有一个实际问题：WorksheetRangeStyle 是可变对象，属性每次返回新实例，调用方即使就地改也不会污染模板；字段共享实例，某次调用不小心改了 Flag，下一次套用就是错的。多线程场景下，共享可变对象还会产生竞态。

颜色值建议统一从设计规范里取，写进一个静态类，不要在模板里散落。示例的六个模板已经把常用语义覆盖得差不多，新增语义时先看看能不能复用，避免模板数量膨胀。

### 6.5.2 使用样式模板

使用模板只有一行调用：把区域和样式传给 SetRangeStyles。示例演示了表头、数据行、强调、错误四种场景，每个区域可以套不同模板，互不影响。

套用顺序会影响最终效果。先套数据行样式，再对个别单元格套强调或错误样式，后套的会覆盖先套的冲突属性；反过来先强调再套整行，强调就被冲掉了。规则是范围大的先套，范围小的后套。

```csharp
public class UseStyleTemplates
{
    public void ApplyTemplates(Worksheet sheet)
    {
        // 应用表头样式
        sheet.SetRangeStyles("A1:E1", StyleTemplates.HeaderStyle);
        
        // 应用数据行样式
        sheet.SetRangeStyles("A2:E100", StyleTemplates.DataRowStyle);
        
        // 应用强调样式
        sheet.SetRangeStyles("C10", StyleTemplates.EmphasisStyle);
        
        // 应用错误样式
        sheet.SetRangeStyles("D20", StyleTemplates.ErrorStyle);
    }
}
```

模板套用之后如果还要修改，直接改模板定义，所有引用处下次套用时生效；已经套上去的单元格不会自动更新，需要重新跑一遍套用逻辑。这一点在实现「切换主题」功能时要特别注意，主题切换的本质就是重新套一遍样式。

数据行样式只设了字体和字号，没有设背景色，因此交替行颜色、条件格式的背景仍然有效，不会被模板覆盖。模板设计时把结构属性（字体、对齐）和装饰属性（背景、边框）分开，套用起来才不会互相打架。

## 6.6 主题与配色方案

### 6.6.1 专业配色方案

配色方案把一组颜色定义成具名常量。示例给了商务蓝、清新绿、暖橙三套，每套五个角色：主色、辅色、强调色、浅色、深色。用角色而不是具体色值引用，换主题时只改这一处。

五个角色的分工大致是：主色用于表头和大标题，辅色用于次级表头或斑马纹，强调色用于需要突出的数字，浅色用于大面积底色，深色用于文字或边框。按这个分工选色，比随手挑颜色更容易得到协调的界面。

颜色值直接写 RGB 的好处是与设计稿一一对应；坏处是不直观，改的时候要在取色器和代码之间来回对。建议在类里加注释写明用途，或者把角色名起得更具体。

```csharp
public class ColorSchemes
{
    /// <summary>
    /// 商务配色方案
    /// </summary>
    public static class Business
    {
        public static Color Primary = Color.FromArgb(0, 112, 192);
        public static Color Secondary = Color.FromArgb(68, 114, 196);
        public static Color Accent = Color.FromArgb(255, 192, 0);
        public static Color Light = Color.FromArgb(217, 225, 242);
        public static Color Dark = Color.FromArgb(31, 78, 120);
    }
    
    /// <summary>
    /// 清新配色方案
    /// </summary>
    public static class Fresh
    {
        public static Color Primary = Color.FromArgb(112, 173, 71);
        public static Color Secondary = Color.FromArgb(169, 208, 142);
        public static Color Accent = Color.FromArgb(255, 230, 153);
        public static Color Light = Color.FromArgb(226, 239, 218);
        public static Color Dark = Color.FromArgb(84, 130, 53);
    }
    
    /// <summary>
    /// 暖色配色方案
    /// </summary>
    public static class Warm
    {
        public static Color Primary = Color.FromArgb(237, 125, 49);
        public static Color Secondary = Color.FromArgb(244, 176, 132);
        public static Color Accent = Color.FromArgb(255, 217, 102);
        public static Color Light = Color.FromArgb(252, 228, 214);
        public static Color Dark = Color.FromArgb(192, 80, 77);
    }
}
```

三套方案的色相不同，明度关系一致，所以同一份样式模板换一套颜色就能得到风格统一、观感不同的表格。自定义配色时保持这个明度阶梯，即使色相偏离设计稿，整体也不会太乱。

深色模式下，浅色背景会变成刺眼的白块。如果程序要支持深色主题，配色方案里应当预留一组深色模式的值，或者在运行时按主题切换。不要把浅色值硬编码在业务代码里。

### 6.6.2 应用主题

应用主题本质上是把配色方案套到各区域的样式模板上。示例里表头用主色、次级表头用辅色、强调单元格用强调色，三处都通过 SetRangeStyles 完成，区域范围按实际表格调整。

主题切换要处理两个问题：一是已套用的旧样式需要覆盖，二是部分单元格有独立样式（如条件格式结果），不能被主题冲掉。稳妥做法是切换时重新套一遍结构类样式，只覆盖背景与字体色，保留边框和其它属性。

```csharp
public class ThemeApplication
{
    public void ApplyBusinessTheme(Worksheet sheet)
    {
        // 表头
        sheet.SetRangeStyles("A1:Z1", new WorksheetRangeStyle
        {
            Flag = PlainStyleFlag.BackColor | PlainStyleFlag.FontColor | PlainStyleFlag.FontBold,
            BackColor = ColorSchemes.Business.Primary,
            FontColor = Color.White,
            Bold = true
        });
        
        // 次级表头
        sheet.SetRangeStyles("A2:Z2", new WorksheetRangeStyle
        {
            Flag = PlainStyleFlag.BackColor | PlainStyleFlag.FontColor,
            BackColor = ColorSchemes.Business.Secondary,
            FontColor = Color.White
        });
        
        // 强调单元格
        sheet.SetRangeStyles("E5", new WorksheetRangeStyle
        {
            Flag = PlainStyleFlag.BackColor,
            BackColor = ColorSchemes.Business.Accent
        });
    }
}
```

主题函数通常只在初始化时调用一次，开销不大。如果支持运行时切换主题，整表重新套样式会触发大面积重绘，建议先 BeginUpdate，套完再 EndUpdate，并接受一次可见的闪烁。

不要用主题去覆盖单元格里已有的语义色。比如错误行的浅红底、警告行的浅黄底，这些是数据状态，不属于主题，切换主题时应当跳过或重新计算。

## 6.7 样式工具类

### 6.7.1 样式辅助方法

工具类把重复的样式操作收成扩展方法。示例四个方法分别解决复制样式、清除样式、设置表头、设置只读外观，最后一类只改了背景和字色，并没有真正限制编辑。

只读外观和只读行为是两件事。SetAsReadOnly 只是把格子涂灰，用户照样能输入。真正禁止编辑要靠单元格的只读属性或编辑前事件拦截，这部分在第十四章事件处理里再展开。

复制样式用 GetRangeStyles 取回源区域样式，再写给目标区域。如果源区域内部样式并不统一，取回的可能是左上角或某一种代表样式，跨区域复制前先确认源区域是统一格式的。

```csharp
public static class StyleHelpers
{
    /// <summary>
    /// 复制样式
    /// </summary>
    public static void CopyStyle(this Worksheet sheet, string sourceRange, string targetRange)
    {
        var sourceStyle = sheet.GetRangeStyles(new RangePosition(sourceRange));
        sheet.SetRangeStyles(targetRange, sourceStyle);
    }
    
    /// <summary>
    /// 清除样式
    /// </summary>
    public static void ClearStyle(this Worksheet sheet, string range)
    {
        sheet.SetRangeStyles(range, WorksheetRangeStyle.Empty);
    }
    
    /// <summary>
    /// 快速设置表头样式
    /// </summary>
    public static void SetAsHeader(this Worksheet sheet, string range)
    {
        sheet.SetRangeStyles(range, new WorksheetRangeStyle
        {
            Flag = PlainStyleFlag.BackColor | 
                   PlainStyleFlag.FontBold | 
                   PlainStyleFlag.HorizontalAlign,
            BackColor = Color.FromArgb(79, 129, 189),
            Bold = true,
            HAlign = ReoGridHorAlign.Center
        });
    }
    
    /// <summary>
    /// 设置只读样式
    /// </summary>
    public static void SetAsReadOnly(this Worksheet sheet, string range)
    {
        sheet.SetRangeStyles(range, new WorksheetRangeStyle
        {
            Flag = PlainStyleFlag.BackColor | PlainStyleFlag.FontColor,
            BackColor = Color.LightGray,
            FontColor = Color.DarkGray
        });
    }
}
```

扩展方法放在静态类里，命名空间与被扩展类型不同时要注意 using。示例中的 this Worksheet sheet 是 C# 扩展方法的标准写法，调用时看起来像 Worksheet 自带的成员，实际定义在工具类里。

清除样式传入 WorksheetRangeStyle.Empty，效果是把区域恢复成默认外观。它会连同边框、对齐一起清掉，只想清背景时不要用这个方法，直接设成白色或透明更精确。

## 6.8 本章小结

本章全面介绍了ReoGrid的样式与外观定制功能，包括字体、背景、边框、对齐等各种视觉效果的设置方法。

回顾一下这一章的骨架：

- Flag 与属性成对使用，Flag 决定改哪些属性，属性决定改成什么值；
- 背景和边框属于装饰，字体和对齐属于结构，两者在设计模板时分开管理；
- 样式模板把配色与排版从业务代码里抽出来，用属性而不是共享字段暴露；
- 主题是配色方案加模板的组合，切换主题等于重新套一遍样式；
- 工具类适合收拢重复调用，但注意「看起来只读」不等于「真的只读」。

调试样式问题的顺序建议是：先看区域范围对不对，再看 Flag 有没有漏，最后看是否有后设的样式覆盖了它。ReoGrid 不会为样式冲突报错，覆盖是静默发生的，排查时要按设置顺序从后往前找。

性能上，单次设置样式几乎无感，成百上千次区域设置才会明显拖慢。批量套样式统一放进 BeginUpdate 块，是这一章唯一需要长期坚持的习惯。
