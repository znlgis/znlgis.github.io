# 第06章 交互范式：LLM 与空间智能体的三种形态

> **本章导读**
>
> 能力不是瓶颈，接口才是——第05章讲地理空间基础模型能做到什么，本章把问题换成“人怎么把活交给模型”。本章对应原报告 5.1—5.4 节：先用三次交互迁移说明第三代的门槛来自工具选择、参数配置与流程组织的转移，再把市面产品压成知识问答、工作流、自主规划三类，接着用超图、上海“云宇星空”与 Esri 三个 MCP 采用点看事实标准与开放边界，最后用 GEOBench-VLM 的 41.7% 与 GEE Agent 的 40.0% 说明空间推理被高估。最该带走的是：让模型直接输出坐标、面积或拓扑关系，属于高风险设计。

## 学习目标

读完本章，你应当能够：

- 复述 5.1 节三次交互迁移的划分标准，说清第三代把哪三件事从人转移给了系统；
- 用 5.2 节的三分法，把一个自称智能体的 GIS 产品归入知识问答式、工作流式或自主规划式，并写出判断依据；
- 说出 5.3 节三个 MCP 采用点的共同指向，区分厂商愿意开放与不愿开放的能力边界；
- 用 GEOBench-VLM 的 41.7% 与零样本 Agent 的 40.0% 两组数字，说明空间推理被高估落在哪三类失败上；
- 写出针对拓扑判定、数值测算、数据引用三类失败的工程约束，各一条；
- 判断当前项目最该先落地三类形态中的哪一种，并说明理由。

## 5.1 交互范式的第三次迁移

| 阶段 | 交互形态 | 用户门槛 | 能力边界 |
| --- | --- | --- | --- |
| 第一代 | 菜单 + 对话框 + 脚本 | 需专业培训 | 会点按钮、会写脚本才能完成任务 |
| 第二代 | Python/JS SDK + Web API + Notebook | 需编程能力 | 可自动化，但流程需人预先编排 |
| 第三代（2025—2026 起） | 自然语言 + 智能体编排 + 结果自解释 | 接近零门槛 | 描述目标即可，系统自主选工具、定参数、出结果 |

第三代的关键不是“能聊天”，而是**把“工具选择、参数配置、流程组织”这三件最耗专业经验的事，从人转移给了系统**。这正是超图在 2026 年 5 月提出“智能体原生地理信息软件”时的核心论述：空间智能体将成为系统中枢与主要交互入口，传统菜单与工具条将被自然语言入口取代。

## 5.2 三种产品形态已经成型，能力边界差异极大

2025—2026 年的公开产品把“LLM + GIS”收敛为三种形态，成熟度差别很大：

| 形态 | 交互方式 | 代表实现 | 成熟度 |
| --- | --- | --- | --- |
| **知识问答式**（Chatflow） | 单轮/多轮问答，检索增强 | 超图 AgentX 知识问答式；ArcGIS 各产品助手；Google Earth Engine “Ask”（2026-09-29 集成 Gemini，无需自备 API Key） | **已产品化** |
| **工作流式**（Workflow） | 预定义工具链，LLM 负责填参与选路 | 超图 AgentX 工作流式；ArcGIS Pro 助手生成 ArcPy / SQL / OpenCypher；AgentX Server 三种模式（工作流/长规划/循环推理） | **Beta—GA** |
| **自主规划式**（Autonomous） | LLM 自主拆解任务、调用工具、反思迭代 | 超图 AgentX 自主规划式；Google Geospatial Reasoning Agent；QGIS 自主取数智能体 | **实验/Beta** |

**这个三分法的实用价值在于：它让“智能体”这个词变得可判断。** 当一个产品声称自己是智能体时，先问它属于哪一类——知识问答式只是检索加强版，工作流式是自动化配置，只有自主规划式才真正涉及“系统自己决定做什么”。三者的风险等级与验收方式完全不同。

## 5.3 工具协议：MCP 成为事实标准，但开放边界很关键

2025—2026 年最实质的工程变化不是模型，而是**工具调用协议的统一**。可核验的采用点有三个：

1. 超图 SuperMap GIS 2025（2025-06-24）新增支持 **MCP（Model Context Protocol）**，“统一地理空间智能体工具接口标准，支持内、外部工具导入和协同调用”；2026 版继续深化。
2. 上海市规划资源局“云宇星空”完成时空数据调用、分析工具等 **MCP 服务改造**并部署于政务网（2025-12）。
3. Esri 在 2026 年推出 **ArcGIS Location Platform MCP（Beta）**。

**但第三条的边界值得单独说明**：据第三方技术分析，ArcGIS Location Platform 的 MCP Beta **只开放地理编码、路径规划、高程、静态地图等云端轻量服务，不开放企业私有全量业务数据、复杂空间分析模型与项目工程文件**。

这个“开放边界”是一个重要信号：**厂商愿意开放的是“云端轻量能力”，不愿意开放的是“私有数据与复杂分析”**——后者恰恰是客户付钱买的核心价值。这也解释了为什么企业级 GIS 智能体短期仍以工作流形态落地，而不是真正的自主智能体。

> **判断**：MCP 会成为 GIS 智能体的“USB 接口”，但它解决的是“能不能接上”，不解决“接上后能做什么”。真正的竞争在于**谁能提供更高质量的 Skills（业务技能封装）**，而不是谁先支持协议。

## 5.4 空间推理：被系统性高估的能力

这是本报告需要重点纠偏的一节。2025—2026 年出现了多个针对地理空间视觉语言模型的基准，结论高度一致——**通用大模型在地理空间任务上很弱**：

| 基准 | 规模/结构 | 关键结论 |
| --- | --- | --- |
| **GEOBench-VLM**（ICCV 2025） | 8 大类 31 子任务，1 万余条人工核验指令 | 最佳模型 LLaVA-OneVision 单选准确率仅 **41.7%**；GPT-4o 约为随机猜测的 2 倍 |
| **PANGAEA**（ESA 主导） | 多数据集、多任务、多分辨率、多模态、多时相 | 标准化 GeoFM 评测协议，可扩展 |
| **CHOICE**（国家对地观测科学数据中心） | 2 大能力（感知/推理）、6 维度、23 子任务 | 支持单选、检测框、分割掩膜等题型 |
| **GeoKTools / GeoExpertQueries**（Google） | 模板化多工具查询 + 开放式专家工作流 | 领域技能与前置规划是空间推理的关键 |

更极端的证据来自 ACL 2026 Findings：**零样本条件下，LLM Agent 调用 Google Earth Engine API 完成地理空间任务，准确率仅 40.0%，且代码在 44% 以上的情况下根本跑不起来**；即便头部模型也仅升至约 60%。

**三类系统性失败及其工程对策**：

| 失败类型 | 表现 | 工程对策 |
| --- | --- | --- |
| 拓扑与方位“想当然” | 自然语言层面尚可，严格拓扑判定（如“是否共享边界但不包含”）错误率显著上升 | **强制把拓扑判定交给计算引擎**，LLM 只负责翻译与解释 |
| 数值与尺度失真 | 面积、长度、密度、比例估算缺乏可靠数值直觉 | 一切数值由工具计算，LLM 只做选择与表述 |
| 幻觉式“数据引用” | 编造不存在的图层、字段或统计值，演示中不易暴露 | **强制结果溯源**：每个数字必须指向具体查询结果或数据版本 |

李飞飞在 2025 年 11 月的长文《From Words to Worlds: Spatial Intelligence is AI's Next Frontier》中进一步指出，即使最新的多模态大模型，在估算距离、方向、大小时的表现也往往不可靠，LLM 时代在物理世界表征与交互上存在根本局限。

**结论：凡是让模型直接输出坐标、面积或拓扑关系的方案，都应视为高风险设计。** 空间计算必须强制调用确定性算子。

## 本章小结

- 第三代的实质是工具选择、参数配置与流程组织三件事从人转移给系统，“能聊天”只是外壳；超图 2026 年 5 月提出“智能体原生地理信息软件”时讲的也是这件事。
- 三分法的价值在验收而不在分类：知识问答式已产品化，工作流式处于 Beta—GA，自主规划式仍在实验/Beta，风险等级与验收方式各不相同。
- MCP 解决“能不能接上”，不解决“接上后能做什么”；ArcGIS Location Platform MCP（Beta）只开放地理编码、路径规划、高程、静态地图等云端轻量服务，不开放企业私有全量数据与复杂空间分析。
- 空间推理的公开证据一致偏低：GEOBench-VLM 上最佳模型单选准确率 41.7%，零样本 Agent 调 GEE API 准确率 40.0%、代码 44% 以上跑不起来，头部模型也仅约 60%。
- 工程对策只有一条主线：拓扑判定交给计算引擎、数值一律由工具计算、每个数字溯源到具体查询结果或数据版本。
- 李飞飞 2025 年 11 月的长文是观点旁证而非基准结果；本章的结论是“让模型直接输出坐标、面积或拓扑关系属高风险设计”，不是“空间智能无法实现”。

## 思考与练习

1. 辨析：有人说“能对话的 GIS 就是空间智能体”。用 5.2 节三分法指出这句话漏掉了什么，并给出判据；再把你熟悉的一个产品归类。
2. 应用题：某市采购“地块变化自动发现”，供应商演示了自然语言查询与自动出图。用 5.2、5.4 两节写三条验收条款：形态归类、准确率下限、人工复核比例。
3. 结合你正在用的 GIS 产品，对照 5.3 节的开放边界，分别列出它已开放与你最需要却未开放的一项接口能力。
4. 用 5.4 节的 40.0% 与 44% 两个数字，估算一个取消人工复核的方案每月需返工多少次，写清样本量与判定口径假设。
5. 辨析：有人认为“拓扑判定交给大模型、再安排人工抽查即可”。用 5.4 节三类失败反驳，并给出替代流程。
6. 若单位决定先做知识问答式助手，写出首批 10 个问题必须覆盖的数据范围，并说明为什么不宜从自主规划式起步。
