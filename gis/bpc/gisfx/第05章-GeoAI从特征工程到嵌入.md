# 第05章 GeoAI：从特征工程到嵌入

> **本章导读**
>
> 2025 年 GeoAI 最实在的变化不在模型参数量，而在产品形态。本章对应原报告 3.6 节（3.6.1—3.6.3），接在第04章的方法体系之后：先讲卫星嵌入从论文走向产品给工程带来的三处改变，再讲 LLM 与 Agent 的位置——它们改变交互层，不改变计算层，最后把空间幻觉、误差传播、评测缺失三类短板摊开。要带走的判断是：嵌入是表示不是判断，模型只该产出意图与参数，坐标、几何与投影变换交给确定性库执行并留下可审计的轨迹。读完你应当能判断一个 GeoAI 需求该把模型放在链路的哪一步。

## 学习目标

读完本章，你应当能够：

- 复述 3.6.1 节卫星嵌入产品化的三点工程含义，并说明项目周期为什么能从“月”压到“周”；
- 用 GeoBenchX 的评测设置（23 个地理函数、四类含无解任务、8 个商用模型）解释“模型会误解几何关系”这条发现；
- 说明为什么“拒答能力”可以被度量，以及它对生产系统为什么比给一个看似合理的答案更重要；
- 写出“模型不产出坐标”的架构原则，并列出一次 Agent 步骤应留下的最小轨迹；
- 用 3.6.3 节区分空间幻觉、误差传播、评测缺失，各给出一个可落地的工程对策；
- 判断一个 GeoAI 需求该把模型放在链路的哪一步，并说明为什么不能放在最终结论那一步。

## 3.6.1 遥感基础模型的实质进展

2025 年最实质的变化是**卫星嵌入（satellite embedding）产品化**。以 AlphaEarth Foundations 为代表：模型把多源对地观测（光学、雷达、气候等）编码为连续嵌入场，官方描述是“像一颗虚拟卫星，可在任意地点、任意时间成像”，输出可直接作为分类、回归、变化检测的输入〔来源：IEEE GRSS ESI-TC 研讨会摘要，2025-11-03〕。

这个转向的工程含义有三点，比“模型很强”更值得关注：

1. **特征工程下沉**：过去每个项目都要自己算 NDVI、纹理、时序统计量；现在可以先用通用嵌入，再在其上做轻量下游模型。项目周期从“月”压缩到“周”。
2. **少样本可行**：嵌入空间具有一定通用性，小样本标注即可微调，缓解了遥感标注昂贵的老问题。
3. **可迁移性提高**：跨区域、跨传感器的迁移成本下降，这对跨气候带或跨境的业务尤其重要。

但边界同样清楚：嵌入是**表示**不是**判断**。它不解决类别定义模糊、标注偏差、业务规则冲突，也不保证可解释性。落地成本的大头在下游验证与业务对齐。

## 3.6.2 LLM 与 Agent：改变交互，不改变计算

自然语言驱动的空间分析已有可运行原型，代表性工作如 GIS Copilot，把“用户意图 → 工具调用 → 结果解释”串成流程〔来源：Kang et al., GIS Copilot, International Journal of Digital Earth, 2025〕。它的价值在降低门槛：不会写 SQL 的业务人员也能完成中等复杂度的分析。

但“能用”与“可靠”之间还有明显距离，**这一点已有公开基准可查**。GeoBenchX（arXiv:2503.18129，v1 2025-03-23，v2 2025-10-22）用 23 个地理函数、四类复杂度递进的任务（含**故意无解**的任务以测试拒答能力）评测了 8 个商用模型：综合表现最好的是 o4-mini 与 Claude 3.5 Sonnet；GPT-4.1、GPT-4o、Gemini 2.5 Pro Preview 紧随其后，其中后两个在识别“无解任务”上更高效；而 Claude Sonnet 4 因为倾向于“无论如何都给一个答案”，准确率反而更低〔来源：arXiv:2503.18129〕。

这份基准最有价值的三条发现，恰好对应工程上的三个坑：

- **误解几何关系**是最高频的错误类型——不是不知道怎么调函数，而是对空间关系的判断本身出错。
- **拒答能力可以度量且差异巨大**。对生产系统而言，“识别出这个问题无解并如实报告”比“给出一个看似合理的错误答案”重要得多。
- **Token 消耗差异显著**（Anthropic 系模型更耗 token），这直接影响按调用计费模式的成本结构。

因此“让模型直接给出结论”是不负责任的架构；“模型编排工具 + 确定性几何库执行 + 结果校验”才是可交付的形态。

必须坚持的架构原则：

- **模型不产出坐标**。坐标、几何、投影变换必须由确定性库（GEOS/PROJ）执行，模型只输出“意图与参数”。
- **结果可验证**。每个 Agent 步骤应留下“调了什么工具、传了什么参数、返回什么”的轨迹，供审计与复现。
- **失败要显式**。空间问题经常是“数据不存在”而非“算错了”，Agent 需要能区分并如实报告，而不是编造一个看似合理的结果。

## 3.6.3 可信度：GeoAI 的真实短板

三类问题在 2026 年仍无通用解法：

- **空间幻觉**：模型给出看似合理但地理上不成立的位置关系（例如把不相邻的区域说成相邻）。
- **误差传播**：分类误差经过叠加、缓冲、聚合后被放大，最终结论的置信区间无人计算。
- **评测缺失**：缺少公认的空间推理基准，“模型 A 比 B 强”多数时候只在特定数据集上成立。

对应的工程对策是：把 GeoAI 输出当作**候选**而非**结论**，在关键节点插入规则校验与人工复核，并把不确定性量化（至少给出置信度或敏感性区间）写进验收标准。

## 本章小结

- 卫星嵌入把多源对地观测编码成连续嵌入场，可直接作为分类、回归、变化检测的输入；工程含义是特征工程下沉、少样本可行、跨区域跨传感器迁移成本下降。
- 嵌入是表示不是判断：它不解决类别定义模糊、标注偏差与业务规则冲突，也不保证可解释性，落地成本的大头在下游验证与业务对齐。
- GeoBenchX（arXiv:2503.18129）用 23 个地理函数、含故意无解任务的四类任务评测 8 个商用模型，综合表现最好是 o4-mini 与 Claude 3.5 Sonnet；Claude Sonnet 4 因倾向“无论如何都给答案”，准确率反而更低。
- 基准最有价值的三条发现对应三个工程坑：误解空间关系是最高频错误、拒答能力可度量且差异巨大、token 消耗差异直接影响按调用计费的成本结构。
- 可交付的形态是“模型编排工具 + 确定性几何库执行 + 结果校验”：坐标与投影变换由 GEOS/PROJ 执行，每一步留下“调了什么工具、传了什么参数、返回什么”。
- 空间幻觉、误差传播、评测缺失在 2026 年仍无通用解法，现实做法是把 GeoAI 输出当候选而非结论，把不确定性量化写进验收标准。

## 思考与练习

1. 为你手上的遥感任务估算：用通用嵌入加轻量下游模型，与自建特征工程相比，标注量能省多少、验证量要多哪些。
2. 取一个你常做的空间分析，写出“模型可以做 / 必须交给几何库”的分工清单，指出越界会出什么错。
3. 辨析：“模型给出了看起来正确的结果，说明它理解了空间关系”。用 3.6.2 节的三条发现判断这句话错在哪。
4. 应用：为一个 Agent 分析流程写验收标准，至少包含工具轨迹留痕、无解识别、不确定性报告三项。
5. 你的项目预算有限。按“模型 2 : 治理与验证 8”的说法，说明这笔钱具体该花在哪几件事上。
6. 借 GeoBenchX 的“故意无解”设计思路，为你所在业务写两道应当拒答的测试题，并说明合格答案长什么样。
