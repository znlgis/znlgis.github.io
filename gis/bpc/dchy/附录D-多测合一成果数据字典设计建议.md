# 附录D 多测合一成果数据字典设计建议

> **本篇导读**
>
> 附录 D 给的是一个可以直接拿去改的模板，而不是一份标准。表 D-1 按 8 个图层组（控制、地籍、建筑、房屋、绿地、人防、交通、注记）给出建议的图层命名、几何类型与主要属性，表 D-2 给出建议所有图层都带上的 11 个公共字段，从 OBJECT_ID、FEATURE_CODE 一直到 CHANGE_TYPE、QC_STATUS；表后还补了三条面积字段的设计建议，对应第 3 章 3.3 节与第 5 章 5.5 节。它要解决的问题是：地方在暂无国家或省级数据标准可依时，仍要有一份能写进委托合同、能拿来做验收的字段清单。最容易做错的地方，是把多个口径的面积塞进一个 AREA 字段，再指望用备注解释差异——正文的对策是分字段存储、每个面积字段配套“计算依据”、跨口径差值另设字段。读完你会明白，数据字典的价值不在于字段多，而在于每个字段的语义只有一种读法。

## 使用提示

- **用途**：当作起点，不是终点。把表 D-1 的图层组与表 D-2 的公共字段抄进本地数据字典草案，再按本地规程增删，比从空白文档起草快得多。
- **口径读法**：图层名与字段名是建议命名，可随本地习惯调整，但语义不能改——OBJECT_ID 必须与几何解耦，DATA_SOURCE 必须能区分实测、沿用、转绘与推算，QC_STATUS 的四态不要自行合并。
- **边界**：图层组与字段是覆盖常见事项的最小集，不是全集；本地若有人防、交通之外的事项，应自行增设图层组并沿用表 D-2 的公共字段，不要为了凑满八组而生造图层。
- **配合使用**：与第 05 章（5.3 节唯一标识、5.5 节属性设计、5.7 节时态、5.8 节元数据）配合读设计理由；与第 09 章和附录 E 配合，把字段定义直接转成可判定的规则。

**说明**：本附录给出一个**建议性的**数据字典框架，供地方编制本地数据字典时参考。**它不是一个标准，不能直接作为验收依据**；实际设计必须结合当地技术规程、既有数据库结构与下游系统要求。

**表 D-2　关键公共字段（建议所有图层均包含）**

| 字段名 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| OBJECT_ID | 字符串 | 是 | 对象唯一标识，与几何解耦，几何变化时不变 |
| FEATURE_CODE | 字符串 | 是 | 要素分类代码，符合要素分类标准 |
| SURVEY_ITEM | 字符串 | 是 | 所属测绘事项代码（对应事项字典） |
| SURVEY_TIME | 日期 | 是 | 测绘时点 |
| DATA_SOURCE | 枚举 | 是 | 数据来源：实测/沿用/转绘/推算 |
| ACCURACY_LEVEL | 枚举 | 是 | 精度等级（一/二/三/四级，按地方规程） |
| EFFECTIVE_DATE | 日期 | 是 | 生效日期（时态管理） |
| EXPIRE_DATE | 日期 | 否 | 失效日期，空表示当前有效 |
| CHANGE_TYPE | 枚举 | 是 | 变更类型：新增/修改/删除/沿用 |
| BATCH_ID | 字符串 | 是 | 所属测绘批次编码 |
| QC_STATUS | 枚举 | 是 | 质检状态：未检/合格/不合格/待复检 |

**关于面积字段的三点设计建议**（对应第 3 章 3.3 节与第 5 章 5.5 节）：

1. **不同口径的面积分字段存储**，如 `AREA_PLAN`（规划口径）、`AREA_HOUSE`（房产口径）、`AREA_LAND`（土地口径），不要用一个 `AREA` 字段承载全部语义；

2. **每个面积字段配套一个“计算依据”字段**，记录所依据的标准号与条款；

3. **跨口径差值另设字段并说明原因**，如 `AREA_DIFF_NOTE`。
