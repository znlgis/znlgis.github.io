# 第04章 精度评价与规则引擎

> **本章导读**
>
> 本章对应原报告 4.3 与 4.4，讲两件决定质检能否被采信的事：误差怎么算，规则怎么编排。4.3 节给出中误差的计算与三条工程要点，即检测点的分布与数量、按批实施、抽样风险与粗差，并说明分类精度为什么必须单独报告小地物。4.4 节从规则引擎的七层架构讲到并行分块的边界陷阱、增量质检的失效范围判定，以及把质检做成发布门禁的三条配套要求。读这一章要带走的判断是：算得出误差不等于判得准，跑得完规则也不等于判得对。

## 学习目标

读完本章，你应当能够：

- 写出中误差的计算式，并说明检测点的分布、数量与批次分别影响结果的哪一部分；
- 解释 GB/T 24356 的计数抽样为什么带有生产方风险与使用方风险，并说明缩减样本量前必须具备什么条件；
- 区分粗差率与中误差的判定地位，说明为什么少量极端错误比整体精度轻微下降更危险；
- 用混淆矩阵给出总体精度、Kappa、生产者精度与用户精度，并说明 AI 提取成果为何要单独报告小地物；
- 按 4.4 节的分层架构写出规则引擎各层职责，并说明可举证、可复用、可回放各自对应什么设计；
- 识别按 tile 并行与按图幅接边两种场景的边界陷阱，给出防止假阳性的做法；
- 用规则版本与数据版本的矩阵，说明规则升级后如何判定历史数据的失效范围。

## 4.3 精度评价的数学基础

**（1）中误差（RMSE）** 是位置精度的通用度量：

   m = sqrt( Σ(Δi²) / n )

工程要点三条：检测点必须**分布均匀且位于可判读的特征点**（三维成果的规范表述为：检测点应选择分布均匀、位置易于辨认的模型特征点，不选对精度不作要求的特殊地物点位；高程精度应同时包含地表点与非地表点如建筑顶部特征点）；检测点数量须与成果重要程度匹配（地方标准中常见做法为单位成果选取 30—50 个检测点或检测边）；检测须按“批”实施，批面积过大时分批。

**（2）抽样推断的风险常被忽视**。GB/T 24356 的抽样方案属于计数抽样，结论带有**生产方风险与使用方风险**。学术侧已有针对“零缺陷抽样（C=0）”的研究指出，在测绘产品检验中采用 C=0 方案通常可将样本量降低 8%—30%，同时保持可接受的风险水平（ISPRS Annals, 2026）。这为“自动质检把缺陷率压到极低后如何合理缩减人工抽样量”提供了方法论依据——但**缩减抽样量必须有统计学论证，不能凭经验拍减**，否则只是在转移风险而非消除风险。

**（3）粗差检测** 的重要性高于中误差：粗差率（工程上常以 5% 为界）是独立判定指标。因为少量极端错误对下游应用（导航、低空、工程）的破坏，远大于整体精度的轻微下降。

**（4）分类精度** 用混淆矩阵表达：总体精度、Kappa、各类别的生产者精度与用户精度。对 AI 提取成果还需补充 F1 与 IoU，并**单独报告小地物类别**——一个总体精度 95% 的模型，可能在“细小道路”“临时构筑物”上完全失效，而这类要素恰恰是变化发现的重点。

## 4.4 规则引擎与算子编排架构

**（1）为什么必须用规则引擎，而不是脚本集合**

规则引擎的价值不在“跑得快”，而在三件事：**可举证**（每条结论能追溯到规则号与标准条款）、**可复用**（跨项目沉淀）、**可回放**（同一规则 + 同一数据 = 同一结果，这是验收争议时的关键）。脚本集合在这三点上全部失分。

**（2）分层架构**

   接入层 : 数据源适配（文件 / 数据库 / 对象存储 / OGC 服务 / 流）
   调度层 : 任务编排（DAG）、分块与并行、失败重试、断点续跑
   规则层 : 规则元数据（rule_id、依据条款、严重级别、适用范围、阈值、抽检策略）
   执行层 : 算子库（SQL / 几何 / 栅格 / 三维 / 模型）
   结果层 : 缺陷记录（定位几何、对象 ID、规则号、证据快照）
   报告层 : 质量评定（扣分/评分/等级）、多形态报告（JSON / HTML / PDF）
   治理层 : 规则版本、白名单、误报标注、结果回流

**（3）关键设计决策**

| 决策点 | 选项 A | 选项 B | 建议 |
| --- | --- | --- | --- |
| 计算位置 | 数据库内（PostGIS / 空间库） | 内存或分布式（DuckDB / Spark / GeoPandas） | 千万级以上且涉及邻域配对 → 库内；百万级以下逐要素判定 → 内存 |
| 分块策略 | 按行政单元 | 按瓦片网格 | 与业务口径一致优先；纯几何计算按瓦片更均衡 |
| 并行粒度 | 规则级并行 | 数据块级并行 | 组合最优，但需控制结果归并成本 |
| 结果存储 | 明细缺陷表 | 聚合统计表 | 两者都要：明细供整改，聚合供评定 |
| 误报处理 | 规则调优 | 白名单 | 白名单必须带有效期与责任人，否则会演变为技术性掩盖 |

**（4）并行与分块的隐藏陷阱**

按 tile 切分并行是主流做法，但**边界要素会被切两次**。必须设计重叠缓冲带，并对跨界要素去重或只由一侧负责判定，否则缝隙与接边类检查会出现大量假阳性。另一个陷阱是：接边检查的输入是**图幅边界**，不能用普通瓦片代替——两者几何定义不同，混用会直接产生错误结论。

**（5）增量质检的难点不在计算**

增量质检依赖变更日志、版本化表或内容哈希（对几何 WKB 与属性做 hash，落一张 hash 表，只对 hash 变化的要素重跑规则）。计算本身很便宜，真正的难点是**规则变更时的失效范围判定**：规则版本升级后，历史已通过的数据需要按影响面重新校验。若没有“规则版本 × 数据版本”的矩阵记录，这一判定就只能全量重跑。

**（6）算子规模化能力的公开数据**

| 案例 | 公开指标 | 时间 |
| --- | --- | --- |
| 四川“一张图”地理底图成果质检系统 | 100 余个质检算子并行、日均处理 8000 万要素 | 2025-07 |
| 北京测绘产品质量评价与信息管理系统 | 检查周期由 2 个月压缩至 1 个月内，效率提升约 50% | 2026-06 |
| 部四川测绘质检站 | 总体合格率 91.2%；生产调度人工干预减少 70%；数据流转效率提升 40% | 2026-01 |

> 数据可用性提示：上述“日均 8000 万要素”类指标多为单位或厂商案例，缺少可复现基准，宜作架构设计的量级参考而非验收承诺。真实吞吐取决于检查类型（几何检查与拓扑检查常差一到两个数量级）、硬件（NVMe 与内存）与是否增量。

这些数字的共同指向是：**自动质检在“筛查”环节的 ROI 已非常明确**，瓶颈转移到了“缺陷确认与整改闭环”这一人工环节。

**（7）质检即门禁（QC as Gate）**

更进一步的工程实践是把质检嵌入数据流水线作为**发布前置门禁**：数据入库或更新 → 触发增量质检 → 通过才允许发布服务。配套要求三条：规则与代码一起版本化（规则变更走评审）；门禁分级（block / warn / info）与流水线阶段绑定，避免把所有规则做成阻断导致交付停滞；质检结果作为数据血缘的一部分记录，支持“这个图层为什么可信”的问答。

云原生空间数据栈已有对应实现路径：以 Iceberg 等表格式管理版本，GeoParquet 存储，把质量信号（校验状态、鲜度、模式变更、数据健康度）作为元数据一并跟踪（CARTO 公开材料，2026-09）。

## 本章小结

- 中误差是位置精度的通用度量，但结论取决于检测点是否分布均匀、位于可判读特征点，以及是否按批实施。
- 抽样推断自带生产方风险与使用方风险；C=0 抽样研究给出样本量可降 8%—30% 的量级，但缩减必须有统计学论证，不能凭经验拍减。
- 粗差率是独立判定指标，工程上常以 5% 为界，不能由中误差达标推出粗差达标。
- 分类精度不能只看总体精度：一个总体精度 95% 的模型，可能在细小道路、临时构筑物上完全失效，而这恰是变化发现的重点。
- 规则引擎的价值在可举证、可复用、可回放；脚本集合在这三点上全部失分。
- 分块并行会让边界要素被切两次，接边检查的输入是图幅边界而不是普通瓦片，混用会直接产生错误结论。
- 自动质检在筛查环节的投资回报已经清楚，瓶颈转到缺陷确认与整改；把质检做成发布门禁时，规则要版本化、门禁要分级、结果要进数据血缘。

## 思考与练习

1. 取一份你单位的位置精度检测记录，按 4.3 节核对检测点数量、分布与批次是否符合要求，并复核一次中误差。
2. 有人认为“C=0 抽样能把样本量降两三成，直接照做即可”。用 4.3 节的表述判断这句话缺了什么前提。
3. 给定某市 40 个 tile 的分块方案，写出边界缓冲带与跨界要素去重的处理办法，并说明它防的是哪类假阳性。
4. 为你单位的一条规则设计 rule_id、依据条款、严重级别、适用范围、阈值与抽检策略六个字段，并说明为何缺一不可。
5. 按 4.4 节的规则版本与数据版本矩阵，设计一张能回答“规则升级后哪些已通过数据需要重检”的表。
6. 用 4.4 节的三条门禁配套要求评估你熟悉的一条数据流水线，指出最缺哪一条、补齐的代价在哪。
