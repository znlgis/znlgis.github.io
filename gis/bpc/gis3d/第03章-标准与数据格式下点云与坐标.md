# 第03章 标准与数据格式（下）：点云格式与坐标精度

> **本章导读**
>
> 坐标系是三维项目里最贵的一笔隐形债务：出问题时不在报价单上，返工时连责任都说不清。本章对应原报告 2.1.3—2.1.4 节：先分清 LAS、LAZ、COPC、EPT 四个名字——LAS 是完整档案，COPC 可流式访问且仅支持 PDRF 6/7/8，EPT 是服务化目录；再把 CGCS2000 的三个 EPSG 编码分清，说明为什么“4490 加一列高程”不是三维成果；最后讲高程基准与似大地水准面模型分省更新的现实，以及 RTC_CENTER 相对化如何解释浏览器里的抖动闪面。上一章讲格式接口，这一章讲接口之下真正会让成果作废的东西。

## 学习目标

读完本章，你应当能够：

- 用一句话区分 LAS、LAZ、COPC、EPT 四个名字的定位与适用场景；
- 复述 COPC 仅支持 PDRF 6/7/8 的约束，并说明为什么交付仍要保留 LAS/LAZ 原始档案；
- 分清 EPSG:4490、4479、4480 三个编码的坐标类型与用途，指出把 4490 加高程当三维成果交付会造成什么后果；
- 解释 1985 国家高程基准的正常高与 GPS 大地高之间的高程异常，并说明为什么必须调用分省的似大地水准面模型；
- 用 2.1.4 节解释倾斜摄影模型在浏览器里抖动、闪面的根因，并说明 RTC_CENTER 的作用；
- 把坐标与高程基准声明、转换参数、检查点残差写成可执行的招标技术要求。

## 2.1.3 点云格式：三个必须分清的名字

点云是三维 GIS 中数据量最大的单一类型，格式选择直接影响成本。

| 格式 | 定位 | 关键特性 | 适用 |
|---|---|---|---|
| **LAS 1.4** | ASPRS 交换标准 | 点记录格式（PDRF）6—10 支持 **64 位点计数**与 **WKT CRS** 描述 | 权威归档、成果交付、跨软件交换 |
| **LAZ** | LAS 的无损压缩 | 压缩率通常 5—10 倍，仍是 LAS 语义 | 大规模存储与传输（COPC 即基于 LAZ 1.4） |
| **COPC** | 云优化点云（规范 1.0，©2021 Hobu） | 在 LAZ 文件内部按**聚类八叉树**组织，支持按空间范围**随机访问子块**，无需下载整份文件。**仅支持 PDRF 6/7/8**——转 COPC 前需确认原始点云的记录格式 | Web 端按需加载、云端点云服务 |
| **EPT** | Entwine Point Tile | 树状目录 + JSON 元数据，HTTP 直接取块 | 自建点云服务（PDAL/Entwine 生态） |

**关键区分**：LAS 是“完整档案”，COPC 是“可流式访问的档案”，EPT 是“服务化的目录结构”。做 Web 三维点云，优先 COPC（格式民主、生态广泛）；做超大规模自建服务，EPT 也可行；但**成果交付必须保留 LAS/LAZ 原始档案**，因为 COPC 内部虽然仍是 LAZ，但行业验收习惯仍以 LAS 为准。

〔来源：ASPRS LAS 1.4 规范；COPC 规范 1.0；PDAL/Entwine 文档〕

## 2.1.4 坐标系统与精度：最容易被忽视的技术债

三维 GIS 里最隐蔽、代价最高的问题几乎都出在坐标上。

**必读的三层坐标概念**：

1. **地理坐标系（GCS）**：经纬度 + 高程。中国法定坐标系为 **CGCS2000**（2000 国家大地坐标系）。三维场景需要 **EPSG:4979**（WGS84 三维，经纬度 + 椭球高）。
2. **投影坐标系（PCS）**：如 CGCS2000 / 3 度带高斯-克吕格投影，单位米。工程设计与施工图多用此类。
3. **地心直角坐标系（ECEF）**：以地球质心为原点，3D Tiles、Cesium 内部计算均基于此。它与 ENU（东-北-天局部坐标系）之间的转换是三维渲染的基础运算。

**CGCS2000 的 EPSG 编码必须分清**（这是最容易出错的地方）：

| EPSG | 类型 | 维度 | 误用后果 |
|---|---|---|---|
| **4490** | 地理坐标（经纬度，度） | 二维 | 直接加个“高度”字段当三维用，**不是三维 CRS** |
| **4479** | 地心直角坐标（X/Y/Z，米） | 三维 | 适合计算，不适合直接出图 |
| **4480** | 地理坐标（经纬度 + **椭球高**） | 三维 | 与 4979 结构相同但基准不同，混用会引入米级偏差 |

**工程上最常见的错误**，是把 4490 的二维数据加一列高程就直接当三维成果交付。真正的三维 CRS 是 4480 或 4479。

**高程基准问题**。这是国内项目最常见的坑：
- **1985 国家高程基准**是法定高程系统，基于**正常高**（似大地水准面）；
- 而 GPS/北斗测得的是**大地高**（相对 WGS84/CGCS2000 椭球）；
- 两者差值即**高程异常**，在中国境内可达数十米不等的量级差异，必须通过似大地水准面精化模型（CQG 系列等）转换。

**这条技术债为什么会爆炸**：倾斜摄影生成的模型通常带的是某种近似高程，BIM 模型用的是场地绝对标高或相对标高，点云来自设备坐标系的局部坐标。如果三者不统一到同一高程基准，就会出现“模型飘在空中”或“埋进地下”的经典事故。而且这类误差**在单栋建筑尺度上很难看出来，在城市尺度上却无法掩盖**。

**还有一个易被忽略的现实**：似大地水准面精化模型**不是全国一张网而是分省更新的**。湖南省自然资源厅于 2025-12-25 公告启用“湖南省似大地水准面精化提升成果”，明确属 1985 国家高程基准〔来源：湖南省人民政府门户网站转载省自然资源厅公告，2025-12-25〕；另有资料称浙江自 2025-04-01 起启用新一代模型、广州自 2026-01-01 起全市统一使用 1985 国家高程基准〔二手转述，**待核实**〕。

**由此得出一条硬约束**：跨省三维项目**不能假设全国统一的高程异常格网**，必须按项目所在省调用对应版本的似大地水准面模型，**并在元数据中记录模型版本**，否则高程成果不可复现。这条在跨省线性工程（管网、高铁、输电走廊）中尤其致命。

**实践建议（可写入招标技术要求）**：
- 合同中明确要求**坐标系与高程基准声明**，并作为交付物的一部分（元数据）；
- 要求提供**坐标转换参数与转换后的精度检验点**（不少于 N 个检查点，给出残差）；
- 对跨带、跨投影区域，要求使用**统一的 ECEF 中间态**而非直接平面转换；
- 明确**似大地水准面模型版本**，跨省项目分省处理；
- 三维模型与正射影像、地形之间的**套合检查**应作为验收项，而非“后期调一调”。

**最后一点关于渲染精度的技术真相**：三维引擎内部统一用 ECEF 或 ENU。Cesium 系的做法是通过 **RTC_CENTER（相对中心）**把顶点坐标写成相对值，避免单精度浮点在米级坐标（约 6.4×10⁶ m）上的精度坍塌。**这才是“倾斜摄影模型在浏览器里抖动、闪面”的最常见根因——不是显卡不行，而是坐标没做相对化。**

## 本章小结

- 四个点云名字的定位不同：LAS 用于权威归档，COPC 支持按空间块流式读取，EPT 是服务化的目录结构；做 Web 点云优先 COPC，但成果交付必须保留 LAS/LAZ。
- COPC 基于 LAZ 1.4、以聚类八叉树支持按空间范围随机取块，但仅支持 PDRF 6/7/8，转换前必须核对原始记录格式。
- 三维 CRS 不是二维坐标加一列高程：CGCS2000 的三维表达是 EPSG:4480 或 4479，4490 是二维地理坐标。
- EPSG:4480 与 WGS84 的 EPSG:4979 结构相同但基准不同，混用会引入米级偏差。
- 高程基准是跨省项目的高危项：似大地水准面精化模型分省更新，不能假设全国一张格网，元数据必须记录模型版本。
- 浏览器里的抖动与闪面，常见根因是坐标未做相对化（RTC_CENTER），而不是显卡能力不足。

## 思考与练习

1. 打开你手头任意一份点云成果的元数据，读出它的 PDRF 编号与 CRS 声明，判断能否直接转 COPC。
2. 辨析：某方案写“采用 CGCS2000 三维坐标系（EPSG:4490）”。请指出其中错误，并给出正确编码与补充说明。
3. 一个跨省输电线路项目要在三个省各采一段点云再拼接。用 2.1.4 节列出高程基准处理步骤与元数据必填项。
4. 用户反馈某倾斜摄影模型在浏览器中抖动、近处闪面，同一模型在桌面端正常。按 2.1.4 节给出两条最可能原因与验证方法。
5. 把 2.1.4 节末尾五条实践建议改写成你所在单位的招标技术要求条款，每条注明验收判据。
