# 第04章 引擎与渲染：三足鼎立的真实格局

> **本章导读**
>
> 引擎选型最常见的错误，是把它当成一道单选题。本章对应原报告 2.2.1—2.2.2 节：先说准三段演进——WebGL 解决普及，WebGPU 解决 GPU 侧计算，但其浏览器基线常被夸大，跨浏览器产品仍要保留 WebGL2 回退路径；再逐行读六款产品的能力表，含 3DGS 与信创适配；最后给出分层选型逻辑：格式层选标准、平台层看国产化、渲染层看终端、分析层看专业模型。读完你应能把“选哪个引擎”改写为“哪一层用谁”。

## 学习目标

读完本章，你应当能够：

- 分别说清 WebGL、WebGPU、原生引擎各自解决什么问题，并复述 WebGPU 的浏览器支持现状与工程含义；
- 按 2.2.2 节的表，为瓦片标准、3DGS、空间分析、信创四项能力各举一款产品的具体表述；
- 说明“未见公开表述”在表里的准确含义，避免把它当成“不具备该能力”；
- 用数据格式与交换、服务与平台、渲染与表现、分析计算四层框架，为一个项目写出选型结论；
- 判断一个项目是否需要游戏引擎侧方案，并给出判断依据；
- 指出 3DGS 在工程化早期的稳定性风险，并写出选型时应要求的验证动作。

## 2.2.1 渲染技术栈的演进

- **WebGL（2011—）**：三维 Web 的普及基础，但受限于 OpenGL ES 2.0/3.0 能力，大量场景依赖 CPU 侧优化与瓦片策略“绕过”性能瓶颈。
- **WebGPU（2023—）**：暴露现代图形 API（compute shader、显式资源管理），对**海量点云、3DGS、体数据**这类需要并行计算的负载是质的提升。但其浏览器基线状态常被夸大，需要说准确：**Chrome 144（2026-01-13）、Edge 144（2026-01-21）、Safari 26（2025-09-15）已支持**；Firefox 侧自 2026 年 1 月起在 Windows 与 macOS（Apple Silicon）可默认开启，但 **Linux、macOS Intel、Android 仍不可用**。Web Platform DX 的结论是“Baseline availability blocked since January 2026 by Firefox”〔来源：Web Platform DX《Web Features Explorer — WebGPU》；caniuse WebGPU〕。**工程含义：Chromium 系可用于生产，跨浏览器产品必须保留 WebGL2 回退路径。** 其意义不仅是“更快”，而是让浏览器端能做**GPU 侧的空间计算**（如实时八叉树遍历、点云压缩解压、泼溅渲染）。
- **原生/引擎侧**：Unreal Engine 5（Nanite、Lumen）与 Unity 承接高保真场景，通过 Cesium for Unreal / for Unity 接入地理数据。

**分水岭在哪**：Web 端解决“广覆盖、轻部署、易集成”；游戏引擎解决“高保真、强仿真、沉浸式”。两者不是替代，而是同一项目的不同终端。

> **读表提醒**：表中“未见公开表述”仅表示本次检索未取得一手材料，不代表不具备该能力；厂商自述的能力项未做第三方测评验证。此外，Cesium for Unreal 2.26.0 曾修复“高斯泼溅在场景中持续累积导致崩溃”的缺陷，说明 **3DGS 在工程化早期仍有稳定性坑**，选型时应要求做长时间运行压测。

**选型逻辑应当是分层的**：
- **数据格式与交换层**：尽量选国际标准（3D Tiles / glTF / IFC / CityGML），保证资产不锁定；
- **服务与平台层**：考虑国产化要求、售后服务、行业模板——这一层国产厂商优势明显（SuperMap 内置 GIM（电力）、Geo3DML 2.0（地质）、S-104（海事）等行业标准对接）；
- **渲染与表现层**：Web 端看性能与兼容，高保真端看引擎能力；
- **分析计算层**：看是否真正具备专业模型（水动力、结构、地质），而不是“能画个淹没面”。

## 本章小结

- 引擎格局是分层而非单一：Web 端解决广覆盖、轻部署、易集成，游戏引擎解决高保真、强仿真、沉浸式，两者是同一项目的不同终端。
- WebGPU 的浏览器基线状态常被夸大：Chrome 144、Edge 144、Safari 26 已支持，Firefox 仅限 Windows 与 macOS Apple Silicon，Linux、macOS Intel、Android 仍不可用；跨浏览器产品必须保留 WebGL2 回退路径。
- 表中“未见公开表述”只表示本次检索未取得一手材料，不代表不具备该能力；厂商自述能力项也未做第三方测评验证。
- 3DGS 在工程化早期仍有稳定性坑：Cesium for Unreal 2.26.0 曾修复高斯泼溅持续累积导致崩溃的缺陷，选型时应要求长时间运行压测。
- 选型逻辑应分层：格式与交换层选国际标准保资产不锁定，服务与平台层看国产化与行业模板，渲染层看终端与兼容，分析层看是否有专业模型。
- 判断分析能力不能看“能画个淹没面”，要看是否真正具备水动力、结构、地质等专业模型内核。

## 思考与练习

1. 按 2.2.2 节表格，为你所在项目列出四项能力的必选项与可选项，标注哪些属于厂商自述、需要实测验证。
2. 辨析：某方案写“采用 WebGPU 以获得最佳性能，不再需要 WebGL 回退”。请用 2.2.1 节的浏览器支持事实判断其风险。
3. 给定场景：省级平台、政务内网、需国产化适配、以查询与审查为主。按四层框架给出选型方案与每层取舍理由。
4. 某投标材料写“支持 3DGS 渲染，效果优于摄影测量”。按 2.2.2 节与 2.2.1 节，列出你需要追问的三个问题。
5. 取一款你正在使用或评估的三维引擎，按 2.2.2 节表格逐格填写，缺失项标“未见公开表述”，并判断可用性。
