# 第五章：变量系统与步骤引用

> 本章深入介绍 GeoPipeAgent 的变量系统和步骤引用机制——这是流水线中数据流转的核心基础。你将学会如何定义变量、引用步骤结果、使用表达式系统、以及排查引用相关的常见问题。

---

## 5.1 变量定义与使用

变量是 GeoPipeAgent 流水线中参数化配置的核心手段。通过变量，你可以将经常变化的值（如文件路径、距离参数、CRS 等）提取出来，方便复用和覆盖。

### 5.1.1 变量定义语法

变量在 `pipeline.variables` 字段中定义：

```yaml
pipeline:
  name: example
  variables:
    # 字符串变量
    input_file: "data/buildings.shp"
    output_dir: "output"
    target_crs: "EPSG:3857"
    layer_name: "buildings"
    
    # 数值变量
    buffer_distance: 500
    tolerance: 0.001
    min_area: 100
    max_features: 10000
    
    # 布尔变量
    run_qc: true
    skip_reproject: false
    verbose_output: true
    
    # 列表变量
    fields_to_keep:
      - id
      - name
      - area
      - type
    
    # 嵌套字典变量
    qc_config:
      check_geometry: true
      check_attributes: true
      check_topology: false
      severity_threshold: "warning"
```

### 5.1.2 变量引用语法

在步骤参数中使用 `${var_name}` 语法引用变量：

```yaml
pipeline:
  name: example
  variables:
    input_file: "data/buildings.shp"
    buffer_distance: 500
    target_crs: "EPSG:3857"
    output_dir: "output"
  
  steps:
    - id: load
      use: io.read_vector
      params:
        path: "${input_file}"              # 纯变量引用

    - id: buffer
      use: vector.buffer
      params:
        input: $load
        distance: ${buffer_distance}       # 数值变量引用
    
    - id: reproject
      use: vector.reproject
      params:
        input: $buffer
        target_crs: ${target_crs}          # 字符串变量引用
    
    - id: save
      use: io.write_vector
      params:
        input: $reproject
        path: "${output_dir}/result.gpkg"  # 变量嵌入字符串
```

### 5.1.3 变量引用的类型保留

GeoPipeAgent 的变量引用具有 **类型保留** 特性：

```yaml
variables:
  buffer_distance: 500           # Python int
  tolerance: 0.001               # Python float
  run_qc: true                   # Python bool
  fields: [id, name, area]       # Python list
  config:                        # Python dict
    key: value
```

**规则：**

| 引用方式 | 说明 | 结果类型 |
|----------|------|----------|
| `${var}` 作为整个参数值 | 保留原始类型 | 原始类型（int, float, bool, list, dict） |
| `"...${var}..."` 嵌入字符串 | 转换为字符串 | str |

```yaml
# 整个参数值 → 保留类型
params:
  distance: ${buffer_distance}       # → int(500)
  tolerance: ${tolerance}            # → float(0.001)
  enabled: ${run_qc}                 # → bool(True)
  fields: ${fields}                  # → list(["id", "name", "area"])
  config: ${config}                  # → dict({"key": "value"})

# 嵌入字符串 → 转为 str
params:
  path: "${output_dir}/file.gpkg"    # → str("output/file.gpkg")
  msg: "Distance is ${buffer_distance}m"  # → str("Distance is 500m")
```

### 5.1.4 变量引用的内部实现

变量解析发生在 `PipelineContext._resolve_variables()` 方法中：

```python
import re

VAR_PATTERN = re.compile(r'\$\{([a-zA-Z_][a-zA-Z0-9_]*)\}')

def _resolve_variables(self, template: str) -> Any:
    """解析变量模板"""
    # 情况 1：整个字符串就是一个变量引用 → 保留原始类型
    full_match = re.fullmatch(r'\$\{([a-zA-Z_][a-zA-Z0-9_]*)\}', template)
    if full_match:
        var_name = full_match.group(1)
        if var_name not in self._variables:
            raise ValueError(f"Variable '{var_name}' not defined")
        return self._variables[var_name]  # 返回原始类型
    
    # 情况 2：变量嵌入在字符串中 → 字符串替换
    def replacer(match):
        var_name = match.group(1)
        if var_name not in self._variables:
            raise ValueError(f"Variable '{var_name}' not defined")
        return str(self._variables[var_name])  # 转为字符串
    
    return VAR_PATTERN.sub(replacer, template)
```

### 5.1.5 变量作用域

| 作用域 | 说明 |
|--------|------|
| 全局 | `pipeline.variables` 中定义的变量在所有步骤中可用 |
| 不可变 | 步骤执行过程中不能修改变量值 |
| CLI 覆盖 | 可通过 `--var` 参数覆盖 |

变量在整个流水线生命周期中 **只读**，不能被步骤修改。这确保了流水线的确定性和可重复性。

## 5.2 步骤引用

步骤引用是 GeoPipeAgent 中步骤间数据传递的核心机制。通过步骤引用，后续步骤可以获取前置步骤的输出数据、统计信息等。

### 5.2.1 引用语法总览

| 引用格式 | 解析结果 | 说明 |
|----------|----------|------|
| `$step_id` | `result.output` | 简写形式，获取步骤主输出 |
| `$step_id.output` | `result.output` | 显式获取主输出 |
| `$step_id.stats` | `result.stats` | 获取统计信息字典 |
| `$step_id.status` | `result.status` | 获取执行状态 |
| `$step_id.<key>` | `result.<key>` 或 `result.stats[<key>]` | 获取结果对象属性或统计字段 |

### 5.2.2 `$step_id` — 简写引用

最常用的引用方式，等价于 `$step_id.output`，获取步骤的主输出对象：

```yaml
steps:
  - id: load_data
    use: io.read_vector
    params:
      path: "data.shp"
  
  - id: buffer
    use: vector.buffer
    params:
      input: $load_data          # ← 获取 load_data 步骤的 GeoDataFrame 输出
      distance: 500
```

当步骤执行 `io.read_vector` 后，其输出是一个 `GeoDataFrame`。后续步骤通过 `$load_data` 就能获取这个 `GeoDataFrame`。

### 5.2.3 `$step_id.output` — 显式输出引用

与 `$step_id` 完全等价，但更明确：

```yaml
- id: buffer
  use: vector.buffer
  params:
    input: $load_data.output     # 显式写法，与 $load_data 等价
    distance: 500
```

推荐在可能产生歧义时使用显式写法。

### 5.2.4 `$step_id.stats` — 统计信息引用

获取步骤执行后的统计信息字典：

```yaml
# 步骤执行后的 stats 示例：
# {
#   "feature_count": 1245,
#   "crs": "EPSG:4326",
#   "geometry_type": ["Polygon"],
#   "bounds": [116.2, 39.8, 116.6, 40.1],
#   "columns": ["id", "name", "area", "geometry"]
# }

# 在 outputs 中引用统计信息
outputs:
  data_stats: $load_data.stats
```

### 5.2.5 `$step_id.<key>` — 属性引用

通过 StepResult 的 `__getattr__` 机制，可以直接访问 stats 中的键：

```yaml
# 在 when 条件中使用属性引用
- id: simplify
  use: vector.simplify
  params:
    input: $buffer_result
    tolerance: 10
  when: "buffer_result.stats.feature_count > 10000"
  # 也可以写成：
  # when: "buffer_result.feature_count > 10000"
  # 因为 StepResult.__getattr__ 会代理到 stats 字典
```

**属性引用的解析链：**

```
$step_id.feature_count
    │
    ├─ 1. 在 StepResult 实例属性中查找 → 找到则返回
    │
    └─ 2. 在 StepResult.stats 字典中查找 → 找到则返回
        │
        └─ 3. 抛出 AttributeError
```

对应的 Python 实现：

```python
@dataclass
class StepResult:
    id: str
    use: str
    status: str = "pending"
    output: Any = None
    stats: dict[str, Any] = field(default_factory=dict)
    error: str | None = None
    reason: str | None = None
    duration_seconds: float = 0.0
    
    def __getattr__(self, name: str) -> Any:
        """
        优先从 stats 中查找属性。
        
        这使得以下两种写法等价：
        - result.stats["feature_count"]
        - result.feature_count
        """
        if name.startswith("_"):
            raise AttributeError(name)
        try:
            return self.stats[name]
        except KeyError:
            raise AttributeError(
                f"'{type(self).__name__}' has no attribute '{name}' "
                f"and key '{name}' not found in stats"
            )
```

### 5.2.6 引用在不同上下文中的使用

**在 params 中使用引用：**

```yaml
params:
  input: $load_data                    # 获取 GeoDataFrame
  clip_mask: $boundary                 # 另一个 GeoDataFrame
  zones: $admin_regions                # 用于分区的 GeoDataFrame
```

**在 when 条件中使用引用：**

```yaml
when: "load_data.stats.feature_count > 0"
when: "check_geom.stats.invalid_features > 0"
when: "load_data.status == 'success'"
```

**在 outputs 中使用引用：**

```yaml
outputs:
  result: $final_step
  statistics: $analysis.stats
  qc_report: $qc_check
```

## 5.3 变量解析机制

GeoPipeAgent 的变量和引用解析由 `PipelineContext` 类统一管理。

### 5.3.1 解析流程

当执行器处理一个步骤时，参数解析按以下流程进行：

```
步骤参数 (raw params)
    │
    ▼
context.resolve_params(params)
    │
    ├─ 对每个参数值调用 _resolve_value(value)
    │     │
    │     ├─ 值是字符串？
    │     │     │
    │     │     ├─ 匹配 $step_id 模式？ → _resolve_reference()
    │     │     │     └─ 从 context._results 获取步骤结果
    │     │     │
    │     │     ├─ 包含 ${var} 模式？ → _resolve_variables()
    │     │     │     ├─ 整个字符串是 ${var}？ → 返回原始类型
    │     │     │     └─ 嵌入字符串？ → 字符串替换
    │     │     │
    │     │     └─ 普通字符串 → 原样返回
    │     │
    │     ├─ 值是列表？ → 递归解析每个元素
    │     │
    │     ├─ 值是字典？ → 递归解析每个值
    │     │
    │     └─ 其他类型 → 原样返回
    │
    ▼
解析后的参数 (resolved params)
```

### 5.3.2 完整的解析示例

**原始 YAML：**

```yaml
pipeline:
  variables:
    buffer_dist: 500
    out_dir: "output"
  
  steps:
    - id: load
      use: io.read_vector
      params:
        path: "data/buildings.shp"
    
    - id: buffer
      use: vector.buffer
      params:
        input: $load
        distance: ${buffer_dist}
    
    - id: save
      use: io.write_vector
      params:
        input: $buffer
        path: "${out_dir}/buffer_${buffer_dist}m.gpkg"
        driver: "GPKG"
```

**解析过程：**

```
步骤 load 的参数：
  path: "data/buildings.shp"
    → 普通字符串，无需解析
    → 结果: "data/buildings.shp"

步骤 buffer 的参数：
  input: "$load"
    → 匹配 $step_id 模式
    → _resolve_reference("load", None)
    → context._results["load"].output
    → 结果: <GeoDataFrame>  (load 步骤的输出)
  
  distance: "${buffer_dist}"
    → 匹配 ${var} 模式（整个字符串是一个变量）
    → context._variables["buffer_dist"]
    → 结果: 500  (保留 int 类型)

步骤 save 的参数：
  input: "$buffer"
    → _resolve_reference("buffer", None)
    → 结果: <GeoDataFrame>  (buffer 步骤的输出)
  
  path: "${out_dir}/buffer_${buffer_dist}m.gpkg"
    → 包含变量的字符串模板
    → "output" + "/buffer_" + "500" + "m.gpkg"
    → 结果: "output/buffer_500m.gpkg"  (字符串拼接)
  
  driver: "GPKG"
    → 普通字符串
    → 结果: "GPKG"
```

### 5.3.3 递归解析

变量解析支持嵌套结构的递归解析：

```yaml
params:
  # 列表中的元素会递归解析
  inputs:
    - $step_a
    - $step_b
    - $step_c
  
  # 字典中的值会递归解析
  config:
    primary: $main_data
    secondary: $aux_data
    threshold: ${min_value}
  
  # 嵌套列表+字典
  rules:
    - field: name
      max_length: ${max_name_length}
    - field: area
      min_value: ${min_area}
```

解析后：

```python
# 列表元素被解析为实际对象
{
    "inputs": [<GeoDataFrame_a>, <GeoDataFrame_b>, <GeoDataFrame_c>],
    "config": {
        "primary": <GeoDataFrame_main>,
        "secondary": <GeoDataFrame_aux>,
        "threshold": 100,  # int
    },
    "rules": [
        {"field": "name", "max_length": 50},  # int
        {"field": "area", "min_value": 10.5},  # float
    ]
}
```

## 5.4 引用链

引用链是指多个步骤通过引用串联在一起，形成一条数据处理链。

### 5.4.1 简单引用链

```yaml
steps:
  - id: step_a            # 第一环
    use: io.read_vector
    params:
      path: "data.shp"
  
  - id: step_b            # 第二环：引用 step_a
    use: vector.buffer
    params:
      input: $step_a
      distance: 500
  
  - id: step_c            # 第三环：引用 step_b
    use: vector.dissolve
    params:
      input: $step_b
      by: "type"
  
  - id: step_d            # 第四环：引用 step_c
    use: io.write_vector
    params:
      input: $step_c
      path: "output.gpkg"
```

数据流：

```
step_a → step_b → step_c → step_d
 读取     缓冲     融合     写入
```

### 5.4.2 分支引用链

一个步骤可以被多个后续步骤引用：

```yaml
steps:
  - id: load
    use: io.read_vector
    params:
      path: "data.shp"
  
  # 分支 1：缓冲分析
  - id: buffer
    use: vector.buffer
    params:
      input: $load           # 引用 load
      distance: 500
  
  # 分支 2：质心计算
  - id: centroid
    use: vector.centroid
    params:
      input: $load           # 也引用 load
  
  # 分支 3：QC 检查
  - id: qc
    use: qc.geometry_validity
    params:
      input: $load           # 也引用 load
```

数据流：

```
         ┌──▶ buffer
load ────┼──▶ centroid
         └──▶ qc
```

### 5.4.3 汇合引用链

多个步骤的输出可以汇合到一个步骤：

```yaml
steps:
  - id: load_buildings
    use: io.read_vector
    params:
      path: "buildings.shp"
  
  - id: load_roads
    use: io.read_vector
    params:
      path: "roads.shp"
  
  - id: road_buffer
    use: vector.buffer
    params:
      input: $load_roads
      distance: 200
  
  # 汇合：同时引用 buildings 和 road_buffer
  - id: spatial_join
    use: analysis.spatial_join
    params:
      left: $load_buildings    # 引用 buildings
      right: $road_buffer      # 引用 road_buffer
      how: "inner"
```

数据流：

```
load_buildings ──────────────┐
                              ├──▶ spatial_join
load_roads ──▶ road_buffer ──┘
```

### 5.4.4 复杂引用链示例

```yaml
pipeline:
  name: complex_chain
  variables:
    buffer_dist: 500
  
  steps:
    # 数据加载层
    - id: buildings
      use: io.read_vector
      params:
        path: "buildings.gpkg"
    
    - id: roads
      use: io.read_vector
      params:
        path: "roads.gpkg"
    
    - id: poi
      use: io.read_vector
      params:
        path: "poi.gpkg"
    
    # 预处理层
    - id: building_centroids
      use: vector.centroid
      params:
        input: $buildings
    
    - id: road_buffer
      use: vector.buffer
      params:
        input: $roads
        distance: ${buffer_dist}
    
    # 分析层
    - id: buildings_near_road
      use: analysis.spatial_join
      params:
        left: $buildings
        right: $road_buffer
        how: "inner"
    
    - id: poi_density
      use: analysis.density
      params:
        input: $poi
        radius: 1000
    
    # 综合层
    - id: overlay_result
      use: analysis.overlay
      params:
        input: $buildings_near_road
        overlay: $poi_density
        operation: "intersection"
    
    # QC 层
    - id: qc_check
      use: qc.geometry_validity
      params:
        input: $overlay_result
    
    # 输出层
    - id: save
      use: io.write_vector
      params:
        input: $overlay_result
        path: "output/result.gpkg"
  
  outputs:
    result: $overlay_result
    qc: $qc_check
```

对应的数据流图：

```
buildings ──┬──▶ building_centroids
            │
            └──▶ buildings_near_road ──┐
                          ▲             │
roads ──▶ road_buffer ───┘             ├──▶ overlay_result ──┬──▶ qc_check
                                       │                     │
poi ──────▶ poi_density ──────────────┘                     └──▶ save
```

## 5.5 CLI 变量覆盖

GeoPipeAgent CLI 的 `--var` 参数允许在运行时覆盖流水线中定义的变量。

### 5.5.1 基本语法

```bash
geopipe-agent run pipeline.yaml --var key=value
```

### 5.5.2 覆盖不同类型的变量

```bash
# 覆盖字符串变量
geopipe-agent run pipeline.yaml --var input_file="new_data.shp"

# 覆盖数值变量
geopipe-agent run pipeline.yaml --var buffer_distance=1000

# 覆盖布尔变量
geopipe-agent run pipeline.yaml --var run_qc=true
geopipe-agent run pipeline.yaml --var skip_reproject=false

# 同时覆盖多个变量
geopipe-agent run pipeline.yaml \
  --var buffer_distance=1000 \
  --var target_crs="EPSG:4326" \
  --var run_qc=true \
  --var output_dir="results/run_001"
```

### 5.5.3 类型推断

CLI 传入的变量值会进行自动类型推断：

| 输入值 | 推断类型 | Python 值 |
|--------|----------|-----------|
| `500` | int | `500` |
| `3.14` | float | `3.14` |
| `true` / `True` | bool | `True` |
| `false` / `False` | bool | `False` |
| `null` / `None` | NoneType | `None` |
| `"text"` 或 `text` | str | `"text"` |

### 5.5.4 覆盖优先级

```
CLI --var 参数  >  YAML variables 定义  >  步骤默认值
    (最高)              (中)                 (最低)
```

```yaml
# YAML 定义
pipeline:
  variables:
    buffer_distance: 500     # YAML 中定义为 500
```

```bash
# CLI 覆盖为 1000
geopipe-agent run pipeline.yaml --var buffer_distance=1000
# 实际使用值：1000
```

### 5.5.5 CLI 覆盖的实现

```python
# cli.py 中的处理逻辑
@main.command()
@click.argument("yaml_path")
@click.option("--var", "-v", multiple=True, help="覆盖变量 (key=value)")
def run(yaml_path, var):
    pipeline = parse(yaml_path)
    
    # 应用 CLI 变量覆盖
    for v in var:
        if "=" not in v:
            raise click.BadParameter(f"Invalid variable format: '{v}'. Use key=value")
        
        key, raw_value = v.split("=", 1)
        value = _infer_type(raw_value)
        pipeline.variables[key] = value
    
    # 继续执行...


def _infer_type(raw: str) -> int | float | bool | None | str:
    """推断 CLI 变量值的类型"""
    # 布尔
    if raw.lower() in ("true", "yes"):
        return True
    if raw.lower() in ("false", "no"):
        return False
    
    # None
    if raw.lower() in ("null", "none"):
        return None
    
    # 整数
    try:
        return int(raw)
    except ValueError:
        pass
    
    # 浮点数
    try:
        return float(raw)
    except ValueError:
        pass
    
    # 字符串（去除外层引号）
    if (raw.startswith('"') and raw.endswith('"')) or \
       (raw.startswith("'") and raw.endswith("'")):
        return raw[1:-1]
    
    return raw
```

### 5.5.6 实际使用场景

**场景一：批量运行不同参数**

```bash
# 运行不同缓冲距离
for dist in 100 500 1000 2000; do
  geopipe-agent run buffer.yaml \
    --var buffer_distance=$dist \
    --var output_dir="output/buffer_${dist}m" \
    --report "reports/buffer_${dist}m.json"
done
```

**场景二：不同环境配置**

```bash
# 开发环境
geopipe-agent run pipeline.yaml \
  --var input_file="test_data/small_sample.shp" \
  --var run_qc=false
```

## 5.6 表达式系统

GeoPipeAgent 的 `when` 条件使用一个安全的表达式系统来评估条件。

### 5.6.1 表达式语法

表达式使用 Python 风格的语法，但经过 AST 级别的安全限制：

```yaml
# 比较表达式
when: "feature_count > 100"
when: "status == 'success'"
when: "error_count != 0"
when: "area >= 500.0"

# 逻辑表达式
when: "run_qc and feature_count > 0"
when: "skip_reproject or needs_transform"
when: "not skip_step"
when: "(a > 0) and (b > 0 or c == 0)"

# 步骤引用属性
when: "load_data.stats.feature_count > 1000"
when: "check_geom.stats.invalid_features == 0"
when: "load_data.status == 'success'"

# 函数调用（仅限白名单函数）
when: "len(fields_to_keep) > 3"
when: "max(min_area, 10) > 50"

# 包含检查
when: "'error' in check_result.status"
when: "buffer_distance in [100, 500, 1000]"
```

### 5.6.2 表达式命名空间

表达式求值时可以访问以下命名空间：

```python
namespace = {
    # 1. 流水线变量
    "buffer_distance": 500,
    "run_qc": True,
    "target_crs": "EPSG:3857",
    
    # 2. 已完成的步骤结果（StepResult 对象）
    "load_data": StepResult(
        id="load_data",
        status="success",
        output=<GeoDataFrame>,
        stats={"feature_count": 1245, "crs": "EPSG:4326"}
    ),
    "check_geom": StepResult(
        id="check_geom",
        status="success",
        output=<QcResult>,
        stats={"invalid_features": 3, "total_features": 1245}
    ),
}
```

### 5.6.3 支持的操作符

| 类别 | 操作符 | 示例 |
|------|--------|------|
| **算术** | `+`, `-`, `*`, `/`, `//`, `%`, `**` | `a + b`, `x * 2`, `n ** 2` |
| **比较** | `==`, `!=`, `<`, `<=`, `>`, `>=` | `count > 100` |
| **逻辑** | `and`, `or`, `not` | `a and b`, `not c` |
| **成员** | `in`, `not in` | `x in [1, 2, 3]` |
| **一元** | `-` (负号) | `-threshold` |
| **属性** | `.` (点号) | `result.stats.count` |

### 5.6.4 允许的内置函数

| 函数 | 说明 | 示例 |
|------|------|------|
| `len()` | 长度/大小 | `len(fields) > 3` |
| `min()` | 最小值 | `min(a, b) > 0` |
| `max()` | 最大值 | `max(count, 10)` |
| `sum()` | 求和 | `sum(values) > 100` |
| `abs()` | 绝对值 | `abs(diff) < 0.01` |
| `round()` | 四舍五入 | `round(ratio, 2) == 0.95` |
| `int()` | 转整数 | `int(value) > 0` |
| `float()` | 转浮点数 | `float(text_num) > 3.14` |
| `str()` | 转字符串 | `str(code) == "4326"` |
| `bool()` | 转布尔 | `bool(count)` |

### 5.6.5 禁止的操作

以下操作被 AST 验证器明确禁止：

```yaml
# ❌ 函数定义
when: "lambda x: x > 0"

# ❌ 导入
when: "__import__('os').system('rm -rf /')"

# ❌ 赋值
when: "x = 5"

# ❌ 未白名单的函数调用
when: "eval('malicious_code')"
when: "exec('malicious_code')"
when: "open('/etc/passwd').read()"

# ❌ 列表推导式
when: "[x for x in range(10)]"

# ❌ 字典推导式
when: "{k: v for k, v in items.items()}"
```

## 5.7 安全求值

GeoPipeAgent 的表达式系统基于 **AST（抽象语法树）** 实现安全求值。

### 5.7.1 为什么需要安全求值

在 AI 驱动的工作流中，YAML 流水线可能由 AI 自动生成。如果使用 Python 的 `eval()` 函数来评估 `when` 条件，AI 生成的恶意表达式可能导致：

- 文件系统操作（读写文件）
- 网络访问（数据泄露）
- 系统命令执行（远程代码执行）
- 无限循环（拒绝服务）

### 5.7.2 AST 验证机制

安全求值的核心原理：

```
表达式字符串
    │
    ▼
ast.parse(expression, mode="eval")
    │
    ▼
AST 语法树
    │
    ▼
递归遍历每个节点
    │
    ├─ ast.Constant → 允许（字面值）
    ├─ ast.Name → 检查是否在命名空间中
    ├─ ast.BinOp → 检查操作符是否在白名单中
    ├─ ast.Compare → 检查比较操作符是否在白名单中
    ├─ ast.BoolOp → 允许（and/or）
    ├─ ast.UnaryOp → 检查一元操作符
    ├─ ast.Attribute → 允许（属性访问）
    ├─ ast.Call → 检查函数是否在白名单中
    │
    └─ 其他节点类型 → 拒绝！抛出 ValueError
```

### 5.7.3 安全求值 vs Python eval

| 特性 | safe_eval | Python eval |
|------|-----------|-------------|
| **安全性** | ✅ AST 级限制 | ❌ 可执行任意代码 |
| **函数调用** | ✅ 仅白名单 | ❌ 可调用任意函数 |
| **导入** | ✅ 禁止 | ❌ 可导入模块 |
| **赋值** | ✅ 禁止 | ❌ 可赋值变量 |
| **文件操作** | ✅ 不可能 | ❌ 可读写文件 |
| **网络访问** | ✅ 不可能 | ❌ 可发起请求 |
| **性能** | 略慢（AST 遍历） | 快（直接执行��� |
| **表达能力** | 有限（设计如此） | 完整 Python |

### 5.7.4 安全求值测试用例

```python
# tests/test_safe_eval.py

import pytest
from geopipe_agent.utils.safe_eval import safe_eval

class TestSafeEval:
    """安全求值测试"""
    
    def test_arithmetic(self):
        assert safe_eval("1 + 2", {}) == 3
        assert safe_eval("10 * 3", {}) == 30
        assert safe_eval("2 ** 10", {}) == 1024
    
    def test_comparison(self):
        assert safe_eval("5 > 3", {}) is True
        assert safe_eval("5 == 5", {}) is True
        assert safe_eval("5 != 3", {}) is True
    
    def test_logical(self):
        assert safe_eval("True and True", {}) is True
        assert safe_eval("True or False", {}) is True
        assert safe_eval("not False", {}) is True
    
    def test_variables(self):
        ns = {"x": 10, "y": 20}
        assert safe_eval("x + y", ns) == 30
        assert safe_eval("x > 5 and y < 30", ns) is True
    
    def test_attribute_access(self):
        class MockResult:
            stats = {"count": 42}
        
        ns = {"result": MockResult()}
        assert safe_eval("result.stats", ns) == {"count": 42}
    
    def test_allowed_functions(self):
        assert safe_eval("len([1,2,3])", {}) == 3
        assert safe_eval("min(5, 3)", {}) == 3
        assert safe_eval("max(5, 3)", {}) == 5
        assert safe_eval("abs(-5)", {}) == 5
    
    def test_reject_import(self):
        with pytest.raises(ValueError):
            safe_eval("__import__('os')", {})
    
    def test_reject_eval(self):
        with pytest.raises(ValueError):
            safe_eval("eval('1+1')", {})
    
    def test_reject_lambda(self):
        with pytest.raises(ValueError):
            safe_eval("(lambda: None)()", {})
    
    def test_reject_assignment(self):
        with pytest.raises(SyntaxError):
            # ast.parse 会拒绝赋值语句
            safe_eval("x = 5", {})
    
    def test_complex_expression(self):
        ns = {
            "feature_count": 1245,
            "run_qc": True,
            "threshold": 1000,
        }
        assert safe_eval(
            "run_qc and feature_count > threshold",
            ns
        ) is True
```

## 5.8 完整示例：复杂引用链

以下是一个包含丰富变量和引用的完整流水线示例：

```yaml
pipeline:
  name: comprehensive_reference_example
  description: 展示所有变量和引用功能的综合示例
  crs: "EPSG:4326"
  
  variables:
    # 文件路径
    data_dir: "data"
    output_dir: "output"
    
    # 分析参数
    buffer_distances:
      - 100
      - 500
      - 1000
    primary_buffer: 500
    min_building_area: 50
    target_crs: "EPSG:3857"
    
    # 控制标志
    run_reproject: true
    run_qc: true
    run_topology: false
    simplify_threshold: 5000
    
    # QC 配置
    qc_severity: "warning"
  
  steps:
    # ═══════════════════════════════════════
    # 第一阶段：数据加载
    # ═══════════════════════════════════════
    
    - id: load_buildings
      use: io.read_vector
      params:
        path: "${data_dir}/buildings.gpkg"
    
    - id: load_roads
      use: io.read_vector
      params:
        path: "${data_dir}/roads.gpkg"
    
    - id: load_boundary
      use: io.read_vector
      params:
        path: "${data_dir}/study_area.gpkg"
    
    # ═══════════════════════════════════════
    # 第二阶段：数据预处理
    # ═══════════════════════════════════════
    
    # 条件重投影
    - id: reproject_buildings
      use: vector.reproject
      params:
        input: $load_buildings
        target_crs: ${target_crs}
      when: "run_reproject"
    
    - id: reproject_roads
      use: vector.reproject
      params:
        input: $load_roads
        target_crs: ${target_crs}
      when: "run_reproject"
    
    # 裁剪到研究区域
    - id: clip_buildings
      use: vector.clip
      params:
        input: $load_buildings
        mask: $load_boundary
    
    # 过滤小面积建筑
    - id: filter_buildings
      use: vector.filter
      params:
        input: $clip_buildings
        expression: "area > ${min_building_area}"
    
    # ═══════════════════════════════════════
    # 第三阶段：空间分析
    # ═══════════════════════════════════════
    
    # 缓冲区分析
    - id: create_buffer
      use: vector.buffer
      params:
        input: $filter_buildings
        distance: ${primary_buffer}
    
    # 道路缓冲区
    - id: road_buffer
      use: vector.buffer
      params:
        input: $load_roads
        distance: 200
    
    # 空间连接
    - id: join_result
      use: analysis.spatial_join
      params:
        left: $filter_buildings
        right: $road_buffer
        how: "inner"
        predicate: "intersects"
    
    # 条件简化（基于要素数量）
    - id: simplify_result
      use: vector.simplify
      params:
        input: $create_buffer
        tolerance: 10
        preserve_topology: true
      when: "create_buffer.stats.feature_count > simplify_threshold"
    
    # ═══════════════════════════════════════
    # 第四阶段：质量检查
    # ═══════════════════════════════════════
    
    - id: qc_geometry
      use: qc.geometry_validity
      params:
        input: $create_buffer
        rules:
          - type: no_self_intersection
            severity: error
          - type: valid_polygon
            severity: ${qc_severity}
      when: "run_qc"
    
    - id: qc_attributes
      use: qc.attribute_check
      params:
        input: $filter_buildings
        rules:
          - field: name
            not_null: true
          - field: area
            min_value: ${min_building_area}
      when: "run_qc"
      on_error: skip
    
    - id: qc_topology
      use: qc.topology_check
      params:
        input: $create_buffer
        rules:
          - type: no_overlaps
          - type: no_gaps
      when: "run_qc and run_topology"
      on_error: skip
    
    # ═══════════════════════════════════════
    # 第五阶段：结果输出
    # ═══════════════════════════════════════
    
    - id: save_buffer
      use: io.write_vector
      params:
        input: $create_buffer
        path: "${output_dir}/buffer_${primary_buffer}m.gpkg"
        driver: "GPKG"
    
    - id: save_join
      use: io.write_vector
      params:
        input: $join_result
        path: "${output_dir}/buildings_near_road.gpkg"
        driver: "GPKG"
  
  outputs:
    buffer_result: $create_buffer
    join_result: $join_result
    building_stats: $filter_buildings.stats
    geometry_qc: $qc_geometry
    attribute_qc: $qc_attributes
```

## 5.9 常见错误与解决

### 5.9.1 前向引用（Forward Reference）

**错误：** 步骤引用了尚未执行的后续步骤。

```yaml
# ❌ 错误：buffer 引用了尚未定义的 load_data
steps:
  - id: buffer
    use: vector.buffer
    params:
      input: $load_data        # load_data 还没有定义！
      distance: 500
  
  - id: load_data
    use: io.read_vector
    params:
      path: "data.shp"
```

**错误信息：**

```
❌ buffer: Parameter 'input' references undefined step: 'load_data'
```

**解决：** 调整步骤顺序，被引用的步骤必须在引用之前定义。

```yaml
# ✅ 正确：load_data 在 buffer 之前
steps:
  - id: load_data
    use: io.read_vector
    params:
      path: "data.shp"
  
  - id: buffer
    use: vector.buffer
    params:
      input: $load_data
      distance: 500
```

### 5.9.2 未定义变量

**错误：** 引用了未在 `variables` 中定义的变量。

```yaml
# ❌ 错误：typo_distance 未定义
pipeline:
  variables:
    buffer_distance: 500
  steps:
    - id: buffer
      use: vector.buffer
      params:
        distance: ${typo_distance}  # 拼写错误！应为 buffer_distance
```

**错误信息：**

```
❌ buffer: Variable 'typo_distance' not defined
```

**解决：** 检查变量名拼写，确保在 `variables` 中有定义。

### 5.9.3 循环依赖

GeoPipeAgent 不支持循环依赖。由于步骤按顺序执行，且禁止前向引用，循环依赖在校验阶段就会被检测到：

```yaml
# ❌ 理论上不可能出现循环依赖
# 因为前向引用已被禁止
# 但如果某种方式绕过校验，执行器也会检测到：

# step_a 引用 step_b（前向引用，会被校验拒绝）
# step_b 引用 step_a
```

### 5.9.4 引用格式错误

```yaml
# ❌ 错误的引用格式
params:
  input: load_data           # 缺少 $ 前缀
  input: $Load_Data          # 大写字母
  input: ${load_data}        # 这是变量语法，不是步骤引用
  input: $load_data.output.data  # 嵌套属性太深

# ✅ 正确的引用格式
params:
  input: $load_data          # 简写引用
  input: $load_data.output   # 显式引用
  input: $load_data.stats    # 统计引用
```

### 5.9.5 类型不匹配

```yaml
# ❌ buffer 需要 geodataframe，但提供了字符串
- id: buffer
  use: vector.buffer
  params:
    input: "not_a_geodataframe"   # 字符串，不是步骤引用
    distance: 500

# ✅ 正确：通过步骤引用传递 GeoDataFrame
- id: buffer
  use: vector.buffer
  params:
    input: $load_data              # 步骤引用 → GeoDataFrame
    distance: 500
```

### 5.9.6 变量类型被意外转换

```yaml
# ⚠️ 注意：嵌入字符串会将变量转为字符串
variables:
  distance: 500

steps:
  - id: buffer
    use: vector.buffer
    params:
      # ❌ 这会变成字符串 "500"，不是数字 500
      distance: "buffer distance is ${distance}"
      
      # ✅ 保持为数字
      distance: ${distance}
```

### 5.9.7 错误速查表

| 错误信息 | 原因 | 解决方案 |
|----------|------|----------|
| `references undefined step` | 前向引用或步骤 ID 拼写错误 | 检查步骤顺序和 ID 拼写 |
| `Variable 'X' not defined` | 变量未定义或拼写错误 | 检查 variables 中的定义 |
| `Duplicate step ID` | 步骤 ID 重复 | 给每个步骤唯一的 ID |
| `Invalid step ID format` | ID 包含非法字符 | 使用 `[a-z][a-z0-9_-]*` 格式 |
| `Unknown step type` | use 指定的步骤类型不存在 | 检查步骤名称，运行 `list-steps` |
| `Parameter 'X' is required` | 缺少必填参数 | 添加必填参数 |
| `Type mismatch for parameter` | 参数类型不匹配 | 检查参数类型 |
| `Condition evaluation failed` | when 表达式执行错误 | 检查表达式语法和引用 |
| `AST node type not allowed` | when 表达式包含禁止操作 | 简化表达式，使用允许的操作 |
| `Step 'X' not found in context` | 运行时引用解析失败 | 检查前置步骤是否成功执行 |

## 5.11 本章小结

本章详细介绍了 GeoPipeAgent 的变量系统和步骤引用机制：

1. **变量定义**：在 `pipeline.variables` 中定义，支持 string、number、boolean、list、dict
2. **变量引用**：使用 `${var_name}` 语法，整个值引用保留类型，嵌入字符串转为 str
3. **步骤引用**：使用 `$step_id` 获取输出，`$step_id.stats` 获取统计，`$step_id.<key>` 获取属性
4. **解析机制**：`PipelineContext` 统一管理，递归解析嵌套结构
5. **引用链**：支持简单链、分支链、汇合链、复杂链
6. **CLI 覆盖**：`--var key=value` 在运行时覆盖变量，支持自动类型推断
7. **表达式系统**：Python 风格，支持比较、逻辑、函数调用（白名单限制）
8. **安全求值**：基于 AST 的安全评估，禁止导入、赋值、任意函数调用
9. **常见错误**：前向引用、未定义变量、类型不匹配等的排查方法
