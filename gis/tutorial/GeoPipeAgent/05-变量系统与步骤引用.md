# 第五章：变量系统与步骤引用

## 5.1 概述

GeoPipeAgent 的变量系统和步骤引用机制是流水线动态性的核心来源。通过这两套机制，YAML 流水线从静态配置文件变成了能够表达数据流和参数化逻辑的"活文档"。

变量系统核心功能：
- **参数化**：用变量替代硬编码值，同一流水线适用于不同场景
- **CLI 覆盖**：运行时动态注入值，实现脚本化批处理
- **表达式求值**：在 `when` 条件中使用变量进行逻辑判断

步骤引用核心功能：
- **数据流传递**：将一个步骤的输出传给下一个步骤作为输入
- **属性提取**：引用步骤输出的元数据属性（CRS、要素数量等）
- **条件决策**：在 `when` 表达式中基于运行时步骤结果做判断

## 5.2 变量系统

### 5.2.1 变量定义

变量在 YAML 顶层的 `variables` 块中定义：

```yaml
variables:
  input_path: "data/roads.shp"
  buffer_dist: 500
  run_qc: true
  tolerance: 0.001
  output_formats:
    - GeoJSON
    - GPKG
```

### 5.2.2 变量引用语法

在 `params`、`when` 等字段中使用 `${变量名}` 引用变量：

```yaml
steps:
  - id: load
    use: io.read_vector
    params:
      path: ${input_path}         # 字符串变量

  - id: buffer
    use: vector.buffer
    params:
      input: $load
      distance: ${buffer_dist}    # 数值变量，直接传递数值类型

  - id: optional-step
    use: vector.simplify
    params:
      input: $load
      tolerance: ${tolerance}
    when: "${run_qc} == true"     # 在 when 表达式中引用布尔变量
```

**类型保留**：变量引用时会保留原始类型。例如 `buffer_dist: 500` 是整数，`${buffer_dist}` 在参数中会作为整数 `500` 传递，而不是字符串 `"500"`。

### 5.2.3 字符串插值

当变量嵌入在字符串中时，支持字符串插值：

```yaml
variables:
  output_dir: "output/"
  run_id: "20240115"
  format: "geojson"

steps:
  - id: save
    use: io.write_vector
    params:
      input: $buffer
      path: "${output_dir}result_${run_id}.${format}"
      # 展开为：output/result_20240115.geojson
```

### 5.2.4 CLI 变量覆盖

通过 `--var` 参数在运行时覆盖 YAML 中定义的变量：

```bash
# 基本覆盖
geopipe-agent run pipeline.yaml --var input_path=data/rivers.shp

# 多变量覆盖
geopipe-agent run pipeline.yaml \
  --var input_path=data/rivers.shp \
  --var buffer_dist=1000 \
  --var run_qc=false

# 字符串值覆盖（注意引号处理）
geopipe-agent run pipeline.yaml --var "output_dir=output/batch_001/"
```

**覆盖优先级**：CLI `--var` > YAML `variables` 中的定义。

### 5.2.5 变量的作用域

`variables` 块中定义的变量具有**全局作用域**，在整个流水线的所有步骤和 `when` 表达式中均可使用。目前 GeoPipeAgent 不支持步骤局部变量，所有变量均为全局可见。

## 5.3 步骤引用机制

### 5.3.1 基本步骤引用

`$step-id` 语法引用某步骤的**主要输出**（通常是 GeoDataFrame 或栅格数组）：

```yaml
steps:
  - id: load                    # 定义步骤 id
    use: io.read_vector
    params:
      path: "data/roads.shp"

  - id: reproject
    use: vector.reproject
    params:
      input: $load              # 引用 load 步骤的输出 GeoDataFrame

  - id: buffer
    use: vector.buffer
    params:
      input: $reproject         # 引用 reproject 步骤的输出
      distance: 500
```

### 5.3.2 步骤属性引用

`$step-id.attribute` 语法引用步骤输出的特定**元数据属性**：

```yaml
steps:
  - id: load
    use: io.read_vector
    params:
      path: "data/roads.shp"

  - id: check-crs
    use: qc.crs_check
    params:
      input: $load
      expected_crs: $load.crs           # 引用 load 步骤输出的 crs 属性

  - id: conditional-buffer
    use: vector.buffer
    params:
      input: $load
      distance: 500
    when: "$load.feature_count > 0"     # 基于要素数量判断是否执行
```

**常见可引用属性**：

矢量数据步骤（`io.read_vector`、`vector.*`）：

| 属性名 | 类型 | 说明 |
|--------|------|------|
| `.crs` | str | CRS 字符串，如 `"EPSG:4326"` |
| `.feature_count` | int | 要素数量 |
| `.geometry_type` | str | 几何类型，如 `"LineString"` |
| `.bbox` | list | 边界框 `[minx, miny, maxx, maxy]` |
| `.columns` | list | 属性字段名称列表 |

栅格数据步骤（`io.read_raster`、`raster.*`）：

| 属性名 | 类型 | 说明 |
|--------|------|------|
| `.crs` | str | CRS 字符串 |
| `.width` | int | 像素宽度 |
| `.height` | int | 像素高度 |
| `.band_count` | int | 波段数量 |
| `.nodata` | float/None | NoData 值 |
| `.resolution` | tuple | 像元大小 `(x_res, y_res)` |

质检步骤（`qc.*`）：

| 属性名 | 类型 | 说明 |
|--------|------|------|
| `.issue_count` | int | 质检问题数量 |
| `.passed` | bool | 是否通过质检（issue_count == 0） |
| `.issues` | list | 质检问题详情列表 |

### 5.3.3 引用与执行顺序

步骤引用严格遵循**前向引用**原则：只能引用在当前步骤之前定义的步骤。

```yaml
steps:
  - id: step-a
    use: io.read_vector
    params: { path: "data.shp" }

  - id: step-b
    use: vector.buffer
    params:
      input: $step-a      # ✅ 合法：step-a 在 step-b 之前

  - id: step-c
    use: vector.clip
    params:
      input: $step-b      # ✅ 合法：step-b 在 step-c 之前
      clip: $step-d       # ❌ 非法：step-d 在 step-c 之后（循环/前向引用）

  - id: step-d
    use: io.read_vector
    params: { path: "boundary.shp" }
```

校验时（`validate` 命令）会检测并报告非法引用。

## 5.4 引用解析的内部机制

GeoPipeAgent 的引用解析在 `engine/context.py` 中实现，核心逻辑如下：

### 5.4.1 `PipelineContext` 对象

引擎维护一个 `PipelineContext` 对象，存储：
- **变量表** (`variables`)：包含 YAML 定义的变量和 CLI 传入的覆盖值
- **步骤结果缓存** (`step_results`)：已执行步骤的 `StepResult` 对象，以步骤 ID 为键

### 5.4.2 参数解析流程

每个步骤执行前，引擎对 `params` 进行递归解析：

1. **识别引用**：扫描参数值中的 `${...}` 和 `$...` 模式
2. **变量替换**：`${var_name}` → 从变量表中查找并替换，保留类型
3. **步骤引用替换**：`$step-id` → 从步骤结果缓存中查找并替换
4. **属性提取**：`$step-id.attr` → 从步骤结果对象中提取对应属性
5. **递归处理**：对嵌套的字典和列表参数递归执行上述过程

### 5.4.3 `when` 表达式求值

`when` 字段的字符串表达式通过 `utils/safe_eval.py` 中的安全求值器处理：

1. 首先对表达式中的 `${...}` 和 `$...` 引用进行替换
2. 然后将替换后的表达式传入安全求值器
3. 安全求值器使用 Python AST（抽象语法树）白名单机制，只允许比较、逻辑、数学运算等安全操作
4. 结果转换为布尔值，决定步骤是否执行

**安全求值的白名单操作**：
- 算术运算：`+`、`-`、`*`、`/`、`//`、`%`、`**`
- 比较运算：`==`、`!=`、`<`、`>`、`<=`、`>=`
- 逻辑运算：`and`、`or`、`not`、`in`、`not in`
- 内置函数：`len`、`str`、`int`、`float`、`bool`、`abs`、`round`

**禁止的操作**（安全原因）：
- `import` 语句
- `exec`、`eval` 调用
- 文件 I/O 操作
- 网络请求
- `__dunder__` 属性访问

## 5.5 高级用法示例

### 5.5.1 基于要素数量的条件分支

```yaml
variables:
  simplify_threshold: 1000    # 超过此数量时执行简化

steps:
  - id: load
    use: io.read_vector
    params:
      path: "data/buildings.shp"

  - id: simplify
    use: vector.simplify
    params:
      input: $load
      tolerance: 5.0
    when: "$load.feature_count > ${simplify_threshold}"
    # 要素数量超过 1000 时才进行简化，避免不必要的处理

  - id: save
    use: io.write_vector
    params:
      input: $simplify     # 如果 simplify 被跳过，这里会如何？
      path: "output/buildings_simplified.geojson"
```

> **注意**：如果 `simplify` 步骤被跳过（`when` 为 false），后续引用 `$simplify` 的步骤会引用到跳过步骤的**上游输入**，即 `$load` 的结果。这是 GeoPipeAgent 的透明跳过设计——跳过的步骤"透明地"传递其输入。

### 5.5.2 批量处理模板

```yaml
# pipeline_template.yaml
name: 批量格式转换模板
description: 将输入文件转换为目标格式并重投影

variables:
  # 以下变量通过 --var 在运行时传入
  input_file: ""              # 输入文件路径（必须通过 --var 传入）
  output_file: ""             # 输出文件路径（必须通过 --var 传入）
  target_crs: "EPSG:4326"     # 默认目标 CRS（可覆盖）
  output_driver: "GeoJSON"    # 默认输出格式（可覆盖）

steps:
  - id: load
    use: io.read_vector
    params:
      path: ${input_file}

  - id: reproject
    use: vector.reproject
    params:
      input: $load
      target_crs: ${target_crs}

  - id: save
    use: io.write_vector
    params:
      input: $reproject
      path: ${output_file}
      driver: ${output_driver}

outputs:
  result: $save
```

批量执行脚本（Shell）：

```bash
#!/bin/bash
# 批量处理 data/ 目录下所有 Shapefile

for f in data/*.shp; do
  base=$(basename "$f" .shp)
  geopipe-agent run pipeline_template.yaml \
    --var input_file="$f" \
    --var output_file="output/${base}.geojson" \
    --var target_crs="EPSG:4326"
  echo "处理完成：$base"
done
```

### 5.5.3 链式步骤的 CRS 传播

```yaml
steps:
  - id: load-boundary
    use: io.read_vector
    params:
      path: "data/boundary.shp"

  - id: load-points
    use: io.read_vector
    params:
      path: "data/points.shp"

  # 将 points 投影到与 boundary 相同的 CRS
  - id: reproject-points
    use: vector.reproject
    params:
      input: $load-points
      target_crs: $load-boundary.crs    # 动态获取 boundary 的 CRS
```

通过 `$load-boundary.crs` 动态获取参考图层的 CRS，实现"自适应"投影，无需硬编码 CRS。

## 5.6 `safe_eval` 安全求值器详解

`utils/safe_eval.py` 实现了一个基于 AST 白名单的安全求值器，用于处理 `when` 条件表达式。

### 工作原理

```python
# 安全求值器的核心逻辑（简化示意）
import ast

ALLOWED_NODE_TYPES = {
    ast.Expression, ast.BoolOp, ast.Compare, ast.BinOp,
    ast.UnaryOp, ast.Num, ast.Str, ast.NameConstant,
    ast.Name, ast.And, ast.Or, ast.Not,
    ast.Eq, ast.NotEq, ast.Lt, ast.Gt, ast.LtE, ast.GtE,
    # ... 其他白名单节点类型
}

def safe_eval(expr: str, context: dict) -> bool:
    tree = ast.parse(expr, mode='eval')
    # 遍历 AST，检查所有节点是否在白名单中
    for node in ast.walk(tree):
        if type(node) not in ALLOWED_NODE_TYPES:
            raise ValueError(f"不允许的操作：{type(node).__name__}")
    return eval(compile(tree, '<string>', 'eval'), {"__builtins__": {}}, context)
```

### 安全约束的意义

在 GIS 自动化和 AI 驱动场景中，YAML 流水线可能由 LLM 生成，安全求值器确保：
1. 即使 AI 生成了"恶意"的 `when` 表达式，也无法执行危险代码
2. 防止路径遍历、文件读取、网络请求等安全风险

## 5.7 小结

本章深入介绍了 GeoPipeAgent 的变量系统和步骤引用机制：

- **变量系统**：`${var}` 语法引用全局变量，支持类型保留和字符串插值，可通过 CLI `--var` 覆盖
- **步骤引用**：`$step-id` 传递步骤输出数据，`$step-id.attr` 提取步骤元数据属性
- **引用解析**：通过 `PipelineContext` 维护变量表和步骤结果缓存，执行前递归替换所有引用
- **安全求值**：`when` 表达式通过 AST 白名单机制安全求值，防止代码注入

掌握变量和引用机制后，下一章将介绍流水线的高级控制能力：条件执行、重试和错误策略。
