# 第五章：变量系统与步骤引用

## 5.1 概述

GeoPipeAgent 提供了两种核心引用机制，使流水线具备**参数化**和**数据流传递**的能力：

| 引用类型 | 语法 | 说明 |
|----------|------|------|
| 变量引用 | `${var_name}` | 引用 `variables` 中定义的值 |
| 步骤输出引用 | `$step-id` | 引用步骤的完整输出（等价于 `$step-id.output`） |
| 步骤属性引用 | `$step-id.attr` | 引用步骤输出的特定属性 |

这两种机制共同构成了 GeoPipeAgent 的**数据流图（DAG）**——数据从一个步骤流向下一个步骤，变量则提供全局可调参数。

---

## 5.2 变量系统（`${var_name}`）

### 5.2.1 定义变量

变量在 `pipeline.variables` 字典中定义：

```yaml
pipeline:
  name: "变量系统演示"
  variables:
    # 路径变量
    input_dir: "data/"
    output_dir: "output/"
    input_file: "roads.geojson"

    # 数值变量
    buffer_distance: 500
    simplify_tolerance: 0.001
    min_area: 100.0

    # 布尔变量
    preserve_topology: true
    enable_debug_output: false

    # CRS 变量
    source_crs: "EPSG:4326"
    target_crs: "EPSG:3857"

  steps:
    - id: load
      use: io.read_vector
      params:
        path: "${input_dir}${input_file}"   # 字符串拼接

    - id: reproject
      use: vector.reproject
      params:
        input: "$load"
        target_crs: "${target_crs}"

    - id: buffer
      use: vector.buffer
      params:
        input: "$reproject"
        distance: "${buffer_distance}"
        preserve_topology: "${preserve_topology}"

    - id: save
      use: io.write_vector
      params:
        input: "$buffer"
        path: "${output_dir}buffered_roads.geojson"
        format: "GeoJSON"
```

### 5.2.2 变量替换规则

变量替换发生在**步骤执行前**，由 `executor.py` 中的变量解析器处理。

**完整替换**（变量独占整个参数值）：

```yaml
params:
  distance: "${buffer_distance}"   # 替换后变为数值 500
  path: "${input_path}"            # 替换后变为字符串
```

**嵌入式替换**（变量嵌入字符串中）：

```yaml
params:
  path: "${output_dir}result_${buffer_distance}m.geojson"
  # 替换后：output/result_500m.geojson
```

**未定义变量**：如果引用了未定义的变量，会报 `VariableResolutionError`：

```
VariableResolutionError: 无法解析变量 'undefined_var'，该变量未在 variables 中定义，也未通过 --var 传入
```

### 5.2.3 通过 CLI 覆盖变量

CLI 的 `--var` 参数可以在运行时覆盖 YAML 中定义的变量，**CLI 值优先**：

```bash
# 基本用法
geopipe-agent run pipeline.yaml --var buffer_distance=1000

# 覆盖多个变量
geopipe-agent run pipeline.yaml \
  --var input_dir=data/beijing/ \
  --var buffer_distance=200 \
  --var output_dir=output/beijing/

# 字符串值
geopipe-agent run pipeline.yaml \
  --var target_crs=EPSG:4490

# 布尔值
geopipe-agent run pipeline.yaml \
  --var enable_debug_output=true
```

### 5.2.4 变量最佳实践

**推荐做法：** 将所有可能变化的值提取为变量：

```yaml
pipeline:
  name: "参数化的分析流水线"
  variables:
    # 输入/输出路径
    input_path: "data/roads.shp"
    output_path: "output/result.geojson"

    # 分析参数
    buffer_dist: 500
    target_crs: "EPSG:3857"
    query_condition: "road_class = 'major'"

    # 功能开关
    run_qc: true
    save_intermediate: false

  steps:
    # ...
```

**变量命名规范**：
- 使用小写字母和下划线（`snake_case`）
- 名称应描述其用途，而非值
- 路径变量以 `_path`、`_dir` 结尾
- 布尔开关以 `enable_`、`run_`、`use_` 开头

## 5.3 步骤输出引用（`$step-id`）

步骤引用是 GeoPipeAgent 中**数据流传递**的核心机制。每个步骤执行后都会产生一个 `StepResult` 对象，后续步骤可以引用这个结果。

### 5.3.1 基本引用语法

#### `$step-id`（简写形式）

等价于 `$step-id.output`，引用步骤的主要输出数据：

```yaml
steps:
  - id: load-roads
    use: io.read_vector
    params:
      path: "data/roads.geojson"

  - id: buffer
    use: vector.buffer
    params:
      input: "$load-roads"       # 引用 load-roads 的输出 GeoDataFrame
      distance: 500
```

#### `$step-id.output`（完整形式）

与 `$step-id` 完全等价：

```yaml
params:
  input: "$load-roads.output"   # 等同于 "$load-roads"
```

#### `$step-id.stats`

引用步骤的统计信息字典：

```yaml
outputs:
  buffer_stats: "$buffer.stats"  # 引用 buffer 步骤的统计信息
```

`stats` 字典的内容因步骤类型而异，例如：
- `io.read_vector` 的 stats：`{feature_count, crs, geometry_type, bbox}`
- `vector.buffer` 的 stats：`{feature_count, total_area}`
- `qc.geometry_validity` 的 stats：`{checked, valid, invalid}`

#### `$step-id.issues`

引用 QC 步骤收集的问题列表（仅 QC 步骤有此属性）：

```yaml
outputs:
  qc_problems: "$check-geom.issues"
```

#### `$step-id.metadata`

引用步骤的元数据字典（包含执行时间、后端信息等）：

```yaml
outputs:
  step_metadata: "$load.metadata"
```

#### `$step-id.stats.key`（访问 stats 中的特定键）

```yaml
# 引用 buffer 步骤统计中的 feature_count
outputs:
  count: "$buffer.stats.feature_count"
```

### 5.3.2 数据流示例

以下是一个完整的数据流示例，展示数据如何在步骤之间传递：

```yaml
pipeline:
  name: "数据流演示"
  steps:
    # 步骤1：读取数据 → 产生 GeoDataFrame
    - id: load
      use: io.read_vector
      params:
        path: "data/cities.geojson"

    # 步骤2：接收步骤1的输出 → 过滤 → 产生新 GeoDataFrame
    - id: filter
      use: vector.query
      params:
        input: "$load"              # ← 引用 load 的输出
        expression: "population > 1000000"

    # 步骤3：接收步骤2的输出 → 投影 → 产生新 GeoDataFrame
    - id: reproject
      use: vector.reproject
      params:
        input: "$filter"            # ← 引用 filter 的输出
        target_crs: "EPSG:3857"

    # 步骤4：接收步骤3的输出 → 缓冲 → 产生新 GeoDataFrame
    - id: buffer
      use: vector.buffer
      params:
        input: "$reproject"         # ← 引用 reproject 的输出
        distance: 10000

    # 步骤5：接收步骤4的输出 → 保存
    - id: save
      use: io.write_vector
      params:
        input: "$buffer"            # ← 引用 buffer 的输出
        path: "output/city_buffer.geojson"
        format: "GeoJSON"

  outputs:
    # 引用不同步骤的不同属性
    input_count: "$load.stats.feature_count"
    filtered_count: "$filter.stats.feature_count"
    final_count: "$buffer.stats.feature_count"
```

这构成了一个线性数据流：
```
load → filter → reproject → buffer → save
```

### 5.3.3 QC 步骤的透传模式

QC 步骤有一个特殊的设计：**输入数据作为 `output` 透传**，问题收集在 `issues` 中。这意味着 QC 步骤不修改数据，只是检查并报告问题，数据继续向后流动：

```yaml
pipeline:
  name: "QC 透传示例"
  steps:
    - id: load
      use: io.read_vector
      params:
        path: "data/roads.geojson"

    # QC 检查：几何有效性
    # 注意：$qc-geom 返回的是原始数据，不是过滤后的数据！
    - id: qc-geom
      use: qc.geometry_validity
      params:
        input: "$load"

    # QC 检查：CRS 检查（输入是 qc-geom 的透传输出）
    - id: qc-crs
      use: qc.crs_check
      params:
        input: "$qc-geom"           # ← 透传的原始数据
        expected_crs: "EPSG:4326"

    # 继续分析（使用透传后的数据）
    - id: buffer
      use: vector.buffer
      params:
        input: "$qc-crs"            # ← 又一次透传
        distance: 100

  outputs:
    geometry_issues: "$qc-geom.issues"    # QC 问题
    crs_issues: "$qc-crs.issues"          # QC 问题
    result: "$buffer"                      # 分析结果
```

## 5.4 引用的高级用法

### 5.4.1 在 `when` 条件中使用引用

```yaml
steps:
  - id: load
    use: io.read_vector
    params:
      path: "data/roads.geojson"

  # 只有数据量超过阈值时才做聚类
  - id: cluster
    use: analysis.cluster
    when: "$load.stats.feature_count > 500"
    params:
      input: "$load"
      algorithm: "dbscan"
      eps: 0.01
      min_samples: 5
```

### 5.4.2 在 `outputs` 中使用引用

```yaml
outputs:
  # 最终输出数据
  final_result: "$save.output"

  # 步骤统计
  load_info: "$load.stats"
  buffer_area: "$buffer.stats.total_area"

  # QC 报告
  all_issues: "$qc-final.issues"

  # 元数据
  execution_meta: "$load.metadata"
```

### 5.4.3 两个步骤引用同一个源

```yaml
steps:
  - id: load
    use: io.read_vector
    params:
      path: "data/roads.geojson"

  # 分支1：主干道分析
  - id: main-roads
    use: vector.query
    params:
      input: "$load"               # 引用 load
      expression: "road_type == '主干道'"

  # 分支2：次干道分析（也引用 load，不是 main-roads）
  - id: secondary-roads
    use: vector.query
    params:
      input: "$load"               # 同样引用 load
      expression: "road_type == '次干道'"

  # 合并结果
  - id: merge-results
    use: vector.overlay
    params:
      input: "$main-roads"
      overlay: "$secondary-roads"
      how: "union"
```

## 5.5 引用解析的内部机制

### 5.5.1 解析时机

引用在**步骤执行时**（而非解析时）进行解析：
1. `parser.py` 解析 YAML 为数据模型，保留引用字符串
2. `validator.py` 检查引用的步骤是否存在（静态检查）
3. `executor.py` 在执行每个步骤前，动态解析引用值

### 5.5.2 `PipelineContext` 与 `StepContext`

`context.py` 中定义了两个上下文类：

```python
# PipelineContext：保存全局变量和所有步骤结果
class PipelineContext:
    variables: dict      # 变量值
    step_results: dict   # {step_id: StepResult}

# StepContext：步骤执行时的上下文，提供便捷方法
class StepContext:
    def param(self, key: str) -> Any:
        """获取步骤参数（自动解析变量和引用）"""
        ...

    def get_step_result(self, step_id: str) -> StepResult:
        """获取其他步骤的结果"""
        ...
```

步骤函数通过 `StepContext` 访问已解析的参数：

```python
@step(id="vector.buffer", ...)
def buffer_step(ctx: StepContext) -> StepResult:
    gdf = ctx.param("input")         # 自动解析 "$load-roads" 为 GeoDataFrame
    distance = ctx.param("distance") # 自动解析 "${buffer_dist}" 为数值
    # ...
```

## 5.6 常见问题与错误

### 问题一：步骤引用循环

```yaml
# ✗ 错误：循环引用
steps:
  - id: step-a
    use: vector.buffer
    params:
      input: "$step-b"   # 引用 step-b

  - id: step-b
    use: vector.clip
    params:
      input: "$step-a"   # 引用 step-a（循环！）
```

`validator.py` 会检测并报告循环引用：
```
PipelineValidationError: 检测到循环引用：step-a → step-b → step-a
```

### 问题二：引用不存在的步骤

```yaml
# ✗ 错误
params:
  input: "$typo-step-id"   # 步骤 ID 拼写错误
```

```
PipelineValidationError: 步骤 'buffer' 引用了不存在的步骤 'typo-step-id'
```

### 问题三：引用步骤的前向引用

步骤只能引用**之前已执行的步骤**：

```yaml
# ✗ 错误：step-b 引用了后面的 step-c
steps:
  - id: step-a
    use: io.read_vector
    params:
      path: "data.geojson"

  - id: step-b
    use: vector.buffer
    params:
      input: "$step-c"   # 错误：step-c 在 step-b 之后

  - id: step-c
    use: vector.reproject
    params:
      input: "$step-a"
      target_crs: "EPSG:3857"
```

```
PipelineValidationError: 步骤 'step-b' 引用了尚未执行的步骤 'step-c'（前向引用）
```

### 问题四：变量拼写错误

```yaml
# ✗ 错误：变量名拼写错误
variables:
  buffer_distance: 500

steps:
  - id: buffer
    use: vector.buffer
    params:
      distance: "${buffer_dist}"   # 应该是 buffer_distance
```

```
VariableResolutionError: 无法解析变量 'buffer_dist'
```

## 5.7 综合示例

以下是一个综合使用变量和引用的完整流水线示例：

```yaml
pipeline:
  name: "综合变量与引用示例"
  description: "展示变量系统和步骤引用的综合使用"
  crs: "EPSG:4326"

  variables:
    # 路径配置
    input_roads: "data/roads.geojson"
    input_boundary: "data/boundary.geojson"
    output_dir: "output/"

    # 分析参数
    working_crs: "EPSG:3857"
    buffer_dist: 300
    road_filter: "road_class IN ('primary', 'secondary')"

    # 功能开关
    run_qc: true

  steps:
    # 1. 加载数据
    - id: load-roads
      use: io.read_vector
      params:
        path: "${input_roads}"

    - id: load-boundary
      use: io.read_vector
      params:
        path: "${input_boundary}"

    # 2. QC 检查（条件执行）
    - id: qc-roads
      use: qc.geometry_validity
      when: "${run_qc}"
      params:
        input: "$load-roads"

    # 3. 过滤主次干道
    - id: filter-roads
      use: vector.query
      params:
        input: "$qc-roads"          # 接 QC 透传输出
        expression: "${road_filter}"

    # 4. 投影转换（米制）
    - id: reproject-roads
      use: vector.reproject
      params:
        input: "$filter-roads"
        target_crs: "${working_crs}"

    - id: reproject-boundary
      use: vector.reproject
      params:
        input: "$load-boundary"
        target_crs: "${working_crs}"

    # 5. 缓冲区分析
    - id: buffer
      use: vector.buffer
      params:
        input: "$reproject-roads"
        distance: "${buffer_dist}"
        cap_style: "round"

    # 6. 裁剪到研究区边界
    - id: clip-result
      use: vector.clip
      params:
        input: "$buffer"
        clip: "$reproject-boundary"

    # 7. 转回 WGS84 并保存
    - id: reproject-back
      use: vector.reproject
      params:
        input: "$clip-result"
        target_crs: "EPSG:4326"

    - id: save
      use: io.write_vector
      params:
        input: "$reproject-back"
        path: "${output_dir}road_service_area.geojson"
        format: "GeoJSON"

  outputs:
    # 数据统计
    input_road_count: "$load-roads.stats.feature_count"
    filtered_road_count: "$filter-roads.stats.feature_count"
    buffer_total_area: "$buffer.stats.total_area"

    # QC 结果
    geometry_issues: "$qc-roads.issues"

    # 最终输出
    result_path: "$save"
```

## 5.8 本章小结

本章深入介绍了 GeoPipeAgent 的变量系统和步骤引用机制：

1. **变量引用**（`${var_name}`）：参数化配置，支持 CLI 运行时覆盖
2. **步骤输出引用**（`$step-id`）：传递主要输出数据
3. **步骤属性引用**（`$step-id.stats`、`$step-id.issues`）：访问统计和问题数据
4. **QC 透传模式**：QC 步骤不修改数据，透传原始数据
5. **引用约束**：不允许循环引用和前向引用

理解这两种引用机制是编写复杂流水线的关键基础。
