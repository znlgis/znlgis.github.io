# 第六章：条件执行、重试与错误策略

## 6.1 概述

真实的 GIS 数据处理工作流中，往往需要根据数据特征动态决定执行哪些步骤，并对网络请求或不稳定操作进行容错处理。GeoPipeAgent 通过三个机制支持这些需求：

| 机制 | 字段 | 说明 |
|------|------|------|
| **条件执行** | `when` | 基于条件表达式决定是否执行步骤 |
| **错误策略** | `on_error` | 步骤失败时的处理方式（fail/skip/retry） |
| **重试机制** | `on_error: retry` | 失败时最多重试 3 次，间隔 0.5 秒 |

---

## 6.2 条件执行（`when` 字段）

### 6.2.1 基本语法

`when` 字段接受一个布尔表达式字符串。当表达式求值为 `True` 时步骤执行，为 `False` 时步骤被**跳过（skipped）**。

```yaml
steps:
  - id: optional-step
    use: vector.simplify
    when: "条件表达式"     # True → 执行，False → 跳过
    params:
      input: "$load"
      tolerance: 0.001
```

### 6.2.2 `when` 表达式中可使用的值

#### 引用变量

```yaml
variables:
  run_simplify: true
  min_feature_count: 1000

steps:
  # 基于布尔变量
  - id: simplify
    use: vector.simplify
    when: "${run_simplify}"          # 变量为 true 时执行
    params:
      input: "$load"
      tolerance: 0.001
```

#### 引用步骤统计值

```yaml
steps:
  - id: load
    use: io.read_vector
    params:
      path: "data.geojson"

  # 只有数据量超过 1000 时才简化（避免过度处理小数据集）
  - id: simplify
    use: vector.simplify
    when: "$load.stats.feature_count > 1000"
    params:
      input: "$load"
      tolerance: 0.001

  # 只有 QC 没有发现问题时才继续处理
  - id: process
    use: vector.buffer
    when: "len($qc.issues) == 0"
    params:
      input: "$qc"
      distance: 100
```

#### 数学与逻辑表达式

```yaml
# 比较运算
when: "$load.stats.feature_count > 100"
when: "$load.stats.feature_count >= 1"
when: "$load.stats.feature_count == 0"
when: "$load.stats.feature_count != 0"

# 逻辑组合
when: "${run_analysis} and $load.stats.feature_count > 0"
when: "${use_gdal} or ${use_qgis}"
when: "not ${skip_this_step}"

# 字符串比较
when: "${target_crs} == 'EPSG:3857'"

# 数值范围
when: "$load.stats.feature_count > 100 and $load.stats.feature_count < 10000"
```

### 6.2.3 条件执行的实际场景

#### 场景一：根据数据量决定是否简化

```yaml
pipeline:
  name: "自适应处理流水线"
  variables:
    simplify_threshold: 5000   # 超过 5000 条要素才简化

  steps:
    - id: load
      use: io.read_vector
      params:
        path: "data/roads.geojson"

    # 大数据集才需要简化
    - id: simplify
      use: vector.simplify
      when: "$load.stats.feature_count > ${simplify_threshold}"
      params:
        input: "$load"
        tolerance: 0.0001
        preserve_topology: true

    # 根据是否简化，选择正确的输入
    # 注意：如果 simplify 被跳过，$simplify 会引用前一步骤的透传数据
    - id: reproject
      use: vector.reproject
      params:
        input: "$simplify"
        target_crs: "EPSG:3857"
```

**注意**：当步骤被 `when` 条件跳过时，该步骤 ID 不会产生输出。如果后续步骤引用了被跳过步骤的输出，执行器会报错。因此，需要合理设计流水线结构，避免引用可能被跳过的步骤。

**推荐做法**：将条件步骤放在流水线末尾，或者使用两个并行路径：

```yaml
pipeline:
  name: "安全的条件分支"
  variables:
    need_simplify: false

  steps:
    - id: load
      use: io.read_vector
      params:
        path: "data/roads.geojson"

    # 不管是否简化，reproject 都需要执行
    - id: reproject
      use: vector.reproject
      params:
        input: "$load"
        target_crs: "EPSG:3857"

    # 条件步骤放在末尾
    - id: buffer
      use: vector.buffer
      params:
        input: "$reproject"
        distance: 100

    # 条件性地保存调试输出
    - id: save-debug
      use: io.write_vector
      when: "${need_simplify}"
      params:
        input: "$buffer"
        path: "debug/buffer_debug.geojson"
        format: "GeoJSON"

    # 主输出（无条件）
    - id: save-main
      use: io.write_vector
      params:
        input: "$buffer"
        path: "output/result.geojson"
        format: "GeoJSON"
```

#### 场景二：开发/生产环境区分

```yaml
pipeline:
  name: "环境感知流水线"
  variables:
    debug_mode: false
    sample_data: false

  steps:
    - id: load
      use: io.read_vector
      params:
        path: "data/large_dataset.geojson"

    # 调试时只取前 100 条数据
    - id: sample
      use: vector.query
      when: "${sample_data}"
      params:
        input: "$load"
        expression: "FID < 100"

    # 正式运行时做完整质检
    - id: full-qc
      use: qc.geometry_validity
      when: "not ${debug_mode}"
      params:
        input: "$load"

    # 调试时额外保存中间结果
    - id: save-intermediate
      use: io.write_vector
      when: "${debug_mode}"
      params:
        input: "$load"
        path: "debug/intermediate.geojson"
        format: "GeoJSON"
```

运行时切换：
```bash
# 调试模式
geopipe-agent run pipeline.yaml --var debug_mode=true --var sample_data=true

# 生产模式
geopipe-agent run pipeline.yaml --var debug_mode=false --var sample_data=false
```

#### 场景三：基于 QC 结果决定是否继续

```yaml
pipeline:
  name: "QC 门控流水线"

  steps:
    - id: load
      use: io.read_vector
      params:
        path: "data/submitted_data.geojson"

    - id: qc-validity
      use: qc.geometry_validity
      params:
        input: "$load"

    - id: qc-crs
      use: qc.crs_check
      params:
        input: "$qc-validity"
        expected_crs: "EPSG:4326"

    # 只有零质检问题时才继续处理
    # 注意：这里使用 issues 列表长度判断
    - id: process
      use: vector.buffer
      when: "len($qc-crs.issues) == 0"
      params:
        input: "$qc-crs"
        distance: 100

    - id: save
      use: io.write_vector
      when: "len($qc-crs.issues) == 0"
      params:
        input: "$process"
        path: "output/result.geojson"
        format: "GeoJSON"
```

## 6.3 错误策略（`on_error` 字段）

### 6.3.1 三种策略详解

#### `on_error: fail`（默认）

步骤失败时立即终止整个流水线。这是最严格的策略，适合**生产环境**，确保不会在错误数据上继续处理。

```yaml
steps:
  - id: critical-load
    use: io.read_vector
    on_error: fail      # 默认值，数据加载失败则停止
    params:
      path: "data/critical.geojson"

  - id: critical-process
    use: vector.buffer
    on_error: fail      # 核心处理步骤，失败则停止
    params:
      input: "$critical-load"
      distance: 100
```

执行报告中的体现：
```json
{
  "status": "failed",
  "steps": [
    {"id": "critical-load", "status": "failed", "error": "文件不存在: data/critical.geojson"}
  ]
}
```

#### `on_error: skip`

步骤失败时跳过该步骤，继续执行后续步骤。适合**可选步骤**或**非关键性处理**。

```yaml
steps:
  - id: load
    use: io.read_vector
    params:
      path: "data/roads.geojson"

  # 可选的在线地理编码步骤，网络失败时跳过
  - id: geocode-extras
    use: network.geocode
    on_error: skip      # 跳过，不影响主流程
    params:
      address: "北京市朝阳区"

  # 可选的高级分析步骤
  - id: advanced-cluster
    use: analysis.cluster
    on_error: skip      # 可选分析，失败跳过
    params:
      input: "$load"
      algorithm: "dbscan"

  # 核心步骤：不论前面是否成功，都要执行
  - id: buffer
    use: vector.buffer
    params:
      input: "$load"    # 直接引用 load，不依赖可选步骤
      distance: 100
```

执行报告中的体现：
```json
{
  "status": "success",
  "steps": [
    {"id": "load",            "status": "success"},
    {"id": "geocode-extras",  "status": "skipped", "reason": "ConnectionError: 网络不可用"},
    {"id": "advanced-cluster","status": "skipped", "reason": "ModuleNotFoundError: scipy 未安装"},
    {"id": "buffer",          "status": "success"}
  ]
}
```

#### `on_error: retry`

步骤失败时自动重试，最多重试 **3 次**，每次间隔 **0.5 秒**（指数退避）。适合**网络请求**或**临时性失败**的操作。

```yaml
steps:
  # 从不稳定的 URL 下载数据
  - id: download-data
    use: io.read_vector
    on_error: retry     # 网络不稳定，最多重试 3 次
    params:
      path: "https://api.example.com/data.geojson"

  # 地理编码服务可能有限流
  - id: geocode
    use: network.geocode
    on_error: retry     # 遇到 429 Too Many Requests 时重试
    params:
      address: "上海市浦东新区"

  # 写入共享存储（可能有临时锁）
  - id: save-shared
    use: io.write_vector
    on_error: retry
    params:
      input: "$buffer"
      path: "/shared/output/result.geojson"
      format: "GeoJSON"
```

**重试行为详细说明**：

```
第 1 次尝试 → 失败
等待 0.5 秒
第 2 次尝试 → 失败
等待 0.5 秒
第 3 次尝试 → 失败
等待 0.5 秒
第 4 次尝试（最后一次）→ 失败
→ 报告失败，终止流水线（等同于 fail 策略）
```

执行报告中的体现：
```json
{
  "id": "download-data",
  "status": "failed",
  "attempts": 4,
  "error": "ConnectionTimeout: 连接超时（已重试 3 次）"
}
```

### 6.3.2 组合使用错误策略

不同步骤可以有不同的错误策略：

```yaml
pipeline:
  name: "综合错误策略示例"

  steps:
    # 核心数据加载 → 失败就停
    - id: load-main
      use: io.read_vector
      on_error: fail
      params:
        path: "data/required_data.geojson"

    # 可选补充数据 → 失败就跳过
    - id: load-supplement
      use: io.read_vector
      on_error: skip
      params:
        path: "data/optional_supplement.geojson"

    # 在线服务 → 重试后失败
    - id: online-service
      use: network.geocode
      on_error: retry
      params:
        address: "北京市"

    # 核心分析 → 失败就停
    - id: core-analysis
      use: vector.buffer
      on_error: fail
      params:
        input: "$load-main"
        distance: 100

    # 可选增强分析 → 失败就跳过
    - id: enhanced-analysis
      use: analysis.cluster
      on_error: skip
      params:
        input: "$core-analysis"
        algorithm: "dbscan"

    # 最终保存 → 重试
    - id: save
      use: io.write_vector
      on_error: retry
      params:
        input: "$core-analysis"
        path: "output/result.geojson"
        format: "GeoJSON"
```

## 6.4 `when` 与 `on_error` 的组合

```yaml
pipeline:
  name: "条件+错误策略组合示例"
  variables:
    enable_network: true

  steps:
    - id: load
      use: io.read_vector
      on_error: fail
      params:
        path: "data/pois.geojson"

    # 条件执行 + 失败跳过（双重保护）
    - id: geocode-pois
      use: network.geocode
      when: "${enable_network}"    # 仅在启用网络时执行
      on_error: skip               # 网络失败时跳过
      params:
        input: "$load"

    # 始终执行，但失败重试
    - id: qc-check
      use: qc.geometry_validity
      on_error: retry
      params:
        input: "$load"

    # 条件执行：QC 通过才做高级分析
    - id: advanced-analysis
      use: analysis.voronoi
      when: "len($qc-check.issues) == 0"
      on_error: skip
      params:
        input: "$load"
```

## 6.5 错误处理的最佳实践

### 原则一：关键路径用 `fail`

```yaml
# 核心数据和核心分析步骤使用 fail（默认）
# 不要让错误在错误数据上静默传播
- id: load-critical-data
  use: io.read_vector
  # on_error: fail  ← 默认，无需显式写
  params:
    path: "data/critical.geojson"
```

### 原则二：增强功能用 `skip`

```yaml
# 非必要的增强功能用 skip
- id: optional-enhancement
  use: analysis.heatmap
  on_error: skip
  params:
    input: "$load"
    bandwidth: 0.01
```

### 原则三：网络/IO 用 `retry`

```yaml
# 所有网络请求和文件写入操作使用 retry
- id: save-to-remote
  use: io.write_vector
  on_error: retry
  params:
    input: "$process"
    path: "s3://bucket/result.geojson"
    format: "GeoJSON"
```

### 原则四：`when` 条件不要引用可能被跳过的步骤

```yaml
# ✗ 不推荐：条件可能因引用跳过步骤而报错
- id: step-a
  use: vector.simplify
  when: "${run_simplify}"
  params:
    input: "$load"
    tolerance: 0.001

- id: step-b
  use: vector.buffer
  params:
    input: "$step-a"    # 如果 step-a 被跳过，这里会报错！
    distance: 100
```

```yaml
# ✓ 推荐：将可选步骤放在末尾，或保证后续步骤不依赖它
- id: main-process
  use: vector.buffer
  params:
    input: "$load"      # 直接引用不会被跳过的步骤
    distance: 100

- id: optional-save
  use: io.write_vector
  when: "${save_intermediate}"
  params:
    input: "$main-process"
    path: "debug/intermediate.geojson"
    format: "GeoJSON"
```

## 6.6 本章小结

本章介绍了 GeoPipeAgent 的三个流程控制机制：

1. **条件执行**（`when`）：布尔表达式控制步骤是否执行，可引用变量和步骤统计
2. **错误策略**（`on_error`）：
   - `fail`（默认）：立即终止，适合关键步骤
   - `skip`：跳过继续，适合可选步骤
   - `retry`：最多重试 3 次，适合网络/IO 操作
3. **组合使用**：`when` + `on_error` 可以构建复杂的容错工作流

关键约束：
- 不要让后续步骤引用可能被 `when` 跳过的步骤输出
- `retry` 最多 3 次，间隔 0.5 秒，全部失败后等同于 `fail`
