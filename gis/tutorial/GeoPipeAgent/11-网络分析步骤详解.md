# 第十一章：网络分析步骤详解

## 11.1 概述

网络分析步骤（`network.*`）提供 **3 个地理网络分析功能**，基于 `networkx` 和 `geopy` 库实现。使用前需安装：

```bash
pip install -e ".[network]"
```

安装内容：
- `networkx`：图论与网络分析库
- `geopy`：地理编码服务（支持 Nominatim 等）

| 步骤 ID | 功能 | 依赖 |
|---------|------|------|
| `network.shortest_path` | 最短路径分析 | networkx |
| `network.service_area` | 服务区分析 | networkx |
| `network.geocode` | 地理编码 | geopy |

---

## 11.2 `network.shortest_path`：最短路径分析

在道路网络中找到从起点到终点的最短（或最优）路径，基于 Dijkstra 算法实现。

### 11.2.1 参数说明

| 参数名 | 类型 | 必填 | 默认值 | 说明 |
|--------|------|------|--------|------|
| `input` | GeoDataFrame | **是** | - | 道路网络（线类型） |
| `origin` | list/string | **是** | - | 起点坐标 `[lon, lat]` 或步骤引用 |
| `destination` | list/string | **是** | - | 终点坐标 `[lon, lat]` 或步骤引用 |
| `weight` | string | 否 | `length` | 权重字段（`length`/自定义字段） |

### 11.2.2 使用示例

```yaml
pipeline:
  name: "最短路径分析"
  description: "在城市道路网络中计算两点间最短路径"

  variables:
    roads_path: "data/city_roads.geojson"
    # 起点：北京天安门
    origin_lon: 116.3912
    origin_lat: 39.9075
    # 终点：北京故宫
    dest_lon: 116.3974
    dest_lat: 39.9163

  steps:
    # 加载道路网络
    - id: load-roads
      use: io.read_vector
      params:
        path: "${roads_path}"

    # 道路网络质检
    - id: qc-roads
      use: qc.geometry_validity
      params:
        input: "$load-roads"

    # 计算最短路径（基于几何长度）
    - id: shortest-path
      use: network.shortest_path
      params:
        input: "$qc-roads"
        origin: [${origin_lon}, ${origin_lat}]
        destination: [${dest_lon}, ${dest_lat}]
        weight: "length"

    # 保存路径结果
    - id: save-path
      use: io.write_vector
      params:
        input: "$shortest-path"
        path: "output/shortest_path.geojson"
        format: "GeoJSON"

  outputs:
    path_length: "$shortest-path.stats.total_length"
    path_segments: "$shortest-path.stats.segment_count"
    result: "$save-path"
```

### 11.2.3 带权重的最短路径

在实际道路分析中，往往需要考虑道路等级、拥堵情况等因素：

```yaml
pipeline:
  name: "加权最短路径分析"
  description: "基于行驶时间的最优路径（考虑速度限制）"

  steps:
    - id: load-roads
      use: io.read_vector
      params:
        path: "data/city_roads.geojson"

    # 添加行驶时间字段（时间 = 长度 / 速度）
    # 注意：这里假设数据中有 length（米）和 speed（km/h）字段
    # 实际使用中可能需要预处理数据

    # 基于时间权重的最短路径（最快路径）
    - id: fastest-path
      use: network.shortest_path
      params:
        input: "$load-roads"
        origin: [116.3912, 39.9075]
        destination: [116.4550, 39.9160]
        weight: "travel_time"    # 使用行驶时间作为权重

    # 基于长度权重的最短路径（最短路径）
    - id: shortest-dist-path
      use: network.shortest_path
      params:
        input: "$load-roads"
        origin: [116.3912, 39.9075]
        destination: [116.4550, 39.9160]
        weight: "length"

    - id: save-fastest
      use: io.write_vector
      params:
        input: "$fastest-path"
        path: "output/fastest_path.geojson"
        format: "GeoJSON"
```

### 11.2.4 输出说明

`network.shortest_path` 输出：
- `output`：路径 GeoDataFrame（线类型）
- `stats.total_length`：路径总长度
- `stats.segment_count`：路段数量
- `stats.path_nodes`：途经节点数

## 11.3 `network.service_area`：服务区分析

从指定起点出发，在给定距离或时间范围内可到达的所有区域，生成服务区多边形。

### 11.3.1 参数说明

| 参数名 | 类型 | 必填 | 默认值 | 说明 |
|--------|------|------|--------|------|
| `input` | GeoDataFrame | **是** | - | 道路网络（线类型） |
| `origin` | list | **是** | - | 中心点坐标 `[lon, lat]` |
| `max_distance` | float | **是** | - | 最大服务距离（与权重单位相同） |
| `weight` | string | 否 | `length` | 权重字段 |
| `intervals` | list | 否 | `null` | 多个距离阈值（生成多个服务区） |

### 11.3.2 使用示例

```yaml
pipeline:
  name: "医院服务区分析"
  description: "计算从医院出发 1km、2km、5km 可达范围"

  variables:
    roads_path: "data/beijing_roads.geojson"
    # 北京协和医院
    hospital_lon: 116.4177
    hospital_lat: 39.9173

  steps:
    - id: load-roads
      use: io.read_vector
      params:
        path: "${roads_path}"

    # 单个距离服务区（5km）
    - id: service-area-5km
      use: network.service_area
      params:
        input: "$load-roads"
        origin: [${hospital_lon}, ${hospital_lat}]
        max_distance: 5000      # 5000 米（需要米制坐标的道路数据）
        weight: "length"

    # 多个距离服务区（等时圈：1km、2km、5km）
    - id: service-area-multi
      use: network.service_area
      params:
        input: "$load-roads"
        origin: [${hospital_lon}, ${hospital_lat}]
        max_distance: 5000
        weight: "length"
        intervals: [1000, 2000, 5000]   # 生成 3 个嵌套服务区

    - id: save-service-area
      use: io.write_vector
      params:
        input: "$service-area-multi"
        path: "output/hospital_service_area.geojson"
        format: "GeoJSON"

  outputs:
    service_area_stats: "$service-area-5km.stats"
    result: "$save-service-area"
```

### 11.3.3 基于时间的服务区（等时圈）

```yaml
pipeline:
  name: "消防站等时圈分析"
  description: "计算消防车 5 分钟、10 分钟、15 分钟可达范围"

  variables:
    roads_path: "data/city_roads_with_speed.geojson"
    # 消防站坐标
    station_lon: 116.4000
    station_lat: 39.9000

  steps:
    - id: load-roads
      use: io.read_vector
      params:
        path: "${roads_path}"

    # 基于行驶时间的等时圈（5/10/15 分钟）
    - id: isochrone
      use: network.service_area
      params:
        input: "$load-roads"
        origin: [${station_lon}, ${station_lat}]
        max_distance: 900        # 最大 15 分钟 = 900 秒
        weight: "travel_time"   # 行驶时间（秒）字段
        intervals: [300, 600, 900]  # 5分钟=300s, 10分钟=600s, 15分钟=900s

    - id: save-isochrone
      use: io.write_vector
      params:
        input: "$isochrone"
        path: "output/fire_station_isochrone.geojson"
        format: "GeoJSON"
```

### 11.3.4 输出说明

`network.service_area` 输出多边形数据，每个多边形对应一个距离阈值：
- 如果指定 `intervals`，输出包含 `distance_threshold` 属性字段
- `stats.area_total`：总服务面积
- `stats.road_length_covered`：覆盖的道路总长

## 11.4 `network.geocode`：地理编码

将文字地址（门牌号、地名等）转换为地理坐标（经纬度），使用 Nominatim 服务（基于 OpenStreetMap 数据）。

### 11.4.1 参数说明

| 参数名 | 类型 | 必填 | 默认值 | 说明 |
|--------|------|------|--------|------|
| `address` | string | 条件必填 | - | 单个地址字符串 |
| `input` | GeoDataFrame | 条件必填 | - | 含地址列的 GeoDataFrame（批量编码） |
| `address_field` | string | 否 | `address` | 地址列名（批量编码时） |
| `user_agent` | string | 否 | `geopipe-agent` | Nominatim 请求的 User-Agent |

**注意**：`address` 和 `input` 至少提供一个。

### 11.4.2 单地址编码

```yaml
pipeline:
  name: "单地址地理编码"
  variables:
    target_address: "北京市朝阳区建国路93号万达广场"

  steps:
    - id: geocode-single
      use: network.geocode
      on_error: retry            # 网络请求，添加重试
      params:
        address: "${target_address}"
        user_agent: "my-gis-app"

  outputs:
    location: "$geocode-single"
    coordinates: "$geocode-single.stats"
```

输出示例：
```json
{
  "id": "geocode-single",
  "status": "success",
  "stats": {
    "address": "北京市朝阳区建国路93号万达广场",
    "longitude": 116.4850,
    "latitude": 39.9035,
    "confidence": 0.85
  }
}
```

### 11.4.3 批量地址编码

```yaml
pipeline:
  name: "批量地址地理编码"
  description: "将地址表格批量转换为坐标点"

  steps:
    - id: load-addresses
      use: io.read_vector
      params:
        path: "data/store_addresses.geojson"
        # 假设数据中有 store_name、address 字段

    # 批量地理编码
    - id: geocode-batch
      use: network.geocode
      on_error: skip              # 部分地址可能编码失败，跳过
      params:
        input: "$load-addresses"
        address_field: "address"  # 地址字段名
        user_agent: "my-store-app"

    # 过滤编码失败的记录
    - id: filter-valid
      use: vector.query
      params:
        input: "$geocode-batch"
        expression: "geocode_success == True"

    - id: save-geocoded
      use: io.write_vector
      params:
        input: "$filter-valid"
        path: "output/stores_geocoded.geojson"
        format: "GeoJSON"

  outputs:
    total_addresses: "$load-addresses.stats.feature_count"
    geocoded_count: "$filter-valid.stats.feature_count"
    result: "$save-geocoded"
```

### 11.4.4 Nominatim 使用限制

Nominatim（OpenStreetMap 的公共地理编码服务）有使用限制：
- **请求频率**：最多 1 次/秒
- **批量限制**：不应用于高频商业用途
- **精度**：中国地区地址精度可能较低

**建议**：
1. 使用 `on_error: retry` 应对限速错误
2. 大量地址建议使用商业地理编码 API（百度地图、高德地图等）
3. 对结果进行人工抽检验证

## 11.5 网络分析综合案例

### 案例：快递站点覆盖分析

分析城市中快递站点的分布是否合理，计算服务覆盖情况。

```yaml
pipeline:
  name: "快递站点覆盖分析"
  description: "分析快递站点的服务范围和覆盖盲区"

  variables:
    stations_path: "data/delivery_stations.geojson"
    roads_path: "data/city_roads.geojson"
    residential_path: "data/residential_areas.geojson"
    max_walk_distance: 500       # 步行 500 米

  steps:
    # 1. 数据加载
    - id: load-stations
      use: io.read_vector
      params:
        path: "${stations_path}"

    - id: load-roads
      use: io.read_vector
      params:
        path: "${roads_path}"

    - id: load-residential
      use: io.read_vector
      params:
        path: "${residential_path}"

    # 2. 数据质检
    - id: qc-roads
      use: qc.geometry_validity
      params:
        input: "$load-roads"

    # 3. 投影转换（米制）
    - id: reproject-stations
      use: vector.reproject
      params:
        input: "$load-stations"
        target_crs: "EPSG:3857"

    - id: reproject-roads
      use: vector.reproject
      params:
        input: "$qc-roads"
        target_crs: "EPSG:3857"

    - id: reproject-residential
      use: vector.reproject
      params:
        input: "$load-residential"
        target_crs: "EPSG:3857"

    # 4. 使用泰森多边形划分服务区域
    - id: station-voronoi
      use: analysis.voronoi
      params:
        input: "$reproject-stations"

    # 5. 为每个站点计算步行服务区
    # 注意：这里简化处理，使用缓冲区代替真实步行网络分析
    - id: station-buffer
      use: vector.buffer
      params:
        input: "$reproject-stations"
        distance: "${max_walk_distance}"
        cap_style: "round"

    # 融合服务区（消除重叠）
    - id: service-union
      use: vector.dissolve
      params:
        input: "$station-buffer"

    # 6. 叠加分析：找出覆盖盲区（居住区 - 服务区）
    - id: coverage-gap
      use: vector.overlay
      params:
        input: "$reproject-residential"
        overlay: "$service-union"
        how: "difference"

    # 7. 站点热力图（分析站点分布密度）
    - id: station-heatmap
      use: analysis.heatmap
      params:
        input: "$reproject-stations"
        bandwidth: 1000          # 1km 带宽
        resolution: 100

    # 8. 保存结果
    - id: save-service-area
      use: io.write_vector
      params:
        input: "$service-union"
        path: "output/delivery_coverage.geojson"
        format: "GeoJSON"

    - id: save-gaps
      use: io.write_vector
      params:
        input: "$coverage-gap"
        path: "output/delivery_coverage_gaps.geojson"
        format: "GeoJSON"

    - id: save-heatmap
      use: io.write_raster
      params:
        input: "$station-heatmap"
        path: "output/station_density.tif"

  outputs:
    total_stations: "$load-stations.stats.feature_count"
    coverage_area: "$service-union.stats.total_area"
    gap_area: "$coverage-gap.stats.total_area"
    coverage_ratio: "$service-union.stats"
```

## 11.6 常见问题

### 问题一：network 模块未安装

```
StepNotFoundError: 步骤 'network.shortest_path' 未找到。
提示：网络分析步骤需要安装 network 依赖，请运行：pip install -e ".[network]"
```

解决：
```bash
pip install -e ".[network]"
```

### 问题二：道路网络不连通

最短路径分析要求道路网络是**连通**的（所有道路节点可互达）。如果网络不连通，可能找不到路径。

解决建议：
1. 使用 `qc.topology` 步骤检查道路连通性
2. 使用 QGIS 或 PostGIS 修复道路网络的拓扑关系

### 问题三：地理编码服务超时

```
network.geocode: ConnectionTimeout 地理编码服务超时
```

解决：
```yaml
- id: geocode
  use: network.geocode
  on_error: retry          # 自动重试 3 次
  params:
    address: "北京市海淀区"
    user_agent: "my-app"
```

## 11.7 本章小结

本章介绍了 3 个网络分析步骤（需要 `network` 依赖包）：

1. **`network.shortest_path`**：Dijkstra 最短路径，支持自定义权重
2. **`network.service_area`**：服务区分析，支持多距离等时圈
3. **`network.geocode`**：地理编码，使用 Nominatim（OpenStreetMap），注意使用限制

网络分析的关键要素：
- 道路网络必须正确建模（节点连接）
- 权重字段的选择影响分析结果（长度/时间/成本）
- 地理编码受网络条件和服务限制影响，建议添加重试和错误处理
