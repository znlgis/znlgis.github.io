# 第十一章：网络分析步骤详解

## 11.1 概述

网络分析步骤（前缀 `network`）提供基于图论和地理编码的网络分析能力，共 3 个步骤：

| 步骤 ID | 名称 | 主要功能 | 依赖包 |
|---------|------|----------|--------|
| `network.shortest_path` | 最短路径分析 | 图论最短路径计算 | networkx |
| `network.service_area` | 服务区分析 | 等时圈/等距圈分析 | networkx |
| `network.geocode` | 地理编码 | 地址/地名转坐标 | geopy |

**安装依赖**：使用网络分析步骤前需安装 `network` 可选依赖：

```bash
pip install -e ".[network]"
```

## 11.2 `network.shortest_path`

### 功能说明

基于线性网络（道路、管线等）构建图模型，计算两点之间的最短路径。底层使用 networkx 的图论算法（Dijkstra 或 A*）。

### 参数说明

| 参数 | 类型 | 必填 | 默认值 | 说明 |
|------|------|------|--------|------|
| `network` | ref | ✅ | — | 路网矢量 GeoDataFrame（LineString） |
| `start` | list/str | ✅ | — | 起点坐标 `[x, y]`，或 WKT 点字符串 |
| `end` | list/str | ✅ | — | 终点坐标 `[x, y]`，或 WKT 点字符串 |
| `weight` | str | ❌ | `"length"` | 边权重字段：`"length"`（欧氏距离）或属性字段名 |
| `algorithm` | str | ❌ | `"dijkstra"` | 最短路径算法：`dijkstra` / `astar` |
| `tolerance` | float | ❌ | 50.0 | 起终点与路网的最大捕捉距离（单位：CRS 坐标单位） |

### 输出结果

输出为矢量 GeoDataFrame，包含：
- `geometry`：最短路径线段（LineString）
- `total_length`：路径总长度
- `segment_count`：路径包含的路段数量

### 使用示例

```yaml
# 加载路网
- id: load-roads
  use: io.read_vector
  params:
    path: "data/road_network.shp"

# 投影到平面坐标系
- id: proj-roads
  use: vector.reproject
  params:
    input: $load-roads
    target_crs: "EPSG:3857"

# 最短路径（坐标定义起终点）
- id: shortest-path
  use: network.shortest_path
  params:
    network: $proj-roads
    start: [12958000, 4825000]     # Web 墨卡托坐标
    end: [12962000, 4828000]
    weight: "length"

# 使用加权路段（考虑道路等级）
- id: weighted-path
  use: network.shortest_path
  params:
    network: $proj-roads
    start: [12958000, 4825000]
    end: [12962000, 4828000]
    weight: "travel_time"    # 按行程时间最短路径

# 保存路径结果
- id: save-path
  use: io.write_vector
  params:
    input: $shortest-path
    path: "output/shortest_path.geojson"
```

### 构建带权路网

要实现按行程时间的最短路径，需要在路网数据中预先计算行程时间字段：

```yaml
# 假设路网有 speed_kmh 字段和 length 字段
# 先计算行程时间（分钟）
- id: calc-time
  use: vector.query
  params:
    input: $load-roads
    expr: "speed_kmh > 0"    # 过滤掉无效速度值

# 实际项目中可以通过 Python 脚本预处理路网
# 添加 travel_time = length / (speed_kmh * 1000 / 60) 字段
```

## 11.3 `network.service_area`

### 功能说明

从给定起点出发，在路网上计算指定时间/距离范围内可到达的服务区（等时圈或等距圈）。

### 参数说明

| 参数 | 类型 | 必填 | 默认值 | 说明 |
|------|------|------|--------|------|
| `network` | ref | ✅ | — | 路网矢量 GeoDataFrame |
| `origin` | list/str | ✅ | — | 起点坐标 `[x, y]` |
| `cutoff` | float/list | ✅ | — | 截断值（最大路径成本）；多个值生成多个等时圈 |
| `weight` | str | ❌ | `"length"` | 成本字段：`"length"` 或自定义字段名 |
| `tolerance` | float | ❌ | 50.0 | 起点捕捉容差 |
| `method` | str | ❌ | `"buffer"` | 服务区生成方法：`buffer`（节点缓冲合并）/`convex_hull`（凸包） |

### 使用示例

```yaml
# 加载路网
- id: load-road
  use: io.read_vector
  params:
    path: "data/roads.shp"

- id: proj-road
  use: vector.reproject
  params:
    input: $load-road
    target_crs: "EPSG:3857"

# 单一服务区（1000 米等距圈）
- id: service-1km
  use: network.service_area
  params:
    network: $proj-road
    origin: [12958000, 4825000]
    cutoff: 1000
    weight: "length"

# 多级等时圈（5/10/15 分钟）
- id: service-isochrones
  use: network.service_area
  params:
    network: $proj-road
    origin: [12958000, 4825000]
    cutoff: [300, 600, 900]    # 5/10/15 分钟（单位：秒），需路网有 travel_time 字段
    weight: "travel_time"

# 保存服务区
- id: save-service
  use: io.write_vector
  params:
    input: $service-1km
    path: "output/service_area.geojson"
```

### 服务区与泰森多边形的区别

| 维度 | 服务区（network.service_area） | 泰森多边形（analysis.voronoi） |
|------|-------------------------------|-------------------------------|
| 考虑道路 | ✅ 是（基于实际路网） | ❌ 否（基于直线距离） |
| 更真实 | ✅ 是 | ❌ 否 |
| 计算成本 | 较高 | 低 |
| 适用场景 | 真实可达性分析 | 快速理论分析 |

## 11.4 `network.geocode`

### 功能说明

将文字地址或地名转换为地理坐标（经纬度），底层使用 geopy 调用 Nominatim 地理编码服务（OpenStreetMap 数据）。

### 参数说明

| 参数 | 类型 | 必填 | 默认值 | 说明 |
|------|------|------|--------|------|
| `address` | str/list | ✅ | — | 待地理编码的地址字符串，或地址列表 |
| `provider` | str | ❌ | `"nominatim"` | 地理编码服务提供商（当前仅支持 `nominatim`） |
| `user_agent` | str | ❌ | `"geopipe-agent"` | Nominatim 必须的 User-Agent 标识 |
| `timeout` | int | ❌ | 10 | 请求超时（秒） |
| `language` | str | ❌ | `"zh"` | 返回结果语言 |
| `country_codes` | str | ❌ | None | 限制搜索国家（ISO 3166 代码，如 `"cn"`） |

### 使用示例

```yaml
# 单地址地理编码（带重试，应对网络波动）
- id: geocode
  use: network.geocode
  params:
    address: "北京市海淀区西二旗大街"
    country_codes: "cn"
  on_error: retry

# 批量地址地理编码
- id: geocode-batch
  use: network.geocode
  params:
    address:
      - "北京市天安门广场"
      - "上海市外滩"
      - "广州市珠江新城"
    country_codes: "cn"
    timeout: 15
  on_error: retry

# 保存地理编码结果
- id: save-geocoded
  use: io.write_vector
  params:
    input: $geocode-batch
    path: "output/geocoded_locations.geojson"
```

### 输出结构

地理编码结果为点 GeoDataFrame，包含：
- `geometry`：Point 几何（经纬度坐标，WGS84）
- `address`：原始输入地址
- `display_name`：Nominatim 返回的完整地址名称
- `confidence`：置信度（如果服务提供）

### Nominatim 使用限制

Nominatim 公共 API 有以下限制：
- 请求频率：最多 1 次/秒
- 必须设置 `user_agent`（标识应用）
- 禁止大批量并发请求
- 中国地址解析精度有限

对于生产环境的大批量地理编码，建议：
1. 部署私有 Nominatim 实例
2. 使用商业地理编码服务（高德、百度等）通过 `generic_cli` 或 `curl_api` 后端调用

## 11.5 综合示例：应急设施可达性分析

```yaml
name: 应急设施可达性分析
description: 分析城区各地点到最近医院的路网可达性

variables:
  road_network: "data/city_roads.gpkg"
  hospitals_csv: "data/hospitals.csv"   # 含医院地址

steps:
  # 加载路网
  - id: load-roads
    use: io.read_vector
    params:
      path: ${road_network}
      layer: "roads"

  # 加载并地理编码医院数据（假设 hospitals.csv 中有 address 字段）
  # 实际使用时，通常直接加载含坐标的数据
  - id: geocode-hospitals
    use: network.geocode
    params:
      address:
        - "北京协和医院"
        - "北京大学人民医院"
        - "北京朝阳医院"
    country_codes: "cn"
  on_error: retry

  # 投影到平面坐标
  - id: proj-roads
    use: vector.reproject
    params:
      input: $load-roads
      target_crs: "EPSG:3857"

  - id: proj-hospitals
    use: vector.reproject
    params:
      input: $geocode-hospitals
      target_crs: "EPSG:3857"

  # 为每家医院生成 15 分钟服务区（简化示例，实际需循环）
  # 注意：当前 service_area 一次处理单个起点
  # 完整批量分析建议通过脚本循环调用

  # 保存医院点位
  - id: save-hospitals
    use: io.write_vector
    params:
      input: $proj-hospitals
      path: "output/hospitals.geojson"

outputs:
  hospitals: $save-hospitals
```

## 11.6 网络分析性能与注意事项

### 路网预处理

networkx 需要将 GeoDataFrame 线要素转换为图结构，这个过程对大型路网（>10 万条路段）可能较慢。建议：

1. 使用 `vector.clip` 将路网裁剪到分析区域，减少要素数量
2. 使用 `vector.query` 过滤掉不需要的道路类型
3. 考虑使用更专业的路网分析工具（OSMnx + NetworkX）

```yaml
# 预处理：只保留主干道和次干道
- id: filter-roads
  use: vector.query
  params:
    input: $load-roads
    expr: "road_class in ['motorway', 'primary', 'secondary']"

- id: clip-to-area
  use: vector.clip
  params:
    input: $filter-roads
    clip: $study-area
```

### 地理编码速率限制

Nominatim 公共 API 限制为 1 次/秒，批量地址编码时需考虑：

```yaml
# 使用 retry 处理偶发超时
- id: geocode
  use: network.geocode
  params:
    address: "北京市朝阳区"
  on_error: retry    # 失败时自动重试
```

### 坐标系一致性

网络分析步骤要求路网和起终点坐标使用相同的坐标系，且建议使用投影坐标系（如 EPSG:3857），以确保距离计算的准确性。

## 11.7 小结

本章介绍了 GeoPipeAgent 的 3 个网络分析步骤（需 `[network]` 依赖）：

- **`network.shortest_path`**：路网最短路径计算，基于 networkx 图论
- **`network.service_area`**：等时圈/等距圈服务区分析，支持多级截断值
- **`network.geocode`**：地址/地名转坐标，底层调用 Nominatim

网络分析步骤依赖外部服务（地理编码）或需要较长计算时间，建议结合 `on_error: retry` 使用。
