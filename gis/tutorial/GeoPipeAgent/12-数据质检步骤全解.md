# 第十二章：数据质检（QC）步骤全解

## 12.1 概述

数据质检（Quality Control，QC）是 GIS 数据处理中的重要环节。GeoPipeAgent 提供 **10 个 QC 步骤**，覆盖矢量和栅格数据的常见质量问题。

### 12.1.1 QC 步骤的核心设计模式：检查并透传

**所有 QC 步骤遵循统一的"检查并透传"模式**：

```
输入数据 → QC 步骤 → 输出（原始数据，未修改）
                    ↓
                  issues（发现的问题列表）
```

- `output`：原始输入数据（透传，不修改）
- `issues`：检测到的质量问题列表（`QcIssue` 对象）
- `stats`：检查统计信息

这意味着 QC 步骤可以**串联在数据流中**，不会中断数据流动，只是在 `issues` 中积累发现的问题。

### 12.1.2 QC 步骤汇总

| 步骤 ID | 检查类型 | 适用数据 |
|---------|----------|----------|
| `qc.geometry_validity` | 几何有效性 | 矢量 |
| `qc.crs_check` | 坐标参考系统 | 矢量 |
| `qc.topology` | 拓扑关系 | 矢量 |
| `qc.attribute_completeness` | 属性完整性 | 矢量 |
| `qc.attribute_domain` | 属性值域 | 矢量 |
| `qc.value_range` | 数值范围 | 矢量 |
| `qc.duplicate_check` | 重复要素 | 矢量 |
| `qc.raster_nodata` | 栅格 NoData | 栅格 |
| `qc.raster_resolution` | 栅格分辨率 | 栅格 |
| `qc.raster_value_range` | 栅格值域 | 栅格 |

## 12.2 矢量 QC 步骤

### 12.2.1 `qc.geometry_validity`：几何有效性检查

检测几何图形是否符合 OGC 规范（如自相交、重叠环等问题）。

**参数**：

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| `input` | GeoDataFrame | **是** | 输入矢量数据 |

**stats 输出**：

```json
{
  "checked": 1000,
  "valid": 998,
  "invalid": 2,
  "invalid_geometry_types": ["自相交", "环方向错误"]
}
```

**issues 输出**（每个问题一条）：

```json
[
  {
    "type": "invalid_geometry",
    "severity": "error",
    "feature_id": 42,
    "message": "多边形自相交",
    "geometry_type": "Polygon"
  }
]
```

**示例**：

```yaml
pipeline:
  name: "几何有效性检查"
  steps:
    - id: load
      use: io.read_vector
      params:
        path: "data/parcels.geojson"

    - id: check-geometry
      use: qc.geometry_validity
      params:
        input: "$load"

    # 继续分析（使用透传数据）
    - id: buffer
      use: vector.buffer
      params:
        input: "$check-geometry"   # 透传的原始数据
        distance: 100

  outputs:
    geometry_issues: "$check-geometry.issues"
    valid_count: "$check-geometry.stats.valid"
    invalid_count: "$check-geometry.stats.invalid"
```

### 12.2.2 `qc.crs_check`：CRS 检查

验证数据的坐标参考系统是否符合预期。

**参数**：

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| `input` | GeoDataFrame | **是** | 输入数据 |
| `expected_crs` | string | 否 | 期望的 CRS（EPSG 代码） |

**示例**：

```yaml
steps:
  - id: load
    use: io.read_vector
    params:
      path: "data/roads.geojson"

  - id: check-crs
    use: qc.crs_check
    params:
      input: "$load"
      expected_crs: "EPSG:4326"

outputs:
  crs_issues: "$check-crs.issues"
```

**stats 输出**：

```json
{
  "actual_crs": "EPSG:32650",
  "expected_crs": "EPSG:4326",
  "match": false
}
```

---

### 12.2.3 `qc.topology`：拓扑关系检查

检查矢量数据的拓扑关系，如重叠、缝隙、悬挂端点等。

**参数**：

| 参数名 | 类型 | 必填 | 默认值 | 说明 |
|--------|------|------|--------|------|
| `input` | GeoDataFrame | **是** | - | 输入数据 |
| `checks` | list | 否 | 全部 | 检查类型列表 |
| `tolerance` | float | 否 | `0.000001` | 拓扑容差 |

**checks 可选值**：
- `overlaps`：检查面要素是否有重叠
- `gaps`：检查面要素之间是否有缝隙
- `dangles`：检查线要素是否有悬挂端点
- `self_intersects`：检查线是否自相交
- `duplicate_nodes`：检查是否有重复节点

**示例**：

```yaml
steps:
  - id: load-landuse
    use: io.read_vector
    params:
      path: "data/landuse_polygons.geojson"

  - id: check-topology
    use: qc.topology
    params:
      input: "$load-landuse"
      checks: ["overlaps", "gaps"]
      tolerance: 0.00001

outputs:
  topology_issues: "$check-topology.issues"
```

---

### 12.2.4 `qc.attribute_completeness`：属性完整性检查

检查必填属性字段是否存在且非空。

**参数**：

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| `input` | GeoDataFrame | **是** | 输入数据 |
| `required_fields` | list | **是** | 必填字段名列表 |

**示例**：

```yaml
steps:
  - id: load
    use: io.read_vector
    params:
      path: "data/buildings.geojson"

  - id: check-completeness
    use: qc.attribute_completeness
    params:
      input: "$load"
      required_fields:
        - "building_id"
        - "floor_count"
        - "construction_year"
        - "usage_type"

outputs:
  completeness_issues: "$check-completeness.issues"
```

**stats 输出**：

```json
{
  "checked_fields": 4,
  "total_features": 500,
  "missing_summary": {
    "construction_year": 23,
    "usage_type": 5
  }
}
```

---

### 12.2.5 `qc.attribute_domain`：属性值域检查

验证属性值是否在允许的值域集合内（枚举类型检查）。

**参数**：

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| `input` | GeoDataFrame | **是** | 输入数据 |
| `field` | string | **是** | 要检查的字段名 |
| `allowed_values` | list | **是** | 允许值列表 |

**示例**：

```yaml
steps:
  - id: load
    use: io.read_vector
    params:
      path: "data/roads.geojson"

  # 检查道路类型是否合法
  - id: check-road-type
    use: qc.attribute_domain
    params:
      input: "$load"
      field: "road_type"
      allowed_values:
        - "主干道"
        - "次干道"
        - "支路"
        - "步行道"

  # 检查道路状态是否合法
  - id: check-road-status
    use: qc.attribute_domain
    params:
      input: "$check-road-type"
      field: "status"
      allowed_values: [0, 1, 2, 3]     # 0=规划, 1=在建, 2=开通, 3=废弃

outputs:
  type_issues: "$check-road-type.issues"
  status_issues: "$check-road-status.issues"
```

---

### 12.2.6 `qc.value_range`：数值范围检查

验证数值属性是否在指定的最小/最大值范围内。

**参数**：

| 参数名 | 类型 | 必填 | 默认值 | 说明 |
|--------|------|------|--------|------|
| `input` | GeoDataFrame | **是** | - | 输入数据 |
| `field` | string | **是** | - | 要检查的字段名 |
| `min_value` | float | 否 | `null` | 最小允许值（含） |
| `max_value` | float | 否 | `null` | 最大允许值（含） |

**示例**：

```yaml
steps:
  - id: load
    use: io.read_vector
    params:
      path: "data/roads.geojson"

  # 检查速度限制（20-120 km/h）
  - id: check-speed
    use: qc.value_range
    params:
      input: "$load"
      field: "speed_limit"
      min_value: 20
      max_value: 120

  # 检查车道数（1-8 车道）
  - id: check-lanes
    use: qc.value_range
    params:
      input: "$check-speed"
      field: "lane_count"
      min_value: 1
      max_value: 8

  # 只检查最大值（高程不超过 8848m，不限下限）
  - id: check-elevation
    use: qc.value_range
    params:
      input: "$check-lanes"
      field: "elevation"
      max_value: 8848

outputs:
  speed_issues: "$check-speed.issues"
  lanes_issues: "$check-lanes.issues"
```

---

### 12.2.7 `qc.duplicate_check`：重复要素检查

检测数据集中是否存在重复的要素（几何完全相同或属性完全相同）。

**参数**：

| 参数名 | 类型 | 必填 | 默认值 | 说明 |
|--------|------|------|--------|------|
| `input` | GeoDataFrame | **是** | - | 输入数据 |
| `check_geometry` | bool | 否 | `true` | 是否检查几何重复 |
| `check_attributes` | bool | 否 | `false` | 是否检查属性重复 |
| `key_fields` | list | 否 | `null` | 用于判断重复的关键字段 |

**示例**：

```yaml
steps:
  - id: load
    use: io.read_vector
    params:
      path: "data/pois.geojson"

  # 检查几何重复（相同位置的重复 POI）
  - id: check-duplicates-geom
    use: qc.duplicate_check
    params:
      input: "$load"
      check_geometry: true
      check_attributes: false

  # 检查属性重复（相同 ID 的重复记录）
  - id: check-duplicates-attr
    use: qc.duplicate_check
    params:
      input: "$check-duplicates-geom"
      check_geometry: false
      check_attributes: true
      key_fields: ["poi_id"]

outputs:
  duplicate_issues: "$check-duplicates-attr.issues"
```

## 12.3 栅格 QC 步骤

### 12.3.1 `qc.raster_nodata`：栅格 NoData 检查

检查栅格数据中 NoData（无效值）的比例是否超出允许范围。

**参数**：

| 参数名 | 类型 | 必填 | 默认值 | 说明 |
|--------|------|------|--------|------|
| `input` | Raster | **是** | - | 输入栅格 |
| `max_nodata_ratio` | float | 否 | `0.1` | 最大 NoData 比例（0-1） |

**示例**：

```yaml
steps:
  - id: load-dem
    use: io.read_raster
    params:
      path: "data/dem.tif"

  - id: check-nodata
    use: qc.raster_nodata
    params:
      input: "$load-dem"
      max_nodata_ratio: 0.05    # NoData 不超过 5%

outputs:
  nodata_issues: "$check-nodata.issues"
```

---

### 12.3.2 `qc.raster_resolution`：栅格分辨率检查

验证栅格数据的分辨率是否符合预期（常用于多栅格一致性验证）。

**参数**：

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| `input` | Raster | **是** | 输入栅格 |
| `expected_resolution` | float/list | **是** | 期望分辨率（单值或 [x_res, y_res]） |
| `tolerance` | float | 否 | `0.0001` | 允许误差 |

**示例**：

```yaml
steps:
  - id: load-raster1
    use: io.read_raster
    params:
      path: "data/band1.tif"

  # 检查分辨率是否为 30m（Landsat）
  - id: check-resolution
    use: qc.raster_resolution
    params:
      input: "$load-raster1"
      expected_resolution: 0.00027    # 约 30m（度单位）
      tolerance: 0.00001
```

---

### 12.3.3 `qc.raster_value_range`：栅格值域检查

验证栅格像元值是否在合理范围内。

**参数**：

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| `input` | Raster | **是** | 输入栅格 |
| `min_value` | float | 否 | 无限制 |
| `max_value` | float | 否 | 无限制 |
| `band` | int | 否 | 全部波段 |

**示例**：

```yaml
steps:
  - id: load-dem
    use: io.read_raster
    params:
      path: "data/dem.tif"

  # 检查 DEM 高程值（-500m 到 9000m）
  - id: check-dem-range
    use: qc.raster_value_range
    params:
      input: "$load-dem"
      min_value: -500
      max_value: 9000
      band: 1

  # 检查 NDVI 值域（-1 到 1）
  - id: load-ndvi
    use: io.read_raster
    params:
      path: "data/ndvi.tif"

  - id: check-ndvi-range
    use: qc.raster_value_range
    params:
      input: "$load-ndvi"
      min_value: -1.0
      max_value: 1.0
```

## 12.4 QC 流水线综合案例

### 案例：完整的 GIS 数据质检流水线

```yaml
pipeline:
  name: "GIS 数据综合质检报告"
  description: "对提交的道路数据进行全面质量检查，生成质检报告"

  variables:
    input_path: "data/submitted_roads.geojson"
    expected_crs: "EPSG:4326"

  steps:
    # 1. 读取数据
    - id: load
      use: io.read_vector
      params:
        path: "${input_path}"

    # 2. 几何有效性检查
    - id: qc-geometry
      use: qc.geometry_validity
      params:
        input: "$load"

    # 3. CRS 检查
    - id: qc-crs
      use: qc.crs_check
      params:
        input: "$qc-geometry"
        expected_crs: "${expected_crs}"

    # 4. 拓扑检查
    - id: qc-topology
      use: qc.topology
      params:
        input: "$qc-crs"
        checks: ["dangles", "self_intersects"]
        tolerance: 0.000001

    # 5. 属性完整性检查
    - id: qc-completeness
      use: qc.attribute_completeness
      params:
        input: "$qc-topology"
        required_fields:
          - "road_id"
          - "road_name"
          - "road_type"
          - "speed_limit"
          - "lane_count"

    # 6. 道路类型值域检查
    - id: qc-road-type
      use: qc.attribute_domain
      params:
        input: "$qc-completeness"
        field: "road_type"
        allowed_values:
          - "expressway"
          - "primary"
          - "secondary"
          - "residential"
          - "service"

    # 7. 速度限制范围检查
    - id: qc-speed
      use: qc.value_range
      params:
        input: "$qc-road-type"
        field: "speed_limit"
        min_value: 10
        max_value: 120

    # 8. 车道数范围检查
    - id: qc-lanes
      use: qc.value_range
      params:
        input: "$qc-speed"
        field: "lane_count"
        min_value: 1
        max_value: 10

    # 9. 重复要素检查
    - id: qc-duplicates
      use: qc.duplicate_check
      params:
        input: "$qc-lanes"
        check_geometry: true
        check_attributes: true
        key_fields: ["road_id"]

  outputs:
    # 各步骤质检结果
    geometry_issues: "$qc-geometry.issues"
    crs_issues: "$qc-crs.issues"
    topology_issues: "$qc-topology.issues"
    completeness_issues: "$qc-completeness.issues"
    road_type_issues: "$qc-road-type.issues"
    speed_issues: "$qc-speed.issues"
    lanes_issues: "$qc-lanes.issues"
    duplicate_issues: "$qc-duplicates.issues"

    # 统计信息
    total_features: "$load.stats.feature_count"
    geometry_valid: "$qc-geometry.stats.valid"
    geometry_invalid: "$qc-geometry.stats.invalid"
```

## 12.5 QC issues 结构

每个 QC 问题（`QcIssue`）包含以下字段：

```python
@dataclass
class QcIssue:
    type: str          # 问题类型（如 "invalid_geometry"）
    severity: str      # 严重程度："error" / "warning" / "info"
    message: str       # 问题描述
    feature_id: Any    # 涉及的要素 ID（可选）
    field: str         # 涉及的字段名（可选）
    value: Any         # 问题值（可选）
```

JSON 序列化示例：
```json
[
  {
    "type": "invalid_geometry",
    "severity": "error",
    "feature_id": 42,
    "message": "多边形存在自相交问题",
    "field": null,
    "value": null
  },
  {
    "type": "value_out_of_range",
    "severity": "warning",
    "feature_id": 128,
    "message": "speed_limit 值 150 超过最大允许值 120",
    "field": "speed_limit",
    "value": 150
  }
]
```

## 12.6 根据 QC 结果决定是否继续

```yaml
steps:
  # ... QC 步骤 ...
  - id: qc-final
    use: qc.duplicate_check
    params:
      input: "$qc-speed"

  # 只有无质检问题时才保存数据
  - id: save-approved
    use: io.write_vector
    when: "len($qc-final.issues) == 0"
    params:
      input: "$qc-final"
      path: "output/approved_data.geojson"
      format: "GeoJSON"

  # 有问题时保存问题报告
  - id: save-rejected-notice
    use: io.write_vector
    when: "len($qc-final.issues) > 0"
    params:
      input: "$qc-final"
      path: "output/rejected_data.geojson"
      format: "GeoJSON"
```

## 12.7 本章小结

本章介绍了 10 个 QC 步骤：

**矢量 QC（7 个）**：
1. `qc.geometry_validity`：几何有效性（自相交等）
2. `qc.crs_check`：坐标系检查
3. `qc.topology`：拓扑关系（重叠、缝隙、悬挂）
4. `qc.attribute_completeness`：必填字段检查
5. `qc.attribute_domain`：枚举值域检查
6. `qc.value_range`：数值范围检查
7. `qc.duplicate_check`：重复要素检查

**栅格 QC（3 个）**：
8. `qc.raster_nodata`：NoData 比例检查
9. `qc.raster_resolution`：分辨率一致性
10. `qc.raster_value_range`：栅格值域检查

**核心模式**：所有 QC 步骤"检查并透传"——数据流动不中断，问题收集在 `issues` 中。
