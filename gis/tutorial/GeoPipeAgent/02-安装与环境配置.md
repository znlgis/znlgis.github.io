# 第2章：安装与环境配置

> 本章详细介绍 GeoPipeAgent 的安装方式、后端环境配置、开发环境搭建以及常见安装问题的解决方案。

---

## 2.1 系统要求

### 2.1.1 Python 版本要求

GeoPipeAgent 要求 **Python 3.10** 或更高版本。这是因为项目使用了 Python 3.10 引入的多项语言特性：

| 特性 | 最低版本 | 用途 |
|------|---------|------|
| 结构化模式匹配 `match/case` | 3.10 | 复杂条件分支处理 |
| 联合类型语法 `X \| Y` | 3.10 | 类型提示简化 |
| `dataclass` 增强 | 3.10 | 模型定义（StepInfo、StepResult 等） |
| `ParamSpec` / `TypeVarTuple` | 3.10 | 装饰器类型推断 |

检查 Python 版本：

```bash
python --version
# 或
python3 --version
```

如果版本低于 3.10，请先升级 Python。

### 2.1.2 操作系统支持

| 操作系统 | 支持状态 | 说明 |
|---------|---------|------|
| **Linux** (Ubuntu 20.04+) | ✅ 完全支持 | 推荐的运行环境 |
| **macOS** (11.0+) | ✅ 完全支持 | 需要 Homebrew 安装 GDAL |
| **Windows** (10/11) | ✅ 完全支持 | 推荐使用 conda 管理依赖 |

### 2.1.3 硬件建议

| 用途 | 内存 | 磁盘空间 |
|------|------|---------|
| 基本使用 | 4GB+ | 2GB+ |
| 大数据处理 | 16GB+ | 10GB+ |
| 栅格分析 | 16GB+ | 20GB+ |

## 2.2 安装方式详解

### 2.2.1 基础安装

基础安装包含 GeoPipeAgent 的核心功能和 `native_python` 后端所需的所有依赖：

```bash
pip install geopipe-agent
```

基础安装将安装以下依赖（定义在 `pyproject.toml` 的 `[project.dependencies]` 中）：

```
click>=8.0          # CLI 框架
pyyaml>=6.0         # YAML 解析
geopandas>=0.14     # 矢量数据处理
shapely>=2.0        # 几何运算
fiona>=1.9          # 矢量数据 IO
rasterio>=1.3       # 栅格数据处理
```

安装完成后，您就可以使用 `native_python` 后端执行流水线了。

### 2.2.2 完整安装

如果您需要使用空间分析和网络分析功能，可以安装可选依赖：

```bash
# 安装分析依赖
pip install geopipe-agent[analysis]

# 安装网络分析依赖
pip install geopipe-agent[network]

# 安装所有可选依赖
pip install geopipe-agent[analysis,network]

# 安装开发依赖
pip install geopipe-agent[dev]

# 安装全部（含开发依赖）
pip install geopipe-agent[analysis,network,dev]
```

### 2.2.3 各可选依赖组详解

**分析依赖 `[analysis]`**

| 包 | 版本 | 用途 |
|---|------|------|
| `scipy` | >=1.10 | 科学计算库，提供空间统计（最近邻、距离矩阵等）和插值功能 |
| `scikit-learn` | >=1.2 | 机器学习库，用于空间聚类分析（DBSCAN、K-Means）和异常检测 |
| `matplotlib` | >=3.7 | 可视化库，用于生成分析结果图表和空间分布图 |

**网络分析依赖 `[network]`**

| 包 | 版本 | 用途 |
|---|------|------|
| `networkx` | >=3.0 | 图论算法库，用于路径分析、网络连通性分析和服务区计算 |
| `geopy` | >=2.3 | 地理编码库，用于地址到坐标的转换和距离计算 |

**开发依赖 `[dev]`**

| 包 | 版本 | 用途 |
|---|------|------|
| `pytest` | >=7.0 | Python 测试框架 |
| `pytest-cov` | >=4.0 | 代码覆盖率统计 |

### 2.2.4 从源码安装

```bash
# 克隆仓库
git clone https://github.com/your-org/geopipe-agent.git
cd geopipe-agent

# 以开发模式安装
pip install -e ".[analysis,network,dev]"
```

`-e` 参数表示以"可编辑模式"安装，代码修改会立即生效，适合开发调试。

## 2.3 虚拟环境配置

### 2.3.1 使用 venv

Python 内置的 `venv` 模块适合大多数场景：

```bash
# 创建虚拟环境
python3 -m venv geopipe-env

# 激活虚拟环境
# Linux/macOS:
source geopipe-env/bin/activate
# Windows:
geopipe-env\Scripts\activate

# 安装 GeoPipeAgent
pip install geopipe-agent[analysis,network]

# 验证
geopipe-agent info

# 退出虚拟环境
deactivate
```

### 2.3.2 使用 conda

conda 在处理 GDAL 等 C/C++ 依赖时有显著优势：

```bash
# 创建 conda 环境
conda create -n geopipe python=3.11 -y
conda activate geopipe

# 安装 GDAL（conda 管理 C 库更方便）
conda install -c conda-forge gdal -y

# 安装 GeoPipeAgent
pip install geopipe-agent[analysis,network]

# 验证
geopipe-agent info
geopipe-agent backends
```

**使用 conda 的优势**：

```
┌────────────────────────────────────────────┐
│         venv vs conda 对比                  │
├──────────────┬─────────────────────────────┤
│   维度       │  venv        │  conda       │
├──────────────┼─────────────┼──────────────┤
│  Python包    │  ✅ pip      │  ✅ conda/pip│
│  C/C++库     │  ❌ 需手动   │  ✅ 自动管理 │
│  GDAL 安装   │  复杂       │  一键安装     │
│  跨平台      │  需各自处理  │  统一管理     │
│  环境隔离    │  ✅          │  ✅           │
│  磁盘占用    │  较小        │  较大         │
└──────────────┴─────────────┴──────────────┘
```

### 2.3.3 环境管理最佳实践

```bash
# 导出当前环境依赖（用于复现）
pip freeze > requirements.txt

# 在新环境中复现
pip install -r requirements.txt

# 使用 conda 导出
conda env export > environment.yml

# 从 yml 文件复现
conda env create -f environment.yml
```

## 2.4 验证安装

### 2.4.1 基本验证命令

安装完成后，执行以下命令验证：

```bash
# 1. 查看工具信息
geopipe-agent info
```

预期输出：

```
GeoPipeAgent - AI-Native GIS Pipeline Framework
Version: x.x.x
Python: 3.11.x
Platform: linux
```

```bash
# 2. 查看可用后端
geopipe-agent backends
```

预期输出（基础安装）：

```
Available backends:
  ✓ native_python    GeoPandas 0.14.x + Shapely 2.0.x
  ✗ gdal_cli         ogr2ogr not found in PATH
  ✗ gdal_python      osgeo package not available
  ✗ qgis_process     qgis_process not found in PATH
  ✗ pyqgis           qgis.core not available
```

每个后端的可用性由对应的 `is_available()` 方法检测，该方法定义在 `backends/base.py` 的 `GeoBackend` 抽象基类中，各后端子类实现具体的检测逻辑。

### 2.4.2 步骤列表验证

```bash
# 3. 列出所有可用步骤
geopipe-agent list-steps
```

预期输出（部分）：

```
IO Steps (4):
  io.read_file        Read spatial data file
  io.write_file       Write spatial data to file
  ...

Vector Steps (7):
  vector.buffer       Create buffer around geometries
  vector.clip         Clip geometries by mask
  vector.dissolve     Dissolve geometries by attribute
  ...

Raster Steps (5):
  raster.read         Read raster data
  ...

Analysis Steps (4):
  analysis.spatial_join    Spatial join between layers
  analysis.overlay         Overlay analysis
  ...

Network Steps (3):
  network.shortest_path    Find shortest path
  ...

QC Steps (10):
  qc.check_geometry   Check geometry validity
  qc.check_crs        Check CRS consistency
  ...
```

### 2.4.3 单步骤详情验证

```bash
# 4. 查看某个步骤的详细信息
geopipe-agent describe vector.buffer
```

预期输出：

```
Step: vector.buffer
Name: Buffer
Category: vector
Description: Create buffer zones around geometries

Parameters:
  input       (geodataframe)  Input geometries     [required]
  distance    (number)        Buffer distance       [required]
  resolution  (integer)       Buffer resolution     [optional, default: 16]

Outputs:
  output      (geodataframe)  Buffered geometries

Supported Backends:
  native_python, gdal_cli, gdal_python

Examples:
  - id: buffer_step
    use: vector.buffer
    params:
      input: $previous_step
      distance: 100
```

步骤信息来源于 `StepInfo` 数据类（`steps/registry.py`），包括 `id`、`func`、`name`、`description`、`category`、`params`、`outputs`、`backends`、`examples` 等字段。

## 2.5 后端环境配置

### 2.5.1 native_python 后端（默认）

基础安装即可使用，无需额外配置。该后端基于 GeoPandas + Shapely 实现（`backends/native_python_backend.py`）。

后端提供的核心操作：

```python
# GeoBackend 抽象基类定义的标准接口
class GeoBackend:
    def name(self) -> str: ...
    def is_available(self) -> bool: ...
    def buffer(self, gdf, distance, **kwargs): ...
    def clip(self, gdf, mask, **kwargs): ...
    def reproject(self, gdf, crs, **kwargs): ...
    def dissolve(self, gdf, by, **kwargs): ...
    def simplify(self, gdf, tolerance, **kwargs): ...
    def overlay(self, gdf, other, how, **kwargs): ...
```

### 2.5.2 GDAL CLI 后端

GDAL CLI 后端（`backends/gdal_cli.py`）通过调用 `ogr2ogr` 等命令行工具执行操作。

**Linux (Ubuntu/Debian) 安装**：

```bash
sudo apt-get update
sudo apt-get install -y gdal-bin
# 验证
ogr2ogr --version
ogrinfo --version
```

**macOS 安装**：

```bash
brew install gdal
# 验证
ogr2ogr --version
```

**Windows 安装**：

```bash
# 使用 OSGeo4W 安装器
# 下载: https://trac.osgeo.org/osgeo4w/
# 或使用 conda:
conda install -c conda-forge gdal
```

安装完成后验证：

```bash
geopipe-agent backends
# 应显示: ✓ gdal_cli
```

### 2.5.3 GDAL Python 后端

GDAL Python 后端（`backends/gdal_python_backend.py`）使用 GDAL/OGR 的 Python 绑定。

```bash
# 方法1: 使用 conda（推荐）
conda install -c conda-forge gdal

# 方法2: 使用 pip（需要系统已安装 GDAL 开发库）
pip install GDAL==$(gdal-config --version)

# 验证
python -c "from osgeo import ogr, osr, gdal; print(gdal.VersionInfo())"
```

**注意**：使用 pip 安装 GDAL Python 绑定时，系统必须已经安装了 GDAL 开发库（`libgdal-dev`），并且 pip 安装的版本必须与系统 GDAL 版本匹配。

### 2.5.4 QGIS Process 后端

QGIS Process 后端（`backends/qgis_process.py`）通过 QGIS 的 Processing CLI 工具执行操作。

**Linux 安装**：

```bash
# Ubuntu
sudo apt-get install -y qgis qgis-plugin-grass
# 验证
qgis_process --help
```

**macOS 安装**：

```bash
brew install --cask qgis
# qgis_process 通常在: /Applications/QGIS.app/Contents/MacOS/bin/
export PATH="/Applications/QGIS.app/Contents/MacOS/bin:$PATH"
```

**验证**：

```bash
qgis_process list
geopipe-agent backends
# 应显示: ✓ qgis_process
```

### 2.5.5 PyQGIS 后端

PyQGIS 后端（`backends/pyqgis_backend.py`）使用 QGIS 的 Python API。

```bash
# 通常与 QGIS 安装一起提供
# 需要正确配置 Python 路径

# Linux: 检查 PyQGIS 路径
python -c "import qgis.core; print('PyQGIS available')"

# 如果导入失败，可能需要设置 PYTHONPATH:
export PYTHONPATH="/usr/share/qgis/python:$PYTHONPATH"
```

### 2.5.6 后端选择策略

```
┌────────────────────────────────────────────────┐
│           后端选择决策树                         │
│                                                │
│  需要处理的数据量？                              │
│  ├── 小数据 (<100MB)                           │
│  │   └── native_python ✓                       │
│  ├── 中等数据 (100MB-1GB)                      │
│  │   ├── 需要精细控制？                         │

│  │   └── 已有 QGIS 环境？                       │
│  │       └── 是 → qgis_process                 │
│  └── 大数据 (>1GB)                             │
│      └── gdal_cli ✓ (内存效率最高)              │
└────────────────────────────────────────────────┘
```

### 2.6.3 项目目录结构

开发时的典型项目结构：

```
geopipe-agent/
├── src/
│   └── geopipe_agent/
│       ├── __init__.py          # 包入口，自动加载步骤
│       ├── cli.py               # CLI 定义
│       ├── errors.py            # 异常定义
│       ├── backends/            # 后端实现
│       ├── engine/              # 引擎核心
│       ├── models/              # 数据模型
│       ├── steps/               # 步骤实现
│       ├── skillgen/            # Skill 生成
│       └── utils/               # 工具函数
├── tests/                       # 测试文件
├── pyproject.toml               # 项目配置
├── README.md                    # 项目说明
└── LICENSE                      # MIT 许可证
```

`__init__.py` 负责在包导入时自动发现和加载所有内置步骤，使用 `pkgutil.walk_packages` 遍历 `steps/` 目录下的所有子模块。

## 2.7 常见安装问题与解决

### 2.7.1 GDAL 编译问题

**问题**：`pip install GDAL` 时出现编译错误

```
error: command 'gcc' failed with exit status 1
```

**解决方案**：

```bash
# Ubuntu/Debian - 安装开发库
sudo apt-get install -y libgdal-dev
export CPLUS_INCLUDE_PATH=/usr/include/gdal
export C_INCLUDE_PATH=/usr/include/gdal
pip install GDAL==$(gdal-config --version)

# 或使用 conda（推荐，跳过编译）
conda install -c conda-forge gdal
```

### 2.7.2 Fiona 安装失败

**问题**：安装 fiona 时出现 GDAL 相关错误

```
fiona/_shim.pyx:... fatal error: gdal.h: No such file or directory
```

**解决方案**：

```bash
# 确保 GDAL 开发库已安装
sudo apt-get install -y libgdal-dev

# 或使用 conda
conda install -c conda-forge fiona
```

### 2.7.3 GeoPandas 依赖冲突

**问题**：安装 GeoPandas 时出现依赖版本冲突

**解决方案**：

```bash
# 创建干净的虚拟环境
python3 -m venv fresh-env
source fresh-env/bin/activate

# 按顺序安装
pip install --upgrade pip
pip install geopipe-agent
```

### 2.7.4 rasterio 安装问题

**问题**：rasterio 需要 GDAL 库支持

**解决方案**：

```bash
# Ubuntu
sudo apt-get install -y libgdal-dev
pip install rasterio

# macOS
brew install gdal
pip install rasterio

# conda（推荐）
conda install -c conda-forge rasterio
```

### 2.7.5 Python 版本不兼容

**问题**：安装时提示 Python 版本不满足要求

```
ERROR: Package requires Python >=3.10
```

**解决方案**：

```bash
# 使用 pyenv 安装指定 Python 版本
pyenv install 3.11.5
pyenv local 3.11.5

# 或使用 conda
conda create -n geopipe python=3.11 -y
```

### 2.7.6 QGIS 环境变量问题

**问题**：已安装 QGIS 但 `qgis_process` 或 PyQGIS 不可用

**解决方案**：

```bash
# Linux - 添加 QGIS 到 PATH
export PATH="/usr/bin:$PATH"
which qgis_process

# macOS - 添加 QGIS 应用路径
export PATH="/Applications/QGIS.app/Contents/MacOS/bin:$PATH"
export PYTHONPATH="/Applications/QGIS.app/Contents/Resources/python:$PYTHONPATH"

# 写入 shell 配置文件使其永久生效
echo 'export PATH="/Applications/QGIS.app/Contents/MacOS/bin:$PATH"' >> ~/.zshrc
```

### 2.7.7 网络依赖安装失败

**问题**：networkx 或 geopy 安装失败

**解决方案**：

```bash
# 网络依赖是纯 Python 包，通常不会有编译问题
# 如果是网络问题，使用国内镜像
pip install geopipe-agent[network] -i https://pypi.tuna.tsinghua.edu.cn/simple
```
