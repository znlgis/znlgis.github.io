# 第二章：安装与环境配置

> 本章详细介绍 GeoPipeAgent 的所有安装方式、依赖管理、Docker 部署方案以及开发环境搭建，帮助你在各种环境下顺利运行 GeoPipeAgent。

## 2.1 Python 环境要求

GeoPipeAgent 要求 **Python 3.10 或更高版本**。这是因为框架大量使用了以下 Python 3.10+ 特性：

### 2.1.1 Python 版本要求

| Python 版本 | 支持状态 | 说明 |
|-------------|----------|------|
| Python 3.10 | ✅ 最低版本 | 使用 `match/case`、`ParamSpec`、`TypeAlias` |
| Python 3.11 | ✅ 推荐版本 | 性能提升 10-60%，更好的错误提示 |
| Python 3.12 | ✅ 完全兼容 | 最新稳定版，更快的启动速度 |
| Python 3.13 | ⚠️ 实验性 | 尚未完全测试 |
| Python 3.9 及以下 | ❌ 不支持 | 缺少必要语法特性 |

### 2.1.2 使用的 Python 3.10+ 特性

```python
# 1. match/case 语句（用于参数类型匹配）
match param_type:
    case "geodataframe":
        return resolve_geodataframe(value)
    case "number":
        return float(value)
    case "string":
        return str(value)
    case _:
        raise ValueError(f"Unknown type: {param_type}")

# 2. TypeAlias（用于类型别名）
from typing import TypeAlias

StepParams: TypeAlias = dict[str, Any]
StepFunction: TypeAlias = Callable[..., Any]

# 3. dataclass 增强（slots=True, kw_only=True）
from dataclasses import dataclass, field

@dataclass(slots=True, kw_only=True)
class StepDefinition:
    id: str
    use: str
    params: dict[str, Any] = field(default_factory=dict)
    when: str | None = None
    on_error: str = "fail"
    backend: str | None = None

# 4. Union 类型简写 (X | Y)
def resolve(value: str | int | float | None) -> Any:
    ...
```

### 2.1.3 检查 Python 版本

```bash
# 检查 Python 版本

# Python 3.11.5

# 如果版本不满足，使用 pyenv 安装
```

## 2.2 pip 安装方式

GeoPipeAgent 使用标准的 Python 包管理工具 pip 进行安装，支持多种安装配置。

### 2.2.1 基础安装

```bash
# 克隆仓库
git clone https://github.com/your-org/GeoPipeAgent.git
cd GeoPipeAgent

# 基础安装（仅核心依赖）
pip install -e .
```

基础安装包含运行 GeoPipeAgent 核心功能所需的最小依赖集。

### 2.2.2 可选依赖组安装

GeoPipeAgent 将依赖分为多个可选组，可以按需安装：

```bash
# 安装所有开发依赖
pip install -e ".[dev]"

# 安装高级分析依赖
pip install -e ".[analysis]"

# 安装网络分析依赖
pip install -e ".[network]"

# 安装 Web 服务依赖
pip install -e ".[web]"

# 安装所有依赖（开发 + 分析 + 网络 + Web）
pip install -e ".[dev,analysis,network,web]"
```

### 2.3.1 关键配置项说明

**构建系统**

```toml
[build-system]
requires = ["setuptools>=68.0", "wheel"]
build-backend = "setuptools.build_meta"
```

使用 setuptools 作为构建后端。setuptools 68.0+ 完全支持 PEP 621 的 `[project]` 表。

**CLI 入口点**

```toml
[project.scripts]
geopipe-agent = "geopipe_agent.cli:main"
```

这行配置意味着安装后会创建一个 `geopipe-agent` 命令，指向 `src/geopipe_agent/cli.py` 中的 `main()` 函数。

**包发现**

```toml
[tool.setuptools.packages.find]
where = ["src"]
```

告诉 setuptools 从 `src/` 目录下查找 Python 包。这是 `src-layout` 的标准配置。

## 2.4 Docker 部署方式

GeoPipeAgent 提供了完整的 Docker 部署方案，适合生产环境使用。

### 2.4.1 docker-compose.yml 完整配置

```yaml
version: "3.8"

services:
  # ─────────────────────────────────────────
  # 前端服务：Vue.js + Nginx
  # ─────────────────────────────────────────
  frontend:
    build:
      context: ./web/frontend
      dockerfile: Dockerfile
    ports:
      - "${FRONTEND_PORT:-8080}:80"
    depends_on:
      - backend
    environment:
      - API_BASE_URL=http://backend:8000
    networks:
      - geopipe-net
    restart: unless-stopped
    healthcheck:
      test: ["CMD", "curl", "-f", "http://localhost:80/"]
      interval: 30s
      timeout: 10s
      retries: 3

  # ─────────────────────────────────────────
  # 后端服务：FastAPI + GDAL
  # ─────────────────────────────────────────
  backend:
    build:
      context: .
      dockerfile: Dockerfile
      args:
        - INSTALL_EXTRAS=analysis,network,web
    ports:
      - "${BACKEND_PORT:-8000}:8000"
    depends_on:
      redis:
        condition: service_healthy
    environment:
      - REDIS_URL=redis://redis:6379/0
      - GEOPIPE_LOG_LEVEL=${GEOPIPE_LOG_LEVEL:-INFO}
      - GEOPIPE_MAX_WORKERS=${GEOPIPE_MAX_WORKERS:-4}
      - GEOPIPE_DATA_DIR=/data
      - GEOPIPE_OUTPUT_DIR=/output
      - GEOPIPE_TEMP_DIR=/workspace
      - GEOPIPE_ALLOWED_BACKENDS=${GEOPIPE_ALLOWED_BACKENDS:-native_python,gdal_cli,gdal_python}
      - GEOPIPE_MAX_PIPELINE_DURATION=${GEOPIPE_MAX_PIPELINE_DURATION:-3600}
    volumes:
      - geopipe-data:/data
      - geopipe-output:/output
      - geopipe-workspace:/workspace
    networks:
      - geopipe-net
    restart: unless-stopped
    healthcheck:
      test: ["CMD", "curl", "-f", "http://localhost:8000/health"]
      interval: 30s
      timeout: 10s
      retries: 3
    deploy:
      resources:
        limits:
          memory: 4G
          cpus: "2.0"

  # ─────────────────────────────────────────
  # Redis：消息队列和缓存
  # ─────────────────────────────────────────
  redis:
    image: redis:7-alpine
    ports:
      - "${REDIS_PORT:-6379}:6379"
    volumes:
      - redis-data:/data
    networks:
      - geopipe-net
    restart: unless-stopped
    healthcheck:
      test: ["CMD", "redis-cli", "ping"]
      interval: 10s
      timeout: 5s
      retries: 5
    command: redis-server --appendonly yes --maxmemory 256mb --maxmemory-policy allkeys-lru

  # ─────────────────────────────────────────
  # Worker：后台任务处理进程
  # ─────────────────────────────────────────
  worker:
    build:
      context: .
      dockerfile: Dockerfile
      args:
        - INSTALL_EXTRAS=analysis,network,web
    depends_on:
      redis:
        condition: service_healthy
    environment:
      - REDIS_URL=redis://redis:6379/0
      - GEOPIPE_LOG_LEVEL=${GEOPIPE_LOG_LEVEL:-INFO}
      - GEOPIPE_DATA_DIR=/data
      - GEOPIPE_OUTPUT_DIR=/output
      - GEOPIPE_TEMP_DIR=/workspace
    volumes:
      - geopipe-data:/data
      - geopipe-output:/output
      - geopipe-workspace:/workspace
    networks:
      - geopipe-net
    restart: unless-stopped
    command: python -m geopipe_agent.web.worker
    deploy:
      replicas: ${WORKER_REPLICAS:-2}
      resources:
        limits:
          memory: 4G
          cpus: "2.0"

volumes:
  geopipe-data:
    driver: local
  geopipe-output:
    driver: local
  geopipe-workspace:
    driver: local
  redis-data:
    driver: local

networks:
  geopipe-net:
    driver: bridge
```

### 2.4.2 后端 Dockerfile

```dockerfile
# ============================================
# GeoPipeAgent Backend Dockerfile
# ============================================
FROM ghcr.io/osgeo/gdal:ubuntu-full-3.7.2 AS base

# 系统依赖
RUN apt-get update && apt-get install -y --no-install-recommends \
    python3-pip \
    python3-venv \
    python3-dev \
    build-essential \
    curl \
    && rm -rf /var/lib/apt/lists/*

# 设置工作目录
WORKDIR /app

# 复制项目文件
COPY pyproject.toml README.md LICENSE ./
COPY src/ src/
COPY web/backend/ web/backend/

# 安装 Python 依赖
ARG INSTALL_EXTRAS="analysis,network,web"
RUN pip install --no-cache-dir -e ".[$INSTALL_EXTRAS]"

# 创建数据目录
RUN mkdir -p /data /output /workspace

# 非 root 用户
RUN useradd --create-home --shell /bin/bash geopipe
RUN chown -R geopipe:geopipe /app /data /output /workspace
USER geopipe

# 暴露端口
EXPOSE 8000

# 启动命令
CMD ["uvicorn", "geopipe_agent.web.backend.main:app", \
     "--host", "0.0.0.0", "--port", "8000", \
     "--workers", "4"]
```

### 2.5.2 环境变量优先级

GeoPipeAgent 按以下优先级读取配置（从高到低）：

```
1. CLI 命令行参数        (--verbose, --var key=value)
2. 环境变量             (GEOPIPE_LOG_LEVEL=DEBUG)
3. .env 文件           (项目根目录下的 .env)
4. YAML 流水线内配置    (pipeline.variables)
5. 默认值              (代码中定义)
```

## 2.8 常见问题排查

### 2.8.1 GDAL 安装问题

GDAL 是 GeoPipeAgent 最常遇到的安装难点。以下是各平台的解决方案：

**Ubuntu/Debian**

```bash
# 安装系统级 GDAL
sudo apt-get update
sudo apt-get install -y gdal-bin libgdal-dev python3-gdal

# 确认 GDAL 版本
gdal-config --version
# 3.7.2

# 安装与系统 GDAL 版本匹配的 Python 绑定
pip install GDAL==$(gdal-config --version)

# 验证
python -c "from osgeo import gdal; print(gdal.__version__)"
```

**macOS**

```bash
# 使用 Homebrew
brew install gdal

# 设置环境变量
export GDAL_CONFIG=$(brew --prefix gdal)/bin/gdal-config
export CPLUS_INCLUDE_PATH=$(brew --prefix gdal)/include
export C_INCLUDE_PATH=$(brew --prefix gdal)/include

# 安装 Python 绑定
pip install GDAL==$(gdal-config --version)
```

**Windows**

```powershell
# 方式一：使用 OSGeo4W
# 下载并安装 OSGeo4W: https://trac.osgeo.org/osgeo4w/
# 在 OSGeo4W Shell 中运行：
pip install GDAL

# 方式二：使用 conda
conda install -c conda-forge gdal

# 方式三：使用预编译 wheel
pip install GDAL --find-links https://github.com/cgohlke/geospatial-wheels/releases
```

**Docker（推荐，最简单）**

```bash
# 使用 GDAL 官方镜像
docker run -it ghcr.io/osgeo/gdal:ubuntu-full-3.7.2 python3 -c \
    "from osgeo import gdal; print(gdal.__version__)"
```

### 2.8.2 QGIS 路径配置

如果需要使用 QGIS 后端，需要正确配置 QGIS 路径：

```bash
# Linux：安装 QGIS
sudo apt-get install qgis qgis-plugin-grass

# 查找 qgis_process
which qgis_process
# /usr/bin/qgis_process

# 设置 PyQGIS 路径
export PYTHONPATH="/usr/share/qgis/python:$PYTHONPATH"
export QGIS_PREFIX_PATH="/usr"

# 验证 qgis_process
qgis_process --version
# QGIS 3.34.0

# 验证 PyQGIS
python -c "from qgis.core import QgsApplication; print('PyQGIS OK')"
```

```bash
# macOS：QGIS 通常安装在 /Applications
export QGIS_PREFIX_PATH="/Applications/QGIS.app/Contents/MacOS"
export PYTHONPATH="/Applications/QGIS.app/Contents/Resources/python:$PYTHONPATH"

# Windows：通常在 C:\Program Files\QGIS 3.xx
set QGIS_PREFIX_PATH=C:\Program Files\QGIS 3.34
set PYTHONPATH=C:\Program Files\QGIS 3.34\apps\qgis\python;%PYTHONPATH%
```

### 2.8.3 GeoPandas 依赖冲突

GeoPandas 依赖链较复杂，可能出现版本冲突：

```bash
# 检查依赖树
pip install pipdeptree
pipdeptree --packages geopandas

# 如果遇到冲突，尝试使用 conda
conda install -c conda-forge geopandas

# 或手动指定兼容版本
pip install geopandas==0.14.1 shapely==2.0.2 fiona==1.9.5 pyproj==3.6.1
```

### 2.8.4 Rasterio 安装失败

```bash
# Linux
sudo apt-get install -y libgdal-dev
pip install rasterio

# macOS
brew install gdal
pip install rasterio

# 如果仍然失败，使用 conda
conda install -c conda-forge rasterio

# 验证
python -c "import rasterio; print(rasterio.__version__)"
```

### 2.8.5 权限问题

```bash
# 如果遇到 "Permission denied" 错误
# 确保在虚拟环境中操作
which python  # 应该指向 .venv/bin/python

# 如果是 Docker 容器中的权限问题
# 确保数据卷的权限正确
docker-compose exec backend ls -la /data
docker-compose exec backend chown -R geopipe:geopipe /data
```

### 2.8.6 PROJ 数据库问题

```bash
# 如果遇到 "PROJ: proj_create_from_database" 错误
# 设置 PROJ 数据目录
export PROJ_LIB=$(python -c "import pyproj; print(pyproj.datadir.get_data_dir())")

# 或手动下载 PROJ 数据
pip install pyproj[grids]

# 验证
python -c "from pyproj import CRS; print(CRS('EPSG:4326').name)"
# WGS 84
```

### 2.8.7 速查诊断表

| 症状 | 可能原因 | 解决方案 |
|------|----------|----------|
| `ModuleNotFoundError: No module named 'geopipe_agent'` | 未安装或未在虚拟环境中 | `pip install -e .` |
| `geopipe-agent: command not found` | CLI 入口点未安装 | `pip install -e .` 并确保 PATH 包含 `.venv/bin` |
| `ImportError: libgdal.so.XX` | GDAL 共享库缺失 | 安装系统级 GDAL |
| `GDAL version mismatch` | Python GDAL 版本与系统不一致 | `pip install GDAL==$(gdal-config --version)` |
| `fiona.errors.DriverError` | 文件驱动未安装 | 更新 GDAL 或安装对应驱动 |
| `pyproj.exceptions.CRSError` | PROJ 数据库缺失 | 设置 `PROJ_LIB` 或 `pip install pyproj[grids]` |
| `qgis_process: command not found` | QGIS 未安装 | 安装 QGIS 或跳过 QGIS 后端 |
| `redis.exceptions.ConnectionError` | Redis 未运行 | `docker-compose up -d redis` 或 `redis-server` |
| `MemoryError` | 数据量超出内存限制 | 增加内存或使用分块处理 |
| `OSError: [Errno 28] No space left on device` | 磁盘空间不足 | 清理临时文件或扩展存储 |
