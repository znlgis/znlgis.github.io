# 第五章：变量系统与引用机制

## 5.1 概述

GeoPipeAgent 的变量系统和引用机制是流水线中步骤间数据传递的核心。本章将从源码层面深入分析变量替换和步骤引用的实现原理，帮助用户理解其工作方式并正确使用。

变量系统由 `engine/context.py` 中的 `PipelineContext` 类实现，包含两大功能：

1. **变量替换**：`${var_name}` 语法，从 `variables` 定义中获取值
2. **步骤引用**：`$step_id` 和 `$step_id.attr` 语法，引用前一步骤的输出

## 5.2 PipelineContext 上下文管理器

`PipelineContext` 是变量和引用解析的核心类：

```python
class PipelineContext:
    def __init__(self, variables: dict | None = None) -> None:
        self.variables: dict = dict(variables or {})
        self._step_outputs: dict[str, StepResult] = {}

    def set_output(self, step_id: str, result: StepResult) -> None:
        """存储步骤结果"""
        self._step_outputs[step_id] = result

    def get_output(self, step_id: str) -> StepResult:
        """获取步骤结果"""
        ...

    def resolve(self, value: Any) -> Any:
        """解析值中的变量引用和步骤引用"""
        ...

    def resolve_params(self, params: dict) -> dict:
        """解析参数字典中的所有引用"""
        ...
```

### 5.2.1 内部状态

- `variables`：存储流水线定义的变量，加上命令行 `--var` 覆盖的变量
- `_step_outputs`：存储每个已执行步骤的 `StepResult` 对象

### 5.2.2 解析入口

`resolve()` 方法是值解析的入口，它根据值的类型和格式分派到不同的解析函数：

```python
def resolve(self, value: Any) -> Any:
    if not isinstance(value, str):
        return value                          # 非字符串直接返回

    if value.startswith("$") and not value.startswith("${"):
        return self._resolve_step_ref(value)  # $step_id → 步骤引用

    if "${" in value:
        return self._substitute_variables(value)  # ${var} → 变量替换

    return value                              # 普通字符串直接返回
```

## 5.3 变量替换详解

### 5.3.1 完整替换

当参数值完全是一个 `${var}` 引用时，返回变量的原始值（保持类型）：

```python
# 变量定义
variables:
  buffer_dist: 500        # int 类型
  enable_qc: true         # bool 类型
  input_path: "data.shp"  # str 类型

# 参数引用
params:
  distance: "${buffer_dist}"    # → 500 (int)
  auto_fix: "${enable_qc}"     # → True (bool)
  path: "${input_path}"        # → "data.shp" (str)
```

源码实现使用正则匹配整个字符串：

```python
match = re.fullmatch(r"\$\{(\w+)\}", text)
if match:
    var_name = match.group(1)
    return self.variables[var_name]  # 返回原始类型
```

### 5.3.2 嵌入替换

当 `${var}` 嵌入在字符串中时，执行字符串插值（结果为字符串）：

```yaml
variables:
  output_dir: "output"
  name: "roads"

params:
  path: "${output_dir}/${name}_buffer.geojson"
  # → "output/roads_buffer.geojson" (str)
```

源码使用 `re.sub` 进行替换：

```python
def _replace(m: re.Match) -> str:
    var_name = m.group(1)
    return str(self.variables[var_name])  # 转为字符串

return re.sub(r"\$\{(\w+)\}", _replace, text)
```

### 5.3.3 类型保持规则总结

| 场景 | 示例 | 结果类型 |
|------|------|----------|
| 完整引用 | `"${buffer_dist}"` 其中 `buffer_dist = 500` | `int` (500) |
| 完整引用 | `"${enable}"` 其中 `enable = true` | `bool` (True) |
| 嵌入引用 | `"${dir}/file.shp"` | `str` |
| 多个引用 | `"${dir}/${name}.shp"` | `str` |

### 5.3.4 变量未定义错误

引用不存在的变量会抛出 `VariableResolutionError`：

```python
raise VariableResolutionError(
    f"Variable '${{{var_name}}}' is not defined. "
    f"Available variables: {list(self.variables.keys())}"
)
```

错误信息包含所有可用变量列表，便于调试。

## 5.4 步骤引用详解

### 5.4.1 简写引用

`$step_id` 是 `$step_id.output` 的简写形式：

```yaml
- id: buffer
  use: vector.buffer
  params:
    input: "$load"    # 等价于 "$load.output"
    distance: 500
```

### 5.4.2 属性引用

`$step_id.attr` 引用步骤结果的具体属性：

```yaml
- id: save-issues
  use: io.write_vector
  params:
    input: "$check.issues_gdf"     # 引用 issues_gdf 属性
  when: "$check.issues_count > 0"  # 引用 issues_count 属性
```

### 5.4.3 属性解析机制

`StepResult` 类实现了 `__getattr__` 方法，允许通过点号访问 `stats` 和 `metadata` 中的键：

```python
@dataclass
class StepResult:
    output: Any = None
    stats: dict = field(default_factory=dict)
    metadata: dict = field(default_factory=dict)
    issues: list[QcIssue] = field(default_factory=list)

    def __getattr__(self, name: str) -> Any:
        # 依次在 stats 和 metadata 中查找
        stats = self.__dict__.get("stats", {})
        metadata = self.__dict__.get("metadata", {})
        if name in stats:
            return stats[name]
        if name in metadata:
            return metadata[name]
        raise AttributeError(...)
```

例如，如果一个步骤返回的 `StepResult` 的 `stats` 为 `{"feature_count": 42, "crs": "EPSG:4326"}`，则：

- `$step.output` → 主输出数据
- `$step.feature_count` → 42
- `$step.crs` → "EPSG:4326"

### 5.4.4 引用解析源码

```python
def _resolve_step_ref(self, ref: str) -> Any:
    ref_body = ref[1:]  # 去掉前导 $
    if "." not in ref_body:
        step_id, attr = ref_body, "output"  # 简写形式
    else:
        step_id, attr = ref_body.split(".", 1)

    result = self._step_outputs[step_id]
    return getattr(result, attr)
```

## 5.5 递归解析

### 5.5.1 嵌套字典和列表

`resolve_params()` 方法会递归解析参数中的嵌套结构：

```python
def _resolve_value(self, value: Any) -> Any:
    if isinstance(value, dict):
        return {k: self._resolve_value(v) for k, v in value.items()}
    if isinstance(value, list):
        return [self._resolve_value(v) for v in value]
    return self.resolve(value)
```

这意味着变量引用和步骤引用可以出现在任何层级的参数中：

```yaml
params:
  rules: ["no_overlaps", "no_gaps"]           # 列表中的字面量
  config:
    input: "$load"                             # 嵌套字典中的步骤引用
    threshold: "${tolerance}"                   # 嵌套字典中的变量引用
  paths:
    - "${dir}/file1.shp"                       # 列表中的变量引用
    - "${dir}/file2.shp"
```

## 5.6 校验机制

### 5.6.1 编译时校验

流水线校验器（`engine/validator.py`）在执行前检查引用的有效性：

**步骤引用校验**：

```python
# 检查引用的步骤是否存在且在当前步骤之前
if ref_step_id not in available_outputs:
    raise PipelineValidationError(
        f"Step '{step_id}', param '{key}': references step '{ref_step_id}' "
        f"which has not been defined before this step."
    )
```

**变量引用校验**：

```python
# 检查变量是否在 pipeline.variables 中定义
for match in re.finditer(r"\$\{(\w+)\}", value):
    var_name = match.group(1)
    if var_name not in variables:
        raise PipelineValidationError(
            f"Variable '${{{var_name}}}' is not defined in pipeline.variables."
        )
```

### 5.6.2 校验规则

| 规则 | 检查内容 | 错误类型 |
|------|----------|----------|
| 前向引用检查 | 步骤引用必须指向之前定义的步骤 | `PipelineValidationError` |
| 变量存在性检查 | `${var}` 引用的变量必须在 `variables` 中定义 | `PipelineValidationError` |
| 步骤 ID 格式 | 必须匹配 `[a-z0-9_-]` | `PipelineValidationError` |
| 步骤 ID 唯一性 | 不允许重复的步骤 ID | `PipelineValidationError` |
| 步骤类型存在性 | `use` 字段指定的步骤必须已注册 | `PipelineValidationError` |
| 输出引用检查 | `outputs` 中引用的步骤必须存在 | `PipelineValidationError` |

## 5.7 命令行变量覆盖

### 5.7.1 使用方法

通过 `--var key=value` 选项覆盖流水线中定义的变量：

```bash
geopipe-agent run pipeline.yaml \
  --var input_path=new_data.shp \
  --var buffer_dist=1000 \
  --var output_dir=results
```

### 5.7.2 实现原理

CLI 的 `run` 命令在解析完 YAML 后，将 `--var` 参数合并到 `pipeline.variables` 中：

```python
for v in var:
    key, _, value = v.partition("=")
    pipeline.variables[key.strip()] = value.strip()
```

注意：通过命令行传入的值始终为字符串类型。框架的类型强制转换机制会在执行时将字符串类型的数字和布尔值自动转换为对应类型。

## 5.8 类型强制转换

执行器在运行步骤前会根据步骤的参数类型定义自动转换参数值：

```python
# 数字类型转换
if expected == "number" and isinstance(value, str):
    resolved_params[name] = float(value) if "." in value else int(value)

# 布尔类型转换
elif expected == "boolean" and isinstance(value, str):
    resolved_params[name] = value.lower() in ("true", "1", "yes")
```

## 5.9 StepContext 便捷访问

`StepContext` 封装了解析后的参数，提供便捷的访问方法：

```python
class StepContext:
    def __init__(self, params, backend=None, pipeline_context=None):
        self._params = params
        self.backend = backend
        self.pipeline_context = pipeline_context

    def param(self, name: str, default: Any = None) -> Any:
        """获取参数值，支持默认值"""
        return self._params.get(name, default)

    def input(self, name: str = "input") -> Any:
        """快捷获取 input 参数"""
        return self._params.get(name)

    @property
    def params(self) -> dict:
        return self._params
```

步骤函数中的典型用法：

```python
def my_step(ctx: StepContext) -> StepResult:
    gdf = ctx.param("input")           # 获取输入数据
    distance = ctx.param("distance")   # 获取距离参数
    cap = ctx.param("cap_style", "round")  # 获取可选参数（带默认值）
    # ... 处理逻辑
```

## 5.10 本章小结

本章深入分析了 GeoPipeAgent 的变量系统和引用机制。变量替换支持完整引用（保持类型）和嵌入引用（字符串插值）两种模式。步骤引用支持简写形式（`$step_id`）和属性引用形式（`$step_id.attr`）。所有引用在流水线校验阶段会被检查有效性，确保不存在前向引用和未定义变量的问题。`PipelineContext` 是变量和引用解析的核心，递归解析嵌套的参数结构。
