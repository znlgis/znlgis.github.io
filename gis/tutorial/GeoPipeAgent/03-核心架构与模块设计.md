# 第三章：核心架构与模块设计

## 3.1 整体架构

GeoPipeAgent 采用分层架构设计，各层之间职责清晰、耦合度低。整体架构可以分为以下五层：

```
┌─────────────────────────────────────────────────────┐
│                   CLI 层 (cli.py)                     │
│             Click 命令行接口，用户交互入口              │
├─────────────────────────────────────────────────────┤
│                Engine 层 (engine/)                     │
│     Parser → Validator → Executor → Reporter          │
│           流水线解析、校验、执行、报告                   │
├─────────────────────────────────────────────────────┤
│                 Steps 层 (steps/)                      │
│   io/ │ vector/ │ raster/ │ analysis/ │ network/ │ qc/ │
│        33 个内置步骤，通过 @step 装饰器注册             │
├─────────────────────────────────────────────────────┤
│               Backends 层 (backends/)                  │
│   NativePython │ GDAL CLI │ GDAL Python │ QGIS │ PyQGIS│
│              五种 GIS 后端的统一抽象                    │
├─────────────────────────────────────────────────────┤
│               Models 层 (models/)                      │
│     PipelineDefinition │ StepResult │ QcIssue          │
│              数据模型定义                               │
├─────────────────────────────────────────────────────┤
│            Utils & SkillGen 层                         │
│     logging │ safe_eval │ skillgen/generator            │
│          工具函数和 AI Skill 生成器                     │
└─────────────────────────────────────────────────────┘
```

## 3.2 模块详解

### 3.2.1 包入口（`__init__.py`）

`src/geopipe_agent/__init__.py` 是整个包的入口文件，它负责：

1. **导出公共 API**：`step`、`StepInfo`、`StepContext`、`StepResult`、`QcIssue`
2. **自动加载内置步骤**：调用 `load_builtin_steps()` 触发所有步骤模块的导入和注册

```python
"""GeoPipeAgent — AI-Native GIS Analysis Pipeline Framework."""

from geopipe_agent.steps.registry import step, StepInfo
from geopipe_agent.engine.context import StepContext
from geopipe_agent.models.result import StepResult
from geopipe_agent.models.qc import QcIssue

__version__ = "0.1.0"

# Auto-load all built-in steps so callers never need to do it manually.
from geopipe_agent.steps import load_builtin_steps as _load_builtin_steps
_load_builtin_steps()
```

这意味着只要 `import geopipe_agent`，所有 33 个内置步骤就会自动注册到步骤注册表中。

### 3.2.2 CLI 模块（`cli.py`）

CLI 模块基于 Click 框架实现，提供了 11 个命令：

| 命令 | 功能 |
|------|------|
| `run` | 执行 YAML 流水线 |
| `validate` | 校验 YAML 流水线（不执行） |
| `list-steps` | 列出所有可用步骤 |
| `describe` | 查看步骤详情 |
| `info` | 查看 GIS 数据文件摘要 |
| `backends` | 列出可用后端 |
| `generate-skill-doc` | 生成步骤参考文档 |
| `generate-skill` | 生成 AI Skill 文件集 |

CLI 模块的设计遵循 Click 的最佳实践：使用 `@click.group()` 定义命令组，使用 `@main.command()` 定义子命令，所有输出都采用 JSON 格式以便机器解析。

### 3.2.3 Engine 模块（`engine/`）

引擎模块是 GeoPipeAgent 的核心，包含五个组件：

| 文件 | 类/函数 | 职责 |
|------|---------|------|
| `parser.py` | `parse_yaml()` | 将 YAML 文件解析为 `PipelineDefinition` |
| `validator.py` | `validate_pipeline()` | 校验流水线的合法性（ID 格式、引用有效性等） |
| `executor.py` | `execute_pipeline()` | 按顺序执行流水线中的每个步骤 |
| `context.py` | `PipelineContext`、`StepContext` | 管理变量、步骤输出和引用解析 |
| `reporter.py` | `build_report()` | 生成 JSON 执行报告 |

**执行流程**：

```
YAML 文件 → parse_yaml() → PipelineDefinition
    → validate_pipeline() → warnings
    → execute_pipeline()
        → 对每个步骤：
            1. 评估 when 条件
            2. 解析参数中的变量和引用
            3. 查找步骤注册信息
            4. 选择后端
            5. 创建 StepContext
            6. 调用步骤函数
            7. 存储结果到上下文
        → build_report() → JSON 报告
```

### 3.2.4 Models 模块（`models/`）

数据模型模块定义了三个核心数据类：

| 模型 | 文件 | 说明 |
|------|------|------|
| `PipelineDefinition` | `pipeline.py` | 流水线定义（名称、步骤列表、变量、输出） |
| `StepDefinition` | `pipeline.py` | 单个步骤定义（ID、类型、参数、条件、错误策略） |
| `StepResult` | `result.py` | 步骤执行结果（输出数据、统计信息、元数据、QC 问题） |
| `QcIssue` | `qc.py` | 质检问题记录（规则 ID、严重级别、要素索引、描述） |

所有模型都使用 Python 的 `@dataclass` 装饰器，保持了简洁和清晰。

### 3.2.5 Steps 模块（`steps/`）

步骤模块采用"自动发现 + 注册表"模式：

```
steps/
├── __init__.py          # 自动发现和加载逻辑
├── registry.py          # 步骤注册表和 @step 装饰器
├── io/                  # IO 步骤（4 个）
│   ├── read_vector.py
│   ├── write_vector.py
│   ├── read_raster.py
│   └── write_raster.py
├── vector/              # 矢量步骤（7 个）
│   ├── _delegate.py     # 后端委托辅助函数
│   ├── buffer.py
│   ├── clip.py
│   ├── reproject.py
│   ├── dissolve.py
│   ├── simplify.py
│   ├── query.py
│   └── overlay.py
├── raster/              # 栅格步骤（5 个）
├── analysis/            # 空间分析步骤（4 个）
├── network/             # 网络分析步骤（3 个）
└── qc/                  # 质检步骤（10 个）
    ├── _helpers.py      # QC 辅助函数
    └── ...
```

**自动发现机制**：`load_builtin_steps()` 函数使用 `pkgutil.walk_packages` 遍历 `steps/` 目录下的所有 Python 模块，导入它们触发 `@step` 装饰器的执行，从而自动注册步骤。

### 3.2.6 Backends 模块（`backends/`）

后端模块采用策略模式，定义了统一的 `GeoBackend` 抽象基类：

```
backends/
├── __init__.py                  # BackendManager 管理器
├── base.py                      # GeoBackend 抽象基类 + 工具函数
├── native_python_backend.py     # GeoPandas + Shapely
├── gdal_cli.py                  # ogr2ogr 命令行
├── gdal_python_backend.py       # GDAL/OGR Python 绑定
├── qgis_process.py              # qgis_process CLI
└── pyqgis_backend.py            # PyQGIS Python API
```

`BackendManager` 负责检测可用后端并提供后端选择逻辑。

### 3.2.7 SkillGen 模块（`skillgen/`）

Skill 生成器模块负责从已注册的步骤信息生成 AI 可消费的文档：

```
skillgen/
├── __init__.py
└── generator.py        # 生成 SKILL.md、steps-reference.md、pipeline-schema.md
```

### 3.2.8 Utils 模块（`utils/`）

工具模块提供两个核心工具：

| 文件 | 功能 |
|------|------|
| `logging.py` | 结构化日志系统，支持文本和 JSON 两种格式 |
| `safe_eval.py` | 安全表达式求值，基于 AST 白名单验证 |

## 3.3 核心设计模式

### 3.3.1 装饰器注册模式

GeoPipeAgent 使用 `@step` 装饰器来注册步骤，这是一种经典的注册模式：

```python
@step(
    id="vector.buffer",
    name="矢量缓冲区分析",
    description="对输入的矢量数据生成指定距离的缓冲区",
    category="vector",
    params={...},
    outputs={...},
    backends=["native_python", "qgis_process"],
)
def vector_buffer(ctx: StepContext) -> StepResult:
    ...
```

装饰器在模块导入时执行，自动将步骤信息注册到全局注册表 `_steps` 字典中。

### 3.3.2 策略模式（Backends）

后端系统使用策略模式：所有后端都继承自 `GeoBackend` 抽象基类，提供统一的接口（`buffer`、`clip`、`reproject` 等）。`BackendManager` 根据配置或可用性选择具体的后端实现。

### 3.3.3 上下文传递模式

`PipelineContext` 作为数据流的中枢：
- 存储变量定义
- 存储每个步骤的输出结果
- 提供变量替换和步骤引用的解析

`StepContext` 是传递给每个步骤函数的上下文对象，封装了解析后的参数和后端引用。

### 3.3.4 数据类模型

所有数据模型都使用 Python 的 `@dataclass`，保持了类型安全和简洁性：

```python
@dataclass
class StepDefinition:
    id: str
    use: str
    params: dict = field(default_factory=dict)
    when: str | None = None
    on_error: str = "fail"
    backend: str | None = None
```

### 3.3.5 自动发现模式

步骤的自动发现基于 `pkgutil.walk_packages`，避免了手动维护步骤列表的麻烦。开发者只需将步骤文件放入对应的子目录，框架会自动发现并注册。

## 3.4 数据流分析

### 3.4.1 流水线执行数据流

```
YAML 文件
  │
  ▼
parse_yaml()  ──→  PipelineDefinition
  │                    ├── name, description, crs
  │                    ├── variables: dict
  │                    ├── steps: list[StepDefinition]
  │                    └── outputs: dict
  ▼
validate_pipeline()  ──→  warnings: list[str]
  │
  ▼
execute_pipeline()
  │
  ├── 创建 PipelineContext(variables)
  ├── 创建 BackendManager()
  │
  ├── 对每个 StepDefinition:
  │     ├── 评估 when 条件
  │     ├── context.resolve_params(params)
  │     ├── registry.get(step.use) → StepInfo
  │     ├── backend_manager.get(step.backend)
  │     ├── StepContext(resolved_params, backend)
  │     ├── step_info.func(ctx) → StepResult
  │     └── context.set_output(step.id, result)
  │
  └── build_report() → JSON dict
```

### 3.4.2 步骤间数据传递

步骤之间的数据通过 `PipelineContext` 传递：

1. 步骤 A 执行完毕，返回 `StepResult`
2. `PipelineContext.set_output("step-a", result)` 存储结果
3. 步骤 B 的参数中使用 `$step-a` 引用步骤 A 的输出
4. `PipelineContext.resolve()` 解析引用，获取步骤 A 的结果数据

## 3.5 模块间依赖关系

```
cli.py
  ├── engine/parser.py
  ├── engine/validator.py
  ├── engine/executor.py
  │     ├── engine/context.py
  │     ├── engine/reporter.py
  │     ├── backends/__init__.py (BackendManager)
  │     ├── steps/registry.py
  │     └── utils/safe_eval.py
  ├── steps/registry.py
  ├── skillgen/generator.py
  └── utils/logging.py

models/
  ├── pipeline.py (PipelineDefinition, StepDefinition)  ← engine/parser.py
  ├── result.py (StepResult)                            ← steps/* , engine/executor.py
  └── qc.py (QcIssue)                                  ← steps/qc/*

errors.py  ← 被所有模块引用
```

## 3.6 扩展点

GeoPipeAgent 提供了以下扩展点：

| 扩展点 | 方式 | 说明 |
|--------|------|------|
| 自定义步骤 | `@step` 装饰器 | 在 `steps/` 子目录中添加新文件即可 |
| 自定义后端 | 继承 `GeoBackend` | 实现抽象方法并注册到 `_BACKEND_CLASSES` |
| 自定义错误 | 继承 `GeopipeAgentError` | 添加项目特定的错误类型 |
| 自定义报告 | 修改 `reporter.py` | 自定义报告格式和内容 |

## 3.7 本章小结

本章详细分析了 GeoPipeAgent 的核心架构和模块设计。框架采用分层架构，CLI 层提供用户交互，Engine 层负责流水线的解析、校验和执行，Steps 层包含 33 个内置分析步骤，Backends 层提供 5 种 GIS 后端的统一抽象，Models 层定义了核心数据模型。框架使用了装饰器注册、策略模式、上下文传递和自动发现等多种设计模式，保证了良好的扩展性和可维护性。
