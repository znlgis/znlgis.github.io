## 3.3 第一个流水线：数据读取与信息查看

让我们从最简单的流水线开始——读取数据并查看基本信息。

### 创建流水线文件

```yaml
# pipelines/01-read-data.yaml
pipeline:
  name: "第一步：读取道路数据"
  description: "读取 GeoJSON 道路数据，查看基本信息"
  steps:
    - id: load-roads
      use: io.read_vector
      params:
        path: "data/roads.geojson"
```

## 3.4 第二个流水线：缓冲区分析

现在添加缓冲区分析步骤，这是 GIS 中最基本的空间操作。

**注意**：缓冲区分析需要投影坐标系（单位为米），WGS84（EPSG:4326）是地理坐标系（单位为度），因此需要先进行投影转换。

```yaml
# pipelines/02-buffer-analysis.yaml
pipeline:
  name: "道路缓冲区分析"
  description: "对道路数据做 100 米缓冲区分析"
  crs: "EPSG:4326"

  variables:
    input_path: "data/roads.geojson"
    buffer_dist: 100
    output_path: "output/road_buffer_100m.geojson"

  steps:
    # 步骤1：读取数据
    - id: load-roads
      use: io.read_vector
      params:
        path: "${input_path}"

    # 步骤2：投影转换（WGS84 → Web 墨卡托，单位从度变为米）
    - id: reproject
      use: vector.reproject
      params:
        input: "$load-roads"
        target_crs: "EPSG:3857"

    # 步骤3：缓冲区分析
    - id: buffer
      use: vector.buffer
      params:
        input: "$reproject"
        distance: "${buffer_dist}"
        cap_style: "round"

    # 步骤4：保存结果（转回 WGS84）
    - id: reproject-back
      use: vector.reproject
      params:
        input: "$buffer"
        target_crs: "EPSG:4326"

    - id: save-result
      use: io.write_vector
      params:
        input: "$reproject-back"
        path: "${output_path}"
        format: "GeoJSON"

  outputs:
    buffer_result: "$save-result"
    buffer_stats: "$buffer.stats"
```

```bash
geopipe-agent run pipelines/02-buffer-analysis.yaml
```

## 3.5 第三个流水线：属性查询与过滤

学习如何使用 `vector.query` 步骤按属性条件过滤数据。

```yaml
# pipelines/03-query-filter.yaml
pipeline:
  name: "主干道过滤分析"
  description: "筛选主干道，进行缓冲区分析"

  variables:
    input_path: "data/roads.geojson"

  steps:
    - id: load-roads
      use: io.read_vector
      params:
        path: "${input_path}"

    # 只保留主干道
    - id: filter-main-roads
      use: vector.query
      params:
        input: "$load-roads"
        expression: "road_type == '主干道'"

    # 投影转换
    - id: reproject
      use: vector.reproject
      params:
        input: "$filter-main-roads"
        target_crs: "EPSG:3857"

    # 主干道缓冲区 200 米
    - id: buffer-main
      use: vector.buffer
      params:
        input: "$reproject"
        distance: 200
        cap_style: "round"

    - id: save-result
      use: io.write_vector
      params:
        input: "$buffer-main"
        path: "output/main_road_buffer.geojson"
        format: "GeoJSON"

  outputs:
    filtered_count: "$filter-main-roads.stats"
    result: "$save-result"
```

```bash
geopipe-agent run pipelines/03-query-filter.yaml
```

## 3.6 第四个流水线：数据质检

在处理真实数据之前，先做数据质检是好习惯。

```yaml
# pipelines/04-quality-check.yaml
pipeline:
  name: "道路数据质检"
  description: "对道路数据进行几何有效性和属性完整性检查"

  variables:
    input_path: "data/roads.geojson"

  steps:
    - id: load-roads
      use: io.read_vector
      params:
        path: "${input_path}"

    # 检查几何有效性
    - id: check-geometry
      use: qc.geometry_validity
      params:
        input: "$load-roads"

    # 检查 CRS
    - id: check-crs
      use: qc.crs_check
      params:
        input: "$check-geometry"
        expected_crs: "EPSG:4326"

    # 检查属性完整性
    - id: check-attributes
      use: qc.attribute_completeness
      params:
        input: "$check-crs"
        required_fields:
          - "road_id"
          - "name"
          - "road_type"

    # 检查数值范围（速度限制 20-120）
    - id: check-speed-range
      use: qc.value_range
      params:
        input: "$check-attributes"
        field: "speed_limit"
        min_value: 20
        max_value: 120

  outputs:
    qc_report: "$check-speed-range.issues"
```

```bash
geopipe-agent run pipelines/04-quality-check.yaml
```

## 3.7 使用 `--var` 参数覆盖变量

CLI 支持在运行时覆盖 YAML 中定义的变量，无需修改文件：

```bash
# 覆盖输入路径和缓冲区距离
geopipe-agent run pipelines/02-buffer-analysis.yaml \
  --var input_path=data/highways.geojson \
  --var buffer_dist=500 \
  --var output_path=output/highway_buffer_500m.geojson
```

这个功能非常适合：
- **批量处理**：同一流水线处理多个数据集
- **参数调试**：快速测试不同参数值
- **CI/CD 集成**：通过环境变量动态传入参数

## 3.9 理解执行报告结构

每次运行流水线，GeoPipeAgent 都会生成一个 JSON 格式的执行报告。理解报告结构对于调试和监控非常重要。

```json
{
  "pipeline": "流水线名称",          // 流水线名称
  "status": "success",              // 整体状态：success / failed / partial
  "duration": 0.312,                // 总执行时间（秒）
  "started_at": "2024-01-15T10:30:00.123Z",  // 开始时间
  "finished_at": "2024-01-15T10:30:00.435Z", // 结束时间

  "steps": [                        // 每个步骤的执行结果
    {
      "id": "步骤ID",
      "use": "步骤类型",
      "status": "success",          // success / failed / skipped
      "duration": 0.032,
      "stats": {                    // 步骤统计信息
        "feature_count": 3,
        "crs": "EPSG:4326"
      },
      "issues": [],                 // QC 问题列表（仅 QC 步骤）
      "error": null                 // 错误信息（失败时）
    }
  ],

  "outputs": {                      // 流水线声明的输出
    "output_key": "output_value"
  },

  "variables": {                    // 使用的变量值
    "input_path": "data/roads.geojson",
    "buffer_dist": 100
  }
}
```

## 3.11 本章小结

本章通过四个递进的实际案例，演示了 GeoPipeAgent 的基本使用：

1. **数据读取**：`io.read_vector` 读取 GeoJSON
2. **空间分析**：缓冲区分析需要先投影转换
3. **属性查询**：`vector.query` 按条件过滤数据
4. **数据质检**：QC 步骤"检查并透传"模式
5. **变量覆盖**：`--var` 参数动态修改流水线变量

**关键规则回顾**：
- YAML 必须有 `pipeline:` 顶层键
- 步骤引用用 `$step-id`（等价于 `$step-id.output`）
- 变量用 `${var_name}` 语法
- 缓冲区分析需要投影坐标系（米为单位）
