# 第十四章：多后端系统详解

## 14.1 概述

GeoPipeAgent 的**多后端系统**是其核心架构特性之一。通过在步骤定义中指定 `backend` 字段，同一个流水线可以混合使用不同的 GIS 工具链执行，无需改变流水线的整体结构。

GeoPipeAgent 支持 **7 种后端**：

| 后端名称 | 技术基础 | 默认 | 说明 |
|----------|----------|------|------|
| `native_python` | GeoPandas + Shapely | **是** | 纯 Python，无需外部工具 |
| `gdal_cli` | ogr2ogr 命令行 | 否 | 需要 GDAL 命令行工具 |
| `gdal_python` | GDAL/OGR Python | 否 | 需要 GDAL Python 绑定 |
| `qgis_process` | QGIS Processing CLI | 否 | 需要 QGIS 安装 |
| `pyqgis` | PyQGIS Python API | 否 | 需要 QGIS 安装 |
| `generic_cli` | 任意命令行工具 | 否 | 可调用任何 CLI 工具 |
| `curl_api` | HTTP 请求 | 否 | 调用 Web API 服务 |

---

## 14.2 后端使用方式

### 14.2.1 全局默认后端

不指定 `backend` 时，所有步骤使用 `native_python`：

```yaml
pipeline:
  name: "使用默认后端"
  steps:
    - id: load
      use: io.read_vector
      # backend: native_python  ← 隐式默认
      params:
        path: "data/roads.geojson"
```

### 14.2.2 步骤级别指定后端

每个步骤可以单独指定后端：

```yaml
pipeline:
  name: "混合后端流水线"
  steps:
    # 使用默认 native_python 读取
    - id: load
      use: io.read_vector
      params:
        path: "data/roads.geojson"

    # 使用 GDAL CLI 做格式转换
    - id: convert-to-gpkg
      use: io.write_vector
      backend: gdal_cli
      params:
        input: "$load"
        path: "output/roads.gpkg"
        format: "GPKG"

    # 使用 QGIS Processing 做缓冲区（QGIS 算法）
    - id: buffer
      use: vector.buffer
      backend: qgis_process
      params:
        input: "$load"
        distance: 500

    # 使用默认后端保存
    - id: save
      use: io.write_vector
      params:
        input: "$buffer"
        path: "output/result.geojson"
        format: "GeoJSON"
```

## 14.3 `native_python` 后端（默认）

### 14.3.1 技术栈

- **GeoPandas**：矢量数据处理（基于 Pandas）
- **Shapely**：几何操作（缓冲、裁剪、叠加等）
- **rasterio**：栅格数据读写和处理
- **PyProj**：坐标投影

### 14.3.2 适用场景

- **一般 GIS 数据处理**：日常矢量/栅格操作
- **纯 Python 环境**：无需安装额外 GIS 工具
- **数据分析管道**：与 Pandas、NumPy 生态无缝集成
- **教学和原型开发**：最简单的环境要求

### 14.3.3 优缺点

| 优点 | 缺点 |
|------|------|
| 无需额外安装 | 内存受限（大文件处理性能差） |
| 代码可调试 | 某些高级 GIS 算法不支持 |
| 跨平台 | 不支持部分专业 GIS 格式 |

---

## 14.4 `gdal_cli` 后端

### 14.4.1 技术基础

通过调用 `ogr2ogr`、`gdal_translate` 等 GDAL 命令行工具执行操作。

### 14.4.2 安装要求

```bash
# Ubuntu/Debian
sudo apt-get install gdal-bin

# macOS
brew install gdal

# 验证
ogr2ogr --version
# GDAL 3.6.2, released 2023/01/02
```

### 14.4.3 适用场景

```yaml
pipeline:
  name: "GDAL CLI 后端示例"
  steps:
    # 大文件格式转换（ogr2ogr 内存效率优于 GeoPandas）
    - id: convert-shapefile-to-gpkg
      use: io.write_vector
      backend: gdal_cli
      params:
        input: "$load-large-shp"
        path: "output/large_dataset.gpkg"
        format: "GPKG"

    # 使用 GDAL 特有的格式支持（如 MDB、XLSX 等）
    - id: read-esri-fgdb
      use: io.read_vector
      backend: gdal_cli
      params:
        path: "data/enterprise_data.gdb"
        layer: "roads"

    # 大型栅格重采样（GDAL 内存管理更好）
    - id: resample-large-dem
      use: raster.reproject
      backend: gdal_cli
      params:
        input: "$load-dem"
        target_crs: "EPSG:3857"
```

### 14.4.4 优缺点

| 优点 | 缺点 |
|------|------|
| 支持更多格式（200+） | 需要安装 GDAL |
| 大文件处理效率高 | 命令行调用有开销 |
| 成熟稳定 | 错误信息不如 Python 友好 |
| 支持 Esri 格式（需 GDAL 插件） | 不支持所有步骤 |

---

## 14.5 `gdal_python` 后端

### 14.5.1 技术基础

使用 GDAL/OGR Python 绑定（`osgeo.gdal`、`osgeo.ogr`）直接调用 GDAL API。

### 14.5.2 安装要求

```bash
# 安装 GDAL Python 绑定
pip install gdal==$(gdal-config --version)

# 或通过 conda
conda install -c conda-forge gdal
```

### 14.5.3 适用场景

```yaml
# 需要精细控制 GDAL 读取行为
- id: read-cog
  use: io.read_raster
  backend: gdal_python
  params:
    path: "https://example.com/large_cog.tif"   # Cloud Optimized GeoTIFF

# 使用 GDAL 特有的栅格操作
- id: create-vrt
  use: io.read_raster
  backend: gdal_python
  params:
    path: "data/mosaic.vrt"   # GDAL 虚拟栅格
```

## 14.6 `qgis_process` 后端

### 14.6.1 技术基础

调用 QGIS Processing 框架的命令行工具 `qgis_process`，可以使用 QGIS 的所有处理算法。

### 14.6.2 安装要求

需要安装 QGIS 3.x（带命令行工具）：

```bash
# Ubuntu（QGIS 官方源）
sudo add-apt-repository ppa:ubuntugis/ubuntugis-unstable
sudo apt-get install qgis

# 验证
qgis_process list
# 列出所有可用算法
```

### 14.6.3 适用场景

```yaml
pipeline:
  name: "QGIS Processing 后端示例"
  steps:
    - id: load
      use: io.read_vector
      params:
        path: "data/roads.geojson"

    # 使用 QGIS 的 v.net.path（GRASS 网络分析）
    - id: network-analysis
      use: network.shortest_path
      backend: qgis_process
      params:
        input: "$load"
        origin: [116.39, 39.90]
        destination: [116.45, 39.92]

    # 使用 QGIS 的地形分析算法
    - id: slope-analysis
      use: raster.calc
      backend: qgis_process
      params:
        input: "$load-dem"
        expression: "slope"   # QGIS 坡度算法
```

### 14.6.4 优缺点

| 优点 | 缺点 |
|------|------|
| 海量 QGIS 算法可用（含 GRASS/SAGA） | 需要完整 QGIS 安装（大） |
| 图形界面可视化验证 | 调用速度慢（进程启动开销） |
| 支持 GRASS、SAGA 算法 | 配置复杂 |

---

## 14.7 `pyqgis` 后端

### 14.7.1 技术基础

直接使用 PyQGIS API（`qgis.core`），在 Python 进程中嵌入 QGIS。

### 14.7.2 适用场景

```yaml
# 使用 PyQGIS 特有的渲染和样式功能
- id: render-map
  use: io.write_vector
  backend: pyqgis
  params:
    input: "$buffer"
    path: "output/styled_map.pdf"   # 带样式的地图输出
    format: "PDF"
```

### 14.7.3 初始化配置

使用 PyQGIS 后端前，需要配置 QGIS 安装路径：

```bash
# 设置环境变量
export QGIS_PREFIX_PATH=/usr/share/qgis
export PYTHONPATH=/usr/share/qgis/python:$PYTHONPATH
```

## 14.8 `generic_cli` 后端

### 14.8.1 技术基础

通过 Python 的 `subprocess` 调用任意命令行工具，适合集成非标准 GIS 工具。

### 14.8.2 使用方式

`generic_cli` 后端需要配置命令模板：

```yaml
pipeline:
  name: "通用 CLI 后端示例"
  steps:
    - id: load
      use: io.read_vector
      params:
        path: "data/roads.geojson"

    # 调用自定义脚本处理
    - id: custom-process
      use: io.write_vector
      backend: generic_cli
      params:
        input: "$load"
        command: "my_custom_tool --input {input} --output {output} --format {format}"
        path: "output/processed.geojson"
        format: "GeoJSON"

    # 调用 PostGIS CLI 工具
    - id: load-postgis
      use: io.read_vector
      backend: generic_cli
      params:
        command: "psql -c \"COPY ... TO STDOUT\" | ogr2ogr -f GeoJSON /vsistdout/ PG:'...' layer_name"
        path: "pipe://stdin"
```

### 14.8.3 适用场景

- 调用公司内部开发的 GIS 工具
- 集成遗留系统的 CLI 工具
- 调用专业仪器软件的命令行接口
- 执行 PostGIS/SpatiaLite SQL 操作

## 14.9 `curl_api` 后端

### 14.9.1 技术基础

通过 HTTP 请求调用 Web GIS 服务，底层使用 `curl` 命令或 Python `requests` 库。

### 14.9.2 使用示例

```yaml
pipeline:
  name: "Web API 后端示例"
  steps:
    # 从 WFS 服务读取数据
    - id: load-wfs
      use: io.read_vector
      backend: curl_api
      params:
        url: "https://geoserver.example.com/ows?service=WFS&version=2.0.0&request=GetFeature&typeName=roads&outputFormat=application/json"
        format: "GeoJSON"

    # 调用地理编码 REST API（百度地图）
    - id: geocode-baidu
      use: network.geocode
      backend: curl_api
      params:
        url: "https://api.map.baidu.com/geocoding/v3/"
        method: "GET"
        query_params:
          address: "${target_address}"
          ak: "${baidu_api_key}"
          output: "json"

    # 发布数据到 GeoServer
    - id: publish-to-geoserver
      use: io.write_vector
      backend: curl_api
      on_error: retry
      params:
        input: "$process"
        url: "https://geoserver.example.com/rest/workspaces/ws/datastores/ds/featuretypes"
        method: "POST"
        auth_type: "basic"
        username: "${gs_user}"
        password: "${gs_password}"
```

### 14.9.3 安全注意事项

```yaml
# ✓ 推荐：通过变量传入敏感信息
variables:
  api_key: "${API_KEY}"        # 从环境变量或 --var 传入

# ✗ 避免：在 YAML 中硬编码密钥
variables:
  api_key: "sk-abc123..."     # 不要这样做！
```

## 14.11 后端选择建议

| 场景 | 推荐后端 |
|------|----------|
| 一般 GIS 开发 | `native_python` |
| 大文件处理（>1GB） | `gdal_cli` |
| 格式兼容性（Esri、MDB 等） | `gdal_cli` |
| 使用 QGIS 高级算法 | `qgis_process` |
| 地图渲染和出图 | `pyqgis` |
| 调用企业内部工具 | `generic_cli` |
| 调用云端 GIS 服务 | `curl_api` |
| 网络不稳定的 API 调用 | `curl_api` + `on_error: retry` |

## 14.12 后端不可用时的错误处理

```yaml
steps:
  # 尝试使用 QGIS，不可用时回退到 native_python
  - id: advanced-buffer
    use: vector.buffer
    backend: qgis_process
    on_error: skip         # QGIS 不可用时跳过

  # 如果上一步被跳过，用 native_python 的缓冲区
  - id: fallback-buffer
    use: vector.buffer
    when: "$advanced-buffer.status == 'skipped'"
    params:
      input: "$load"
      distance: 500
```

当指定后端不可用时，执行器会抛出 `BackendNotAvailableError`：
```
BackendNotAvailableError: 后端 'qgis_process' 不可用，请确认 QGIS 已安装且 qgis_process 在 PATH 中
```

## 14.13 本章小结

本章详细介绍了 GeoPipeAgent 的 7 种执行后端：

1. **`native_python`**（默认）：GeoPandas + Shapely，纯 Python，推荐日常使用
2. **`gdal_cli`**：ogr2ogr 命令行，适合大文件和格式转换
3. **`gdal_python`**：GDAL Python API，精细控制
4. **`qgis_process`**：QGIS Processing 算法库
5. **`pyqgis`**：PyQGIS API，含渲染功能
6. **`generic_cli`**：调用任意命令行工具
7. **`curl_api`**：调用 Web API 服务

多后端系统使 GeoPipeAgent 成为一个**工具集成平台**，而不仅仅是一个 GIS 库。
