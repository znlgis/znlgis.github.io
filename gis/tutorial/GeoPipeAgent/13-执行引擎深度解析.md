# 第十三章：执行引擎深度解析

## 13.1 概述

GeoPipeAgent 的执行引擎由四个核心模块组成，分工明确：

| 模块 | 文件 | 职责 |
|------|------|------|
| `parser.py` | 解析器 | 将 YAML 文件转换为 Python 数据模型 |
| `validator.py` | 校验器 | 静态检查流水线的合法性 |
| `executor.py` | 执行器 | 按顺序执行每个步骤，管理错误和重试 |
| `context.py` | 上下文 | 管理变量、步骤结果，解析引用 |
| `reporter.py` | 报告器 | 生成 JSON 格式的执行报告 |

整个执行流程如下：

```
YAML 文件
    ↓  parser.py
PipelineDefinition 数据模型
    ↓  validator.py
通过校验
    ↓  executor.py + context.py
步骤执行（逐步）
    ↓  reporter.py
JSON 报告
```

---

## 13.2 `parser.py`：YAML 解析器

### 13.2.1 解析职责

`parser.py` 的职责是将 YAML 文本转换为结构化的 Python 对象：
- 读取 YAML 文件
- 验证顶层 `pipeline:` 键存在
- 构建 `PipelineDefinition` 和 `StepDefinition` 对象
- **不做**引用有效性检查（这是 validator 的工作）

### 13.2.2 解析流程

```python
# parser.py 伪代码
def parse_pipeline(yaml_path: str) -> PipelineDefinition:
    # 1. 读取 YAML 文件
    with open(yaml_path) as f:
        raw = yaml.safe_load(f)

    # 2. 检查顶层键
    if "pipeline" not in raw:
        raise PipelineParseError(
            f"无效的流水线格式：缺少必要的顶层键 'pipeline'"
        )

    data = raw["pipeline"]

    # 3. 解析必填字段
    if "name" not in data:
        raise PipelineParseError("流水线缺少必填字段 'name'")

    # 4. 解析步骤列表
    steps = []
    for step_data in data.get("steps", []):
        step = StepDefinition(
            id=step_data["id"],
            use=step_data["use"],
            params=step_data.get("params", {}),
            when=step_data.get("when"),
            on_error=step_data.get("on_error", "fail"),
            backend=step_data.get("backend"),
        )
        steps.append(step)

    # 5. 返回 PipelineDefinition
    return PipelineDefinition(
        name=data["name"],
        description=data.get("description", ""),
        crs=data.get("crs"),
        variables=data.get("variables", {}),
        steps=steps,
        outputs=data.get("outputs", {}),
    )
```

### 13.2.3 `PipelineParseError` 触发条件

| 情况 | 错误信息示例 |
|------|-------------|
| 缺少 `pipeline:` 键 | `缺少必要的顶层键 'pipeline'` |
| 缺少 `name` 字段 | `流水线缺少必填字段 'name'` |
| 步骤缺少 `id` 字段 | `第 2 个步骤缺少必填字段 'id'` |
| 步骤缺少 `use` 字段 | `步骤 'step1' 缺少必填字段 'use'` |
| `on_error` 值不合法 | `步骤 'step1' 的 on_error 值 'ignore' 不合法` |
| YAML 格式错误 | `YAML 解析失败：第 5 行缩进错误` |

## 13.3 `validator.py`：流水线校验器

### 13.3.1 校验职责

`validator.py` 在解析完成后进行**静态分析**，检查流水线的逻辑合法性：

1. **步骤 ID 唯一性**：同一流水线中不允许重复的步骤 ID
2. **步骤 ID 格式**：只允许 `[a-z0-9_-]`（小写字母、数字、连字符、下划线）
3. **步骤引用有效性**：引用的步骤 ID 必须存在且在当前步骤之前
4. **循环引用检测**：检测步骤间的循环依赖
5. **步骤注册检查**：引用的步骤类型（`use`）必须已在注册表中

### 13.3.2 校验流程

```python
# validator.py 伪代码
def validate_pipeline(pipeline: PipelineDefinition) -> list[str]:
    errors = []
    seen_ids = set()

    for i, step in enumerate(pipeline.steps):
        # 检查 ID 格式
        if not re.match(r'^[a-z0-9_-]+$', step.id):
            errors.append(f"步骤 ID '{step.id}' 包含非法字符")

        # 检查 ID 唯一性
        if step.id in seen_ids:
            errors.append(f"重复的步骤 ID: '{step.id}'")
        seen_ids.add(step.id)

        # 检查 params 中的引用
        for param_value in _get_all_string_values(step.params):
            refs = _extract_step_refs(param_value)  # 提取 $step-id 引用
            for ref in refs:
                if ref not in seen_ids:  # 前向引用检查
                    errors.append(
                        f"步骤 '{step.id}' 引用了不存在的步骤 '{ref}'"
                    )

    if errors:
        raise PipelineValidationError(errors)
```

### 13.3.3 `PipelineValidationError` 触发条件

| 情况 | 错误信息示例 |
|------|-------------|
| 重复步骤 ID | `发现重复的步骤 ID: 'load'` |
| ID 格式错误 | `步骤 ID 'Load Roads' 包含非法字符，应符合 [a-z0-9_-]` |
| 引用不存在的步骤 | `步骤 'buffer' 引用了不存在的步骤 'load-data'` |
| 前向引用 | `步骤 'buffer' 引用了尚未执行的步骤 'save'（前向引用）` |
| 循环引用 | `检测到循环引用：a → b → a` |

## 13.4 `executor.py`：步骤执行器

### 13.4.1 执行流程

```python
# executor.py 伪代码
class PipelineExecutor:
    def execute(self, pipeline: PipelineDefinition, variables: dict) -> ExecutionResult:
        ctx = PipelineContext(variables=variables)
        results = []

        for step in pipeline.steps:
            # 1. 评估 when 条件
            if step.when is not None:
                condition = self._eval_condition(step.when, ctx)
                if not condition:
                    results.append(StepRecord(id=step.id, status="skipped"))
                    continue

            # 2. 根据 on_error 执行步骤
            if step.on_error == "retry":
                result = self._execute_with_retry(step, ctx)
            elif step.on_error == "skip":
                result = self._execute_with_skip(step, ctx)
            else:  # fail
                result = self._execute_step(step, ctx)

            # 3. 将结果存入上下文
            ctx.set_step_result(step.id, result)
            results.append(result)

        return ExecutionResult(steps=results)
```

### 13.4.2 条件评估（`when` 表达式）

执行器在执行每个步骤前评估 `when` 条件：

```python
def _eval_condition(self, expression: str, ctx: PipelineContext) -> bool:
    # 解析引用
    resolved = self._resolve_refs(expression, ctx)

    # 安全求值（使用受限的 eval 环境）
    safe_globals = {"__builtins__": {}, "len": len, "abs": abs}
    try:
        return bool(eval(resolved, safe_globals))
    except Exception as e:
        raise StepExecutionError(f"条件表达式求值失败: {expression}")
```

### 13.4.3 重试机制

```python
def _execute_with_retry(self, step: StepDefinition, ctx: PipelineContext) -> StepResult:
    max_attempts = 4   # 1 次 + 最多 3 次重试
    delay = 0.5        # 0.5 秒退避间隔

    for attempt in range(max_attempts):
        try:
            return self._execute_step(step, ctx)
        except StepExecutionError as e:
            if attempt < max_attempts - 1:
                time.sleep(delay)
                logger.warning(f"步骤 '{step.id}' 第 {attempt+1} 次尝试失败，准备重试...")
            else:
                logger.error(f"步骤 '{step.id}' 全部重试均失败")
                raise  # 重新抛出，终止流水线
```

### 13.4.4 步骤执行过程

```python
def _execute_step(self, step: StepDefinition, ctx: PipelineContext) -> StepResult:
    # 1. 查找步骤函数
    step_fn = registry.get(step.use)
    if step_fn is None:
        raise StepNotFoundError(step.use)

    # 2. 解析参数（替换变量和引用）
    resolved_params = self._resolve_params(step.params, ctx)

    # 3. 选择后端
    backend = BackendSelector.select(step.backend, step.use)

    # 4. 创建 StepContext
    step_ctx = StepContext(params=resolved_params, pipeline_ctx=ctx, backend=backend)

    # 5. 执行步骤函数
    try:
        start_time = time.time()
        result = step_fn(step_ctx)
        result.metadata["duration"] = time.time() - start_time
        return result
    except Exception as e:
        raise StepExecutionError(
            step_id=step.id,
            message=str(e),
            cause=e
        )
```

## 13.5 `context.py`：上下文管理

### 13.5.1 `PipelineContext`

`PipelineContext` 是整个流水线执行过程中的全局状态容器：

```python
class PipelineContext:
    def __init__(self, variables: dict):
        self.variables: dict = variables
        self.step_results: dict[str, StepResult] = {}

    def set_step_result(self, step_id: str, result: StepResult):
        self.step_results[step_id] = result

    def get_step_result(self, step_id: str) -> StepResult:
        if step_id not in self.step_results:
            raise VariableResolutionError(f"步骤 '{step_id}' 尚未执行或不存在")
        return self.step_results[step_id]

    def resolve_value(self, value: Any) -> Any:
        """解析字符串中的变量引用和步骤引用"""
        if isinstance(value, str):
            # 解析变量引用 ${var_name}
            value = self._resolve_variables(value)
            # 解析步骤引用 $step-id 或 $step-id.attr
            value = self._resolve_step_refs(value)
        return value
```

### 13.5.2 `StepContext`

`StepContext` 是传给每个步骤函数的局部上下文，提供便捷方法：

```python
class StepContext:
    def __init__(self, params: dict, pipeline_ctx: PipelineContext, backend: str):
        self._params = params
        self._pipeline_ctx = pipeline_ctx
        self.backend = backend

    def param(self, key: str, default=None) -> Any:
        """获取已解析的步骤参数"""
        value = self._params.get(key, default)
        return self._pipeline_ctx.resolve_value(value)

    def require_param(self, key: str) -> Any:
        """获取必填参数，不存在则报错"""
        if key not in self._params:
            raise StepExecutionError(f"缺少必填参数: {key}")
        return self.param(key)

    def get_step_output(self, step_id: str) -> Any:
        """直接获取其他步骤的输出"""
        return self._pipeline_ctx.get_step_result(step_id).output
```

### 13.5.3 引用解析详解

```python
def _resolve_step_refs(self, value: str) -> Any:
    """
    解析步骤引用：
    - "$step-id"         → step_results["step-id"].output
    - "$step-id.output"  → step_results["step-id"].output（等价）
    - "$step-id.stats"   → step_results["step-id"].stats
    - "$step-id.issues"  → step_results["step-id"].issues
    - "$step-id.stats.feature_count" → step_results["step-id"].stats["feature_count"]
    """
    # 完整替换：整个字符串就是一个引用
    if re.match(r'^\$[a-z0-9_-]+(\.[a-z_]+)*$', value):
        return self._get_ref_value(value)

    # 嵌入式替换：字符串中包含引用（较少见）
    def replace_ref(match):
        return str(self._get_ref_value(match.group(0)))

    return re.sub(r'\$[a-z0-9_-]+(\.[a-z_]+)*', replace_ref, value)
```

## 13.6 `reporter.py`：报告生成器

### 13.6.1 报告结构

```python
class Reporter:
    def generate(self,
                 pipeline: PipelineDefinition,
                 execution_results: list[StepRecord],
                 variables: dict) -> dict:
        return {
            "pipeline": pipeline.name,
            "description": pipeline.description,
            "status": self._overall_status(execution_results),
            "started_at": self._start_time.isoformat(),
            "finished_at": datetime.now().isoformat(),
            "duration": self._total_duration(),
            "variables": variables,
            "steps": [self._step_record(r) for r in execution_results],
            "outputs": self._resolve_outputs(pipeline.outputs, ctx),
        }
```

### 13.6.2 整体状态计算

| 状态 | 条件 |
|------|------|
| `success` | 所有步骤成功完成（跳过不计） |
| `partial` | 部分步骤跳过，其余成功 |
| `failed` | 至少一个步骤失败 |

## 13.7 错误报告

当步骤执行失败时，报告中会包含详细的错误信息：

```json
{
  "pipeline": "道路分析",
  "status": "failed",
  "steps": [
    {
      "id": "load-roads",
      "status": "failed",
      "error": {
        "type": "StepExecutionError",
        "message": "文件不存在: data/roads.geojson",
        "step_id": "load-roads",
        "suggestion": "请检查文件路径是否正确，当前工作目录为 /home/user/project",
        "cause": "FileNotFoundError"
      },
      "attempts": 1
    }
  ]
}
```

`StepExecutionError` 的三个关键字段：
- `message`：错误描述
- `suggestion`：修复建议（帮助用户快速定位问题）
- `cause`：原始异常类型

## 13.9 本章小结

本章深入解析了 GeoPipeAgent 执行引擎的五个核心模块：

1. **parser.py**：YAML → 数据模型，强制 `pipeline:` 顶层键
2. **validator.py**：静态检查，捕获 ID 冲突、引用错误、循环依赖
3. **executor.py**：顺序执行，处理 `when` 条件、错误策略和重试
4. **context.py**：PipelineContext 管理全局状态，StepContext 提供步骤局部视图
5. **reporter.py**：生成结构化 JSON 报告，记录每步状态、统计和错误

理解执行引擎有助于：
- 诊断复杂流水线的执行问题
- 开发自定义步骤（正确使用 StepContext）
- 优化流水线性能（减少不必要的步骤）
