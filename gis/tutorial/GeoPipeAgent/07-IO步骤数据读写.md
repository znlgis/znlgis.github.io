# 第7章：IO步骤——数据读写

> 本章将详细介绍 GeoPipeAgent 的四个 IO 步骤：`io.read_vector`、`io.write_vector`、`io.read_raster`、`io.write_raster`。您将了解每个步骤的参数定义、返回数据结构、格式支持以及源码实现细节。

---

## 7.1 IO步骤概述

### 7.1.1 四个 IO 步骤

IO 步骤是 GeoPipeAgent 流水线的入口和出口，负责数据的读取与写入。共包含四个步骤：

| 步骤 ID | 功能 | 核心依赖 |
|---------|------|----------|
| `io.read_vector` | 读取矢量数据文件 | geopandas |
| `io.write_vector` | 写入矢量数据文件 | geopandas |
| `io.read_raster` | 读取栅格数据文件 | rasterio |
| `io.write_raster` | 写入栅格数据文件 | rasterio |

### 7.1.2 在流水线中的角色

IO 步骤通常位于流水线的首尾位置：

```
┌──────────────┐    ┌──────────────┐    ┌──────────────┐    ┌───────────────┐
│ io.read_vector│───▶│vector.buffer │───▶│vector.clip   │───▶│io.write_vector│
└──────────────┘    └──────────────┘    └──────────────┘    └───────────────┘
     入口                 处理               处理                  出口
```

一个典型的 YAML 流水线结构：

```yaml
name: 数据处理示例
steps:
  - id: read_data
    step: io.read_vector
    params:
      path: "input/buildings.shp"

  - id: process
    step: vector.buffer
    params:
      input: "$steps.read_data"
      distance: 100

  - id: save
    step: io.write_vector
    params:
      input: "$steps.process"
      path: "output/buffered.gpkg"
      format: gpkg
```

### 7.1.3 IO 步骤的特殊性

与分析步骤不同，IO 步骤：

- **不使用后端委托**：没有 `backends` 属性，因为文件读写逻辑不涉及可替换的算法实现
- **直接操作文件系统**：涉及路径处理、目录创建、文件编码等系统层面操作
- **返回丰富的统计信息**：除了数据本身，还返回 `stats` 字典提供数据概况

## 7.2 io.read_vector 详解

### 7.2.1 步骤注册信息

```python
@step(
    id="io.read_vector",
    name="读取矢量数据",
    description="从文件读取矢量地理数据，支持 Shapefile、GeoJSON、GeoPackage 等格式",
    params={
        "path": {"type": "str", "required": True,
                 "description": "输入文件路径"},
        "layer": {"type": "str", "required": False,
                  "description": "图层名称（用于多图层格式如 GPKG）"},
        "encoding": {"type": "str", "required": False,
                     "default": "utf-8",
                     "description": "文件编码"},
    },
)
def read_vector(ctx):
    ...
```

### 7.2.2 参数详解

| 参数 | 类型 | 必需 | 默认值 | 说明 |
|------|------|------|--------|------|
| `path` | `str` | ✅ | — | 输入文件路径，支持相对路径和绝对路径 |
| `layer` | `str` | ❌ | `None` | 图层名称，用于多图层格式（如 GeoPackage） |
| `encoding` | `str` | ❌ | `"utf-8"` | 文件编码，中文 Shapefile 常需指定为 `"gbk"` |

### 7.2.3 支持的文件格式

`io.read_vector` 基于 `geopandas.read_file()` 实现，支持所有 GDAL/OGR 驱动支持的矢量格式：

| 格式 | 扩展名 | 说明 |
|------|--------|------|
| Shapefile | `.shp` | 最常用的 GIS 矢量格式，需配套 `.dbf`、`.shx`、`.prj` 文件 |
| GeoJSON | `.geojson` / `.json` | 基于 JSON 的地理数据格式，UTF-8 编码 |
| GeoPackage | `.gpkg` | 基于 SQLite 的现代 GIS 格式，支持多图层 |
| KML | `.kml` | Google Earth 格式 |
| CSV | `.csv` | 需包含 WKT 几何列或经纬度列 |

### 7.2.4 返回数据结构

`io.read_vector` 通过 `StepResult` 返回两部分数据：

**output — GeoDataFrame：**

```python
# 读取后的 GeoDataFrame 包含：
#   - geometry 列：几何对象（Point, LineString, Polygon 等）
#   - 属性列：原始数据中的各字段
```

**stats — 统计信息字典：**

```python
stats = {
    "feature_count": 1234,            # 要素数量
    "crs": "EPSG:4326",               # 坐标参考系
    "geometry_types": ["Polygon"],     # 几何类型列表
    "columns": ["name", "area", ...],  # 属性列名列表
}
```

### 7.2.5 源码分析

```python
@step(id="io.read_vector", ...)
def read_vector(ctx):
    path = ctx.param("path")
    layer = ctx.param("layer")
    encoding = ctx.param("encoding")

    # 构建读取参数
    kwargs = {}
    if layer is not None:
        kwargs["layer"] = layer
    if encoding is not None:
        kwargs["encoding"] = encoding

    # 使用 geopandas 读取
    gdf = gpd.read_file(path, **kwargs)

    # 构建统计信息
    stats = {
        "feature_count": len(gdf),
        "crs": str(gdf.crs) if gdf.crs else None,
        "geometry_types": sorted(gdf.geometry.geom_type.unique().tolist()),
        "columns": list(gdf.columns),
    }

    return StepResult(output=gdf, stats=stats)
```

核心流程：

1. 从上下文 `ctx` 中提取参数
2. 仅将非空参数传递给 `gpd.read_file()`
3. 使用 geopandas 的 `read_file()` 方法读取文件
4. 收集统计信息：要素数、坐标系、几何类型、列名
5. 封装为 `StepResult` 返回

## 7.3 io.write_vector 详解

### 7.3.1 步骤注册信息

```python
@step(
    id="io.write_vector",
    name="写入矢量数据",
    description="将 GeoDataFrame 写入矢量数据文件",
    params={
        "input": {"type": "GeoDataFrame", "required": True,
                  "description": "输入矢量数据"},
        "path": {"type": "str", "required": True,
                 "description": "输出文件路径"},
        "format": {"type": "str", "required": False,
                   "default": "gpkg",
                   "description": "输出格式（shp/geojson/gpkg）"},
        "encoding": {"type": "str", "required": False,
                     "default": "utf-8",
                     "description": "文件编码"},
    },
)
def write_vector(ctx):
    ...
```

### 7.3.2 参数详解

| 参数 | 类型 | 必需 | 默认值 | 说明 |
|------|------|------|--------|------|
| `input` | `GeoDataFrame` | ✅ | — | 要写入的矢量数据，通常来自上游步骤引用 |
| `path` | `str` | ✅ | — | 输出文件路径 |
| `format` | `str` | ❌ | `"gpkg"` | 输出格式标识 |
| `encoding` | `str` | ❌ | `"utf-8"` | 文件编码 |

### 7.3.3 格式映射 _FORMAT_MAP

`io.write_vector` 使用 `_FORMAT_MAP` 字典将用户友好的格式名映射为 GDAL 驱动名：

```python
_FORMAT_MAP = {
    "shp":      "ESRI Shapefile",
    "shapefile":"ESRI Shapefile",
    "geojson":  "GeoJSON",
    "json":     "GeoJSON",
    "gpkg":     "GPKG",
    "geopackage": "GPKG",
    "csv":      "CSV",
    "kml":      "KML",
}
```

这意味着用户可以使用简短的格式名称：

```yaml
# 以下写法均有效
format: shp
format: shapefile
format: geojson
format: json
format: gpkg
format: geopackage
```

### 7.3.4 自动创建目录

`io.write_vector` 在写入前会自动创建输出路径中不存在的目录：

```python
output_dir = Path(path).parent
output_dir.mkdir(parents=True, exist_ok=True)
```

这意味着用户无需手动创建输出目录，流水线可以直接指定深层路径：

```yaml
path: "output/2024/processed/result.gpkg"
# output/2024/processed/ 目录会自动创建
```

### 7.3.5 源码分析

```python
@step(id="io.write_vector", ...)
def write_vector(ctx):
    gdf = ctx.input("input")
    path = ctx.param("path")
    fmt = ctx.param("format") or "gpkg"
    encoding = ctx.param("encoding")

    # 格式名标准化
    driver = _FORMAT_MAP.get(fmt.lower(), fmt)

    # 自动创建输出目录
    Path(path).parent.mkdir(parents=True, exist_ok=True)

    # 写入文件
    kwargs = {"driver": driver}
    if encoding is not None:
        kwargs["encoding"] = encoding

    gdf.to_file(path, **kwargs)

    # 返回结果
    stats = {
        "feature_count": len(gdf),
        "path": str(path),
        "format": driver,
    }
    return StepResult(output=gdf, stats=stats)
```

## 7.4 io.read_raster 详解

### 7.4.1 步骤注册信息

```python
@step(
    id="io.read_raster",
    name="读取栅格数据",
    description="从文件读取栅格地理数据（GeoTIFF 等）",
    params={
        "path": {"type": "str", "required": True,
                 "description": "输入文件路径"},
    },
)
def read_raster(ctx):
    ...
```

### 7.4.2 参数详解

| 参数 | 类型 | 必需 | 默认值 | 说明 |
|------|------|------|--------|------|
| `path` | `str` | ✅ | — | 栅格文件路径，支持 GeoTIFF 等格式 |

### 7.4.3 rasterio 读取机制

`io.read_raster` 使用 `rasterio` 库读取栅格数据。与 geopandas 不同，rasterio 采用数据集（dataset）方式访问栅格：

```python
import rasterio

with rasterio.open(path) as src:
    data = src.read()          # 读取所有波段，返回 numpy 数组
    transform = src.transform  # 仿射变换矩阵
    crs = src.crs              # 坐标参考系
    profile = src.profile      # 完整的数据集配置信息
```

### 7.4.4 返回的 raster_info 字典结构

`io.read_raster` 返回一个特殊的 `raster_info` 字典，而非 GeoDataFrame：

```python
raster_info = {
    "data": numpy_array,    # shape: (bands, height, width)
    "transform": transform, # rasterio.transform.Affine 对象
    "crs": crs,             # rasterio.crs.CRS 对象
    "profile": profile,     # 完整的 rasterio profile 字典
    "path": path,           # 原始文件路径
}
```

**`data` 字段详解：**

```python
# data 是三维 numpy 数组
# data.shape = (band_count, height, width)
# 例如：单波段 DEM 数据 shape 为 (1, 512, 512)
# 例如：三波段 RGB 影像 shape 为 (3, 1024, 1024)
```

**`transform` 字段详解：**

仿射变换矩阵将像素坐标映射到地理坐标：

```
| x_geo |   | a  b  c | | col |
| y_geo | = | d  e  f | | row |
|   1   |   | 0  0  1 | |  1  |
```

其中 `a` 是像素宽度，`e` 是像素高度（通常为负值），`c` 和 `f` 是左上角坐标。

**`profile` 字段详解：**

```python
profile = {
    "driver": "GTiff",
    "dtype": "float32",
    "width": 512,
    "height": 512,
    "count": 1,           # 波段数
    "crs": CRS.from_epsg(4326),
    "transform": Affine(...),
    "nodata": -9999.0,
    # ... 其他 TIFF 特定选项
}
```

### 7.4.5 统计信息

```python
stats = {
    "width": src.width,           # 像素宽度
    "height": src.height,         # 像素高度
    "crs": str(src.crs),          # 坐标参考系字符串
    "band_count": src.count,      # 波段数量
    "dtype": str(src.dtypes[0]),  # 数据类型
    "bounds": {                   # 地理范围
        "left": src.bounds.left,
        "bottom": src.bounds.bottom,
        "right": src.bounds.right,
        "top": src.bounds.top,
    },
}
```

### 7.4.6 源码分析

```python
@step(id="io.read_raster", ...)
def read_raster(ctx):
    path = ctx.param("path")

    with rasterio.open(path) as src:
        data = src.read()
        transform = src.transform
        crs = src.crs
        profile = src.profile.copy()

        stats = {
            "width": src.width,
            "height": src.height,
            "crs": str(src.crs),
            "band_count": src.count,
            "dtype": str(src.dtypes[0]),
            "bounds": {
                "left": src.bounds.left,
                "bottom": src.bounds.bottom,
                "right": src.bounds.right,
                "top": src.bounds.top,
            },
        }

    raster_info = {
        "data": data,
        "transform": transform,
        "crs": crs,
        "profile": profile,
        "path": path,
    }

    return StepResult(output=raster_info, stats=stats)
```

## 7.5 io.write_raster 详解

### 7.5.1 步骤注册信息

```python
@step(
    id="io.write_raster",
    name="写入栅格数据",
    description="将栅格数据写入文件（GeoTIFF 格式）",
    params={
        "input": {"type": "dict", "required": True,
                  "description": "输入栅格数据（raster_info 字典）"},
        "path": {"type": "str", "required": True,
                 "description": "输出文件路径"},
    },
)
def write_raster(ctx):
    ...
```

### 7.5.2 参数详解

| 参数 | 类型 | 必需 | 默认值 | 说明 |
|------|------|------|--------|------|
| `input` | `dict` | ✅ | — | 栅格数据字典（`raster_info` 结构） |
| `path` | `str` | ✅ | — | 输出文件路径 |

### 7.5.3 profile 写入机制

`io.write_raster` 使用 `raster_info` 中的 `profile` 来配置输出文件：

```python
profile = raster_info["profile"]
# profile 包含了 driver, dtype, width, height, count, crs, transform, nodata 等
# 直接用作 rasterio.open() 的参数
```

### 7.5.4 源码分析

```python
@step(id="io.write_raster", ...)
def write_raster(ctx):
    raster_info = ctx.input("input")
    path = ctx.param("path")

    data = raster_info["data"]
    profile = raster_info["profile"].copy()

    # 自动创建输出目录
    Path(path).parent.mkdir(parents=True, exist_ok=True)

    # 确保 profile 与实际数据一致
    profile.update({
        "driver": "GTiff",
        "height": data.shape[-2],
        "width": data.shape[-1],
        "count": data.shape[0] if data.ndim == 3 else 1,
    })

    # 写入栅格文件
    with rasterio.open(path, "w", **profile) as dst:
        if data.ndim == 2:
            dst.write(data, 1)
        else:
            dst.write(data)

    stats = {
        "path": str(path),
        "width": profile["width"],
        "height": profile["height"],
        "band_count": profile["count"],
    }

    return StepResult(output=raster_info, stats=stats)
```

核心流程：

1. 从 `raster_info` 中提取 `data` 和 `profile`
2. 自动创建输出目录
3. 更新 `profile` 确保与实际数据维度一致
4. 使用 `rasterio.open()` 以写模式打开文件
5. 根据数据维度（2D 或 3D）选择不同的写入方式

## 7.6 IO步骤使用示例

### 7.6.1 矢量数据读写流水线

```yaml
name: 矢量数据格式转换
description: 将 Shapefile 转换为 GeoPackage 格式

steps:
  - id: read_shp
    step: io.read_vector
    params:
      path: "data/input/buildings.shp"
      encoding: "gbk"

  - id: write_gpkg
    step: io.write_vector
    params:
      input: "$steps.read_shp"
      path: "data/output/buildings.gpkg"
      format: gpkg
```

### 7.6.2 栅格数据读写流水线

```yaml
name: 栅格数据处理
description: 读取 DEM 数据，执行投影转换后写出

steps:
  - id: read_dem
    step: io.read_raster
    params:
      path: "data/input/dem.tif"

  - id: reproject_dem
    step: raster.reproject
    params:
      input: "$steps.read_dem"
      target_crs: "EPSG:3857"

  - id: write_result
    step: io.write_raster
    params:
      input: "$steps.reproject_dem"
      path: "data/output/dem_3857.tif"
```

### 7.6.3 混合读写流水线

```yaml
name: 栅格转矢量
description: 从 DEM 提取等值线并保存为矢量

steps:
  - id: read_dem
    step: io.read_raster
    params:
      path: "data/dem.tif"

  - id: extract_contours
    step: raster.contour
    params:
      input: "$steps.read_dem"
      interval: 100

  - id: save_contours
    step: io.write_vector
    params:
      input: "$steps.extract_contours"
      path: "output/contours.geojson"
      format: geojson
```

## 7.8 最佳实践与注意事项

### 7.8.1 编码问题

中文 Shapefile 常使用 GBK 编码，读取时必须显式指定：

```yaml
# ❌ 错误：默认 UTF-8 可能导致乱码
- step: io.read_vector
  params:
    path: "data/中国城市.shp"

# ✅ 正确：指定 GBK 编码
- step: io.read_vector
  params:
    path: "data/中国城市.shp"
    encoding: "gbk"
```

GeoJSON 和 GeoPackage 格式始终使用 UTF-8 编码，无需额外指定。

### 7.8.2 大文件处理

对于大型矢量数据集，建议：

1. **优先使用 GeoPackage 格式**：内置空间索引，查询效率更高
2. **使用 layer 参数**：GeoPackage 支持多图层，避免将所有数据写入一个文件
3. **注意内存限制**：`io.read_vector` 会将整个文件加载到内存，超大文件可能导致内存不足

对于大型栅格数据：

1. **注意 numpy 数组内存**：一个 10000×10000 的 float32 单波段数据占用约 380MB 内存
2. **使用 Cloud Optimized GeoTIFF (COG)**：支持部分读取，减少内存占用
3. **关注 nodata 处理**：栅格计算时需正确处理 nodata 值

### 7.8.3 路径处理

GeoPipeAgent 支持相对路径和绝对路径：

```yaml
# 相对路径 - 相对于流水线执行时的工作目录
path: "data/input.shp"

# 绝对路径
path: "/home/user/gis_data/input.shp"

# 带变量的路径
path: "$vars.output_dir/result.gpkg"
```

### 7.8.4 格式选择建议

| 场景 | 推荐格式 | 原因 |
|------|----------|------|
| 日常 GIS 数据交换 | GeoPackage | 现代、无限制、多图层 |
| Web 应用 | GeoJSON | 通用、易解析 |
| 与传统软件交互 | Shapefile | 兼容性最广 |
| 栅格数据存储 | GeoTIFF | 行业标准 |
| 大规模栅格分发 | Cloud Optimized GeoTIFF | 支持范围查询 |

## 7.9 本章小结

本章详细介绍了 GeoPipeAgent 的四个 IO 步骤：

1. **`io.read_vector`**：基于 geopandas 读取矢量数据，支持 Shapefile、GeoJSON、GeoPackage 等格式，返回 GeoDataFrame 和统计信息（feature_count、crs、geometry_types、columns）
2. **`io.write_vector`**：将 GeoDataFrame 写入文件，通过 `_FORMAT_MAP` 映射格式名，自动创建输出目录
3. **`io.read_raster`**：基于 rasterio 读取栅格数据，返回 `raster_info` 字典（含 data、transform、crs、profile、path），附带统计信息（width、height、crs、band_count、dtype、bounds）
4. **`io.write_raster`**：将 `raster_info` 字典写入 GeoTIFF 文件，自动创建目录、同步 profile 与数据维度

IO 步骤虽然逻辑相对简单，但它们是整个流水线的数据入口和出口，正确使用编码、格式和路径参数对于构建可靠的流水线至关重要。
