# 第七章：IO 步骤——数据读写

## 7.1 概述

IO 步骤是 GeoPipeAgent 的数据入口和出口，负责从文件系统或 URL 读取地理空间数据，以及将处理结果写回文件。GeoPipeAgent 提供 **4 个 IO 步骤**：

| 步骤 ID | 功能 | 输入 | 输出 |
|---------|------|------|------|
| `io.read_vector` | 读取矢量数据 | 文件路径/URL | GeoDataFrame |
| `io.write_vector` | 写入矢量数据 | GeoDataFrame + 路径 | 文件路径 |
| `io.read_raster` | 读取栅格数据 | 文件路径 | Raster 对象 |
| `io.write_raster` | 写入栅格数据 | Raster 对象 + 路径 | 文件路径 |

---

## 7.2 `io.read_vector`：读取矢量数据

### 7.2.1 参数说明

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| `path` | string | **是** | 文件路径或 URL |
| `layer` | string/int | 否 | 多图层文件时指定图层名或索引 |

### 7.2.2 支持的文件格式

| 格式 | 扩展名 | 说明 |
|------|--------|------|
| GeoJSON | `.geojson`, `.json` | 最常用，纯文本 |
| Shapefile | `.shp` | 经典 GIS 格式，需要配套 .dbf/.shx |
| GeoPackage | `.gpkg` | 现代 OGC 标准，推荐 |
| FileGDB | `.gdb` | Esri 文件地理数据库 |
| KML/KMZ | `.kml`, `.kmz` | Google Earth 格式 |
| CSV（含坐标列） | `.csv` | 需要指定坐标列 |
| PostGIS | `postgresql://...` | 数据库连接字符串 |
| WFS | `WFS:https://...` | OGC Web Feature Service |
| GML | `.gml` | OGC Geographic Markup Language |
| TopoJSON | `.topojson` | 拓扑 JSON |
| FlatGeobuf | `.fgb` | 高性能二进制格式 |

### 7.2.3 基本用法

```yaml
pipeline:
  name: "矢量数据读取示例"
  steps:
    # 读取 GeoJSON
    - id: load-geojson
      use: io.read_vector
      params:
        path: "data/roads.geojson"

    # 读取 Shapefile
    - id: load-shp
      use: io.read_vector
      params:
        path: "data/parcels.shp"

    # 读取 GeoPackage（指定图层名）
    - id: load-gpkg-layer
      use: io.read_vector
      params:
        path: "data/city_data.gpkg"
        layer: "roads"            # 指定图层名

    # 读取 GeoPackage（按索引）
    - id: load-gpkg-index
      use: io.read_vector
      params:
        path: "data/city_data.gpkg"
        layer: 0                  # 第一个图层

    # 读取远程 URL
    - id: load-remote
      use: io.read_vector
      on_error: retry
      params:
        path: "https://example.com/api/features.geojson"
```

### 7.2.4 输出的 `stats` 字段

```json
{
  "feature_count": 1250,
  "crs": "EPSG:4326",
  "geometry_type": "LineString",
  "bbox": [116.38, 39.88, 116.55, 40.05],
  "columns": ["road_id", "name", "road_type", "speed_limit"],
  "file_size_mb": 2.3
}
```

### 7.2.5 注意事项

**Shapefile 编码问题**（中文属性乱码）：

```yaml
# 读取含中文属性的 Shapefile（GeoPandas 默认 UTF-8，可能需要指定编码）
- id: load-chinese-shp
  use: io.read_vector
  params:
    path: "data/chinese_roads.shp"
    # 注意：如果遇到中文乱码，需要在数据源层面处理编码
    # 建议先转换为 GeoJSON（UTF-8）再使用
```

**大型文件处理**：

```yaml
# 大型 Shapefile（>1GB）建议先转换为 GeoPackage 或 FlatGeobuf
- id: load-large
  use: io.read_vector
  params:
    path: "data/national_roads.fgb"   # FlatGeobuf 读取速度快
```

## 7.3 `io.write_vector`：写入矢量数据

### 7.3.1 参数说明

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| `input` | GeoDataFrame | **是** | 输入数据（步骤引用） |
| `path` | string | **是** | 输出文件路径 |
| `format` / `driver` | string | 否 | 输出格式（见下表） |

`format` 和 `driver` 是同一个参数的两种写法，效果相同。

### 7.3.2 支持的输出格式

| 格式值 | 扩展名 | 说明 |
|--------|--------|------|
| `GeoJSON` | `.geojson` | 推荐，通用性好 |
| `GPKG` | `.gpkg` | GeoPackage，多图层 |
| `ESRI Shapefile` | `.shp` | 传统格式 |
| `FlatGeobuf` | `.fgb` | 高性能 |
| `KML` | `.kml` | Google Earth |
| `CSV` | `.csv` | 含 WKT 几何列 |
| `GML` | `.gml` | OGC GML |

### 7.3.3 基本用法

```yaml
pipeline:
  name: "矢量数据写入示例"
  steps:
    - id: load
      use: io.read_vector
      params:
        path: "data/roads.geojson"

    - id: buffer
      use: vector.buffer
      params:
        input: "$load"
        distance: 100

    # 写入 GeoJSON
    - id: save-geojson
      use: io.write_vector
      params:
        input: "$buffer"
        path: "output/road_buffer.geojson"
        format: "GeoJSON"

    # 写入 GeoPackage
    - id: save-gpkg
      use: io.write_vector
      params:
        input: "$buffer"
        path: "output/result.gpkg"
        format: "GPKG"

    # 写入 Shapefile
    - id: save-shp
      use: io.write_vector
      params:
        input: "$buffer"
        path: "output/road_buffer.shp"
        format: "ESRI Shapefile"

    # 写入 FlatGeobuf（高性能）
    - id: save-fgb
      use: io.write_vector
      params:
        input: "$buffer"
        path: "output/road_buffer.fgb"
        driver: "FlatGeobuf"       # 等同于 format: "FlatGeobuf"
```

### 7.3.4 输出目录自动创建

`io.write_vector` 会自动创建不存在的输出目录：

```yaml
params:
  path: "output/2024/01/beijing/roads_buffer.geojson"
  # 如果 output/2024/01/beijing/ 不存在，会自动创建
```

### 7.3.5 `io.write_vector` 的输出 stats

```json
{
  "path": "output/road_buffer.geojson",
  "format": "GeoJSON",
  "feature_count": 1250,
  "file_size_mb": 3.8
}
```

## 7.4 `io.read_raster`：读取栅格数据

### 7.4.1 参数说明

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| `path` | string | **是** | 栅格文件路径 |

### 7.4.2 支持的栅格格式

| 格式 | 扩展名 | 说明 |
|------|--------|------|
| GeoTIFF | `.tif`, `.tiff` | 最常用 |
| Cloud Optimized GeoTIFF | `.tif` (COG) | 云端优化 |
| ERDAS Imagine | `.img` | Esri 格式 |
| NetCDF | `.nc` | 科学数据 |
| HDF5 | `.h5`, `.hdf5` | 大型数据集 |
| VRT | `.vrt` | GDAL 虚拟栅格 |
| ENVI | `.hdr` | ENVI 格式 |
| ASCII Grid | `.asc` | 文本格式 |

### 7.4.3 基本用法

```yaml
pipeline:
  name: "栅格数据读取示例"
  steps:
    # 读取 DEM 数据
    - id: load-dem
      use: io.read_raster
      params:
        path: "data/dem_beijing.tif"

    # 读取遥感影像
    - id: load-imagery
      use: io.read_raster
      params:
        path: "data/sentinel2_rgb.tif"

    # 读取气候数据（NetCDF）
    - id: load-climate
      use: io.read_raster
      params:
        path: "data/temperature_2024.nc"
```

### 7.4.4 输出的 stats 字段

```json
{
  "width": 1024,
  "height": 1024,
  "band_count": 3,
  "crs": "EPSG:4326",
  "resolution": [0.0001, 0.0001],
  "bbox": [116.0, 39.5, 117.0, 40.5],
  "nodata": -9999.0,
  "dtype": "float32"
}
```

## 7.5 `io.write_raster`：写入栅格数据

### 7.5.1 参数说明

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| `input` | Raster | **是** | 输入栅格数据 |
| `path` | string | **是** | 输出文件路径 |

### 7.5.2 基本用法

```yaml
pipeline:
  name: "栅格数据处理示例"
  steps:
    - id: load-dem
      use: io.read_raster
      params:
        path: "data/dem_beijing.tif"

    - id: reproject-dem
      use: raster.reproject
      params:
        input: "$load-dem"
        target_crs: "EPSG:3857"

    # 保存处理后的栅格
    - id: save-dem
      use: io.write_raster
      params:
        input: "$reproject-dem"
        path: "output/dem_web_mercator.tif"
```

## 7.6 综合 IO 示例

### 示例一：矢量-栅格混合读取

```yaml
pipeline:
  name: "矢量栅格混合处理"
  description: "读取 DEM 栅格，用矢量边界裁剪，保存结果"

  variables:
    dem_path: "data/dem_china.tif"
    boundary_path: "data/beijing_boundary.geojson"
    output_path: "output/dem_beijing.tif"

  steps:
    # 读取 DEM
    - id: load-dem
      use: io.read_raster
      params:
        path: "${dem_path}"

    # 读取裁剪边界
    - id: load-boundary
      use: io.read_vector
      params:
        path: "${boundary_path}"

    # 投影对齐（矢量转为和栅格相同的 CRS）
    - id: reproject-boundary
      use: vector.reproject
      params:
        input: "$load-boundary"
        target_crs: "EPSG:4326"

    # 用矢量边界裁剪栅格
    - id: clip-dem
      use: raster.clip
      params:
        input: "$load-dem"
        mask: "$reproject-boundary"

    # 保存裁剪后的 DEM
    - id: save-dem
      use: io.write_raster
      params:
        input: "$clip-dem"
        path: "${output_path}"

  outputs:
    dem_stats: "$clip-dem.stats"
    result: "$save-dem"
```

### 示例二：多格式输出

```yaml
pipeline:
  name: "多格式输出示例"
  description: "将处理结果同时输出为多种格式"

  steps:
    - id: load
      use: io.read_vector
      params:
        path: "data/roads.geojson"

    - id: process
      use: vector.buffer
      params:
        input: "$load"
        distance: 100

    # 输出 GeoJSON（Web 使用）
    - id: save-geojson
      use: io.write_vector
      params:
        input: "$process"
        path: "output/result.geojson"
        format: "GeoJSON"

    # 输出 GeoPackage（桌面 GIS 使用）
    - id: save-gpkg
      use: io.write_vector
      params:
        input: "$process"
        path: "output/result.gpkg"
        format: "GPKG"

    # 输出 Shapefile（传统系统兼容）
    - id: save-shp
      use: io.write_vector
      params:
        input: "$process"
        path: "output/result.shp"
        format: "ESRI Shapefile"

  outputs:
    geojson_path: "$save-geojson"
    gpkg_path: "$save-gpkg"
    shp_path: "$save-shp"
```

### 示例三：批量读取与合并（使用变量参数化）

```yaml
pipeline:
  name: "批量数据处理"
  variables:
    # 通过 --var 覆盖这些路径
    input_path: "data/district_001.geojson"
    output_suffix: "district_001"

  steps:
    - id: load
      use: io.read_vector
      params:
        path: "${input_path}"

    - id: qc
      use: qc.geometry_validity
      params:
        input: "$load"

    - id: process
      use: vector.dissolve
      params:
        input: "$qc"
        by: "admin_code"

    - id: save
      use: io.write_vector
      params:
        input: "$process"
        path: "output/processed_${output_suffix}.geojson"
        format: "GeoJSON"
```

批量执行脚本：
```bash
#!/bin/bash
for i in 001 002 003 004 005; do
  geopipe-agent run pipeline.yaml \
    --var input_path="data/district_${i}.geojson" \
    --var output_suffix="district_${i}"
done
```

## 7.7 常见问题

### 问题一：文件路径中的中文

```yaml
# 路径中包含中文字符
params:
  path: "数据/道路数据.geojson"  # 可能在某些 OS 上出现问题
```

建议使用英文路径名，避免跨平台兼容性问题：
```yaml
params:
  path: "data/roads.geojson"   # 推荐
```

### 问题二：相对路径与工作目录

GeoPipeAgent 的相对路径基于**运行命令时的工作目录**（`cwd`），而非 YAML 文件所在目录：

```bash
# 在项目根目录运行
cd /path/to/project
geopipe-agent run pipelines/analysis.yaml
# data/roads.geojson → /path/to/project/data/roads.geojson ✓
```

```bash
# 在 pipelines/ 子目录运行（错误！）
cd /path/to/project/pipelines
geopipe-agent run analysis.yaml
# data/roads.geojson → /path/to/project/pipelines/data/roads.geojson ✗
```

**最佳实践**：始终从项目根目录运行命令。

### 问题三：GeoPackage 多图层

```yaml
# 错误：GeoPackage 有多个图层，必须指定
- id: load-gpkg
  use: io.read_vector
  params:
    path: "data/city.gpkg"
    # 不指定 layer → 读取第一个图层（可能不是想要的）
```

```yaml
# 正确：明确指定图层
- id: load-roads
  use: io.read_vector
  params:
    path: "data/city.gpkg"
    layer: "roads"           # 指定图层名

- id: load-buildings
  use: io.read_vector
  params:
    path: "data/city.gpkg"
    layer: "buildings"       # 同一文件，不同图层
```

## 7.8 本章小结

本章介绍了 GeoPipeAgent 的 4 个 IO 步骤：

1. **`io.read_vector`**：支持 GeoJSON、Shapefile、GeoPackage 等格式，可读取远程 URL
2. **`io.write_vector`**：支持多种输出格式，自动创建输出目录
3. **`io.read_raster`**：支持 GeoTIFF、NetCDF 等栅格格式
4. **`io.write_raster`**：保存处理后的栅格数据

IO 步骤是所有流水线的入口和出口，理解其支持的格式和参数是构建有效流水线的基础。
