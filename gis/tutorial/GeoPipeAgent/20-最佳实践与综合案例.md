## 20.2 流水线设计最佳实践

### 20.2.1 命名规范

**流水线名称**：使用描述性名称，包含数据类型和操作类型：
```yaml
# ✓ 好的命名
name: "北京市道路缓冲区服务范围分析 v2.0"
name: "城市绿地覆盖率 QC 与统计分析"

# ✗ 不好的命名
name: "分析"
name: "test"
name: "pipeline1"
```

**步骤 ID**：动词-名词格式，清晰描述操作：
```yaml
# ✓ 好的步骤 ID
id: load-roads
id: filter-primary-roads
id: reproject-to-utm
id: buffer-analysis
id: clip-to-boundary
id: save-result

# ✗ 不好的步骤 ID
id: step1
id: s
id: load
id: tmp
```

**变量名**：使用 snake_case，名称描述用途而非值：
```yaml
# ✓ 好的变量名
variables:
  input_roads_path: "data/roads.geojson"
  analysis_crs: "EPSG:3857"
  buffer_distance_m: 500
  output_format: "GeoJSON"

# ✗ 不好的变量名
variables:
  p: "data/roads.geojson"
  c: "EPSG:3857"
  n: 500
```

### 20.2.2 流水线结构规范

**标准流水线模板**：

```yaml
pipeline:
  name: "[数据类型] [操作类型] 分析"
  description: |
    详细说明这个流水线做什么，
    为什么这样设计，
    以及输出结果的用途。
  crs: "EPSG:4326"

  variables:
    # === 输入/输出路径 ===
    input_path: "data/input.geojson"
    output_dir: "output/"

    # === 分析参数 ===
    analysis_crs: "EPSG:3857"   # 米制坐标系用于距离计算

    # === 功能开关 ===
    run_qc: true
    save_intermediate: false

  steps:
    # ─── 第一阶段：数据加载 ─────────────────────
    - id: load-input
      use: io.read_vector
      on_error: fail          # 核心数据加载失败则停止
      params:
        path: "${input_path}"

    # ─── 第二阶段：数据质检 ─────────────────────
    - id: qc-geometry
      use: qc.geometry_validity
      when: "${run_qc}"        # 可按需跳过质检
      params:
        input: "$load-input"

    # ─── 第三阶段：数据预处理 ───────────────────
    - id: reproject
      use: vector.reproject
      params:
        input: "$qc-geometry"
        target_crs: "${analysis_crs}"

    # ─── 第四阶段：核心分析 ─────────────────────
    - id: analysis-step
      use: vector.buffer
      params:
        input: "$reproject"
        distance: 500

    # ─── 第五阶段：结果输出 ─────────────────────
    - id: reproject-back
      use: vector.reproject
      params:
        input: "$analysis-step"
        target_crs: "EPSG:4326"

    - id: save-result
      use: io.write_vector
      on_error: retry          # 文件写入失败重试
      params:
        input: "$reproject-back"
        path: "${output_dir}result.geojson"
        format: "GeoJSON"

  outputs:
    result: "$save-result"
    statistics: "$analysis-step.stats"
    qc_issues: "$qc-geometry.issues"
```

### 20.2.3 错误处理策略

```yaml
# 策略分级原则：
# - 数据加载（必须成功）：on_error: fail（默认）
# - 可选增强（允许跳过）：on_error: skip
# - 网络/文件写入（可重试）：on_error: retry
# - AI 服务调用（可重试+跳过）：on_error: retry（失败后等于skip）

steps:
  # 核心数据：fail（默认）
  - id: load-required-data
    use: io.read_vector
    params:
      path: "data/required.geojson"

  # 可选补充数据：skip
  - id: load-optional-data
    use: io.read_vector
    on_error: skip
    params:
      path: "data/optional.geojson"

  # 网络 API：retry
  - id: fetch-online-data
    use: io.read_vector
    on_error: retry
    params:
      path: "https://api.example.com/data.geojson"

  # 结果保存：retry
  - id: save-to-shared-storage
    use: io.write_vector
    on_error: retry
    params:
      input: "$process"
      path: "/mnt/shared/result.geojson"
      format: "GeoJSON"
```

### 20.2.4 变量参数化

将所有可能变化的值提取为变量，使流水线可以重用于不同数据集：

```bash
# 同一个流水线处理不同城市
geopipe-agent run city_analysis.yaml --var city=beijing --var year=2024
geopipe-agent run city_analysis.yaml --var city=shanghai --var year=2024
geopipe-agent run city_analysis.yaml --var city=guangzhou --var year=2024
```

## 20.3 综合案例一：城市绿地覆盖率分析

### 案例背景
分析城市各行政区的绿地覆盖情况：读取绿地和行政区数据，质检后做叠加分析，计算各区绿地面积和覆盖率。

```yaml
pipeline:
  name: "城市绿地覆盖率分析"
  description: |
    分析城市各行政区的绿地覆盖情况：
    1. 读取绿地（面）和行政区（面）数据
    2. 进行数据质检
    3. 叠加分析计算各区绿地面积
    4. 统计覆盖率并保存结果
  crs: "EPSG:4326"

  variables:
    # 输入数据
    greenland_path: "data/greenland.geojson"
    districts_path: "data/districts.geojson"

    # 分析配置
    analysis_crs: "EPSG:3857"

    # 输出路径
    output_dir: "output/greenland_coverage/"

    # 功能开关
    run_qc: true

  steps:
    # ═══ 第一阶段：数据加载 ═══════════════════
    - id: load-greenland
      use: io.read_vector
      on_error: fail
      params:
        path: "${greenland_path}"

    - id: load-districts
      use: io.read_vector
      on_error: fail
      params:
        path: "${districts_path}"

    # ═══ 第二阶段：数据质检 ═══════════════════
    - id: qc-greenland-geometry
      use: qc.geometry_validity
      when: "${run_qc}"
      params:
        input: "$load-greenland"

    - id: qc-districts-geometry
      use: qc.geometry_validity
      when: "${run_qc}"
      params:
        input: "$load-districts"

    - id: qc-greenland-crs
      use: qc.crs_check
      when: "${run_qc}"
      params:
        input: "$qc-greenland-geometry"
        expected_crs: "EPSG:4326"

    - id: qc-districts-crs
      use: qc.crs_check
      when: "${run_qc}"
      params:
        input: "$qc-districts-geometry"
        expected_crs: "EPSG:4326"

    # ═══ 第三阶段：数据预处理 ════════════════
    - id: reproject-greenland
      use: vector.reproject
      params:
        input: "$qc-greenland-crs"
        target_crs: "${analysis_crs}"

    - id: reproject-districts
      use: vector.reproject
      params:
        input: "$qc-districts-crs"
        target_crs: "${analysis_crs}"

    # 修复无效几何（如有）
    # 注意：需要一个修复几何的自定义步骤，这里用 simplify 近似
    - id: fix-greenland
      use: vector.simplify
      params:
        input: "$reproject-greenland"
        tolerance: 0.001
        preserve_topology: true

    # ═══ 第四阶段：叠加分析 ══════════════════
    # 交集：各行政区内的绿地
    - id: greenland-in-districts
      use: vector.overlay
      params:
        input: "$fix-greenland"
        overlay: "$reproject-districts"
        how: "intersection"

    # 按行政区融合计算各区总绿地面积
    - id: greenland-by-district
      use: vector.dissolve
      params:
        input: "$greenland-in-districts"
        by: "district_code"           # 行政区代码字段
        aggfunc:
          greenland_area: "sum"        # 各区绿地面积求和
          parcel_count: "count"        # 绿地斑块数量

    # ═══ 第五阶段：统计分析 ══════════════════
    # 行政区面积统计（融合同一行政区的所有记录）
    - id: district-total-area
      use: vector.dissolve
      params:
        input: "$reproject-districts"
        by: "district_code"
        aggfunc:
          district_area: "sum"

    # ═══ 第六阶段：转回 WGS84 并保存 ════════
    - id: result-wgs84
      use: vector.reproject
      params:
        input: "$greenland-by-district"
        target_crs: "EPSG:4326"

    - id: save-coverage
      use: io.write_vector
      on_error: retry
      params:
        input: "$result-wgs84"
        path: "${output_dir}greenland_by_district.geojson"
        format: "GeoJSON"

    - id: save-greenland-clipped
      use: io.write_vector
      on_error: retry
      params:
        input: "$greenland-in-districts"
        path: "${output_dir}greenland_clipped.geojson"
        format: "GeoJSON"

  outputs:
    coverage_result: "$save-coverage"
    clipped_greenland: "$save-greenland-clipped"
    greenland_qc_issues: "$qc-greenland-geometry.issues"
    districts_qc_issues: "$qc-districts-geometry.issues"
    greenland_count: "$load-greenland.stats.feature_count"
    district_count: "$load-districts.stats.feature_count"
    analysis_stats: "$greenland-by-district.stats"
```

## 20.4 综合案例二：多城市批量数据处理

### 案例背景
对多个城市的道路数据进行标准化批量处理：质检 → 过滤 → 投影 → 缓冲区 → 保存，通过变量参数化支持批量运行。

```yaml
# city_road_analysis.yaml
pipeline:
  name: "城市道路标准化处理 - ${city_name}"
  description: |
    对 ${city_name} 的道路数据进行标准化处理：
    - 几何质检
    - 筛选主次干道
    - 投影到米制坐标系
    - 生成 500 米服务缓冲区
    - 保存 GeoJSON 格式
  crs: "EPSG:4326"

  variables:
    # === 城市配置（通过 --var 覆盖）===
    city_name: "北京"
    city_code: "110000"
    input_path: "data/beijing/roads.geojson"
    output_dir: "output/beijing/"

    # === 分析参数 ===
    filter_condition: "road_class in ['primary', 'secondary']"
    buffer_distance: 500
    analysis_crs: "EPSG:3857"

    # === 功能开关 ===
    run_qc: true
    save_intermediate: false

  steps:
    # 数据加载
    - id: load-roads
      use: io.read_vector
      on_error: fail
      params:
        path: "${input_path}"

    # 质检
    - id: qc-geometry
      use: qc.geometry_validity
      when: "${run_qc}"
      params:
        input: "$load-roads"

    - id: qc-attributes
      use: qc.attribute_completeness
      when: "${run_qc}"
      params:
        input: "$qc-geometry"
        required_fields:
          - "road_id"
          - "road_class"
          - "road_name"

    # 过滤
    - id: filter-roads
      use: vector.query
      params:
        input: "$qc-attributes"
        expression: "${filter_condition}"

    # 中间结果（可选保存）
    - id: save-filtered
      use: io.write_vector
      when: "${save_intermediate}"
      on_error: skip
      params:
        input: "$filter-roads"
        path: "${output_dir}filtered_roads.geojson"
        format: "GeoJSON"

    # 投影到米制
    - id: reproject
      use: vector.reproject
      params:
        input: "$filter-roads"
        target_crs: "${analysis_crs}"

    # 缓冲区分析
    - id: buffer
      use: vector.buffer
      params:
        input: "$reproject"
        distance: "${buffer_distance}"
        cap_style: "round"

    # 融合缓冲区
    - id: dissolve-buffer
      use: vector.dissolve
      params:
        input: "$buffer"

    # 转回 WGS84
    - id: reproject-back
      use: vector.reproject
      params:
        input: "$dissolve-buffer"
        target_crs: "EPSG:4326"

    # 保存最终结果
    - id: save-result
      use: io.write_vector
      on_error: retry
      params:
        input: "$reproject-back"
        path: "${output_dir}road_service_area_${buffer_distance}m.geojson"
        format: "GeoJSON"

  outputs:
    input_count: "$load-roads.stats.feature_count"
    filtered_count: "$filter-roads.stats.feature_count"
    buffer_area: "$dissolve-buffer.stats.total_area"
    qc_issues: "$qc-attributes.issues"
    result: "$save-result"
```

### 批量运行脚本

```bash
#!/bin/bash
# batch_city_analysis.sh

declare -A CITIES=(
  ["北京"]="110000:data/beijing/roads.geojson:output/beijing/"
  ["上海"]="310000:data/shanghai/roads.geojson:output/shanghai/"
  ["广州"]="440100:data/guangzhou/roads.geojson:output/guangzhou/"
  ["深圳"]="440300:data/shenzhen/roads.geojson:output/shenzhen/"
)

SUCCESS=0
FAILED=0

for city in "${!CITIES[@]}"; do
  IFS=':' read -r code input_path output_dir <<< "${CITIES[$city]}"

  echo "======================================"
  echo "处理城市: $city ($code)"
  echo "======================================"

  # 创建输出目录
  mkdir -p "$output_dir"

  # 运行流水线
  geopipe-agent run city_road_analysis.yaml \
    --var city_name="$city" \
    --var city_code="$code" \
    --var input_path="$input_path" \
    --var output_dir="$output_dir" \
    --var buffer_distance=500 \
    --log-level INFO \
    --output "${output_dir}report.json" \
    2>&1 | tee "${output_dir}run.log"

  if [ $? -eq 0 ]; then
    echo "✓ $city 处理成功"
    ((SUCCESS++))
  else
    echo "✗ $city 处理失败！查看日志: ${output_dir}run.log"
    ((FAILED++))
  fi
done

echo ""
echo "======================================"
echo "批量处理完成"
echo "成功: $SUCCESS / $((SUCCESS + FAILED))"
echo "失败: $FAILED / $((SUCCESS + FAILED))"
```

## 20.5 综合案例三：AI 驱动的自适应分析

### 案例背景
通过 AI 生成流水线，结合条件执行实现自适应处理：根据数据特征动态决定处理策略。

```yaml
# adaptive_analysis.yaml
pipeline:
  name: "自适应 GIS 数据分析"
  description: |
    自适应数据处理流水线：
    - 数据量小（<1000条）：做详细分析（热力图+聚类）
    - 数据量大（>=1000条）：先简化，再做基础分析
    - 质检发现问题：保存质检报告，跳过分析
  crs: "EPSG:4326"

  variables:
    input_path: "data/pois.geojson"
    large_dataset_threshold: 1000
    enable_advanced_analysis: true

  steps:
    # 加载数据
    - id: load
      use: io.read_vector
      params:
        path: "${input_path}"

    # 质检
    - id: qc-geometry
      use: qc.geometry_validity
      params:
        input: "$load"

    - id: qc-attributes
      use: qc.attribute_completeness
      params:
        input: "$qc-geometry"
        required_fields: ["poi_id", "category", "name"]

    # 质检失败：保存问题报告，停止后续分析
    - id: save-qc-report
      use: io.write_vector
      when: "len($qc-attributes.issues) > 0"
      on_error: skip
      params:
        input: "$qc-attributes"
        path: "output/qc_failed_report.geojson"
        format: "GeoJSON"

    # 大数据集：先简化（降采样）
    - id: simplify-large
      use: vector.simplify
      when: "$load.stats.feature_count >= ${large_dataset_threshold} and len($qc-attributes.issues) == 0"
      params:
        input: "$qc-attributes"
        tolerance: 0.0001

    # 小数据集：不做简化，直接分析
    # （不需要步骤，直接引用 $qc-attributes）

    # 投影到米制（两条分支汇合处理有点复杂，这里用 qc-attributes 作为公共输入点）
    - id: reproject
      use: vector.reproject
      when: "len($qc-attributes.issues) == 0"
      params:
        input: "$qc-attributes"
        target_crs: "EPSG:3857"

    # 基础分析：缓冲区（所有规模数据都做）
    - id: buffer
      use: vector.buffer
      when: "len($qc-attributes.issues) == 0"
      params:
        input: "$reproject"
        distance: 200

    # 高级分析：聚类（所有规模+启用时）
    - id: cluster
      use: analysis.cluster
      when: "len($qc-attributes.issues) == 0 and ${enable_advanced_analysis}"
      on_error: skip    # analysis 依赖可能未安装
      params:
        input: "$reproject"
        algorithm: "dbscan"
        eps: 300
        min_samples: 5

    # 高级分析：热力图（小数据集+启用时）
    - id: heatmap
      use: analysis.heatmap
      when: "$load.stats.feature_count < ${large_dataset_threshold} and ${enable_advanced_analysis} and len($qc-attributes.issues) == 0"
      on_error: skip
      params:
        input: "$reproject"
        bandwidth: 500
        resolution: 50

    # 保存结果
    - id: save-buffer
      use: io.write_vector
      when: "len($qc-attributes.issues) == 0"
      on_error: retry
      params:
        input: "$buffer"
        path: "output/poi_buffer_200m.geojson"
        format: "GeoJSON"

    - id: save-clusters
      use: io.write_vector
      when: "len($qc-attributes.issues) == 0 and ${enable_advanced_analysis}"
      on_error: skip
      params:
        input: "$cluster"
        path: "output/poi_clusters.geojson"
        format: "GeoJSON"

    - id: save-heatmap
      use: io.write_raster
      when: "$load.stats.feature_count < ${large_dataset_threshold} and ${enable_advanced_analysis} and len($qc-attributes.issues) == 0"
      on_error: skip
      params:
        input: "$heatmap"
        path: "output/poi_heatmap.tif"

  outputs:
    input_count: "$load.stats.feature_count"
    qc_issues: "$qc-attributes.issues"
    buffer_result: "$save-buffer"
    cluster_result: "$save-clusters"
    heatmap_result: "$save-heatmap"
```

## 20.6 性能优化建议

### 20.6.1 大数据集处理

```yaml
steps:
  # 先过滤再分析（减少数据量）
  - id: filter-first
    use: vector.query
    params:
      input: "$load"
      expression: "active == 1"    # 先过滤无效数据

  # 大文件使用 GDAL 后端
  - id: reproject-large
    use: vector.reproject
    backend: gdal_cli              # GDAL 内存管理更好
    params:
      input: "$filter-first"
      target_crs: "EPSG:3857"

  # 简化后再做叠加分析
  - id: simplify-before-overlay
    use: vector.simplify
    when: "$load.stats.feature_count > 10000"
    params:
      input: "$reproject-large"
      tolerance: 1                 # 1 米容差（米制坐标）
```

### 20.6.2 避免重复读取

```yaml
# ✓ 好：一次读取，多次引用
- id: load
  use: io.read_vector
  params:
    path: "large_dataset.geojson"

- id: filter1
  use: vector.query
  params:
    input: "$load"               # 引用同一个加载结果
    expression: "type == 'A'"

- id: filter2
  use: vector.query
  params:
    input: "$load"               # 再次引用，不重新读文件
    expression: "type == 'B'"
```

## 20.7 安全最佳实践

### 20.7.1 保护敏感信息

```bash
# ✓ 通过环境变量传入 API Key
export OPENAI_API_KEY="sk-..."
geopipe-agent run pipeline.yaml --var api_key=$OPENAI_API_KEY

# ✓ 通过 .env 文件（不加入版本控制）
# .env
API_KEY=sk-...
DB_PASSWORD=secret123

# ✗ 不要在 YAML 中硬编码密钥
variables:
  api_key: "sk-..."    # 危险！会被提交到版本库
```

```bash
# .gitignore 中排除包含敏感信息的文件

# 对流水线 YAML 进行版本控制
```

### 20.8.3 保存中间结果

```yaml
variables:
  debug: false

steps:
  - id: reproject
    use: vector.reproject
    params:
      input: "$load"
      target_crs: "EPSG:3857"

  # 调试时保存中间结果
  - id: debug-save-reproject
    use: io.write_vector
    when: "${debug}"
    on_error: skip
    params:
      input: "$reproject"
      path: "debug/reproject.geojson"
      format: "GeoJSON"
```

```bash
# 调试运行
geopipe-agent run pipeline.yaml --var debug=true

# 正式运行
geopipe-agent run pipeline.yaml --var debug=false
```
