# 第十五章：数据模型与错误体系

## 15.1 概述

GeoPipeAgent 使用明确的 Python 数据类（dataclass）定义内部数据结构，并建立了层次化的错误体系。理解这些数据模型对于开发自定义步骤和处理错误至关重要。

---

## 15.2 核心数据模型

### 15.2.1 `PipelineDefinition`：流水线定义

对应 YAML 文件中 `pipeline:` 块的 Python 表示：

```python
from dataclasses import dataclass, field

@dataclass
class PipelineDefinition:
    # 必填字段
    name: str
    steps: list["StepDefinition"]

    # 可选字段（有默认值）
    description: str = ""
    crs: str | None = None
    variables: dict = field(default_factory=dict)
    outputs: dict = field(default_factory=dict)
```

**字段说明**：

| 字段 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `name` | str | 必填 | 流水线名称 |
| `steps` | list[StepDefinition] | 必填 | 步骤列表 |
| `description` | str | `""` | 流水线描述 |
| `crs` | str \| None | `None` | 默认 CRS |
| `variables` | dict | `{}` | 变量定义 |
| `outputs` | dict | `{}` | 输出声明 |

### 15.2.2 `StepDefinition`：步骤定义

对应 YAML 中每个步骤块的 Python 表示：

```python
@dataclass
class StepDefinition:
    # 必填字段
    id: str
    use: str

    # 可选字段
    params: dict = field(default_factory=dict)
    when: str | None = None
    on_error: str = "fail"       # "fail" | "skip" | "retry"
    backend: str | None = None   # None 表示使用默认后端
```

**字段说明**：

| 字段 | 类型 | 默认值 | 约束 |
|------|------|--------|------|
| `id` | str | 必填 | 匹配 `[a-z0-9_-]`，全局唯一 |
| `use` | str | 必填 | 格式 `category.action` |
| `params` | dict | `{}` | 任意键值对 |
| `when` | str \| None | `None` | 布尔表达式字符串 |
| `on_error` | str | `"fail"` | `fail` / `skip` / `retry` |
| `backend` | str \| None | `None` | 后端名称，`None` 使用默认 |

### 15.2.3 `StepResult`：步骤结果

每个步骤执行后返回的结果对象：

```python
@dataclass
class StepResult:
    # 主要输出
    output: Any = None          # 步骤的主要输出（GeoDataFrame、Raster 等）

    # 统计信息
    stats: dict = field(default_factory=dict)

    # 元数据
    metadata: dict = field(default_factory=dict)

    # QC 问题（仅 QC 步骤使用）
    issues: list["QcIssue"] = field(default_factory=list)
```

**字段说明**：

| 字段 | 类型 | 说明 |
|------|------|------|
| `output` | Any | 主输出，被 `$step-id` 或 `$step-id.output` 引用 |
| `stats` | dict | 统计信息，被 `$step-id.stats` 引用 |
| `metadata` | dict | 元数据（执行时间、后端等） |
| `issues` | list[QcIssue] | QC 问题，被 `$step-id.issues` 引用 |

**stats 字段的动态访问**：

```yaml
# 访问 stats 中的任意键
outputs:
  count: "$load.stats.feature_count"
  crs: "$load.stats.crs"
  area: "$buffer.stats.total_area"
```

这是通过 `StepResult` 的 `__getattr__` 实现的：

```python
def __getattr__(self, name: str):
    # 支持 result.feature_count → result.stats["feature_count"]
    if name in self.stats:
        return self.stats[name]
    raise AttributeError(f"StepResult 没有属性 '{name}'")
```

### 15.2.4 `QcIssue`：质检问题

QC 步骤发现的质量问题：

```python
@dataclass
class QcIssue:
    type: str             # 问题类型
    severity: str         # "error" | "warning" | "info"
    message: str          # 人类可读的问题描述

    # 可选的定位信息
    feature_id: Any = None    # 涉及的要素 ID
    field: str | None = None  # 涉及的字段名
    value: Any = None         # 问题值
```

**severity 级别**：

| 级别 | 含义 | 示例 |
|------|------|------|
| `error` | 严重问题，数据可能不可用 | 几何无效、必填字段缺失 |
| `warning` | 潜在问题，需要人工确认 | 数值超出常见范围 |
| `info` | 信息性提示，不影响使用 | CRS 不是推荐标准 |

## 15.3 错误体系

GeoPipeAgent 定义了一套层次化的错误类，继承自统一的基类 `GeopipeAgentError`。

### 15.3.1 错误类层次结构

```
GeopipeAgentError（基类）
├── PipelineParseError          # YAML 解析错误
├── PipelineValidationError     # 流水线校验错误
├── StepExecutionError          # 步骤执行错误
│   └── （包含 step_id, suggestion, cause）
├── BackendNotAvailableError    # 后端不可用
├── StepNotFoundError           # 步骤未注册
└── VariableResolutionError     # 变量解析失败
```

### 15.3.2 `GeopipeAgentError`：基类

```python
class GeopipeAgentError(Exception):
    """GeoPipeAgent 所有错误的基类"""

    def __init__(self, message: str):
        super().__init__(message)
        self.message = message

    def to_dict(self) -> dict:
        return {
            "type": self.__class__.__name__,
            "message": self.message
        }
```

**使用场景**：捕获所有 GeoPipeAgent 相关错误：

```python
try:
    run_pipeline("pipeline.yaml")
except GeopipeAgentError as e:
    print(f"流水线错误: {e.message}")
    print(f"错误类型: {type(e).__name__}")
```

### 15.3.3 `PipelineParseError`：解析错误

在 `parser.py` 中触发，表示 YAML 文件格式不正确：

```python
class PipelineParseError(GeopipeAgentError):
    """YAML 流水线文件解析失败"""
    pass
```

**常见触发情形**：
- 缺少 `pipeline:` 顶层键
- YAML 语法错误
- 必填字段缺失（`name`、`id`、`use`）
- `on_error` 值不合法

```python
# 捕获示例
try:
    pipeline = parse_pipeline("broken.yaml")
except PipelineParseError as e:
    print(f"YAML 格式错误: {e.message}")
```

### 15.3.4 `PipelineValidationError`：校验错误

在 `validator.py` 中触发，表示流水线逻辑不合法：

```python
class PipelineValidationError(GeopipeAgentError):
    """流水线校验失败，可包含多个错误"""

    def __init__(self, errors: list[str]):
        message = f"流水线校验失败，发现 {len(errors)} 个错误:\n" + \
                  "\n".join(f"  - {e}" for e in errors)
        super().__init__(message)
        self.errors = errors  # 所有错误的列表
```

**常见触发情形**：
- 重复的步骤 ID
- 步骤 ID 格式错误
- 引用不存在的步骤
- 前向引用
- 循环引用

```python
try:
    validate_pipeline(pipeline)
except PipelineValidationError as e:
    for error in e.errors:
        print(f"校验错误: {error}")
```

### 15.3.5 `StepExecutionError`：步骤执行错误

在 `executor.py` 中触发，表示步骤执行过程中发生了错误：

```python
class StepExecutionError(GeopipeAgentError):
    """步骤执行失败，包含详细的诊断信息"""

    def __init__(self,
                 step_id: str,
                 message: str,
                 suggestion: str = "",
                 cause: Exception = None):
        super().__init__(message)
        self.step_id = step_id          # 失败的步骤 ID
        self.suggestion = suggestion    # 修复建议（AI 友好）
        self.cause = cause              # 原始异常

    def to_dict(self) -> dict:
        return {
            "type": "StepExecutionError",
            "step_id": self.step_id,
            "message": self.message,
            "suggestion": self.suggestion,
            "cause": type(self.cause).__name__ if self.cause else None
        }
```

**`suggestion` 字段**：这是 GeoPipeAgent 的一个重要设计——步骤在抛出错误时会提供修复建议，帮助用户（和 AI）快速定位问题原因：

```json
{
  "type": "StepExecutionError",
  "step_id": "load-roads",
  "message": "文件不存在: data/roads.geojson",
  "suggestion": "请检查文件路径是否正确。当前工作目录为 /home/user/project。如果文件在子目录中，请确保路径包含完整的相对路径。",
  "cause": "FileNotFoundError"
}
```

### 15.3.6 `BackendNotAvailableError`：后端不可用

```python
class BackendNotAvailableError(GeopipeAgentError):
    """指定的后端不可用（未安装或配置错误）"""

    def __init__(self, backend_name: str, reason: str = ""):
        message = f"后端 '{backend_name}' 不可用"
        if reason:
            message += f": {reason}"
        super().__init__(message)
        self.backend_name = backend_name
```

### 15.3.7 `StepNotFoundError`：步骤未注册

```python
class StepNotFoundError(GeopipeAgentError):
    """指定的步骤 ID 未在注册表中找到"""

    def __init__(self, step_use: str):
        message = f"步骤 '{step_use}' 未找到"
        suggestion = _get_suggestion_for_step(step_use)
        super().__init__(f"{message}。{suggestion}")
        self.step_use = step_use
```

常见原因：
- 步骤类型（`use`）拼写错误
- 相关可选依赖未安装（如 `analysis.*` 需要 `pip install -e ".[analysis]"`）

### 15.3.8 `VariableResolutionError`：变量解析失败

```python
class VariableResolutionError(GeopipeAgentError):
    """变量或步骤引用解析失败"""

    def __init__(self, variable_name: str, context: str = ""):
        message = f"无法解析变量或引用 '{variable_name}'"
        if context:
            message += f"（上下文: {context}）"
        super().__init__(message)
        self.variable_name = variable_name
```

## 15.4 在 Python API 中使用数据模型

### 15.4.1 编程式构建流水线

```python
from geopipe_agent.models.pipeline import PipelineDefinition
from geopipe_agent.models.step import StepDefinition
from geopipe_agent.engine.executor import PipelineExecutor
from geopipe_agent.engine.reporter import Reporter

# 编程式构建流水线
pipeline = PipelineDefinition(
    name="编程式流水线",
    description="通过 Python API 构建的流水线",
    variables={
        "input_path": "data/roads.geojson",
        "buffer_dist": 500,
    },
    steps=[
        StepDefinition(
            id="load",
            use="io.read_vector",
            params={"path": "${input_path}"},
        ),
        StepDefinition(
            id="reproject",
            use="vector.reproject",
            params={"input": "$load", "target_crs": "EPSG:3857"},
        ),
        StepDefinition(
            id="buffer",
            use="vector.buffer",
            params={"input": "$reproject", "distance": "${buffer_dist}"},
        ),
        StepDefinition(
            id="save",
            use="io.write_vector",
            params={
                "input": "$buffer",
                "path": "output/result.geojson",
                "format": "GeoJSON"
            },
        ),
    ],
    outputs={"result": "$save"},
)

# 执行流水线
executor = PipelineExecutor()
result = executor.execute(pipeline)

# 生成报告
reporter = Reporter()
report = reporter.generate(pipeline, result)
print(report)
```

### 15.4.2 错误处理最佳实践

```python
from geopipe_agent.errors import (
    GeopipeAgentError,
    PipelineParseError,
    PipelineValidationError,
    StepExecutionError,
)

def run_pipeline_safe(yaml_path: str) -> dict:
    """安全执行流水线，处理所有可能的错误"""
    try:
        pipeline = parse_pipeline(yaml_path)
        validate_pipeline(pipeline)
        result = execute_pipeline(pipeline)
        return {"status": "success", "result": result}

    except PipelineParseError as e:
        # YAML 格式错误，不可恢复
        return {
            "status": "error",
            "error_type": "parse_error",
            "message": e.message,
            "suggestion": "请检查 YAML 格式，确保有 pipeline: 顶层键"
        }

    except PipelineValidationError as e:
        # 校验错误，返回所有错误列表
        return {
            "status": "error",
            "error_type": "validation_error",
            "errors": e.errors
        }

    except StepExecutionError as e:
        # 步骤执行错误，包含修复建议
        return {
            "status": "error",
            "error_type": "execution_error",
            "step_id": e.step_id,
            "message": e.message,
            "suggestion": e.suggestion
        }

    except GeopipeAgentError as e:
        # 其他框架错误
        return {
            "status": "error",
            "error_type": type(e).__name__,
            "message": e.message
        }
```

## 15.5 `StepResult` 的实际使用

### 在自定义步骤中构建 `StepResult`

```python
from geopipe_agent.models.result import StepResult
from geopipe_agent.models.qc import QcIssue

@step(id="custom.my_analysis", ...)
def my_analysis(ctx: StepContext) -> StepResult:
    gdf = ctx.param("input")

    # 执行分析
    result_gdf = perform_analysis(gdf)

    # 构建统计信息
    stats = {
        "feature_count": len(result_gdf),
        "total_area": result_gdf.geometry.area.sum(),
        "crs": str(result_gdf.crs),
    }

    # 收集 QC 问题（可选）
    issues = []
    if len(result_gdf) == 0:
        issues.append(QcIssue(
            type="empty_result",
            severity="warning",
            message="分析结果为空，请检查输入数据或参数"
        ))

    # 元数据
    metadata = {
        "algorithm": "my_algorithm_v2",
        "parameters": ctx._params,
    }

    return StepResult(
        output=result_gdf,
        stats=stats,
        issues=issues,
        metadata=metadata,
    )
```

## 15.6 数据类型约定

不同步骤的 `output` 字段类型：

| 步骤类别 | `output` 类型 |
|----------|---------------|
| `io.read_vector` | `geopandas.GeoDataFrame` |
| `io.write_vector` | `str`（输出文件路径） |
| `io.read_raster` | `rasterio.DatasetReader` 或自定义 Raster 对象 |
| `io.write_raster` | `str`（输出文件路径） |
| `vector.*` | `geopandas.GeoDataFrame` |
| `raster.*` | Raster 对象（rasterio 格式） |
| `analysis.*` | 取决于步骤（矢量或栅格） |
| `network.*` | `geopandas.GeoDataFrame`（路径/服务区）或坐标 |
| `qc.*` | 与输入相同（透传） |

## 15.7 本章小结

本章介绍了 GeoPipeAgent 的数据模型和错误体系：

**核心数据模型**：
1. `PipelineDefinition`：流水线定义（name, steps, variables, outputs 等）
2. `StepDefinition`：步骤定义（id, use, params, when, on_error, backend）
3. `StepResult`：步骤结果（output, stats, issues, metadata）
4. `QcIssue`：质检问题（type, severity, message, feature_id 等）

**错误层次体系**：
- `GeopipeAgentError`（基类）
- `PipelineParseError`：YAML 解析失败
- `PipelineValidationError`：逻辑校验失败，包含错误列表
- `StepExecutionError`：步骤执行失败，包含 suggestion 修复建议
- `BackendNotAvailableError`：后端不可用
- `StepNotFoundError`：步骤未注册
- `VariableResolutionError`：变量/引用解析失败

理解这些数据模型是开发自定义步骤和正确处理错误的基础。
