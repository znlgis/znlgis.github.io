# 第6章：条件执行与错误处理策略

在实际的地理数据处理流水线中，我们常常需要根据上一步的结果或外部条件来决定是否执行某个步骤，同时也需要优雅地处理运行过程中可能出现的各种错误。GeoPipeAgent 提供了完善的条件执行机制和多层次的错误处理策略，让流水线既灵活又健壮。

本章将深入讲解 `when` 条件表达式、AST 安全求值机制、`on_error` 错误策略、异常层级体系以及 AI 友好的错误消息系统。

## 6.1 条件执行（when 字段）

### 6.1.1 基本概念

GeoPipeAgent 的每个步骤（step）都可以通过 `when` 字段指定一个条件表达式。只有当该表达式求值为 `True` 时，该步骤才会被执行；否则将被跳过。

```yaml
steps:
  - id: reproject_step
    step: vector.reproject
    params:
      input: ${read_step.output}
      target_crs: "EPSG:4326"
    when: "${read_step.stats.crs} != 'EPSG:4326'"
```

在上面的示例中，`reproject_step` 仅在读入数据的 CRS 不是 `EPSG:4326` 时才执行。如果数据已经是 WGS84 坐标系，则该步骤自动跳过，节省处理时间。

### 6.1.2 when 表达式语法

`when` 字段接受一个字符串表达式，该表达式会在运行时被求值。表达式中可以包含：

| 元素类型 | 说明 | 示例 |
|---------|------|------|
| 变量引用 | 引用前序步骤的输出或统计信息 | `${read_step.stats.feature_count}` |
| 管道变量 | 引用 `vars` 中定义的变量 | `${vars.threshold}` |
| 字符串字面量 | 用单引号或双引号括起来的文本 | `'EPSG:4326'`、`"Shapefile"` |
| 数值字面量 | 整数或浮点数 | `100`、`3.14` |
| 布尔字面量 | 布尔值 | `True`、`False` |
| 比较运算符 | 各种比较操作 | `==`、`!=`、`<`、`>`、`<=`、`>=` |
| 逻辑运算符 | 布尔逻辑组合 | `and`、`or`、`not` |

#### 完整语法示例：

```yaml
# 简单比较
when: "${read_step.stats.feature_count} > 0"

# 字符串相等比较
when: "${read_step.stats.crs} == 'EPSG:4326'"

# 字符串不等比较
when: "${read_step.stats.crs} != 'EPSG:4326'"

# 数值范围比较
when: "${read_step.stats.feature_count} >= 100"

# 布尔值判断
when: "${vars.enable_qc} == True"

# 组合条件（and）
when: "${read_step.stats.feature_count} > 0 and ${read_step.stats.crs} != 'EPSG:4326'"

# 组合条件（or）
when: "${vars.force_reproject} == True or ${read_step.stats.crs} != 'EPSG:4326'"

# 取反条件（not）
when: "not ${vars.skip_validation}"

# 复杂嵌套条件
when: "(${read_step.stats.feature_count} > 100 and ${vars.enable_simplify} == True) or ${vars.force_simplify} == True"
```

### 6.1.3 比较运算符详解

GeoPipeAgent 支持以下比较运算符：

| 运算符 | 含义 | 示例 | 说明 |
|--------|------|------|------|
| `==` | 等于 | `${a} == 100` | 判断值是否相等 |
| `!=` | 不等于 | `${a} != 'EPSG:4326'` | 判断值是否不相等 |
| `<` | 小于 | `${a} < 50` | 数值小于比较 |
| `>` | 大于 | `${a} > 100` | 数值大于比较 |
| `<=` | 小于等于 | `${a} <= 1000` | 数值小于等于比较 |
| `>=` | 大于等于 | `${a} >= 0` | 数值大于等于比较 |

**类型自动转换规则：**

- 如果变量值是字符串形式的数字（如 `"100"`），与数值字面量比较时会自动转换为数值类型
- 字符串比较使用 Python 的字符串比较语义
- 布尔值 `True`/`False` 直接使用 Python 语义

```yaml
# 数值比较 - 自动类型转换
when: "${read_step.stats.feature_count} > 100"
# 如果 feature_count 是整数 200，则 200 > 100 → True

# 字符串比较 - 精确匹配
when: "${read_step.stats.crs} == 'EPSG:4326'"
# 如果 crs 是字符串 "EPSG:4326"，则相等 → True

# 布尔比较
when: "${vars.enable_qc} == True"
# 如果 enable_qc 是布尔值 True，则相等 → True
```

### 6.1.4 布尔逻辑运算

GeoPipeAgent 支持三种布尔逻辑运算符：

#### `and` 运算符

两个条件都为 `True` 时，整体结果为 `True`。

```yaml
when: "${read_step.stats.feature_count} > 0 and ${read_step.stats.feature_count} < 10000"
```

#### `or` 运算符

两个条件中任一为 `True`，整体结果为 `True`。

```yaml
when: "${vars.force_process} == True or ${read_step.stats.feature_count} > 0"
```

#### `not` 运算符

对条件取反。

```yaml
when: "not ${vars.skip_step}"
```

#### 运算符优先级

运算符的优先级从高到低为：

1. **`not`** — 一元取反，优先级最高
2. **`and`** — 逻辑与
3. **`or`** — 逻辑或，优先级最低

可以使用括号 `()` 来改变优先级：

```yaml
# 不使用括号 - and 优先于 or
when: "${a} > 0 or ${b} > 0 and ${c} > 0"
# 等价于: ${a} > 0 or (${b} > 0 and ${c} > 0)

# 使用括号 - 明确优先级
when: "(${a} > 0 or ${b} > 0) and ${c} > 0"
```

### 6.1.5 变量替换在条件中的工作方式

`when` 表达式中的变量引用（`${...}`）会在条件求值之前被替换为实际值。替换过程如下：

1. **解析变量引用**：识别表达式中所有 `${...}` 形式的变量引用
2. **查找变量值**：从步骤结果或管道变量中获取实际值
3. **替换变量**：将变量引用替换为字符串形式的实际值
4. **安全求值**：对替换后的表达式进行 AST 安全求值

```
原始表达式:   ${read_step.stats.feature_count} > 100
变量替换后:   500 > 100
求值结果:     True
```

**注意事项：**

- 如果引用的变量不存在，会抛出 `VariableResolutionError`
- 字符串值在替换时会自动加上引号
- 数值和布尔值直接替换

```yaml
vars:
  threshold: 100
  enable_qc: true
  target_crs: "EPSG:4326"

steps:
  - id: read_data
    step: io.read_vector
    params:
      path: "input.shp"

  # 变量替换示例
  - id: conditional_step
    step: vector.buffer
    params:
      input: ${read_data.output}
      distance: 100
    # 原始: ${read_data.stats.feature_count} > ${vars.threshold}
    # 替换后: 500 > 100
    # 结果: True → 执行该步骤
    when: "${read_data.stats.feature_count} > ${vars.threshold}"
```

### 6.1.6 Truthy 值判断

当 `when` 表达式的结果不是严格的布尔值时，GeoPipeAgent 会按照以下规则进行 truthy/falsy 判断：

| 值类型 | Truthy 值 | Falsy 值 |
|--------|----------|----------|
| 布尔值 | `True` | `False` |
| 数值 | 非零值（如 `1`, `3.14`, `-1`） | `0`, `0.0` |
| 字符串 | 非空字符串（如 `"hello"`, `"EPSG:4326"`） | 空字符串 `""` |
| None | — | `None` |
| 列表 | 非空列表 | 空列表 `[]` |

```yaml
# 以下 when 条件等价
when: "${read_step.stats.feature_count} > 0"
when: "${read_step.stats.feature_count}"  # 非零值即为 truthy

# 直接使用布尔变量
when: "${vars.enable_qc}"  # True 为 truthy，False 为 falsy
```

## 6.2 AST 安全求值机制

### 6.2.1 为什么需要安全求值？

在处理 `when` 条件表达式时，最简单的做法是使用 Python 的 `eval()` 函数直接执行。但这样做存在严重的安全风险——恶意用户可能在 YAML 文件中注入危险代码：

```yaml
# 危险！如果直接 eval，可能执行恶意代码
when: "__import__('os').system('rm -rf /')"
```

为了防止这种注入攻击，GeoPipeAgent 实现了基于 Python AST（抽象语法树）的安全求值机制。

### 6.2.2 safe_eval.py 的工作原理

`safe_eval.py` 模块负责安全地求值条件表达式。其核心思路是：

1. **将表达式解析为 AST**：使用 Python 的 `ast.parse()` 将字符串表达式解析为抽象语法树
2. **白名单校验**：遍历 AST 节点，确保每个节点都在允许的类型列表中
3. **安全求值**：只有通过校验的表达式才会被执行

#### 允许的 AST 节点类型

safe_eval 严格限制了允许出现在表达式中的 AST 节点类型，只允许以下七种：

| AST 节点类型 | 说明 | 对应语法示例 |
|-------------|------|-------------|
| `ast.Compare` | 比较表达式 | `a > 100`、`a == 'text'` |
| `ast.BoolOp` | 布尔运算（and/or） | `a > 0 and b < 100` |
| `ast.UnaryOp` | 一元运算（not） | `not a` |
| `ast.Num` | 数值字面量 | `100`、`3.14` |
| `ast.Str` | 字符串字面量 | `'EPSG:4326'` |
| `ast.Name` | 变量名 | `True`、`False`、`None` |
| `ast.Attribute` | 属性访问 | 在变量替换后一般不会出现 |

#### 不允许的 AST 节点类型（部分列举）

以下类型的节点一旦出现在表达式中，就会立即拒绝求值：

| 被禁止的节点类型 | 说明 | 危险示例 |
|-----------------|------|---------|
| `ast.Call` | 函数调用 | `__import__('os')` |
| `ast.Import` | 导入语句 | `import os` |
| `ast.FunctionDef` | 函数定义 | `def hack(): ...` |
| `ast.ClassDef` | 类定义 | `class Evil: ...` |
| `ast.Subscript` | 下标访问 | `globals()['os']` |
| `ast.Lambda` | Lambda 表达式 | `lambda: os.system(...)` |
| `ast.Exec` | exec 语句 | `exec('malicious code')` |

### 6.2.3 safe_eval 的实现详解

以下是 `safe_eval.py` 的核心实现逻辑：

```python
"""
safe_eval.py - GeoPipeAgent 安全表达式求值模块

仅允许安全的比较和布尔运算，防止代码注入攻击。
"""
import ast
import operator
from typing import Any

# 允许的 AST 节点类型白名单
ALLOWED_NODES = (
    ast.Expression,  # 顶层表达式包装器
    ast.Compare,     # 比较运算: a > b, a == b
    ast.BoolOp,      # 布尔运算: a and b, a or b
    ast.UnaryOp,     # 一元运算: not a
    ast.Num,         # 数值字面量: 100, 3.14
    ast.Str,         # 字符串字面量: 'hello'
    ast.Name,        # 变量名: True, False, None
    ast.Attribute,   # 属性访问（变量替换后的残留）
    ast.NameConstant,# Python 3.8+ 中的 True/False/None
    ast.Constant,    # Python 3.8+ 统一的常量节点
    ast.And,         # and 运算符
    ast.Or,          # or 运算符
    ast.Not,         # not 运算符
    ast.Eq,          # == 运算符
    ast.NotEq,       # != 运算符
    ast.Lt,          # < 运算符
    ast.LtE,         # <= 运算符
    ast.Gt,          # > 运算符
    ast.GtE,         # >= 运算符
    ast.Load,        # 变量加载上下文
)

# 允许的 Name 节点值（只能引用 True/False/None）
ALLOWED_NAMES = {"True": True, "False": False, "None": None}

# 比较运算符映射
COMPARE_OPS = {
    ast.Eq: operator.eq,
    ast.NotEq: operator.ne,
    ast.Lt: operator.lt,
    ast.LtE: operator.le,
    ast.Gt: operator.gt,
    ast.GtE: operator.ge,
}


class UnsafeExpressionError(Exception):
    """当表达式包含不允许的 AST 节点时抛出此异常。"""
    pass


def _validate_node(node: ast.AST) -> None:
    """
    递归校验 AST 节点是否在白名单中。

    Args:
        node: 要校验的 AST 节点

    Raises:
        UnsafeExpressionError: 当发现不在白名单中的节点类型时
    """
    if not isinstance(node, ALLOWED_NODES):
        raise UnsafeExpressionError(
            f"不允许的表达式节点类型: {type(node).__name__}。"
            f"仅允许比较和布尔运算。"
        )
    for child in ast.iter_child_nodes(node):
        _validate_node(child)


def _eval_node(node: ast.AST) -> Any:
    """
    递归求值已验证安全的 AST 节点。

    Args:
        node: 已通过安全校验的 AST 节点

    Returns:
        求值结果
    """
    # Python 3.8+ 统一常量节点
    if isinstance(node, ast.Constant):
        return node.value

    # 数值字面量
    if isinstance(node, ast.Num):
        return node.n

    # 字符串字面量
    if isinstance(node, ast.Str):
        return node.s

    # 变量名（仅 True/False/None）
    if isinstance(node, ast.Name):
        if node.id in ALLOWED_NAMES:
            return ALLOWED_NAMES[node.id]
        raise UnsafeExpressionError(f"不允许的变量名: {node.id}")

    # Python 3.8+ 的 NameConstant
    if isinstance(node, ast.NameConstant):
        return node.value

    # 比较表达式
    if isinstance(node, ast.Compare):
        left = _eval_node(node.left)
        for op, comparator in zip(node.ops, node.comparators):
            right = _eval_node(comparator)
            op_func = COMPARE_OPS.get(type(op))
            if op_func is None:
                raise UnsafeExpressionError(
                    f"不支持的比较运算符: {type(op).__name__}"
                )
            if not op_func(left, right):
                return False
            left = right
        return True

    # 布尔运算（and/or）
    if isinstance(node, ast.BoolOp):
        if isinstance(node.op, ast.And):
            return all(_eval_node(v) for v in node.values)
        if isinstance(node.op, ast.Or):
            return any(_eval_node(v) for v in node.values)

    # 一元运算（not）
    if isinstance(node, ast.UnaryOp):
        if isinstance(node.op, ast.Not):
            return not _eval_node(node.operand)

    raise UnsafeExpressionError(f"无法求值的节点类型: {type(node).__name__}")


def safe_eval(expression: str) -> Any:
    """
    安全求值条件表达式。

    仅允许比较运算、布尔运算和基本字面量。
    禁止函数调用、导入、属性访问等危险操作。

    Args:
        expression: 要求值的表达式字符串

    Returns:
        表达式的求值结果（通常为 bool）

    Raises:
        UnsafeExpressionError: 当表达式包含不安全的节点时
        SyntaxError: 当表达式语法错误时
    """
    # 第1步: 解析为 AST
    try:
        tree = ast.parse(expression, mode='eval')
    except SyntaxError as e:
        raise SyntaxError(f"条件表达式语法错误: {expression}") from e

    # 第2步: 安全校验
    _validate_node(tree)

    # 第3步: 安全求值
    return _eval_node(tree.body)
```

### 6.2.4 安全防护示例

以下展示了安全求值机制如何阻止各种注入攻击：

```python
from geopipe_agent.safe_eval import safe_eval, UnsafeExpressionError

# ✅ 安全表达式 - 正常工作
result = safe_eval("500 > 100")  # True
result = safe_eval("'EPSG:4326' == 'EPSG:4326'")  # True
result = safe_eval("100 > 0 and 200 < 500")  # True
result = safe_eval("not False")  # True

# ❌ 危险表达式 - 被拦截
try:
    safe_eval("__import__('os').system('rm -rf /')")
except UnsafeExpressionError as e:
    print(f"拦截: {e}")
    # 拦截: 不允许的表达式节点类型: Call

try:
    safe_eval("exec('import os; os.system(\"ls\")')")
except UnsafeExpressionError as e:
    print(f"拦截: {e}")
    # 拦截: 不允许的表达式节点类型: Call

try:
    safe_eval("globals()['__builtins__']")
except UnsafeExpressionError as e:
    print(f"拦截: {e}")
    # 拦截: 不允许的表达式节点类型: Subscript

try:
    safe_eval("(lambda: None)()")
except UnsafeExpressionError as e:
    print(f"拦截: {e}")
    # 拦截: 不允许的表达式节点类型: Lambda
```

### 6.2.5 条件表达式求值的完整流程

以下是 GeoPipeAgent 处理 `when` 条件的完整流程：

```
[YAML when 表达式]
        │
        ▼
[变量替换: ${...} → 实际值]
        │
        ▼
[ast.parse() 解析为 AST]
        │
        ▼
[_validate_node() 白名单校验]
        │
    ┌───┴───┐
    │       │
  通过    不通过
    │       │
    ▼       ▼
[安全求值] [抛出 UnsafeExpressionError]
    │
    ▼
[根据结果决定步骤执行/跳过]
```

**变量替换前后对比：**

```
输入:    "${read.stats.feature_count} > 100 and ${read.stats.crs} != 'EPSG:4326'"
替换后:  "500 > 100 and 'EPSG:3857' != 'EPSG:4326'"
AST:     BoolOp(And, [Compare(500, [Gt], [100]), Compare('EPSG:3857', [NotEq], ['EPSG:4326'])])
结果:    True
```

## 6.3 on_error 错误处理策略

### 6.3.1 基本概念

每个步骤都可以通过 `on_error` 字段指定当该步骤执行失败时的处理策略。GeoPipeAgent 支持三种策略：

| 策略 | 行为 | 适用场景 |
|------|------|---------|
| `fail` | 停止整个流水线，抛出异常 | 关键步骤，失败则无法继续 |
| `skip` | 跳过当前步骤，继续执行后续步骤 | 可选步骤，失败不影响整体 |
| `retry` | 重试当前步骤（最多3次，指数退避） | 可能因临时原因失败的步骤 |

### 6.3.2 fail 策略（默认）

`fail` 是默认的错误处理策略。当步骤执行失败时，立即停止整个流水线并抛出 `StepExecutionError` 异常。

```yaml
steps:
  - id: read_data
    step: io.read_vector
    params:
      path: "critical_data.shp"
    on_error: fail  # 默认值，可以省略

  - id: process_data
    step: vector.buffer
    params:
      input: ${read_data.output}
      distance: 100
    # 未指定 on_error，默认为 fail
```

**执行行为：**

```
步骤 read_data 执行失败
  → 抛出 StepExecutionError
  → 流水线立即终止
  → 后续步骤 process_data 不会执行
  → 返回错误信息和建议修复方案
```

**适用场景：**
- 数据读取步骤：没有数据则后续步骤无意义
- 核心处理步骤：结果是后续步骤的输入依赖
- 数据写出步骤：必须保证结果成功保存

### 6.3.3 skip 策略

`skip` 策略在步骤执行失败时跳过该步骤，继续执行后续步骤。跳过的步骤不会产生输出，后续步骤如果依赖该步骤的输出，需要注意处理。

```yaml
steps:
  - id: read_data
    step: io.read_vector
    params:
      path: "input.shp"

  - id: optional_qc
    step: qc.geometry_validity
    params:
      input: ${read_data.output}
    on_error: skip  # QC 失败不影响整体流程

  - id: buffer_step
    step: vector.buffer
    params:
      input: ${read_data.output}  # 注意：引用原始数据，而非 QC 输出
      distance: 100
```

**执行行为：**

```
步骤 optional_qc 执行失败
  → 记录警告日志
  → 跳过该步骤，标记为 "skipped"
  → 继续执行 buffer_step
  → 流水线正常完成
```

**使用注意事项：**

1. 被跳过步骤的输出（如 `${optional_qc.output}`）将为 `None`
2. 后续步骤如果引用被跳过步骤的输出，可能会出错
3. 建议结合 `when` 条件检查前序步骤的状态

```yaml
steps:
  - id: optional_qc
    step: qc.geometry_validity
    params:
      input: ${read_data.output}
    on_error: skip

  # 仅当 QC 步骤成功执行时才运行修复
  - id: fix_geometries
    step: qc.geometry_validity
    params:
      input: ${read_data.output}
      auto_fix: true
    when: "${optional_qc.status} == 'failed'"
```

### 6.3.4 retry 策略

`retry` 策略在步骤执行失败时进行自动重试，最多重试 3 次，采用指数退避（exponential backoff）算法控制重试间隔。

```yaml
steps:
  - id: read_remote
    step: io.read_vector
    params:
      path: "https://example.com/data.geojson"
    on_error: retry  # 网络请求可能因临时故障失败
```

**重试机制详解：**

```
第1次尝试: 执行步骤
  → 失败
  → 等待 1 秒

第2次尝试: 重新执行步骤
  → 失败
  → 等待 2 秒（1 * 2^1）

第3次尝试: 重新执行步骤
  → 失败
  → 等待 4 秒（1 * 2^2）

第4次尝试（最后一次）: 重新执行步骤
  → 如果成功: 继续执行后续步骤
  → 如果失败: 抛出 StepExecutionError，流水线终止
```

**指数退避算法：**

```python
import time

MAX_RETRIES = 3
BASE_DELAY = 1  # 秒

for attempt in range(MAX_RETRIES + 1):
    try:
        result = execute_step(step)
        break  # 成功则跳出循环
    except Exception as e:
        if attempt == MAX_RETRIES:
            raise StepExecutionError(
                step_id=step.id,
                message=f"步骤 {step.id} 在 {MAX_RETRIES + 1} 次尝试后仍然失败",
                cause=e,
            )
        delay = BASE_DELAY * (2 ** attempt)
        logger.warning(
            f"步骤 {step.id} 第 {attempt + 1} 次执行失败，"
            f"{delay} 秒后重试... 错误: {e}"
        )
        time.sleep(delay)
```

**适用场景：**
- 网络数据读取（URL 数据源）
- 外部服务调用（如 WFS/WMS 服务）
- 文件锁冲突（多进程并发时）
- 数据库连接不稳定

### 6.3.5 on_error 配置示例

以下是一个完整的流水线示例，展示了三种策略的组合使用：

```yaml
name: 综合错误处理示例
description: 展示不同错误处理策略的组合使用

steps:
  # 关键步骤 - 必须成功
  - id: read_data
    step: io.read_vector
    params:
      path: "input.shp"
    on_error: fail

  # 可选的 QC 步骤 - 失败可以跳过
  - id: check_quality
    step: qc.geometry_validity
    params:
      input: ${read_data.output}
    on_error: skip

  # 可能因 CRS 服务不稳定而失败 - 重试
  - id: reproject_data
    step: vector.reproject
    params:
      input: ${read_data.output}
      target_crs: "EPSG:4326"
    on_error: retry

  # 关键输出步骤 - 必须成功
  - id: save_result

      path: "output.geojson"
```

## 6.4 StepExecutionError 异常类

### 6.4.1 类定义与属性

`StepExecutionError` 是 GeoPipeAgent 中最常见的异常类型，它封装了步骤执行失败时的完整上下文信息。

```python
class StepExecutionError(GeopipeAgentError):
    """
    步骤执行错误。

    当某个步骤在执行过程中发生异常时抛出。包含详细的错误上下文
    信息和 AI 友好的修复建议。
    """

    def __init__(
        self,
        step_id: str,
        message: str,
        cause: Optional[Exception] = None,
        suggestion: Optional[str] = None,
    ):
        """
        初始化步骤执行错误。

        Args:
            step_id: 失败的步骤 ID
            message: 错误描述消息
            cause: 导致失败的原始异常（可选）
            suggestion: AI 友好的修复建议（可选）
        """
        self.step_id = step_id
        self.message = message
        self.cause = cause
        self.suggestion = suggestion
        super().__init__(self._format_message())

    def _format_message(self) -> str:
        """格式化完整的错误消息。"""
        parts = [f"步骤 '{self.step_id}' 执行失败: {self.message}"]
        if self.cause:
            parts.append(f"原因: {type(self.cause).__name__}: {self.cause}")
        if self.suggestion:
            parts.append(f"建议: {self.suggestion}")
        return "\n".join(parts)

    def to_dict(self) -> dict:
        """
        将错误信息转换为字典格式。

        方便 JSON 序列化输出，用于日志记录和 API 响应。

        Returns:
            包含错误详情的字典
        """
        return {
            "error_type": "StepExecutionError",
            "step_id": self.step_id,
            "message": self.message,
            "cause": str(self.cause) if self.cause else None,
            "cause_type": type(self.cause).__name__ if self.cause else None,
            "suggestion": self.suggestion,
        }
```

### 6.4.2 属性详解

| 属性 | 类型 | 说明 |
|------|------|------|
| `step_id` | `str` | 失败步骤的唯一标识符 |
| `message` | `str` | 人类可读的错误描述 |
| `cause` | `Optional[Exception]` | 导致失败的原始异常对象 |
| `suggestion` | `Optional[str]` | AI 友好的修复建议文本 |

### 6.4.3 to_dict() 方法

`to_dict()` 方法将错误信息转换为字典格式，方便 JSON 序列化。这在以下场景中特别有用：

- **JSON 日志输出**：使用 `--json-log` 选项时，错误信息以 JSON 格式写入日志
- **API 响应**：当 GeoPipeAgent 作为服务运行时，返回结构化错误响应
- **错误报告**：生成结构化的错误报告

```python
try:
    pipeline.execute()
except StepExecutionError as e:
    error_dict = e.to_dict()
    print(json.dumps(error_dict, indent=2, ensure_ascii=False))
```

输出示例：

```json
{
  "error_type": "StepExecutionError",
  "step_id": "buffer_step",
  "message": "缓冲区分析失败：输入数据包含无效几何体",
  "cause": "GEOSException: TopologyException: side location conflict",
  "cause_type": "GEOSException",
  "suggestion": "输入数据可能包含自相交几何体。建议在此步骤之前添加 'qc.geometry_validity' 步骤并启用 auto_fix=true 选项。"
}
```

### 6.4.4 完整使用示例

```python

    try:
        result = step.run(context)
        return result
    except FileNotFoundError as e:
        raise StepExecutionError(
            step_id=step.id,
            message=f"输入文件不存在: {e.filename}",
            cause=e,
            suggestion=(
                f"请检查文件路径 '{e.filename}' 是否正确。"
                f"确保文件存在且程序有读取权限。"
            ),
        )
    except Exception as e:
        # 使用 AI 友好错误消息系统自动生成建议
        suggestion = generate_suggestion(step, e)
        raise StepExecutionError(
            step_id=step.id,
            message=str(e),
            cause=e,
            suggestion=suggestion,
        )
```

```python
    pipeline.validate()
    result = pipeline.execute()

except PipelineParseError as e:
    # YAML 文件格式问题 - 需要修复 YAML 文件
    logger.error(f"YAML 解析错误: {e}")

except PipelineValidationError as e:
    # 配置逻辑问题 - 需要修复步骤配置
    logger.error(f"配置验证错误: {e}")

except StepNotFoundError as e:
    # 步骤不存在 - 检查步骤名称
    logger.error(f"步骤未找到: {e}")
    logger.info(f"可用步骤: {registry.list_all()}")

except BackendNotAvailableError as e:
    # 后端缺失 - 安装后端或切换后端
    logger.error(f"后端不可用: {e}")

except VariableResolutionError as e:
    # 变量解析失败 - 检查变量引用
    logger.error(f"变量解析错误: {e}")

except StepExecutionError as e:
    # 步骤执行失败 - 根据建议修复
    logger.error(f"步骤执行错误: {e}")
    if e.suggestion:
        logger.info(f"修复建议: {e.suggestion}")
    error_dict = e.to_dict()
    # 将错误信息发送给 AI Agent 进行自动修复

except GeopipeAgentError as e:
    # 其他未分类的 GeoPipeAgent 错误
    logger.error(f"GeoPipeAgent 错误: {e}")
```

## 6.7 完整示例

### 6.7.1 条件质量检查流水线

```yaml
name: 条件质量检查流水线
description: |
  根据数据特征自动选择执行不同的质量检查步骤。
  演示 when 条件表达式的使用。

vars:
  enable_qc: true
  max_features: 50000
  target_crs: "EPSG:4326"

steps:
  # 第1步: 读取数据
  - id: read_data
    step: io.read_vector
    params:
      path: "input.shp"

  # 第2步: 坐标系检查与转换（条件执行）
  # 仅当数据 CRS 不是目标 CRS 时执行
  - id: reproject
    step: vector.reproject
    params:
      input: ${read_data.output}
      target_crs: ${vars.target_crs}
    when: "${read_data.stats.crs} != '${vars.target_crs}'"

  # 第3步: 获取当前数据（根据是否执行了投影变换选择输入）
  # 使用条件执行来选择正确的数据源
  - id: geometry_check
    step: qc.geometry_validity
    params:
      input: ${reproject.output}
      auto_fix: true
    when: "${vars.enable_qc} == True and ${read_data.stats.crs} != '${vars.target_crs}'"

  - id: geometry_check_no_reproject
    step: qc.geometry_validity
    params:
      input: ${read_data.output}
      auto_fix: true
    when: "${vars.enable_qc} == True and ${read_data.stats.crs} == '${vars.target_crs}'"

  # 第4步: 大数据集简化（条件执行）
  # 仅当要素数量超过阈值时执行简化
  - id: simplify_large
    step: vector.simplify
    params:
      input: ${geometry_check.output}
      tolerance: 0.001
      preserve_topology: true
    when: "${read_data.stats.feature_count} > ${vars.max_features}"

  # 第5步: 保存结果
  - id: save_result
    step: io.write_vector
    params:
      input: ${simplify_large.output}
      path: "output_qc.geojson"
    when: "${read_data.stats.feature_count} > ${vars.max_features}"

  - id: save_result_normal
    step: io.write_vector
    params:
      input: ${geometry_check.output}
      path: "output_qc.geojson"
    when: "${read_data.stats.feature_count} <= ${vars.max_features}"
```

### 6.7.2 错误处理流水线

```yaml
name: 健壮的数据处理流水线
description: |
  展示不同 on_error 策略的综合使用。
  即使部分步骤失败，也能尽量完成处理。

steps:
  # 读取数据 - 失败则终止（默认行为）
  - id: read_data
    step: io.read_vector
    params:
      path: "input.shp"
    on_error: fail

  # 几何修复 - 允许跳过
  - id: fix_geometry
    step: qc.geometry_validity
    params:
      input: ${read_data.output}
      auto_fix: true
    on_error: skip

  # 坐标转换 - 网络服务可能不稳定，允许重试
  - id: reproject
    step: vector.reproject
    params:
      input: ${read_data.output}
      target_crs: "EPSG:4326"
    on_error: retry

  # 缓冲区分析 - 核心步骤，失败则终止
  - id: buffer
    step: vector.buffer
    params:
      input: ${reproject.output}
      distance: 100
    on_error: fail

  # 属性统计 - 可选功能，允许跳过
  - id: statistics
    step: analysis.attribute_stats
    params:
      input: ${buffer.output}
      fields: ["area", "perimeter"]
    on_error: skip

  # 保存结果 - 必须成功
  - id: save
    step: io.write_vector
    params:
      input: ${buffer.output}
      path: "output.geojson"
    on_error: fail
```

### 6.7.3 重试模式示例

```yaml
name: 远程数据处理流水线
description: |
  从网络服务读取数据并处理。
  使用 retry 策略应对网络不稳定。

steps:
  # 从 WFS 服务读取数据 - 网络请求，使用 retry
  - id: read_wfs
    step: io.read_vector
    params:
      path: "WFS:https://example.com/wfs?service=WFS&request=GetFeature&typeName=buildings"
    on_error: retry

  # 从另一个服务读取裁剪范围 - 也使用 retry
  - id: read_boundary
    step: io.read_vector
    params:
      path: "https://example.com/boundary.geojson"
    on_error: retry

  # 裁剪操作 - 本地计算，使用 fail
  - id: clip_data
    step: vector.clip
    params:
      input: ${read_wfs.output}
      clip_geometry: ${read_boundary.output}
    on_error: fail

  # 保存到本地 - 必须成功
  - id: save_local
    step: io.write_vector
    params:
      input: ${clip_data.output}
      path: "buildings_clipped.gpkg"
    on_error: fail

  # 上传到远程服务 - 网络操作，使用 retry
  - id: upload_result
    step: io.write_vector
    params:
      input: ${clip_data.output}
      path: "https://example.com/upload/buildings_clipped.gpkg"
    on_error: retry
```

## 6.9 本章小结

本章详细介绍了 GeoPipeAgent 的条件执行和错误处理机制：

| 主题 | 要点 |
|------|------|
| **when 条件** | 支持比较运算、布尔逻辑、变量替换，可灵活控制步骤是否执行 |
| **AST 安全求值** | 基于白名单的安全表达式求值，防止代码注入攻击 |
| **on_error 策略** | fail（终止）、skip（跳过）、retry（重试），三种策略灵活组合 |
| **异常体系** | 层级化异常设计，每种错误类型提供针对性的上下文信息 |
| **AI 友好消息** | 自动生成修复建议，AI Agent 可基于建议自动修复流水线 |
| **调试技巧** | DEBUG 日志、JSON 日志、步骤结果检查，多维度排查问题 |
