# 第16章：粒子系统与特效

## 16.1 粒子系统基础

粒子系统用于生成大量短生命周期的小图元：雨滴、雪花、火焰、烟雾、爆炸碎片、扫描光点。它和实体走两条完全不同的渲染路径——粒子直接挂在 `scene.primitives` 上，由 GPU 批量绘制，一个 `ParticleSystem` 对应一次绘制调用，粒子的位置、颜色、缩放、寿命都在着色器里按时间参数化计算。这带来两个直接结果：一是粒子的数量可以很大（数千到数万），二是你无法像操作实体那样逐个拾取、逐个修改某个粒子。

需要“点一下这个雨滴”这种交互时，粒子系统不是合适的选择。粒子的用途是氛围与示意，业务上要能选取、要能查询属性的对象仍然应该用 Entity 或 Primitive 表达。

### 16.1.1 ParticleSystem 概述

构造参数可以分成四组来理解。第一组决定“长什么样”：`image` 是粒子贴图，可以是 PNG 的 URL，也可以是 canvas 元素；`startScale`、`endScale` 是单个粒子从出生到消亡的缩放范围；`startColor`、`endColor` 决定颜色渐变，同时通过 alpha 控制淡入淡出，示例里从红色半透明渐变到黄色全透明，火焰的观感一半来自这条颜色曲线。

第二组决定“从哪里出来、出来多少”：`emitter` 是发射器形状，`emissionRate` 是每秒发射的粒子数。发射率乘以粒子的平均寿命，大致等于场景里同时存在的粒子数——`emissionRate: 50`、寿命 1.6 秒，约有 80 个粒子同时在飞。这个乘积是性能估算的依据，不是发射率越大越好看，数量超过屏幕像素密度之后只会糊成一片。

第三组决定“怎么运动”：`speed` 是初速度，`lifetime` 是整个粒子系统持续发射的时长（不是单个粒子的寿命），后者由 `minimumParticleLife`、`maximumParticleLife` 一对参数控制。本章示例里写的 `particleLife` 并不是 `ParticleSystem` 的构造参数（正确的写法是上面这对最小/最大寿命），多余的选项会被静默忽略，粒子落到默认寿命上；碰到“粒子刚出来就没了”或者“一直挂在空中不掉”时，先核对自己的参数名是否写成了文档里的成对参数，这类拼写错误不会报错，调试成本却很高。

第四组决定“放在哪”：`modelMatrix` 把粒子系统定位到世界坐标。`Cesium.Transforms.eastNorthUpToFixedFrame(cartesian)` 生成一个以该点为原点、东北天为轴的局部坐标系，所以发射器的半径、粒子速度都按米来解释。漏掉 `modelMatrix` 时系统会落在原点（地心），什么都看不见。

`viewer.scene.primitives.add(particleSystem)` 之后系统才开始发射。要停掉它用 `viewer.scene.primitives.remove(particleSystem)`，或者设 `particleSystem.show = false` 只是隐藏、仍在消耗计算。切换天气这类场景反复创建、移除粒子系统时，记得把旧的实例引用清空，它不会自动回收。

```javascript
// 创建基本粒子系统
const particleSystem = new Cesium.ParticleSystem({
    image: 'particle.png',
    
    // 发射器
    emitter: new Cesium.CircleEmitter(2.0),
    
    // 发射速率
    emissionRate: 50,
    
    // 粒子属性
    startScale: 1.0,
    endScale: 4.0,
    startColor: Cesium.Color.RED.withAlpha(0.7),
    endColor: Cesium.Color.YELLOW.withAlpha(0.0),
    
    // 速度
    speed: 5.0,
    
    // 生命周期
    lifetime: 1.6,
    
    // 模型矩阵
    modelMatrix: Cesium.Transforms.eastNorthUpToFixedFrame(
        Cesium.Cartesian3.fromDegrees(116.4, 39.9, 100)
    )
});

viewer.scene.primitives.add(particleSystem);
```

### 16.1.2 发射器类型

发射器决定粒子的出生位置分布，四种形状对应四类效果组织方式。`CircleEmitter(radius)` 在一个圆盘内随机取点，粒子的初速度方向沿圆盘法向偏散，适合烟囱、地面喷泉这类“从一个面向上升起”的效果；`SphereEmitter(radius)` 在球体内取点，适合爆炸、体积雾；`BoxEmitter(cartesian3)` 在一个长宽高的盒子内随机取点，雨雪效果用它把发射区域铺满相机周围的一大块空间；`ConeEmitter(angle)` 在锥体内发射，参数是锥的半角（用 `Cesium.Math.toRadians` 换算成弧度），角度越小方向越集中，火焰、喷射、探照灯都属这一类。

发射器的尺寸单位是米，与 `modelMatrix` 定义的局部坐标系一致。把 `CircleEmitter(2.0)` 放在城市尺度场景里几乎是一个点，而用在模型内部又可能比整个模型还大，参数值要结合场景尺度调整，不能照抄示例。盒子发射器的尺寸还可以配合 `sizeInMeters` 让粒子大小随距离变化，远处不显得突兀。

发射器只负责位置，方向由发射器类型和速度共同决定；没有单独的“方向”参数。要让粒子朝某个固定方向喷，用锥形发射器并旋转 `modelMatrix`，或者给粒子系统加 `emitterModelMatrix`，它作用在发射器局部坐标上，把发射口挪到模型的某个部位，比如烟囱顶端而不是烟囱中心。

```javascript
// 圆形发射器
new Cesium.CircleEmitter(radius)

// 球形发射器
new Cesium.SphereEmitter(radius)

// 盒子发射器
new Cesium.BoxEmitter(new Cesium.Cartesian3(width, height, depth))

// 锥形发射器
new Cesium.ConeEmitter(angle)
```

## 16.2 常见特效实现

特效代码多半是这个结构：一段程序化生成的粒子贴图 + 一组色彩与尺寸的起止值 + 一个发射器 + 一个把系统放到场景里的 `modelMatrix`。理解了这个骨架，换成喷泉、爆炸、尾迹都只是改参数的事；真正决定“像不像”的往往是贴图与颜色曲线，而不是粒子数量。

### 16.2.1 火焰效果

火焰由三件事叠出来：向上的锥形发射、由亮黄到暗红的颜色衰减、从小到大的尺寸膨胀。代码里 `ConeEmitter(Cesium.Math.toRadians(30))` 给了 30 度半角的锥体，`speed: 5.0` 把粒子往上推，颜色从 `(1, 1, 0, 0.7)` 的黄渐变到 `(1, 0, 0, 0)` 的红，透明度归零的那一刻粒子消失，视觉上就是火焰由中心到边缘逐渐熄灭。`endScale: 4.0` 让粒子在上升过程中膨胀，模拟热气扩散。

`getFireParticle` 用 canvas 画了一张 64×64 的圆形渐变贴图，中心接近白色、向外过渡到透明橙红。粒子系统对贴图的 alpha 通道做混合，所以贴图边缘必须透明，否则每个粒子会出现一个方块轮廓。canvas 生成贴图的好处是不依赖外部文件、颜色随时可调；代价是每创建一个系统就生成一张纹理，反复创建时应该把结果缓存起来复用。

示例中的 `lifetime: 16.0` 是整个系统的时间上限，配合 `loop: true` 时会重新开始；两个值一起看，`lifetime` 设得比实际观察时间长没有意义，设短了系统会整体重启，粒子出现“同时消失又同时出现”的断层。要判断火焰是否还活着，看 `particleSystem.show` 或者自己维护的引用，不要依赖寿命。

```javascript
function createFireEffect(viewer, position) {
    const particleSystem = new Cesium.ParticleSystem({
        image: getFireParticle(),
        startScale: 1.0,
        endScale: 4.0,
        particleLife: 1.5,
        speed: 5.0,
        emitter: new Cesium.ConeEmitter(Cesium.Math.toRadians(30)),
        emissionRate: 30.0,
        startColor: new Cesium.Color(1, 1, 0, 0.7),
        endColor: new Cesium.Color(1, 0, 0, 0.0),
        imageSize: new Cesium.Cartesian2(25, 25),
        modelMatrix: Cesium.Transforms.eastNorthUpToFixedFrame(
            Cesium.Cartesian3.fromDegrees(position.lon, position.lat, position.height)
        ),
        lifetime: 16.0,
        loop: true
    });
    
    viewer.scene.primitives.add(particleSystem);
    return particleSystem;
}

function getFireParticle() {
    const canvas = document.createElement('canvas');
    canvas.width = 64;
    canvas.height = 64;
    const ctx = canvas.getContext('2d');
    
    const gradient = ctx.createRadialGradient(32, 32, 0, 32, 32, 32);
    gradient.addColorStop(0, 'rgba(255, 255, 200, 1)');
    gradient.addColorStop(0.3, 'rgba(255, 200, 0, 0.8)');
    gradient.addColorStop(1, 'rgba(255, 100, 0, 0)');
    
    ctx.fillStyle = gradient;
    ctx.fillRect(0, 0, 64, 64);
    
    return canvas;
}
```

### 16.2.2 烟雾效果

烟雾和火焰的参数结构相同，差异都在数值上：发射率从 30 降到 10，粒子稀疏散漫；`startScale` 到 `endScale` 从 1 放大到 8，粒子膨胀更明显；颜色从半透明灰到几乎完全透明的浅灰，`endColor` 的 alpha 为 0 让烟雾自然消散；`CircleEmitter(5.0)` 用了更大的发射面，烟柱底部显得更宽。

`particleLife: 4.0` 这项同样属于简写问题，实际应使用成对的寿命参数；寿命越长，同一发射率下同时存在的粒子越多，性能开销随寿命线性增长。烟雾要“飘”得慢，把 `speed` 降到 3.0 只是降低初速度，要真正拖慢上升速度还得配合重力或者让 endScale 增大使视觉上变慢。

一个容易被忽略的点：这段函数只 return 粒子系统、没有 `add` 到场景，调用方必须自己 `viewer.scene.primitives.add(createSmokeEffect(...))`。和 16.2.1 的火焰函数对比可以看出两者的约定不一致，封装公共特效库时应当统一，避免调用方漏掉添加步骤导致“代码跑了但看不到效果”。

```javascript
function createSmokeEffect(viewer, position) {
    return new Cesium.ParticleSystem({
        image: getSmokeParticle(),
        startScale: 1.0,
        endScale: 8.0,
        particleLife: 4.0,
        speed: 3.0,
        emitter: new Cesium.CircleEmitter(5.0),
        emissionRate: 10.0,
        startColor: new Cesium.Color(0.5, 0.5, 0.5, 0.5),
        endColor: new Cesium.Color(0.8, 0.8, 0.8, 0.0),
        imageSize: new Cesium.Cartesian2(30, 30),
        modelMatrix: Cesium.Transforms.eastNorthUpToFixedFrame(
            Cesium.Cartesian3.fromDegrees(position.lon, position.lat, position.height)
        ),
        lifetime: 16.0,
        loop: true
    });
}
```

### 16.2.3 雨雪效果

雨雪是典型的“跟随相机”特效。发射器是一个 1000×1000×50 米的盒子，这个盒子必须始终罩在相机上方，否则相机一动，雨就下在了别处。代码用 `scene.preRender` 每帧重算 `modelMatrix`：取相机位置沿视线方向偏移 500 米，再转成东北天坐标系。偏移量取正还是取负、取多大，取决于想让雨幕出现在视野的哪一段——常见的做法是沿视线方向偏移，让发射盒正好覆盖相机前方和上方的可视区域。

`gravity: new Cesium.Cartesian3(0, 0, -9.8)` 在东北天坐标系里就是竖直向下，配合 `speed` 可以做出先向上抛再落下的抛物线，或者直接零初速下落。雨的 `imageSize` 是 2×20 的竖条，雪的贴图是 8×8 的圆点，`emissionRate` 相差四倍（2000 对 500），雨密雪疏。粒子尺寸单位默认是像素，所以缩放地图时雨滴大小不变，观感稳定。

每帧在 `preRender` 里给 `particleSystem.modelMatrix` 重新赋值，会让整个粒子系统跟着相机平移，正在下落的粒子也会一起被拖走，看起来像雨幕固定在画面上。这是这类方案的固有妥协：想做物理正确的降雨，只能把发射盒开得很大、只在相机进入该区域时才启用粒子系统。

`createRainEffect` 里注册的 `preRender` 监听器没有返回、也没有注销入口，移除粒子系统之后回调仍在执行并访问已销毁的对象。正式代码应当保存这个回调函数，在清理时用 `viewer.scene.preRender.removeEventListener` 移除。

```javascript
// 雨效果
function createRainEffect(viewer) {
    const rainParticle = createRainParticle();
    
    const particleSystem = new Cesium.ParticleSystem({
        image: rainParticle,
        startScale: 1.0,
        endScale: 1.0,
        particleLife: 1.5,
        emitter: new Cesium.BoxEmitter(new Cesium.Cartesian3(1000, 1000, 50)),
        emissionRate: 2000,
        startColor: Cesium.Color.WHITE.withAlpha(0.5),
        endColor: Cesium.Color.WHITE.withAlpha(0.3),
        imageSize: new Cesium.Cartesian2(2, 20),
        gravity: new Cesium.Cartesian3(0, 0, -9.8),
        lifetime: 16.0,
        loop: true,
        modelMatrix: computeRainMatrix()
    });
    
    viewer.scene.primitives.add(particleSystem);
    
    // 跟随相机
    viewer.scene.preRender.addEventListener(function() {
        particleSystem.modelMatrix = computeRainMatrix();
    });
    
    return particleSystem;
}

function computeRainMatrix() {
    const camera = viewer.camera;
    const offset = Cesium.Cartesian3.multiplyByScalar(
        camera.direction, 500, new Cesium.Cartesian3()
    );
    const position = Cesium.Cartesian3.add(camera.position, offset, new Cesium.Cartesian3());
    return Cesium.Transforms.eastNorthUpToFixedFrame(position);
}

// 雪效果
function createSnowEffect(viewer) {
    const particleSystem = new Cesium.ParticleSystem({
        image: getSnowParticle(),
        startScale: 1.0,
        endScale: 1.0,
        particleLife: 6.0,
        emitter: new Cesium.BoxEmitter(new Cesium.Cartesian3(1000, 1000, 50)),
        emissionRate: 500,
        startColor: Cesium.Color.WHITE,
        endColor: Cesium.Color.WHITE.withAlpha(0.0),
        imageSize: new Cesium.Cartesian2(8, 8),
        gravity: new Cesium.Cartesian3(0, 0, -1),
        lifetime: 16.0,
        loop: true
    });
    
    viewer.scene.primitives.add(particleSystem);
    return particleSystem;
}
```

## 16.3 动态线效果

动态线不是粒子，而是用 `Cesium.Material` 自定义的着色器材质，作用在折线或墙体的表面。它的取巧之处在于把“流动”表达成纹理坐标上的一个随时间移动的亮带：`materialInput.st` 是面片上归一化的纹理坐标，`s` 沿着线的走向从 0 到 1，`czm_frameNumber` 是引擎维护的帧计数，不断增长，用它对时间取模就得到一个不断循环的相位。

`fabric` 里的 `uniforms` 是外部可调的参数，`source` 是拼进着色器模板的 GLSL 片段。Cesium 内置材质也是这套结构，所以自定义材质和 `ColorMaterialProperty`、`PolylineGlowMaterialProperty` 在管线上是平级的，可以互相替换。

```javascript
// 流动线效果
class FlowingLineMaterial {
    constructor(options = {}) {
        this.color = options.color || Cesium.Color.CYAN;
        this.speed = options.speed || 5.0;
        this.percent = options.percent || 0.1;
        this.gradient = options.gradient || 0.05;
    }
    
    getMaterial() {
        return new Cesium.Material({
            fabric: {
                type: 'FlowingLine',
                uniforms: {
                    color: this.color,
                    speed: this.speed,
                    percent: this.percent,
                    gradient: this.gradient
                },
                source: `
                    uniform vec4 color;
                    uniform float speed;
                    uniform float percent;
                    uniform float gradient;
                    
                    czm_material czm_getMaterial(czm_materialInput materialInput) {
                        czm_material material = czm_getDefaultMaterial(materialInput);
                        vec2 st = materialInput.st;
                        float t = fract(czm_frameNumber * speed / 1000.0);
                        t *= (1.0 + percent);
                        float alpha = smoothstep(t - percent, t, st.s) * step(-t, -st.s);
                        alpha += gradient;
                        material.diffuse = color.rgb;
                        material.alpha = alpha * color.a;
                        return material;
                    }
                `
            }
        });
    }
}

// 使用
const flowingMaterial = new FlowingLineMaterial({
    color: Cesium.Color.CYAN,
    speed: 10.0
});

viewer.entities.add({
    polyline: {
        positions: Cesium.Cartesian3.fromDegreesArray([116, 39, 117, 40]),
        width: 5,
        material: flowingMaterial.getMaterial()
    }
});
```

## 16.4 本章小结

粒子与特效调试的经验可以归成几条。看不到粒子：先确认系统被加进了 `scene.primitives`，再确认 `modelMatrix` 不是默认的地心坐标，最后确认贴图的透明通道正常。粒子位置不对：检查 `emitter` 的尺寸单位和 `modelMatrix` 的坐标系，发射器参数按米计。特效“跑起来了但很糊”：检查同时存在的粒子数（发射率乘寿命）是否远超屏幕能表达的程度，减少数量、加大单个粒子尺寸往往比加数量更好看。帧率骤降：先关掉粒子系统验证是不是它，再考虑降低发射率、缩短寿命。清理不干净：粒子系统、`preRender` 监听、canvas 贴图三样都要显式处理，缺一样都会在反复进出场景时留下泄漏。
