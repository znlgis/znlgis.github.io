# 第13章：动画与时间系统

## 13.1 时钟系统

Cesium 把时间当成场景的一部分，而不是挂在外面的一个计时器。相机朝向、实体位置、影像图层的可见区间、模型的动画帧，最终都由 `viewer.clock` 的当前时刻决定。默认情况下时钟从页面加载的那一刻起步，此后在没有配置时间范围、也没有开启播放的前提下保持静止。很多“动画不生效”的问题，第一步排查对象就是这个对象的三个量：当前时刻、播放速率、边界行为。

当前时刻的类型不是原生 `Date`，而是 `Cesium.JulianDate`。JulianDate 用儒略日表达一个绝对时刻，好处是不受时区、夏令时影响，跨年跨月的加减也很简单；代价是不能直接把 `new Date()` 赋给它，必须通过 `fromIso8601`、`fromDate`、`now` 之类的工厂方法转换，取回可读时间时用 `toIso8601`。整章的代码都遵守这条约定，凡是给 `startTime`、`currentTime`、`addSample` 传时间的位置，传的都是 JulianDate。

### 13.1.1 Clock 配置

`startTime` 与 `stopTime` 划出可用区间，`currentTime` 是播放头所在的位置。三者都是 JulianDate，赋值时如果混入 Date 对象或时间戳，控制台未必立刻报错，但时间轴会显示到 1970 年或者直接不刷新，这类问题往往到播放阶段才发现。区间一旦确定，`clockRange` 决定播放头撞到端点之后怎么办：

| 属性 | 类型 | 含义 |
|---|---|---|
| `startTime` / `stopTime` | JulianDate | 时间区间端点，也决定时间轴默认显示范围 |
| `currentTime` | JulianDate | 当前时刻，可随时赋值跳转 |
| `multiplier` | Number | 相对真实时间的倍率，1 表示同速，可小数、可负数 |
| `shouldAnimate` | Boolean | 播放开关，false 时时刻冻结 |
| `clockRange` | ClockRange | 到达端点后的行为：UNBOUNDED 忽略区间、CLAMPED 停在末端、LOOP_STOP 回到起点 |
| `clockStep` | ClockStep | 时间推进方式：按系统时间乘倍率，或每帧固定步进 |

`multiplier = 60` 表示现实里过 1 秒、场景里过 1 分钟。它可以是 0.5 这样的慢放，也可以是负数——负倍率配合 `shouldAnimate = true` 就是倒放，不需要另外写一套倒放逻辑。`shouldAnimate` 只是开关：关掉再打开，时刻从暂停的位置继续走，不会把暂停的这段时间补上；需要跳到指定时刻，直接给 `currentTime` 赋值比快进更快也更准确。

`clockStep` 的选择影响动画与帧率的关系。默认的 `SYSTEM_CLOCK_MULTIPLIER` 把真实时间当作时间源再乘倍率，渲染卡顿时画面掉帧，但场景时间照常流逝，最终看到的是“跳帧但速度正确”，这也是三维场景里通常想要的效果。`TICK_DEPENDENT` 每帧固定推进 `multiplier` 秒（这时 multiplier 被当成每帧步长，而不是倍率），适合逐帧录制、离线渲染这类要求每一帧时间严格相等的场景；用它做交互式播放，机器快慢会直接改变动画速度。`SYSTEM_CLOCK` 则绕过倍率，始终跟随系统时钟，一般只用于“显示当前真实时间”的实时态势场景。

```javascript
const clock = viewer.clock;

// 时间范围
clock.startTime = Cesium.JulianDate.fromIso8601('2024-01-01T00:00:00Z');
clock.stopTime = Cesium.JulianDate.fromIso8601('2024-01-07T00:00:00Z');
clock.currentTime = Cesium.JulianDate.fromIso8601('2024-01-01T12:00:00Z');

// 播放速度
clock.multiplier = 60;        // 60倍速
clock.shouldAnimate = true;   // 开始播放

// 时钟范围模式
clock.clockRange = Cesium.ClockRange.LOOP_STOP;  // 循环
// Cesium.ClockRange.UNBOUNDED   // 无限制
// Cesium.ClockRange.CLAMPED     // 限制在范围内

// 时钟步进
clock.clockStep = Cesium.ClockStep.SYSTEM_CLOCK_MULTIPLIER;
// Cesium.ClockStep.TICK_DEPENDENT        // 依赖tick
// Cesium.ClockStep.SYSTEM_CLOCK          // 系统时钟
```

### 13.1.2 时间事件

`clock.onTick` 与 `clock.onStop` 都是 `Cesium.Event` 实例，接口是 `addEventListener` 与 `removeEventListener`，不是浏览器的 DOM 事件。移除监听时要把添加时的那个函数引用原样传回去：写成匿名函数之后就没有句柄可以移除，监听器会常驻在时钟上；在单页应用里反复打开、关闭三维组件，这类残留监听会让回调执行次数越积越多，表现为“第一次卡、用久了更卡”。

tick 的频率与渲染循环同步，通常一秒六十次。回调里适合做轻量的事：按当前时刻更新界面上的时间文本、判断是否跨过某个整点再触发一次数据加载、根据时刻切换图层的 `show`。遍历几千个实体重算位置、重建几何这类工作放进去，会把每帧的预算吃光，因为渲染线程和这段 JavaScript 同在主线程上。必须做批量计算时，在回调里只记录“该做了”，把实际工作挪到 `scene.postRender` 或下一帧的微任务里，并加节流。

`onStop` 在时钟停下时触发：手动把 `shouldAnimate` 置为 false、或者播放头被边界行为止住，都会走到这里。用它判断“一段动画已经播完”并不完全可靠，因为暂停也会触发；更稳的判断是在 tick 里比较 `currentTime` 与 `stopTime` 的差值，或者直接监听实体 `availability` 区间的结束时刻。

```javascript
// 监听时钟tick
clock.onTick.addEventListener(function(clock) {
    const currentTime = clock.currentTime;
    console.log('当前时间:', Cesium.JulianDate.toIso8601(currentTime));
});

// 监听时钟停止
clock.onStop.addEventListener(function(clock) {
    console.log('时钟停止');
});
```

## 13.2 Timeline 控件

`viewer.timeline` 是底部的时刻轴控件，负责两件事：把 `clock` 的区间画成刻度、让用户拖动播放头。它本身不保存时间，拖动之后改的是 `clock.currentTime`，所以时钟没配置正确时，时间轴上的刻度就会失真。

`timeline.zoomTo(start, end)` 改的是控件显示范围，不是时钟区间。两者不一致时最典型的现象是：时间轴很长，播放头只在中间一小段里移动。正确顺序是先设 `clock.startTime` / `clock.stopTime`，再用相同端点调用 `zoomTo`；换数据集时两处都要更新。

`settime` 在用户操作时间轴之后触发，回调的 `e` 里带有新的时间。拖动过程中这个事件会连续触发，可用来同步界面上的时间标签，或者按新时刻请求瓦片；不要在回调里同步发起大量网络请求，应当把请求做成可取消的，并在下一次事件里覆盖掉上一次未完成的请求。

时间轴和右下角的动画控件（`viewer.animation`）是配套的：后者提供播放/暂停按钮与倍率下拉框，操作结果同样是改写 clock。不需要它们时，最干净的做法是在创建 Viewer 时传入 `timeline: false`、`animation: false`，控件根本不会生成；运行期间临时隐藏可以设 `viewer.timeline.container.style.display = 'none'`，注意隐藏的是容器而不是删除 DOM，Cesium 内部仍会向它写入状态。

```javascript
const timeline = viewer.timeline;

// 缩放时间轴
timeline.zoomTo(
    Cesium.JulianDate.fromIso8601('2024-01-01'),
    Cesium.JulianDate.fromIso8601('2024-01-31')
);

// 监听时间轴事件
timeline.addEventListener('settime', function(e) {
    console.log('时间轴时间改变');
}, false);
```

## 13.3 时间动态属性

实体上的每个可视化属性——位置、颜色、材质、显隐——既能接受常量，也能接受 `Property`。Property 的本质是一个以时间为入参的函数：渲染前 Cesium 拿着当前时刻调用它的 `getValue(time, result)`，得到这一帧该用的值。常量会被自动包装成 `ConstantProperty`，所以“传常量”和“传 Property”在渲染管线上走的是同一条路。

理解这一点之后，动态效果就不必依赖轮询和手动赋值：把采样数据交给 Cesium，插值、求值、重绘都由引擎按帧完成，时间轴一拖动，画面立即跟着变。下面三节分别介绍连续插值、离散区间和手动补间三类做法，它们的适用场景并不重叠。

### 13.3.1 SampledProperty

`SampledPositionProperty` 是带插值的位置属性：给它若干“时刻—位置”样本，中间时刻由插值算法补出来。示例严格按时间顺序添加样本，这是推荐做法：样本时刻决定了覆盖区间，乱序或重复时刻会让求值结果难以预料，加样本前先排序、去掉重复时刻更稳妥。

`setInterpolationOptions` 的两个参数要一起看。`interpolationAlgorithm` 决定用什么曲线穿过样本点，`interpolationDegree` 决定曲线的阶数。默认是线性插值，相邻样本之间拉直线，拐点生硬；`LagrangePolynomialApproximation` 用拉格朗日多项式，5 阶意味着曲线同时穿过相邻六个样本，连续性好，但样本稀疏、方向变化剧烈时会出现过冲，模型在转弯处短暂甩到航迹外侧。航迹数据一般按等时间间隔采样，用 5 阶 Lagrange 问题不大；弯道密集或采样点很少时，把阶数降到 2 到 3 更稳，或者补采样点。`HermitePolynomialApproximation` 在插值时还会利用速度信息，适用于已知速度矢量的轨迹。

样本时间不必等间隔，这一点在解析真实 GPS 数据时很重要：设备可能在拐弯时提高采样频率，直道上间隔很疏。Cesium 按时间轴插值，间隔不均匀不会导致错误，只意味着速度快慢由样本时刻本身决定。

超出首尾样本时刻之后如何取值，由 `forwardExtrapolationType` 与 `backwardExtrapolationType` 控制：`NONE` 返回 undefined，实体直接消失；`HOLD` 保持端点样本值；`EXTRAPOLATE` 沿着最后一段的趋势外推。位置一旦求值为 undefined，依赖它的 `path`、`orientation` 也会一并失效，画面上就是整条航迹闪断。给实体添加 `availability` 区间，把有效时间显式限定在样本覆盖范围内，比依赖默认值更可控。

`availability` 是 `TimeIntervalCollection`，可以包含多段不连续区间，实体只在这些区间内被渲染。`path.leadTime` 与 `path.trailTime` 以秒为单位控制轨迹画多长：`trailTime: 3600` 表示只画当前时刻往前一小时的部分，`leadTime` 则向未来方向延伸，两者为 0 时轨迹退化成当前点。`VelocityOrientationProperty` 通过相邻采样点的位置差推算朝向，只对运动中的模型有意义，用来给飞机、车辆摆正机头。

`viewer.trackedEntity = movingEntity` 把相机锁到实体上，默认保持一个斜俯视角。用户一旦拖动鼠标，Cesium 会解除跟踪，这是正常行为；需要在跟踪解除时做界面同步，可以监听 `viewer.trackedEntityChanged`。

```javascript
// 创建采样位置属性
const positionProperty = new Cesium.SampledPositionProperty();

// 添加采样点
const times = [
    Cesium.JulianDate.fromIso8601('2024-01-01T00:00:00Z'),
    Cesium.JulianDate.fromIso8601('2024-01-01T01:00:00Z'),
    Cesium.JulianDate.fromIso8601('2024-01-01T02:00:00Z')
];
const positions = [
    Cesium.Cartesian3.fromDegrees(116.0, 39.0, 1000),
    Cesium.Cartesian3.fromDegrees(117.0, 39.5, 2000),
    Cesium.Cartesian3.fromDegrees(118.0, 40.0, 1500)
];

for (let i = 0; i < times.length; i++) {
    positionProperty.addSample(times[i], positions[i]);
}

// 设置插值
positionProperty.setInterpolationOptions({
    interpolationDegree: 5,
    interpolationAlgorithm: Cesium.LagrangePolynomialApproximation
    // Cesium.LinearApproximation
    // Cesium.HermitePolynomialApproximation
});

// 创建动态实体
const movingEntity = viewer.entities.add({
    name: '移动对象',
    availability: new Cesium.TimeIntervalCollection([
        new Cesium.TimeInterval({
            start: times[0],
            stop: times[times.length - 1]
        })
    ]),
    position: positionProperty,
    orientation: new Cesium.VelocityOrientationProperty(positionProperty),
    model: {
        uri: 'aircraft.glb',
        scale: 100
    },
    path: {
        material: Cesium.Color.YELLOW,
        width: 2,
        leadTime: 0,
        trailTime: 3600
    }
});

// 跟踪实体
viewer.trackedEntity = movingEntity;
```

### 13.3.2 其他动态属性

`SampledProperty` 的第一个参数是值类型，构造时就确定了整条属性只能存放什么：`Cesium.Color`、`Number`、`Cesium.Cartesian3` 都行，`addSample` 传入的值类型不对会立即抛错。颜色插值按 RGBA 四个分量各自线性过渡，两个色相相差很大时中间会经过灰色带，这是 RGB 插值的固有现象，需要色相平滑要自己按 HSL 采样。数值属性则可以直接驱动 `model.scale`、`point.pixelSize` 这类标量。

`TimeIntervalCollectionProperty` 不插值：时刻落在某个区间里就返回该区间 `data` 上的值，落在所有区间之外返回 undefined。颜色的变化是“跳变”，没有过渡。它适合表达离散状态，比如白天与夜晚两套配色、施工阶段的符号切换、时段限行区域的高亮。

建区间时注意端点归属：`Cesium.TimeInterval` 的 `isStartIncluded` 与 `isStopIncluded` 默认都是 true，两段相邻的 `[t0, t1]` 与 `[t1, t2]` 在 t1 这个时刻会同时命中，最终取哪个取决于区间在集合里的顺序，排查起来很费时间。把不包含端点的那个区间显式写成 `isStartIncluded: false`，让相邻区间首尾错开，行为就确定了。区间之间有空隙时求值为 undefined，这可以用来表达“该时刻这个对象不存在”。

```javascript
// 采样颜色属性
const colorProperty = new Cesium.SampledProperty(Cesium.Color);
colorProperty.addSample(times[0], Cesium.Color.RED);
colorProperty.addSample(times[1], Cesium.Color.GREEN);
colorProperty.addSample(times[2], Cesium.Color.BLUE);

// 采样数值属性
const scaleProperty = new Cesium.SampledProperty(Number);
scaleProperty.addSample(times[0], 1.0);
scaleProperty.addSample(times[1], 2.0);
scaleProperty.addSample(times[2], 1.5);

// 时间区间颜色
const timeIntervalColor = new Cesium.TimeIntervalCollectionProperty();
timeIntervalColor.intervals.addInterval(new Cesium.TimeInterval({
    start: times[0],
    stop: times[1],
    data: Cesium.Color.RED
}));
timeIntervalColor.intervals.addInterval(new Cesium.TimeInterval({
    start: times[1],
    stop: times[2],
    data: Cesium.Color.BLUE
}));
```

## 13.4 场景动画

场景里的动画有两类实现路线，选型时先问一句“这个动画需不需要跟时间轴同步”。需要同步、需要回拖、需要暂停后从中间继续的，把数据做成 Property 交给时钟，即 13.3 节的做法；只是一次性的视觉反馈，比如选中要素放大、加载完成后淡出，用 `requestAnimationFrame` 直接改属性更直接，也不占用时间轴。

### 13.4.1 属性动画

这段代码用 `performance.now()` 记录起点，每一帧算出已经过去多少毫秒，除以总时长得到 0 到 1 之间的进度，再用缓动函数把进度映射成缩放值。`performance.now()` 单调递增且精度高于 `Date.now()`，不受系统时间调整影响，是手动补间的标准计时源。

`Math.min(elapsed / (duration * 1000), 1)` 的截断不能省。最后一帧的时间差通常会略微超过总时长，不截断的话 `QUADRATIC_IN_OUT` 收到的参数大于 1，缓动函数的输出跟着越界，缩放值会冲过目标再回弹一下。`Cesium.EasingFunction.QUADRATIC_IN_OUT` 是函数表上的静态函数，输入输出都在 0 到 1 区间，端点处速度为零、中段最快，适合“从 A 到 B 看似自然”的过渡；线性过渡直接用 progress，需要回弹可以换 `BACK_OUT` 之类的函数。

直接给 `entity.model.scale` 赋值，等价于每帧把常量包装成 `ConstantProperty` 重新挂上去。对少量实体无妨，几百个实体同时缩放就值得换成 `CallbackProperty`，或者把动画做进 `Cesium.Model` 的矩阵里。这段代码还隐含一个前提：实体本身已经带有 `model` 组件，否则 `entity.model` 是 undefined，赋值会抛异常。做通用工具函数时先判空，缺失组件就跳过。

`requestAnimationFrame` 在标签页切到后台时会被暂停，而 `performance.now()` 不会停。切回来时 progress 已经远超 1，画面直接跳到终点，这是正常现象；如果业务上要求“后台时保持动画连续”，就要监听 `visibilitychange`，在重新可见时重置起点。另外这段代码没有保存 `requestAnimationFrame` 的返回值，也没有取消逻辑，组件销毁后回调仍可能再跑一次并访问已删除的实体，封装成类时把 rafId 存下来，在 `destroy` 里 `cancelAnimationFrame` 更稳妥。

```javascript
// 实体属性动画
function animateEntityScale(entity, fromScale, toScale, duration) {
    const startTime = performance.now();
    
    function animate() {
        const elapsed = performance.now() - startTime;
        const progress = Math.min(elapsed / (duration * 1000), 1);
        
        // 缓动函数
        const easedProgress = Cesium.EasingFunction.QUADRATIC_IN_OUT(progress);
        const currentScale = fromScale + (toScale - fromScale) * easedProgress;
        
        entity.model.scale = currentScale;
        
        if (progress < 1) {
            requestAnimationFrame(animate);
        }
    }
    
    animate();
}

// 颜色渐变动画
function animateColor(entity, fromColor, toColor, duration) {
    const startTime = performance.now();
    
    function animate() {
        const elapsed = performance.now() - startTime;
        const progress = Math.min(elapsed / (duration * 1000), 1);
        
        const currentColor = Cesium.Color.lerp(fromColor, toColor, progress, new Cesium.Color());
        
        if (entity.polygon) {
            entity.polygon.material = currentColor;
        }
        
        if (progress < 1) {
            requestAnimationFrame(animate);
        }
    }
    
    animate();
}
```

### 13.4.2 轨迹动画

`TrajectoryAnimation` 把轨迹拆成三块：数据（waypoints）、时长（duration）、由前两者生成的时钟区间和采样属性。`create` 里做的顺序很关键——先确定起止时刻并写入 clock，再按时刻生成位置样本，最后创建实体并挂上 `availability`。顺序颠倒时，实体可能先于时钟区间创建，第一帧的 `currentTime` 落在区间之外，表现为动画开头短暂空白。

起止时刻用 `Cesium.JulianDate.now()` 取当前系统时刻，而不是写死日期。这样每次调用 `create` 时间轴都从“现在”开始，重复播放时不用手工改时间；如果希望每次演示都从固定日期起步（比如回放历史轨迹），把 `now()` 换成 `fromIso8601` 传入数据采集的起始时间即可。

`interval = duration / (waypoints.length - 1)` 把总时长均分给相邻点之间的路段，最后一个点正好落在 `stopTime` 上。这里隐含一个假设：路段的实际长度与时间间隔无关，因此点距大的路段走得快、点距小的走得慢。真实轨迹要求匀速时，得按每段的地理距离分配时间，用 `Cesium.Cartesian3.distance` 累加距离做权重即可。

`multiplier` 保持 1，`clockRange` 用 `LOOP_STOP`，动画播到末端会回到起点继续，适合展厅大屏这类不断循环的场景；要只播一遍，改成 `CLAMPED`，播放到 `stopTime` 停住。`setSpeed` 直接改倍率，传负数就是倒放，不需要重建轨迹。`path.trailTime` 设为总时长，已走过的整条轨迹都留在画面上，形成尾迹效果；想只保留最近一段，把 `trailTime` 改成十几秒。

`destroy` 里移除了实体，但相机可能仍然处于跟踪状态，删除被跟踪实体之前先把 `viewer.trackedEntity` 置为 undefined，可以避免相机停在旧位置、用户再也找不回全局视角。如果外部还给实体绑定了 `ScreenSpaceEventHandler` 或 `CallbackProperty`，也要在这时一并解除。

```javascript
// 创建轨迹动画
class TrajectoryAnimation {
    constructor(viewer, waypoints, options = {}) {
        this.viewer = viewer;
        this.waypoints = waypoints;
        this.duration = options.duration || 60;  // 秒
        this.entity = null;
    }
    
    create() {
        const startTime = Cesium.JulianDate.now();
        const stopTime = Cesium.JulianDate.addSeconds(startTime, this.duration, new Cesium.JulianDate());
        
        // 配置时钟
        this.viewer.clock.startTime = startTime.clone();
        this.viewer.clock.stopTime = stopTime.clone();
        this.viewer.clock.currentTime = startTime.clone();
        this.viewer.clock.clockRange = Cesium.ClockRange.LOOP_STOP;
        this.viewer.clock.multiplier = 1;
        
        // 创建位置属性
        const positionProperty = new Cesium.SampledPositionProperty();
        const interval = this.duration / (this.waypoints.length - 1);
        
        this.waypoints.forEach((wp, i) => {
            const time = Cesium.JulianDate.addSeconds(startTime, i * interval, new Cesium.JulianDate());
            const position = Cesium.Cartesian3.fromDegrees(wp.lon, wp.lat, wp.height || 0);
            positionProperty.addSample(time, position);
        });
        
        positionProperty.setInterpolationOptions({
            interpolationDegree: 5,
            interpolationAlgorithm: Cesium.LagrangePolynomialApproximation
        });
        
        // 创建实体
        this.entity = this.viewer.entities.add({
            name: '动画对象',
            availability: new Cesium.TimeIntervalCollection([
                new Cesium.TimeInterval({ start: startTime, stop: stopTime })
            ]),
            position: positionProperty,
            orientation: new Cesium.VelocityOrientationProperty(positionProperty),
            point: { pixelSize: 12, color: Cesium.Color.RED },
            path: {
                material: Cesium.Color.YELLOW,
                width: 2,
                trailTime: this.duration
            }
        });
        
        return this.entity;
    }
    
    play() {
        this.viewer.clock.shouldAnimate = true;
    }
    
    pause() {
        this.viewer.clock.shouldAnimate = false;
    }
    
    setSpeed(multiplier) {
        this.viewer.clock.multiplier = multiplier;
    }
    
    track() {
        this.viewer.trackedEntity = this.entity;
    }
    
    destroy() {
        if (this.entity) {
            this.viewer.entities.remove(this.entity);
            this.entity = null;
        }
    }
}

// 使用
const animation = new TrajectoryAnimation(viewer, [
    { lon: 116.0, lat: 39.0, height: 1000 },
    { lon: 117.0, lat: 39.5, height: 2000 },
    { lon: 118.0, lat: 40.0, height: 1500 },
    { lon: 119.0, lat: 39.5, height: 1000 }
], { duration: 120 });

animation.create();
animation.track();
animation.play();
```

## 13.5 本章小结

时间相关的代码出错时，现象往往很隐蔽，按下面的顺序排查能覆盖大多数情况。画面不动：先看 `viewer.clock.shouldAnimate`，默认是 false；再看 `multiplier` 是否为 0；再看 `clockRange` 是否已经把播放头钉在端点。时间显示在 1970 年：检查是不是把 Date 或时间戳直接赋给了 JulianDate 类型的字段。动画速度忽快忽慢：检查 `clockStep` 是否被设成了 `TICK_DEPENDENT`，帧率波动会直接传到时间推进上。时间轴拖不动或者刻度不对：检查 `zoomTo` 的端点和 `clock.startTime/stopTime` 是否一致。
