# 第15章：样式与可视化效果

## 15.1 颜色与材质

三维场景里的“样式”和二维地图里的符号概念不同。二维地图的符号是一张事先画好的图，属性决定用哪张图；Cesium 里的样式最终要落到着色器参数上——颜色值、纹理、透明度、线宽，都由 GPU 在绘制时读取。正因为如此，同一个颜色常量可以用在点、线、面、模型上，而材质则是“这个面怎么着色”的具体策略，两者不在一个层次上。

选择用常量颜色还是材质属性，先看数据会不会随时间变化。颜色、材质都可以是 `Property`，即具有 `getValue(time)` 方法的对象；传入常量时 Cesium 会自动包装成 `ConstantProperty`。手工补间动画、按属性分色这类需求，最终都要把材质写成 `CallbackProperty` 或者 `ColorMaterialProperty`，直接在渲染循环里改常量是最低频的做法。

### 15.1.1 颜色定义

`Cesium.Color` 的内部存储是四个 0 到 1 的浮点分量，顺序为红、绿、蓝、透明度。`new Cesium.Color(1.0, 0.0, 0.0, 1.0)` 构造纯红，四个参数都必须给；只传三个时透明度不会被省略成 1，旧版本会直接报参数数量错误，写代码时不要依赖“默认值”的猜测。

实际开发中更常用的是 `fromCssColorString`——设计稿里的色值本来就是 `#RRGGBB` 或 `rgba(...)` 形式，交给它转换比手动除以 255 可靠。注意这个方法遇到无法解析的字符串时不会抛异常，而是返回 undefined，随后赋给材质会导致该图元不渲染；把解析结果先判空，是排查“某类要素莫名消失”的一个常规步骤。

`withAlpha` 不改原对象，而是返回一个新颜色实例。很多人写成 `entity.color = color.withAlpha(0.5)` 之后又用 `color` 去设置别的图元，结果第二个图元完全没有透明度变化——`color` 本身没被修改。需要就地修改用 `withAlpha(alpha, result)` 把结果写进同一个实例，或者直接用 `Color.fromAlpha(source, alpha, result)` 复用对象减少 GC 压力。

`fromHsl` 的第一个参数是色相，取值 0 到 1（不是 0 到 360），第二、三个参数是饱和度与亮度。做“按数值映射色相”的专题图时用它最方便：把数值归一化到 0 到 1 作为色相，就能得到一条彩虹渐变，不必手写 RGB 分量。`fromRandom` 主要用在调试阶段区分不同要素，`options.alpha` 可以固定透明度，还可以传入 `minimumRed` 这类上下界约束取值范围。

```javascript
// 预定义颜色
Cesium.Color.RED
Cesium.Color.GREEN
Cesium.Color.BLUE
Cesium.Color.YELLOW
Cesium.Color.WHITE
Cesium.Color.BLACK
Cesium.Color.TRANSPARENT

// 带透明度
Cesium.Color.RED.withAlpha(0.5)

// CSS 颜色字符串
Cesium.Color.fromCssColorString('#ff0000')
Cesium.Color.fromCssColorString('rgb(255, 0, 0)')
Cesium.Color.fromCssColorString('rgba(255, 0, 0, 0.5)')

// RGBA 值 (0-1)
new Cesium.Color(1.0, 0.0, 0.0, 1.0)

// 字节值 (0-255)
Cesium.Color.fromBytes(255, 0, 0, 255)

// HSL
Cesium.Color.fromHsl(0.0, 1.0, 0.5, 1.0)

// 随机颜色
Cesium.Color.fromRandom({ alpha: 0.8 })
```

### 15.1.2 材质类型

材质属性只对“面”类图元有意义——多边形、矩形、椭圆、墙体、圆柱的侧面。它们的共同点是最终由三角面片光栅化，着色器可以在面片内按纹理坐标取色。点、标签、折线走的是另一条绘制路径，把 `ImageMaterialProperty` 赋给 `point` 不起作用，也不会报错，这是样式“设了没效果”最常见的原因之一。

`ImageMaterialProperty` 的 `image` 可以接收图片 URL、`HTMLImageElement` 或者 canvas 元素。传入 canvas 时，Cesium 在需要时把它的当前内容上传为纹理；因为纹理上传有缓存，后续对 canvas 的绘制要重新触发上传，最稳的方式每次生成新的 `HTMLCanvasElement` 或给图片 URL 加时间戳参数。`repeat` 是纹理在面内重复的次数，`transparent: true` 让图片的透明通道参与混合。

程序化材质的好处是不依赖外部图片资源，颜色、间距都能由参数驱动。`StripeMaterialProperty` 画条纹，`repeat` 是条纹周期数，`offset` 平移相位，`orientation` 决定横竖；`GridMaterialProperty` 画方格，`cellAlpha` 控制格内透明度，`lineCount` 与 `lineThickness` 都接受 `Cartesian2`，分别控制横向纵向的数量与线宽；`CheckerboardMaterialProperty` 与 `DotMaterialProperty` 同理。这些材质本质上是着色器里按纹理坐标算出来的图案，缩放地图时图案密度保持不变，适合做规划范围、矿区边界这类示意表达。

需要注意材质对象挂在实体上之后，修改属性要改材质实例本身，而不是替换 `material`：`entity.polygon.material` 拿到的可能已经是 Cesium 包装过的 `ColorMaterialProperty`，取内部颜色需要访问 `material.color.getValue(time)`。类型判断错误时，赋值会被静默忽略，看控制台也不会有提示。

```javascript
// 纯色材质
entity.polygon.material = Cesium.Color.RED

// 图片材质
entity.polygon.material = new Cesium.ImageMaterialProperty({
    image: 'texture.png',
    repeat: new Cesium.Cartesian2(4, 4),
    transparent: true
})

// 条纹材质
entity.polygon.material = new Cesium.StripeMaterialProperty({
    evenColor: Cesium.Color.WHITE,
    oddColor: Cesium.Color.BLACK,
    repeat: 10,
    offset: 0,
    orientation: Cesium.StripeOrientation.HORIZONTAL
})

// 网格材质
entity.polygon.material = new Cesium.GridMaterialProperty({
    color: Cesium.Color.YELLOW,
    cellAlpha: 0.2,
    lineCount: new Cesium.Cartesian2(8, 8),
    lineThickness: new Cesium.Cartesian2(2, 2)
})

// 棋盘格材质
entity.polygon.material = new Cesium.CheckerboardMaterialProperty({
    evenColor: Cesium.Color.WHITE,
    oddColor: Cesium.Color.BLACK,
    repeat: new Cesium.Cartesian2(4, 4)
})

// 点阵材质
entity.polygon.material = new Cesium.DotMaterialProperty({
    lightColor: Cesium.Color.WHITE,
    darkColor: Cesium.Color.BLACK,
    repeat: new Cesium.Cartesian2(8, 8)
})
```

### 15.1.3 折线材质

折线的材质参数里有两个容易踩坑的地方：`width` 与 `dashLength`。线宽在多数桌面浏览器上会被 WebGL 实现截断为 1 像素，`polyline.width = 5` 看起来和 1 没区别，这是底层 `gl.LINES` 的限制，解决办法是改用 `PolylineVolume` 或者用带纹理的 `Corridor` 几何体来画粗线。虚线则依赖 `PolylineDashMaterialProperty` 的着色器计算，导线宽度较大时才能看清断口。

`dashLength` 单位是像素，不是米，缩放场景时虚线密度不变。`dashPattern` 是一个 16 位整数，每一位代表该段是否绘制，`parseInt('1111000011110000', 2)` 表示画四段空四段。直接写十进制数字（例如 61440）也可以工作，但没人看得懂；用二进制字符串再解析更易维护。修改 `dashPattern` 后必须换一个新的材质实例才会生效，因为属性值在材质创建时就被读取了一次。

`PolylineArrowMaterialProperty` 在整条线的终点处画箭头，适合表达流向；它的箭头大小随线宽变化，线宽被限制为 1 像素时箭头会小得几乎看不见。`PolylineGlowMaterialProperty` 用叠加发光的做法模拟光晕，`glowPower` 越大光斑越集中，`taperPower` 控制两端收细的程度，常见于航线、管线的高亮。`PolylineOutlineMaterialProperty` 是实心线加描边，`outlineWidth` 同样受线宽限制影响。

折线材质在贴地模式下有一个额外选项 `clampToGround`，开启后线会沿地形起伏绘制，但虚线、发光的像素级效果在没有深度信息的地表会失真，宁可改成 `heightReference: CLAMP_TO_GROUND` 并用普通实线。

```javascript
// 实线
entity.polyline.material = Cesium.Color.RED

// 虚线
entity.polyline.material = new Cesium.PolylineDashMaterialProperty({
    color: Cesium.Color.RED,
    dashLength: 16,
    dashPattern: parseInt('1111000011110000', 2)
})

// 箭头
entity.polyline.material = new Cesium.PolylineArrowMaterialProperty(Cesium.Color.RED)

// 发光
entity.polyline.material = new Cesium.PolylineGlowMaterialProperty({
    color: Cesium.Color.CYAN,
    glowPower: 0.3,
    taperPower: 1.0
})

// 轮廓
entity.polyline.material = new Cesium.PolylineOutlineMaterialProperty({
    color: Cesium.Color.RED,
    outlineWidth: 2,
    outlineColor: Cesium.Color.BLACK
})
```

## 15.2 后处理效果

后处理（post-processing）是把整个场景渲染到一张离屏纹理，再对这张纹理做全屏计算，最后把结果输出到屏幕。它影响的是“成品画面”，不是单个图元，所以能把泛光、抗锯齿、色调映射这类效果统一施加到地形、模型、影像、标签上——这是逐图元改材质做不到的。五光十色的效果背后是同一条固定管线，成本也固定：启用一个后处理阶段，就多一次全屏绘制。

### 15.2.1 内置后处理

`viewer.scene.postProcessStages` 上挂着 Cesium 预置的几个阶段，通过 `enabled` 开关，通过 `uniforms` 调参数。这些对象的创建是有条件的：`bloom`、`ambientOcclusion` 等在 `Viewer` 初始化时就按默认参数生成，直接访问 `.uniforms.xxx` 即可，不需要先 new 一个。

泛光（bloom）让亮部向外溢出光晕，常用于夜景、态势大屏。`brightness` 是亮度阈值，低于它的像素不参与发光；`glowOnly` 为 true 时只显示光晕、丢掉原画面，一般保持 false；`contrast`、`delta`、`sigma` 共同决定阈值过渡的柔和程度；`stepSize` 是采样步长，调大能提升性能但光晕会出现阶梯感。环境光遮蔽（ambient occlusion）在物体夹缝、墙角处压暗，`intensity` 是强度，`bias` 用来缓解自遮挡噪声，`lengthCap` 限制采样射线长度（数值与场景尺度相关），`frustumLength` 控制可视范围外的过渡。FXAA 是廉价的抗锯齿，开关没有参数，`enabled = true` 即可。

后处理阶段按添加顺序执行，顺序不同结果可能差别很大：先泛光再灰度，得到的是“黑白的光晕画面”；先灰度再泛光，阈值判断作用在灰度图上，只有接近白色的区域发光。Cesium 内置阶段的顺序由引擎决定，自定义阶段用 `postProcessStages.add` 追加在末尾。

性能上，移动端和集成显卡上同时开三个以上后处理阶段，帧率会明显下降。低配档位切换时，把各内置阶段的 `enabled` 逐个置 false 最直接；自定义阶段则从集合里 `remove` 掉。这些开关都是运行时可改的，不需要重建 Viewer。

```javascript
// 泛光效果
viewer.scene.postProcessStages.bloom.enabled = true
viewer.scene.postProcessStages.bloom.uniforms.brightness = 1.0
viewer.scene.postProcessStages.bloom.uniforms.glowOnly = false
viewer.scene.postProcessStages.bloom.uniforms.contrast = 128
viewer.scene.postProcessStages.bloom.uniforms.delta = 1.0
viewer.scene.postProcessStages.bloom.uniforms.sigma = 3.78
viewer.scene.postProcessStages.bloom.uniforms.stepSize = 5

// 环境光遮蔽
viewer.scene.postProcessStages.ambientOcclusion.enabled = true
viewer.scene.postProcessStages.ambientOcclusion.uniforms.intensity = 3.0
viewer.scene.postProcessStages.ambientOcclusion.uniforms.bias = 0.1
viewer.scene.postProcessStages.ambientOcclusion.uniforms.lengthCap = 0.03
viewer.scene.postProcessStages.ambientOcclusion.uniforms.stepSize = 1.0
viewer.scene.postProcessStages.ambientOcclusion.uniforms.frustumLength = 1000

// FXAA 抗锯齿
viewer.scene.postProcessStages.fxaa.enabled = true
```

### 15.2.2 自定义后处理

`PostProcessStage` 接收一段片元着色器，输入是上一阶段的渲染结果，输出是颜色。着色器约定几件事：`colorTexture` 是采样纹理，`v_textureCoordinates` 是当前像素的纹理坐标，输出写进 `out_FragColor`。Cesium 会把这段代码拼接到内置的顶点着色器之后，所以不要自己声明 `in`/`out` 之外的全局变量，也不要写 `#version`。

两段示例都是逐像素操作：灰度效果按 0.299、0.587、0.114 的权重把 RGB 加权求和，这是常用的亮度公式，人眼对绿色最敏感，权重最大；反色效果用 `vec3(1.0) - color.rgb`，透明通道保持原值，避免半透明区域的反色结果被误判为不透明。

`viewer.scene.postProcessStages.add(stage)` 把阶段追加到管线末尾，阶段对象可以之后通过 `stage.enabled` 开关。重复添加同一个实例没有意义，重复添加多个实例会叠加执行。想只对画面的一部分生效，`PostProcessStage` 本身没有区域参数：可以在着色器里用 `v_textureCoordinates` 自己判断范围，或者换用 `PostProcessStageComposite` 组合多个阶段来做局部处理。

自定义着色器里的常量最好走 uniform 传，而不是把数值写死在字符串里：`new PostProcessStage({ fragmentShader, uniforms: { uStrength: 0.5 } })`，着色器里声明 `uniform float uStrength;`，运行时改 `stage.uniforms.uStrength = ...` 就能实时调整，不必重建阶段——重建阶段会触发着色器重新编译，有明显卡顿。

```javascript
// 灰度效果
const grayscaleStage = new Cesium.PostProcessStage({
    fragmentShader: `
        uniform sampler2D colorTexture;
        in vec2 v_textureCoordinates;
        
        void main() {
            vec4 color = texture(colorTexture, v_textureCoordinates);
            float gray = dot(color.rgb, vec3(0.299, 0.587, 0.114));
            out_FragColor = vec4(vec3(gray), color.a);
        }
    `
});
viewer.scene.postProcessStages.add(grayscaleStage);

// 反色效果
const invertStage = new Cesium.PostProcessStage({
    fragmentShader: `
        uniform sampler2D colorTexture;
        in vec2 v_textureCoordinates;
        
        void main() {
            vec4 color = texture(colorTexture, v_textureCoordinates);
            out_FragColor = vec4(vec3(1.0) - color.rgb, color.a);
        }
    `
});
viewer.scene.postProcessStages.add(invertStage);
```

## 15.3 光照与阴影

光照是场景级的开关，影响所有受光材质：地形、三维模型、多边形。二维符号（点、标签、折线）不受光照影响，颜色始终是设定值，这也是同一套配色在白天和夜晚模式下观感不一致的原因之一。

`globe.enableLighting = true` 打开地表光照，`dynamicAtmosphereLighting` 让大气颜色随太阳位置变化，两者配合才是有意义的“昼夜交替”，只开前者会出现地表变暗但天空仍然亮着的割裂感。太阳位置由时钟决定，所以时间轴拖到夜里，场景自然变暗，这也是第 13 章时钟系统的直接应用。

阴影需要一个可用的光源和一张阴影贴图。`viewer.shadows = true` 打开模型阴影，`viewer.terrainShadows` 决定地形是否参与投影，`Cesium.ShadowMode.ENABLED` 表示地形既接收也投射阴影；`Cesium.ShadowMode.RECEIVE_ONLY` 只接收不投射，性能更好。`shadowMap.size` 是阴影贴图边长，2048 相比 1024 更清晰但显存翻倍；`softShadows` 用多次采样软化边缘；`darkness` 控制阴影浓度，0 表示完全不压暗。

`viewer.scene.light` 默认是一个随太阳方向变化的光源。替换成 `DirectionalLight` 可以固定光照方向，让同一天的任何时刻画面一致，适合做汇报截图；`intensity` 大于 1 会过曝，需要同步调低材质颜色或开启色调映射。自定义光源后 `enableLighting` 的语义不变，但太阳位置不再影响画面，`dynamicAtmosphereLighting` 的天空颜色仍由时钟计算，两处不再自洽，演示昼夜时要考虑是否保留。

```javascript
// 启用光照
viewer.scene.globe.enableLighting = true
viewer.scene.globe.dynamicAtmosphereLighting = true

// 阴影配置
viewer.shadows = true
viewer.terrainShadows = Cesium.ShadowMode.ENABLED

const shadowMap = viewer.scene.shadowMap
shadowMap.enabled = true
shadowMap.size = 2048
shadowMap.softShadows = true
shadowMap.darkness = 0.3

// 自定义光源
viewer.scene.light = new Cesium.DirectionalLight({
    direction: new Cesium.Cartesian3(0.5, -0.5, -0.5),
    color: Cesium.Color.WHITE,
    intensity: 2.0
})
```

## 15.4 热力图效果

这段代码的思路是借浏览器的 2D 画布做“伪热力”：先在一个固定尺寸的 canvas 上按数据点画径向渐变，再把整张 canvas 作为纹理铺到一个覆盖研究范围的矩形上。热力图的计算全在 CPU 完成，Cesium 只负责把结果贴到地表；数据点规模在几百到几千时够用，上万点就要换方案——要么预渲染成图片瓦片，要么写自定义着色器在 GPU 里计算。

径向渐变的构造方式是每次循环 `createRadialGradient(x, y, 0, x, y, radius)`，内圈用点的强度作为透明度，外圈全透明，然后 `fillRect` 出一块方形区域。多个点叠加时，`alpha` 按 `globalCompositeOperation` 的方式混合，默认的 `source-over` 会把重叠区越叠越亮，形成自然的聚集效果；如果效果太平，可以在绘制前设置 `ctx.globalCompositeOperation = 'lighter'` 加强叠加。

原代码存在一处必须补上的缺陷：构造函数没有给 `this.bounds` 赋值，而 `create` 里直接用 `this.bounds.west` 取范围，运行时会抛 `Cannot read property 'west' of undefined`。调用方必须显式传入边界，例如把 `options.bounds` 存成 `this.bounds = options.bounds`，或者在构造时根据数据点坐标算出包围盒。这是抄示例代码时最容易漏掉的一行。

另外，矩形铺在地表时应当配合 `heightReference: Cesium.HeightReference.CLAMP_TO_GROUND`，否则默认高度为 0，在山地会出现热力图悬空或被地形遮挡。canvas 尺寸固定为 512×512，放大后纹理被拉伸会发糊，研究范围较大时把尺寸提到 1024 或按范围的长宽比设置，清晰度会明显改善。`ImageMaterialProperty` 的 `transparent: true` 必须保留，否则画布透明区域会显示成黑色。

```javascript
// 简单热力图实现
class HeatmapLayer {
    constructor(viewer, data, options = {}) {
        this.viewer = viewer
        this.data = data
        this.radius = options.radius || 20
        this.blur = options.blur || 15
        this.entity = null
    }
    
    create() {
        // 使用 Canvas 生成热力图
        const canvas = document.createElement('canvas')
        canvas.width = 512
        canvas.height = 512
        const ctx = canvas.getContext('2d')
        
        // 绘制热力点
        this.data.forEach(point => {
            const gradient = ctx.createRadialGradient(
                point.x, point.y, 0,
                point.x, point.y, this.radius
            )
            gradient.addColorStop(0, `rgba(255, 0, 0, ${point.intensity})`)
            gradient.addColorStop(1, 'rgba(255, 0, 0, 0)')
            
            ctx.fillStyle = gradient
            ctx.fillRect(point.x - this.radius, point.y - this.radius, 
                         this.radius * 2, this.radius * 2)
        })
        
        // 添加到场景
        this.entity = this.viewer.entities.add({
            rectangle: {
                coordinates: Cesium.Rectangle.fromDegrees(
                    this.bounds.west, this.bounds.south,
                    this.bounds.east, this.bounds.north
                ),
                material: new Cesium.ImageMaterialProperty({
                    image: canvas,
                    transparent: true
                })
            }
        })
    }
    
    remove() {
        if (this.entity) {
            this.viewer.entities.remove(this.entity)
        }
    }
}
```

## 15.5 本章小结

样式相关的问题大多出在三个地方：图元类型与材质的匹配、属性对象的传递方式、后处理开关的作用范围。多边形设了图片材质不显示，先确认颜色纹理有没有被跨域策略拦下；点设置材质不生效，先确认材质只服务于面图元；修改颜色后画面没反应，先确认改的是属性实例还是被 Cesium 包装过的只读外壳。光照和阴影属于整场景行为，调试时一次只开一个，能更快定位是颜色问题还是光线问题。

本章介绍了样式与可视化效果：

1. **颜色材质**：颜色定义、各种材质类型
2. **后处理**：泛光、环境光遮蔽、自定义效果
3. **光照阴影**：光照配置、阴影设置
4. **热力图**：简单热力图实现
