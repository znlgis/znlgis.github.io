# 第13章 - 地图事件与动画

## 13.1 事件系统

OpenLayers 的事件体系建立在 `ol/Observable` 上，`map`、`view`、`layer`、`source` 都是可观察对象，用 `on(type, listener)` 注册、用 `un(type, listener)` 注销。事件对象的类型和属性因事件而异，但都带 `target`，可以从它反查是哪个对象触发的。事件机制是整个交互的基础：点击拾取、图层联动、面板同步、动画驱动，最终都落在某个事件回调里。

事件回调的执行频率差异极大。`movestart`、`moveend` 在每次拖动时各触发一次，`pointermove` 每帧可能触发多次，`postrender` 也是每帧。在这些高频事件里做重活（遍历要素、算几何、发请求）会直接拖慢渲染，因为回调与渲染同在主线程。判断标准很简单：回调里如果出现的操作在 1000 个要素上执行，就一定会卡。

### 13.1.1 地图事件

`click` 是底层事件，鼠标按下再抬起就触发；`singleclick` 会等一小段延时确认没有第二次点击才触发。两者的区别在交互场景里很实际：双击缩放时，`click` 会先触发两次，然后才触发 `dblclick`；用 `singleclick` 做要素选中，可以避免双击时误选中。选中逻辑优先用它。

`event.coordinate` 是地图坐标（视图投影，默认 EPSG:3857），`event.pixel` 是屏幕像素坐标。`map.forEachFeatureAtPixel(pixel, callback)` 用像素坐标做拾取，`map.getCoordinateFromPixel(pixel)` 把像素转成地图坐标。这两个坐标系不要混用：用 `coordinate` 去做像素拾取，永远拾不到东西，而且不会报错。

双击回调里的 `event.preventDefault()` 置位的是 OpenLayers 事件对象的传播标志，影响后续监听器，不会撤销浏览器或交互层的默认行为；它也不阻止已经排队等待判定的 `click`、`singleclick`。地图的双击缩放由 `DoubleClickZoom` 交互提供，要彻底禁用应当 `map.removeInteraction` 掉它，或者创建地图时不注册。

`pointermove` 回调里判断 `event.dragging`，拖动中不做悬停检测，这是必要的性能优化。悬停检测通常要调用 `forEachFeatureAtPixel`，它要遍历所有可见图层、逐个命中测试，代价不低；指针每移动一像素就做一次，不节流的话滚动地图会明显掉帧。更稳妥的做法是用 `requestAnimationFrame` 合并同一帧内的多次移动事件，或者只在移动距离超过阈值时才重新检测。

`movestart`、`moveend` 描述的是视图状态的变化，不是鼠标动作。用动画跳转时也会触发，`moveend` 是“动画结束或拖动结束”的统一出口，适合在它里面做数据加载、地址反查、范围统计。注意 `moveend` 在连续拖动中只触发一次，拖动过程中的中间状态要用 `moveend` 之外的事件（如 `pointermove`）配合。

`postrender` 每帧渲染后触发，`rendercomplete` 在所有图层都完成渲染后触发——瓦片没加载完时 `postrender` 会持续触发，而 `rendercomplete` 要等瓦片到齐。截图、导出这类操作必须等 `rendercomplete`，用 `postrender` 可能拿到空白瓦片。动画驱动的场景（13.3.2）反过来要用 `postrender`，因为它每帧都要重绘。

```javascript
// 点击事件
map.on('click', (event) => {
  console.log('坐标:', event.coordinate);
  console.log('像素:', event.pixel);
});

// 单击（等待确认不是双击）
map.on('singleclick', (event) => {
  console.log('单击');
});

// 双击
map.on('dblclick', (event) => {
  event.preventDefault(); // 阻止默认缩放
});

// 指针移动
map.on('pointermove', (event) => {
  if (!event.dragging) {
    // 悬停检测
  }
});

// 地图移动
map.on('movestart', () => console.log('移动开始'));
map.on('moveend', () => console.log('移动结束'));

// 渲染事件
map.on('postrender', () => { /* 每帧渲染后 */ });
map.on('rendercomplete', () => { /* 渲染完成 */ });
```

### 13.1.2 视图事件

`change:center`、`change:resolution`、`change:rotation` 是属性变更事件，只在属性真正变化时触发。拖动地图的过程中这些事件不会逐像素触发，因为 `View` 内部对连续变化的属性做了动画式更新——它是在“动画帧”里改属性，每次 `setCenter` 调用只触发一次。所以监听这几个事件做业务处理，频率是可控的。

`change:resolution` 里通常不直接读 `getResolution()`，而是用 `getZoom()`。分辨率是“每个像素代表多少地图单位”，随投影变化；缩放级别是视图对分辨率的封装，更接近用户的直觉。两者换算关系是 `resolution = initialResolution / 2^zoom`，不同投影的 `initialResolution` 不同，硬编码换算会出错。

这几个事件只在视图层面变化时触发，不区分是用户操作还是代码调用。要在事件里区分来源，只能自己加标志位（比如调用 `animate` 前设 `this.animating = true`，在 `moveend` 里清掉），或者用 `map.on('movestart')` 判断是否由交互引起。不要在 `change:center` 里再调 `setCenter`，会形成自触发循环。

```javascript
const view = map.getView();

// 属性变化
view.on('change:center', () => {
  console.log('中心点:', view.getCenter());
});

view.on('change:resolution', () => {
  console.log('缩放级别:', view.getZoom());
});

view.on('change:rotation', () => {
  console.log('旋转角度:', view.getRotation());
});
```

### 13.1.3 图层事件

`change:visible`、`change:opacity` 是 `Layer` 基类提供的属性变更事件，所有图层类型都有。它们适合做界面同步：图层面板上的勾选框、透明度滑块与图层状态双向绑定，靠的就是这两个事件加上 `setVisible`/`setOpacity` 的调用。

`vectorSource.on('addfeature')` 在要素加入数据源时触发，`removefeature` 在移除时触发，批量操作时会逐个触发。`addFeatures` 加入一千个要素就是一千次回调，回调里如果做 DOM 更新会非常慢；批量导入时应当先挂起同步或只监听一次 `change`，导入完成后再统一刷新界面。`ol/source/Vector` 还支持 `featuresloadstart`、`featuresloadend`、`featuresloaderror`，用于异步加载数据源的进度与结果。

要素的几何被修改不会触发 `addfeature`，触发的是 `changefeature`（`VectorSource` 上的事件）以及要素自身的 `change` 事件。修改要素后要刷新属性面板，应当监听 `changefeature`；监听 `addfeature` 只能捕获新增。事件选错时现象是“新增能刷新、编辑不刷新”，很容易被忽略。

```javascript
// 图层可见性变化
layer.on('change:visible', () => {
  console.log('可见性:', layer.getVisible());
});

// 透明度变化
layer.on('change:opacity', () => {
  console.log('透明度:', layer.getOpacity());
});

// 矢量源事件
vectorSource.on('addfeature', (event) => {
  console.log('添加要素:', event.feature);
});

vectorSource.on('removefeature', (event) => {
  console.log('移除要素:', event.feature);
});
```

## 13.2 视图动画

`view.animate()` 是让地图“平滑变化”的标准方式，内部用 `requestAnimationFrame` 逐帧插值属性，动画期间阻断用户输入（可选），结束后触发 `moveend`。它比直接 `setCenter` 好在有过程：用户能看到地图从当前位置滑到目标位置，空间上的前后关系得以保持，不会因为瞬间跳转而失去方位感。

### 13.2.1 基本动画

`animate` 的参数是一个或多个“视图状态片段”，每个片段里写目标属性：`center`、`zoom`、`resolution`、`rotation` 可以任选组合，`duration` 是该片段的时长，`easing` 是缓动函数。片段里没写的属性保持当前值；同时写 `zoom` 和 `resolution` 时，`resolution` 优先，`zoom` 被忽略——这两个是同一个量的两种表达。

`duration` 的单位是毫秒，默认 1000 左右。太短看不出过程，太长用户会觉得卡顿；交互触发（点按钮定位）用 500 到 800，自动演示可以到 2000。移动端上 `duration` 建议略短，触屏的动画感知更敏感。

平移动画的 `center` 必须是视图投影坐标，示例用 `fromLonLat` 转换，这是正确写法。直接传经纬度数组，地图会飞到地球另一侧（数值差了几个数量级），不会报错但现象很夸张。缩放动画只写 `zoom` 即可，不需要同时写 `center`，除非想让缩放和平移同时发生。

`rotation` 的单位是弧度，正方向是逆时针（在屏幕坐标里看是顺时针，因为 y 轴向下）。旋转 90 度写 `Math.PI / 2`，写 `90` 会让地图转几十圈。旋转后鼠标拖动的方向仍然与地图内容一致，OpenLayers 内部处理了变换，但自定义的像素计算（如量测的屏幕距离）要记得考虑旋转角。

组合动画把多个属性放进同一个片段，它们是同时变化的。若希望“先平移再缩放”，要用多个片段（13.2.3），不要塞进一段。片段的顺序就是执行顺序，每段的 `duration` 独立计时。

```javascript
const view = map.getView();

// 平移动画
view.animate({
  center: fromLonLat([121.4737, 31.2304]),
  duration: 1000
});

// 缩放动画
view.animate({
  zoom: 15,
  duration: 500
});

// 旋转动画
view.animate({
  rotation: Math.PI / 2,
  duration: 500
});

// 组合动画
view.animate({
  center: fromLonLat([121.4737, 31.2304]),
  zoom: 15,
  rotation: 0,
  duration: 1500
});
```

### 13.2.2 缓动函数

缓动函数的作用是把线性的时间进度映射成非线性的动画进度，输入输出都在 0 到 1 之间。`linear` 是匀速，`easeIn` 慢起快停，`easeOut` 快起慢停，`inAndOut` 两端慢中间快。地图上的平移动画通常用 `easeOut`，起步快、收尾缓，符合“甩出去再停住”的物理直觉。

自定义缓动的实现要满足两个约束：`f(0)` 必须为 0，`f(1)` 必须为 1。中间可以任意发挥，包括超出 0 到 1 区间（回弹效果），OpenLayers 不会裁剪返回值，超出部分会直接反映到属性上。`bounce` 函数里分段用的常数 `s = 7.5625`、`p = 2.75` 是经典的弹跳曲线参数，每段的边界值 `1/p`、`2/p`、`2.5/p` 对应弹跳的不同阶段。

缓动函数被逐帧调用，里面不要放耗时计算或者访问 DOM。纯数学运算可以，每次动画几十帧，开销可以忽略。函数有副作用时（比如计数），一帧可能被调用多次（插值内部可能重算），计数会不准。

```javascript
import { easeIn, easeOut, inAndOut, linear } from 'ol/easing';

// 使用缓动函数
view.animate({
  center: destination,
  duration: 1000,
  easing: easeOut // 先快后慢
});

// 自定义缓动
function bounce(t) {
  const s = 7.5625, p = 2.75;
  if (t < 1/p) return s*t*t;
  if (t < 2/p) { t -= 1.5/p; return s*t*t + 0.75; }
  if (t < 2.5/p) { t -= 2.25/p; return s*t*t + 0.9375; }
  t -= 2.625/p;
  return s*t*t + 0.984375;
}

view.animate({
  center: destination,
  duration: 1500,
  easing: bounce
});
```

### 13.2.3 连续动画

`view.animate` 接受多个参数时，片段按顺序播放。每个片段结束后自动开始下一段，中间不会触发额外的 `movestart`；整个序列结束才触发一次 `moveend`。这个特性让“先平移到中点、再缩放”这类复合动作可以用一行代码表达，不必写回调嵌套。

`animate` 的最后一个参数是完成回调，每完成一个**片段**调用一次，参数 `complete` 表示该片段是否完整播放（被新的动画打断时为 false）。示例里用 `parts = 2` 计数，等两个动画序列各完成一次才打印“飞行完成”，因为这段代码同时启动了两个 `animate` 序列——它们会互相打断，实际效果与预期不同，这是示例本身的逻辑问题。正确做法是把飞行拆成单个序列：先缩小、再平移、再放大，或者用 `animate` 的片段数组一次排好。

同一个视图上同时只能有一个动画序列在跑，后启动的会打断前一个。需要编排复杂动作时，把动作写成片段数组，用一次 `animate` 调用执行；确实要跨阶段做逻辑（比如在第一段结束后加载数据），用完成回调里再启动下一段 `animate`，注意这时 `complete` 可能为 false。

```javascript
// 按顺序执行
view.animate(
  { center: point1, duration: 500 },
  { center: point2, duration: 500 },
  { center: point3, duration: 500 }
);

// 飞行效果
function flyTo(destination, zoom) {
  const startZoom = view.getZoom();
  const minZoom = Math.min(startZoom, zoom, 5);
  
  view.animate(
    { center: destination, duration: 1000 },
    callback
  );
  
  view.animate(
    { zoom: minZoom, duration: 500 },
    { zoom: zoom, duration: 500 },
    callback
  );
  
  let parts = 2;
  function callback(complete) {
    if (--parts === 0) {
      console.log('飞行完成');
    }
  }
}
```

## 13.3 要素动画

要素动画和视图动画的区别在于“谁在动”。视图动画改的是相机，要素在世界里不动；要素动画改的是要素坐标，相机可能需要跟随。前者由 `View` 内部驱动，后者要自己用 `requestAnimationFrame` 驱动，并且每一帧修改几何坐标之后让地图重绘。

### 13.3.1 位置动画

`animateFeature` 记录起点坐标和起始时间，每帧算进度、套缓动、插值出新坐标，写入几何。`geometry.setCoordinates` 会触发要素的 `change` 事件，进而让矢量图层重绘，所以不需要手动调用 `map.render()`。前提是要素确实在某个已加入地图的矢量源里；如果要素是游离的，改坐标不会有人去渲染。

`Date.now()` 的精度是毫秒，用作动画计时够用；`performance.now()` 精度更高且单调，更适合做逐帧计时（13.3 节的 Cesium 那种写法）。用 `Date.now()` 时要注意系统时间被调整会让进度跳变，`performance.now()` 不会。

`animateAlongPath` 用 `path.getCoordinateAt(progress)` 沿路径取点，`path` 是 `LineString` 几何。`getCoordinateAt` 的参数是 0 到 1 的比例，按**线段索引**均匀分配，不是按长度——两条长度不同的线段，短的那条走得更快。要按距离匀速，得先算总长度，再用 `getCoordinateAt` 之外的方法（如按累计距离查找），或者把路径加密成等距点。

`animateAlongPath` 里每帧调用了 `map.render()`，`animateFeature` 里没有。前者没写错但多余：`setCoordinates` 已经触发了重绘请求，再调 `render()` 只是提前，不改变结果。真正的区别在于两个函数都没有保存 `requestAnimationFrame` 的句柄，也没有停止条件之外的中断机制——要素被删除、地图被销毁之后，动画仍会跑完，访问已释放的对象可能抛错。封装成类时把句柄存起来，在 `destroy` 里取消。

```javascript
// 要素移动动画
function animateFeature(feature, destination, duration = 1000) {
  const geometry = feature.getGeometry();
  const start = geometry.getCoordinates();
  const startTime = Date.now();
  
  function animate() {
    const elapsed = Date.now() - startTime;
    const progress = Math.min(elapsed / duration, 1);
    
    // 使用缓动
    const eased = easeOut(progress);
    
    const x = start[0] + (destination[0] - start[0]) * eased;
    const y = start[1] + (destination[1] - start[1]) * eased;
    
    geometry.setCoordinates([x, y]);
    
    if (progress < 1) {
      requestAnimationFrame(animate);
    }
  }
  
  animate();
}

// 沿路径移动
function animateAlongPath(feature, path, duration = 5000) {
  const startTime = Date.now();
  
  function animate() {
    const elapsed = Date.now() - startTime;
    const progress = Math.min(elapsed / duration, 1);
    
    // 计算当前位置
    const point = path.getCoordinateAt(progress);
    feature.getGeometry().setCoordinates(point);
    
    if (progress < 1) {
      requestAnimationFrame(animate);
      map.render();
    }
  }
  
  animate();
}
```

### 13.3.2 样式动画

样式动画不改变要素几何，而是每帧返回不同的 `Style`。`createPulseStyle` 返回一个样式函数，OpenLayers 在每次渲染要素时调用它；函数内部用闭包变量 `radius` 记录当前半径，每次调用递增或递减，形成脉冲效果。这个写法依赖“每次渲染都调用样式函数”这个前提，而渲染只在需要时发生，所以必须配合 13.3 末尾的重绘循环。

`startAnimation` 里监听 `postrender` 再调 `map.render()`，等于每帧渲染完成后立刻请求下一帧，形成无限循环。这样能驱动样式函数不断被调用，代价是地图永远处于 100% 占用：即使没有任何变化，CPU 与 GPU 也在不停重绘，风扇转、电量掉。正确的做法是只在动画需要时开启循环，动画停止后注销监听。

`createBlinkStyle` 用 `Date.now() / 500 % 2` 判断当前是否可见，返回 `null` 表示不渲染该要素。样式函数返回 null 是合法写法，OpenLayers 会跳过这个要素，比返回一个透明样式更省。闪烁频率由除数控制，500 毫秒一个周期，即 1 秒两次。

样式函数会被非常频繁地调用（每个可见要素每帧一次），里面不要创建大量临时对象，否则 GC 压力明显。`new Style`、`new Circle` 每帧每个要素都新建，要素多时性能会崩。优化方式是把样式预先建好，动画只改可变的属性（如 `circle.setRadius`）——但样式对象在渲染时可能被克隆，改克隆体不生效，需要先拿到原始样式引用。

```javascript
// 脉冲效果
function createPulseStyle() {
  let radius = 5;
  let increasing = true;
  
  return function(feature) {
    if (increasing) {
      radius += 0.5;
      if (radius >= 15) increasing = false;
    } else {
      radius -= 0.5;
      if (radius <= 5) increasing = true;
    }
    
    return new Style({
      image: new Circle({
        radius: radius,
        fill: new Fill({ color: 'rgba(255, 0, 0, 0.5)' }),
        stroke: new Stroke({ color: 'red', width: 2 })
      })
    });
  };
}

// 闪烁效果
function createBlinkStyle() {
  return function(feature) {
    const visible = Math.floor(Date.now() / 500) % 2 === 0;
    
    return visible ? new Style({
      image: new Circle({
        radius: 8,
        fill: new Fill({ color: 'red' })
      })
    }) : null;
  };
}

// 需要持续渲染
function startAnimation() {
  map.on('postrender', () => map.render());
}
```

## 13.4 轨迹回放

轨迹回放是要素动画的一个完整应用：一个点沿着坐标数组移动，图标跟随方向旋转，地图中心跟着走。它把前面几节的内容串了起来——要素坐标更新、样式修改、定时驱动、视图跟随。理解了这个类的结构，做车辆监控、人员轨迹、船舶航迹的回放都是同一套骨架。

```javascript
class TrackPlayer {
  constructor(map, layer, coordinates) {
    this.map = map;
    this.layer = layer;
    this.coordinates = coordinates;
    this.currentIndex = 0;
    this.playing = false;
    this.speed = 1;
    
    // 创建移动的点要素
    this.marker = new Feature({
      geometry: new Point(coordinates[0])
    });
    
    this.marker.setStyle(new Style({
      image: new Icon({
        src: '/images/car.png',
        rotation: 0
      })
    }));
    
    layer.getSource().addFeature(this.marker);
  }
  
  play() {
    this.playing = true;
    this.animate();
  }
  
  pause() {
    this.playing = false;
  }
  
  stop() {
    this.playing = false;
    this.currentIndex = 0;
    this.updatePosition();
  }
  
  setSpeed(speed) {
    this.speed = speed;
  }
  
  animate() {
    if (!this.playing) return;
    if (this.currentIndex >= this.coordinates.length - 1) {
      this.playing = false;
      return;
    }
    
    const start = this.coordinates[this.currentIndex];
    const end = this.coordinates[this.currentIndex + 1];
    
    // 计算方向
    const dx = end[0] - start[0];
    const dy = end[1] - start[1];
    const rotation = -Math.atan2(dy, dx);
    
    // 更新图标旋转
    this.marker.getStyle().getImage().setRotation(rotation);
    
    // 移动到下一点
    this.currentIndex++;
    this.updatePosition();
    
    // 延迟后继续
    setTimeout(() => this.animate(), 100 / this.speed);
  }
  
  updatePosition() {
    const coord = this.coordinates[this.currentIndex];
    this.marker.getGeometry().setCoordinates(coord);
    
    // 地图跟随
    this.map.getView().setCenter(coord);
  }
}

// 使用示例
const coordinates = [/* 轨迹坐标数组 */];
const player = new TrackPlayer(map, vectorLayer, coordinates);

document.getElementById('play-btn').onclick = () => player.play();
document.getElementById('pause-btn').onclick = () => player.pause();
document.getElementById('stop-btn').onclick = () => player.stop();
```

## 13.5 地图截图与导出

把地图导出成图片，本质是把各个图层的 canvas 按顺序叠画到一张新 canvas 上。OpenLayers 每个图层渲染到自己的 canvas（或同一个 canvas 的不同区域），DOM 里表现为 `.ol-layer canvas` 节点；`rendercomplete` 保证所有瓦片、矢量都画完了，此时读取 canvas 内容才是完整的。

有两个硬性限制必须知道：一是跨域图片会污染 canvas，调用 `toDataURL`/`toBlob` 会抛安全错误。加载跨域瓦片、图标时，数据源要配置 `crossOrigin: 'anonymous'`，服务端要返回 `Access-Control-Allow-Origin`。二是 `canvas.toDataURL()` 在图层很多、地图很大时可能超时或内存暴涨，导出大图要分块或降低像素比。

```javascript
// 导出为图片
function exportMapAsImage(map, filename = 'map.png') {
  map.once('rendercomplete', () => {
    const canvas = document.createElement('canvas');
    const size = map.getSize();
    canvas.width = size[0];
    canvas.height = size[1];
    const context = canvas.getContext('2d');
    
    document.querySelectorAll('.ol-layer canvas').forEach(layerCanvas => {
      if (layerCanvas.width > 0) {
        const opacity = layerCanvas.parentNode.style.opacity || 1;
        context.globalAlpha = opacity;
        context.drawImage(layerCanvas, 0, 0);
      }
    });
    
    // 下载
    const link = document.createElement('a');
    link.download = filename;
    link.href = canvas.toDataURL();
    link.click();
  });
  
  map.renderSync();
}

// 复制到剪贴板
async function copyMapToClipboard(map) {
  map.once('rendercomplete', async () => {
    const canvas = document.createElement('canvas');
    const size = map.getSize();
    canvas.width = size[0];
    canvas.height = size[1];
    const context = canvas.getContext('2d');
    
    document.querySelectorAll('.ol-layer canvas').forEach(layerCanvas => {
      if (layerCanvas.width > 0) {
        context.drawImage(layerCanvas, 0, 0);
      }
    });
    
    canvas.toBlob(async (blob) => {
      await navigator.clipboard.write([
        new ClipboardItem({ 'image/png': blob })
      ]);
      console.log('已复制到剪贴板');
    });
  });
  
  map.renderSync();
}
```

## 13.6 本章小结

事件用错层级、动画忘了清理，是这一章最容易留下的两类问题。事件层面：高频事件（`pointermove`、`postrender`）里不做重活，拾取用 `singleclick` 而不是 `click`，截图等 `rendercomplete` 而不是 `postrender`。动画层面：视图动画用 `view.animate` 的片段数组编排，要素动画自己管好 `requestAnimationFrame` 句柄，样式动画的重绘循环必须能停。做到这几点，交互流畅度和稳定性都会明显不同。

本章介绍了地图事件与动画：

1. **事件系统**：地图、视图、图层事件
2. **视图动画**：平移、缩放、旋转、缓动函数
3. **要素动画**：位置动画、样式动画
4. **轨迹回放**：沿路径移动、播放控制
5. **地图导出**：截图、剪贴板

### 关键要点

- 使用 view.animate() 实现平滑过渡
- 缓动函数控制动画节奏
- requestAnimationFrame 实现自定义动画
