# 第15章 - 要素编辑与绘制

## 15.1 绘制功能

绘制与编辑在 OpenLayers 里由一组交互（Interaction）实现：`Draw` 负责新增，`Modify` 负责改形状，`Snap` 负责吸附，`Translate` 负责整体平移，`Select` 负责选中。它们都挂在 `map` 上，同一时刻可能有多个处于激活状态，谁先接收到鼠标事件由注册顺序和内部条件决定。理解这一点，前面几章反复出现的“交互顺序重要”就有了具体含义。

编辑功能对图层有要求：矢量图层的数据源必须是可写的 `VectorSource`，样式要能区分“编辑中”的要素，最好再加一个独立的编辑图层与业务展示图层分开。把编辑要素直接混在展示图层里，撤销、清空、导出都会互相影响；独立图层也让样式定制简单得多。

### 15.1.1 基本绘制

`VectorSource` 是要素的容器，`VectorLayer` 负责渲染它。示例创建一个空源、一个带样式的图层，加到地图上，再创建四个 `Draw` 实例分别对应点、线、面、圆。四个实例并没有被 `map.addInteraction`，也就是说这段代码只是“准备好”了绘制工具，真正启用还要加一句 `map.addInteraction(drawPoint)`。这是示例代码容易让人误解的地方：创建交互不会自动生效。

`Draw` 的 `type` 参数决定几何类型，取值是几何类型名字符串：`'Point'`、`'LineString'`、`'Polygon'`、`'Circle'`、`'MultiPoint'`、`'MultiLineString'`、`'MultiPolygon'`。`Circle` 在 OpenLayers 里是一个特殊的几何类型，本质上是中心点加半径，与用 `Polygon` 画出来的圆不同，后续做面积计算、导出 GeoJSON 时行为不一样。

`source` 指定绘制结果写入哪个数据源。`Draw` 在 `drawend` 时把要素加进这个源，所以源必须是可写的；如果传的是只读源（比如从 WFS 读来的），要素加不进去，画面上只在绘制瞬间显示预览。`style` 参数控制绘制过程中的预览样式，不传时用图层样式，两者风格不一致会造成“画的时候一个样、画完另一个样”。

四个绘制工具同时创建、都没有激活，实际业务里一次只能用一个。切换的工具逻辑见 15.3 的工具栏，核心是先移除旧的 `Draw` 交互，再添加新的，否则多个 `Draw` 同时监听鼠标，一次点击会同时开始多个绘制。

```javascript
import Draw from 'ol/interaction/Draw';
import VectorSource from 'ol/source/Vector';
import VectorLayer from 'ol/layer/Vector';
import { Style, Fill, Stroke, Circle } from 'ol/style';

// 创建编辑图层
const editSource = new VectorSource();
const editLayer = new VectorLayer({
  source: editSource,
  style: new Style({
    fill: new Fill({ color: 'rgba(66, 133, 244, 0.3)' }),
    stroke: new Stroke({ color: '#4285F4', width: 2 }),
    image: new Circle({
      radius: 6,
      fill: new Fill({ color: '#4285F4' })
    })
  })
});
map.addLayer(editLayer);

// 绘制点
const drawPoint = new Draw({ source: editSource, type: 'Point' });

// 绘制线
const drawLine = new Draw({ source: editSource, type: 'LineString' });

// 绘制面
const drawPolygon = new Draw({ source: editSource, type: 'Polygon' });

// 绘制圆
const drawCircle = new Draw({ source: editSource, type: 'Circle' });
```

### 15.1.2 特殊形状绘制

`geometryFunction` 是 `Draw` 的扩展点，用来把用户的原始操作（比如拖出一个圆）转换成别的几何。`createBox()` 把“圆心加半径”的拖拽解释成矩形，`createRegularPolygon(4)` 解释成正方形，`createRegularPolygon(6)` 解释成正六边形。注意 `type` 仍然写 `'Circle'`，因为用户的操作方式是拖拽定形，最终几何由 `geometryFunction` 生成。

`createRegularPolygon(n)` 生成正 n 边形，n 为 4 时是正方形，但它旋转了 45 度（顶点朝上），视觉上像一个菱形。要得到边与坐标轴平行的正方形，需要自己写 `geometryFunction`，或者用 `createBox()` 之后再旋转。这是初学者常问的“为什么正方形是斜的”，原因是正多边形的顶点从正上方开始排布。

`freehand: true` 让 `Draw` 在鼠标按下期间持续记录坐标，松开即完成，不需要逐点单击。它适合画自由曲线、手写标注，不适合需要精确顶点位置的面。开启 `freehand` 后，点样式（顶点的小圆点）不再显示，因为顶点是连续生成的，没有“逐个落点”的概念。

`geometryFunction` 必须返回符合 `type` 声明类型的几何，返回其他类型会导致后续步骤出错。自己实现时，函数签名是 `(coordinates, geometry, projection)`，`coordinates` 是当前操作的坐标数组，`geometry` 是上一次生成的几何（可用于增量更新），返回值会被 `Draw` 用来生成最终要素。

```javascript
import { createBox, createRegularPolygon } from 'ol/interaction/Draw';

// 矩形
const drawBox = new Draw({
  source: editSource,
  type: 'Circle',
  geometryFunction: createBox()
});

// 正方形
const drawSquare = new Draw({
  source: editSource,
  type: 'Circle',
  geometryFunction: createRegularPolygon(4)
});

// 正六边形
const drawHexagon = new Draw({
  source: editSource,
  type: 'Circle',
  geometryFunction: createRegularPolygon(6)
});

// 自由绘制
const freehand = new Draw({
  source: editSource,
  type: 'LineString',
  freehand: true
});
```

### 15.1.3 绘制事件

`drawstart` 在用户按下第一个点时触发，`drawend` 在几何完成时触发，`drawabort` 在绘制被取消时触发。三个事件都带 `event.feature`，其中 `drawstart` 阶段的要素几何还不完整，只能拿到初始坐标；`drawend` 阶段几何已经是最终状态。在 `drawend` 里做面积、长度计算是安全的，在 `drawstart` 里算没有意义。

`getArea(feature.getGeometry())` 来自 `ol/sphere`，按球面计算，**要求几何坐标是经纬度**。示例绘制在默认的 EPSG:3857 视图上，要素坐标是 Web Mercator 的米制坐标，直接传给 `getArea` 会得到错误结果——通常是实际面积的数倍。正确写法是先 `geom.clone().transform('EPSG:3857', 'EPSG:4326')` 再计算，或者用 `ol/sphere` 的第二个参数显式传投影。这是测量功能里最常见的一处错误。

`draw.abortDrawing()` 用于取消当前正在进行的绘制，键盘监听里用 Esc 调用。这个方法只对“正在绘制”的状态有效，没有绘制进行时调用什么也不会发生。`drawabort` 事件里的要素会被丢弃，不会加进数据源；如果业务上需要记录“用户取消了一次绘制”，可以在这个事件里打点。

`document.addEventListener('keydown')` 是全局监听，页面里所有输入框都会触发它。用户在搜索框里按 Esc 时，绘制也会被取消，这通常不是期望行为。判断 `event.target` 是不是输入元素，或者把监听范围限制在 `map.getTargetElement()` 上，可以避免这个问题。

```javascript
const draw = new Draw({ source: editSource, type: 'Polygon' });

draw.on('drawstart', (event) => {
  console.log('开始绘制');
});

draw.on('drawend', (event) => {
  const feature = event.feature;
  const area = getArea(feature.getGeometry());
  console.log('绘制完成，面积:', area, '平方米');
});

draw.on('drawabort', () => {
  console.log('取消绘制');
});

// Esc 键取消绘制
document.addEventListener('keydown', (e) => {
  if (e.key === 'Escape') {
    draw.abortDrawing();
  }
});
```

## 15.2 编辑功能

编辑类交互的共同点是“作用于已有的要素”。`Modify` 修改顶点，`Translate` 整体平移，删除则在应用代码里完成。它们都依赖要素能从一个可写数据源里找到，或者通过 `features` 集合指定。选错数据源、要素没有加进源，交互就不会有任何反应，而且不报错。

### 15.2.1 修改要素

`new Modify({ source: editSource })` 修改数据源里的所有要素，鼠标悬停到要素上就会出现可拖拽的顶点。`new Modify({ features: select.getFeatures() })` 只修改被选中的要素，未选中时拖拽无效。后者是业务系统里的常规做法：先点选、再编辑，避免误改无关要素。`source` 与 `features` 二选一，同时传时行为以实现为准，不要依赖。

`Select` 交互负责选中，它的 `getFeatures()` 返回一个 `Collection`，`Modify` 直接监听这个集合。选中样式由 `Select` 的 `style` 参数控制，默认会覆盖图层样式显示选中态；不配置时可能看不清哪些要素被选中。`Select` 还有 `multi`、`condition`、`hitTolerance` 等参数，分别控制多选、触发条件、命中容差，移动端上 `hitTolerance` 适当放大能显著改善点选体验。

`Snap` 让编辑时的顶点吸附到已有要素的顶点、边或中点，`source` 指向参照的数据源。它必须与 `Modify` 或 `Draw` 同时激活才有效，单独使用没有意义。捕捉精度由 `pixelTolerance` 控制（像素），默认 10；数值太大时顶点会吸到很远的要素上，太小则几乎吸不住。

“交互顺序重要”的说法在这里的具体含义是：`Select` 要在 `Modify` 之前添加，否则 `Modify` 先响应鼠标，选中状态永远建立不起来。`Snap` 放最后，它在其他交互处理完之后修正坐标。顺序反了不会报错，现象是“点了没反应”或“选不中”。

`modify.on('modifyend')` 在用户松开鼠标、完成一次修改时触发，`event.features` 是被修改的要素集合。这是保存修改到后端的时机——不要在修改进行中保存，中间的坐标是半成品。频繁拖拽会产生多次 `modifyend`，保存请求要做防抖，或者只在用户离开编辑模式时统一提交。

注意示例里 `select` 与 `modifySelected` 都创建了，但真正加进地图的是 `modifySelected`；`modify` 这个“修改所有要素”的实例没有被 `addInteraction`，只用来演示两种构造方式。照抄时如果同时添加 `modify` 和 `modifySelected`，同一要素会被两套逻辑同时处理，行为难以预期。

```javascript
import Modify from 'ol/interaction/Modify';
import Snap from 'ol/interaction/Snap';

// 修改所有要素
const modify = new Modify({ source: editSource });

// 修改选中要素
const select = new Select();
const modifySelected = new Modify({ features: select.getFeatures() });

// 捕捉
const snap = new Snap({ source: editSource });

// 添加交互（顺序重要）
map.addInteraction(select);
map.addInteraction(modifySelected);
map.addInteraction(snap);

// 事件
modify.on('modifyend', (event) => {
  console.log('修改完成');
});
```

### 15.2.2 删除要素

删除要素从数据源里移除即可：`editSource.removeFeature(feature)`。`Select.getFeatures()` 返回的是选中集合，遍历它逐个移除，最后 `clear()` 清空选中状态——不清理的话，`Modify` 仍然持有已被删除的要素引用，后续拖拽可能访问到已释放的对象。

键盘删除监听同样是全局的，输入框里按 Delete 会触发删除要素，这个交互很危险。判断事件目标、或在焦点进入输入框时把删除逻辑屏蔽，是必须做的防护。生产系统一般还会在删除前弹确认框，尤其是批量删除。

`map.on('contextmenu')` 的右键删除：`event.preventDefault()` 阻止浏览器默认菜单，`forEachFeatureAtPixel` 拾取要素，找到就删。`forEachFeatureAtPixel` 返回的是第一个命中要素（回调返回真值即停止），如果回调写成 `f => f`，它总是返回第一个要素，所以这里拿到的是最上层的那一个。多图层叠加时，右键删除可能删到不是用户以为的那个要素，需要给拾取加 `layerFilter` 限定图层。

删除是不可逆操作，`VectorSource` 没有内置的撤销栈。要实现撤销，得自己在删除前把要素及其索引保存下来，重建时按原位置插回（`VectorSource` 没有按索引插入的接口，通常用重新排序或维护一个业务顺序字段）。15.3 的工具栏把撤销留成空方法，原因就在这。

```javascript
// 删除选中要素
function deleteSelected() {
  const features = select.getFeatures();
  features.forEach(feature => {
    editSource.removeFeature(feature);
  });
  features.clear();
}

// 按 Delete 键删除
document.addEventListener('keydown', (e) => {
  if (e.key === 'Delete') {
    deleteSelected();
  }
});

// 右键菜单删除
map.on('contextmenu', (event) => {
  event.preventDefault();
  const feature = map.forEachFeatureAtPixel(event.pixel, f => f);
  if (feature) {
    editSource.removeFeature(feature);
  }
});
```

### 15.2.3 平移要素

`Translate` 拖动整个要素，不改变形状。`features` 参数限定可平移的要素集合，不传时可以对数据源里的所有要素平移（需要同时传 `source` 或 `layers`）。与 `Modify` 的关系是：`Modify` 动顶点，`Translate` 动整体，两者可以同时添加，按住顶点拖是修改、按住要素内部拖是平移，具体谁响应由命中测试决定。

`translateend` 在平移结束时触发，`event.features` 是被移动的要素，`event.coordinate` 是移动后的位置。批量平移多个要素时，它们按相同的位移量移动。平移不会改变要素的几何类型，但会改变所有顶点坐标，如果要素有依赖坐标的属性（如中心点坐标字段），需要在事件里同步更新。

`Translate` 默认只处理点、线、面等简单几何，对 `GeometryCollection` 这类复合几何的行为依实现而定。业务数据里如果有复合要素，最好在编辑前先分解成简单几何，避免平移后部分子几何没动。

```javascript
import Translate from 'ol/interaction/Translate';

// 平移选中要素
const translate = new Translate({
  features: select.getFeatures()
});

translate.on('translateend', (event) => {
  console.log('平移完成');
});

map.addInteraction(translate);
```

## 15.3 编辑工具栏

这一版的 `EditToolbar` 把编辑相关的交互收进一个类，用 `activateTool` 统一切换当前工具。它的设计思路与第 10 章的工具栏一致：同一时刻只有一个“编辑模式”，切换时先停用旧的、再启用新的。区别在于它管理的是交互（`Draw`、`Select`、`Modify`、`Snap`），不是控件。

构造函数里 `Select`、`Modify`、`Snap` 三个交互一次创建并加入地图，然后 `select` 与 `modify` 被 `setActive(false)` 关掉，`snap` 没有关。这意味着默认状态下吸附仍然生效——在没有绘制或修改交互时它不影响操作，但一旦激活 `Draw`，吸附就会起作用。这个细节是有意的（吸附是辅助行为），只是代码里没有注释，读起来容易困惑。

`activateTool('select')` 同时开启 `select` 与 `modify`，这是“选中即可改”的便利设计；`activateTool` 传入几何类型时则移除所有编辑交互、新建一个 `Draw`。两组工具互斥，`deactivate()` 负责把状态清干净。注意 `activateTool` 里没有把 `snap` 一起关掉，所以绘制时吸附始终在工作——这对画相邻地块是好特性。

```javascript
class EditToolbar {
  constructor(map, source) {
    this.map = map;
    this.source = source;
    this.activeInteraction = null;
    
    // 选择和修改交互
    this.select = new Select();
    this.modify = new Modify({ features: this.select.getFeatures() });
    this.snap = new Snap({ source });
    
    map.addInteraction(this.select);
    map.addInteraction(this.modify);
    map.addInteraction(this.snap);
    
    this.select.setActive(false);
    this.modify.setActive(false);
  }
  
  activateTool(type) {
    this.deactivate();
    
    if (type === 'select') {
      this.select.setActive(true);
      this.modify.setActive(true);
    } else if (['Point', 'LineString', 'Polygon', 'Circle'].includes(type)) {
      this.activeInteraction = new Draw({
        source: this.source,
        type: type
      });
      this.map.addInteraction(this.activeInteraction);
    }
  }
  
  deactivate() {
    this.select.setActive(false);
    this.modify.setActive(false);
    
    if (this.activeInteraction) {
      this.map.removeInteraction(this.activeInteraction);
      this.activeInteraction = null;
    }
  }
  
  deleteSelected() {
    const features = this.select.getFeatures();
    features.forEach(f => this.source.removeFeature(f));
    features.clear();
  }
  
  clear() {
    this.source.clear();
    this.select.getFeatures().clear();
  }
  
  undo() {
    // 实现撤销功能需要历史记录
  }
}

// 使用
const toolbar = new EditToolbar(map, editSource);

document.getElementById('draw-point').onclick = () => toolbar.activateTool('Point');
document.getElementById('draw-line').onclick = () => toolbar.activateTool('LineString');
document.getElementById('draw-polygon').onclick = () => toolbar.activateTool('Polygon');
document.getElementById('select').onclick = () => toolbar.activateTool('select');
document.getElementById('delete').onclick = () => toolbar.deleteSelected();
document.getElementById('clear').onclick = () => toolbar.clear();
```

## 15.4 测量功能

`MeasureTool` 在绘制过程中实时显示长度或面积，用 `Overlay` 跟随鼠标位置。它比第 10 章的测量控件更完整：控件只负责按钮，这里把绘制、实时计算、提示框、清理串成了一条线。结构上仍然遵循“独立数据源 + 独立图层”的原则，测量结果不会污染业务图层。

```javascript
import { getLength, getArea } from 'ol/sphere';

class MeasureTool {
  constructor(map) {
    this.map = map;
    this.source = new VectorSource();
    this.layer = new VectorLayer({
      source: this.source,
      style: this.createStyle()
    });
    
    map.addLayer(this.layer);
    this.draw = null;
    this.tooltip = null;
  }
  
  measureDistance() {
    this.clear();
    this.draw = new Draw({ source: this.source, type: 'LineString' });
    
    this.draw.on('drawstart', (e) => {
      e.feature.on('change', () => {
        const geom = e.feature.getGeometry();
        const length = getLength(geom);
        this.updateTooltip(geom.getLastCoordinate(), this.formatLength(length));
      });
    });
    
    this.draw.on('drawend', () => {
      this.tooltip = null;
    });
    
    this.map.addInteraction(this.draw);
  }
  
  measureArea() {
    this.clear();
    this.draw = new Draw({ source: this.source, type: 'Polygon' });
    
    this.draw.on('drawstart', (e) => {
      e.feature.on('change', () => {
        const geom = e.feature.getGeometry();
        const area = getArea(geom);
        const coord = geom.getInteriorPoint().getCoordinates();
        this.updateTooltip(coord, this.formatArea(area));
      });
    });
    
    this.map.addInteraction(this.draw);
  }
  
  formatLength(length) {
    return length > 1000 ? 
      `${(length / 1000).toFixed(2)} km` : 
      `${length.toFixed(2)} m`;
  }
  
  formatArea(area) {
    return area > 1000000 ? 
      `${(area / 1000000).toFixed(2)} km²` : 
      `${area.toFixed(2)} m²`;
  }
  
  createStyle() {
    return new Style({
      fill: new Fill({ color: 'rgba(255, 255, 255, 0.2)' }),
      stroke: new Stroke({ color: '#ffcc33', width: 2 }),
      image: new Circle({
        radius: 5,
        fill: new Fill({ color: '#ffcc33' })
      })
    });
  }
  
  updateTooltip(coordinate, text) {
    // 创建或更新工具提示
    if (!this.tooltip) {
      this.tooltip = new Overlay({
        element: this.createTooltipElement(),
        offset: [0, -15],
        positioning: 'bottom-center'
      });
      this.map.addOverlay(this.tooltip);
    }
    
    this.tooltip.getElement().innerHTML = text;
    this.tooltip.setPosition(coordinate);
  }
  
  createTooltipElement() {
    const element = document.createElement('div');
    element.className = 'measure-tooltip';
    return element;
  }
  
  clear() {
    if (this.draw) {
      this.map.removeInteraction(this.draw);
      this.draw = null;
    }
    this.source.clear();
    if (this.tooltip) {
      this.map.removeOverlay(this.tooltip);
      this.tooltip = null;
    }
  }
}
```

## 15.5 数据导入导出

GeoJSON 是浏览器端最常用的交换格式，OpenLayers 用 `ol/format/GeoJSON` 读写。读写时有两个投影参数：`dataProjection` 是文件里的坐标系，`featureProjection` 是地图要素的坐标系。GeoJSON 规范规定坐标是 WGS84 经纬度，所以 `dataProjection` 基本固定写 `'EPSG:4326'`；`featureProjection` 要写视图的实际投影，默认视图是 `'EPSG:3857'`。两个参数漏写，坐标不会被转换，导出的文件会是 Web Mercator 的米制坐标，别的系统读进去偏移巨大。

`writeFeatures` 返回一个字符串，示例里包成 `Blob` 再生成临时 URL 下载。`URL.createObjectURL` 创建的对象必须 `revokeObjectURL` 释放，示例在 `click()` 之后立刻回收——部分浏览器上点击下载是异步的，立即回收可能导致下载失败，稳妥做法是 `setTimeout` 延迟回收或监听下载完成。

导入侧用 `FileReader` 读文本，`readFeatures` 解析并转换坐标，`addFeatures` 批量加入数据源。错误处理是缺失的：文件不是合法 JSON、坐标超出范围、几何类型不支持，都会在 `onload` 里抛异常，而这里没有 `try/catch`，页面会静默失败。导入功能必须捕获异常并提示用户具体原因（哪个要素、哪一行），否则用户只知道“没反应”。

拖放导入的监听挂在 `map.getTargetElement()` 上，`dragover` 里 `preventDefault` 是必须的，否则浏览器默认行为会打开文件。`drop` 里只判断了扩展名，没有校验 MIME 类型和文件大小；大文件读取会阻塞主线程，几兆以上建议用 `FileReader` 的分片读取或 Web Worker。示例 `import KML from 'ol/format/KML'` 引入了但没用到，KML 的用法与 GeoJSON 类似，注意 KML 里可能有样式和文件夹结构，`readFeatures` 只取几何与属性。

```javascript
import GeoJSON from 'ol/format/GeoJSON';
import KML from 'ol/format/KML';

// 导出 GeoJSON
function exportGeoJSON(source) {
  const format = new GeoJSON();
  const features = source.getFeatures();
  
  const json = format.writeFeatures(features, {
    dataProjection: 'EPSG:4326',
    featureProjection: 'EPSG:3857'
  });
  
  const blob = new Blob([json], { type: 'application/json' });
  const url = URL.createObjectURL(blob);
  
  const link = document.createElement('a');
  link.href = url;
  link.download = 'features.geojson';
  link.click();
  
  URL.revokeObjectURL(url);
}

// 导入 GeoJSON
function importGeoJSON(source, file) {
  const reader = new FileReader();
  
  reader.onload = (e) => {
    const format = new GeoJSON();
    const features = format.readFeatures(e.target.result, {
      dataProjection: 'EPSG:4326',
      featureProjection: 'EPSG:3857'
    });
    
    source.addFeatures(features);
  };
  
  reader.readAsText(file);
}

// 文件拖放导入
map.getTargetElement().addEventListener('dragover', (e) => {
  e.preventDefault();
});

map.getTargetElement().addEventListener('drop', (e) => {
  e.preventDefault();
  const file = e.dataTransfer.files[0];
  if (file.name.endsWith('.geojson') || file.name.endsWith('.json')) {
    importGeoJSON(editSource, file);
  }
});
```

## 15.6 本章小结

编辑功能的实现顺序建议是：先定数据模型（独立编辑图层、要素带哪些属性），再做交互（Draw → Select → Modify → Snap → Translate），然后做状态管理（当前工具、撤销栈、脏数据标记），最后才是界面。顺序反过来写，常见的结果是交互能跑但状态混乱，切换工具时残留上一轮的监听与临时要素。

量测类代码记得把几何转到经纬度再算，导入导出记得显式声明两个投影，删除与清空记得给确认和保护。这几条都是小改动，但漏掉时产生的是“数据错了却看不出来”的问题，排查成本远高于写的时候多想一步。

本章介绍了要素编辑与绘制：

1. **绘制功能**：点、线、面、特殊形状
2. **编辑功能**：修改、删除、平移
3. **编辑工具栏**：工具管理
4. **测量功能**：距离、面积测量
5. **数据导入导出**：GeoJSON、KML

### 关键要点

- Draw 交互实现绘制
- Modify + Snap 实现编辑
- 使用 GeoJSON 格式导入导出
