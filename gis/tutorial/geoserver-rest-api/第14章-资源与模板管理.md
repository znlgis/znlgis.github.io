# 第14章：资源与模板管理

GeoServer 的数据目录里除了数据源配置，还有一批以文件形式存在的资源：样式文件、SLD 引用的图标、字体、GeoServer 用来生成 WMS 输出的模板，以及安全相关的证书和密钥库。REST API 为这些文件单独开了一个资源入口，可以在不登录服务器、不碰文件系统的前提下读写它们。

资源管理和样式管理有重叠，边界要分清：样式端点管的是"样式这个配置对象"，会做解析和校验；资源端点管的是"文件本身"，按字节搬运，不解释内容。用资源端点上传一个 SLD 文件并不会创建样式记录，要让它变成图层能引用的样式，还得走样式端点。

## 14.1 资源管理概述

GeoServer 允许管理各种资源文件，包括样式文件、图标、字体、模板等。这些资源可以在全局级别或工作空间级别管理。

资源的定位靠一个相对路径。路径相对于 GeoServer 数据目录下的资源根，通常形如 styles/xxx.sld、workspaces/{workspace}/styles/icons/marker.png。路径里可以带子目录，目录不存在时有的操作会自动创建，有的会失败，脚本里最好显式建目录。工作空间级资源放在该工作空间目录下，全局资源放在根目录下，两者互不影响，同名文件可以并存。

读写接口对内容类型有要求。文本类资源（SLD、HTML 模板、properties）按文本上传即可；图片、字体、证书必须按二进制上传，否则字节被当成字符串转码，文件会损坏。上传后用 HEAD 或 GET 回读一次，比对字节数，是确认资源写对了的最简单办法。

## 14.2 ResourceService 核心功能

ResourceService 的四个方法对应资源端点的 CRUD：列目录、取内容、写内容、删文件。列表接口返回目录下的条目，包括子目录名，通常还要看条目上的类型区分文件和目录；取内容时服务端按资源类型返回不同 Content-Type，文本资源拿到字符串，二进制资源拿到字节流。

上传要注意幂等性。同一个路径重复上传是覆盖还是报错，取决于封装内部用的是 PUT 还是 POST：PUT 语义是存在即覆盖，POST 更适合新建。覆盖式上传会直接替换线上资源，没有版本记录，脚本里给资源路径加时间戳或内容摘要，或者先备份旧文件，能避免误覆盖后无从恢复。

删除是硬删除，删掉的资源立即从服务端消失，引用它的配置可能在下次渲染时才报错。删除前先确认没有样式、图层、模板在用它，尤其是公共图标目录这种被多个 SLD 引用的位置。

```csharp
public class ResourceService
{
    // 列出资源
    public async Task<Resource[]> ListResourcesAsync(string path);
    
    // 获取资源内容
    public async Task<string> GetResourceAsync(string path);
    
    // 上传资源
    public async Task UploadResourceAsync(string path, byte[] content);
    
    // 删除资源
    public async Task DeleteResourceAsync(string path);
}
```

接口返回类型里没有错误码，失败靠异常抛出。调用方应当把 404（路径不存在）和 403（无权限）分开处理：前者多半是路径拼错或目录层级不对，后者是账号权限不足或工作空间受限。资源路径大小写敏感，Windows 服务器上开发时无所谓，迁到 Linux 就会立刻暴露问题。

路径分隔符统一用正斜杠。服务端会把它映射到数据目录，用反斜杠在 Linux 部署上会被当成文件名的一部分，表现为上传成功但找不到文件。

## 14.3 管理样式资源

样式资源的典型用法是把 SLD 文件和它引用的图片一起上传。SLD 里用 ExternalGraphic 引用本地图片时，路径相对于样式文件所在目录写相对路径，例如 icons/marker.png；上传时保持同样的相对目录结构，样式才能找到图。图片建议用 PNG，尺寸控制在常见屏幕像素范围内，太大会拖慢每次渲染。

上传路径里的 styles 指的是 GeoServer 数据目录下的 styles 目录，不等于"样式记录"。传了 custom_style.sld 只是多了个文件，要让图层用上它，仍需在样式端点创建同名样式并把 SLD 内容写进去，或者用管理页面从文件导入。很多"资源传上去了、样式列表里没有"的困惑都出在这里。

图标更新后记得清地图缓存。图标是按文件名引用的，浏览器和 GeoWebCache 都可能缓存旧图，换图后看不到变化的概率比想象中高。

```csharp
// 上传SLD文件
var sldContent = File.ReadAllBytes("style.sld");
await resourceService.UploadResourceAsync(
    "styles/custom_style.sld", 
    sldContent);

// 上传样式图标
var iconContent = File.ReadAllBytes("icon.png");
await resourceService.UploadResourceAsync(
    "styles/icons/marker.png", 
    iconContent);
```

二进制上传不要经过字符串。File.ReadAllBytes 读出的是原始字节，直接交给上传方法；如果中间把它转成字符串再写回，非 ASCII 字节会被替换或转义，PNG 会变成打不开的文件。上传完成后把资源取回来，和本地文件比对长度，就能发现这类问题。

资源列表用于巡检很合适：定期拉一次目录，检查关键图标、字体、证书是否还在，比等用户报错再查主动得多。目录里出现临时文件（编辑器备份、隐藏文件）时，也可以按后缀或名称规则清理。

## 14.4 TemplateService - 模板管理

模板决定 GeoServer 生成描述文档时输出的内容。WMS 的 GetFeatureInfo 结果、WFS 的 GetFeature 响应、图层预览页，都可以用模板定制。模板按要素类型或图层组织，通常放在数据存储或工作空间目录下，命名规则由 GeoServer 约定，比如某一类响应对应固定后缀的 HTML 或 XML 文件。

模板里能引用要素属性和请求参数，写法是 FreeMarker 语法。改模板的风险高于改样式：模板输出的是服务响应本身，语法错会让整个请求返回 500，字段名写错则显示为空。先在测试实例上传、用真实请求验证，再同步到生产，是比较稳妥的流程。

模板和样式的职责不要混。模板不能改变地图图片的样子，样式也不能改变 GetFeatureInfo 的返回结构；想调整弹窗里的字段和版式，改的是模板，不是 SLD。

```csharp
public class TemplateService
{
    // 获取模板列表
    public async Task<Template[]> GetTemplatesAsync(string workspaceName, string storeName);
    
    // 获取模板内容
    public async Task<string> GetTemplateAsync(string path);
    
    // 更新模板
    public async Task UpdateTemplateAsync(string path, string content);
}
```

读模板时拿到的是一段文本，写回时整段覆盖。用字符串拼接改模板容易破坏结构，更稳的做法是本地维护一份完整模板文件，改动走代码评审，部署时整份上传。模板里如果要显示中文字段，注意声明字符编码为 UTF-8，否则响应头编码和文件编码不一致时会出现乱码。

模板缓存也需要留意。GeoServer 通常按需加载模板并缓存，替换模板后不一定立即生效，确认方式仍是发一次真实请求看输出。

## 14.5 FontService - 字体管理

地图上标注中文时，服务端必须能找到对应字体。GeoServer 自带一套基础字体，中文字体一般要手动放进数据目录的字体目录（通常是 data_dir/fonts），重启后才会被加载。用字体端点可以查询当前可用的字体名，部署自查时先确认目标字体在列表里，再去查 SLD 里的字体名有没有写错。

字体名要用字体文件内部的 family name，不是文件名。把 simhei.ttf 放进去，SLD 里写的应该是"黑体"或"SimHei"，具体取哪个以字体列表返回的为准。字体名对不上时，GeoServer 会悄悄换成默认字体，地图上出现方框或英文替身，不会报错。

字体文件有版权，商用项目要确认授权，别直接把 Windows 系统字体拷进生产服务器。开源中文字体（如思源系列）体积大但授权清晰，适合随应用一起分发。

```csharp
var fontService = factory.CreateFontService();

// 获取可用字体列表
var fonts = await fontService.GetAvailableFontsAsync();

foreach (var font in fonts)
{
    Console.WriteLine($"字体: {font.Name}");
}
```

字体列表是一次加载的结果，运行时新加字体文件不会自动出现，需要重启服务或调用配置重载。自动化部署里把字体文件放进数据目录属于"初始化步骤"，和业务脚本分开执行，能避免每次发布都重复拷贝大文件。

排查中文乱码或方框时按这个顺序走：确认字体文件已放到正确目录；确认服务已重载并出现在字体列表；确认 SLD 里写的字体名与列表一致；最后确认模板或响应声明的编码是 UTF-8。四步里任何一步不满足，显示都会不正常。

## 14.6 本章小结

本章学习了GeoServer的资源管理功能，包括样式资源、模板和字体的管理方法。

把资源、模板、字体放在一起看，它们有一个共同点：都是"文件"，改动不需要动数据源，也不需要重新发布图层。也正因为如此，它们最容易被脚本误覆盖、被缓存拖住、被编码问题坑到。管理上建议把这几类文件纳入版本控制，用部署脚本下发，上传后回读校验，再配合一次真实服务请求确认生效。

下一章转到系统层面：版本信息、配置重载、日志和监控。资源配错了可以回读比对，系统状态配错了只能靠监控发现问题。
