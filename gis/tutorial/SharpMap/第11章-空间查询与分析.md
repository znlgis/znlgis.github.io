# 第11章：空间查询与分析

地图能画出来只是第一步。业务里的"点一下地图看看这里有什么""统计这个范围内的学校数量""找出最近的加油站"，都要落到查询上。SharpMap 的查询能力分两层：数据提供者负责按范围取要素，几何对象负责判断空间关系；前者减少要处理的数据量，后者给出精确结果。两层配合，才能在大数据量下保持响应速度。

这一章按查询方式、属性过滤、空间关系、空间分析、空间索引的顺序展开。重点是理解每个 API 的参数单位和坐标参照系——距离、容差、缓冲区半径这些数值，用的都是数据本身坐标系的单位，经纬度数据和投影坐标数据混着用时，同样的数字代表的意义完全不同。

## 11.1 空间查询基础

范围查询是空间查询的基本形式：给定一个矩形，取出落在其中的要素。矩形在 SharpMap 里用 Envelope 表示，构造参数顺序是 minX、maxX、minY、maxY，和数学上常见的 (minX, minY, maxX, maxY) 顺序不同，写反了会得到一个宽高为负的无效范围，查询结果为空却不报错。

执行查询用数据提供者的 ExecuteIntersectionQuery，结果填进 FeatureDataSet。这个过程是"相交即返回"：几何只要与矩形有交集就会被选中，不做进一步裁剪。所以拿到的要素可能有一部分在范围外，需要精确判断时再逐个用几何对象做相交运算。

### 11.1.1 范围查询

下面这段代码演示完整流程：构造范围、执行查询、遍历结果。看得出结果集也是 DataTable 结构，可以直接绑定到表格控件，也可以按列名取值。

```csharp
// 创建查询范围
var queryEnvelope = new Envelope(116.0, 117.0, 39.0, 40.0);

// 执行范围查询
var featureDataSet = new FeatureDataSet();
vectorLayer.DataSource.ExecuteIntersectionQuery(queryEnvelope, featureDataSet);

// 获取结果
if (featureDataSet.Tables.Count > 0)
{
    var table = featureDataSet.Tables[0];
    Console.WriteLine($"查询到 {table.Rows.Count} 个要素");
    
    foreach (FeatureDataRow row in table.Rows)
    {
        Console.WriteLine($"ID: {row["ID"]}, Name: {row["NAME"]}");
        Console.WriteLine($"几何类型: {row.Geometry.GeometryType}");
    }
}
```

遍历结果时要用 FeatureDataRow 而不是基类 DataRow，Geometry 属性只在 FeatureDataRow 上才有。取属性值用列名索引，列名写错会抛异常而不是返回空，写查询代码时先确认图层里有哪些字段，可以用 GetColumns 或查看要素类型的字段定义。

结果集为空是正常情况，不代表出错。Tables.Count 为 0、Rows.Count 为 0 都要判断，很多程序崩溃是因为直接取 Tables[0] 而没有检查集合是否为空。

编码问题也常出现在这一步：Shapefile 的 DBF 默认编码不一定是 UTF-8，中文字段读出来是乱码时，检查创建 ShapeFile 提供者时指定的编码参数。

### 11.1.2 几何查询

范围查询本质上也是几何查询，只是查询几何固定为矩形。实际业务里的条件往往更复杂：圆形范围、任意多边形范围、沿着河流的带状范围。ExecuteIntersectionQuery 接受任意 Geometry，把缓冲区、手绘多边形传进去都能用。

```csharp
// 创建查询几何
var factory = new GeometryFactory();
var queryPoint = factory.CreatePoint(new Coordinate(116.4, 39.9));
var queryBuffer = queryPoint.Buffer(0.1);  // 0.1度缓冲区

// 执行几何查询
var featureDataSet = new FeatureDataSet();
vectorLayer.DataSource.ExecuteIntersectionQuery(queryBuffer, featureDataSet);
```

### 11.1.3 点击查询

点击查询把屏幕坐标换成地理坐标再查，是 Web 和桌面地图最常用的交互。难点在容差：用户点的是一个像素，要命中的却是有面积的要素，直接用点去查几乎什么都查不到。做法是把点击位置扩成一个小矩形，再按矩形查询。

下面这段代码先调用 ImageToWorld 把屏幕坐标转成世界坐标，再用 pixelWidth 把像素容差换算成世界单位。换算关系建立在当前地图范围上，缩放级别不同，同一个像素容差对应的地理距离也不同，所以容差必须在每次点击时重新计算，不能缓存。

```csharp
public class PointQueryHelper
{
    private readonly Map _map;
    
    public PointQueryHelper(Map map)
    {
        _map = map;
    }
    
    public IEnumerable<FeatureDataRow> QueryAtPoint(PointF screenPoint, double tolerance = 5)
    {
        // 转换为地理坐标
        var worldPoint = _map.ImageToWorld(screenPoint);
        
        // 创建查询范围（考虑容差）
        double worldTolerance = tolerance * _map.PixelWidth;
        var queryEnvelope = new Envelope(
            worldPoint.X - worldTolerance,
            worldPoint.X + worldTolerance,
            worldPoint.Y - worldTolerance,
            worldPoint.Y + worldTolerance);
        
        var results = new List<FeatureDataRow>();
        
        // 查询所有矢量图层
        foreach (var layer in _map.Layers.OfType<VectorLayer>().Where(l => l.Enabled))
        {
            var ds = new FeatureDataSet();
            layer.DataSource.ExecuteIntersectionQuery(queryEnvelope, ds);
            
            if (ds.Tables.Count > 0)
            {
                results.AddRange(ds.Tables[0].Rows.Cast<FeatureDataRow>());
            }
        }
        
        return results;
    }
}
```

这段代码有几个可以改进的地方。tolerance 乘以 PixelWidth 得到的是 X 方向容差，Y 方向应当乘 PixelHeight，比例尺很极端时两者差别明显。查询所有矢量图层时没有排除不可见的图层之外的情况，比如图层已禁用但没从集合移除，或者图层在当前比例尺下不显示；这些都要按业务需求补充判断条件。

结果没有排序，也没有去重。多个图层同时命中时，返回列表的顺序取决于图层顺序，界面上要做高亮的话，最好带上图层名，避免同名要素混在一起。

## 11.2 属性查询

属性查询处理的是"按字段筛选"，和空间位置无关。SharpMap 的数据提供者只提供按范围取数，没有通用的 SQL 查询接口——ShapeFile 没有数据库引擎，PostGIS 这类提供者虽然有，但接口层不暴露 SQL。所以属性过滤一般分两步：先用一个大范围把数据取进内存，再用 LINQ 过滤。

这个做法在数据量小时很方便，数据量大时就是性能陷阱：为了找几个人口过百万的城市，把全国要素全读进内存。更好的策略是把过滤条件下推到数据源，用提供者自己的查询能力（PostGIS 走 SQL，Shapefile 走 DBF 过滤），或者建立空间索引先缩小范围。

### 11.2.1 使用 LINQ 查询

示例先把所有要素读进 IEnumerable，再做 Where、OrderBy、Take。注意 Take 的位置：如果先过滤再排序再取前十条，数据量已经很小；如果顺序反过来，先取十条再过滤，结果就不对。

```csharp
// 获取所有要素
var allFeatures = GetAllFeatures(vectorLayer);

// LINQ 过滤
var filtered = allFeatures
    .Where(f => Convert.ToDouble(f["POPULATION"]) > 1000000)
    .OrderByDescending(f => Convert.ToDouble(f["POPULATION"]))
    .Take(10);

foreach (var feature in filtered)
{
    Console.WriteLine($"{feature["NAME"]}: {feature["POPULATION"]}");
}

// 辅助方法
private IEnumerable<FeatureDataRow> GetAllFeatures(VectorLayer layer)
{
    var ds = new FeatureDataSet();
    layer.DataSource.ExecuteIntersectionQuery(layer.Envelope, ds);
    
    if (ds.Tables.Count > 0)
    {
        return ds.Tables[0].Rows.Cast<FeatureDataRow>();
    }
    return Enumerable.Empty<FeatureDataRow>();
}
```

GetAllFeatures 用图层自身的 Envelope 作为查询范围，相当于把整个图层读出来。图层的 Envelope 在数据源加载后才有值，图层刚创建还没绑定数据源时，这个属性可能是空的，调用前应确认。

取字段值时标量类型不确定。DBF 里的数字列读出来可能是 double、decimal 或 int，直接 Convert.ToDouble 前要判空；示例里的 Convert.ToDouble(f["POPULATION"]) 遇到 NULL 会抛异常，生产代码应当先做空值判断。

### 11.2.2 SQL 风格查询

FeatureQuery 这个辅助类把常见的过滤和投影操作包装成静态方法，写法接近 SQL。Where 直接复用 LINQ 的谓词，Select 则做字段裁剪：新建一行，复制几何和指定字段。

投影查询的价值在传输和内存。一个要素类型可能有几十个字段，界面只用到名称和类型两个，全量返回浪费带宽也浪费内存。裁剪之后，要素的几何还在，属性只保留需要的部分。

```csharp
public class FeatureQuery
{
    public static IEnumerable<FeatureDataRow> Where(IEnumerable<FeatureDataRow> features, 
        Func<FeatureDataRow, bool> predicate)
    {
        return features.Where(predicate);
    }
    
    public static IEnumerable<FeatureDataRow> Select(IEnumerable<FeatureDataRow> features,
        string[] columns)
    {
        // 投影查询（只返回指定字段）
        foreach (var feature in features)
        {
            var newRow = feature.Table.NewRow() as FeatureDataRow;
            newRow.Geometry = feature.Geometry;
            
            foreach (var col in columns)
            {
                if (feature.Table.Columns.Contains(col))
                {
                    newRow[col] = feature[col];
                }
            }
            
            yield return newRow;
        }
    }
}

// 使用
var results = FeatureQuery.Where(allFeatures, f => 
    f["TYPE"]?.ToString() == "City" && 
    Convert.ToDouble(f["POPULATION"] ?? 0) > 500000);
```

Select 里用了 yield return，意味着延迟执行：调用时不会立即遍历，真正取数据发生在 foreach 或 ToList 时。这本身没问题，但要注意原表的生命周期——如果原表在枚举前被释放或修改，延迟执行就会出问题。需要立即执行时加 ToList。

newRow 通过 Table.NewRow 创建，类型是 DataRow，需要转成 FeatureDataRow 才能设置 Geometry。转换失败说明表不是要素表，通常是查询结果为空后自己造表造成的。另外这种行属于"游离行"，没有真正加入表里，某些操作会失效，只适合做只读展示。

## 11.3 空间关系判断

空间关系判断是几何层的精确计算，输入输出都是 NetTopologySuite 的 Geometry。它不查数据源，只比较两个几何对象的位置关系，所以既可以用于内存中的要素，也可以用于用户画出来的临时图形。

几种关系容易混淆：Contains 表示 A 包含 B，B 的所有点都在 A 的内部或边界上；Within 是反过来的包含；Intersects 只要有公共点就算；Touches 只接触边界、内部不相交；Crosses 一般用于线与面、线与线的交叉；Overlaps 要求部分重叠但不包含。用错关系会得到"看起来差不多、统计结果不对"的答案，业务代码里最好用具体到语义的方法，不要一律用 Intersects。

### 11.3.1 基本空间关系

示例里用五个坐标点构造了一个正方形面，再判断点、面之间的各种关系。构造多边形时首尾坐标要相同（形成闭合环），少一个点或者首尾不同，构造出来的几何就是无效的，后续判断结果不可信。

几何对象一旦创建就不可变。每次 buffer、intersection 都会生成新对象，原来的对象不受影响。这个特性让代码写起来安全，代价是频繁操作会产生大量临时对象，循环里要注意内存。

```csharp
using NetTopologySuite.Geometries;

var factory = new GeometryFactory();

var polygon = factory.CreatePolygon(new Coordinate[]
{
    new Coordinate(0, 0),
    new Coordinate(10, 0),
    new Coordinate(10, 10),
    new Coordinate(0, 10),
    new Coordinate(0, 0)
});

var point = factory.CreatePoint(new Coordinate(5, 5));
var outsidePoint = factory.CreatePoint(new Coordinate(15, 15));

// 空间关系判断
Console.WriteLine($"包含: {polygon.Contains(point)}");         // true
Console.WriteLine($"在内部: {point.Within(polygon)}");         // true
Console.WriteLine($"相交: {polygon.Intersects(point)}");       // true
Console.WriteLine($"分离: {polygon.Disjoint(outsidePoint)}");  // true
Console.WriteLine($"相邻: {polygon.Touches(point)}");          // false
```

注释里的期望值可以帮助理解语义：点在面内时 Contains 为 true，Within 为 true，Intersects 为 true；Touches 为 false，因为点在内部而不只是边界接触。把这几行打印结果和期望值对照跑一遍，比读文档更容易记清区别。

真实数据里的几何常有自相交、重复点、未闭合环这些问题，空间关系计算在无效几何上的结果没有保证。批量判断前先做一次有效性检查，无效的修掉或跳过，比事后解释异常结果省事。

### 11.3.2 空间关系查询

SpatialRelationQuery 把关系判断应用到要素集合上，是"查询里带空间条件"的实现方式。每个方法都是一次全量遍历，适合内存里已经有候选集的情况；数据量大时应当先用空间索引或范围查询把候选集缩小。

WithinDistance 用 Distance 判断，Distance 返回的是两个几何之间的最短距离，单位是坐标系单位。经纬度坐标下这个值是多少度，不是米，判断"五百米内"必须先把数据投影到米制坐标系，或者用球面距离公式自己算。

```csharp
public class SpatialRelationQuery
{
    public static IEnumerable<FeatureDataRow> Contains(
        IEnumerable<FeatureDataRow> features, Geometry queryGeometry)
    {
        return features.Where(f => f.Geometry.Contains(queryGeometry));
    }
    
    public static IEnumerable<FeatureDataRow> Within(
        IEnumerable<FeatureDataRow> features, Geometry queryGeometry)
    {
        return features.Where(f => f.Geometry.Within(queryGeometry));
    }
    
    public static IEnumerable<FeatureDataRow> Intersects(
        IEnumerable<FeatureDataRow> features, Geometry queryGeometry)
    {
        return features.Where(f => f.Geometry.Intersects(queryGeometry));
    }
    
    public static IEnumerable<FeatureDataRow> WithinDistance(
        IEnumerable<FeatureDataRow> features, Geometry queryGeometry, double distance)
    {
        return features.Where(f => f.Geometry.Distance(queryGeometry) <= distance);
    }
}
```

这四个方法把"先算关系再过滤"的模式固定下来，业务代码里可以直接调用，不用每次都写 Where。参数顺序要注意：Contains(features, queryGeometry) 判断的是"要素是否包含查询几何"，业务语义如果是"查询几何是否包含要素"，两个参数就要换位置。

关系判断的运算符在几何层都是精确计算，几千个要素的遍历还能接受，几十万条就要换思路。下一节的空间分析会引入更多开销更大的运算，索引的重要性会更明显。

## 11.4 空间分析

空间分析在几何运算的基础上做变换：给点画一个圆、给面扩一圈、把两个面合并或相减。这些运算都要经过计算几何库，输入几何越复杂、输出可能越慢，标准做法是先简化、再运算，运算完按需要还原精度。

分析结果通常用于可视化和统计，不直接写回数据源。需要持久化的，新建图层或写进新的要素类型；原数据保持不动，方便重算和对比。

### 11.4.1 缓冲区分析

缓冲区是最常用的分析操作：给定几何和距离，向外扩出一定宽度。点在缓冲区后变成圆（多边形近似），线变成带状，面变成更大的面。多段线的拐角处会按端点样式处理，Round 是圆弧，Flat 是平头，Square 是方头，选哪种取决于业务对拐角的解释。

缓冲距离的单位仍是坐标系单位。经纬度数据上的 0.1 表示 0.1 度，约十一公里（赤道附近），不是 0.1 米。要做以米为单位的缓冲区，先把数据投影到米制坐标系，处理完再转回来。

```csharp
// 单一缓冲区
var point = factory.CreatePoint(new Coordinate(116.4, 39.9));
var buffer = point.Buffer(0.1);  // 0.1 度缓冲区

// 不同端点样式
var lineBuffer1 = line.Buffer(10, EndCapStyle.Round);    // 圆形端点
var lineBuffer2 = line.Buffer(10, EndCapStyle.Flat);     // 平头端点
var lineBuffer3 = line.Buffer(10, EndCapStyle.Square);   // 方形端点

// 多环缓冲区
public static List<Geometry> CreateMultiRingBuffer(Geometry geometry, double[] distances)
{
    var buffers = new List<Geometry>();
    Geometry previousBuffer = geometry;
    
    foreach (var distance in distances.OrderBy(d => d))
    {
        var buffer = geometry.Buffer(distance);
        var ring = buffer.Difference(previousBuffer);
        buffers.Add(ring);
        previousBuffer = buffer;
    }
    
    return buffers;
}

// 使用
var rings = CreateMultiRingBuffer(centerPoint, new[] { 1.0, 2.0, 3.0, 5.0 });
```

多环缓冲区的实现思路是"大环减小环"。每次算出一个更大的缓冲区，再和上一次的结果做 Difference，得到中间那圈带状区域。环的顺序按距离升序，所以第一圈是最内层。

这段代码每次都对原始几何重新 buffer，而不是在内层结果上叠加，算出来的环是准确的。代价是重复计算，距离数组很大时比较慢，实际项目里环的层数一般不超过五层。

### 11.4.2 叠加分析

叠加分析处理"两个面之间的空间关系"：交集是两个面共同覆盖的部分，并集是合并后的整体，差集是第一个面去掉与第二个面的公共部分，对称差是两个面各自独有部分的合并。行政区划调整、用地冲突检测、服务范围合并，都是这几种运算的组合。

运算结果的几何类型会变化。两个不相交的面求交，结果是空几何；两个只接触边界的面求交，可能是线或点；差集运算可能把一个面切成多个面，结果类型是 MultiPolygon 或 GeometryCollection。下游代码必须按实际类型处理，不能假定一定还是 Polygon。

```csharp
// 交集
var intersection = polygon1.Intersection(polygon2);

// 并集
var union = polygon1.Union(polygon2);

// 差集
var difference = polygon1.Difference(polygon2);

// 对称差
var symDifference = polygon1.SymmetricDifference(polygon2);

// 批量合并
public static Geometry UnionAll(IEnumerable<Geometry> geometries)
{
    return geometries.Aggregate((current, next) => current.Union(next));
}

// 使用 CascadedPolygonUnion 提高性能
using NetTopologySuite.Operation.Union;
var geometryList = new List<Geometry> { polygon1, polygon2, polygon3 };
var unionResult = CascadedPolygonUnion.Union(geometryList);
```

小规模合并用 Aggregate 逐个 Union 就行，几十上百个面时速度还过得去。面一多，逐个合并的复杂度增长很快，CascadedPolygonUnion 用分治策略把合并拆成多层，性能明显更好。合并之前先把无效几何修掉，否则一次异常就会中断整个聚合。

聚合的结果可能包含大量非常小的碎片多边形，来自相邻面之间几毫米的缝隙。展示前按面积阈值过滤，或者先统一精度再合并，能减少这种视觉噪声。

### 11.4.3 距离计算

Distance 计算两个几何之间的最短距离。点与点之间就是直线距离的度量，点与面之间是点到面边界的最近距离，面与面之间是两者边界的最近距离。GeoJSON 意义上"落在面内"的两个点，Distance 为 0，因为它们的最近点在面上。

最近点的计算通过 DistanceOp.NearestPoints 完成，返回两个点组成的数组，分别对应两个几何上的最近位置。做"找回最近设施并画连线"这类需求时，比只算距离值多一份信息。

```csharp
// 两点距离
var distance = point1.Distance(point2);

// 最近点
var nearestPoints = NetTopologySuite.Operation.Distance.DistanceOp
    .NearestPoints(geometry1, geometry2);

// 查找最近要素
public static FeatureDataRow FindNearest(IEnumerable<FeatureDataRow> features, 
    Geometry queryGeometry)
{
    return features
        .OrderBy(f => f.Geometry.Distance(queryGeometry))
        .FirstOrDefault();
}

// 查找距离范围内的要素
public static IEnumerable<FeatureDataRow> FindWithinDistance(
    IEnumerable<FeatureDataRow> features, Geometry queryGeometry, double maxDistance)
{
    return features
        .Where(f => f.Geometry.Distance(queryGeometry) <= maxDistance)
        .OrderBy(f => f.Geometry.Distance(queryGeometry));
}
```

查找最近要素用 OrderBy 排序后取第一个，时间复杂度是全部比较。数据量大时这很浪费，因为只需要最小值的那个；用循环或 MinBy 只记录当前最优，能少一次完整排序。真正高效的方案还是空间索引，先用索引缩小候选范围，再在候选里算距离。

FindWithinDistance 里对每个要素都算了一次 Distance，Where 和 OrderBy 又各算一次。LINQ 的延迟执行会让距离计算重复发生，数据量大时值得先把结果投影成带距离的中间对象，再排序。

### 11.4.4 面积和长度计算

Area 和 Length 直接读几何的度量和，计算快但单位是坐标系单位。投影坐标系的单位通常是米，面积就是平方米，可以直接用；经纬度坐标系的单位是度，面积算出来是"平方度"，没有物理意义，不能直接当平方米展示。

需要在经纬度数据上算真实面积或距离，就得用球面或椭球面公式，示例里的 Haversine 计算的是两点间的大圆距离，结果以米为单位。注意它只适合算距离，算面积要复杂得多，一般转投影坐标系处理。

```csharp
// 面积（坐标系单位）
double area = polygon.Area;

// 长度（坐标系单位）
double length = lineString.Length;

// 周长
double perimeter = polygon.Length;

// 计算地理坐标系下的实际距离（使用 Haversine 公式）
public static double CalculateDistance(Coordinate point1, Coordinate point2)
{
    const double R = 6371000;  // 地球半径（米）
    
    double lat1 = point1.Y * Math.PI / 180;
    double lat2 = point2.Y * Math.PI / 180;
    double deltaLat = (point2.Y - point1.Y) * Math.PI / 180;
    double deltaLon = (point2.X - point1.X) * Math.PI / 180;
    
    double a = Math.Sin(deltaLat / 2) * Math.Sin(deltaLat / 2) +
               Math.Cos(lat1) * Math.Cos(lat2) *
               Math.Sin(deltaLon / 2) * Math.Sin(deltaLon / 2);
    
    double c = 2 * Math.Atan2(Math.Sqrt(a), Math.Sqrt(1 - a));
    
    return R * c;  // 米
}

```

这段代码里有个值得说明的取舍：CalculateGeographicArea 没有实现，而是直接抛异常。这比返回一个错误的数字更诚实，调用方会立刻发现功能缺失，而不是拿着"平方度"当平方米去写报告。生产代码里遇到精度要求高的地理计算，用成熟的投影库或地理计算库，不要自己手写公式。

Haversine 公式假设地球是正球体，与真实椭球有千分之三左右的误差。导航、测绘这类场景需要更精确的 Vincenty 或投影计算，普通展示够用了。

## 11.5 空间索引

索引解决的是"如何不遍历全部要素就找到候选"。把每个要素的外包矩形插进树结构，查询时先用范围筛选出可能有交集的候选，再对候选做精确判断。SharpMap 本身不做图层级索引，但数据提供者（ShapeFile、PostGIS）内部通常有索引，手工建索引主要用在"把结果集缓存在内存里反复查询"的场景。

网格索引、四叉树、STRtree 各有适用规模。STRtree 是批量构建的静态索引，适合一次建好反复查；数据频繁增删时重建成本比较高。

### 11.5.1 使用 STRtree

构建索引分两步：逐个 Insert 外包矩形和要素，然后 Build。Build 之后树结构才真正生成，之前的查询可能返回空或不完整，所以插入和查询的顺序不能颠倒。

查询接受 Envelope，返回外包矩形与它相交的所有要素。这是粗筛，结果里可能有实际几何并不相交的要素，需要再调用 Intersects、Contains 做精确过滤。

```csharp
using NetTopologySuite.Index.Strtree;

// 创建空间索引
var index = new STRtree<FeatureDataRow>();

// 添加要素到索引
foreach (FeatureDataRow feature in featureTable.Rows)
{
    index.Insert(feature.Geometry.EnvelopeInternal, feature);
}

// 构建索引
index.Build();

// 查询
var queryEnvelope = new Envelope(116.0, 117.0, 39.0, 40.0);
var results = index.Query(queryEnvelope);

// 精确过滤
var preciseResults = results
    .Where(f => f.Geometry.Intersects(queryGeometry))
    .ToList();
```

索引里存的是引用，要素对象本身没有被复制。这带来两个影响：修改要素的几何之后，索引里记录的外包矩形就过期了，必须重建；要素从集合里移除后，索引仍然持有它，会造成内存泄漏。索引的生命周期要跟着数据走。

STRtree 也有区域查询和 k 近邻查询，泛型参数类型决定了能存什么。如果只是临时查一次，建索引的开销可能超过收益，索引适合"一次构建、多次查询"的场景。

### 11.5.2 使用 Quadtree

四叉树把空间按四分不断细分，适合数据分布比较均匀的场景。接口和 STRtree 类似：Insert 外包矩形、Query 范围。区别在构建方式和更新成本，四叉树可以增量插入，STRtree 更适合一次性批量构建。

选择和数据类型匹配的索引。城市 POI 分布不均，四叉树容易在密集区域退化成链表；STRtree 的批量构建对这种分布更稳。数据更新频繁时，还要考虑重建成本。

```csharp
using NetTopologySuite.Index.Quadtree;

var quadtree = new Quadtree<FeatureDataRow>();

// 添加要素
foreach (FeatureDataRow feature in featureTable.Rows)
{
    quadtree.Insert(feature.Geometry.EnvelopeInternal, feature);
}

// 查询
var results = quadtree.Query(queryEnvelope);
```

四叉树的 Query 同样只做外包矩形判断，精确过滤要自己补。两种索引都只对内存中的要素集合有效，不能直接替换数据源查询；真正要加速数据源查询，应当配置数据库空间索引或 Shapefile 的索引文件。

## 11.6 空间分析示例

前面各节是零件，这一节把它们装成完整功能。示例代码都遵循同一个模式：先用索引或范围查询得到候选，再对候选做精确判断，最后按业务需要组织结果。这个"粗筛加精判"的组合，是空间查询性能的关键。

### 11.6.1 点在面内查询

点在面内查询用来回答"这个坐标落在哪个行政区/服务区/网格里"。如果每个点都遍历所有面，几万个点乘以几千个面就是几千万次判断，响应时间会到秒级。先把面建进 STRtree，查询时只取出外包矩形包含该点的少量候选，再逐个 Contains，速度能提高几个数量级。

构造索引的代价是一次性的，之后可以反复查。数据更新后记得重建，否则新加的面查不到、删掉的面还能查出来。

```csharp
public class PointInPolygonQuery
{
    private readonly STRtree<FeatureDataRow> _polygonIndex;
    
    public PointInPolygonQuery(IEnumerable<FeatureDataRow> polygons)
    {
        _polygonIndex = new STRtree<FeatureDataRow>();
        
        foreach (var polygon in polygons)
        {
            _polygonIndex.Insert(polygon.Geometry.EnvelopeInternal, polygon);
        }
        
        _polygonIndex.Build();
    }
    
    public FeatureDataRow FindContainingPolygon(Point point)
    {
        var candidates = _polygonIndex.Query(point.EnvelopeInternal);
        
        return candidates.FirstOrDefault(p => p.Geometry.Contains(point));
    }
    
    public Dictionary<string, int> CountPointsInPolygons(IEnumerable<Point> points, 
        string polygonIdField)
    {
        var counts = new Dictionary<string, int>();
        
        foreach (var point in points)
        {
            var polygon = FindContainingPolygon(point);
            if (polygon != null)
            {
                string id = polygon[polygonIdField]?.ToString() ?? "";
                if (!counts.ContainsKey(id))
                    counts[id] = 0;
                counts[id]++;
            }
        }
        
        return counts;
    }
}
```

CountPointsInPolygons 会调 FindContainingPolygon，每次查询都走一遍索引，整体复杂度是点数乘以少量候选判断，可以接受。如果点的数量特别大，可以先把点也按索引批量组织，或者用空间连接的方式在数据库里做，避免逐点查。

FindContainingPolygon 返回第一个命中的面。行政边界可能重叠（比如开发区和行政区），业务上要指定优先级时，把所有命中面都取出来再按规则选，而不是直接取第一个。

### 11.6.2 最近邻分析

最近邻分析的朴素做法是两两算距离，源要素和目标要素各有几万个时计算量爆炸。示例用 STRtree 存目标要素，先按源要素的外包矩形扩大一点范围查询候选，找不到再逐步扩大，直到找到为止。

这个"逐步扩大"的循环要小心边界。目标集为空时，循环会一直扩大下去，永远不会退出；查询范围扩到世界范围仍然没结果，应当跳出循环并返回空。示例代码没有处理这两种情况，生产实现必须补上终止条件。

```csharp
public class NearestNeighborAnalysis
{
    public static Dictionary<FeatureDataRow, FeatureDataRow> FindNearestNeighbors(
        IEnumerable<FeatureDataRow> sourceFeatures,
        IEnumerable<FeatureDataRow> targetFeatures)
    {
        var results = new Dictionary<FeatureDataRow, FeatureDataRow>();
        var targetIndex = new STRtree<FeatureDataRow>();
        
        foreach (var target in targetFeatures)
        {
            targetIndex.Insert(target.Geometry.EnvelopeInternal, target);
        }
        targetIndex.Build();
        
        foreach (var source in sourceFeatures)
        {
            var envelope = source.Geometry.EnvelopeInternal;
            envelope.ExpandBy(1);  // 初始搜索范围
            
            FeatureDataRow nearest = null;
            double minDistance = double.MaxValue;
            
            while (nearest == null)
            {
                var candidates = targetIndex.Query(envelope);
                
                foreach (var candidate in candidates)
                {
                    var dist = source.Geometry.Distance(candidate.Geometry);
                    if (dist < minDistance)
                    {
                        minDistance = dist;
                        nearest = candidate;
                    }
                }
                
                if (nearest == null)
                {
                    envelope.ExpandBy(envelope.Width);  // 扩大搜索范围
                }
            }
            
            results[source] = nearest;
        }
        
        return results;
    }
}
```

扩大搜索范围时，每次只按宽度 expand 未必覆盖所有方向。比较稳的做法是第一次就放大一个较大的范围，或者分几档扩大，同时记录已查询过的范围避免重复。候选集排序后再取最近，比判断"当前最优"再继续扩大更容易写对。

还有一点：距离比较的口径要统一。源要素和目标要素必须在同一坐标系，否则算出来的距离没有意义。跨坐标系的数据先转换再比较，不要拿经纬度的度数和投影的米数直接比大小。

## 11.7 本章小结

本章介绍了 SharpMap 的空间查询与分析功能：

1. **空间查询**：范围查询、几何查询、点击查询
2. **属性查询**：LINQ 查询、SQL 风格查询
3. **空间关系**：Contains、Within、Intersects 等判断
4. **空间分析**：缓冲区、叠加分析、距离计算
5. **空间索引**：STRtree、Quadtree 的使用

把这一章的内容整理成几条实践规则：查询前先明确坐标系的单位，距离、容差、缓冲半径都按这个单位传值；能用范围查询和索引缩小候选集的，不要全量遍历；空间关系用语义最贴近业务的那个方法，不要一律用 Intersects；几何运算前检查有效性，运算后按实际返回类型处理；索引一次建好反复使用，数据变了就重建。

最容易出错的地方集中在单位换算和坐标顺序上：经纬度上做缓冲、用度数判断米、Envelope 参数顺序写反，这三类问题不会抛异常，只会给出"看起来不对"的结果。写查询代码时把单位写进变量名或注释，能减少很多排查时间。
