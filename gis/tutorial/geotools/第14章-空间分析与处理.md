# 第14章 - 空间分析与处理

## 14.1 空间分析概述

GeoTools 的空间分析能力大部分来自 JTS（Java Topology Suite）。JTS 实现了 OGC Simple Features 规范定义的那套几何模型与空间谓词，GeoTools 在它之上补上了要素、属性、坐标系与渲染。所以做分析时心里要有两层：几何运算交给 JTS，数据组织与坐标问题交给 GeoTools。很多“结果不对”的问题最终能追到坐标参考系上，而不是算法上。

这里必须先说清楚一个前提：JTS 只认平面坐标。它不知道数据是经纬度还是投影坐标，`buffer`、`distance`、`getArea` 都是按坐标数值直接算的。把 WGS84 的经纬度直接喂进去，算出来的面积单位是“平方度”，距离单位是“度”，缓冲区半径 0.01 表示 0.01 度而不是 10 米。JTS 不报错，因为从它的角度看这是合法的平面几何。做任何量算类分析之前，先把数据重投影到合适的投影坐标系，是这一章所有代码的使用前提。

## 14.2 缓冲区分析

缓冲区的本质是把几何向外（或向内）膨胀一个距离，膨胀后的边界由圆弧或折线逼近。JTS 的 `buffer` 用固定的圆弧逼近精度：默认每个象限 8 段，一个整圆被画成 32 边形。这个精度对显示够用，对量算有细微误差，半径越大误差绝对值越大。需要更精确时用带 `quadrantSegments` 参数的重载。

### 14.2.1 基本缓冲区

点、线、面的 `buffer(distance)` 走的是同一个实现，结果类型会变：点缓冲得到面，线缓冲得到面（两端加圆头），面缓冲仍然得到面。返回值统一声明为 `Geometry` 而不是 `Polygon`，因为复杂几何的缓冲结果可能是 `MultiPolygon`，甚至包含空洞。调用方拿到结果后要判类型，不能假定它一定是可以当作单个 `Polygon` 用的对象。

`polygon.buffer(-distance)` 是内缩的标准写法。内缩的取值范围有物理限制：距离超过多边形内切圆半径时，结果会变成空几何（`isEmpty()` 返回 true），而不是报错。批量内缩时逐个判断空几何，可以识别出“所有边都被吃掉”的退化地块。内缩还可能把一个面拆成多个部分，比如哑铃形地块从中间收缩断开，结果就是 `MultiPolygon`。

`quadrantSegments` 控制每四分之一圆的线段数。默认 8，一个整圆 32 段；改成 16 得到 64 段，接近正圆。参数加大不是没有代价：每个缓冲结果的顶点数按比例增长，后续的空间判断、渲染、序列化都会变慢。地图上显示用的缓冲区取 8 到 12 足够，量算边界用于面积统计时可以到 16 以上。另有一个参数叫 `mitreLimit`，只在尖角连接方式下起作用，示例里没有展示。

`styledBuffer` 用 `BufferParameters` 控制端点与拐角样式。`setEndCapStyle` 支持 `CAP_ROUND`（圆头）、`CAP_FLAT`（平头）、`CAP_SQUARE`（方头），平头缓冲在道路两侧取范围时更贴合线本身，方头会向两端多伸出一个半径。`setJoinStyle` 支持 `JOIN_ROUND`、`JOIN_MITRE`、`JOIN_BEVEL`，尖角连接（mitre）在拐角很锐时会产生很长的尖刺，用 `setMitreLimit` 限制尖刺长度。参数对象可以在多次调用间复用，只要业务配置不变。

`singleSideBuffer` 是单侧缓冲：`setSingleSided(true)` 之后，正距离缓冲在线的左侧，负距离在右侧，具体哪一侧取决于线的走向（有向线段的左边）。这个功能用于河道、道路的“一侧影响范围”很好用，但它依赖线方向，数据方向不一致时结果会左右乱跳，使用前应确认方向已经规范化。注意示例里 `leftSide` 的取值和距离正负的对应关系在不同 JTS 版本上表现一致，但 GML/GeoJSON 的坐标顺序会改变“左”的定义，跨数据源时要验证。

```java
public class BufferAnalysis {
    
    // 点缓冲区
    public static Geometry pointBuffer(Point point, double distance) {
        return point.buffer(distance);
    }
    
    // 线缓冲区
    public static Geometry lineBuffer(LineString line, double distance) {
        return line.buffer(distance);
    }
    
    // 面缓冲区（外扩）
    public static Geometry polygonBuffer(Polygon polygon, double distance) {
        return polygon.buffer(distance);
    }
    
    // 面缓冲区（内缩）
    public static Geometry polygonShrink(Polygon polygon, double distance) {
        return polygon.buffer(-distance);  // 负值表示内缩
    }
    
    // 控制缓冲区质量
    public static Geometry qualityBuffer(Geometry geom, double distance, 
            int quadrantSegments) {
        // quadrantSegments: 每象限的线段数，值越大越圆滑
        return geom.buffer(distance, quadrantSegments);
    }
    
    // 不同端点样式的缓冲区
    public static Geometry styledBuffer(LineString line, double distance,
            int capStyle, int joinStyle) {
        BufferParameters params = new BufferParameters();
        params.setEndCapStyle(capStyle);     // CAP_ROUND, CAP_FLAT, CAP_SQUARE
        params.setJoinStyle(joinStyle);      // JOIN_ROUND, JOIN_MITRE, JOIN_BEVEL
        
        return BufferOp.bufferOp(line, distance, params);
    }
    
    // 单侧缓冲区
    public static Geometry singleSideBuffer(LineString line, double distance,
            boolean leftSide) {
        BufferParameters params = new BufferParameters();
        params.setSingleSided(true);
        
        double d = leftSide ? distance : -distance;
        return BufferOp.bufferOp(line, d, params);
    }
}
```

### 14.2.2 要素集合缓冲区

从单个几何到要素集合，多出来的是“类型定义”这一层。GeoTools 的 `SimpleFeatureType` 描述字段名、类型、坐标系，`SimpleFeatureBuilder` 按这个定义逐列填值，`DefaultFeatureCollection` 承接结果。三者的顺序不能乱：先建类型，再建 builder，最后往集合里加要素。

`SimpleFeatureTypeBuilder` 的写法值得逐行看：`setName` 给结果类型一个新的名字，与服务端发布图层名冲突时容易排查；`setCRS` 继承源数据的坐标系，不设的话结果要素没有坐标系信息，后续重投影会报“找不到 CRS”；`add("the_geom", Polygon.class)` 显式声明几何列的类型为面，这一步决定了输出是面图层。

复制属性的循环跳过了 `GeometryDescriptor`，也就是跳过了源数据的几何列。必须跳过，否则结果类型里会有两个几何列，`SimpleFeatureBuilder` 在 build 时不知道该用哪一个。这里用 `desc instanceof GeometryDescriptor` 判断，比按字段名判断可靠，因为几何列的名字在不同数据源里不一定是 `the_geom`。

`builder.add(buffer)` 之后逐个 `add` 非几何属性，顺序必须与 `resultType` 中字段的顺序一致。示例里类型是先几何后属性，属性复制也先几何再依次加属性，顺序对得上。`feature.getAttributeCount()` 包含几何列，所以循环里也要用 `instanceof Geometry` 跳过；如果漏掉这一步，属性列会整体错位一格，数据看起来“有值”但全错了位置，这是最隐蔽的一类 bug。

`builder.buildFeature(null)` 传入 null 表示不指定 FID，由集合自行分配。批量生成结果时不需要关心 FID，但写回带主键的数据库时要换成有意义的 ID。`try (SimpleFeatureIterator iter = features.features())` 的 try-with-resources 写法是必需的，迭代器持有底层连接与游标，不关闭会导致连接泄漏，数据量大时表现为“跑几百次之后连接池耗尽”。

```java
public class CollectionBuffer {
    
    public static SimpleFeatureCollection bufferCollection(
            SimpleFeatureCollection features, double distance) throws Exception {
        
        SimpleFeatureType originalType = features.getSchema();
        
        // 创建结果类型
        SimpleFeatureTypeBuilder typeBuilder = new SimpleFeatureTypeBuilder();
        typeBuilder.setName(originalType.getTypeName() + "_buffer");
        typeBuilder.setCRS(originalType.getCoordinateReferenceSystem());
        typeBuilder.add("the_geom", Polygon.class);
        
        // 复制原有属性
        for (AttributeDescriptor desc : originalType.getAttributeDescriptors()) {
            if (!(desc instanceof GeometryDescriptor)) {
                typeBuilder.add(desc);
            }
        }
        
        SimpleFeatureType resultType = typeBuilder.buildFeatureType();
        
        // 创建缓冲区
        DefaultFeatureCollection result = new DefaultFeatureCollection();
        SimpleFeatureBuilder builder = new SimpleFeatureBuilder(resultType);
        
        try (SimpleFeatureIterator iter = features.features()) {
            while (iter.hasNext()) {
                SimpleFeature feature = iter.next();
                Geometry geom = (Geometry) feature.getDefaultGeometry();
                Geometry buffer = geom.buffer(distance);
                
                builder.add(buffer);
                for (int i = 0; i < feature.getAttributeCount(); i++) {
                    if (!(feature.getAttribute(i) instanceof Geometry)) {
                        builder.add(feature.getAttribute(i));
                    }
                }
                
                result.add(builder.buildFeature(null));
            }
        }
        
        return result;
    }
}
```

## 14.3 叠加分析

叠加分析在 JTS 里对应四个二元运算：`intersection`、`union`、`difference`、`symDifference`。它们都返回新几何，输入几何不变；语义与集合运算一致，但对几何类型有要求：交集的结果类型由输入决定，面与面交可能得到面、线或点（只在边界接触时），直接当作 Polygon 用会在后续步骤出错。

### 14.3.1 相交分析

`clipFeatures` 是最常用的裁剪操作：用一个裁剪几何去切要素集合，保留落在其中的部分。实现上有两处效率可以改进。一是没有先用 `clipGeom.getEnvelopeInternal()` 做粗筛，逐要素调用 `intersects` 本身是精确判断，比包围盒判断慢；数据量大时应当先用 `Envelope.intersects` 过滤候选项。二是逐要素创建新几何没有释放，几何对象在 JTS 里是不可变对象，交给 GC 回收，批量处理时注意堆内存。

`builder` 只创建了一次，在循环里反复使用。`SimpleFeatureBuilder` 每次 `buildFeature` 之后需要重新填值，示例里每次循环都从头 `add` 全部字段，这样是对的；如果某些字段在某些分支没填，builder 会残留上一轮的值，生成“复用脏数据”的要素。养成“每轮都填满、build 之后当作已清空”的习惯，能避免这类串值。

`CascadedPolygonUnion.union(geometries)` 是 JTS 针对面集合合并优化的算法：先把多边形按包围盒聚合，再分层合并，比逐对 `union` 快。它有两个限制：输入必须全是 Polygon 或 MultiPolygon，混入线或点会抛异常；输入集合为空时返回 null。示例里没有做类型校验，调用方要自己保证。对少量几何，直接循环 `union` 更简单；几百个以上再换这个算法。

`difference` 与 `symDifference` 的语义差别值得记一下：差集从第一个几何中减去第二个，结果落在第一个几何的范围内；对称差保留“只属于其中一个”的部分，等于先并再减去交。两者都不会因为第二个几何完全覆盖第一个而报错，结果是空几何，调用方要判 `isEmpty`。

```java
public class OverlayAnalysis {
    
    // 两个几何的交集
    public static Geometry intersection(Geometry geom1, Geometry geom2) {
        return geom1.intersection(geom2);
    }
    
    // 要素裁剪
    public static SimpleFeatureCollection clipFeatures(
            SimpleFeatureCollection features, Geometry clipGeom) throws Exception {
        
        DefaultFeatureCollection result = new DefaultFeatureCollection();
        SimpleFeatureBuilder builder = new SimpleFeatureBuilder(features.getSchema());
        
        try (SimpleFeatureIterator iter = features.features()) {
            while (iter.hasNext()) {
                SimpleFeature feature = iter.next();
                Geometry geom = (Geometry) feature.getDefaultGeometry();
                
                if (geom.intersects(clipGeom)) {
                    Geometry clipped = geom.intersection(clipGeom);
                    
                    if (!clipped.isEmpty()) {
                        for (int i = 0; i < feature.getAttributeCount(); i++) {
                            Object attr = feature.getAttribute(i);
                            if (attr instanceof Geometry) {
                                builder.add(clipped);
                            } else {
                                builder.add(attr);
                            }
                        }
                        result.add(builder.buildFeature(null));
                    }
                }
            }
        }
        
        return result;
    }
    
    // 合并几何
    public static Geometry union(List<Geometry> geometries) {
        return CascadedPolygonUnion.union(geometries);
    }
    
    // 差集
    public static Geometry difference(Geometry geom1, Geometry geom2) {
        return geom1.difference(geom2);
    }
    
    // 对称差集
    public static Geometry symmetricDifference(Geometry geom1, Geometry geom2) {
        return geom1.symDifference(geom2);
    }
}
```

### 14.3.2 空间连接

空间连接用空间索引把两层要素按几何关系配对。索引的作用是把“每个目标要素与所有连接要素比较”的笛卡尔积，缩小成“只与包围盒相交的少数候选比较”。示例用 `STRtree` 装连接要素，按包围盒查询候选，再用精确谓词确认。这个模式在所有 GIS 平台里都一样，区别只在索引实现。

`joinFeatures` 这个 `Map<Envelope, SimpleFeature>` 是多余的：索引里已经存了要素，`index.query` 返回的就是要素本身，这个 Map 建了却没有用。真实代码里可以删掉，省一次哈希表插入和内存占用。类似地，`index.insert` 的 key 是包围盒，查询时传的也是包围盒，这是 STRtree 的用法，不需要额外存映射。

`index.build()` 一定要调用。STRtree 是静态索引，插入阶段只记录数据，`build` 之后才建立树结构，不调用 build 直接 query 会抛异常（部分版本）或返回错误结果。静态索引意味着建好之后不能再插入，元素集合变化就要重建；数据频繁增删时应当改用 `Quadtree`，或者每次变化后重建索引。

结果类型用 `typeBuilder.init(targetType)` 起手，复制目标图层的全部字段和坐标系，再给连接图层的非几何字段加 `join_` 前缀。这里用 `desc.getType().getBinding()` 取 Java 类型，比用字符串类型名更可靠，因为 `AttributeDescriptor` 携带的是实际绑定类型。`init` 之后 `setName` 会重置名字——顺序要小心，先 init 再 setName，否则结果类型会继承目标图层的名字，写回同名数据源时冲突。

执行部分调用了 `targetGeom.intersects(joinGeom)`，这里示例代码里变量名 `joinType` 既用来表示连接类型字符串，又和 `SimpleFeatureType joinTypeDef` 混在一起，读代码时要分清。另外它把 `switch` 写在候选循环内部，每个候选都要重新判断一次字符串，可以提到循环外面按类型取一个谓词函数，和 GDAL 章节的做法一样。

```java
public class SpatialJoin {
    
    public static SimpleFeatureCollection spatialJoin(
            SimpleFeatureCollection target,
            SimpleFeatureCollection join,
            String joinType) throws Exception {  // "intersects", "contains", "within"
        
        // 构建空间索引
        STRtree index = new STRtree();
        
        Map<Envelope, SimpleFeature> joinFeatures = new HashMap<>();
        try (SimpleFeatureIterator iter = join.features()) {
            while (iter.hasNext()) {
                SimpleFeature f = iter.next();
                Geometry g = (Geometry) f.getDefaultGeometry();
                Envelope env = g.getEnvelopeInternal();
                index.insert(env, f);
                joinFeatures.put(env, f);
            }
        }
        index.build();
        
        // 构建结果类型
        SimpleFeatureType targetType = target.getSchema();
        SimpleFeatureType joinTypeDef = join.getSchema();
        
        SimpleFeatureTypeBuilder typeBuilder = new SimpleFeatureTypeBuilder();
        typeBuilder.init(targetType);
        
        for (AttributeDescriptor desc : joinTypeDef.getAttributeDescriptors()) {
            if (!(desc instanceof GeometryDescriptor)) {
                String name = "join_" + desc.getLocalName();
                typeBuilder.add(name, desc.getType().getBinding());
            }
        }
        
        SimpleFeatureType resultType = typeBuilder.buildFeatureType();
        DefaultFeatureCollection result = new DefaultFeatureCollection();
        SimpleFeatureBuilder builder = new SimpleFeatureBuilder(resultType);
        
        // 执行连接
        try (SimpleFeatureIterator iter = target.features()) {
            while (iter.hasNext()) {
                SimpleFeature targetFeature = iter.next();
                Geometry targetGeom = (Geometry) targetFeature.getDefaultGeometry();
                
                // 查询候选
                List<?> candidates = index.query(targetGeom.getEnvelopeInternal());
                
                for (Object candidate : candidates) {
                    SimpleFeature joinFeature = (SimpleFeature) candidate;
                    Geometry joinGeom = (Geometry) joinFeature.getDefaultGeometry();
                    
                    boolean matches = false;
                    switch (joinType) {
                        case "intersects":
                            matches = targetGeom.intersects(joinGeom);
                            break;
                        case "contains":
                            matches = targetGeom.contains(joinGeom);
                            break;
                        case "within":
                            matches = targetGeom.within(joinGeom);
                            break;
                    }
                    
                    if (matches) {
                        // 复制目标属性
                        for (int i = 0; i < targetFeature.getAttributeCount(); i++) {
                            builder.add(targetFeature.getAttribute(i));
                        }
                        
                        // 复制连接属性
                        for (int i = 0; i < joinFeature.getAttributeCount(); i++) {
                            if (!(joinFeature.getAttribute(i) instanceof Geometry)) {
                                builder.add(joinFeature.getAttribute(i));
                            }
                        }
                        
                        result.add(builder.buildFeature(null));
                    }
                }
            }
        }
        
        return result;
    }
}
```

## 14.4 空间查询

空间查询有两种用法：一种是“给我落在某个范围内的要素”，用过滤器交给数据源去查；另一种是“给我最接近某个位置的那一个”，只能靠遍历或空间索引。前者利用数据库或文件的空间索引，能下推到存储层；后者在数据量不大时遍历反而更简单，几万条以上才值得建索引。

### 14.4.1 最近邻查询

`findNearest` 是暴力做法：遍历所有要素，逐个算 `distance`，记录最小值。`Geometry.distance` 计算的是两个几何之间的最短距离，对点与面、面与面都有效，不只是点对点。复杂度是 O(n) 次几何距离计算，每次计算都要比较所有边的最近点，数据量大时开销明显。几千条以内可以接受，几十万条就不能这么写了。

`findNearestWithIndex` 用 `STRtree.nearestNeighbour` 做索引查询，理论复杂度接近对数级。这里有两处必须注意。一是 `ItemDistance` 里的 `item1`、`item2` 取出来的对象类型必须与树里实际存的对象一致：如果建索引时存的是 `SimpleFeature`，这里 `(Geometry) item1.getItem()` 会抛 `ClassCastException`；如果存的是 `Geometry`，最后 `(SimpleFeature) nearest` 又会失败。示例只给了查询侧代码，没有给建索引侧，实际使用时两边要统一。二是传给 `nearestNeighbour` 的第二个参数是查询对象，它会在 `ItemDistance` 里被当作 `item2` 参与距离计算，类型同样要匹配。

`nearestNeighbour` 返回的是树里存的原始对象，可能是 `SimpleFeature`，也可能是 `Geometry`，取决于插入时传了什么。返回 null 表示树是空的。这里的边界处理比暴力版本更隐晦，封装时最好把类型转换和空判断放在方法内部完成。

`findWithinDistance` 分两步：先用缓冲区把范围查询转成几何相交查询（粗筛），再用精确距离确认（精筛）。这样写比直接逐个算距离稍微聪明一点，但粗筛仍然在内存里遍历所有要素，没有用到索引。真正的做法是先用 `STRtree.query(buffer.getEnvelopeInternal())` 拿到候选，再对候选做精确判断，索引的过滤效果在候选量与总量差距大时非常明显。

```java
public class NearestNeighbor {
    
    // 查找最近的要素
    public static SimpleFeature findNearest(SimpleFeatureCollection features,
            Geometry queryGeom) throws Exception {
        
        SimpleFeature nearest = null;
        double minDistance = Double.MAX_VALUE;
        
        try (SimpleFeatureIterator iter = features.features()) {
            while (iter.hasNext()) {
                SimpleFeature feature = iter.next();
                Geometry geom = (Geometry) feature.getDefaultGeometry();
                
                double distance = queryGeom.distance(geom);
                if (distance < minDistance) {
                    minDistance = distance;
                    nearest = feature;
                }
            }
        }
        
        return nearest;
    }
    
    // 使用空间索引的最近邻查询
    public static SimpleFeature findNearestWithIndex(STRtree index,
            Point queryPoint) {
        
        Object nearest = index.nearestNeighbour(
            queryPoint.getEnvelopeInternal(),
            queryPoint,
            new ItemDistance() {
                @Override
                public double distance(ItemBoundable item1, ItemBoundable item2) {
                    Geometry g1 = (Geometry) item1.getItem();
                    Geometry g2 = (Geometry) item2.getItem();
                    return g1.distance(g2);
                }
            }
        );
        
        return (SimpleFeature) nearest;
    }
    
    // 查找距离范围内的所有要素
    public static List<SimpleFeature> findWithinDistance(
            SimpleFeatureCollection features,
            Geometry queryGeom, double distance) throws Exception {
        
        List<SimpleFeature> result = new ArrayList<>();
        
        // 先用缓冲区粗筛
        Geometry buffer = queryGeom.buffer(distance);
        
        try (SimpleFeatureIterator iter = features.features()) {
            while (iter.hasNext()) {
                SimpleFeature feature = iter.next();
                Geometry geom = (Geometry) feature.getDefaultGeometry();
                
                if (geom.intersects(buffer) && queryGeom.distance(geom) <= distance) {
                    result.add(feature);
                }
            }
        }
        
        return result;
    }
}
```

### 14.4.2 空间过滤器

过滤器是 OGC Filter 规范在 GeoTools 里的实现，`FilterFactory2` 负责构造。它的价值在于“可下推”：交给 `source.getFeatures(query)` 之后，数据源能把它翻译成 SQL 的 `ST_Intersects` 或文件的空间索引查询，只在返回结果时才把要素读进来，比全量读出再过滤快一个数量级。示例把构造逻辑封装成静态方法，返回 `Filter` 对象供调用方组合，这个做法适合把查询条件做成配置。

`ff.bbox(property, minX, minY, maxX, maxY, srs)` 的最后一个参数是坐标参考系字符串，它决定这个包围盒按哪个坐标系解释。如果数据源是 EPSG:3857 而过滤条件按 EPSG:4326 传，GeoTools 会在 SQL 层做转换，结果正确但可能用不上空间索引，性能变差。传数据源自身的坐标系最稳妥。

`ff.intersects`、`ff.contains`、`ff.within` 的语义与 JTS 同名方法对应，但参数顺序要分清：`ff.intersects(property, literal)` 表示“要素的几何与给定几何相交”，`ff.within(property, literal)` 表示“要素几何落在给定几何内”。两者方向相反，写反了结果会完全不同，而且都能正常执行，不会报错。

`ff.dwithin(property, literal, distance, units)` 是“距离在阈值内”的过滤器，`units` 是单位字符串（如 `"m"`、`"km"`），GeoTools 会按单位与坐标系做换算。`ff.beyond` 相反，表示超出阈值。这两个过滤器依赖坐标系信息，没有 CRS 的数据源上用会抛异常。把单位字符串写成 `"meters"`、`"meter"` 之类变体时，部分版本不认，统一用 `"m"` 最安全。

```java
public class SpatialFilters {
    
    private static final FilterFactory2 ff = CommonFactoryFinder.getFilterFactory2();
    
    // BBOX 过滤
    public static Filter createBBoxFilter(String geomProperty, 
            double minX, double minY, double maxX, double maxY, String srs) {
        return ff.bbox(ff.property(geomProperty), minX, minY, maxX, maxY, srs);
    }
    
    // 相交过滤
    public static Filter createIntersectsFilter(String geomProperty, Geometry geom) {
        return ff.intersects(ff.property(geomProperty), ff.literal(geom));
    }
    
    // 包含过滤
    public static Filter createContainsFilter(String geomProperty, Geometry geom) {
        return ff.contains(ff.property(geomProperty), ff.literal(geom));
    }
    
    // 在...内部
    public static Filter createWithinFilter(String geomProperty, Geometry geom) {
        return ff.within(ff.property(geomProperty), ff.literal(geom));
    }
    
    // 距离过滤
    public static Filter createDWithinFilter(String geomProperty, 
            Geometry geom, double distance, String units) {
        return ff.dwithin(ff.property(geomProperty), ff.literal(geom), 
            distance, units);
    }
    
    // 超出距离
    public static Filter createBeyondFilter(String geomProperty,
            Geometry geom, double distance, String units) {
        return ff.beyond(ff.property(geomProperty), ff.literal(geom),
            distance, units);
    }
}
```

## 14.5 统计分析

几何统计的坑几乎全在单位上。`geom.getArea()` 返回的是“坐标单位的平方”，`geom.getLength()` 返回坐标单位长度；投影坐标系下是平方米、米，地理坐标系下是平方度、度。同一个多边形在 EPSG:4326 下 `getArea` 得到 0.0001 量级，重投影到 UTM 后得到几百万，相差几个数量级。示例代码没有任何单位处理，直接拿结果展示，会得到让业务方困惑的数字。

### 14.5.1 几何统计

`calculateAreaStats` 遍历所有要素，累计总面积、最小值、最大值、数量，最后算出均值。这是单遍扫描（one-pass）算法，只需读一次数据，适合大数据集。要注意 `minArea` 用 `Double.MAX_VALUE` 起手，如果集合为空，返回的 min 会是这个巨大的数而不是 0，统计结果需要额外判空；`count == 0` 时均值用三元表达式兜成 0，处理了除零但没有处理 min 的语义。

把 `count` 塞进 `Map<String, Double>` 里，是把整型放进浮点容器，值大了会有精度问题（超过 2^53 之后不精确）。计数用单独的 `long` 返回更合适。这个 Map 设计的好处是接口统一、便于转成 JSON 输出，代价是类型不安全；生产代码里可以换成专门的统计结果类。

`groupBySum` 用 `Map<Object, Double>` 按分组字段求和，`result.merge(groupValue, sumValue, Double::sum)` 是 Java 8 的写法，分组值为 null 时也支持（`HashMap` 允许 null 键）。求和值用 `((Number) attr).doubleValue()` 转换，如果字段是 `Integer`、`Long`、`BigDecimal` 都能处理；如果字段是 String 存了数字，会抛 `ClassCastException`，需要先做解析。

分组统计的准确性依赖分组值的类型一致性。同一个含义的分组键如果一半是字符串 `"110000"`、一半是整数 `110000`，会分成两组，结果看起来“数据少了”。清洗阶段统一键类型，比在统计阶段做类型判断更省事。

```java
public class GeometryStatistics {
    
    // 计算面积统计
    public static Map<String, Double> calculateAreaStats(
            SimpleFeatureCollection features) throws Exception {
        
        double totalArea = 0;
        double minArea = Double.MAX_VALUE;
        double maxArea = 0;
        int count = 0;
        
        try (SimpleFeatureIterator iter = features.features()) {
            while (iter.hasNext()) {
                SimpleFeature feature = iter.next();
                Geometry geom = (Geometry) feature.getDefaultGeometry();
                
                double area = geom.getArea();
                totalArea += area;
                minArea = Math.min(minArea, area);
                maxArea = Math.max(maxArea, area);
                count++;
            }
        }
        
        Map<String, Double> stats = new HashMap<>();
        stats.put("total", totalArea);
        stats.put("min", minArea);
        stats.put("max", maxArea);
        stats.put("mean", count > 0 ? totalArea / count : 0);
        stats.put("count", (double) count);
        
        return stats;
    }
    
    // 按属性分组统计
    public static Map<Object, Double> groupBySum(SimpleFeatureCollection features,
            String groupField, String sumField) throws Exception {
        
        Map<Object, Double> result = new HashMap<>();
        
        try (SimpleFeatureIterator iter = features.features()) {
            while (iter.hasNext()) {
                SimpleFeature feature = iter.next();
                Object groupValue = feature.getAttribute(groupField);
                double sumValue = ((Number) feature.getAttribute(sumField)).doubleValue();
                
                result.merge(groupValue, sumValue, Double::sum);
            }
        }
        
        return result;
    }
}
```

## 14.6 Process API

Process API 把常用的空间处理封装成带参数描述的“处理对象”，统一用 `execute(Map<String,Object> input, ProgressListener)` 调用、返回一个结果 Map。它最早是为了 GIS 服务端（WPS）设计的：参数名、类型、说明都能被自动发现，可以生成 WPS 的能力文档。在普通 Java 程序里用它的好处是复用现成的实现，坏处是参数通过字符串键传递，编译期检查不到。

### 14.6.1 使用内置处理

`BufferProcess`、`PointStackerProcess` 这类具体实现分散在 GeoTools 的多个 Maven 模块里（gt-process、gt-process-feature 等），只引入 gt-main 是找不到它们的。工程里用到哪个 process，就要确认它所在的 artifact 并显式加依赖，否则编译期报“找不到符号”。运行期还可能需要 SPI 注册的工厂类，缺依赖时的报错往往出现在 `CommonFactoryFinder` 里，容易被误解为配置问题。

输入 Map 的键来自 process 类上声明的参数对象：`BufferProcess.INPUT.key` 就是参数 `INPUT` 的键名，用常量而不是手写字符串，能避免键名拼错——这是 Process API 里少数有编译期保障的部分。结果 Map 的键同理，`RESULT.key` 对应输出结果。传入的参数类型必须与声明的类型匹配，传错时会抛 `ProcessException`，错误信息里通常带有期望的类型。

`execute(input, null)` 的第二个参数是 `ProgressListener`，传 null 表示不汇报进度。处理耗时较长的 process 时，可以传一个监听器实现，定期收到进度百分比，用来更新 UI 或写日志。Process API 的取消机制也依赖这个监听器，没有监听器就只能在外部线程中断。

`PointStackerProcess` 的输入键在示例里写成了字符串 `"data"`、`"cellSize"`，与 `BufferProcess` 用常量的写法不一致。具体键名要以该 process 类的定义为准，不同版本可能调整；稳妥的做法仍然是引用类上的静态参数常量。`cellSize` 表示聚合网格的边长（像素或地图单位，取决于实现），值越大聚合越粗，点数越少。

```java
import org.geotools.process.vector.VectorProcess;

public class ProcessExample {
    
    // 使用缓冲区处理
    public static SimpleFeatureCollection bufferProcess(
            SimpleFeatureCollection features, double distance) throws Exception {
        
        BufferProcess process = new BufferProcess();
        
        Map<String, Object> input = new HashMap<>();
        input.put(BufferProcess.INPUT.key, features);
        input.put(BufferProcess.DISTANCE.key, distance);
        
        Map<String, Object> result = process.execute(input, null);
        
        return (SimpleFeatureCollection) result.get(BufferProcess.RESULT.key);
    }
    
    // 点聚合处理
    public static SimpleFeatureCollection pointStacker(
            SimpleFeatureCollection features, int cellSize) throws Exception {
        
        PointStackerProcess process = new PointStackerProcess();
        
        Map<String, Object> input = new HashMap<>();
        input.put("data", features);
        input.put("cellSize", cellSize);
        
        Map<String, Object> result = process.execute(input, null);
        
        return (SimpleFeatureCollection) result.get("result");
    }
}
```

## 14.7 本章小结

本章代码量大，但结构上只有三种：单几何运算（buffer、intersection 这一层的 JTS 调用）、要素集合处理（类型定义 + 索引 + 迭代器）、查询与统计（过滤器、空间索引、分组求和）。写新功能时先判断属于哪一类，再套对应的模板，比从头设计快。

实际项目里最容易出问题的三处：坐标系，所有量算类操作都要先确认单位，地理坐标必须先投影；资源，迭代器用 try-with-resources，数据源用 finally 里 dispose；索引，静态 STRtree 建好要 build，数据变化要重建或换 Quadtree。这三条不属于算法问题，但占了线上问题的一大半。

本章详细介绍了 GeoTools 的空间分析功能：

1. **缓冲区分析**
   - 基本缓冲区
   - 样式控制
   - 单侧缓冲区

2. **叠加分析**
   - 相交、合并、差集
   - 空间裁剪
   - 空间连接

3. **空间查询**
   - 最近邻查询
   - 空间过滤器

4. **统计分析**
   - 几何统计
   - 分组统计

5. **Process API**
   - 内置处理
   - 自定义处理

### 关键要点

- 使用空间索引提高查询效率
- 合理选择空间关系类型
- Process API 提供可重用的分析功能
