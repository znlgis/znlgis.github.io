# 第08章：质量检查与报告

> **产品官网**：[https://shandianweihu.com/](https://shandianweihu.com/)

## 8.1 本章概述

翻译完成之后、译文回写之前，有一道无法绕过的关键工序——**质量检查**。

在工程图纸翻译中，质量检查的意义远不止"确保翻译正确"这么简单。图纸翻译有其特殊的质量维度：占位符完整性直接影响回写后的格式呈现，术语一致性关乎整批图纸的专业可信度，译文长度溢出则可能让标注文字被截断在图纸上完全不可见。这些风险是通用文本翻译中不存在或不被关注的，但对工程图纸交付来说，每一项都可能构成致命缺陷。

同文（Tongwen）内置了一套完整的质量检查（QA，Quality Assurance）系统，覆盖占位符保护、术语验证和长度溢出三项核心检查，并按四级风险等级对发现的问题进行分级管理。配合翻译工作区内的实时风险展示和详情面板中的逐条查阅，以及 JSON/CSV 格式的完整报告导出，您可以在回写之前全面掌控译文质量——不必担心漏掉任何一个潜在的隐患。

本章将从 QA 系统的工作原理讲起，逐步深入到三种验证器的检查逻辑、四级风险等级的解读、翻译工作区中 QA 结果的查看方式、QA 发现的处理方法、报告导出的使用场景，以及批量审查 HTML 报告的功能和最佳实践。

**本章阅读建议**：如果您是首次了解同文的 QA 功能，建议从头到尾按顺序阅读。如果您已经熟悉基本概念，可以直接跳转到"8.4 如何在翻译工作区查看 QA 结果"或后续章节。

## 8.2 QA 概述

### 8.2.1 什么是质量检查

质量检查（QA）是同文翻译工作流中的一个**自动化审查环节**。在翻译人员完成译文输入之后、审校人员确认之前（或在回写 CAD 图纸之前），系统会自动对译文进行多项规则化检查，逐条标记出可能存在的问题，并生成结构化的检查报告。

质量检查并非替代人工审校——它是对人工审校的**增强与前置**。机器擅长发现规则化的问题（如"格式码有没有丢"、"术语表里的标准译法有没有用对"），而人擅长判断语义的专业性和语境适配性。两者结合，才能在保证效率的同时达到工程级的质量水准。

### 8.2.2 为什么工程图纸翻译需要专门的质量检查

通用翻译场景的质量检查主要关注拼写错误、语法问题、漏译等。工程图纸翻译的质量检查还需要额外关注以下几个维度：

| 质量维度 | 说明 | 检查方式 |
|----------|------|----------|
| **格式码完整性** | MText 中包含大量内嵌格式码（字体切换、颜色、字高、下划线、堆叠文字等）。翻译过程中这些格式码被替换为占位符，回写时必须完整还原。 | 占位符验证器 |
| **术语一致性** | "混凝土强度等级"在术语库中定义的标准译法是"Concrete Strength Grade"，如果翻译人员将其译为"Strength Grade of Concrete"，虽然语义通顺，但违反了术语约束。 | 术语验证器 |
| **译文长度溢出** | 中文"钢筋混凝土框架结构"翻译为英文"Reinforced Concrete Frame Structure"后，文字长度显著增加。在 CAD 图纸的文本框内，溢出可能导致文字被截断或溢出到其他图形上。 | 长度溢出验证器 |

这三项检查分别对应工程图纸翻译中最高发的三类问题：**格式丢失、术语混乱、空间溢出**。如果不在回写前发现并修复，任何一项都可能导致翻译成果无法直接使用。

### 8.2.3 QA 在翻译流程中的位置

在同文的完整翻译工作流中，QA 处于翻译完成和回写交付之间的审查节点：

```
图纸提取 → 机翻/记忆填充 → 人工翻译 → QA 检查 → 修复 → 审批 → 回写图纸
                                  ↑__________↓
                                  （反复验证）
```

更详细的工作流如下：

1. **图纸提取**：将 CAD 图纸中的文字提取到翻译会话中。
2. **自动填充**：系统根据翻译记忆（TM）和机器翻译引擎自动填充初始译文。
3. **人工翻译与编辑**：翻译人员在翻译工作区中对自动填充的译文进行逐条确认和人工修改。
4. **QA 检查**：对翻译结果执行自动化的质量检查，生成风险报告。
5. **QA 修复**：根据 QA 报告逐条处理发现的问题——修复阻断级和高风险问题，审核中低风险问题。
6. **审批确认**：审校负责人对 QA 修复后的译文进行最终确认。
7. **回写图纸**：将通过审批的译文回写到原始 DWG 文件。

QA 环节是一道**安全阀**——在译文离开翻译环境、进入 CAD 图纸之前，做最后一次系统化的质量把关。

## 8.3 三种验证器详解

同文的 QA 系统内置三种验证器，分别针对格式完整性、术语一致性和长度溢出三个维度进行自动化检查。每种验证器有独立的检查逻辑和发现问题后的标记方式。下面逐一详解。

### 8.3.1 占位符验证（PlaceholderValidator）

#### 检查原理

占位符验证器负责检查翻译后的文本中，占位符是否完整保留且顺序正确。

**背景**：在 CAD 图纸中，MText（多行文字）实体内部含有大量格式码——例如 `\fArial|b1|i0|c0|p34;` 表示字体切换为 Arial、加粗、非斜体、颜色索引 0、字高 34。如果将这些格式码直接展示给翻译人员，不仅可读性极差，还极易在编辑过程中被误修改或误删除。因此，同文在提取 MText 时，会将这些格式码替换为形如 `⟨F1⟩`、`⟨F2⟩` 的占位符，翻译工作区中显示的是纯净的文本内容。

当翻译完成后、回写之前，占位符验证器会执行以下检查：

1. **统计原文占位符**：解析原文文本，识别出所有占位符标记（如 `⟨F1⟩`、`⟨F2⟩` 等），记录每个占位符的类型和数量。
2. **统计译文占位符**：解析译文文本，同样识别出所有占位符标记。
3. **逐一比对**：将原文和译文的占位符列表进行比对，检查是否存在缺失、多余或类型不匹配的情况。

**检查的占位符类型包括但不限于**：

| 占位符类型 | 标记格式 | 代表含义 | 回写时的还原行为 |
|-----------|----------|----------|-----------------|
| 格式控制符 | `⟨F1⟩`、`⟨F2⟩`... | 字体、颜色、字高、加粗/斜体等格式切换指令 | 还原为原始格式控制码 |
| 堆叠文字符 | `⟨S1⟩`、`⟨S2⟩`... | 分数、公差等堆叠文字的格式包围码 | 还原为堆叠格式控制序列 |
| 特殊转义符 | `⟨E1⟩`... | 反斜杠、大括号等需要转义的特殊字符 | 还原为对应的转义序列 |

#### 检查结果

占位符验证器会产生以下三种结论之一：

| 检查结果 | 含义 | 风险等级 |
|----------|------|----------|
| **完全一致** | 译文中包含与原文完全相同的一组占位符，类型和数量均匹配。 | 无风险 |
| **占位符缺失** | 译文中缺少原文中存在的某个或某些占位符。 | 🚫 阻断 |
| **占位符多余** | 译文中出现了原文中不存在的占位符（通常是因为翻译人员手动输入了类似占位符格式的文本）。 | 🚫 阻断 |
| **占位符不匹配** | 原文和译文的占位符数量一致，但类型/顺序不一致。 | 🚫 阻断 |

#### 典型发现的示例

**示例 1：占位符缺失**

```
原文：混凝土强度等级⟨F1⟩为 C30
译文：Concrete Strength Grade is C30
QA 发现：[阻断] 译文缺少占位符 ⟨F1⟩
说明：占位符 ⟨F1⟩ 在译文中不存在。回写后，C30 将丢失原有的格式（如加粗或特殊字体）。
```

**示例 2：占位符完整保留（正确）**

```
原文：钢筋⟨F1⟩保护层厚度⟨F2⟩≥20mm
译文：Rebar⟨F1⟩ Cover Thickness⟨F2⟩ ≥20mm
QA 发现：无
说明：所有占位符在译文中完整保留，回写后格式不变。
```

**示例 3：占位符多余（误输入）**

```
原文：设计强度为 C30
译文：Design Strength is⟨F1⟩ C30
QA 发现：[阻断] 译文中出现了原文中没有的占位符 ⟨F1⟩
说明：翻译人员可能在编辑时误输入了类似占位符格式的标记，这在回写时会导致格式错乱。
```

#### 如何解读发现结果

当占位符验证器报告问题时，您需要：

1. **打开详情面板**：在翻译工作区中选中该翻译单元，查看右侧详情面板的"QA 发现"区域，确认具体是哪个占位符出了问题。
2. **核对原文和译文**：将原文的占位符位置与译文的相应位置进行对比。占位符不需要放在完全相同的位置（因为中英文语序不同），但必须在译文中存在且类型匹配。
3. **差异修复**：如果占位符缺失，在译文中相应位置插入同类型的占位符；如果占位符多余，删除译文中误输入的标记。

> **重要提示**：占位符缺失或多余属于🚫阻断级风险。在修复之前，同文会阻止该翻译单元的回写操作。这意味着只要 QA 面板中显示占位符阻断问题，对应的文字就不会被写入 CAD 图纸——这是最后一道安全保障。

### 8.3.2 术语验证（TerminologyValidator）

#### 检查原理

术语验证器负责检查翻译结果是否遵循了术语库中定义的标准译法。

同文的翻译知识系统包含四层结构，其中**术语表（Glossary）**是术语验证器的核心参照数据源。术语表定义了特定原文词汇在不同专业语境下的标准翻译。例如：

| 原文 | 专业 | 标准译法 | 是否强制 |
|------|------|----------|----------|
| 混凝土 | 建筑 | Concrete | 是 |
| 混凝土 | 结构 | Concrete | 是 |
| 标高 | 建筑 | Elevation | 是 |
| 标高 | 测量 | Level | 是 |
| 节点 | 结构 | Joint | 否（建议译法） |
| 节点 | 电气 | Node | 是 |

术语验证器的工作流程：

1. **加载术语表**：根据当前任务所选的**专业方向**（建筑、结构、暖通、给排水、电气等）加载对应的术语表内容。
2. **扫描原文文本**：在当前翻译单元的原文中，逐条搜索术语表中定义的原文词汇。如果原文包含术语表中收录的词汇，该词汇即被标记为"受术语约束"。
3. **提取实际译文**：对已翻译完成的译文，提取对应的译法。
4. **比对验证**：将实际译法与术语表中定义的标准译法进行比对。比对过程不是简单的字符串相等判断——验证器会考虑词形变化（如单复数、时态）和常见的同义词替换。
5. **生成发现**：根据比对结果生成术语相关的问题报告。

术语验证器会检测两类问题：

| 问题类型 | 含义 | 风险等级 |
|----------|------|----------|
| **术语冲突** | 原文中存在术语表收录的词汇，但译文未采用标准译法。例如术语表要求"标高"译为"Elevation"，但译文使用了"Height"。 | 🔴 高 |
| **术语缺失** | 术语表中标记为"必须翻译"（强制）的术语，在译文中完全没有体现（可能被漏译或误删）。 | 🔴 高 |

#### 检查范围内的"同义词宽容"

术语验证器的比对并非机械的字符串完全匹配。对于以下情况，验证器会进行智能宽容：

- **词形变化**：英文中常见的单复数（如"wall"与"walls"）、时态变化，验证器会识别为术语正确使用。
- **大小写差异**：术语比对不区分大小写——"Concrete"与"concrete"视为相同。
- **前后空格**：译文两端多余的空格不影响术语比对结果。

但以下情况会被判定为术语冲突：

- **使用了不同的词根**：术语表要求"Reinforcement"，译文使用了"Rebar"——虽然在某些语境下两者可互换，但在同文的术语管理体系中这是不通过校验的（除非术语表中将两者都收录为等价译法）。
- **词序颠倒**：术语表要求"Concrete Strength Grade"，译文使用了"Strength Grade of Concrete"——词序改变导致字面不匹配。
- **添加了多余修饰词**：术语表要求"Column"，译文使用了"Concrete Column"。

#### 典型发现的示例

**示例 1：术语冲突**

```
原文：混凝土强度等级为 C30
术语表定义：混凝土 → Concrete（建筑专业，强制）
实际译文：Cement strength grade is C30
QA 发现：[高] 术语冲突 — "混凝土"在术语表中标准译法为"Concrete"，当前译文使用了"Cement"
建议：将译文中的"Cement"修改为"Concrete"。
```

**示例 2：术语缺失**

```
原文：抗震设防烈度为 7 度
术语表定义：抗震设防烈度 → Seismic Fortification Intensity（结构专业，强制）
实际译文：is 7 degrees
QA 发现：[高] 术语缺失 — "抗震设防烈度"为强制翻译术语，但译文中未找到对应译法
建议：将译文补充为"Seismic Fortification Intensity is 7 degrees"。
```

**示例 3：无术语冲突（建议译法未被遵循——不触发警告）**

```
原文：节点详图见 2-2 剖面
术语表定义：节点 → Node（电气专业，非强制/建议译法）
实际译文：See section 2-2 for joint details
QA 发现：无 — "节点"在术语表中仅为建议译法，翻译人员可自由选择其他译法
说明：如果"节点"被标记为强制术语，则使用"Joint"而非"Node"会被标记为冲突。
```

#### 如何解读发现结果

当术语验证器报告问题时，您需要：

1. **确认专业方向**：首先检查当前任务的专业方向是否正确——术语表是按专业组织的，如果任务被错误标记为"暖通"而实际图纸是"建筑"专业，术语比对将以错误的参照系进行。
2. **判断是否为误报**：某些情况下，原文中的词汇恰好与术语表收录的原文相同，但在当前语境的句子里该词汇并不是作为独立术语使用的。例如"框架"在结构中定义为"Frame"，但在"在框架协议下"这句话中，"框架"应该译为"Framework"。这种情况需要人工判断。
3. **决定处理方式**：
   - 如果确实是翻译疏漏，修改译文以匹配术语表。
   - 如果术语表的定义在当前语境不适用，可以忽略该 QA 发现（低级别发现问题标记为"已忽略"）。
   - 如果术语表的定义本身有问题，可以在术语库中修正术语表，然后重新运行 QA。

> **重要提示**：术语冲突属于🔴高级风险。虽然不会阻止回写，但强烈建议在回写前解决——因为同一批图纸中术语不统一是最影响专业形象的问题之一。

### 8.3.3 长度溢出验证（LengthOverflowValidator）

#### 检查原理

长度溢出验证器负责检查译文长度是否可能超出 CAD 图纸中文本框的容纳范围。

在 CAD 图纸中，每个文字实体（DBText、MText、AttributeReference）都有其几何占位——**包围盒（Bounding Box）**。包围盒是文字在图纸上实际占据的矩形区域。对于已设定固定宽度的 MText，其包围盒的宽度是确定的；对于 DBText，其包围盒由文字的几何属性（字高、宽度因子、对齐方式等）和文字内容共同决定。

长度溢出验证器的核心逻辑：

1. **获取原文包围盒**：从文字提取阶段保存的几何信息中，读取原文文本的包围盒尺寸（宽度 W_original 和高度 H_original）。
2. **估算译文包围盒**：基于目标语言文字的排版特性（字符平均宽度、字高、宽度因子等），结合当前译文的文本长度，估算译文在 CAD 图纸中的预计包围盒尺寸（W_translated 和 H_translated）。
3. **计算溢出程度**：将译文预计包围盒与原文包围盒进行比较，计算溢出比例。
4. **生成发现**：根据溢出程度，标记对应的风险等级。

#### 溢出程度的计算

长度溢出验证器不是简单按字符数来判断，而是基于实际的几何估算：

| 计算要素 | 说明 |
|----------|------|
| **原文包围盒宽度** | 从提取阶段保存的几何数据中直接读取。 |
| **译文预计宽度** | 基于译文字符串长度 × 目标语言字符平均宽度 × 字高 × 宽度因子，考虑空格、标点、换行等因素后的综合估算。 |
| **对齐方式** | 考虑文字的对齐点——居中对齐的文字向两侧溢出，左对齐的文字向右侧溢出。对齐方式影响溢出的视觉效果和可用容差。 |
| **宽度因子（Width Factor）** | 某些 AutoCAD 文字样式设置了特殊的宽度因子（如 0.8 表示字符宽度为正常宽度的 80%）。这会影响实际占用的空间。 |

#### 溢出程度的判定与风险赋级

验证器根据溢出程度将问题分为三个等级：

| 溢出程度 | 风险等级 | 说明 |
|----------|----------|------|
| 超出包围盒宽度 ≥ 20% | 🔴 高 | 译文大概率会被截断或在图纸上显示不全。必须处理。 |
| 超出包围盒宽度 10%~20% | 🟡 中 | 译文可能在边界条件下溢出（如字体替换导致实际渲染宽度变化）。建议处理。 |
| 超出包围盒宽度 < 10% | 🔵 低 | 译文长度接近边界，但不一定会实际溢出。建议优化——例如使用更简洁的表达。 |
| 完全在包围盒内 | 无风险 | 译文预计不会超出原文包围盒。 |

#### 典型发现的示例

**示例 1：严重溢出**

```
原文：钢筋保护层厚度（共 25 字）
译文：Thickness of Concrete Cover for Reinforcement（共 48 字符）
原文包围盒宽度：120mm
译文预计宽度：189mm（超出约 57%）
QA 发现：[高] 长度溢出 — 译文预计宽度超出原文包围盒 57%
建议：缩减译文或调整 CAD 文字框宽度。
```

**示例 2：轻微溢出**

```
原文：详见结构说明（共 6 字）
译文：Refer to Structural Notes for Details（共 39 字符）
原文包围盒宽度：45mm
译文预计宽度：52mm（超出约 16%）
QA 发现：[中] 长度溢出 — 译文预计宽度超出原文包围盒 16%
建议：考虑使用更简洁的译法，或在 CAD 中调整文本框。
```

**示例 3：中译英长度不增反减（无风险）**

```
原文：钢筋混凝土框架-剪力墙结构体系（共 16 字）
译文：RC Frame-Shear Wall Structure（共 30 字符）
原文包围盒宽度：180mm
译文预计宽度：120mm
QA 发现：无
说明：虽然英文单词数更多，但中文每个字符的宽度通常远大于英文字母的平均宽度，因此实际占用空间更小。
```

#### 如何解读发现结果

长度溢出验证的结果需要结合具体的图纸场景来判断：

1. **高溢出**：几乎可以肯定回写后文字会被截断或在图纸上超过图框边界。您有两个处理方向：
   - **修改译文**：使用缩写（如"钢筋混凝土"缩为"RC"）、压缩表达（Engineering → Eng.）。
   - **修改图纸**：在 CAD 中扩大文本框宽度，或调整文字样式的宽度因子。
2. **中溢出**：在大多数 CAD 版本和字体环境下可能会溢出。建议处理，但如果时间紧张且溢出不严重，可以在回写后通过 CAD 中的快速检查来验证。
3. **低溢出**：通常在 CAD 的渲染容差范围内。您可以标记为"已确认"而不做修改。

> **重要提示**：长度溢出验证的结果是**估算值**，不是精确值。AutoCAD 中的文字实际渲染宽度受多种因素影响（字体引擎、TrueType vs SHX 字体、DPI 缩放等），因此估计可能存在一定的误差。对于标记为🟡中和🔵低的溢出，建议在回写后打开图纸进行目视抽查。

## 8.4 四级风险等级解读

同文的 QA 系统将发现的问题分为四个风险等级。每个等级有明确的含义、对回写流程的影响和推荐的处理策略。

### 8.4.1 等级总览

| 等级 | 标识 | 含义 | 对回写的影响 | 推荐处理 |
|------|------|------|-------------|----------|
| 🚫 阻断（Blocker） | 红色 | 该翻译单元存在严重问题，回写后将破坏图纸格式或导致数据丢失。 | **禁止回写**。存在阻断级发现的翻译单元不会被写入 CAD 图纸。 | 必须修复。修复后重新运行 QA 确认问题已消除。 |
| 🔴 高（High） | 橙色 | 该翻译单元存在明显的质量问题，回写后可能影响图纸的可用性或专业形象。 | 不会阻止回写，但系统会弹窗提示并要求确认。 | **建议在回写前修复**。如果紧急交付，可以在了解风险后确认继续。 |
| 🟡 中（Medium） | 橙色（略浅） | 该翻译单元存在潜在问题，在特定条件下可能影响质量。 | 不会阻止回写，仅在 QA 报告中记录。 | 建议审核确认。如果经确认无实际影响，可标记为"已确认"。 |
| 🔵 低（Low） | 蓝色 | 该翻译单元存在可以优化的空间，当前状态无功能性问题。 | 完全不阻断，仅为优化建议。 | 可选处理。根据时间情况决定是否优化。 |

### 8.4.2 阻断级（Blocker）🚫

**触发条件**：占位符缺失、占位符多余或占位符类型不匹配。

**为什么是阻断**：占位符是 MText 格式码在翻译工作区中的代理。如果占位符在翻译过程中丢失，回写时系统无法将格式码正确还原——这意味着译文的字体、颜色、字高、加粗/斜体等格式将全部出错，甚至导致整个 MText 实体的格式序列崩溃。这不是"译文好不好看"的问题，而是"图纸还能不能用"的问题。

**处理方式**：

1. 在翻译工作区的详情面板中查看具体的占位符问题。
2. 参照原文的占位符分布，在译文中插入正确的占位符类型。
3. 保存译文后重新运行 QA，确认该阻断问题已消除。
4. **在阻断问题消除之前，该翻译单元无法回写**。

**示例场景**：

```
原文：梁截面尺寸⟨F1⟩ 300×600⟨F2⟩
译文：Beam Section Size 300×600
阻断原因：⟨F1⟩ 和 ⟨F2⟩ 在译文中缺失
修复方式：Beam Section Size⟨F1⟩ 300×600⟨F2⟩
```

### 8.4.3 高级（High）🔴

**触发条件**：
- 术语冲突：翻译结果违反了术语表中的强制译法定义。
- 术语缺失：强制术语在译文中完全未出现。
- 长度严重溢出：译文预计宽度超出原文包围盒 20% 以上。

**为什么是高级**：术语不一致会严重损害整批图纸的专业可信度——甲方发现同一张图纸中"标高"有时是"Elevation"有时是"Height"，会对翻译质量产生根本性质疑。长度严重溢出则意味着译文在图纸上大概率不可见或被截断，等同于漏译。

**处理方式**：

1. **术语问题**：对照术语库中的标准译法，修正译文。如果认为术语表的定义不适用于当前语境，可以忽略该发现并在备注中说明理由。
2. **长度溢出**：优先尝试缩简译文（使用行业公认的缩写、压缩冗余表达）；如果无法缩简，需要在 CAD 中调整文本框。
3. 处理完成后重新运行 QA 确认。

### 8.4.4 中级（Medium）🟡

**触发条件**：译文预计宽度超出原文包围盒 10%~20%。

**为什么是中级**：溢出不严重，在大多数情况下实际渲染宽度可能仍在容差范围内。但存在边界风险——如果目标图纸使用的字体与估算基准不同，或如果 CAD 版本的渲染引擎存在差异，实际溢出可能比估算更严重。

**处理方式**：

1. 查看译文内容，判断是否有缩简空间。
2. 如果译文已经是最简洁的表达，可以标记为"已确认"而不修改。
3. 建议在回写后对溢出条目做一次快速的目视抽查。

### 8.4.5 低级（Low）🔵

**触发条件**：译文预计宽度超出原文包围盒 10% 以下。

**为什么是低级**：微小溢出几乎不会在 CAD 渲染中产生实际可见的问题。更多是提醒翻译人员"译文长度已经满了，注意不要再增加内容"。

**处理方式**：

1. 如果时间允许，可以优化表达使其更紧凑。
2. 如果时间紧张，可以直接标记为"已确认"，不影响回写。

## 8.5 如何在翻译工作区查看 QA 结果

同文将 QA 结果直接集成到翻译工作区界面中，您无需切换到单独的 QA 页面即可实时了解每个翻译单元的质量状况。

### 8.5.1 数据表格中的"风险"列

在翻译工作区的数据表格（即翻译单元列表）中，有一列名为**"风险"**。这一列展示了每个翻译单元的当前最高风险等级。

**风险列的显示规则**：

| 显示内容 | 含义 |
|----------|------|
| 🚫 阻断（红色背景/图标） | 该单元至少有一个阻断级 QA 发现。 |
| 🔴 高（橙色背景/图标） | 该单元没有阻断级发现，但至少有一个高级发现。 |
| 🟡 中（橙色背景/图标） | 该单元没有阻断和高级发现，但至少有一个中级发现。 |
| 🔵 低（蓝色背景/图标） | 该单元只有低级发现。 |
| 空白 / 无标记 | 该单元没有任何 QA 发现（或尚未执行 QA）。 |

**颜色的含义**：

- **红色**：需立即处理，否则无法回写。
- **橙色**：建议优先处理，影响翻译质量。
- **蓝色**：仅优化建议，不影响基本功能。

风险列让您可以**快速扫描**整个翻译工作区。例如，将表格按"风险"列排序，所有阻断和高风险的条目一目了然，您可以优先处理这些问题。

### 8.5.2 详情面板中的"QA 发现"区域

在翻译工作区中，当您单击某个翻译单元（即选中表格中的某一行），右侧的**详情面板（Detail Panel）**会显示该单元的完整信息。详情面板中有一个专门的**"QA 发现"区域**，列出了该翻译单元的全部风险发现。

**QA 发现区域的内容**：

每条 QA 发现包含以下信息：

| 信息项 | 说明 |
|--------|------|
| **风险等级** | 🚫阻断 / 🔴高 / 🟡中 / 🔵低，以图标和颜色标识。 |
| **验证器类型** | 占位符验证 / 术语验证 / 长度溢出验证。 |
| **问题描述** | 自然语言描述的具体问题——例如"译文缺少占位符 ⟨F1⟩"。 |
| **原文/译文对照** | 显示相关的原文片段和译文片段，方便快速定位问题位置。 |
| **建议操作** | 如果验证器能自动推断修复方式，此处会显示建议（如"请将译文中的'Cement'替换为'Concrete'"）。 |

**使用方式**：

1. 在翻译工作区的数据表格中，点击任意一行（翻译单元）。
2. 查看右侧详情面板中的"QA 发现"区域。
3. 如果该单元有多个 QA 发现，在面板中会逐条列出。您可以从上到下逐条阅读和处理。
4. 点击某条 QA 发现，系统会自动将编辑焦点定位到译文编辑框中对应的位置（如果问题涉及特定文本区域）。

### 8.5.3 QA 发现与编辑联动

QA 发现不是静态的报告——它们与翻译编辑功能紧密联动：

- **点击 QA 发现**：如果发现涉及译文中特定的文本片段（如术语冲突中的词汇位置），点击该发现在编辑框中高亮对应的文本区域。
- **修复后自动刷新**：在您修改译文后，如果问题被修复，该条 QA 发现会自动从列表中消失（或状态变为"已修复"）。
- **重新运行 QA**：修改译文后，您可以手动触发该单元的 QA 重新检查（通常在详情面板中有"重新检查"按钮），确认所有问题均已解决。

## 8.6 如何处理 QA 发现

QA 发现的处理不是简单的"修复所有问题"——不同等级、不同类型的问题有不同的处理优先级和策略。

### 8.6.1 阻断级问题修复指南

阻断级问题全部来自占位符验证器。处理流程如下：

**步骤 1：定位问题**

在详情面板的"QA 发现"区域中，确认具体是哪个占位符出了问题。

**步骤 2：参照原文修复**

将目光移到原文显示区域，找到对应的占位符位置。在译文中相应的语义位置插入同类型的占位符。

**注意**：占位符的位置不一定与原文一一对应（因为中英语序不同），但必须在译文中存在。例如：

```
原文：混凝土⟨F1⟩强度等级⟨F2⟩为 C30
译文：Concrete⟨F1⟩ Strength Grade⟨F2⟩ is C30
```
`⟨F1⟩` 和 `⟨F2⟩` 的位置在中英文中不同，但两者都在译文中完整存在。

**步骤 3：不要手动输入占位符**

占位符是在提取阶段由系统自动生成的，您不能（也不需要）手动输入类似 `⟨F1⟩` 的文本。如果您在译文中误删了占位符，可以：

- 使用编辑框中的"恢复占位符"功能（如果存在）。
- 从原文中复制占位符，粘贴到译文中的合适位置。
- 如果无法恢复，联系系统管理员检查会话文件。

**步骤 4：保存并重新运行 QA**

修复译文后，保存翻译。然后重新运行该单元的 QA 检查，确认阻断问题已消除。

**步骤 5：逐条处理，不要跳过**

一个翻译单元可能有多个阻断级发现。您需要逐一处理，直到该单元的"风险"列不再显示红色。

### 8.6.2 高级问题审核建议

高级问题来自术语验证器和长度溢出验证器。处理策略如下：

**术语冲突和术语缺失**：

1. **首先确认术语表是否正确**：打开术语库，查看该术语的收录情况——是否在当前专业下、是否为强制译法、标准译法是否确实适用于当前语境。
2. **如果术语表正确**：修改译文以匹配术语表的标准译法。
3. **如果术语表不适用当前语境**：在 QA 发现上标记"已确认（例外）"，并在备注中简要说明理由（如"本句中的'框架'指合同框架，非结构框架"）。
4. **如果术语表本身需要更新**：在术语库中更新术语定义，然后重新运行 QA。

**长度严重溢出**：

1. **检查译文是否可以缩简**：
   - 使用行业标准缩写：如"钢筋混凝土"→"RC"（Reinforced Concrete）。
   - 压缩冗余表达：如"Please refer to the structural drawing for detailed information"→"See structural drawing for details"。
   - 考虑使用更短的同义词。
2. **如果无法缩简**：
   - 在 CAD 图纸中手动扩大文本框宽度。
   - 或在 CAD 中调整文字样式的宽度因子（将 Width Factor 从 1.0 调整为 0.8）。
3. **记录处理方式**：在 QA 发现的备注中说明您采取的措施。

### 8.6.3 低级别问题处理策略

中级和低级问题主要来自长度溢出验证。这些问题的处理优先级低于阻断和高级问题。

**处理策略**：

1. **先处理阻断和高级**：在所有红色和橙色问题处理完毕之前，不要花时间在蓝色问题上。
2. **中级问题逐条审核**：对于🟡中等问题，快速浏览——如果译文确实可以缩简且不损失信息量，顺手优化；如果译文已经很紧凑，标记为"已确认"。
3. **低级问题批量处理**：对于🔵低级问题，可以在扫尾阶段统一标记为"已确认"。
4. **回写后抽查**：对于标记为"已确认"的溢出问题，建议在回写后用 AutoCAD 打开图纸，抽查几个典型的溢出条目，确认实际渲染效果在可接受范围内。

### 8.6.4 QA 发现的处理状态

每条 QA 发现都有一个处理状态，帮助您追踪处理进度：

| 状态 | 含义 |
|------|------|
| **待处理** | QA 发现未被处理，仍处于活跃状态。 |
| **已修复** | 翻译人员已修改译文，问题解决。重新运行 QA 后状态会自动更新。 |
| **已确认** | 翻译人员审核后认为该问题不影响质量或不适用于当前语境，手动确认。 |
| **已忽略** | 翻译人员明确将该问题忽略（通常用于建议性术语而非强制术语）。 |

## 8.7 QA 报告导出

同文支持两种 QA 报告导出格式：

```json
    "mediumCount": 28,
    "lowCount": 41
  }
}
```

**JSON 报告中的关键字段**：

| 字段 | 说明 |
|------|------|
| `report.generatedAt` | 报告生成时间（ISO 8601 格式）。 |
| `report.projectName` | 项目名称。 |
| `report.taskName` | 任务名称。 |
| `report.totalUnits` | 翻译单元总数。 |
| `report.totalFindings` | QA 发现总数。 |
| `findings[].unitId` | 翻译单元唯一标识符，可用于精确定位。 |
| `findings[].riskLevel` | 风险等级：`Blocker`（阻断）、`High`（高）、`Medium`（中）、`Low`（低）。 |
| `findings[].validator` | 触发该发现的验证器类型。 |
| `findings[].suggestion` | 系统建议的修复方案（部分发现不包含此字段）。 |
| `findings[].glossaryEntry` | 相关的术语表条目（仅术语验证发现包含）。 |
| `summary` | 按风险等级的计数汇总。 |

### 8.7.3 CSV 格式报告详解

CSV 格式的 QA 报告是一种轻量级的表格格式，可以在 Excel、WPS 表格、Google Sheets 等工具中直接打开。

**CSV 报告的列结构**：

| 列名 | 内容示例 | 说明 |
|------|----------|------|
| 单元编号 | U-0472 | 翻译单元唯一标识。 |
| 风险等级 | 阻断 | 🚫阻断 / 🔴高 / 🟡中 / 🔵低。 |
| 验证类型 | 占位符验证 | 占位符验证 / 术语验证 / 长度溢出验证。 |
| 问题描述 | 译文缺少占位符 ⟨F1⟩ | 自然语言描述的问题。 |
| 原文 | 混凝土强度等级⟨F1⟩为 C30 | 原文片段。 |
| 译文 | Concrete Strength Grade is C30 | 译文片段。 |
| 图层 | S-STRU-TEXT | 文字所在的 CAD 图层。 |
| 处理状态 | 待处理 | 待处理 / 已修复 / 已确认 / 已忽略。 |

**JSON vs CSV 的使用场景建议**：

| 场景 | 推荐格式 | 原因 |
|------|----------|------|
| 团队内部质量审校 | JSON | 结构化数据，可与同文系统对接、可被自动化工具解析。 |
| 提交给甲方/监理的质量报告 | CSV | 可读性好，无需特殊工具即可在 Excel 中打开，适合非技术人员阅读。 |
| 历史归档 | JSON | 数据完整，未来可重新解析和分析。 |
| 快速排查问题 | CSV | 可以在 Excel 中快速筛选和排序，按风险等级或图层归类。 |
| 与外部系统对接 | JSON | 标准化数据结构，适合通过 API 或脚本导入到其他质量管理系统。 |

### 8.7.4 导出操作步骤

**在 Studio 中导出 QA 报告**：

1. 打开对应的翻译任务，进入翻译工作区。
2. 在翻译工作区的工具栏中，找到 **"QA 报告"**或**"导出"**按钮。
3. 在弹出的菜单中选择导出格式：**"导出 JSON 报告"**或**"导出 CSV 报告"**。
4. 系统弹出文件保存对话框，选择保存位置和文件名，点击"保存"。
5. 等待导出完成的提示。JSON 报告体积可能较大（包含完整的原文、译文和 QA 发现详情），导出大项目时可能需要几秒钟。

**何时导出 QA 报告**：

- **在 QA 检查完成后**：生成初始报告，了解当前项目的整体质量状况。
- **在修复完成后**：生成最终报告，作为翻译质量的交付凭证归档。
- **在审批之前**：提交给审校负责人作为审批参考。
- **在项目交付时**：随同翻译后的图纸一起交付给甲方，作为质量保证的书面证明。

## 8.8 批量审查 HTML 报告（Review CLI）

对于大型翻译项目（数十张甚至上百张图纸），逐条在翻译工作区中处理 QA 发现效率有限。同文提供了 **Review CLI**（审查命令行工具），可以生成一个独立的 **HTML 审查报告**，将所有翻译单元的原文、译文和 QA 发现汇总在一个可交互的网页中，支持批量浏览、筛选和注释。

### 8.8.1 什么是 Review CLI

Review CLI 是同文的命令行工具集中的一个组件，专门用于生成翻译审查用的 HTML 报告。它与 Studio 中的交互式 QA 不是替代关系，而是互补关系：

- Studio 中的 QA 面板：适合逐条精细编辑和修复。
- Review CLI 生成的 HTML 报告：适合批量审查、团队协作审查、离线分发审校。

### 8.8.2 HTML 审查报告的功能

Review CLI 生成的 HTML 审查报告是一个独立的、无需任何服务器即可在浏览器中打开的网页文件。它包含以下功能：

**核心视图**：

| 视图区域 | 说明 |
|----------|------|
| **翻译单元列表** | 以表格形式列出所有翻译单元的编号、原文、译文、QA 风险等级、状态。 |
| **筛选面板** | 可按风险等级（阻断/高/中/低/无风险）、处理状态、图层、实体类型等条件筛选显示的翻译单元。 |
| **详情弹窗** | 点击某个翻译单元后，展开显示完整的原文、译文、QA 发现详情和建议。 |
| **注释与标记** | 审查人员可以在报告中为每条翻译单元添加注释和标记状态（如"已审核"、"需修改"、"已确认"）。 |
| **统计概览** | 报告顶部显示总览统计——翻译单元总数、各风险等级的发现数量、已完成审核的比例等。 |

**筛选和排序**：

HTML 报告中的翻译单元列表支持多条件组合筛选。以下是一些典型的筛选场景：

- "只显示风险等级为阻断的条目"——快速定位必须立即修复的问题。
- "只显示术语验证发现且风险等级为高的条目"——集中审核术语一致性问题。
- "按图层筛选"——例如只看"S-STRU-TEXT"图层的翻译，审核结构专业的文本。
- "按状态筛选未处理的条目"——确保没有遗漏。

**交互式注释**：

审查人员可以直接在 HTML 报告中为每个翻译单元添加注释。例如：

- 在某条术语冲突的发现旁注释："当前语境为合同条款，'框架'译为'Framework'是正确的，忽略术语表冲突"。
- 在某条长度溢出的发现旁注释："已联系 CAD 设计人员扩大文本框，待确认"。

这些注释可以保存到 HTML 文件中（通常通过浏览器本地存储），或导出为独立文件发给翻译人员参考。

### 8.8.3 使用场景

**场景 1：项目经理批量审查**

项目经理收到翻译团队提交的译文后，不打开 Studio，而是运行 Review CLI 生成 HTML 报告。在浏览器中按风险等级排序，优先查看所有阻断和高级条目，快速判断哪些需要退回翻译人员修改。

**场景 2：第三方审校**

翻译任务外包给外部翻译公司，内部审校人员不需要安装同文 Studio。翻译公司交付会话文件后，审校人员运行 Review CLI 生成 HTML 报告，直接在浏览器中完成审校。审校结果（注释和标记）可以导回给翻译公司作为修改依据。

**场景 3：甲方质量验收**

项目交付时，甲方可能需要审查翻译质量。将 Review CLI 生成的 HTML 报告作为交付物的一部分，甲方可以直观地查看翻译质量状况——每一条原文、译文、QA 发现一目了然，不需要任何专业软件。

### 8.8.4 Review CLI 的基本用法

Review CLI 通过命令行运行，最简单的用法如下：

```bash
tongwen review --session "项目路径/结构施工图.tw" --output "审查报告.html"
```

常用参数说明：

| 参数 | 说明 | 示例 |
|------|------|------|
| `--session` | 指定翻译会话文件（`.tw` 文件）的路径。 | `--session "C:\Projects\深圳湾\task_001.tw"` |
| `--output` | 指定输出的 HTML 文件路径。 | `--output "D:\报表\审查报告_20260722.html"` |
| `--language` | 指定报告界面语言。默认为系统语言。 | `--language zh-CN` 或 `--language en` |
| `--filter` | 预设筛选条件。 | `--filter "risk=Blocker"` 表示只包含阻断级发现。 |

> **注意**：Review CLI 的具体命令行参数和用法可能因版本而异。请以当前版本内置的帮助信息为准——在命令行中运行 `tongwen review --help` 可查看完整的参数说明。

### 8.8.5 HTML 报告与 Studio QA 的协同

Review CLI 生成的 HTML 报告和 Studio 中的实时 QA 面板不是两个独立的系统——它们共享相同的 QA 引擎和数据。两者的定位是：

| 维度 | Studio QA 面板 | Review CLI HTML 报告 |
|------|---------------|---------------------|
| 使用场景 | 翻译过程中的实时质量监控 | 翻译完成后的批量审查和交付 |
| 交互方式 | 逐条编辑修复 | 批量浏览、筛选、注释 |
| 操作人员 | 翻译人员 | 审校人员、项目经理、甲方 |
| 是否需要 Studio | 是 | 否（仅需浏览器） |
| 能否修改译文 | 能 | 不能（仅注释和标记） |

推荐的协作流程：

1. **翻译人员在 Studio 中完成翻译**，利用实时 QA 面板进行初步质量自查，修复所有阻断问题。
2. **翻译人员运行 Review CLI**，生成 HTML 审查报告。
3. **审校人员在浏览器中打开 HTML 报告**，逐条审核并添加注释。
4. **审校人员将注释导回翻译人员**（通过导出注释文件或直接共享 HTML 文件）。
5. **翻译人员在 Studio 中根据注释修改译文**，再次运行 QA 确认。
6. **最终生成 HTML 报告作为交付归档**。

## 8.9 QA 最佳实践

经过大量工程图纸翻译项目的实践检验，以下最佳实践可以帮助您最高效地利用同文的 QA 系统。

### 8.9.1 批量检查，不要逐条等待

**为什么**：一张中型结构施工图可能包含 500~800 个翻译单元。如果在翻译每一条之后立即运行 QA，虽然能及时发现问题，但频繁的操作中断会严重拖慢翻译效率。

**推荐做法**：

1. 完成整张图纸（或至少一个完整的图层/区域）的翻译后，再统一运行 QA。
2. 使用"全部重新检查"功能（而非逐条检查），获得当前翻译会话的完整质量快照。
3. 在翻译工作区的数据表格中按"风险"列排序，将注意力集中在阻断和高级条目上。

### 8.9.2 逐条处理，不要批量忽略

**为什么**：QA 发现的每一条都有其产生的具体原因。将所有高级发现批量标记为"已确认"看似高效，但实际上等同于关闭了质量检查的价值。

**推荐做法**：

1. 先按风险等级从高到低排序。
2. 对每一条阻断级发现，逐条参照原文占位符修复译文。
3. 对每一条高级发现，打开术语库核实标准译法，判断是否真的需要修改。
4. 对每一条中级发现，确认是否需要优化。
5. 低级发现可以在最后批量处理。

### 8.9.3 反复验证，修复后必须重新运行 QA

**为什么**：修复一个 QA 发现的过程中，可能引入新的问题。例如您在译文中手动添加占位符时，可能添加了错误类型或多余的数量。

**推荐做法**：

1. 修复完一批发现后，对该批翻译单元重新运行 QA。
2. 确认所有被修复的问题状态变为"已修复"或从列表中消失。
3. 确认没有因为修改而引入新的 QA 发现。
4. 只有当所有翻译单元的阻断级和高级发现被清除后，才进入审批流程。

### 8.9.4 术语库维护先行

**为什么**：术语验证器的检查质量完全取决于术语库的收录质量。如果术语库不完整或存在错误，术语验证器会漏报真正的问题，或误报正确的内容。

**推荐做法**：

1. 在翻译开始之前，先花时间检查术语库——确保项目相关的核心术语已被收录且标准译法正确。
2. 对于新的工程领域或新的甲方，先导入甲方提供的术语表。
3. 在翻译过程中，如果发现术语库缺失某个高频术语，随时补充到术语库中，然后重新运行 QA。
4. 项目结束后，将本项目新增的术语审核后纳入公司级的术语标准库。

### 8.9.5 团队 QA 协作中的角色分工

| 角色 | QA 职责 | 使用的工具 |
|------|---------|-----------|
| **翻译人员** | 翻译译文，清除所有阻断和高级发现。 | Studio QA 面板 |
| **审校人员** | 审核术语一致性、语义准确性和语境适配性；标注需要修改的条目。 | Review CLI HTML 报告 |
| **项目经理** | 监控项目整体 QA 指标（阻断/高/中/低发现数量、完成率）；决定哪些发现需要退回修改。 | Review CLI HTML 报告 + QA 导出报告 |
| **CAD 设计人员** | 处理长度溢出中需要修改图纸的情况（扩大文本框、调整文字样式）。 | AutoCAD |

### 8.9.6 建立项目级 QA 通过标准

不同项目对翻译质量的要求不同。建议在项目启动时明确 QA 通过标准：

| 项目类型 | 阻断 | 高 | 中 | 低 |
|----------|------|----|----|----|
| 海外投标图纸 | 0 | 0 | 允许少量 | 允许 |
| 施工图交付 | 0 | 0 | 全部确认 | 允许 |
| 内部参考图纸 | 0 | 允许少数 | 允许 | 允许 |

建立明确的标准可以避免无休止的 QA 修改循环——当已知会甲方可以接受一定数量的中级问题时，审校人员不必为了追求"零发现"而反复修改微小的溢出问题。

## 8.10 常见 QA 问题与处理方法

以下整理了在实际项目中最常遇到的 QA 问题类型、典型案例和对应处理方法。

### 8.10.1 占位符丢失

**问题描述**：译文中缺少原文中存在的占位符。

**典型案例**：

```
原文：梁截面尺寸⟨F1⟩ 300×600⟨F2⟩，配筋⟨F3⟩见详图
译文：Beam section 300×600, see detail drawing for reinforcement
QA 发现：三个阻断 — ⟨F1⟩、⟨F2⟩、⟨F3⟩ 均缺失
```

**原因分析**：

1. 翻译人员在编辑译文时，不慎将占位符连同前后的空格一起删除。
2. 使用了外部翻译工具或复制粘贴了外部内容，占位符在过程中丢失。
3. 在翻译工作区中使用了"全部替换"功能，将占位符的文本表示也替换掉了。

**处理方法**：

1. 如果翻译记忆中有该占位符的备份，使用"从记忆恢复占位符"功能。
2. 如果无法自动恢复，从原文中逐个复制占位符，粘贴到译文中对应的语义位置。
3. 修复后重新运行 QA，确认所有阻断消除。

**预防措施**：

- 在翻译工作区中编辑译文时，注意不要删除形如 `⟨Fx⟩` 的标记——它们虽然看起来像普通文本，但在系统中是占位符。
- 不要使用剪切板从外部粘贴整段译文来代替逐条翻译——这很容易丢失占位符。

---

### 8.10.2 术语不一致

**问题描述**：同一术语在术语表中有标准译法，但翻译结果使用了其他译法。

**典型案例**：

```
图纸 A 中：混凝土 → Concrete
图纸 B 中：混凝土 → Cement
图纸 C 中：混凝土 → RC
术语表定义：混凝土 → Concrete（建筑专业，强制）
```

这种不一致在批量翻译中非常常见，尤其是多人协作时。

**处理方法**：

1. **短期修复**：打开术语库，确认标准译法。在翻译工作区中使用"查找替换"功能，将不一致的译法批量替换为标准译法。替换后重新运行 QA。
2. **长期改善**：
   - 在项目开始前统一导入术语表到所有翻译人员的同文工作台中。
   - 利用翻译记忆（TM）的自动填充功能——记忆库中已有的标准译法会自动填充到新的翻译单元中，减少人工翻译带来的不一致性。
   - 定期运行 QA，发现术语不一致后立即修正记忆库中的对应条目。

---

### 8.10.3 术语缺失

**问题描述**：原文中包含术语表中标记为强制翻译的术语，但译文中完全找不到对应的译法——即该术语被漏译。

**典型案例**：

```
原文：抗震设防烈度为 7 度，设计基本地震加速度值为 0.10g
术语表定义：抗震设防烈度 → Seismic Fortification Intensity（结构专业，强制）
          设计基本地震加速度 → Design Basic Earthquake Acceleration（结构专业，强制）
译文：is 7 degrees, value is 0.10g
QA 发现：两个高级 — "抗震设防烈度"和"设计基本地震加速度"均缺失
```

**原因分析**：

1. 翻译人员将注意力集中在数字和单位上，忽略了前面的术语名词。
2. 使用了机器翻译引擎，而该引擎将该术语视为"不可翻译的专有名词"，直接跳过了。

**处理方法**：

1. 对照原文，找出被遗漏的术语位置。
2. 在译文中补充标准译法——将术语表定义的标准译法插入到译文的正确位置。
3. 如果术语缺失是机翻引擎导致的，将该术语标记为"必须翻译"后重新运行机翻，或手动补充。

---

### 8.10.4 译文长度严重溢出

**问题描述**：中译英时，英文长度远超过中文原文，译文预计宽度超出图纸文本框。

**典型案例**：

```
原文：钢筋混凝土框架-剪力墙结构（共 12 字）
包围盒宽度：96mm
译文：Reinforced Concrete Frame-Shear Wall Structure（共 49 字符）
译文预计宽度：178mm（超出 85%）
QA 发现：高 — 长度溢出 85%
```

**处理方法**：

**方案 A：缩简译文**

使用行业公认的缩写和压缩表达：

- "钢筋混凝土"→"RC"（Reinforced Concrete）
- "框架-剪力墙结构"→"Frame-Shear Wall"
- "详见"→"See"
- "示意图"→"Dwg."（Drawing 的缩写）

缩简后的译文："RC Frame-Shear Wall Structure"，预计宽度大幅降低。

**方案 B：调整 CAD 文本框**

如果 ABB（Abbreviation）在甲方规范中不允许使用，或缩简后仍溢出：

1. 在 AutoCAD 中打开原始图纸。
2. 找到该文字实体，使用属性面板或 `STRETCH` 命令扩大文本框的宽度。
3. 保存图纸后，重新在同文中运行 QA——新的包围盒数据会在下次提取时更新。

**方案 C：调整文字样式**

在 AutoCAD 中调整该文字样式的宽度因子（Width Factor）：

- 默认宽度因子为 1.0。
- 调整为 0.8 表示字符宽度压缩 20%，相同长度的文字占用更小的空间。
- 注意：过度压缩会影响可读性，一般建议不低于 0.75。

### 8.10.5 数字和单位的格式码问题

**问题描述**：图纸中经常出现带格式码的数字标注（如"⟨F1⟩300⟨F2⟩×⟨F3⟩600⟨F4⟩"），翻译时格式码容易丢失或错位。

**典型案例**：

```
原文：梁截面⟨F1⟩300⟨F2⟩×⟨F3⟩600⟨F4⟩
译文：Beam Section 300×600
QA 发现：四个阻断 — ⟨F1⟩、⟨F2⟩、⟨F3⟩、⟨F4⟩ 均缺失
```

**处理方法**：

1. 数字和符号本身不需要翻译（300 和 600 以及 × 符号在中英文中一致）。
2. 但占位符必须保留——因为格式码控制的是数字的字体、字高或颜色，与语言无关。
3. 修复后的译文应为：`Beam Section⟨F1⟩300⟨F2⟩×⟨F3⟩600⟨F4⟩`。

**注意**：数字和乘号在原文和译文中保持不变，但占位符的语义位置可能需要调整。在本例中，`⟨F1⟩` 到 `⟨F4⟩` 的位置与原文一致，因为数字和符号的顺序没有改变。

---

### 8.10.6 同一翻译单元多个 QA 发现

**问题描述**：一条翻译单元同时有占位符缺失、术语冲突和长度溢出三个问题。

**处理方法**：

1. **处理优先级**：先修复占位符缺失（阻断），再处理术语冲突（高），最后处理长度溢出（中/低）。
2. **分批处理**：不要试图一次解决所有问题——先修复阻断，重新运行 QA 确认阻断消除后，再处理高级问题。
3. **记录处理进度**：在 QA 发现列表中使用状态标记（待处理→已修复→已确认），追踪每一条发现的处理情况。

## 8.11 本章小结

本章全面介绍了同文（Tongwen）质量检查与报告系统的各项功能和使用方法：

1. **QA 概述**：质量检查是翻译完成和回写交付之间的自动化审查环节，专门针对工程图纸翻译的格式码完整性、术语一致性和长度溢出三个维度进行系统化把关。

2. **三种验证器**：
   - **占位符验证器**检查 MText 格式码占位符是否完整保留——任何缺失或多余都会触发阻断级风险。
   - **术语验证器**检查翻译结果是否遵循术语库中定义的标准译法——术语冲突和术语缺失属于高级风险。
   - **长度溢出验证器**基于包围盒估算检查译文是否可能超出 CAD 文本框——溢出程度对应不同的风险等级。

3. **四级风险等级**：🚫阻断（禁止回写）、🔴高（默认要求人工审核）、🟡中（可确认继续）、🔵低（建议优化）——每级有明确的触发条件、回写影响和处理策略。

4. **在翻译工作区查看 QA 结果**：数据表格的"风险"列以颜色标识每个翻译单元的最高风险等级；详情面板中的"QA 发现"区域逐条列出详情和建议。

5. **处理 QA 发现**：阻断级问题必须修复；高级问题建议在回写前处理；中低级问题可审核确认。每条发现都有处理状态追踪。

6. **QA 报告导出**：JSON 格式提供完整的结构化数据用于归档和系统集成；CSV 格式提供汇总级指标适合在 Excel 中快速浏览和交付给非技术方。

7. **批量审查 HTML 报告**：Review CLI 生成可交互的 HTML 审查报告，支持浏览器离线查看、多条件筛选、注释标记，适合团队协作和甲方交付。

8. **QA 最佳实践**：批量检查再逐条处理、修复后反复验证、术语库维护先行、建立项目级 QA 通过标准。

9. **常见问题与处理方法**：覆盖占位符丢失、术语不一致/缺失、长度溢出、数字格式码处理等典型场景的解决步骤。

质量检查是同文"无损翻译"承诺的关键保障。通过系统化的 QA 流程，您可以确保每一句译文在写回 CAD 图纸之前都经过了严格的格式、术语和空间验证——最终交付的不仅是翻译后的图纸，更是一份经得起审查的质量保证。
