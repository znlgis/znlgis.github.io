# 第01章：产品概述

## 1.1 产品简介

同文（Tongwen）是一套面向工程图纸的本地优先 CAD/BIM 无损翻译套件。其名称取自中国古代"车同轨，书同文"的统一理念——正如秦始皇统一度量衡与文字奠定了中华文明的基础，同文致力于为工程图纸的跨语言交流提供统一、精确、无损的翻译解决方案。

在全球化工程协作的背景下，一张建筑结构图纸、暖通管道图或电气布线图往往需要同时交付中英文版本，甚至面对日本监理、德国业主、阿拉伯承包商的多语种需求。传统的翻译方式——导出文字到 Excel、手动翻译、再逐条回填——不仅耗时费力、容易出错，更致命的缺陷是：翻译过程会破坏图纸的图层结构、文字样式、坐标定位和对象关联关系，导致翻译后的图纸无法直接用于后续设计变更。

同文从根本上解决了这一难题：它在完整保留图纸原生数据（图层、坐标、文字样式、块属性、工程符号、对象关联）的前提下，实现文本的自动提取、术语约束下的智能翻译、人工精细化审查以及受控回写，最终输出与原始图纸结构完全一致的翻译版本。整个过程对图纸"零破坏"——这就是"无损翻译"的核心承诺。

> **产品官网**：[https://shandianweihu.com/](https://shandianweihu.com/)

### 1.1.1 解决的核心问题

工程图纸翻译面临的痛点，同文逐一给出对策：

| 痛点 | 传统做法 | 同文的方案 |
|------|---------|-----------|
| 文字提取繁琐，需逐条复制粘贴 | 手动点选每个文字对象，导出到 Excel | 自动扫描全图文本，批量提取，保留精确坐标与属性 |
| 术语不统一，同一词汇反复出现不同译法 | 依赖人工记忆或零散的术语表 | 内置四层翻译知识系统，术语约束自动生效 |
| 翻译后图层错乱、样式丢失 | 爆破文字对象后重新手写，原格式不复存在 | 三种回写策略，完整保留图层/颜色/字体/高度/旋转角度等全部属性 |
| 图纸协作中审校环节缺失 | 翻译完成即交付，质量全靠个人 | 四级风险质量检查（阻断/高/中/低），支持人工审校与修正记忆积累 |
| 批量处理效率低下 | 逐张图纸打开、翻译、保存，百张图需要数天 | 命令行批量处理模式，一次配置，批量执行 |
| 数据安全担忧 | 上传至第三方云平台翻译，图纸泄密风险高 | 本地优先架构，所有数据不出本地，支持纯离线运行 |

### 1.1.2 名称的寓意

"同文"二字承载着深刻的产品哲学：

- **同**——统一。统一术语、统一译文、统一质量标准。让同一张图纸的中文版和英文版在技术上完全等价，不会因为语言转换而丢失任何工程信息。
- **文**——文字，亦是文化。文字是工程信息的载体，更是技术交流的桥梁。同文不仅要做好文字翻译，更要打通中外工程协作的语言壁垒。

## 1.2 产品定位与目标用户

### 1.2.1 产品定位

同文定位为一款**专业级工程图纸翻译工具**，而非通用翻译软件。它与 Google Translate、DeepL 等通用翻译服务有着本质区别：

- 通用翻译服务于自然语言文本，不关心文本的来源载体和空间属性
- 同文服务于工程图纸语境下的专业文本，必须严守在图纸结构完整性的前提下完成翻译

具体来说，同文面向以下核心需求场景：

1. **图纸双语化交付**：国内设计院向海外业主/监理交付图纸时，需提供中英（或中+第三方语言）双语版本
2. **海外项目出图**：中国工程企业承接海外项目，需要将全套施工图翻译为当地语言
3. **图纸翻译审校**：已有翻译版本需要质量审查、术语一致性校验、格式核对
4. **多语种图纸归档**：大型项目需要同时保留多个语言版本的竣工图档案

### 1.2.2 目标用户

同文主要面向以下工程技术人员：

- **建筑设计师**：需要将建筑平面图、立面图、剖面图翻译为英文或其他语种
- **MEP 工程师**：暖通（HVAC）、给排水（Plumbing）、电气（Electrical）专业图纸的翻译需求最为密集，文本量大、术语多、符号复杂
- **结构工程师**：结构配筋图、节点详图中包含大量技术参数和专业注释
- **材料工程师**：材料表、设备清单等表格类文本翻译
- **翻译公司/BIM 咨询团队**：专业从事工程图纸翻译服务的团队，需要高效的工具链
- **海外项目经理**：需要快速审校外包翻译质量的技术管理人员

### 1.2.3 使用门槛

同文在设计上充分考虑了工程人员的使用习惯：

- 如果日常工作已在使用 AutoCAD 绘图，AutoCAD 插件模式几乎零学习成本——侧边面板集成在熟悉的绘图界面中
- 如果不打开 AutoCAD，WPF Studio 桌面工作台提供独立的项目管理、翻译编辑和术语维护环境
- 批量处理场景下，命令行工具支持脚本集成，适合 IT 管理员配置自动化流水线

## 1.3 核心特性

### 1.3.1 本地优先，数据安全

同文采用**本地优先（Local-First）**架构，所有数据——原始图纸、提取文本、术语库、翻译记忆、译文——全部存储于用户本地计算机。不依赖任何云服务即可完成全部翻译工作流。

这意味着：

- 涉密图纸（军工、核电、敏感基础设施）可以放心使用，图纸数据绝不离开本地网络
- 无网络环境下完全可用（仅在需要调用云端大模型翻译时才需联网，但此功能为可选）
- 翻译记忆和术语库作为本地资产持续积累，形成团队专属的知识沉淀

### 1.3.2 无损翻译

"无损"是同文最核心的技术承诺，具体体现为三个层面：

**数据无损**：翻译前后的 DWG 文件，除文字内容外，其他所有图元数据（线段、多段线、圆弧、填充、块参照、尺寸标注等）完全不变。文字对象的图层归属、颜色、字体、高度、宽度因子、倾斜角、旋转角、对齐方式、坐标位置——无一丢失。

**关系无损**：块属性文字、属性定义、多行文字段落格式、字段引用等复杂文字对象的内部关联关系得到完整保留。不会因为翻译将块参照"炸开"为散落文字。

**可逆无损**：通过"创建新图层"回写策略，原文文字保留在原始图层，译文写入新建图层。设计人员可随时通过开关图层在一秒内切换原文/译文视图，或同时显示双语对照。

### 1.3.3 智能术语约束

通用翻译引擎不了解工程语境——它会把建筑图中的"柱"翻译成 pillar（柱子），而结构专业要求的是 column（框架柱）；会把电气图中的"回路"翻译成 circuit（电路），而电气专业有时需要 loop。更严重的是，同一张图纸中的同一术语可能前后译法不一，给施工方造成歧义。

同文构建了**四层翻译知识系统**，按优先级从高到低：

1. **人工修正记忆（CM, Correction Memory）**——用户在对翻译结果进行人工修正后，修正记录自动保存。下次遇到相同或相似的源文，优先使用修正后的译文。这是最可靠的翻译来源，因为它代表了用户对具体语境的最终判断。

2. **翻译记忆（TM, Translation Memory）**——翻译引擎确认通过的原文-译文对自动积累为翻译记忆。相当于传统 CAT 工具的记忆库，确保重复出现的文本保持翻译一致。

3. **术语表（Glossary）**——用户预先维护的专业术语对照表，按领域（建筑/暖通/给排水/电气/结构/材料/通用）组织。翻译引擎在工作时必须遵循术语表的约束——术语表中已有的译法不得被覆盖。

4. **大语言模型（LLM）**——当前三层知识库无匹配时，由 AI 翻译引擎（支持 DeepSeek v4 快速/高质量两种模式）根据上下文生成译文。大模型提供兜底能力，但始终受前三级知识约束。

这套四层系统确保了两个关键质量指标：**术语一致性**（同一术语整图统一译法）和**领域适配性**（建筑术语不会翻译成通用含义）。

### 1.3.4 人机协同审查

同文不追求"全自动翻译"——在工程图纸这一高精度领域，人的判断不可替代。同文的设计理念是：**机器做它擅长的（批量提取、术语匹配、一致性检查、格式保留），人做人擅长的（语境判断、歧义消解、专业审查），两者通过高效的交互界面无缝衔接。**

具体体现为三个环节：

1. **翻译工作区**：集中展示原文、机器译文、术语提示，支持单条编辑、批量确认、批量驳回。用户可以逐条审视每一处翻译，修改确认后自动记入修正记忆。

2. **质量检查（QA）**：内置三类自动检查——占位符验证（如 `%%D`、`%%C` 等 AutoCAD 特殊符号是否被破坏）、术语验证（译文是否遵循术语表约束）、长度溢出验证（翻译后的文字是否超出了原始文字的空间范围）。每项问题标注风险等级：阻断/高/中/低，帮助审校人员优先处理严重问题。

3. **修正记忆积累**：每一次人工修正都在提升系统的翻译能力。随着使用时间增加，同文对特定设计院/特定项目/特定专业图纸的翻译质量会持续提升，越来越贴合实际需求。

## 1.4 核心功能概览

### 1.4.1 文本提取

文本提取是同文工作流的起点。系统自动扫描 DWG 图纸中的全部文字对象，包括：

- 单行文字（TEXT）
- 多行文字（MTEXT）
- 块属性文字（ATTRIB）
- 属性定义（ATTDEF）
- 尺寸标注文字（DIMENSION）
- 多重引线文字（MLEADER）
- 表格文字（TABLE）

提取过程中记录每一条文字的完整属性快照：图层、文字样式、字体、高度、颜色、宽度因子、倾斜角、旋转角、对齐点坐标、附着点、段落格式（多行文字）、所属块名称（属性文字）等。这些属性在回写阶段被完整还原，是实现无损翻译的基础。

文本提取支持以下筛选控制：

- **图层筛选**：仅提取指定图层上的文字（例如只翻译中文图层，保留英文图层不变）
- **内容筛选**：排除纯数字、纯标点、已为全英文等无需翻译的文本
- **长度筛选**：排除过短（如单字母标注）或过长（如冗长的技术说明，可单独处理）的文本

### 1.4.2 翻译工作区

翻译工作区是同文人机协同的中央控制台，提供两大视图模式：

**WPF Studio 桌面工作台模式**：独立应用程序，适合在不打开 AutoCAD 时集中管理翻译项目。功能包括：

- 项目创建与管理（一个项目可包含多张关联图纸）
- 原文-译文对照编辑（类 Excel 表格界面，支持筛选、排序、搜索）
- 术语提示面板（实时显示当前选中文本相关的术语条目）
- 翻译引擎调用（一键翻译当前项目全部待译文本）
- 批量确认/批量驳回（支持快捷键操作，提升审校效率）
- 项目管理（图纸关联、翻译状态追踪、版本历史）

**AutoCAD 侧边面板模式**：嵌入在 AutoCAD 界面中，适合边看图边翻译。在侧边栏中选中文字条目时，图纸视口自动缩放到对应文字位置，实现"所见即所译"。这种图文联动的方式极大降低了因脱离图纸语境而产生的翻译错误。

### 1.4.3 术语库管理

术语库是同文翻译质量的基石。系统提供独立的术语管理界面，支持：

- **多领域组织**：术语按专业领域分类——建筑、暖通（HVAC）、给排水（Plumbing）、电气（Electrical）、结构（Structural）、材料（Material）、通用（General）。用户可以按领域筛选和维护术语，翻译时系统根据图纸专业自动匹配对应术语集。
- **术语导入/导出**：支持从 Excel/CSV 文件批量导入术语，也支持将当前术语库导出为标准格式用于团队共享。
- **术语冲突检测**：导入时自动检测重复或冲突的术语条目，提示用户确认或合并。
- **双语术语**：每一条术语包含原文、译文、所属领域，可选附注用法说明和示例。

大型设计院通常需要维护数百至数千条专业术语。同文的术语库可作为团队级别的知识资产持续积累和版本管理。

### 1.4.4 回写策略

翻译完成并通过审校后，同文提供三种回写（Write-Back）策略，将译文写回 DWG 图纸：

**策略一：创建新图层（Create New Layer）**

最安全的回写方式。为每个被翻译的原始图层创建一个对应的译文图层（命名规则：`原图层名_目标语言`，如 `TEXT_CHN` → `TEXT_ENG`），译文文字写入新图层，原始文字完全保留。

- 优点：完全可逆，原文一毫不损；可通过图层开关自由切换双语/纯原文/纯译文显示；适合需要同时保留双语版本的交付场景
- 适用场景：设计院内部校审、双语竣工图归档

**策略二：原位替换（In-Place Replace）**

直接将原文文字对象的内容替换为译文，图层和所有属性保持不变。

- 优点：输出的图纸结构与原始完全一致，不增加额外图层，文件体积不变；适合直接交付外方使用的场景
- 注意：此操作为不可逆操作，建议在执行前保留原始图纸备份
- 适用场景：最终交付海外业主/监理的单语种版本

**策略三：双语追加（Bilingual Append）**

在原文文字内容后追加译文，形成"原文 / 译文"的双语显示格式（分隔符可自定义，如 ` / ` 或换行符）。

- 优点：一张图纸同时展示双语，施工人员可对照阅读
- 注意：文字长度显著增加，可能导致文字超出原有空间范围（QA 模块的长度溢出检查可提前预警）
- 适用场景：施工现场用图、多语种协作图纸

### 1.4.5 质量检查（QA）

质量检查是同文保障翻译交付质量的最后一道防线。系统提供三类自动检查：

**占位符验证**

AutoCAD 图纸中大量使用特殊控制符，如 `%%D`（度符号 °）、`%%C`（直径符号 φ）、`%%P`（正负符号 ±）、`%%U`（下划线开关）等。翻译过程若不小心破坏这些控制符，会导致图纸显示异常。同文自动检测每条译文中的占位符是否与原文一致，发现异常标记为"阻断"级风险——必须修正后才能回写。

**术语验证**

对照术语库中已维护的条目，检查译文中是否出现了与术语表规定不一致的译法。例如术语表规定"钢筋混凝土"→"reinforced concrete"，若某条译文使用了"steel concrete"或"RC concrete"，系统将标记为"高"级风险并提示正确译法。

**长度溢出验证**

翻译后的文字长度通常与原文不同（中文译英文通常变长 30%-50%），可能导致文字超出原有标注空间，与其他图元重叠。同文根据原文文字的属性（字体、高度、宽度因子）估算译文的几何宽度，与原始文字框宽度对比，超出阈值则标记风险。风险分级：
- 低：超出 0-10%（可接受范围）
- 中：超出 10-30%（建议调整文字高度或宽度因子）
- 高：超出 30-50%（必须处理，否则影响图面清晰度）
- 阻断：超出 50% 以上（严重溢出，会遮挡相邻图元）

### 1.4.6 批量处理（Batch Processing）

当面临数十甚至数百张图纸的翻译任务时，手动逐张操作效率极低。同文提供命令行批量处理模式（CLI），支持：

- **批量文本提取**：指定文件夹，一次性提取所有 DWG 图纸中的文本，汇总输出为翻译工作文件
- **批量翻译**：基于已配置的术语库和翻译引擎，自动翻译全部待译文本
- **批量回写**：按选定的回写策略，将译文批量写回所有图纸
- **批量质量检查**：对所有图纸执行 QA 检查，输出汇总质量报告

批量处理模式特别适合：
- 项目收尾阶段的全套图纸翻译
- 翻译公司的批量订单处理
- 图纸版本更新后的大规模重新翻译

### 1.4.7 Web API 服务

对于需要将图纸翻译能力集成到自有业务系统中的团队，同文提供 Web API 服务。通过标准的 HTTP 接口，可以实现：

- 远程提交图纸翻译任务
- 查询翻译进度和状态
- 下载翻译结果文件

这一功能使得同文可以作为翻译中台，嵌入到设计院的协同设计平台、项目管理系统或 BIM 平台上，实现翻译能力的系统级复用。

## 1.5 支持平台

### 1.5.1 CAD 平台

同文通过多版本 AutoCAD 插件适配，支持以下 AutoCAD 版本：

| 版本 | 支持状态 | 说明 |
|------|---------|------|
| AutoCAD 2019 | 支持 | 基础版本起点 |
| AutoCAD 2021 | 支持 | 广泛使用的稳定版本 |

- 将图纸导出为 AutoCAD DWG 格式，在同文中完成翻译后，再导回原平台
- 通过 Web API 提交 DWG 文件进行远程处理

### 1.5.2 运行模式

同文提供三种运行模式，覆盖不同使用场景：

**模式一：AutoCAD GUI 插件模式**

在 AutoCAD 内部运行，提供侧边面板和翻译工作台窗口。最直观的使用方式，看图与翻译同屏联动。适合日常的图纸翻译工作。

**模式二：WPF Studio 桌面模式**

独立的 Windows 桌面应用程序，不依赖 AutoCAD 运行。适合以下场景：
- 专职翻译人员无需安装 AutoCAD 即可进行翻译审校工作
- 统一管理多个项目的术语库和翻译记忆
- 在不打开图纸的情况下集中审校翻译内容

**模式三：批量命令行模式（Headless/Batch）**

在命令行环境运行，无图形界面，通过 Core Console 操作 DWG 文件。适合：
- 服务器端批量处理
- CI/CD 流水线中的图纸翻译自动化
- IT 管理员配置定期翻译任务

三种模式共享同一套术语库和翻译记忆，切换模式不会丢失任何数据。

## 1.6 支持语言

同文支持 **26 种**语言之间的互译，覆盖了全球主要工程市场的语言需求：

**东亚语言（5 种）**：中文（简体）、繁体中文（台湾/香港）、日文、韩文

**欧洲语言（16 种）**：英文、法文、西班牙文、德文、俄文、葡萄牙文、意大利文、希腊文、荷兰文、波兰文、保加利亚文、爱沙尼亚文、丹麦文、芬兰文、捷克文、罗马尼亚文、斯洛文尼亚文、瑞典文、匈牙利文

**东南亚/中东语言（2 种）**：泰文、越南文、阿拉伯文

这些语言覆盖了中国工程企业海外业务的主要目的地——东南亚、中东、非洲（法/葡语区）、中东欧、独联体、拉美等区域。翻译方向以"中文→其他语言"为主，"多语言→中文"同样支持。

### 语言组合的注意事项

由于不同语种的文字特点差异显著，在使用中需要注意：

- **中文→英文**：英文文本通常比中文长约 30-50%，容易造成长度溢出。建议优先使用"创建新图层"回写策略，并通过长度溢出检查功能提前评估影响。
- **中文→阿拉伯文**：阿拉伯文为从右向左书写（RTL），AutoCAD 对 RTL 文字的支持有限。建议在实际项目中充分测试，必要时采用表格式排版替代多行文字。
- **中文→俄文/德文**：这两种语言的单词普遍较长，长度溢出风险较高。建议适当减小文字高度或增大宽度因子。
- **中文→日文/韩文**：字符宽度与中文相近，长度变化较小，翻译后排版调整最少。

## 1.7 专业技术特点

本节从用户视角描述同文的技术优势，帮助您理解为什么同文能实现普通翻译工具无法达到的效果。

### 1.7.1 翻译精度保障

同文的翻译精度由两条线共同保障：**术语一致性**和**格式完整性**。

术语一致性由四层翻译知识系统（CM → TM → Glossary → LLM）逐级约束。越是核心的、重复出现的术语，越高概率被前几级知识命中，从而确保全图译法统一。例如一张暖通图纸中"排烟风机"可能出现 20 次，只要用户确认过一次正确的译文"smoke exhaust fan"，后续 19 次都会被修正记忆自动匹配，无需人工重复确认。

格式完整性由文本属性快照机制保障。提取时记录的文字属性被原样写入译文文字对象——不是"复制样式"，而是创建与原文字完全同构的新文字对象。这意味着即使原文使用了罕见字体、特殊倾斜角或非标准宽度因子，译文也能精准还原。

### 1.7.2 本地数据安全

同文的本地优先架构确保图纸数据从源头到输出全程不出用户本地环境。具体来说：

- 图纸文件驻留在用户指定的本地目录中，同文不复制、不上传、不移走原始文件
- 提取的文本数据以本地文件（SQLite 数据库或 JSON 文件）存储，位于项目工作目录下
- 术语库、翻译记忆、修正记忆均为本地数据库文件，用户拥有完全控制权
- 仅在用户明确选择使用云端大模型翻译时，待翻译的纯文本（不含图纸本身）才会通过网络发送给 AI 服务商。用户可在设置中关闭联网功能，此时仅使用本地术语库和翻译记忆进行离线翻译

### 1.7.3 离线能力

在不联网的情况下，同文依然可以完成大部分翻译工作：

- 基于已积累的翻译记忆（TM）和修正记忆（CM），系统可自动匹配已翻译过的文本，实现离线翻译
- 术语库始终可用，不受网络状态影响
- 所有编辑、审校、回写功能完全离线运行

离线能力对于以下场景至关重要：
- 涉密单位的内网环境
- 施工现场的网络不稳定环境
- 海外项目的低带宽环境

### 1.7.4 可积累的翻译能力

同文不是一次性工具——它是一个"越用越聪明"的知识系统。随着使用时间的推移：

- 修正记忆（CM）不断沉淀设计院/项目组的专属译法偏好。例如某设计院习惯将"预留洞"翻译为"reserved opening"而非"precast hole"，这种偏好被 CM 记录后，后续所有项目自动遵循。
- 术语库（Glossary）作为团队级知识资产持续完善。新项目中的新术语被补充进术语库，全团队受益。
- 翻译记忆（TM）随项目数量增长，大段落的常用说明文字（如图框说明、施工注意事项）可被完全复用。

这些积累意味着：同一团队使用同文翻译的图纸越多，翻译效率越高、质量越稳定。

### 1.7.5 翻译引擎选择

同文支持两种翻译引擎模式，用户可根据需求自由切换：

**DeepSeek v4（云端大模型）**

- **Flash 快速模式**：响应速度快，适合大批量常规文本的初译，作为翻译候选提交给人工审校
- **Pro 高质量模式**：推理更深，对复杂句式、含技术参数的文本处理更准确，适合关键图纸的核心内容翻译
- 需联网使用，文本通过网络发送给 AI 服务商处理

**Mock 测试引擎（本地离线）**

- 完全在本地运行，不需要网络
- 主要用于测试工作流、验证术语约束效果、培训新用户
- 产生"模拟翻译"输出（如在原文前后添加标记），帮助用户理解翻译系统的处理逻辑

两种引擎在实际使用中可以组合：日常积累翻译记忆时使用 Mock 引擎，正式翻译时切换为 DeepSeek 引擎，充分利用已积累的 TM/CM 提升翻译质量。

## 1.8 适用场景

### 1.8.1 场景一：建筑/MEP/结构图纸双语化

**典型需求**：国内某大型设计院承接中东某国的大型商业综合体项目，合同要求交付全套中英双语施工图，图纸数量约 500 张，涵盖建筑、结构、暖通、给排水、电气五个专业。

**同文方案**：
1. 各专业负责人使用同文 Studio 工作台创建翻译项目，导入本专业全部 DWG 图纸
2. 按专业配置术语库——结构组使用结构术语集，暖通组使用暖通术语集，避免跨专业术语干扰
3. 一次性执行全项目文本提取（500 张图纸的全量文本在数分钟内提取完毕）
4. 使用 DeepSeek Pro 引擎批量初译，系统自动遵循术语约束
5. 各专业工程师在翻译工作区逐条审校，修正确认后的译文自动记入修正记忆
6. QA 检查发现 23 处高风险长度溢出，工程师调整文字高度后重新验证通过
7. 采用"创建新图层"策略批量回写，生成双语 DWG 文件交付

**效果**：传统方式下 500 张图纸人工翻译审校需约 3 周，同文辅助下压缩至约 3 天。

### 1.8.2 场景二：海外项目出图

**典型需求**：中国某 EPC 总承包商承建东非某国水电站项目，需将全套施工图纸（约 800 张）翻译为英文和法文两个版本，交付业主和当地政府审批。图纸中包含大量水工专业术语（"蜗壳""尾水管""压力钢管"等），通用翻译工具完全无法胜任。

**同文方案**：
1. 翻译团队预先建立水工专业术语表（约 300 条核心术语），导入同文术语库
2. 两周内完成全部图纸的文本提取和初译
3. 组建 5 人审校团队，分工协作——同文支持多人共享术语库和翻译记忆（通过局域网文件共享）
4. 两轮审校后达到交付标准，QA 检查零阻断项
5. 先以"原位替换"策略生成英文版交付件，再以同样流程生成法文版

**效果**：两个语种的翻译可在同一套工作流中完成，术语在两个语种间保持一致性映射。

### 1.8.3 场景三：图纸翻译审校

**典型需求**：某设计院将一批图纸外包给翻译公司，收到译文后需进行质量审查——检查术语准确性和格式完整性。审查人员需要高效工具而非逐条肉眼比对。

**同文方案**：
1. 使用同文的"仅提取+QA"模式（不执行翻译），提取原文和外包译文
2. 将外包译文作为"译文"导入，原文作为"原文"对照
3. 运行 QA 检查——术语验证功能发现 47 处术语不一致问题，长度溢出检查发现 12 处高风险溢出
4. 生成 QA 报告，标注具体位置和问题等级，交翻译公司整改

**效果**：原本需要 2 人天的人工审校，同文 QA 在 10 分钟内完成初筛，审校人员只需聚焦高风险项。

### 1.8.4 场景四：多语种图纸归档

**典型需求**：大型国际工程项目竣工后，需要提交中、英、日三语版本的竣工图归档。三语版本需要保持图面结构完全一致，仅文字内容不同。

**同文方案**：
1. 以中文版为基准图纸，提取全部文字
2. 使用四层翻译知识系统分别翻译为英文和日文
3. 分别以"创建新图层"策略回写——中文版输出：原始图层含中文，英文图层含英文；日文版同理
4. 三个语种的图层可共存于同一 DWG 文件，通过图层管理器自由切换显示

**效果**：一个 DWG 文件即可容纳三语版本，归档管理极为便利。

## 1.9 产品架构简述

同文的产品架构设计遵循"本地优先、模块解耦、多端协同"的原则。从用户视角来看，其组成如下：

- **桌面工作台（WPF Studio）**：项目管理中枢，提供翻译编辑、术语库维护、设置管理等全部功能的统一操作界面。适合独立翻译人员和项目经理使用。

- **AutoCAD 插件**：在 AutoCAD 内部运行的扩展模块，提供侧边面板和翻译工作台窗口，支持 22 个命令行命令实现快捷操作。适合设计工程师在绘图环境中边看图边翻译。

- **翻译引擎适配层**：连接多种翻译引擎（DeepSeek v4 Flash/Pro、Mock 引擎），提供统一的翻译请求接口。用户可在设置中切换引擎，不影响上层工作流。

- **翻译知识库**：本地数据存储层，管理术语库（Glossary）、翻译记忆（TM）、修正记忆（CM）和项目配置。所有知识数据以文件形式存储在用户指定的本地目录中。

- **DWG 处理核心**：负责 DWG 文件的文本提取和译文回写，基于 AutoCAD 原生 API 开发，确保操作的精确性和兼容性。

- **命令行工具（CLI）**：独立可执行程序，提供批量处理、自动化集成能力。与桌面工作台共享同一套配置和知识库。

- **Web API 服务**：可选的网络服务模块，将核心翻译能力以 HTTP 接口形式暴露，支持第三方系统集成。

各模块之间通过统一的文件格式（项目文件、术语库文件、翻译记忆文件）实现数据互通，用户在桌面工作台中维护的术语库，在 AutoCAD 插件中可以即时使用，在命令行批量处理中同样生效。

## 1.10 产品优势总结

综合以上介绍，同文相对于其他图纸翻译方案（通用翻译软件、人工翻译、其他图纸翻译工具）的核心优势体现在：

1. **本地数据安全**：图纸不出本地，敏感项目可放心使用。这是许多涉密单位和大型设计院选择同文的首要原因。

2. **真正无损翻译**：图层、样式、坐标、块属性、工程符号全部原样保留。不是"再排版"，而是"仅替换文字内容"。

3. **术语知识可积累**：修正记忆、翻译记忆、术语库三大知识资产随项目持续沉淀，翻译质量越用越高，团队效率越用越快。

4. **人机高效协同**：机器处理批量提取、术语匹配、格式保留、质量检查等重复性高、规则明确的工作；人聚焦于语境判断和专业审查。两者各司其职，整体效率远超纯人工或纯自动。

5. **灵活的部署方式**：三种运行模式（AutoCAD 插件、桌面工作台、命令行）覆盖从个人单图翻译到团队批量作战的全场景需求，三种模式共享数据、无缝切换。

6. **广泛的兼容性**：支持 AutoCAD 2019-2026 四个版本，覆盖 26 种目标语言，适配建筑/MEP/结构/材料五大专业领域。

7. **完善的闭环能力**：从文本提取、翻译、审校、质量检查到回写，形成完整的翻译闭环。不需要在不同工具间导出导入数据，一个平台完成全部工作。
