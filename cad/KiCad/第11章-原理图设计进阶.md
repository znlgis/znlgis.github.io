# 第十一章：原理图设计进阶

上一章走通了从新建工程到生成网表的整条链路，也熟悉了原理图编辑器里的基本操作。这一章处理的是规模变大以后才会暴露的问题：图纸变多、符号变复杂、BOM 要对得上采购、改版要能追溯、仿真要能跑起来。这些内容在单页小电路上都不显眼，一旦进入多人协作或者多轮改版，就决定了一次设计能不能顺利交付。下面按设计组织、符号、文档标注、BOM、版本控制、仿真的次序展开。

## 11.1 复杂原理图设计策略

先看设计组织。原理图的设计质量有一半在画第一根导线之前就决定了：模块怎么分、每张图负责什么、信号从哪里进来又从哪里出去。项目越大，这部分返工越贵——画到两百个元件再回头改命名和接口，动的是全部图纸。

### 11.1.1 大型项目组织

对于复杂项目，良好的组织至关重要：

```
项目组织策略：
├── 功能模块划分
│   ├── 电源模块
│   ├── 处理器模块
│   ├── 通信模块
│   └── 接口模块
│
├── 层次化设计
│   ├── 顶层原理图（系统框图）
│   ├── 功能子图（详细电路）
│   └── 可复用模块
│
└── 命名规范
    ├── 网络命名
    ├── 元器件命名
    └── 页面命名
```

上面三层对应三个不同维度：功能模块划分回答「电路由哪几块组成」，层次化设计回答「这些块放进哪些文件」，命名规范回答「人和工具怎么定位它」。落地时有几条经验值得记：模块边界按「能不能单独测试、单独复用」来切，而不是按元件数量平均分；电源、时钟、调试接口通常独立成图，因为其他模块都要引用它们；一个模块对应一张子图，模块的电源入口、复位和对外接口画在子图边缘，内部不要出现跨模块的隐式连接。
命名规范要能被检查，网络名用「功能_方向」的形式（如 SPI1_MOSI、VBUS_EN），位号按功能分段（100 段电源、200 段 MCU、300 段接口），页面名与文件名一致。另外，不要依赖 KiCad 自动生成的 Net-(...) 名字，它随网络增删而变化，后续的 PCB 规则、测试点、仿真探针引用都会对不上。

### 11.1.2 层次化设计最佳实践

```
设计原则：
1. 合理划分模块边界
2. 定义清晰的接口
3. 避免过深的层次嵌套（3-4层为宜）
4. 保持子图的独立性
5. 统一命名规范

层次标签使用：
- Input：从父图到子图
- Output：从子图到父图
- Bidirectional：双向信号
- Power：电源接口
```

这几条原则里，前两条决定结构，后三条决定这套结构能不能维持。接口是否清晰，判断标准是：把子图单独拿出去，只凭它的端口和标签就能说明输入输出，不需要翻父图。层次嵌套控制在 3-4 层，是因为过深之后网表里的 sheet path 会变得很长，ERC 报错定位到具体图页的难度上升，评审时也很难在屏幕上铺开。子图独立性最容易被破坏的地方是全局标签：它在整个工程内可见，子图里一旦用了，这个子图就不能原样搬到别的项目。
跨层信号走层次标签，只有电源、复位这类确实全局的信号才用全局标签。标签方向不只是图形，ERC 会据此判断驱动关系，输入标签接到输出标签才算正常，方向标反会报「输入引脚未被驱动」或「输出短接」。列表里的 Power 并非 KiCad 标签形状中的一类——标签形状只有输入、输出、双向、三态、无源五种——它指的是电源类接口这一用途，实际处理时电源一般直接用电源符号，或者在子图上单列一个电源端口。

## 11.2 高级符号技术

符号是原理图的最小表达单位。库里现成的符号覆盖常规器件，遇到多运放、逻辑门阵列、特殊封装，或者要区分模拟地与数字地时，就得自己改符号。

### 11.2.1 多单元符号设计

```
应用场景：
- 四运放（如LM324）
- 六反相器（如74HC04）
- 双MOSFET
- 多通道ADC

设计要点：
1. 设置正确的单元数
2. 定义共享引脚（电源）
3. 设置单元可交换性
4. 合理安排引脚布局
```

多单元符号在 KiCad 的符号属性里用 Units 字段设置单元数。共享的电源引脚放在公共单元（unit 0）里，这样无论把 A/B/C/D 哪个单元放到图纸上，V+ 和 GND 都会自动出现；如果把电源脚画在单元 A 上，其余三个单元就没有供电引脚，ERC 会报电源引脚未连接。位号只有一套，四个单元共享 U1，各自引脚号不同，在 BOM 里表现为一行、数量 1，这一点和拆成四个独立符号有本质区别。
单元可交换的前提是封装内电气等价，运放的四个单元输入正负、输出、供电引脚都相同，可以互换；但某些器件手册明确某个单元承担特殊功能时，不要勾选可交换。引脚布局建议按信号流向来安排，A 单元先画输入侧，四个单元图形完全一样虽然合法，读图时反而要靠引脚号去辨认。

### 11.2.2 替代符号

```
同一元器件的不同显示方式：
- DeMorgan等效符号
- 简化符号
- 功能框图符号

创建方法：
1. 添加替代体定义
2. 绘制替代图形
3. 保持引脚编号一致
```

替代符号（De Morgan 等效）解决的是同一个器件换一种画法更易读的问题，典型场景是负逻辑：与门在低有效信号链里画成或非门形状，逻辑关系一眼就能对上。KiCad 符号编辑器里用 body style 选择器管理，每种风格单独画图形，引脚号和电气属性共用，切换只改变显示，不改变网表，PCB 也不受影响。代价是要维护两套图形，改引脚时要改两处，所以只在确实提升可读性时使用。另有一个容易混淆的功能是引脚的交替模式（alternate pin mode），它描述的是同一物理引脚在不同配置下承担不同功能，改变的是引脚名称与电气类型，和替代体的图形切换不是一回事，两者不要混用。

### 11.2.3 电源符号定制

```
自定义电源符号：
1. 创建新符号
2. 设置为电源符号类型
3. 定义默认网络名
4. 设计合适的图形

常用自定义电源：
+3V3, +1V8, +12V, -5V
VBAT, VBUS, VREF
DGND, AGND, PGND
```

电源符号本身是一个单引脚符号：引脚类型设为电源输入、引脚名隐藏，符号属性里勾选「定义为电源符号」。真正决定网络名的是 Value 字段——KiCad 用它的值作为网络名，所以 +3V3 的 Value 必须写成 +3V3，不能写成「3.3V电源」；同一网络的所有电源符号 Value 必须完全一致，差一个字符就会被当成两个网络。
模拟地、数字地、保护地要分开时，DGND、AGND、PGND 是三个网络，在单点用 0Ω 电阻或磁珠连到 PGND；如果三个符号都叫 GND，等于在图上直接短接，单点连接就失去意义。图形只影响可读性，不影响连接，但一个工程里最好让每种电源固定一种形状，读图时能靠轮廓快速分辨。

## 11.3 高级注释与文档

原理图不只给设计者自己看，它要经过评审、交给生产、附在交付文档里。图上写清楚参数依据和设计意图，能省掉后续大量口头确认。

### 11.3.1 设计参数标注

```
重要参数标注：
- 关键电压/电流值
- 计算公式
- 设计依据
- 调整说明

示例：
R1 = VREF × R2 / (VOUT - VREF)
     = 1.25V × 10k / (5V - 1.25V)
     = 3.33k → 选用3.3k
```

把公式写在图上，目的不是好看，而是让下一个改动这个电路的人知道 3.3k 是怎么来的。KiCad 的文本对象支持多行，推导过程可以直接放进原理图，导出 PDF 后跟着图纸一起走，不会像外部文档那样容易失联。标注位置放在对应电路旁边，不要集中堆在页面角落；文本不要压住导线和元件值，导出 PDF 前用高对比度模式或打印预览检查遮挡。公式里同时写出计算值和最终选用的标称值，并注明偏差（3.33k 选 3.3k，误差约 0.9%），评审时能直接判断是否落在容差内。分压、限流、滤波截止频率这类参数都值得这样标注，涉及 EMC 或安规的元件还应在文本里写明选型依据。

### 11.3.2 变量和参数

```
使用变量简化设计：
${PROJECT_NAME}  : 项目名称
${REVISION}      : 版本号
${DATE}          : 日期
${AUTHOR}        : 作者

自定义变量：
在项目设置中定义
用于标题栏和注释
```

变量分两类。内置变量由 KiCad 提供，标题栏、图纸模板和文本里都能引用，常用的有 ${TITLE}、${REVISION}、${ISSUE_DATE}、${COMPANY}、${PROJECTNAME} 等；自定义变量在项目设置里登记，键值对形式，适合放项目代号、版本阶段、负责人这类每次改版都要同步的信息。上面代码块里列出的 ${PROJECT_NAME}、${DATE}、${AUTHOR} 是示意写法，实际变量名以项目设置为准。写错变量名不会报错，只会原样输出，所以导出 PDF 后要扫一眼标题栏。变量只做文本替换，不参与 ERC，也不会因为变量没定义而阻止生成网表。

### 11.3.3 设计块和模板

```
创建可复用设计块：
1. 选择电路区域
2. 另存为设计块
3. 在其他项目中导入

模板使用：
1. 创建标准页面模板
2. 包含常用电路
3. 预设网络名和标签
```

设计块的用途是把已经验证过的电路（电源入口、晶振、调试接口、隔离电路）存成可复用单元。直接复制粘贴也能用，但粘贴进来的是新的位号和一份独立副本，改一处不会同步到另一处；设计块保留内部连接与网络名，重复使用时更容易比对差异。导入时要检查两类冲突：位号冲突由 KiCad 自动重新编号解决，网络名冲突不会——如果设计块内部用了全局标签，两次导入同名全局标签会把两处电路短接在一起，所以设计块内部尽量只用局部标签。
图纸模板管的是边框、标题栏和字段位置，属于文档资源；工程模板通常是一套配好页面、规则、字段名的工程副本，用来当新项目的起点。不要把电路塞进图纸模板，那会让模板变成隐式的电路库，换项目时很难清理。

## 11.4 BOM管理高级技巧

BOM 是设计到采购的接口。原理图里的每个字段，最后要么变成采购单上的一行，要么变成生产时的疑问；字段设计得好，BOM 可以直接交给采购，设计得差，每次下单都要人工核对。

### 11.4.1 字段配置

```
推荐BOM字段：
├── 基本字段
│   ├── Reference
│   ├── Value
│   ├── Footprint
│   └── Description
│
├── 采购字段
│   ├── Manufacturer
│   ├── MPN（制造商料号）
│   ├── Supplier
│   └── SPN（供应商料号）
│
└── 工程字段
    ├── Tolerance
    ├── Voltage Rating
    └── Power Rating
```

三类字段的用途不同。基本字段来自符号本身，KiCad 生成 BOM 时天然带出，可靠性最高；采购字段（Manufacturer、MPN、Supplier、SPN）是外部系统要的，最容易在改版时丢失，因为它们在符号库里往往没有默认值，靠人工逐个填；工程字段（容差、耐压、功率）是选型依据，评审时要看，替代料评估时也常用到。可行的做法是在符号库层面把常用字段的默认值配好，比在图上逐个补可靠；字段名要和 BOM 脚本、ERP 导入模板里的键完全一致，否则每次导出都要做一次映射。KiCad 本身不能强制某字段必填，但可以在 BOM 脚本里加校验：缺 MPN 直接报错退出，比悄悄合并成一行要好得多。

### 11.4.2 BOM导出脚本

```python
# 自定义BOM生成脚本示例
import csv

def generate_bom(components):
    # 按MPN合并相同元器件
    merged = {}
    for comp in components:
        mpn = comp['MPN']
        if mpn in merged:
            merged[mpn]['Qty'] += 1
            merged[mpn]['Refs'].append(comp['Reference'])
        else:
            merged[mpn] = {
                'MPN': mpn,
                'Qty': 1,
                'Refs': [comp['Reference']],
                'Value': comp['Value'],
                'Footprint': comp['Footprint']
            }
    
    return list(merged.values())
```

这段脚本只做一件事：把元件列表按 MPN 合并。输入 components 是字典列表，每条含 MPN、Reference、Value、Footprint；merged 以 MPN 为键，命中就把 Qty 加一并把位号追加到 Refs，未命中则新建记录并复制 Value 与 Footprint。有四处细节在真实项目里会出问题。第一，MPN 为空字符串时，所有没填料号的元件会被合并成一行，数量看着对、内容全错，合并前必须过滤或直接报错。
第二，输出顺序取决于输入顺序，采购习惯按位号或按 Value 排序，需要再排一次。第三，Refs 是 Python 列表，直接写进 CSV 会变成带方括号和引号的字符串，应在写行时用分号连接并排序。第四，Value 和 Footprint 取的是第一次出现的元件，同一 MPN 在不同位号上填了不同值会被静默吞掉，合并前应校验同 MPN 的这些字段是否一致。脚本前后还缺两段：前面解析 KiCad 导出的网表或字段表，后面按模板写 CSV。

### 11.4.3 与ERP系统集成

```
BOM导出格式：
- CSV（通用）
- XML（结构化）
- JSON（现代系统）

集成方式：
1. 导出标准格式BOM
2. 映射字段到ERP系统
3. 自动化导入流程
```

CSV 通用，但字段含义靠约定，列错位、编码（GBK 与 UTF-8）、小数点与千分位都是常见问题；XML 和 JSON 结构化，适合直接对接接口，缺点是人工打不开、排错成本高。字段映射表要落成文件放进版本库，例如 bom_mapping.json，写明源字段、目标字段、转换规则，别放在某个人的机器上。导入前做三步校验：料号能否在系统里查到、数量是否等于位号数、必填字段是否为空。批量导入失败时先取一行数据手工走一遍系统，确认是字段问题、编码问题还是系统侧问题，再回头改脚本。

## 11.5 版本控制与协作

原理图和 PCB 从 KiCad 6 起都是文本格式的 S-expression 工程文件，这意味着它们可以像代码一样放进 Git 管理。但「能 diff」和「diff 好看」是两件事，直接照搬代码仓库的工作流会遇到一些具体障碍。

### 11.5.1 Git工作流

```
推荐分支策略：
├── main          : 发布版本
├── develop       : 开发分支
└── feature/*     : 功能分支

提交规范：
feat: 新功能
fix: 修复问题
docs: 文档更新
refactor: 重构
style: 格式调整
```

工程文件是文本，diff 出来的差异却经常膨胀：保存时对象顺序调整、UUID 重新生成、时间戳更新，都会制造大量与设计无关的改动。缓解办法有几种。提交前先看 git diff --stat，确认改动规模与预期相符，只提交真正改过的图页。把备份目录和缓存排除掉，包括 *-backups/、_autosave-*、fp-info-cache 以及 .kicad_prl 这类保存界面状态的个人文件。
评审时用 git diff --word-diff 看行内变化，比整行替换清楚。分支策略照搬代码那套即可，但原理图和 PCB 不适合长时间并行改同一张图——S-expression 的合并基本只能手工做，减少冲突的根本办法还是按模块拆分文件。

### 11.5.2 变更管理

```
设计变更流程：
1. 创建变更请求
2. 评审变更影响
3. 更新版本号
4. 记录变更日志
5. 更新相关文档

版本号规范：
v1.0.0 - 初始发布
v1.1.0 - 功能更新
v1.0.1 - 问题修复
```

变更单要回答三个问题：改了什么、为什么改、影响了哪些位号和网络。只写「优化电源部分」等于没写。版本号三段式的含义要固定在团队里：主版本对应接口或封装变更（会动结构件和连接器），次版本对应功能增加，修订号对应纠错。版本号要写进标题栏的 REVISION 字段，这样导出的 PDF、BOM、装配图自动带上同一编号，避免图纸和实物对不上。每次变更后重跑 ERC 和 DRC，把结果报告归档到变更单里，评审时看的是当时的检查结果，不是「我记得跑过」。

### 11.5.3 设计审查

```
审查清单：
□ 电路功能正确性
□ 元器件选型合理
□ 封装分配正确
□ ERC检查通过
□ 命名规范符合
□ 注释完整
□ BOM准确
```

清单的价值在于防止「知道但忘了」。功能正确性靠对照需求逐条标注测试点，评审时逐项确认；选型合理性看降额——电容耐压、电阻功率、连接器电流、电感饱和电流，任何一项贴着额定值用都要写理由；封装分配在评审时必须对着数据手册或 3D 模型核对，封装错是打样报废最常见的原因之一。ERC 通过不等于设计正确，它只说明引脚连接在电气规则上自洽：两个输出短接、电源引脚未驱动会报，但去耦电容放错位置、分压比算错都不会报。命名规范、注释完整、BOM 准确属于交付质量，放在同一张清单里一起过。

## 11.6 与仿真集成

KiCad 内置 ngspice 仿真，原理图画完可以直接在同一个工程里跑直流、交流、瞬态分析。仿真能不能用起来，取决于原理图是否为仿真做了准备。

### 11.6.1 为仿真准备原理图

```
仿真准备步骤：
1. 为所有元器件分配SPICE模型
2. 添加仿真专用电源
3. 设置测量节点
4. 配置仿真参数
```

仿真前要给器件指定模型。无源器件大多有内置模型，晶体管、运放、稳压器需要对应的 SPICE 模型库。KiCad 的做法是在符号字段里填仿真参数：Sim.Device 指定器件类型（如 R、C、D、Q），Sim.Params 填器件参数，Sim.Model 填模型名，Sim.Pins 做引脚映射，具体字段名以所用版本为准。激励源要用仿真类型的电源符号，普通电源符号在仿真里没有激励定义，运行时会报节点没有直流通路或者波形全为零。
配置分析参数时，瞬态分析的步长和终止时间要与电路时间常数匹配：RC 时间常数 10ms 的电路，终止时间给 100ms 左右足够，步长取时间常数的百分之一量级；开关电源这类高频电路则要按开关频率设置，否则波形全是锯齿。仿真通过只说明结果在这套模型下成立，模型通常理想化，缺少寄生参数、温度漂移和器件离散性。

### 11.6.2 混合信号设计

```
处理数字和模拟混合：
- 分离数字和模拟地
- 使用正确的电源符号
- 注意信号完整性
- 添加适当的滤波
```

混合信号板的常规做法是分区而不分割：地平面保持完整，用布局把数字器件和模拟小信号器件分开，模拟部分的回流自然集中在自己的区域，再把模拟地和数字地在一点连接。原理图层面的对应工作是分开网络：AGND 与 DGND 两个电源符号、AVDD 与 DVDD 两路电源，各自去耦，最后在连接点用 0Ω 电阻或磁珠桥接。ADC 的模拟输入前加 RC 低通，电阻不宜过大，否则会与采样电容形成误差；数字信号跨越分区时要注意回流路径，必要时加串联电阻或缓冲。晶振、基准源、运放这类器件远离 DC-DC 的电感与开关节点，原理图上标注清楚敏感区域，布局时才有依据。

## 11.7 本章小结

本章介绍了原理图设计的进阶技术：

1. **复杂项目组织**：学会了大型项目的组织策略。
2. **高级符号技术**：掌握了多单元符号和替代符号。
3. **文档与注释**：了解了高级标注和模板使用。
4. **BOM管理**：学会了高级BOM配置和导出。
5. **版本控制**：掌握了Git工作流和变更管理。
6. **仿真集成**：了解了为仿真准备原理图的方法。

通过本章学习，读者可以处理更复杂的原理图设计任务。

把这些内容串起来看，原理图进阶的核心是让设计可被检查、可被复用、可被追溯：层次化让修改范围可控，符号技术让表达准确，注释和变量让文档自解释，BOM 字段让设计与采购对齐，版本控制让每次改动有据可查，仿真在打样前提供一次低成本验证。这些做法单独看都是小事，叠在一起才构成一个能交给别人接着做的工程。
