# 功能需求

把需求先说清楚，后面的技术选型和页面结构才有依据。这个 DEMO 的目标是做一个“一张图”式的 GeoServer 服务浏览与地图展示前端：左侧列出服务资源，右侧地图实时渲染选中的图层，并且能在界面上完成服务的增删改查。

需求分两块：地图展示和服务管理。两块共用一个资源树组件，树的节点来自 GeoServer 的 REST 接口，地图部分用 OpenLayers 按选中的服务类型加载。下面的拆解把验收标准也写进去，开发时可以逐条对照。


基于GeoServer现有功能，以地图展示和服务管理为核心，实现一张图DEMO。

## 1. 地图展示


**交互要求**：单击树节点，地图切换到对应的服务；勾选缓存和图层时不要闪白屏，尽量复用已有的地图实例，只替换数据源。缩放、平移、比例尺这些基础能力要有，至少支持滚轮缩放和拖拽平移。

**验收标准**：树里选一个 WMS 图层，地图在 2 秒内显示出图面；切换图层后旧图层被替换而不是叠加；地图中心点和缩放级别在切换前后基本保持，不要每次都跳回默认视图。

**技术边界**：WMS 是图片服务，前端只能整层出图；WFS 返回矢量要素，可以按要素做样式和交互。两种服务在树里要区分开，图标或后缀标出类型，避免用户点开 WFS 却以为是在看图片。


树状展示各种地图服务，并以地图的形式展示出来。

## 2. 服务管理

**列表与详情**：树按工作区（workspace）分组，每个节点下展示数据存储、图层、样式、图层组这几类资源。点击节点展开详情，详情面板给出名称、类型、CRS、边界框等关键属性。

**新增**：支持新建工作区、数据存储（PostGIS、Shapefile 等）、图层。表单字段与 GeoServer REST API 要求的参数保持一致，提交前做必填校验，提交后刷新树并定位到新节点。

**修改**：可修改工作区、数据存储的连接参数和图层的基本属性。修改数据存储时注意，GeoServer 的 PUT 请求是整体替换，字段要全量提交，只传改动字段会把其他配置清空。

**删除**：删除前弹确认框，说明会连带删除的内容（删工作区会删掉里面的所有数据存储和图层）。删除后同步刷新树和地图，正在显示的图层被删除时要把地图切回空状态。

**验收标准**：增删改都走 GeoServer REST 接口，刷新页面后状态保持；操作失败时有明确的错误提示，不出现“界面成功、服务端没改”的假成功；删除操作有二次确认，且不会因为误删导致地图组件报错。

## 3. 非功能需求

- 浏览器兼容：以 Chrome 和 Edge 最新版为准，Firefox 作为次要目标。
- 服务地址可配置：GeoServer 的地址和账号通过环境变量或配置文件注入，不写死在代码里。
- 错误处理：GeoServer 不可达时，树面板显示错误状态和重试按钮，不能整页白屏。
- 权限：DEMO 阶段用 GeoServer 的管理员账号，正式环境需要按角色控制可管理的资源范围。

## 4. 页面结构

整个界面走经典的三段式布局：顶部是标题栏和工具按钮，左侧是约 300px 宽的服务资源树，右侧是地图容器。详情和编辑表单以抽屉或弹窗形式从右侧滑出，不挤占地图空间。

```text
┌──────────────────────────────┐
│  标题栏 / 工具按钮            │
├─────────┬────────────────────┤
│ 服务树   │                    │
│         │      地图容器       │
│         │                    │
└─────────┴────────────────────┘
```

这个结构先定下来，后面所有组件都往这个骨架里填，避免边开发边改布局。


树状管理各种地图服务，包括添加、删除、修改、查看等操作。
