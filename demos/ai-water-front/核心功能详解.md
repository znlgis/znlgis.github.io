# AI 水务前端核心功能详解

## 一、地图系统

这个 demo 演示的是「地图 + 大模型 + 空间服务」这套组合的最小可用形态：用户在聊天面板里提问，Dify 应用返回文字，回答里如果带有几何数据，前端把它解析出来画在 OpenLayers 地图上；另一侧通过 GeoServer 拉取业务图层。读这套代码建议按数据流走一遍：Dify 客户端拿到响应，geoJsonService 从中提取几何，地图模块负责渲染，面板组件把这些串起来。下面按这个顺序逐个模块拆。

### 1. 地图组件（DemoMap.vue）

地图是整个界面的底座，所有空间数据最终都画在它上面。选择 OpenLayers 而不是 Leaflet 或 Cesium，原因在于它同时支持 2D 矢量、瓦片和多种投影，后续接 GeoServer 的 WMS/WFS 也更自然。

基于 OpenLayers 实现的地图组件：

```javascript
import Map from 'ol/Map'
import View from 'ol/View'
import TileLayer from 'ol/layer/Tile'
import OSM from 'ol/source/OSM'
import { fromLonLat } from 'ol/proj'

// 创建地图实例
const map = new Map({
  target: 'map',
  layers: [
    new TileLayer({
      source: new OSM(),
      properties: { name: 'OpenStreetMap', isBase: true }
    })
  ],
  view: new View({
    center: fromLonLat([116.4074, 39.9042]), // 北京坐标
    zoom: 10
  })
})
```

这段初始化代码做三件事：创建一个 OSM 底图瓦片图层，用 properties 打上 name 与 isBase 两个标记，再用 View 指定初始中心和缩放级别。自定义属性不影响渲染，但在图层面板里可以用 isBase 把底图和业务图层区分开，底图不允许删除，业务图层可以。fromLonLat 把经纬度转换成 Web 墨卡托坐标，因为 View 默认使用 EPSG:3857，直接传经纬度会把地图定位到错误的位置。OSM 公共瓦片有使用政策与限流，生产环境应换成自建或商业瓦片服务，并把瓦片地址做成配置项。

### 2. 地图实例管理（mapInstance.js）

全局地图实例管理：

```javascript
// mapInstance.js
export let mapInstance = null

export function setMap(map) {
  mapInstance = map
}

export function getMap() {
  return mapInstance
}
```

mapInstance.js 是一个模块级单例：变量用 let 声明，通过 setMap 赋值，其他模块 import 后拿到的是同一条引用。ES module 的导出绑定是实时的，所以 import 进来的 mapInstance 也能读到 setMap 之后的新值；但不要在别的模块里给它重新赋值，导入绑定在严格模式下只读，赋值会直接抛错。这种写法的代价是实例唯一，单页应用里路由切换或热更新时旧实例可能没有被销毁，控制台会出现地图容器已存在的报错。规范做法是组件挂载时创建、卸载时调用 map.setTarget(undefined) 释放，再清空引用。

使用方式：

```javascript
import { mapInstance, setMap } from './mapInstance.js'

// 设置地图实例
setMap(map)

// 在其他地方使用
const map = mapInstance
map.addLayer(newLayer)
```

### 3. 坐标转换

OpenLayers 默认使用 EPSG:3857 投影，需要进行坐标转换：

```javascript
import { fromLonLat, toLonLat } from 'ol/proj'

// 经纬度转投影坐标
const mapCoord = fromLonLat([116.4074, 39.9042])

// 投影坐标转经纬度
const lonLat = toLonLat([12914834, 4865942])
```

EPSG:3857 的单位是米，EPSG:4326 的单位是度。两套坐标混用在经纬度跨度大的时候非常明显，少做一次转换的表现是图层整体偏移，或者缩放到错误的级别上。fromLonLat 与 toLonLat 互逆，传参顺序都是 [经度, 纬度]，和常见的「纬度在前」写法相反。后端返回的 GeoJSON 本身就是 4326，交给 ol/format/GeoJSON 读取时指定 dataProjection 即可，不需要手工逐个点转换；手工转换容易在环的闭合点或坐标顺序上出错。

## 二、GeoJSON 服务

### 1. GeoJSON 数据提取

AI 返回的是自然语言，几何数据夹在结构化字段里。geoJsonService 承担两件事：把响应里的几何抽取成标准 GeoJSON，再把它交给地图渲染。中间任何一步失败，界面都应该退化成「只有文字」，而不是整块崩掉。

从 AI 响应中提取 GeoJSON 数据：

```javascript
// geoJsonService.js
export function extractGeoJsonFromResponse(responseText) {
  if (!responseText || typeof responseText !== 'string') return null

  try {
    let parsedData = JSON.parse(responseText)
    let geoJson = []
    
    if (parsedData?.data) {
      const content = parsedData.data
      const parsed = JSON.parse(content)
      const arr = Array.isArray(parsed) ? parsed : parsed != null ? [parsed] : []

      for (const item of arr) {
        const geom = item.geom
        geoJson.push(JSON.parse(geom))
      }
    }

    return geoJson
  } catch (error) {
    console.warn('提取GeoJSON时出错:', error)
    return null
  }
}
```

这段函数处理的是 Dify 应用自定义的输出结构：响应整体的 data 字段里是字符串，解析后得到数组或单个对象，每一项里的 geom 又是一段 JSON 字符串——后端为了让几何能塞进文本字段，做了两次序列化。因此解析要按三层来：先 parse 响应，取 data 再 parse，取 item.geom 再 parse，顺序错一层就拿不到数据。
函数对非字符串输入直接返回 null，所有解析异常由一个 try/catch 兜住，只打一条 warn，这是处理 AI 输出的稳妥做法：一条坏消息不应该影响整个对话。排查时值得在 catch 里同时打出 error 和原文前若干字符，否则「没有数据」和「格式变了」两种情况看起来一样。单条响应通常只有几 KB，性能不用特别处理，但不要对累积的流式文本反复调用这个函数。

### 2. 在地图上显示 GeoJSON

```javascript
import VectorLayer from 'ol/layer/Vector'
import VectorSource from 'ol/source/Vector'
import GeoJSON from 'ol/format/GeoJSON'
import { Style, Stroke, Fill, Circle } from 'ol/style'

export function displayGeoJsonOnMap(geoJsonData) {
  if (!geoJsonData || !mapInstance) {
    console.warn('无法显示GeoJSON: 缺少数据或地图实例')
    return null
  }

  // 标准化为 FeatureCollection
  const featureCollection = normalizeToFeatureCollection(geoJsonData)
  
  // 创建矢量数据源
  const vectorSource = new VectorSource({
    features: new GeoJSON().readFeatures(featureCollection, {
      featureProjection: 'EPSG:3857',
      dataProjection: 'EPSG:4326'
    })
  })

  // 创建矢量图层
  const vectorLayer = new VectorLayer({
    source: vectorSource,
    style: createHighlightStyle(),
    properties: { 
      name: 'geojson-highlight',
      isGeoJsonLayer: true,
      timestamp: Date.now()
    }
  })

  // 添加到地图
  mapInstance.addLayer(vectorLayer)

  // 添加闪烁动画
  addBlinkingAnimation(vectorLayer)

  // 调整视图
  fitViewToGeoJson(vectorSource)

  return vectorLayer
}
```

displayGeoJsonOnMap 把数据变成图层，分四步。第一步标准化成 FeatureCollection，兼容后端返回单个 Feature、单个几何或数组的情况（normalizeToFeatureCollection 的职责就是这些）。第二步用 ol/format/GeoJSON 读要素，同时指定 dataProjection 为 EPSG:4326、featureProjection 为 EPSG:3857，这一步决定了数据会不会画错位置。
第三步建矢量源和矢量图层，样式用 createHighlightStyle()，并写入三个自定义属性：name 供图层面板显示，isGeoJsonLayer 供后续批量清理，timestamp 供闪烁动画计时。第四步把图层加到地图、启动闪烁、把视图调整到数据范围。mapInstance 为空时函数直接返回 null，调用方要判断返回值；这里样式传的是 Style 实例，所有要素共用一套，如果要按属性区分颜色，应改传一个接收 feature 的函数。

### 3. 高亮样式

```javascript
function createHighlightStyle() {
  return new Style({
    stroke: new Stroke({
      color: '#ff4444',
      width: 3,
      lineDash: [5, 5]
    }),
    fill: new Fill({
      color: 'rgba(255, 68, 68, 0.2)'
    }),
    image: new Circle({
      radius: 8,
      stroke: new Stroke({
        color: '#ff4444',
        width: 3
      }),
      fill: new Fill({
        color: 'rgba(255, 68, 68, 0.3)'
      })
    })
  })
}
```

样式由三部分组成：Stroke 控制轮廓，红色、3px、5/5 虚线；Fill 控制面填充，同色两成透明度；image 控制点要素，半径 8 的圆并带描边和半透明填充。虚线只对线和面边界生效，点要素必须通过 image 指定。红色在 OSM 底图上对比度高，半透明填充又不会完全盖掉底图信息，适合「指出这里」这类临时高亮。同时高亮多条数据时建议换不同色相，全红会让用户分不清哪些是本次查询结果、哪些是上一次留下的。

### 4. 闪烁动画效果

```javascript
function addBlinkingAnimation(layer) {
  let opacity = 1
  let direction = -0.1
  
  const animate = () => {
    opacity += direction
    if (opacity <= 0.3) {
      opacity = 0.3
      direction = 0.1
    } else if (opacity >= 1) {
      opacity = 1
      direction = -0.1
    }
    
    layer.setOpacity(opacity)
    
    // 持续闪烁5秒
    if (Date.now() - layer.get('timestamp') < 5000) {
      requestAnimationFrame(animate)
    } else {
      layer.setOpacity(1)
    }
  }
  
  requestAnimationFrame(animate)
}
```

动画用一个 requestAnimationFrame 循环逐帧改图层透明度，在 1 与 0.3 之间往返，5 秒后恢复到 1。方向变量 direction 负责在边界处反向，避免透明度越界。这段实现有两个值得注意的地方：每帧修改 opacity 会触发整个图层重绘，要素数量大时开销明显，只适合少量高亮；循环的终止条件只看时间戳，没有检查图层是否还在图上，如果用户在 5 秒内清除图层或切换页面，动画回调仍会继续跑。
严谨的写法是在回调里判断 layer.getMap() 是否为空，或者把 requestAnimationFrame 的句柄存下来，在清理图层时 cancelAnimationFrame。

### 5. 清除 GeoJSON 图层

```javascript
export function clearGeoJsonLayers() {
  if (!mapInstance) return

  const layersToRemove = []
  mapInstance.getLayers().forEach(layer => {
    if (layer.get('isGeoJsonLayer')) {
      layersToRemove.push(layer)
    }
  })

  layersToRemove.forEach(layer => {
    mapInstance.removeLayer(layer)
  })
}
```

清理时先把命中的图层收集到数组，再统一 removeLayer，不能边遍历边删——OpenLayers 的图层集合在遍历过程中被修改会跳过元素，留下个别图层删不掉。判断依据用自定义属性 isGeoJsonLayer 而不是图层名称，名称可能被改动，属性是这套代码自己写入的标记，语义更稳定。如果同时要停掉闪烁动画，还需要在这里取消对应的 rAF 回调，否则会出现已移除图层仍在被修改透明度的现象。

## 三、Dify AI 客户端

Dify 是这套 demo 的后端 AI 应用平台，前端通过它的 chat-messages 接口对话。这个客户端封装了两件事：把回调式的调用包装成一组事件回调，以及处理流式响应。参数基本对应 Dify 的接口字段，理解字段含义比记函数签名重要。

### 1. 发送聊天消息

支持流式和普通两种响应模式：

```javascript
// difyClient.js
export async function sendChatMessage(query, opt = {}) {
  const {
    onMessage = () => {},        // 流式增量文本回调
    onCompleted = () => {},      // 完成回调
    onError = () => {},          // 错误回调
    onGeoJsonDetected = () => {},// GeoJSON 检测回调
    abortSignal,                 // 取消信号
    inputs = {},                 // 自定义变量
    stream = true,               // 是否使用流式
    user = 'web-user'            // 用户标识
  } = opt

  const url = BASE_URL + '/v1/chat-messages'
  const body = {
    inputs,
    query,
    response_mode: stream ? 'streaming' : 'blocking',
    user
  }

  // 流式处理
  if (stream) {
    const resp = await fetch(url, {
      method: 'POST',
      headers: {
        'Authorization': `Bearer ${API_KEY}`,
        'Content-Type': 'application/json'
      },
      body: JSON.stringify(body),
      signal: abortSignal
    })
    
    const reader = resp.body.getReader()
    const decoder = new TextDecoder('utf-8')
    let buffer = ''
    let fullResponseText = ''
    
    while (true) {
      const { value, done } = await reader.read()
      if (done) break
      buffer += decoder.decode(value, { stream: true })
      
      // SSE 解析
      // ...处理流式数据
    }
  }
}
```

参数逐项看：query 是用户问题；inputs 对应 Dify 应用里定义的自定义变量，用来传地图当前范围、选中图层这类上下文；user 是终端用户标识，Dify 用它区分会话与统计，同一用户应保持稳定；response_mode 在 streaming 与 blocking 之间切换，流式适合聊天界面，非流式适合只要最终结果的场景。stream 为真时走 fetch 加 ReadableStream，需要自己解析 SSE：服务端按行推送 data: {...} 事件，一个事件可能被拆在两个 chunk 里，所以要用 buffer 累积、按行切分、只处理完整行，残缺的尾部留到下一次 read 再拼。
代码里 SSE 解析部分省略了，这是实际接入时最容易出错的地方。onMessage 收到增量文本，onCompleted 在流结束时调用，onError 处理网络错误和接口错误码，onGeoJsonDetected 是这套 demo 自己加的扩展：文本累积到一定程度后尝试提取几何，命中就回调给地图。

### 2. 使用示例

```javascript
import { sendChatMessage } from './services/difyClient'

// 发送消息
sendChatMessage('查询北京市水系', {
  onMessage: (chunk) => {
    // 处理增量文本
    console.log('收到:', chunk)
  },
  onCompleted: () => {
    console.log('完成')
  },
  onError: (err) => {
    console.error('错误:', err)
  },
  onGeoJsonDetected: (geoJson) => {
    // 自动在地图上显示
    displayGeoJsonOnMap(geoJson)
  }
})
```

调用方式把四个回调一次性传进去：增量文本用于刷新气泡内容，完成回调用于结束「正在输入」状态，错误回调用于提示并允许重试，几何检测回调直接调用地图模块的显示函数。回调式接口的好处是组件里不用写一长串 Promise 链，坏处是回调里抛出的异常会中断后续处理，所以每个回调内部应该自己 try/catch，尤其是地图渲染——渲染失败不应该让已经拿到的文字消失。

### 3. 取消请求

```javascript
const controller = new AbortController()

sendChatMessage('查询...', {
  abortSignal: controller.signal,
  // ...其他选项
})

// 取消请求
controller.abort()
```

AbortController 传给 fetch 的 signal，调用 abort() 之后 fetch 会以 AbortError 拒绝，正在读取的流也会中断。代码里要区分两种失败：用户主动取消属于正常流程，不应该弹错误提示；网络或服务端错误才需要提示，判断依据是 error.name === 'AbortError'。每个请求配一个独立的 controller，不要复用，取消过的 signal 也不能再用。

## 四、GeoServer 集成

GeoServer 负责发布和管理空间数据服务。前端不直接操作数据库，而是通过它的 REST API 读服务状态、图层清单和图层信息，地图上的 WMS/WFS 请求也走同一台服务器。

### 1. REST API 封装

```javascript
// GeoServerRestApi.js
import axios from 'axios'

const geoserverApi = axios.create({
  baseURL: '/geoserver',
  timeout: 10000
})

// 获取服务信息
export async function getAbout() {
  const response = await geoserverApi.get('/rest/about/status.json')
  return response.data
}

// 获取图层列表
export async function getLayers() {
  const response = await geoserverApi.get('/rest/layers.json')
  return response.data
}
```

这里用 axios 建了一个实例，baseURL 设为 /geoserver，所有请求走同源路径，由开发服务器或网关代理到实际的 GeoServer。直接好处是避开跨域：GeoServer 默认不开启 CORS，前端直连会被浏览器拦下。超时给 10 秒，REST 接口在图层重载时偶尔会变慢，超时太短会误报。getAbout 读 /rest/about/status.json 做健康检查，图层列表读 /rest/layers.json。生产环境的 REST 接口通常需要认证，凭据不能写在前端代码里，应通过后端代理转发并在代理层加认证。

### 2. 图层管理

```javascript
// Layers.js
export async function getLayerList() {
  const data = await getLayers()
  return data.layers?.layer || []
}

export async function getLayerInfo(layerName) {
  const response = await geoserverApi.get(`/rest/layers/${layerName}.json`)
  return response.data
}
```

getLayers 返回的 JSON 是分层的，真正的图层数组在 data.layers.layer 里，直接用 data.layers 遍历会拿到对象而不是数组，这是 GeoServer REST 的固定结构。列表接口只给图层的基本描述，取单个图层的详细信息要再请求 /rest/layers/{name}.json。图层名可能带命名空间前缀（workspace:layer），拼 URL 时要做 encodeURIComponent，否则冒号会被误解析。图层管理与地图显示是两条路径：列表用于面板展示与开关，真正的瓦片请求由 OpenLayers 的 WMS 源发起，两者通过图层名对应。

## 五、面板组件

界面由三个面板组成：左侧图层列表，右侧 AI 对话，中间地图。面板之间通过地图实例与事件通信，不直接互相引用，这样任何一个面板都可以单独调试。

### 1. 图层面板（LayerPanel.vue）

功能：
- 显示可用图层列表
- 图层可见性控制
- 图层添加/移除

图层面板的数据来源有两处：OSM 底图这类创建时就带 isBase 标记的图层，以及从 GeoServer 拉取的图层列表。面板要做的不只是显示，还要维护可见性状态——切换勾选时调用图层的 setVisible，而不是删除再加回，后者会触发重新请求瓦片。图层的增删统一走 mapInstance，保证面板状态与地图状态一致。

### 2. AI 助手面板（AIAssistantPanel.vue）

功能：
- 聊天消息输入
- 流式响应显示
- 历史消息管理
- GeoJSON 自动识别

AI 面板管三件事：输入与发送、流式消息的渲染、历史消息。发送时把当前地图状态作为 inputs 传过去，模型回答里如果包含几何，onGeoJsonDetected 会触发地图高亮。历史消息只保存在前端内存里，刷新即丢失；需要持久化的话，应该在发送时把消息与会话 ID 一起存到后端，而不是只依赖 localStorage。渲染流式文本时不要每来一个字符就重建整个消息列表，按消息对象增量更新节点，否则长对话会明显卡顿。

### 3. 可调整布局

```javascript
// App.vue 中的布局调整逻辑
const startVDrag = (e) => {
  isDraggingV.value = true
  startY.value = e.clientY
  startHeight.value = topHeight.value
  document.body.classList.add('resizing-v')
}

const startHDrag = (e) => {
  isDraggingH.value = true
  startX.value = e.clientX
  startLeftWidth.value = leftWidth.value
  document.body.classList.add('resizing-h')
}
```

布局调整用鼠标按下、移动、松开三个事件实现：按下时记录起始坐标与当前尺寸，移动时按差值更新面板宽高，松开时结束拖拽。拖拽期间给 body 加 resizing-v 或 resizing-h 类，用 CSS 关掉文本选中和光标变化，否则拖动经过文字时会出现蓝色选区。松开时必须移除这两个类，漏掉的话整个页面之后都不能正常选中文本。

布局状态自动保存：

```javascript
// 保存到 localStorage
localStorage.setItem('layerPanelHeight', String(topHeight.value))
localStorage.setItem('leftPanelWidth', String(leftWidth.value))

// 读取保存的状态
const storedHeight = parseInt(localStorage.getItem('layerPanelHeight') || '0', 10)
const storedWidth = parseInt(localStorage.getItem('leftPanelWidth') || '0', 10)
```

面板尺寸存在 localStorage 里，刷新后恢复。三个细节：parseInt 之后要判断 NaN，第一次访问时键不存在，直接参与布局计算会得到 NaN；恢复值要限制在合理范围，比如最小 200px、最大不超过视口，否则用户换到小屏幕后可能打不开面板；localStorage 按源隔离，换端口或域名就失效，开发环境里不要把它当持久配置。

## 六、开发工具

调试空间数据时，等 AI 返回一段带几何的回答太慢。demo 在开发模式下挂了几个全局函数，可以在浏览器控制台直接构造数据、验证渲染链路。

### GeoJSON 测试工具

开发模式下自动加载的测试工具：

```javascript
// geoJsonTestUtils.js
// 在控制台可用的测试方法

// 测试 GeoJSON 渲染
window.testGeoJson = (geoJson) => {
  displayGeoJsonOnMap(geoJson)
}

// 清除测试图层
window.clearGeoJsonLayers = () => {
  clearGeoJsonLayers()
}

// 测试数据
window.testData = {
  point: {
    type: 'Point',
    coordinates: [116.4074, 39.9042]
  },
  polygon: {
    type: 'Polygon',
    coordinates: [[[116.3, 39.8], [116.5, 39.8], [116.5, 40.0], [116.3, 40.0], [116.3, 39.8]]]
  }
}
```

这些函数挂在 window 上，只在开发模式加载：生产构建时应先判断 import.meta.env.DEV 再挂载，否则任何页面脚本都能调用它们，也会污染全局命名空间。testGeoJson 直接调用显示函数，用来验证投影、样式、视图调整这几步是否正常；testData.point 和 testData.polygon 都是 4326 经纬度，正好覆盖坐标转换路径。除了内置样例，也可以把后端返回的原始响应粘进控制台，先跑 extractGeoJsonFromResponse 看解析结果，再交给 displayGeoJsonOnMap，把「解析错」和「渲染错」分开定位。

使用方式：

```javascript
// 浏览器控制台
window.testGeoJson(window.testData.point)
window.testGeoJson(window.testData.polygon)
window.clearGeoJsonLayers()
```
