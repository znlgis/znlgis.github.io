# OGU4J概述与入门

## 前言

在GIS开发领域，处理空间数据是一项核心任务。不同的数据源（Shapefile、GeoJSON、PostGIS、FileGDB等）有着不同的API和数据模型，这给开发者带来了额外的学习成本和代码维护负担。

OGU4J（OpenGIS Utils for Java）是一个专注于解决这些问题的Java GIS工具库。它的核心思想是：**通过统一的图层模型，屏蔽底层GIS库的差异，让开发者专注于业务逻辑。**

## 核心设计思想

### 问题背景

传统GIS开发中，读取不同格式的数据需要使用不同的API：

```java
// 读取Shapefile - 使用GeoTools
ShapefileDataStore store = new ShapefileDataStore(file.toURI().toURL());
SimpleFeatureSource source = store.getFeatureSource();

// 读取GeoJSON - 使用FeatureJSON
FeatureJSON fjson = new FeatureJSON();
FeatureCollection fc = fjson.readFeatureCollection(inputStream);

// 读取PostGIS - 使用JDBCDataStore
Map<String, Object> params = new HashMap<>();
params.put("dbtype", "postgis");
// ... 更多配置
DataStore dataStore = DataStoreFinder.getDataStore(params);
```

这种方式导致：
- 代码冗余，每种格式都需要不同的处理逻辑
- 数据模型不统一，难以复用业务代码
- 切换数据源需要大量代码修改

### 解决方案：统一图层模型

OGU4J提供了一套简洁的统一模型：

| 类名 | 说明 | 对应概念 |
|------|------|----------|
| OguLayer | 图层 | 一个数据表或一个文件 |
| OguFeature | 要素 | 一条记录 |
| OguField | 字段 | 字段定义 |
| OguFieldValue | 字段值 | 属性值 |
| OguCoordinate | 坐标 | 坐标点 |

使用统一模型后，读取不同格式的代码变得一致：

```java
// 读取Shapefile
OguLayer layer1 = SimpleLayerConverter.fromShapefile(shpPath, null, null, GisEngineType.GEOTOOLS);

// 读取GeoJSON
OguLayer layer2 = SimpleLayerConverter.fromGeoJSON(geojsonPath, GisEngineType.GEOTOOLS);

// 读取PostGIS
OguLayer layer3 = SimpleLayerConverter.fromPostGIS(dbConn, "tableName", null, null, GisEngineType.GEOTOOLS);

// 读取后，处理逻辑完全相同
for (OguFeature feature : layer.getFeatures()) {
    String wkt = feature.getWkt();
    Object value = feature.getValue("fieldName");
    // 业务处理...
}
```

## 统一图层模型详解

### OguLayer - 图层

图层是GIS数据的基本组织单位，包含：

```java
public class OguLayer {
    private String ywName;        // 业务名称（英文）
    private String zwName;        // 中文名称
    private Integer wkid;         // 坐标系代码（如4490表示CGCS2000）
    private Double tolerance;     // 坐标容差
    private GeometryType geometryType;  // 几何类型
    private List<OguField> fields;      // 字段列表
    private List<OguFeature> features;  // 要素列表
}
```

**关键设计点**：
- 使用WKID（Well-Known ID）表示坐标系，简化坐标系管理
- 几何以WKT格式存储，保证跨平台兼容性
- 提供验证方法确保数据完整性

### OguFeature - 要素

要素是图层中的一条记录：

```java
public class OguFeature {
    private String wfId;          // 要素ID
    private String wkt;           // 几何数据（WKT格式）
    private List<OguFieldValue> fieldValues;  // 属性值列表
}
```

**实用方法**：

```java
OguFeature feature = layer.getFeatures().get(0);

// 获取几何WKT
String wkt = feature.getWkt();

// 获取属性值
Object value = feature.getValue("fieldName");

// 获取类型安全的属性值
OguFieldValue fv = feature.getAttribute("fieldName");
String strValue = fv.getStringValue();
Integer intValue = fv.getIntValue();
Double doubleValue = fv.getDoubleValue();

// 设置属性值
feature.setValue("fieldName", newValue);
```

### OguField - 字段定义

字段定义描述属性的元数据：

```java
public class OguField {
    private String ywName;        // 字段名（英文）
    private String zwName;        // 字段别名（中文）
    private FieldDataType dataType;  // 数据类型
}
```

**支持的数据类型**：

| 类型 | 说明 |
|------|------|
| STRING | 字符串 |
| INTEGER | 整数 |
| LONG | 长整数 |
| DOUBLE | 双精度浮点数 |
| DATE | 日期 |
| BOOLEAN | 布尔值 |

## 快速入门

### 基本操作流程

```java
// 1. 从文件或数据库读取图层
OguLayer layer = SimpleLayerConverter.fromShapefile(
    "data/parcels.shp", 
    null,   // 属性过滤条件
    null,   // 空间过滤条件
    GisEngineType.GEOTOOLS
);

// 2. 验证图层数据
layer.validate();

// 3. 遍历处理要素
for (OguFeature feature : layer.getFeatures()) {
    // 获取几何
    String wkt = feature.getWkt();
    Geometry geom = GeometryConverter.wkt2Geometry(wkt);
    
    // 获取属性
    String name = feature.getAttribute("NAME").getStringValue();
    Double area = feature.getAttribute("AREA").getDoubleValue();
    
    // 业务处理...
    System.out.println(name + ": " + area + "平方米");
}

// 4. 输出到其他格式
SimpleLayerConverter.toGeoJSON(layer, "output/parcels.geojson", GisEngineType.GEOTOOLS);
```

### 要素过滤

使用函数式接口进行要素过滤：

```java
// 过滤特定类型的要素
List<OguFeature> filtered = layer.filter(feature ->
    "住宅".equals(feature.getValue("LAND_TYPE")));

// 过滤面积大于1000的要素
List<OguFeature> largeParcels = layer.filter(feature -> {
    Double area = feature.getAttribute("AREA").getDoubleValue();
    return area != null && area > 1000;
});
```

### JSON序列化

图层可以直接转换为JSON：

```java
// 转换为JSON字符串
String json = layer.toJSON();

// 从JSON字符串创建
OguLayer restored = OguLayer.fromJSON(json);
```

## 双引擎架构

OGU4J支持两种GIS引擎，可根据需求灵活切换：

### GeoTools引擎

GeoTools是开源Java GIS工具包，特点：
- 纯Java实现，跨平台
- 社区活跃，文档丰富
- 支持OGC标准
- 适合大多数常规场景

```java
// 使用GeoTools引擎
OguLayer layer = SimpleLayerConverter.fromShapefile(
    shpPath, null, null, GisEngineType.GEOTOOLS);
```

### GDAL/OGR引擎

GDAL是最强大的地理数据抽象库，特点：
- 支持几乎所有GIS格式
- 高性能，底层C++实现
- 对FileGDB等专有格式支持更好
- 需要安装本地库

```java
// 使用GDAL引擎
OguLayer layer = SimpleLayerConverter.fromFileGDB(
    gdbPath, "layerName", null, null, GisEngineType.GDAL);
```

### 引擎选择建议

| 场景 | 推荐引擎 |
|------|----------|
| 通用开发 | GeoTools |
| FileGDB处理 | GDAL |
| 跨平台部署 | GeoTools |
| 最佳性能 | GDAL |
| 格式兼容性 | GDAL |

## 数据处理思路

使用OGU4J处理GIS数据的典型流程：

```
数据输入 → 统一模型 → 数据处理 → 统一模型 → 数据输出
   ↓           ↓           ↓           ↓           ↓
Shapefile   OguLayer   业务逻辑    OguLayer   GeoJSON
GeoJSON       ↓        空间分析      ↓        PostGIS
PostGIS    OguFeature  坐标转换   OguFeature  Shapefile
FileGDB                属性计算                FileGDB
```

### 典型应用场景

1. **格式转换**：Shapefile → GeoJSON → PostGIS
2. **数据整合**：多源数据统一入库
3. **空间分析**：叠加分析、缓冲区分析
4. **坐标转换**：不同坐标系间的数据统一
5. **批量处理**：遍历处理大量要素

| 依赖 | 版本 | 用途 |
|------|------|------|
| JTS | 1.20.0 | 几何对象模型和空间操作 |
| GeoTools | 34.1 | 数据读写和坐标系支持 |
| ESRI Geometry API | 2.2.4 | 高性能几何运算 |
| GDAL | 3.11.0 | FileGDB等格式支持（可选） |

## 小结

本章介绍了OGU4J的核心概念：

1. **统一图层模型**：OguLayer、OguFeature、OguField等类屏蔽了底层差异
2. **双引擎架构**：GeoTools和GDAL可根据需求灵活选择
3. **WKT作为几何载体**：保证跨平台兼容性
4. **简洁的API**：读取、处理、输出流程清晰
