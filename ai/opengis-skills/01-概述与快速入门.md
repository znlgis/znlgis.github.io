# 第一章：OpenGIS-Skills 概述与快速入门

OpenGIS-Skills 是一个面向 AI 编程助手（Claude Code、Cursor、Cline、VS Code Copilot Chat、DeepSeek、OpenCode 等）的**开源技能集（Skill Collection）**。它不提供可执行代码，不依赖任何特定的 IDE 或平台，只通过一系列结构化的 `SKILL.md` 文件，为 AI 注入 GIS、CAD、C#、AI、IoT、3D 六大领域的专业知识，让 AI 更准确地编写代码、调用 API、排查错误。

这个仓库源于真实项目中的反复踩坑——GDAL 命令参数记不住、CesiumJS 的 API 版本总对不上、FreeCAD 的 Python API 每次都要重新翻阅上百页文档。与其每次都把零散的提示词粘贴进聊天框，不如把它们沉淀成一套结构化的、可版本管理的、被 AI 工具原生支持的技能文件。这正是 OpenGIS-Skills 要做的事情。

本教程基于 [znlgis/opengis-skills](https://github.com/znlgis/opengis-skills) 仓库当前版本（截至 2026 年中，67 个技能文件）全面分析整理，面向中文读者系统讲解设计理念、三层索引架构、SKILL.md 编写规范、与主流 AI 工具的集成方式，以及六大领域每个技能的深度解析。

---

## 1.1 一句话理解

> **OpenGIS-Skills 是一套用 Markdown 编写的"AI 专业技能教材"——你把它放进项目里，AI 编程助手就会自动习得 GIS/CAD/C#/AI/IoT/3D 六大领域的专业知识。**

它不改变 AI 工具本身，也不重新训练模型，而是利用当今主流 AI 编程助手都支持的 **Skill/Agent Skill/Rules/Instructions** 机制，在对话上下文中按需注入领域知识。你可以把它理解为：

- 一本给 AI 看的"GIS 开发速查手册"
- 一份可版本管理、可团队共享的"AI 提示词库"
- 一套覆盖六大领域的"专业开发知识图谱"

因为知识是以纯文本 Markdown 文件形式存在的，它天然具备可读性、可维护性、可贡献性——人类开发者可以直接阅读和审校内容，AI 工具可以高效解析和执行其中的指令。

## 1.2 它解决什么问题

传统 AI 辅助编程在专业领域开发中面临四个核心痛点，OpenGIS-Skills 针对性地给出了解法。

### 痛点一：AI 不懂专业领域

通用大语言模型对 Web 开发、Python 脚本等常见场景表现尚可，但遇到专业领域库就直接暴露短板：

- 让 AI 写 GDAL 的矢量数据投影转换代码，它可能编造一个不存在的 `gdal.ProjectVector()` 函数
- 让 AI 调用 CesiumJS 的 3D Tiles 加载 API，它给出的方法签名可能来自三年前的旧版本文档
- 让 AI 操作 FreeCAD 的 PartDesign 工作台，它可能混淆 Part 模块和 PartDesign 模块的 API

**OpenGIS-Skills 的解法：** 每个技能文件都包含该工具的**真实 API 签名、正确用法示例、常见错误排查**——这些内容基于官方文档实地核对，不是从 AI 训练数据中"猜测"出来的。AI 加载技能后，相当于有了一份准确的参考手册。

### 痛点二：上下文爆炸

把整个 GDAL 官方文档（几千页）或 CesiumJS API 参考塞进提示词里，既不现实也不经济——当前主流模型的上下文窗口虽然越来越大，但长上下文中信息检索的准确性会下降，Token 成本也直线上升。

**OpenGIS-Skills 的解法：** 采用三层索引架构，AI 先读全局索引导航、再按需加载具体技能，每次只注入当前任务真正需要的那几 KB 知识。一个典型的 GDAL 重投影任务，AI 只需要加载 `gis/gdal/SKILL.md`（约 10-20 KB），而不是整个 GIS 知识库。

### 痛点三：知识无法复用

团队中每个开发者每次遇到同样的 GDAL 命令拼写错误、同样的 CesiumJS API 版本问题，都要花费时间重新向 AI 解释、重新调试、重新验证。张三踩过的坑李四还要再踩一遍。

**OpenGIS-Skills 的解法：** 技能文件是可提交进 Git 的文本资产。一次编写，全团队（甚至全社区）永久复用。当 GDAL 升级到新版本，只需更新一个技能文件，所有开发者的 AI 助手同步获得最新知识。

### 痛点四：信息过时

AI 大模型的训练数据存在截止日期，而 GIS 和 CAD 工具库的版本迭代速度非常快——GDAL 每半年一个大版本、CesiumJS 每月都有新发布、FreeCAD 的 Python API 随主版本不断变化。

**OpenGIS-Skills 的解法：** 技能文件是手写的内容，由社区维护者根据最新版本文档持续更新。当工具的 API 发生变化时，技能文件的更新速度远快于模型重训练周期。

## 1.3 核心特性

### 3.1 67 个技能，覆盖六大领域

OpenGIS-Skills 当前包含 67 个技能文件（截至 2026 年中），横跨 GIS、CAD、C#、AI、IoT、3D 六个专业领域，外加一个 Others 分类收纳通用开发工具。每个技能都包含该工具的核心理念、常用 API、代码示例和典型错误排查。

这种广度意味着：一个同时做 GIS 后端（GDAL/GeoServer）和前端（CesiumJS/OpenLayers）的全栈 GIS 开发者，只需要这一套技能集就能覆盖日常工作 80% 以上的专业 API 查询需求。

### 3.2 三层索引架构：全局入口 → 分类索引 → 项目技能

这是 OpenGIS-Skills 最核心的设计思想，也是它区别于普通"提示词合集"的关键所在：

- **第一层：根 SKILL.md**——AI 加载后获得全部 67 个技能的全局索引，包括每个技能的名称、简介、适用场景、文件路径。这一层约 5-10 KB，足够 AI 完成后续导航。
- **第二层：分类索引**——`gis/SKILL.md`、`cad/SKILL.md` 等六个分类概述文件，详细描述该领域下所有技能的功能侧重、彼此关系、推荐组合。
- **第三层：项目技能**——具体的工具技能文件，如 `gis/gdal/SKILL.md`，包含 API 签名、代码示例、CLI 命令模板、常见错误和解决方案。

这个设计让 AI 实现了"先看目录、再翻章节"的高效信息获取模式，避免了每次对话都把整个知识库灌进上下文的低效做法。

### 3.3 统一的 SKILL.md 规范

所有技能文件遵循统一的格式规范：

- **YAML frontmatter**：声明技能名称、分类、标签、适用 AI 工具列表等元数据，供 AI 工具做索引和搜索
- **结构化正文**：包含概述、核心 API、代码示例（含 Python/JS/C#/bash 多语言）、常见错误、参考链接
- **中文为主 + 代码示例丰富**：面向国内开发者，正文以中文撰写，但 API 签名、命令参数等关键信息保留英文原文以避免歧义

### 3.4 兼容主流 AI 工具

OpenGIS-Skills 不与任何特定工具绑定。目前已验证兼容的 AI 编程助手包括：

- **Claude Code**（Anthropic）：通过 `@path/to/SKILL.md` 引用技能文件
- **Cursor**：将技能文件目录添加到项目 Rules 或作为上下文文件
- **Cline**（VS Code 插件）：通过 `.clinerules` 或直接引用技能文件
- **VS Code Copilot Chat**：通过 `#file:path/to/SKILL.md` 引用
- **DeepSeek 系列**：作为 `.deepseek/rules/` 目录下的规则文件加载
- **OpenCode**：通过 Skill 机制或 `AGENTS.md` 引用
- **Pi Agent**、**OpenClaw**、**Hermes Agent** 等其他 AI 编码代理

无论你用的哪款工具，只需一种方式把技能文件内容注入 AI 的上下文即可——具体方法在第四章《AI 工具集成指南》中逐一详解。

### 3.5 MIT 开源许可证

OpenGIS-Skills 以 MIT 许可证开源，意味着你可以：

- 自由使用、修改、分发这些技能文件
- 将其集成到商业产品或内部工具中
- Fork 后衍生出面向特定行业（如测绘、规划、BIM）的定制版本

社区贡献通过 Pull Request 进行，所有贡献者保留署名权。详见第十二章《贡献指南与社区》。

## 1.4 30 秒快速体验

以下是最简单的上手流程，不涉及任何安装或配置——前提是你已经有一个支持 Skill 机制的 AI 编程助手（以 Claude Code 为例）。

### 第一步：克隆仓库

```bash
git clone https://github.com/znlgis/opengis-skills.git
cd opengis-skills
```

### 第二步：在 AI 助手中加载技能

```bash
# 在 Claude Code 中，用 @ 引用根入口
@SKILL.md
```

AI 会立即读取根索引，获得 67 个技能的全局视图。此时它已经知道 `gis/gdal/SKILL.md` 是 GDAL 的技能文件、`gis/cesiumjs/SKILL.md` 是 CesiumJS 的技能文件，以此类推。

### 第三步：加载具体技能并提问

```bash
# 加载 GDAL 技能
@gis/gdal/SKILL.md

# 现在向 AI 提问
"帮我把 data/input.shp 转成 GeoJSON 并重投影到 EPSG:4326"
```

AI 会利用技能文件中的 GDAL CLI 知识，准确给出类似以下命令：

```bash
ogr2ogr -f GeoJSON -t_srs EPSG:4326 output.geojson data/input.shp
```

它还能解释每个参数的含义、指出 `-t_srs` 和 `-s_srs` 的区别、提醒你 GeoJSON 格式不支持多几何类型的注意事项。

同样的流程适用于任何技能。再举一个 C# 开发的例子：

```bash
# 加载 SQLSugar 技能
@csharp/sqlsugar/SKILL.md

# 提问
"用 SQLSugar 写一个分页查询，按创建时间倒序，每页 20 条"
```

AI 会基于技能文件中的 SQLSugar ORM API 知识，生成正确的 C# 代码并解释 `ToPageListAsync` 的参数。

### 零配置也可以直接使用

如果你不想克隆整个仓库，也可以直接在 AI 对话中粘贴技能文件的 Web URL：

```
请阅读并学习以下技能文件的内容：
https://raw.githubusercontent.com/znlgis/opengis-skills/main/gis/gdal/SKILL.md

然后帮我...
```

这种方式适合快速试用，但不适合日常使用（每次都要手动粘贴 URL）。长期使用建议克隆仓库到本地并配置 AI 工具自动加载。

## 1.5 适用人群

OpenGIS-Skills 的价值对不同角色的开发者有不同的体现：

### GIS/CAD 开发者

你每天和 GDAL、GeoServer、PostGIS、CesiumJS、OpenLayers、FreeCAD、OCCT 这些专业库打交道。你希望 AI 编程助手能准确写出可运行的代码，而不是编造 API 或使用过时的方法签名。OpenGIS-Skills 就是你的"AI 专业技能外挂"，让它真正理解你的领域。

### 团队技术负责人 / Tech Lead

你希望把团队积累的 GIS 数据处理 SOP、C# 后端开发规范、CAD 自动化脚本模板沉淀为可复用的知识资产，而不是散落在每个人的聊天记录里。OpenGIS-Skills 的 SKILL.md 规范提供了一种标准化的知识编码方式——你既可以复用社区已有的 67 个技能，也可以按相同规范编写团队专属技能。

### 全栈 GIS 项目团队

你的项目同时涉及 Web 前端（CesiumJS/OpenLayers）、后端服务（GeoServer/Furion/SqlSugar）、数据处理（GDAL/Geopandas/PyQGIS），团队成员各司其职但都需要 AI 辅助。用一套 OpenGIS-Skills 覆盖所有技术栈，避免了"前端团队自己找 CesiumJS 提示词、后端团队另外整理 GeoServer 提示词"的分裂状态。

### 开源 GIS/CAD 项目维护者

你维护着一个 GIS 或 CAD 相关的开源项目，希望让 AI 工具更好地支持你的项目 API。你可以参照 OpenGIS-Skills 的规范，为你的项目编写专属技能文件，甚至可以贡献回主仓库，让更多开发者受益。

### AI 工具重度用户

你已经深度使用 Claude Code、Cursor、Cline 等 AI 编程助手，但目前主要靠临时编写的提示词或从聊天记录中复制粘贴。你发现散乱的提示词难以维护、效果不稳定。OpenGIS-Skills 给你一套结构化的、可持续改进的知识管理方案——用技能文件替代一次性提示词。

结构设计的几个要点：

1. **每个目录都是三层架构的组成部分**——`SKILL.md` 在项目根目录是第一层（全局索引），在各领域目录下是第二层（分类索引），在各工具目录下是第三层（具体技能）。
2. **扁平而非深层嵌套**——最多三层目录深度，技能路径简单直观（`gis/gdal/SKILL.md` 而不是 `gis/vector/ogr/gdal/SKILL.md`）。
3. **约定优于配置**——`SKILL.md` 是固定命名，AI 工具可以自动发现而无需配置文件指定路径。
4. **人类可直接浏览**——即便不用 AI 工具，开发者也可以在 GitHub 上直接浏览和搜索这些技能文件，把它们当做一份结构化的技术速查手册。
