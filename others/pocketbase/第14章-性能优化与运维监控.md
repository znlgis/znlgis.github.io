# 第14章 性能优化与运维监控

## 14.1 性能优化概述

PocketBase 基于 Go 语言和 SQLite 构建，具有出色的性能表现。单实例可处理数千并发连接，但在高负载场景下仍需进行优化。本章将从数据库、应用、系统等层面介绍性能优化策略，并讲解运维监控的最佳实践。

## 14.2 SQLite性能优化

### 14.2.1 WAL模式

PocketBase 默认使用 SQLite 的 WAL（Write-Ahead Logging）模式，这是并发读写性能的关键：

```sql
PRAGMA journal_mode=WAL;
```

WAL 模式的优势：
- 读写操作可以并发执行
- 读操作不会阻塞写操作
- 写操作不会阻塞读操作
- 显著提升并发性能

### 14.2.2 索引优化

合理的索引设计是提升查询性能的关键：

```
// 在Admin UI中为常用查询字段添加索引
// 或通过migration文件添加

// pb_migrations/xxx_add_indexes.js
migrate((app) => {
    const collection = app.findCollectionByNameOrId("posts")
    collection.indexes = [
        "CREATE INDEX idx_posts_author ON posts (author)",
        "CREATE INDEX idx_posts_created ON posts (created)",
        "CREATE INDEX idx_posts_status ON posts (status)",
        "CREATE UNIQUE INDEX idx_posts_slug ON posts (slug)"
    ]
    app.save(collection)
})
```

**索引设计原则：**

| 场景 | 建议 |
|------|------|
| 频繁查询的字段 | 添加普通索引 |
| 唯一性约束 | 添加唯一索引 |
| 多字段组合查询 | 添加复合索引 |
| 排序字段 | 添加索引 |
| 数据量小的字段 | 不需要索引 |
| 频繁更新的字段 | 谨慎添加索引 |

### 14.3.4 缓存策略

```javascript
// 前端缓存示例
class PBCache {
    constructor(ttl = 60000) {
        this.cache = new Map();
        this.ttl = ttl;
    }
    
    get(key) {
        const item = this.cache.get(key);
        if (!item) return null;
        if (Date.now() - item.timestamp > this.ttl) {
            this.cache.delete(key);
            return null;
        }
        return item.data;
    }
    
    set(key, data) {
        this.cache.set(key, { data, timestamp: Date.now() });
    }
}

const cache = new PBCache(30000); // 30秒缓存

async function getPost(id) {
    const cached = cache.get(`post_${id}`);
    if (cached) return cached;
    
    const record = await pb.collection('posts').getOne(id);
    cache.set(`post_${id}`, record);
    return record;
}
```

### 14.4.3 重连策略

```javascript
// 实现指数退避重连
let reconnectAttempts = 0;
const maxReconnectDelay = 30000;

function reconnect() {
    const delay = Math.min(
        1000 * Math.pow(2, reconnectAttempts),
        maxReconnectDelay
    );
    
    setTimeout(() => {
        reconnectAttempts++;
        pb.collection('messages').subscribe('*', handleChange)
            .then(() => {
                reconnectAttempts = 0;
                console.log('重连成功');
            })
            .catch(() => {
                console.log(`重连失败，${delay/1000}秒后重试`);
                reconnect();
            });
    }, delay);
}
```

### 14.6.2 性能指标监控

```go
// 自定义Go中间件收集性能指标
package main

import (
    "sync/atomic"
    "time"
    "fmt"
    "github.com/pocketbase/pocketbase"
    "github.com/pocketbase/pocketbase/core"
)

var (
    totalRequests   int64
    activeRequests  int64
    totalErrors     int64
    startTime       time.Time
)

func main() {
    app := pocketbase.New()
    startTime = time.Now()
    
    app.OnServe().BindFunc(func(se *core.ServeEvent) error {
        // 请求计数中间件
        se.Router.Use(func(re *core.RequestEvent) error {
            atomic.AddInt64(&totalRequests, 1)
            atomic.AddInt64(&activeRequests, 1)
            defer atomic.AddInt64(&activeRequests, -1)
            
            err := re.Next()
            if err != nil {
                atomic.AddInt64(&totalErrors, 1)
            }
            return err
        })
        
        // 指标端点
        se.Router.GET("/api/metrics", func(re *core.RequestEvent) error {
            uptime := time.Since(startTime).Seconds()
            metrics := fmt.Sprintf(
                "# PocketBase Metrics\n"+
                "uptime_seconds %.2f\n"+
                "total_requests %d\n"+
                "active_requests %d\n"+
                "total_errors %d\n",
                uptime,
                atomic.LoadInt64(&totalRequests),
                atomic.LoadInt64(&activeRequests),
                atomic.LoadInt64(&totalErrors),
            )
            return re.String(200, metrics)
        })
        
        return se.Next()
    })
    
    app.Start()
}
```

## 14.8 故障排除

### 14.8.1 常见问题及解决方案

| 问题 | 可能原因 | 解决方案 |
|------|----------|----------|
| 服务启动失败 | 端口被占用 | 更换端口或停止占用进程 |
| 数据库锁定 | 并发写入冲突 | 确保WAL模式启用 |
| 内存溢出 | 数据量过大 | 设置GOMEMLIMIT |
| 连接超时 | 文件描述符不足 | 增加ulimit值 |
| 实时订阅断开 | Token过期 | 实现自动刷新机制 |
| 文件上传失败 | 磁盘空间不足 | 清理磁盘或扩容 |
| API响应慢 | 缺少索引 | 添加合适的数据库索引 |

### 14.9.2 性能基准

单实例 PocketBase 的典型性能表现：
- **读取操作**：每秒可处理 5000-10000+ 次查询
- **写入操作**：每秒约 500-1000 次写入（SQLite WAL 模式）
- **实时连接**：支持 10000+ 并发 SSE 连接
- **文件上传**：受网络带宽和磁盘 I/O 限制
