# 第03章 管理面板与数据建模

本章将深入介绍PocketBase的管理面板(Admin UI)和数据建模功能。你将学习如何通过可视化界面管理数据结构、配置访问规则，以及数据建模的最佳实践。

---

## 3.1 管理面板概述

### 3.1.1 访问管理面板

PocketBase内置了一个功能强大的Web管理面板(Admin UI)，用于可视化管理后端服务的所有方面。

**访问地址：** `http://127.0.0.1:8090/_/`

```
┌──────────────────────────────────────────────────────────┐
│  PocketBase Admin UI                                      │
│  http://127.0.0.1:8090/_/                                │
├──────────────────────────────────────────────────────────┤
│                                                           │
│  ┌─────────┐                                             │
│  │ 侧边栏   │    主内容区域                                │
│  │         │                                              │
│  │ 集合列表  │    数据表格 / 设置面板                       │
│  │         │                                              │
│  │ - users │                                              │
│  │ - posts │                                              │
│  │ - tags  │                                              │
│  │         │                                              │
│  │ 设置     │                                             │
│  │ 日志     │                                             │
│  └─────────┘                                             │
│                                                           │
└──────────────────────────────────────────────────────────┘
```

### 3.1.2 Admin UI功能模块

管理面板包含以下核心功能模块：

| 功能模块 | 说明 |
|---------|------|
| **集合管理** | 创建、编辑、删除集合(Collection)，管理字段 |
| **数据浏览** | 以表格形式查看、搜索、筛选、编辑记录 |
| **API规则** | 可视化配置集合的访问权限规则 |
| **系统设置** | 邮件配置、S3存储配置、OAuth2提供商配置 |
| **日志查看** | 查看API请求日志和系统日志 |
| **备份管理** | 数据库备份和恢复功能 |
| **API预览** | 自动生成的API文档和测试界面 |

### 3.1.3 管理面板的安全性

Admin UI默认只有超级用户(管理员)才能访问。安全要点：

- Admin UI路径(`/_/`)受管理员认证保护
- 管理员token与普通用户token分开管理
- 建议在生产环境中通过反向代理限制Admin UI的访问IP

```nginx
# Nginx反向代理配置示例 - 限制Admin UI访问
server {
    listen 80;
    server_name api.example.com;

    # Admin UI仅允许特定IP访问
    location /_/ {
        allow 192.168.1.0/24;  # 内网IP段
        allow 10.0.0.100;       # 管理员IP
        deny all;
        proxy_pass http://127.0.0.1:8090;
    }

    # API对所有人开放
    location /api/ {
        proxy_pass http://127.0.0.1:8090;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
```

## 3.2 管理员账号管理

### 3.2.1 创建管理员

**方法一：通过Admin UI创建(首次访问)**

首次访问`http://127.0.0.1:8090/_/`时，系统会自动引导你创建第一个管理员账号。

**方法二：通过命令行创建**

```bash
# 交互式创建
./pocketbase superuser create

# 直接指定邮箱和密码
./pocketbase superuser create admin@example.com MySecurePassword123
```

**方法三：通过API创建(需要现有管理员Token)**

```bash
# 先获取管理员Token
curl -X POST http://127.0.0.1:8090/api/admins/auth-with-password \
  -H "Content-Type: application/json" \
  -d '{
    "identity": "admin@example.com",
    "password": "MySecurePassword123"
  }'
```

### 3.2.2 修改管理员信息

```bash
# 通过命令行修改管理员密码
./pocketbase superuser update admin@example.com NewPassword456
```

在Admin UI中，点击右上角的管理员头像也可以修改当前管理员的信息。

### 3.2.3 多管理员管理

PocketBase支持创建多个管理员账号，便于团队协作：

```bash
# 列出所有管理员
./pocketbase superuser list

# 创建额外的管理员
./pocketbase superuser create dev@example.com DevPassword123

# 删除管理员
./pocketbase superuser delete dev@example.com
```

### 3.2.4 安全设置建议

| 安全措施 | 说明 |
|---------|------|
| **强密码** | 管理员密码至少10个字符，包含大小写字母、数字和特殊字符 |
| **限制访问** | 通过反向代理限制Admin UI的访问来源IP |
| **HTTPS** | 在生产环境中始终使用HTTPS |
| **定期更换密码** | 建议每90天更换管理员密码 |
| **最小权限** | 仅给需要管理后台的人创建管理员账号 |

## 3.3 集合(Collection)概念

### 3.3.1 什么是集合

在PocketBase中，**集合(Collection)** 相当于传统数据库中的**表(Table)**。每个集合定义了一组字段(Field)，用于存储特定类型的数据。

```
传统数据库概念对照：
┌──────────────────┬──────────────────┐
│   传统数据库      │    PocketBase    │
├──────────────────┼──────────────────┤
│   数据库          │    PocketBase实例 │
│   表(Table)       │    集合(Collection)│
│   列(Column)      │    字段(Field)    │
│   行(Row)         │    记录(Record)   │
│   主键(PK)        │    id(自动生成)   │
└──────────────────┴──────────────────┘
```

### 3.3.2 三种集合类型

PocketBase提供三种集合类型：

#### Base集合(基础集合)

最常用的集合类型，用于存储普通数据：

```
Base集合特点：
- 自动生成id、created、updated系统字段
- 支持所有字段类型
- 自动生成CRUD API
- 可配置访问规则

适用场景：文章、产品、订单、评论等业务数据
```

```javascript
// Base集合的API使用示例
// 创建posts集合后自动生成的API：
// GET    /api/collections/posts/records
// POST   /api/collections/posts/records
// GET    /api/collections/posts/records/:id
// PATCH  /api/collections/posts/records/:id
// DELETE /api/collections/posts/records/:id
```

#### Auth集合(认证集合)

专门用于存储用户数据的集合，在Base集合的基础上额外提供认证功能：

```
Auth集合额外特性：
- 内置email、password、verified、tokenKey等认证字段
- 自动提供注册、登录、密码重置API
- 支持OAuth2社交登录
- 支持邮箱验证
- 支持多个Auth集合（如users、admins、members等）

系统自动添加的字段：
├── id          (文本，15位随机字符)
├── email       (邮箱)
├── password    (密码，加密存储)
├── verified    (布尔，邮箱是否验证)
├── tokenKey    (文本，Token密钥)
├── created     (日期时间)
└── updated     (日期时间)
```

```bash
# Auth集合额外的API端点：

# 用户注册
POST /api/collections/users/records

# 邮箱密码登录
POST /api/collections/users/auth-with-password

# OAuth2登录
POST /api/collections/users/auth-with-oauth2

# 刷新认证
POST /api/collections/users/auth-refresh

# 请求密码重置
POST /api/collections/users/request-password-reset

# 确认密码重置
POST /api/collections/users/confirm-password-reset

# 请求邮箱验证
POST /api/collections/users/request-verification

# 确认邮箱验证
POST /api/collections/users/confirm-verification

# 请求邮箱变更
POST /api/collections/users/request-email-change

# 确认邮箱变更
POST /api/collections/users/confirm-email-change
```

#### View集合(视图集合)

基于SQL查询的只读虚拟集合，类似于数据库视图(View)：

```
View集合特点：
- 基于SQL SELECT查询
- 只读，不支持创建、更新、删除操作
- 可以跨多个集合查询和聚合数据
- 适合创建统计报表和数据汇总

适用场景：数据统计、报表视图、复合查询
```

```sql
-- View集合的SQL查询示例

-- 统计每个用户的文章数量
SELECT
    u.id,
    u.name,
    u.email,
    COUNT(p.id) as postCount
FROM users u
LEFT JOIN posts p ON p.author = u.id
GROUP BY u.id

-- 获取最近7天的评论统计
SELECT
    DATE(c.created) as date,
    COUNT(*) as commentCount
FROM comments c
WHERE c.created >= DATE('now', '-7 days')
GROUP BY DATE(c.created)
ORDER BY date DESC

-- 带分类名称的文章列表
SELECT
    p.id,
    p.title,
    p.content,
    p.created,
    c.name as categoryName
FROM posts p
LEFT JOIN categories c ON p.category = c.id
WHERE p.published = true
```

### 3.3.3 系统集合

PocketBase默认创建一个系统Auth集合：

- **users**：默认的用户集合，包含基本的用户认证字段

```javascript
// 默认users集合的字段
{
    "id": "auto-generated",
    "email": "user@example.com",
    "name": "",
    "avatar": "",           // 文件字段
    "verified": false,
    "created": "2024-01-01 00:00:00.000Z",
    "updated": "2024-01-01 00:00:00.000Z"
}
```

## 3.4 创建集合

### 3.4.1 通过Admin UI创建集合

**步骤一：进入集合管理**

1. 登录Admin UI (`http://127.0.0.1:8090/_/`)
2. 点击左侧边栏的"New collection"按钮

**步骤二：选择集合类型**

选择要创建的集合类型：
- Base：普通数据集合
- Auth：用户认证集合
- View：视图集合

**步骤三：设置集合名称**

```
集合命名规则：
- 使用小写字母和下划线
- 建议使用英文复数形式
- 例如：posts、categories、user_profiles、order_items
- 避免使用保留字：_collections、_admins等以下划线开头的名称
```

**步骤四：添加字段**

在集合编辑界面中添加所需的字段，每个字段需要设置：

- **字段名称**：英文标识符，如`title`、`content`
- **字段类型**：从可用类型中选择
- **是否必填**：是否允许空值
- **其他选项**：根据字段类型的特定选项

### 3.4.2 通过API创建集合

管理员可以通过API创建集合：

```bash
# 获取管理员Token
TOKEN=$(curl -s -X POST http://127.0.0.1:8090/api/admins/auth-with-password \
  -H "Content-Type: application/json" \
  -d '{"identity":"admin@example.com","password":"adminpassword"}' \
  | jq -r '.token')

# 创建Base集合
curl -X POST http://127.0.0.1:8090/api/collections \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $TOKEN" \
  -d '{
    "name": "posts",
    "type": "base",
    "fields": [
      {
        "name": "title",
        "type": "text",
        "required": true,
        "options": {
          "min": 3,
          "max": 200
        }
      },
      {
        "name": "content",
        "type": "editor",
        "required": false
      },
      {
        "name": "published",
        "type": "bool"
      },
      {
        "name": "views",
        "type": "number",
        "options": {
          "min": 0
        }
      },
      {
        "name": "tags",
        "type": "select",
        "options": {
          "maxSelect": 5,
          "values": ["技术", "生活", "教程", "新闻", "其他"]
        }
      },
      {
        "name": "cover",
        "type": "file",
        "options": {
          "maxSelect": 1,
          "maxSize": 5242880,
          "mimeTypes": ["image/jpeg", "image/png", "image/webp"]
        }
      }
    ]
  }'
```

### 3.4.3 通过迁移文件创建集合

推荐在团队开发中使用迁移文件管理集合结构：

```javascript
// pb_migrations/1700000001_create_posts.js

migrate((app) => {
    const collection = new Collection({
        name: "posts",
        type: "base",
        fields: [
            {
                name: "title",
                type: "text",
                required: true,
                options: {
                    min: 3,
                    max: 200
                }
            },
            {
                name: "content",
                type: "editor"
            },
            {
                name: "published",
                type: "bool"
            },
            {
                name: "author",
                type: "relation",
                required: true,
                options: {
                    collectionId: "users",
                    maxSelect: 1
                }
            }
        ],
        indexes: [
            "CREATE INDEX idx_posts_title ON posts (title)",
            "CREATE INDEX idx_posts_author ON posts (author)",
            "CREATE INDEX idx_posts_created ON posts (created)"
        ]
    });

    return app.save(collection);
}, (app) => {
    const collection = app.findCollectionByNameOrId("posts");
    return app.delete(collection);
});
```

## 3.5 字段类型概览

### 3.5.1 所有字段类型

PocketBase支持以下字段类型：

| 字段类型 | 说明 | 存储类型 | 示例值 |
|---------|------|---------|-------|
| `text` | 文本 | TEXT | `"Hello World"` |
| `number` | 数字 | REAL | `42`, `3.14` |
| `bool` | 布尔值 | BOOLEAN | `true`, `false` |
| `email` | 邮箱地址 | TEXT | `"user@example.com"` |
| `url` | URL链接 | TEXT | `"https://example.com"` |
| `date` | 日期时间 | TEXT | `"2024-01-15 10:30:00.000Z"` |
| `select` | 选择项 | TEXT/JSON | `"option1"`, `["a","b"]` |
| `relation` | 关联关系 | TEXT/JSON | `"RECORD_ID"` |
| `file` | 文件上传 | TEXT/JSON | `"filename.jpg"` |
| `json` | JSON数据 | JSON | `{"key": "value"}` |
| `editor` | 富文本编辑器 | TEXT | `"<p>HTML内容</p>"` |
| `autodate` | 自动日期 | TEXT | 自动设置创建/更新时间 |

### 3.5.2 text - 文本字段

最基础的字段类型，用于存储纯文本数据：

```javascript
// 字段配置
{
    "name": "title",
    "type": "text",
    "required": true,
    "options": {
        "min": 1,        // 最小字符数
        "max": 500,      // 最大字符数
        "pattern": ""    // 正则表达式验证
    }
}
```

```javascript
// 使用正则表达式验证
// 只允许字母、数字和中文
{
    "name": "username",
    "type": "text",
    "options": {
        "min": 3,
        "max": 20,
        "pattern": "^[a-zA-Z0-9\\u4e00-\\u9fa5]+$"
    }
}

// 手机号验证
{
    "name": "phone",
    "type": "text",
    "options": {
        "pattern": "^1[3-9]\\d{9}$"
    }
}
```

### 3.5.3 number - 数字字段

存储整数或浮点数：

```javascript
{
    "name": "price",
    "type": "number",
    "required": true,
    "options": {
        "min": 0,         // 最小值
        "max": 999999.99, // 最大值
        "noDecimal": false // 是否禁止小数
    }
}

// 整数字段(如年龄)
{
    "name": "age",
    "type": "number",
    "options": {
        "min": 0,
        "max": 150,
        "noDecimal": true
    }
}
```

### 3.5.4 bool - 布尔字段

存储true/false值：

```javascript
{
    "name": "published",
    "type": "bool"
}
// 默认值为false
// API中返回: "published": true 或 "published": false
```

### 3.5.5 email - 邮箱字段

自动验证邮箱格式：

```javascript
{
    "name": "contactEmail",
    "type": "email",
    "required": true,
    "options": {
        "exceptDomains": [],     // 排除的域名
        "onlyDomains": []        // 仅允许的域名
    }
}

// 只允许公司邮箱
{
    "name": "workEmail",
    "type": "email",
    "options": {
        "onlyDomains": ["company.com", "corp.company.com"]
    }
}
```

### 3.5.6 url - URL字段

自动验证URL格式：

```javascript
{
    "name": "website",
    "type": "url",
    "options": {
        "exceptDomains": [],
        "onlyDomains": []
    }
}
```

### 3.5.7 date - 日期字段

存储日期时间值：

```javascript
{
    "name": "publishDate",
    "type": "date",
    "required": false,
    "options": {
        "min": "",    // 最早日期
        "max": ""     // 最晚日期
    }
}

// 限制日期范围
{
    "name": "eventDate",
    "type": "date",
    "options": {
        "min": "2024-01-01 00:00:00.000Z",
        "max": "2025-12-31 23:59:59.999Z"
    }
}
```

日期格式统一使用ISO 8601：`"2024-01-15 10:30:00.000Z"`

### 3.5.8 select - 选择字段

单选或多选下拉列表：

```javascript
// 单选
{
    "name": "status",
    "type": "select",
    "required": true,
    "options": {
        "maxSelect": 1,
        "values": ["草稿", "审核中", "已发布", "已下架"]
    }
}

// 多选
{
    "name": "tags",
    "type": "select",
    "options": {
        "maxSelect": 5,
        "values": ["JavaScript", "Python", "Go", "Rust", "TypeScript", "Java", "C++"]
    }
}
```

```bash
# 使用单选字段筛选
curl "http://127.0.0.1:8090/api/collections/posts/records?filter=(status='已发布')"

# 使用多选字段筛选(包含某个值)
curl "http://127.0.0.1:8090/api/collections/posts/records?filter=(tags~'JavaScript')"
```

### 3.5.9 relation - 关联字段

建立集合之间的关联关系：

```javascript
// 多对一关系(一篇文章属于一个作者)
{
    "name": "author",
    "type": "relation",
    "required": true,
    "options": {
        "collectionId": "<users集合的ID>",
        "cascadeDelete": false,   // 是否级联删除
        "maxSelect": 1,           // 1=单选(多对一)
        "minSelect": 0
    }
}

// 多对多关系(一篇文章可以有多个标签)
{
    "name": "categories",
    "type": "relation",
    "options": {
        "collectionId": "<categories集合的ID>",
        "cascadeDelete": false,
        "maxSelect": null,   // null=无限制(多对多)
        "minSelect": 0
    }
}
```

```bash
# 查询时展开关联数据
curl "http://127.0.0.1:8090/api/collections/posts/records?expand=author,categories"

# 返回的数据中会包含关联记录的完整信息
# {
#   "id": "...",
#   "title": "文章标题",
#   "author": "USER_ID",
#   "expand": {
#     "author": {
#       "id": "USER_ID",
#       "name": "张三",
#       "email": "zhangsan@example.com"
#     },
#     "categories": [...]
#   }
# }
```

### 3.5.10 file - 文件字段

用于文件上传：

```javascript
// 单文件上传(如头像)
{
    "name": "avatar",
    "type": "file",
    "options": {
        "maxSelect": 1,
        "maxSize": 2097152,   // 2MB (字节)
        "mimeTypes": [
            "image/jpeg",
            "image/png",
            "image/gif",
            "image/webp"
        ],
        "thumbs": ["100x100", "200x200"]  // 自动生成缩略图
    }
}

// 多文件上传(如相册)
{
    "name": "photos",
    "type": "file",
```

## 3.6 数据建模最佳实践

### 3.6.1 表设计原则

**原则一：遵循规范化设计**

```
# 不好的设计(数据冗余)
posts集合:
├── title
├── content
├── authorName     ← 作者名称直接存在文章表中
├── authorEmail    ← 作者邮箱直接存在文章表中
└── authorAvatar   ← 作者头像直接存在文章表中

# 好的设计(使用关联)
posts集合:              users集合:
├── title              ├── name
├── content            ├── email
└── author (relation)  └── avatar
    └── → users.id
```

**原则二：合理选择字段类型**

```javascript
// 正确的字段类型选择
{
    "email": "email类型",      // 不要用text存储邮箱
    "website": "url类型",      // 不要用text存储URL
    "price": "number类型",     // 不要用text存储数字
    "isActive": "bool类型",    // 不要用text存储true/false
    "status": "select类型",    // 不要用text存储枚举值
    "publishAt": "date类型"    // 不要用text存储日期
}
```

**原则三：适度反范式化**

在某些场景下，为了查询性能，可以适度冗余：

```javascript
// 评论集合中冗余作者名称，避免每次查询都展开关联
// 适用于不经常变更的数据
{
    "name": "comments",
    "fields": [
        { "name": "content", "type": "text" },
        { "name": "author", "type": "relation" },    // 关联到用户
        { "name": "authorName", "type": "text" }      // 冗余作者名称
    ]
}
```

### 3.6.2 关联关系设计

**一对多关系（最常见）**

```
示例：一个用户有多篇文章

users集合            posts集合
┌────────┐          ┌────────────┐
│ id     │◄─────────│ author     │ (relation, maxSelect=1)
│ name   │          │ title      │
│ email  │          │ content    │
└────────┘          └────────────┘
```

```javascript
// posts集合的author字段配置
{
    "name": "author",
    "type": "relation",
    "options": {
        "collectionId": "<users集合ID>",
        "maxSelect": 1
    }
}
```

**多对多关系**

```
示例：文章和标签的多对多关系

posts集合                     tags集合
┌──────────────┐             ┌────────┐
│ id           │             │ id     │
│ title        │             │ name   │
│ tags         │─────────────│        │
│ (relation)   │  maxSelect  └────────┘
│              │  = null
└──────────────┘
```

```javascript
// posts集合的tags字段配置
{
    "name": "tags",
    "type": "relation",
    "options": {
        "collectionId": "<tags集合ID>",
        "maxSelect": null  // null表示无限制
    }
}
```

**自引用关系**

```
示例：评论的层级回复

comments集合
┌───────────────┐
│ id            │
│ content       │
│ author        │ → users
│ parentComment │ → comments (自引用)
└───────────────┘
```

```javascript
// comments集合的自引用字段
{
    "name": "parentComment",
    "type": "relation",
    "required": false,
    "options": {
        "collectionId": "<comments集合自身的ID>",
        "maxSelect": 1
    }
}
```

### 3.6.3 索引设计

PocketBase支持在集合上创建自定义索引以提升查询性能：

```javascript
// 在迁移文件中创建索引
migrate((app) => {
    const collection = new Collection({
        name: "posts",
        type: "base",
        fields: [
            { "name": "title", "type": "text", "required": true },
            { "name": "slug", "type": "text", "required": true },
            { "name": "status", "type": "select", "options": { "values": ["draft", "published"] } },
            { "name": "author", "type": "relation" },
            { "name": "publishDate", "type": "date" }
        ],
        indexes: [
            // 唯一索引(slug不能重复)
            "CREATE UNIQUE INDEX idx_posts_slug ON posts (slug)",

            // 普通索引(加速按状态筛选)
            "CREATE INDEX idx_posts_status ON posts (status)",

            // 复合索引(加速按作者和状态联合查询)
            "CREATE INDEX idx_posts_author_status ON posts (author, status)",

            // 排序索引(加速按发布日期排序)
            "CREATE INDEX idx_posts_publish_date ON posts (publishDate DESC)"
        ]
    });

    return app.save(collection);
});
```

**索引设计建议：**

```
✅ 为经常在filter中使用的字段创建索引
✅ 为经常在sort中使用的字段创建索引
✅ 为relation字段创建索引(PocketBase通常自动创建)
✅ 为需要唯一性约束的字段创建唯一索引

❌ 不要为很少查询的字段创建索引
❌ 不要创建过多索引(影响写入性能)
❌ 不要为bool类型字段单独创建索引(选择性太低)
```

## 3.7 API规则设置

### 3.7.1 API规则概述

PocketBase通过API规则(API Rules)来控制谁可以对集合数据执行什么操作。每个集合有五种操作的规则：

| 操作 | 说明 | HTTP方法 |
|------|------|---------|
| **List** | 列表查询 | GET (获取多条记录) |
| **View** | 查看单条记录 | GET (获取指定ID的记录) |
| **Create** | 创建记录 | POST |
| **Update** | 更新记录 | PATCH |
| **Delete** | 删除记录 | DELETE |

### 3.7.2 规则语法

API规则使用类似SQL WHERE子句的过滤表达式：

```
规则值说明：
- 空值(未设置)：拒绝所有请求(锁定)
- 空字符串("")：允许所有请求(公开)
- 表达式：只有满足条件的请求才被允许
```

```javascript
// 常用的规则变量
@request.auth.id          // 当前认证用户的ID
@request.auth.email       // 当前认证用户的邮箱
@request.auth.verified    // 当前用户是否已验证邮箱
@request.auth.collectionName  // 认证集合名称
@request.data.fieldName   // 请求体中的字段值
@collection.name.fieldName // 引用其他集合的字段
```

### 3.7.3 规则配置示例

**场景一：公开博客文章（仅已发布的可以公开查看）**

```
List规则: published = true
View规则: published = true
Create规则: @request.auth.id != ""
Update规则: @request.auth.id = author
Delete规则: @request.auth.id = author
```

解释：
- 任何人可以查看和列出已发布的文章
- 已登录用户可以创建文章
- 只有作者本人可以更新或删除自己的文章

**场景二：私人笔记（仅自己可见）**

```
List规则: @request.auth.id = owner
View规则: @request.auth.id = owner
Create规则: @request.auth.id != ""
Update规则: @request.auth.id = owner
Delete规则: @request.auth.id = owner
```

**场景三：评论系统（所有人可查看，登录后可评论，管理员可删除）**

```
List规则: ""  (所有人可查看)
View规则: ""  (所有人可查看)
Create规则: @request.auth.id != ""
Update规则: @request.auth.id = author
Delete规则: @request.auth.id = author || @request.auth.role = "admin"
```

1. 进入Admin UI，选择目标集合
2. 点击集合设置图标(齿轮图标)
3. 在"API Rules"选项卡中配置各操作的规则
4. 使用内置的规则编辑器，支持自动补全

### 3.7.5 复杂规则示例

```javascript
// 限制用户只能修改自己的数据，且不能修改role字段
"@request.auth.id = id && @request.data.role:isset = false"
```

## 3.9 集合迁移

### 3.9.1 什么是迁移

迁移(Migration)是一种以代码方式管理数据库结构变更的机制。它允许你：

- 在版本控制中跟踪数据库结构变化
- 在不同环境中保持数据库结构一致
- 在团队协作中共享数据库变更
- 支持结构变更的回滚

### 3.9.2 迁移文件格式

PocketBase使用JavaScript编写迁移文件，存放在`pb_migrations/`目录中：

```javascript
// pb_migrations/1700000001_create_categories.js

migrate((app) => {
    // 正向迁移：创建集合
    const collection = new Collection({
        name: "categories",
        type: "base",
        fields: [
            {
                name: "name",
                type: "text",
                required: true,
                options: {
                    min: 1,
                    max: 100
                }
            },
            {
                name: "slug",
                type: "text",
                required: true
            },
            {
                name: "description",
                type: "text"
            },
            {
                name: "sortOrder",
                type: "number",
                options: {
                    min: 0,
                    noDecimal: true
                }
            }
        ],
        indexes: [
            "CREATE UNIQUE INDEX idx_categories_slug ON categories (slug)"
        ]
    });

    return app.save(collection);
}, (app) => {
    // 反向迁移：回滚(删除集合)
    const collection = app.findCollectionByNameOrId("categories");
    return app.delete(collection);
});
```

### 3.9.3 迁移文件命名规则

```
文件名格式：<时间戳>_<描述>.js

示例：
1700000001_create_categories.js
1700000002_create_posts.js
1700000003_add_views_to_posts.js
1700000004_create_comments.js
1700000005_add_index_to_posts.js
```

时间戳确保迁移按顺序执行。可以使用Unix时间戳或自增数字。

### 3.9.4 常见迁移操作

**添加新字段：**

```javascript
// pb_migrations/1700000003_add_views_to_posts.js

migrate((app) => {
    const collection = app.findCollectionByNameOrId("posts");

    collection.fields.push({
        name: "views",
        type: "number",
        options: {
            min: 0,
            noDecimal: true
        }
    });

    return app.save(collection);
}, (app) => {
    const collection = app.findCollectionByNameOrId("posts");
    const field = collection.fields.find(f => f.name === "views");
    if (field) {
        collection.fields.splice(collection.fields.indexOf(field), 1);
    }
    return app.save(collection);
});
```

**修改字段属性：**

```javascript
// pb_migrations/1700000004_update_title_max_length.js

migrate((app) => {
    const collection = app.findCollectionByNameOrId("posts");
    const titleField = collection.fields.find(f => f.name === "title");

    if (titleField) {
        titleField.options.max = 300;  // 将最大长度从200改为300
    }

    return app.save(collection);
}, (app) => {
    const collection = app.findCollectionByNameOrId("posts");
    const titleField = collection.fields.find(f => f.name === "title");

    if (titleField) {
        titleField.options.max = 200;  // 回滚
    }

    return app.save(collection);
});
```

**添加索引：**

```javascript
// pb_migrations/1700000005_add_posts_indexes.js

migrate((app) => {
    const collection = app.findCollectionByNameOrId("posts");

    collection.indexes.push(
        "CREATE INDEX idx_posts_status ON posts (status)",
        "CREATE INDEX idx_posts_author_created ON posts (author, created DESC)"
    );

    return app.save(collection);
}, (app) => {
    const collection = app.findCollectionByNameOrId("posts");

    collection.indexes = collection.indexes.filter(idx =>
        !idx.includes("idx_posts_status") &&
        !idx.includes("idx_posts_author_created")
    );

    return app.save(collection);
});
```

### 3.9.5 运行迁移

PocketBase会在启动时自动运行未执行的迁移文件：

```bash
# 启动时自动执行迁移
./pocketbase serve

# 迁移状态记录在数据库中，已执行的迁移不会重复执行
```

### 3.9.6 迁移最佳实践

```
✅ 推荐做法：
- 每个变更创建独立的迁移文件
- 始终编写回滚逻辑(第二个函数)
- 将迁移文件纳入版本控制(Git)
- 在开发环境中测试迁移后再应用到生产环境
- 使用有意义的文件名描述

❌ 避免做法：
- 不要修改已执行的迁移文件
- 不要在迁移中包含大量数据操作(使用单独的seed脚本)
- 不要依赖特定的记录ID(ID是随机生成的)
- 不要在迁移中引入外部依赖
```

### 3.9.7 从Admin UI导出迁移

在Admin UI中修改集合结构后，可以导出为迁移文件：

1. 在Admin UI中进行集合结构修改
2. PocketBase会在`pb_migrations/`目录中自动生成对应的迁移文件
3. 将这些迁移文件提交到版本控制

这样可以在可视化操作和代码管理之间取得平衡。
