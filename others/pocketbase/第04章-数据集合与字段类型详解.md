# 第04章 数据集合与字段类型详解

PocketBase 的核心数据模型围绕**集合(Collection)**构建。每个集合相当于一张数据库表，而字段(Field)则定义了表中的列。本章将深入讲解 PocketBase 支持的三种集合类型以及所有内置字段类型的配置与使用方式。

---

## 4.1 集合类型深入解析

PocketBase 提供三种集合类型，每种类型适用于不同的业务场景。

### 4.1.1 Base 集合（普通数据表）

Base 集合是最常用的集合类型，用于存储普通业务数据。它等价于关系型数据库中的一张标准数据表。

**特点：**
- 自动包含 `id`、`created`、`updated` 系统字段
- 支持所有字段类型
- 支持自定义 API 规则（增删改查权限控制）
- 支持字段索引

**创建 Base 集合示例（通过 Admin UI）：**

1. 登录管理面板，点击左侧「Collections」
2. 点击「New collection」
3. 选择「Base」类型
4. 输入集合名称，例如 `posts`
5. 添加所需字段并保存

**通过 API 创建 Base 集合：**

```bash
curl -X POST http://127.0.0.1:8090/api/collections \
  -H "Authorization: Bearer ADMIN_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "posts",
    "type": "base",
    "schema": [
      {
        "name": "title",
        "type": "text",
        "required": true,
        "options": {
          "min": 1,
          "max": 200
        }
      },
      {
        "name": "content",
        "type": "editor"
      },
      {
        "name": "published",
        "type": "bool"
      }
    ]
  }'
```

### 4.1.2 Auth 集合（用户认证表）

Auth 集合是专门用于用户认证的集合类型。它在 Base 集合的基础上内置了认证相关的系统字段和功能。

**内置系统字段：**

| 字段名 | 类型 | 说明 |
|--------|------|------|
| `id` | string | 唯一标识符，15位随机字符串 |
| `email` | string | 用户邮箱，自动格式验证 |
| `emailVisibility` | bool | 邮箱是否对外可见 |
| `password` | string | 密码，自动加密存储(bcrypt) |
| `verified` | bool | 邮箱是否已验证 |
| `username` | string | 用户名，唯一约束 |
| `created` | datetime | 创建时间 |
| `updated` | datetime | 更新时间 |

**Auth 集合特有功能：**

- 用户注册与登录 API
- JWT Token 签发与验证
- OAuth2 第三方登录
- 邮箱验证流程
- 密码重置流程
- 多因素认证(MFA)

**创建 Auth 集合：**

```bash
curl -X POST http://127.0.0.1:8090/api/collections \
  -H "Authorization: Bearer ADMIN_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "customers",
    "type": "auth",
    "schema": [
      {
        "name": "nickname",
        "type": "text",
        "options": {
          "max": 50
        }
      },
      {
        "name": "avatar",
        "type": "file",
        "options": {
          "maxSelect": 1,
          "maxSize": 5242880,
          "mimeTypes": ["image/jpeg", "image/png", "image/webp"]
        }
      },
      {
        "name": "role",
        "type": "select",
        "options": {
          "maxSelect": 1,
          "values": ["user", "vip", "admin"]
        }
      }
    ]
  }'
```

**可以创建多个 Auth 集合：**

PocketBase 允许创建多个 Auth 集合以区分不同角色的用户。例如：
- `users` — 普通用户
- `admins` — 管理员
- `merchants` — 商家

每个 Auth 集合都有独立的认证端点和 API 规则。

### 4.1.3 View 集合（基于 SQL 视图的虚拟集合）

View 集合是基于 SQL SELECT 查询创建的只读虚拟集合。它不会在数据库中创建实际的数据表，而是在查询时动态生成数据。

**特点：**
- 只读集合，不支持创建、更新、删除操作
- 基于 SQL 查询定义
- 可以跨集合联合查询
- 查询结果的第一个字段必须是 `id`
- 适合创建统计视图、聚合数据

**创建 View 集合示例：**

```sql
-- 文章统计视图：统计每个作者的文章数量
SELECT
  authors.id as id,
  authors.name as author_name,
  COUNT(posts.id) as post_count,
  MAX(posts.created) as latest_post_date
FROM authors
LEFT JOIN posts ON posts.author = authors.id
GROUP BY authors.id
```

**通过 API 创建 View 集合：**

```bash
curl -X POST http://127.0.0.1:8090/api/collections \
  -H "Authorization: Bearer ADMIN_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "post_stats",
    "type": "view",
    "options": {
      "query": "SELECT authors.id as id, authors.name as author_name, COUNT(posts.id) as post_count FROM authors LEFT JOIN posts ON posts.author = authors.id GROUP BY authors.id"
    }
  }'
```

**View 集合的常见用途：**

- 数据聚合与统计报表
- 多表联合查询结果
- 简化复杂查询逻辑
- 创建数据汇总视图

## 4.2 系统字段说明

每个 Base 和 Auth 集合都自动包含以下系统字段，无需手动创建。

### 4.2.1 id 字段

- **类型：** 15 位随机字符串
- **格式：** 由小写字母和数字组成
- **自动生成：** 创建记录时自动分配
- **可自定义：** 创建记录时可以指定自定义 id（需保证唯一性）
- **主键：** 作为记录的唯一标识符

```bash
# 创建记录时使用自定义 id
curl -X POST http://127.0.0.1:8090/api/collections/posts/records \
  -H "Content-Type: application/json" \
  -d '{
    "id": "custom_id_12345",
    "title": "自定义ID的文章"
  }'
```

### 4.2.2 created 字段

- **类型：** datetime
- **格式：** `YYYY-MM-DD HH:MM:SS.sssZ`（UTC 时间）
- **自动管理：** 创建记录时自动设置为当前时间
- **不可修改：** 创建后无法通过 API 修改

### 4.2.3 updated 字段

- **类型：** datetime
- **格式：** `YYYY-MM-DD HH:MM:SS.sssZ`（UTC 时间）
- **自动管理：** 每次更新记录时自动刷新
- **不可修改：** 无法通过 API 手动设置

**系统字段在 API 响应中的示例：**

```json
{
  "id": "abc123def456789",
  "created": "2024-01-15 08:30:00.000Z",
  "updated": "2024-01-15 10:45:30.123Z",
  "title": "示例文章",
  "content": "文章内容..."
}
```

## 4.3 Text 字段

Text 字段用于存储纯文本内容，是最常用的字段类型之一。

### 配置选项

| 选项 | 类型 | 说明 |
|------|------|------|
| `min` | int | 最小字符长度 |
| `max` | int | 最大字符长度 |
| `pattern` | string | 正则表达式验证 |

### 使用示例

```bash
# 创建带有 Text 字段的集合
curl -X POST http://127.0.0.1:8090/api/collections \
  -H "Authorization: Bearer ADMIN_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "products",
    "type": "base",
    "schema": [
      {
        "name": "name",
        "type": "text",
        "required": true,
        "options": {
          "min": 2,
          "max": 100
        }
      },
      {
        "name": "sku",
        "type": "text",
        "required": true,
        "options": {
          "min": 6,
          "max": 20,
          "pattern": "^[A-Z]{2,4}-[0-9]{4,}$"
        }
      },
      {
        "name": "description",
        "type": "text",
        "options": {
          "max": 5000
        }
      }
    ]
  }'
```

### 正则验证示例

```
# 手机号验证
^1[3-9]\d{9}$

# 身份证号验证
^\d{17}[\dXx]$

# SKU 编号验证
^[A-Z]{2,4}-[0-9]{4,}$

# 仅允许中文字符
^[\u4e00-\u9fa5]+$
```

**注意事项：**
- Text 字段默认不限制长度，建议始终设置 `max` 避免滥用
- `required: true` 会确保该字段不能为空字符串
- 正则表达式使用 Go 语言的 `regexp` 语法

## 4.4 Number 字段

Number 字段用于存储数值数据，支持整数和浮点数。

### 配置选项

| 选项 | 类型 | 说明 |
|------|------|------|
| `min` | number | 最小值 |
| `max` | number | 最大值 |
| `noDecimal` | bool | 是否只允许整数 |

### 使用示例

```bash
# 在 products 集合中添加数字字段
curl -X PATCH http://127.0.0.1:8090/api/collections/products \
  -H "Authorization: Bearer ADMIN_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "schema": [
      {
        "name": "price",
        "type": "number",
        "required": true,
        "options": {
          "min": 0,
          "max": 999999.99,
          "noDecimal": false
        }
      },
      {
        "name": "stock",
        "type": "number",
        "required": true,
        "options": {
          "min": 0,
          "noDecimal": true
        }
      },
      {
        "name": "rating",
        "type": "number",
        "options": {
          "min": 0,
          "max": 5
        }
      }
    ]
  }'
```

**注意事项：**
- Number 字段默认值为 `0`
- 如果设置 `noDecimal: true`，提交浮点数将被拒绝
- 未设置 `min` 时允许负数

## 4.5 Bool 字段

Bool 字段用于存储布尔值（`true` / `false`）。

### 使用示例

```bash
# 创建包含布尔字段的记录
curl -X POST http://127.0.0.1:8090/api/collections/posts/records \
  -H "Content-Type: application/json" \
  -d '{
    "title": "PocketBase 入门教程",
    "published": true,
    "featured": false,
    "allow_comments": true
  }'
```

**注意事项：**
- 默认值为 `false`
- API 接受 `true`、`false`、`1`、`0` 作为有效值
- 在过滤查询中可以直接使用：`?filter=(published=true)`

## 4.6 Email 字段

Email 字段专门用于存储电子邮件地址，内置邮箱格式验证。

### 配置选项

| 选项 | 类型 | 说明 |
|------|------|------|
| `exceptDomains` | []string | 排除的域名列表（黑名单） |
| `onlyDomains` | []string | 仅允许的域名列表（白名单） |

### 使用示例

```bash
# 创建带邮箱字段的集合
curl -X POST http://127.0.0.1:8090/api/collections \
  -H "Authorization: Bearer ADMIN_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "contacts",
    "type": "base",
    "schema": [
      {
        "name": "work_email",
        "type": "email",
        "required": true,
        "options": {
          "exceptDomains": ["tempmail.com", "throwaway.email"]
        }
      },
      {
        "name": "corporate_email",
        "type": "email",
        "options": {
          "onlyDomains": ["company.com", "company.cn"]
        }
      }
    ]
  }'
```

**验证规则：**
- 自动验证邮箱格式（RFC 5322 标准）
- `exceptDomains` 和 `onlyDomains` 互斥，只能设置其中之一
- 不区分大小写

## 4.7 URL 字段

URL 字段用于存储网址链接，内置 URL 格式验证。

### 配置选项

| 选项 | 类型 | 说明 |
|------|------|------|
| `exceptDomains` | []string | 排除的域名列表 |
| `onlyDomains` | []string | 仅允许的域名列表 |

### 使用示例

```bash
# 创建包含 URL 字段的记录
curl -X POST http://127.0.0.1:8090/api/collections/bookmarks/records \
  -H "Content-Type: application/json" \
  -d '{
    "title": "PocketBase 官方文档",
    "url": "https://pocketbase.io/docs",
    "source_url": "https://github.com/pocketbase/pocketbase"
  }'
```

**验证规则：**
- 必须包含协议前缀（`http://` 或 `https://`）
- 自动验证 URL 格式是否合法
- 支持域名白名单/黑名单控制

## 4.8 Date 字段

Date 字段用于存储日期和时间信息。

### 配置选项

| 选项 | 类型 | 说明 |
|------|------|------|
| `min` | string | 最早允许的日期时间 |
| `max` | string | 最晚允许的日期时间 |

### 使用示例

```bash
# 创建带日期字段的集合
curl -X POST http://127.0.0.1:8090/api/collections \
  -H "Authorization: Bearer ADMIN_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "events",
    "type": "base",
    "schema": [
      {
        "name": "event_name",
        "type": "text",
        "required": true
      },
      {
        "name": "start_time",
        "type": "date",
        "required": true,
        "options": {
          "min": "2024-01-01 00:00:00.000Z"
        }
      },
      {
        "name": "end_time",
        "type": "date",
        "options": {
          "min": "2024-01-01 00:00:00.000Z",
          "max": "2030-12-31 23:59:59.999Z"
        }
      }
    ]
  }'
```

### 时区处理

PocketBase 内部统一使用 **UTC 时间** 存储所有日期时间数据。

```javascript
// JavaScript SDK 中的时区处理
const record = await pb.collection('events').create({
  event_name: '技术分享会',
  // 客户端需要将本地时间转换为 UTC
  start_time: new Date('2024-06-15T14:00:00+08:00').toISOString()
});

// 显示时转换回本地时间
const localTime = new Date(record.start_time).toLocaleString('zh-CN', {
  timeZone: 'Asia/Shanghai'
});
console.log(localTime); // 2024/6/15 14:00:00
```

**注意事项：**
- 日期格式为 `YYYY-MM-DD HH:MM:SS.sssZ`
- 前端显示时务必进行时区转换
- 空日期字段返回空字符串 `""`

## 4.9 Select 字段

Select 字段提供预定义选项的单选或多选功能。

### 配置选项

| 选项 | 类型 | 说明 |
|------|------|------|
| `values` | []string | 可选值列表 |
| `maxSelect` | int | 最大可选数量，1 为单选 |

### 使用示例

```bash
# 单选字段
{
  "name": "status",
  "type": "select",
  "required": true,
  "options": {
    "maxSelect": 1,
    "values": ["draft", "published", "archived"]
  }
}

# 多选字段
{
  "name": "tags",
  "type": "select",
  "options": {
    "maxSelect": 5,
    "values": ["技术", "生活", "旅行", "美食", "音乐", "电影", "读书"]
  }
}
```

```bash
# 创建带多选字段的记录
curl -X POST http://127.0.0.1:8090/api/collections/posts/records \
  -H "Content-Type: application/json" \
  -d '{
    "title": "我的旅行日记",
    "status": "published",
    "tags": ["旅行", "生活", "美食"]
  }'
```

**过滤查询示例：**

```bash
# 查询包含特定标签的记录
curl "http://127.0.0.1:8090/api/collections/posts/records?filter=(tags~'旅行')"

# 查询状态为已发布的记录
curl "http://127.0.0.1:8090/api/collections/posts/records?filter=(status='published')"
```

**注意事项：**
- 单选字段（`maxSelect: 1`）返回字符串
- 多选字段（`maxSelect > 1`）返回字符串数组
- 选项值只能是字符串类型

## 4.10 Relation 字段

Relation 字段用于建立集合之间的关联关系，类似于关系型数据库中的外键。

### 配置选项

| 选项 | 类型 | 说明 |
|------|------|------|
| `collectionId` | string | 关联的目标集合 ID |
| `cascadeDelete` | bool | 是否级联删除 |
| `minSelect` | int | 最少关联数量 |
| `maxSelect` | int | 最大关联数量，1 为单关联 |

### 单关联示例（一对一 / 多对一）

```bash
# 文章关联作者（多对一）
{
  "name": "author",
  "type": "relation",
  "required": true,
  "options": {
    "collectionId": "USERS_COLLECTION_ID",
    "cascadeDelete": false,
    "maxSelect": 1
  }
}
```

```bash
# 创建文章并关联作者
curl -X POST http://127.0.0.1:8090/api/collections/posts/records \
  -H "Content-Type: application/json" \
  -d '{
    "title": "PocketBase 教程",
    "author": "USER_RECORD_ID",
    "content": "..."
  }'
```

### 多关联示例（多对多）

```bash
# 文章关联多个标签（多对多）
{
  "name": "categories",
  "type": "relation",
  "options": {
    "collectionId": "CATEGORIES_COLLECTION_ID",
    "cascadeDelete": false,
    "maxSelect": 10
  }
}
```

```bash
# 创建文章并关联多个分类
curl -X POST http://127.0.0.1:8090/api/collections/posts/records \
  -H "Content-Type: application/json" \
  -d '{
    "title": "跨领域技术分享",
    "categories": ["cat_id_001", "cat_id_002", "cat_id_003"]
  }'
```

### 级联删除

当设置 `cascadeDelete: true` 时：
- 删除被关联的记录时，所有引用该记录的记录也会被自动删除
- 适用于强依赖关系，例如「删除用户时同时删除其所有文章」
- **谨慎使用**，避免意外数据丢失

```bash
# 带级联删除的关联
{
  "name": "order_items",
  "type": "relation",
  "options": {
    "collectionId": "ITEMS_COLLECTION_ID",
    "cascadeDelete": true,
    "maxSelect": null
  }
}
```

### 展开关联数据

通过 API 查询时，使用 `expand` 参数可以将关联的记录数据一并返回：

```bash
# 查询文章并展开作者信息
curl "http://127.0.0.1:8090/api/collections/posts/records?expand=author"

# 多层级展开
curl "http://127.0.0.1:8090/api/collections/posts/records?expand=author,categories"
```

## 4.11 File 字段

File 字段用于处理文件上传，支持图片、文档等各类文件。

### 配置选项

| 选项 | 类型 | 说明 |
|------|------|------|
| `maxSelect` | int | 最大文件数量 |
| `maxSize` | int | 单个文件最大大小（字节） |
| `mimeTypes` | []string | 允许的 MIME 类型 |
| `thumbs` | []string | 缩略图配置（仅图片） |
| `protected` | bool | 是否需要认证才能访问 |

### 使用示例

```bash
# 图片上传字段配置
{
  "name": "cover_image",
  "type": "file",
  "options": {
    "maxSelect": 1,
    "maxSize": 5242880,
    "mimeTypes": [
      "image/jpeg",
      "image/png",
      "image/webp",
      "image/gif"
    ],
    "thumbs": ["100x100", "300x200", "640x0"]
  }
}

# 多文件上传字段配置
{
  "name": "attachments",
  "type": "file",
  "options": {
    "maxSelect": 10,
    "maxSize": 10485760,
    "mimeTypes": [
      "application/pdf",
      "application/msword",
      "application/vnd.openxmlformats-officedocument.wordprocessingml.document",
      "image/jpeg",
      "image/png"
    ],
    "protected": true
  }
}
```

### 上传文件

文件上传必须使用 `multipart/form-data` 格式：

```bash
# 上传单个文件
curl -X POST http://127.0.0.1:8090/api/collections/posts/records \
  -H "Authorization: Bearer USER_TOKEN" \
  -F "title=带封面的文章" \
  -F "cover_image=@/path/to/image.jpg"

# 上传多个文件
curl -X POST http://127.0.0.1:8090/api/collections/posts/records \
  -H "Authorization: Bearer USER_TOKEN" \
  -F "title=带附件的文章" \
  -F "attachments=@/path/to/doc1.pdf" \
  -F "attachments=@/path/to/doc2.pdf" \
  -F "attachments=@/path/to/image.png"
```

### 访问文件

文件通过以下 URL 格式访问：

```
http://127.0.0.1:8090/api/files/{collectionId}/{recordId}/{filename}
```

**缩略图访问：**

```
# 原图
http://127.0.0.1:8090/api/files/posts/RECORD_ID/cover.jpg

# 100x100 缩略图
http://127.0.0.1:8090/api/files/posts/RECORD_ID/cover.jpg?thumb=100x100

# 宽度为 640，高度自适应
http://127.0.0.1:8090/api/files/posts/RECORD_ID/cover.jpg?thumb=640x0
```

### 缩略图配置说明

| 格式 | 说明 |
|------|------|
| `100x100` | 裁剪为 100×100 像素 |
| `300x200` | 裁剪为 300×200 像素 |
| `640x0` | 宽度 640，高度等比缩放 |
| `0x480` | 高度 480，宽度等比缩放 |
| `100x100t` | 居中裁剪为 100×100 |
| `100x100b` | 底部裁剪为 100×100 |
| `100x100f` | 适应(fit) 100×100 |

**注意事项：**
- 文件存储在 `pb_data/storage` 目录下
- 单个文件字段（`maxSelect: 1`）返回文件名字符串
- 多文件字段（`maxSelect > 1`）返回文件名数组
- 设置 `protected: true` 后，访问文件需要有效 token

## 4.12 JSON 字段

JSON 字段用于存储任意结构的 JSON 数据，适合存储灵活的、不固定结构的数据。

### 配置选项

| 选项 | 类型 | 说明 |
|------|------|------|
| `maxSize` | int | JSON 数据最大大小（字节） |

### 使用示例

```bash

        "sms": true
```

可以在过滤条件中通过点号语法访问 JSON 内部字段：


## 4.14 Autodate 字段

Autodate 字段会在记录创建或更新时自动设置为当前日期时间。

### 配置选项

| 选项 | 类型 | 说明 |
|------|------|------|
| `onCreate` | bool | 创建记录时自动设置 |
| `onUpdate` | bool | 更新记录时自动设置 |


- 该字段值不能通过 API 手动设置，完全由系统自动管理

## 4.15 字段索引与唯一性约束

### 创建索引

PocketBase 支持在字段上创建索引以提高查询性能。

```bash
# 通过 API 创建索引
curl -X PATCH http://127.0.0.1:8090/api/collections/posts \
  -H "Authorization: Bearer ADMIN_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "indexes": [
      "CREATE INDEX idx_posts_title ON posts (title)",
      "CREATE UNIQUE INDEX idx_posts_slug ON posts (slug)",
      "CREATE INDEX idx_posts_status_created ON posts (status, created)"
    ]
  }'
```

### 索引类型

| 类型 | SQL 语法 | 说明 |
|------|----------|------|
| 普通索引 | `CREATE INDEX` | 加速查询，允许重复值 |
| 唯一索引 | `CREATE UNIQUE INDEX` | 加速查询且保证值唯一 |
| 复合索引 | 多字段索引 | 加速多字段组合查询 |

### 唯一性约束

```bash
# 确保 slug 字段全局唯一
"CREATE UNIQUE INDEX idx_unique_slug ON posts (slug)"

# 确保同一作者下的文章标题唯一
"CREATE UNIQUE INDEX idx_unique_author_title ON posts (author, title)"
```

**注意事项：**
- 索引通过 Admin UI 的「索引」选项卡管理更加直观
- 过多的索引会影响写入性能
- 经常在 `filter` 和 `sort` 中使用的字段应该建立索引
- 唯一索引同时兼具查询加速和数据约束的功能

## 4.16 字段验证规则详解

PocketBase 提供了丰富的字段验证功能，确保数据质量。

### 内置验证

每种字段类型都有相应的内置验证：

| 字段类型 | 内置验证 |
|----------|----------|
| Text | 长度范围、正则模式 |
| Number | 数值范围、整数约束 |
| Email | RFC 5322 邮箱格式 |
| URL | 合法 URL 格式 |
| Date | 日期范围 |
| Select | 值必须在预定义选项中 |
| File | MIME 类型、文件大小 |
| JSON | 合法 JSON 格式 |
| Relation | 关联记录必须存在 |

### required 验证

```bash
# 必填字段
{
  "name": "title",
  "type": "text",
  "required": true
}
```

`required: true` 的行为因字段类型而异：
- **Text**：不能为空字符串
- **Number**：不能为 `0`（如果 0 是有效值，请勿设置 required）
- **Bool**：必须为 `true`
- **Relation**：必须关联至少一条记录
- **File**：必须上传至少一个文件
- **Select**：必须选择至少一个选项

### API 规则中的字段验证

可以在集合的 API 规则中使用字段条件进行更复杂的验证：

```
# 只允许修改自己的记录
@request.auth.id = author

# 只允许已验证的用户创建记录
@request.auth.verified = true

# 验证关联字段引用的记录满足条件
@request.data.category.active = true
```

### 完整的字段验证示例

```bash
# 创建一个具有丰富验证规则的集合
curl -X POST http://127.0.0.1:8090/api/collections \
  -H "Authorization: Bearer ADMIN_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "orders",
    "type": "base",
    "schema": [
      {
        "name": "order_no",
        "type": "text",
        "required": true,
        "options": {
          "min": 10,
          "max": 20,
          "pattern": "^ORD-[0-9]{8,}$"
        }
      },
      {
        "name": "amount",
        "type": "number",
        "required": true,
        "options": {
          "min": 0.01,
          "max": 9999999.99
        }
      },
      {
        "name": "status",
        "type": "select",
        "required": true,
        "options": {
          "maxSelect": 1,
          "values": ["pending", "paid", "shipped", "delivered", "cancelled"]
        }
      },
      {
        "name": "customer_email",
        "type": "email",
        "required": true,
        "options": {
          "exceptDomains": ["tempmail.com"]
        }
      },
      {
        "name": "shipping_address",
        "type": "json",
        "required": true,
        "options": {
          "maxSize": 2048
        }
      },
      {
        "name": "items",
        "type": "relation",
        "required": true,
        "options": {
          "collectionId": "PRODUCTS_COLLECTION_ID",
          "maxSelect": 50
        }
      }
    ],
    "indexes": [
      "CREATE UNIQUE INDEX idx_order_no ON orders (order_no)",
      "CREATE INDEX idx_order_status ON orders (status)",
      "CREATE INDEX idx_order_created ON orders (created)"
    ]
  }'
```

## 本章小结

本章详细介绍了 PocketBase 的三种集合类型（Base、Auth、View）以及所有内置字段类型的配置选项和使用方法。关键要点：

1. **Base 集合**适用于普通业务数据，**Auth 集合**专用于用户认证，**View 集合**用于创建只读的虚拟视图
2. 系统字段 `id`、`created`、`updated` 自动管理，无需手动维护
3. 每种字段类型都有特定的验证选项，合理配置可以保证数据质量
4. **Relation 字段**是建立数据关联的关键，支持单关联和多关联
5. **File 字段**提供了完善的文件上传管理功能，包括缩略图自动生成
6. 合理使用索引和唯一性约束可以提升查询性能并保证数据完整性
