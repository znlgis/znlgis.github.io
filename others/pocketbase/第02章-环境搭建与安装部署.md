# 第02章 环境搭建与安装部署

本章将详细介绍PocketBase的安装、部署和开发环境配置。无论你使用的是Windows、macOS还是Linux，都能按照本章的指南快速搭建PocketBase运行环境。

---

## 2.1 系统要求

### 2.1.1 支持的操作系统

PocketBase提供以下平台的预编译二进制文件：

| 操作系统 | 架构 | 文件名示例 |
|---------|------|-----------|
| **Linux** | amd64 (x86_64) | `pocketbase_0.25.0_linux_amd64.zip` |
| **Linux** | arm64 (aarch64) | `pocketbase_0.25.0_linux_arm64.zip` |
| **macOS** | amd64 (Intel) | `pocketbase_0.25.0_darwin_amd64.zip` |
| **macOS** | arm64 (Apple Silicon) | `pocketbase_0.25.0_darwin_arm64.zip` |
| **Windows** | amd64 (x86_64) | `pocketbase_0.25.0_windows_amd64.zip` |
| **Windows** | arm64 | `pocketbase_0.25.0_windows_arm64.zip` |

### 2.1.2 硬件要求

PocketBase对硬件要求极低：

| 资源 | 最低要求 | 推荐配置 | 生产环境 |
|------|---------|---------|---------|
| **CPU** | 1核 | 2核 | 2核+ |
| **内存** | 128MB | 512MB | 1GB+ |
| **磁盘** | 100MB(程序) | 10GB SSD | 根据数据量 |
| **网络** | 无特殊要求 | 稳定连接 | 固定IP/域名 |

> **提示**：PocketBase在树莓派(Raspberry Pi)等ARM设备上也能良好运行，非常适合边缘计算和物联网场景。

### 2.1.3 端口要求

PocketBase默认使用以下端口：

- **8090**：HTTP服务端口(默认)
- 可通过`--http`参数自定义端口
- 支持HTTPS，可通过`--https`参数配置

```bash
# 默认端口
./pocketbase serve
# 服务运行在 http://127.0.0.1:8090

# 自定义端口
./pocketbase serve --http=0.0.0.0:9090
# 服务运行在 http://0.0.0.0:9090
```

## 2.2 下载与安装

### 2.2.1 从GitHub Releases下载

PocketBase的所有版本都发布在GitHub Releases页面：

**下载地址**：https://github.com/pocketbase/pocketbase/releases

选择与你的操作系统和CPU架构匹配的压缩包进行下载。

### 2.2.2 Linux安装步骤

```bash
# 1. 创建安装目录
mkdir -p /opt/pocketbase
cd /opt/pocketbase

# 2. 下载最新版本(以v0.25.0为例)
wget https://github.com/pocketbase/pocketbase/releases/download/v0.25.0/pocketbase_0.25.0_linux_amd64.zip

# 3. 解压
unzip pocketbase_0.25.0_linux_amd64.zip

# 4. 赋予执行权限
chmod +x pocketbase

# 5. 验证安装
./pocketbase --version
# 输出: pocketbase version 0.25.0

# 6. 清理压缩包
rm pocketbase_0.25.0_linux_amd64.zip
```

**ARM64架构(如树莓派4)：**

```bash
wget https://github.com/pocketbase/pocketbase/releases/download/v0.25.0/pocketbase_0.25.0_linux_arm64.zip
unzip pocketbase_0.25.0_linux_arm64.zip
chmod +x pocketbase
```

### 2.2.3 macOS安装步骤

**方法一：手动下载安装**

```bash
# Apple Silicon (M1/M2/M3)
curl -LO https://github.com/pocketbase/pocketbase/releases/download/v0.25.0/pocketbase_0.25.0_darwin_arm64.zip

# Intel Mac
curl -LO https://github.com/pocketbase/pocketbase/releases/download/v0.25.0/pocketbase_0.25.0_darwin_amd64.zip

# 解压
unzip pocketbase_0.25.0_darwin_arm64.zip

# 验证
./pocketbase --version
```

**方法二：使用Homebrew(社区维护)**

```bash
# 注意：这是社区维护的tap，可能不是最新版本
brew install pocketbase/tap/pocketbase

# 或手动管理
mkdir ~/pocketbase && cd ~/pocketbase
# 下载并解压...
```

> **macOS安全提示**：首次运行时，macOS可能会提示"无法验证开发者"。解决方法：
> 1. 在"系统偏好设置" → "安全性与隐私"中点击"仍要打开"
> 2. 或者使用命令：`xattr -d com.apple.quarantine ./pocketbase`

### 2.2.4 Windows安装步骤

```powershell
# 1. 创建安装目录
mkdir C:\pocketbase
cd C:\pocketbase

# 2. 使用PowerShell下载
Invoke-WebRequest -Uri "https://github.com/pocketbase/pocketbase/releases/download/v0.25.0/pocketbase_0.25.0_windows_amd64.zip" -OutFile "pocketbase.zip"

# 3. 解压
Expand-Archive -Path "pocketbase.zip" -DestinationPath "."

# 4. 验证安装
.\pocketbase.exe --version

# 5. 清理
Remove-Item "pocketbase.zip"
```

也可以直接从浏览器访问GitHub Releases页面下载ZIP文件，然后解压到任意目录。

### 2.2.5 使用安装脚本(Linux/macOS)

可以编写一个自动化安装脚本：

```bash
#!/bin/bash
# install_pocketbase.sh - PocketBase自动安装脚本

VERSION="0.25.0"
INSTALL_DIR="/opt/pocketbase"

# 检测系统和架构
OS=$(uname -s | tr '[:upper:]' '[:lower:]')
ARCH=$(uname -m)

case "$ARCH" in
    x86_64)  ARCH="amd64" ;;
    aarch64) ARCH="arm64" ;;
    arm64)   ARCH="arm64" ;;
    *)       echo "不支持的架构: $ARCH"; exit 1 ;;
esac

case "$OS" in
    linux)  OS="linux" ;;
    darwin) OS="darwin" ;;
    *)      echo "不支持的操作系统: $OS"; exit 1 ;;
esac

FILENAME="pocketbase_${VERSION}_${OS}_${ARCH}.zip"
URL="https://github.com/pocketbase/pocketbase/releases/download/v${VERSION}/${FILENAME}"

echo "下载 PocketBase v${VERSION} (${OS}/${ARCH})..."
mkdir -p "$INSTALL_DIR"
cd "$INSTALL_DIR"
curl -LO "$URL"
unzip -o "$FILENAME"
chmod +x pocketbase
rm "$FILENAME"

echo "PocketBase 已安装到 ${INSTALL_DIR}"
./pocketbase --version
```

使用方法：

```bash
chmod +x install_pocketbase.sh
sudo ./install_pocketbase.sh
```

## 2.3 首次启动

### 2.3.1 启动PocketBase

```bash
# 基本启动命令
./pocketbase serve

# 输出示例：
# 2024/01/15 10:30:00 Server started at http://127.0.0.1:8090
#   - REST API: http://127.0.0.1:8090/api/
#   - Admin UI: http://127.0.0.1:8090/_/
```

默认情况下，PocketBase会：
- 在当前目录创建`pb_data/`目录存放数据
- 在端口`8090`上启动HTTP服务
- 仅监听`127.0.0.1`(本地回环地址)

### 2.3.2 创建管理员账号

首次访问管理面板时，需要创建管理员账号：

1. 在浏览器中打开 `http://127.0.0.1:8090/_/`
2. 系统会自动跳转到管理员创建页面
3. 输入管理员邮箱和密码
4. 点击"Create"完成创建

也可以通过命令行创建管理员：

```bash
# 交互式创建管理员
./pocketbase superuser create

# 指定邮箱和密码创建
./pocketbase superuser create admin@example.com yourpassword123
```

> **安全提醒**：
> - 管理员密码至少10个字符
> - 在生产环境中请使用强密码
> - 管理员邮箱将用于登录Admin UI

### 2.3.3 监听所有网络接口

默认情况下PocketBase只监听本地地址(127.0.0.1)。要让其他设备也能访问，需要监听所有接口：

```bash
# 监听所有网络接口
./pocketbase serve --http=0.0.0.0:8090

# 使用自定义端口
./pocketbase serve --http=0.0.0.0:3000
```

> **安全警告**：在生产环境中，强烈建议在PocketBase前面配置反向代理(如Nginx或Caddy)，而不是直接暴露PocketBase到公网。

### 2.3.4 验证服务运行

```bash
# 检查API健康状态
curl http://127.0.0.1:8090/api/health

# 返回示例：
# {"code":200,"message":"API is healthy."}

# 检查集合列表（需要认证）
curl http://127.0.0.1:8090/api/collections \
  -H "Authorization: Bearer ADMIN_TOKEN"
```

## 2.4 命令行参数详解

### 2.4.1 主要命令

PocketBase可执行文件支持以下主要命令：

```bash
# 查看帮助
./pocketbase --help

# 输出：
# PocketBase CLI
#
# Usage:
#   pocketbase [command]
#
# Available Commands:
#   serve       启动Web服务器
#   superuser   管理超级用户(管理员)
#   help        帮助信息
```

### 2.4.2 serve命令详解

`serve`是最常用的命令，用于启动PocketBase服务：

```bash
./pocketbase serve [flags]
```

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `--http` | `127.0.0.1:8090` | HTTP监听地址和端口 |
| `--https` | (空) | HTTPS监听地址和端口 |
| `--dir` | `./pb_data` | 数据目录路径 |
| `--publicDir` | `./pb_public` | 静态文件目录路径 |
| `--hooksDir` | `./pb_hooks` | JavaScript钩子目录路径 |
| `--migrationsDir` | `./pb_migrations` | 迁移文件目录路径 |
| `--dev` | `false` | 开发模式，启用更详细的日志 |

**使用示例：**

```bash
# 开发模式启动
./pocketbase serve --dev

# 自定义数据目录
./pocketbase serve --dir=/var/lib/pocketbase/data

# 指定HTTPS(自动Let's Encrypt证书)
./pocketbase serve --https=yourdomain.com:443

# 同时指定HTTP和HTTPS
./pocketbase serve \
  --http=0.0.0.0:80 \
  --https=0.0.0.0:443

# 完整的生产环境启动示例
./pocketbase serve \
  --http=0.0.0.0:8090 \
  --dir=/data/pocketbase/pb_data \
  --publicDir=/data/pocketbase/pb_public \
  --hooksDir=/data/pocketbase/pb_hooks \
  --migrationsDir=/data/pocketbase/pb_migrations
```

### 2.4.3 superuser命令

用于管理超级用户(管理员)账号：

```bash
# 创建管理员
./pocketbase superuser create admin@example.com password123

# 修改管理员密码
./pocketbase superuser update admin@example.com newpassword456

# 删除管理员
./pocketbase superuser delete admin@example.com

# 列出所有管理员
./pocketbase superuser list
```

### 2.4.4 开发模式

开发模式(`--dev`)提供以下额外功能：

- 更详细的日志输出
- 自动重载JavaScript钩子文件(修改后无需重启)
- 显示更详细的错误信息

```bash
# 开发模式启动
./pocketbase serve --dev

# 推荐在开发阶段始终使用开发模式
```

## 2.5 目录结构说明

### 2.5.1 总览

PocketBase启动后会在工作目录中创建以下目录结构：

```
项目根目录/
├── pocketbase              # PocketBase可执行文件
├── pb_data/                # 数据目录(自动创建)
│   ├── data.db             # 主数据库文件(SQLite)
│   ├── logs.db             # 日志数据库文件
│   ├── auxiliary.db        # 辅助数据库文件
│   ├── storage/            # 文件存储目录
│   │   └── <collection_id>/
│   │       └── <record_id>/
│   │           └── uploaded_file.jpg
│   └── types.d.ts          # TypeScript类型定义(用于JS钩子)
├── pb_public/              # 静态文件目录(可选，手动创建)
│   ├── index.html
│   ├── css/
│   └── js/
├── pb_hooks/               # JavaScript钩子目录(可选，手动创建)
│   ├── main.pb.js
│   └── utils.pb.js
└── pb_migrations/          # 迁移文件目录(可选，手动创建)
    ├── 1700000000_init.js
    └── 1700000001_add_posts.js
```

### 2.5.2 pb_data/ - 数据目录

这是PocketBase最重要的目录，包含所有持久化数据：

```bash
pb_data/
├── data.db            # SQLite主数据库，存储所有集合和记录数据
├── data.db-shm        # SQLite共享内存文件(运行时产生)
├── data.db-wal        # SQLite WAL日志文件(运行时产生)
├── logs.db            # 请求日志数据库
├── auxiliary.db       # 辅助数据(如cron任务状态等)
├── storage/           # 上传文件的存储目录
│   └── <集合ID>/
│       └── <记录ID>/
│           ├── image_abc123.jpg
│           └── thumb_100x100_image_abc123.jpg  # 自动生成的缩略图
└── types.d.ts         # 自动生成的TypeScript类型定义
```

> **备份要点**：备份PocketBase只需要备份整个`pb_data/`目录即可。建议在PocketBase停止运行时进行备份，以确保数据一致性。

```bash
# 简单备份脚本
#!/bin/bash
BACKUP_DIR="/backups/pocketbase"
DATE=$(date +%Y%m%d_%H%M%S)
mkdir -p "$BACKUP_DIR"

# 使用SQLite的.backup命令进行在线备份
sqlite3 /opt/pocketbase/pb_data/data.db ".backup '${BACKUP_DIR}/data_${DATE}.db'"

# 备份存储文件
tar czf "${BACKUP_DIR}/storage_${DATE}.tar.gz" /opt/pocketbase/pb_data/storage/

echo "备份完成: ${BACKUP_DIR}"
```

### 2.5.3 pb_public/ - 静态文件目录

此目录用于托管静态前端文件。PocketBase会自动将该目录下的文件作为静态资源提供服务：

```bash
# 创建静态文件目录
mkdir pb_public

# 放入前端文件
echo '<html><body><h1>欢迎使用PocketBase</h1></body></html>' > pb_public/index.html
```

访问 `http://127.0.0.1:8090/` 就会显示 `pb_public/index.html` 的内容。

这使得PocketBase可以同时充当API服务器和静态文件服务器，非常适合部署单页应用(SPA)：

```bash
# 部署Vue/React/Svelte应用
# 1. 构建前端项目
cd my-frontend-project
npm run build

# 2. 将构建产物复制到pb_public
cp -r dist/* /opt/pocketbase/pb_public/
```

### 2.5.4 pb_hooks/ - JavaScript钩子目录

此目录用于存放JavaScript扩展文件。PocketBase会自动加载所有以`.pb.js`结尾的文件：

```bash
mkdir pb_hooks

# 创建钩子文件
cat > pb_hooks/main.pb.js << 'EOF'
// 自定义API路由
routerAdd("GET", "/api/hello", (e) => {
    return e.json(200, {
        message: "你好，PocketBase！",
        timestamp: new Date().toISOString()
    });
});

// 记录创建前的钩子
onRecordCreate((e) => {
    console.log("新记录被创建:", e.record.id);
    e.next();
});

// 定时任务
cronAdd("dailyCleanup", "0 2 * * *", () => {
    console.log("执行每日清理任务...");
});
EOF
```

> **注意**：在开发模式(`--dev`)下，修改钩子文件后会自动重载。在生产模式下，修改后需要重启PocketBase。

### 2.5.5 pb_migrations/ - 迁移文件目录

迁移文件用于以代码方式管理数据库结构变更，便于版本控制和团队协作：

```bash
mkdir pb_migrations

# 迁移文件示例
cat > pb_migrations/1700000001_create_posts.js << 'EOF'
// pb_migrations/1700000001_create_posts.js

migrate((app) => {
    const collection = new Collection({
        name: "posts",
        type: "base",
        fields: [
            {
                name: "title",
                type: "text",
                required: true,
            },
            {
                name: "content",
                type: "editor",
            },
            {
                name: "published",
                type: "bool",
                required: false,
            }
        ]
    });

    return app.save(collection);
}, (app) => {
    // 回滚操作
    const collection = app.findCollectionByNameOrId("posts");
    return app.delete(collection);
});
EOF
```

## 2.6 使用Go编译安装

### 2.6.1 为什么需要Go编译

在以下场景中，你可能需要从源码编译PocketBase：

- 需要对PocketBase进行Go语言级别的深度定制
- 需要集成自定义的Go模块
- 使用不受官方预编译支持的平台
- 希望优化特定平台的编译参数

### 2.6.2 Go环境准备

```bash
# 1. 安装Go语言(需要 Go 1.23+)
# Linux
wget https://go.dev/dl/go1.23.4.linux-amd64.tar.gz
sudo tar -C /usr/local -xzf go1.23.4.linux-amd64.tar.gz
export PATH=$PATH:/usr/local/go/bin

# macOS (使用Homebrew)
brew install go

# 验证Go安装
go version
# 输出: go version go1.23.4 linux/amd64
```

### 2.6.3 创建自定义PocketBase项目

```bash
# 1. 创建项目目录
mkdir my-pocketbase && cd my-pocketbase

# 2. 初始化Go模块
go mod init my-pocketbase

# 3. 创建主文件
cat > main.go << 'GOEOF'
package main

import (
    "log"

    "github.com/pocketbase/pocketbase"
    "github.com/pocketbase/pocketbase/core"
)

func main() {
    app := pocketbase.New()

    // 自定义路由示例
    app.OnServe().BindFunc(func(se *core.ServeEvent) error {
        se.Router.GET("/api/custom/hello", func(e *core.RequestEvent) error {
            return e.JSON(200, map[string]string{
                "message": "你好，这是自定义PocketBase！",
            })
        })
        return se.Next()
    })

    if err := app.Start(); err != nil {
        log.Fatal(err)
    }
}
GOEOF

# 4. 下载依赖
go mod tidy

# 5. 编译
go build -o pocketbase .

# 6. 运行
./pocketbase serve
```

### 2.6.4 交叉编译

Go语言支持交叉编译，可以在一个平台上编译其他平台的可执行文件：

```bash
# 为Linux AMD64编译
GOOS=linux GOARCH=amd64 go build -o pocketbase_linux_amd64 .

# 为Linux ARM64编译
GOOS=linux GOARCH=arm64 go build -o pocketbase_linux_arm64 .

# 为macOS ARM64编译(Apple Silicon)
GOOS=darwin GOARCH=arm64 go build -o pocketbase_darwin_arm64 .

# 为Windows AMD64编译
GOOS=windows GOARCH=amd64 go build -o pocketbase_windows_amd64.exe .
```

### 2.6.5 编译优化

```bash
# 减小二进制文件大小
go build -ldflags="-s -w" -o pocketbase .

# 使用UPX进一步压缩(可选)
upx --best pocketbase

# 静态编译(Linux)
CGO_ENABLED=0 go build -ldflags="-s -w" -o pocketbase .
```

## 2.7 macOS/Linux系统服务配置

### 2.7.1 使用systemd配置服务(推荐)

在Linux服务器上，推荐使用systemd管理PocketBase服务：

```bash
# 1. 创建专用系统用户
sudo useradd -r -s /bin/false pocketbase

# 2. 设置目录权限
sudo mkdir -p /opt/pocketbase
sudo chown -R pocketbase:pocketbase /opt/pocketbase

# 3. 创建systemd服务文件
sudo cat > /etc/systemd/system/pocketbase.service << 'EOF'
[Unit]
Description=PocketBase Backend Service
After=network.target

[Service]
Type=simple
User=pocketbase
Group=pocketbase
WorkingDirectory=/opt/pocketbase
ExecStart=/opt/pocketbase/pocketbase serve --http=0.0.0.0:8090
Restart=on-failure
RestartSec=5s
LimitNOFILE=4096

# 安全加固选项
NoNewPrivileges=true
ProtectSystem=strict
ProtectHome=true
ReadWritePaths=/opt/pocketbase/pb_data
PrivateTmp=true

# 环境变量(可选)
# Environment=SMTP_HOST=smtp.example.com
# Environment=SMTP_PORT=587

[Install]
WantedBy=multi-user.target
EOF
```

### 2.7.2 管理systemd服务

```bash
# 重新加载systemd配置
sudo systemctl daemon-reload

# 启动PocketBase
sudo systemctl start pocketbase

# 停止PocketBase
sudo systemctl stop pocketbase

# 重启PocketBase
sudo systemctl restart pocketbase

# 查看运行状态
sudo systemctl status pocketbase

# 设置开机自启
sudo systemctl enable pocketbase

# 取消开机自启
sudo systemctl disable pocketbase

# 查看日志
sudo journalctl -u pocketbase -f
# 查看最近100行日志
sudo journalctl -u pocketbase -n 100
```

### 2.7.3 systemd服务文件的高级配置

```ini
[Unit]
Description=PocketBase Backend Service
After=network-online.target
Wants=network-online.target
Documentation=https://pocketbase.io/docs/

[Service]
Type=simple
User=pocketbase
Group=pocketbase
WorkingDirectory=/opt/pocketbase

# 主启动命令
ExecStart=/opt/pocketbase/pocketbase serve --http=0.0.0.0:8090

# 优雅关闭
ExecStop=/bin/kill -TERM $MAINPID
TimeoutStopSec=30

# 自动重启配置
Restart=on-failure
```

## 2.8 Windows服务配置

### 2.8.1 使用NSSM配置Windows服务

NSSM(Non-Sucking Service Manager)是在Windows上将程序注册为系统服务的常用工具。

```powershell
# 1. 下载NSSM
# 访问 https://nssm.cc/download 下载最新版本

# 2. 安装PocketBase为Windows服务
nssm install PocketBase "C:\pocketbase\pocketbase.exe" "serve --http=0.0.0.0:8090"

# 3. 配置服务参数
nssm set PocketBase AppDirectory "C:\pocketbase"
nssm set PocketBase Description "PocketBase Backend Service"
nssm set PocketBase Start SERVICE_AUTO_START
nssm set PocketBase AppStdout "C:\pocketbase\logs\stdout.log"
nssm set PocketBase AppStderr "C:\pocketbase\logs\stderr.log"
nssm set PocketBase AppRotateFiles 1
nssm set PocketBase AppRotateBytes 10485760

# 4. 启动服务
nssm start PocketBase
```

### 2.8.2 管理Windows服务

```powershell
# 使用NSSM管理
nssm start PocketBase      # 启动
nssm stop PocketBase       # 停止
nssm restart PocketBase    # 重启
nssm status PocketBase     # 查看状态
nssm remove PocketBase     # 移除服务

# 或使用Windows原生命令
net start PocketBase
net stop PocketBase
sc query PocketBase
```

### 2.8.3 使用PowerShell创建Windows服务

Windows自带的`sc.exe`命令也可以创建服务，但需要程序本身支持Windows Service接口。对于PocketBase，推荐使用NSSM或WinSW等包装工具。

**使用WinSW的替代方案：**

```xml
<!-- pocketbase-service.xml -->
<service>
  <id>pocketbase</id>
  <name>PocketBase</name>
  <description>PocketBase Backend Service</description>
  <executable>C:\pocketbase\pocketbase.exe</executable>
  <arguments>serve --http=0.0.0.0:8090</arguments>
  <workingdirectory>C:\pocketbase</workingdirectory>
  <log mode="roll-by-size">
    <sizeThreshold>10240</sizeThreshold>
    <keepFiles>8</keepFiles>
  </log>
</service>
```

```powershell
# 安装服务
winsw install pocketbase-service.xml

# 启动服务
winsw start pocketbase-service.xml
```

### 2.9.6 使用Makefile管理常用命令

```makefile
# Makefile

.PHONY: dev start stop backup clean

PB_DIR = ./backend
PB_BIN = $(PB_DIR)/pocketbase

# 开发模式启动
dev:
	cd $(PB_DIR) && ./pocketbase serve --dev

# 生产模式启动
start:
	cd $(PB_DIR) && ./pocketbase serve --http=0.0.0.0:8090

# 备份数据
backup:
	@mkdir -p backups
	@DATE=$$(date +%Y%m%d_%H%M%S); \
	cp -r $(PB_DIR)/pb_data "backups/pb_data_$$DATE"; \
	echo "备份完成: backups/pb_data_$$DATE"

# 创建管理员
admin:
	cd $(PB_DIR) && ./pocketbase superuser create

# 清理数据(危险!)
clean:
	@echo "警告: 这将删除所有数据!"
	@read -p "确认删除? (y/N): " confirm; \
	if [ "$$confirm" = "y" ]; then \
		rm -rf $(PB_DIR)/pb_data; \
		echo "数据已清理"; \
	fi
```

使用方法：

```bash
make dev      # 开发模式启动
make backup   # 备份数据
make admin    # 创建管理员
```
