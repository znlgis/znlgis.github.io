# 第12章 - 实战：开发一个新的典故

## 12.1 目标

前面十一章把 CHAGS 的每个零件都拆开讲过了。这一章把它们装回去：从零添加一个全新的典故「孔融让梨」，走完内容、游戏包、注册、测试、验证的完整流程。

- **id**：`kongrong`
- **定性**：信史（东汉），`yearApprox: 190`
- **动词**：让
- **玩法**：复用 `place` 模板（把东西放到它该去的地方）—— 三只大小不同的梨，一只只送到三位家人手里
- **预期改动**：内容 JSON、英文补丁、一个游戏包（5 个文件）、外壳注册两处、端到端用例一条

选 `place` 不是偷懒：模板库的设计目标就是「新典故优先复用，装不下再新增模板」（`place` 在项目文档里明确列过「孔融让梨、完璧归赵、负荆请罪」等复用面）。本章最后也给出「什么时候该新写模板」的判断。

### src/art.ts（全部画面由代码画）

```ts
import type Phaser from 'phaser';
import { THEME, circle, groundShadow, roundRect, shade } from '@chags/phaser-kit';

const PEAR_SIZE: Record<string, number> = { big: 54, mid: 42, small: 30 };

function drawPear(g: Phaser.GameObjects.Graphics, x: number, y: number, kind: string): void {
  const r = PEAR_SIZE[kind] ?? 40;
  g.fillStyle(THEME.leaf, 1);
  g.fillEllipse(x, y - r * 1.3, r * 0.9, r * 0.55);          // 叶子
  g.fillStyle(0xf5d76e, 1);
  g.fillEllipse(x, y, r * 1.7, r * 2.1);                     // 梨身
  g.lineStyle(6, THEME.outline, 1);
  g.strokeEllipse(x, y, r * 1.7, r * 2.1);
  g.fillStyle(shade(0xf5d76e, 0.86), 1);
  g.fillCircle(x - r * 0.4, y + r * 0.35, r * 0.28);         // 腮部阴影
}

/** 光球：一只梨，大小按 kind（big / mid / small） */
export function drawOrb(g: Phaser.GameObjects.Graphics, kind: string): void {
  drawPear(g, 0, 0, kind);
}

/** 槽位：三位家人；归位后手里多一只梨 */
export function drawPiece(
  g: Phaser.GameObjects.Graphics,
  kind: string,
  x: number,
  y: number,
  filled: boolean,
): void {
  const s = kind === 'second' ? 1.06 : 0.96;
  groundShadow(g, x, y + 96, 150 * s, 26, 0.14);
  roundRect(g, x - 54 * s, y - 60 * s, 108 * s, 150 * s, 44,
    kind === 'kong' ? THEME.red : THEME.teal, THEME.outline, 6);
  circle(g, x, y - 96 * s, 44 * s, THEME.sand, THEME.outline, 6);
  if (filled) {
    const size = kind === 'elder' ? 'big' : kind === 'second' ? 'mid' : 'small';
    drawPear(g, x + 70, y - 34, size);
  }
}

/** 分幕插图：第一幕一盘梨，第二幕三个孩子 */
export function drawBeat(
  g: Phaser.GameObjects.Graphics,
  index: number,
  rect: { x: number; y: number; w: number; h: number },
): void {
  const cx = rect.x + rect.w / 2;
  const cy = rect.y + rect.h / 2;
  if (index === 0) {
    roundRect(g, cx - 200, cy + 90, 400, 40, 20, THEME.wood, THEME.outline, 6);
    drawPear(g, cx - 90, cy + 20, 'big');
    drawPear(g, cx, cy + 52, 'mid');
    drawPear(g, cx + 90, cy + 76, 'small');
    return;
  }
  for (const [dx, h] of [[-170, 300], [-40, 330], [110, 190]] as const) {
    groundShadow(g, cx + dx, cy + 170, h * 0.7, 30, 0.14);
    roundRect(g, cx + dx - h * 0.18, cy + 170 - h, h * 0.36, h, 60, THEME.teal, THEME.outline, 6);
    circle(g, cx + dx, cy + 170 - h - 46, h * 0.22, THEME.sand, THEME.outline, 6);
  }
}
```

画法遵循第 8 章的工具箱约定：厚描边（`THEME.outline`）、落地阴影、每个梨三种尺寸（视觉上能直接看出大小）。后续要换真美术，只改这个文件。

### src/logic.test.ts

```ts
import { getAllusion } from '@chags/content';
import { isPlaceComplete, slotFor } from '@chags/templates/place.logic';
import { describe, expect, it } from 'vitest';
import { placeLevel } from './logic';

describe('孔融让梨 · 关卡数据', () => {
  const raw = getAllusion('kongrong');

  it('三位家人、三只梨，一一对应', () => {
    const level = placeLevel(raw!);
    expect(level.slots.length).toBe(3);
    expect(level.orbs.length).toBe(3);
    for (const orb of level.orbs) expect(slotFor(level, orb)).toBeTruthy();
  });

  it('最大的梨在大哥的槽位，最小的留给孔融', () => {
    const level = placeLevel(raw!);
    const orb = (id: string) => level.orbs.find((o) => o.id === id);
    expect(orb('pearBig')?.slotId).toBe('elder');
    expect(orb('pearSmall')?.slotId).toBe('kong');
  });

  it('每个梨归位时都有一句念白', () => {
    const level = placeLevel(raw!);
    for (const orb of level.orbs) expect(orb.speak.length).toBeGreaterThan(0);
  });

  it('集齐三只梨才算完成，重复归位不算', () => {
    const level = placeLevel(raw!);
    expect(isPlaceComplete(level, ['elder', 'second', 'kong'])).toBe(true);
    expect(isPlaceComplete(level, ['elder', 'elder', 'elder'])).toBe(false);
  });
});
```

## 12.9 什么时候该新写一个模板

复用优先，但遇到下面任一情况，就该按第 7 章 7.14 的清单新增模板（而不是硬塞进现有模板）：

- **判定语义不同**：`place` 判「放对位置」，如果玩法核心是「在正确的时间点动手」（守株待兔、一鼓作气），这是新模板 `timing`；
- **教学核心需要新的强制约束**：`sort` 的「先尝后分」是数据约束，不是表现效果 —— 塞进 `place` 会把教学核心降级成文案；
- **输入原语不存在**：棋盘对阵（田忌赛马）、剧情分支（完璧归赵）与现有任何模板都不共享判定；
- 同一段「定制代码」在两个典故里重复出现 —— 到第三个就该泛化，而不是复制。

判断标准可以归结为一句话：**新模板的价值是让第二个典故变便宜，否则它只是一次性代码。**

| 步骤 | 文件 | 校验者 |
|---|---|---|
| 1. 内容 JSON | `packages/content/src/allusions/kongrong.json` | `AllusionSchema`（构建期） |
| 2. 内容注册 | `allusions/index.ts` | 编译期 |
| 3. 英文补丁 | `i18n/en/kongrong.json` + `i18n/index.ts` | `content:check`（结构 / 长度 / 漏翻） |
| 4. 游戏包 ×5 | `games/kongrong/src/*` | `vue-tsc` / `eslint` / `vitest` |
| 5. 外壳注册 ×2 | `registry.ts` + `apps/site/package.json` | `registry.test.ts` |
| 6. 端到端 | `e2e/smoke.spec.ts` | Playwright |
| 7. 全量验证 | — | `pnpm verify` + `pnpm e2e` + `audit:i18n` |

内容先行、画面后补、测试兜底 —— 这套流程对「第 13 个典故」和「第 30 个典故」是一样的。
