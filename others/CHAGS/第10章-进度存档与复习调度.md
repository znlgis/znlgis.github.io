# 第10章 - 进度存档与复习调度

## 10.1 progress 包的位置

`packages/progress` 是「让孩子记住」这条主线的数据层：存档结构、迁移、星星、复习计划。它由四个文件组成，全是纯 TypeScript：

```
packages/progress/src/
├─ manager.ts     # ProgressManager：读档（single-flight）、迁移、通关与复习记录、到期查询、清档
├─ review.ts      # 复习调度：简化版 SM-2（间隔递增，答错降级）+ 天数换算
├─ review.test.ts # 15 项单测（调度 + 迁移 + 逐条容错 + 只增不减）
└─ index.ts
```

没有 Phaser、没有 DOM、没有 `Date.now()`（时钟由构造函数注入）—— 它满足「逻辑与渲染分离」铁律的最严格标准，因此可以在 Node 里被完整单测。整个复习链路里唯一与「界面」有关的纯逻辑是 `apps/site/src/review/quiz.ts`（小测验状态机），它同样不碰 DOM、不读时钟。

## 10.2 存档的数据结构

```ts
// packages/game-kit/src/contract.ts —— 类型定义在契约层
export const SAVE_SCHEMA_VERSION = 1;

export interface SaveData {
  schemaVersion: number;
  /**
   * 每条内容的进度，键是内容 id。
   * **字段名刻意保留 `allusions`**：改名会让所有老存档读不出来 ——
   * 玩家的星星不能因为一次重命名凭空消失。
   */
  allusions: Record<string, EntryProgress>;
  updatedAt: number;
}

export interface EntryProgress {
  entryId: string;
  stars: Stars;              // 0 | 1 | 2 | 3，只增不减
  completions: number;
  lastPlayedAt: number | null;
  review: ReviewState;
}

export interface ReviewState {
  level: number;             // 当前复习等级（对应 1/3/7/21/60 天）
  dueAt: number | null;      // 下次到期时间
  lastGrade: Stars | null;
  reviews: number;           // 累计复习次数
}
```

四个设计点：

- **整份存档是一个键（`save`）**：MVP 无后端、无并发写入，一个对象简单可靠；
- **`schemaVersion` 从第一天就有**，并且现在真的有迁移链了（下一节）；
- **`stars` 与 `review` 分离**：星星是给孩子的（只增不减），复习等级是给调度器的（可升可降），两个关注点不混在一个数字里；
- **字段名 `allusions` 刻意不改**：内容层已经从 `allusions` 改名为 `entries`，但存档字段一旦改名，所有老玩家的星星都会读不出来。类型与目录可以改，存档结构不能。

## 10.3 迁移：逐级升级，坏一条只丢一条

2026-10-18 之前这里是「版本不等 → 清空」：

```ts
// 旧实现（已删除）
if (data.schemaVersion !== SAVE_SCHEMA_VERSION) return emptySave(now);
```

对一个已经有真实用户的游戏来说，这等于「升级一次 = 清零一次」。现在的实现是一条迁移链：

```ts
/**
 * 存档迁移链：{ 旧版本号: 升到下一版的函数 }。
 *
 * 现在只有 v1，所以这张表是空的 —— 但流程先立起来：
 * 以后给 SaveData 加字段时，把 SAVE_SCHEMA_VERSION 改成 2，并在这里补一条
 * `1: (data) => ({ ...data, 新字段: 默认值 })`。老玩家的星星与复习计划会被
 * **升级**而不是清空。
 */
const MIGRATIONS: Record<number, (data: RawSave, now: number) => RawSave> = {};

export function migrate(raw: unknown, now: number): SaveData {
  if (!isRecord(raw)) return emptySave(now);
  const version = typeof raw.schemaVersion === 'number' ? raw.schemaVersion : 0;
  // 用新版玩过、又装回旧版：结构解释不了，不猜
  if (version > SAVE_SCHEMA_VERSION) return emptySave(now);

  let data: RawSave = raw;
  for (let from = version; from < SAVE_SCHEMA_VERSION; from += 1) {
    const step = MIGRATIONS[from];
    if (!step) return emptySave(now);
    data = step(data, now);
  }

  if (!isRecord(data.allusions)) return emptySave(now);
  // 键才是内容 id 的权威；老存档里的 entryId 字段可能缺、也可能过期
  const allusions: SaveData['allusions'] = {};
  for (const [id, value] of Object.entries(data.allusions)) {
    const entry = sanitizeEntry(id, value);
    if (entry !== null) allusions[id] = entry;
  }
  return { schemaVersion: SAVE_SCHEMA_VERSION, allusions, updatedAt: finiteNumber(data.updatedAt, now) };
}
```

三条规则值得记住：

1. **从版本 0 起逐级跑迁移**，缺任何一级的迁移函数就降到空档 —— 「宁可少数据，也不能拿读不懂的结构去炸界面」；
2. **来自未来版本的存档不猜**（用新版玩过又装回旧版），直接空档；
3. **逐条容错**：`sanitizeEntry()` 对每一条进度做体检（`stars` 夹到 0..3、`completions` 不小于 0、`review` 缺字段补默认），坏一条只丢这一条，不连累整份存档。

第 3 条是修出来的：以前这里是直接 `value.entryId` —— 一条 `null` 就能让读档在 IndexedDB 回调里抛异常，`init()` 的 promise 永远不 resolve，大厅一直显示 0 星。

## 10.4 ProgressManager：存档的唯一入口

```ts
export class ProgressManager {
  private readonly store: ProgressStore;
  private readonly clock: () => number;
  private data: SaveData;
  private loading: Promise<SaveData> | null = null;

  /**
   * 读档只做一次（single-flight）：界面可能从多个地方 await 它，
   * 重复读会把"刚写进去的进度"用旧快照盖掉。
   */
  init(): Promise<SaveData> {
    this.loading ??= (async () => {
      let raw: unknown;
      try { raw = await this.store.load(); } catch { raw = null; }
      this.data = migrate(raw, this.clock());
      return this.data;
    })();
    return this.loading;
  }

  /** 家长页的「清除本机存档」：清空并立刻落盘（界面上有长按确认，防误触） */
  async clear(): Promise<SaveData> {
    this.data = emptySave(this.clock());
    await this.store.save(this.data);
    return this.data;
  }

  /** 通关：记录星星（只增不减，对小朋友永远正向）与复习计划 */
  async recordCompletion(entryId: string, stars: Stars, grade: Stars): Promise<EntryProgress> {
    const now = this.clock();
    const prev = this.get(entryId);
    const next: EntryProgress = {
      ...prev,
      stars: Math.max(prev.stars, stars) as Stars,   // ★ 只增不减
      completions: prev.completions + 1,
      lastPlayedAt: now,
      review: nextReview(prev.review, grade, now),
    };
    this.data = { ...this.data, allusions: { ...this.data.allusions, [entryId]: next }, updatedAt: now };
    await this.store.save(this.data);
    return next;
  }

  /** 复习关卡的评分（不影响星星） */
  async recordReview(entryId: string, grade: Stars): Promise<EntryProgress> {
    const now = this.clock();
    const prev = this.get(entryId);
    const next: EntryProgress = { ...prev, lastPlayedAt: now, review: nextReview(prev.review, grade, now) };
    this.data = { ...this.data, allusions: { ...this.data.allusions, [entryId]: next }, updatedAt: now };
    await this.store.save(this.data);
    return next;
  }

  /** 到期待复习的内容条目（大厅横幅 / 图鉴徽章的输入） */
  due(entryIds: string[]): string[] { /* dueAt !== null && dueAt <= now */ }
}
```

- **不可变更新**（每次生成新对象再保存）：与 Vue 的响应式刷新天然合拍，快照一换视图自动更新；
- **`stars: Math.max(...)`**：重玩不会掉星；
- **`recordReview()` 一个字节都不碰 `stars`**：这是本轮最要紧的一条口径 —— 复习答错就扣星，等于把复习变成惩罚，孩子下次就不会点它了（10.6 详述）；
- **`due()` 是查询而非副作用**，现在有了三个消费方：大厅横幅、图鉴徽章、家长页（本周玩过什么）。

## 10.5 复习调度：简化版 SM-2

```ts
export const DAY_MS = 86_400_000;
/** 简化版 SM-2：间隔递增，答错降级 */
export const REVIEW_INTERVALS_DAYS: readonly number[] = [1, 3, 7, 21, 60];

export function nextReview(state: ReviewState, grade: 0 | 1 | 2 | 3, now: number): ReviewState {
  const maxLevel = REVIEW_INTERVALS_DAYS.length - 1;
  const level = grade >= 2 ? Math.min(state.level + 1, maxLevel) : Math.max(state.level - 1, 0);
  const days = REVIEW_INTERVALS_DAYS[level] ?? 1;
  return { level, dueAt: now + days * DAY_MS, lastGrade: grade, reviews: state.reviews + 1 };
}

export function isDue(state: ReviewState, now: number): boolean {
  return state.dueAt !== null && state.dueAt <= now;
}

/**
 * 距离下次复习还有几天 —— 结果页要显示"隔 n 天再来复习"。
 * 向上取整且至少 1：刚答完（dueAt 在未来）永远显示"1 天"以上。
 */
export function daysUntil(dueAt: number, now: number): number {
  return Math.max(1, Math.ceil((dueAt - now) / DAY_MS));
}

/**
 * 答对率 → 0..3 级，用于安排下次复习间隔。
 * 门槛刻意放宽（60% 即 2 级）：这是给小朋友的，宁可多复习一次，也不要打击信心。
 */
export function gradeFromScore(correct: number, total: number): 0 | 1 | 2 | 3 {
  if (total <= 0) return 0;
  const ratio = correct / total;
  if (ratio >= 1) return 3;
  if (ratio >= 0.6) return 2;
  if (ratio >= 0.3) return 1;
  return 0;
}
```

调度规则一句话概括：**答得不错就升级、间隔变长；答得不好就降级、很快再见**。

| 答对率 | 评级 | 等级变化 | 下次间隔 |
|---|---|---|---|
| 100% | 3 | +1 级（封顶） | 1 / 3 / 7 / 21 / 60 天中对应那一档 |
| ≥60% | 2 | +1 级（封顶） | 同上 |
| ≥30% | 1 | −1 级（最低 0） | 1 天 |
| <30% | 0 | −1 级（最低 0） | 1 天 |

「首次通关就写入 `dueAt`」这一点常被忽略：新内容第一次通关时 `level = 0`、`grade` 通常 ≥2，于是 `dueAt = now + 1 天` ——「明天再来看看」从第一局就成立，不需要等「学完一单元」。

`review.test.ts` 的 15 项单测覆盖了：升级 / 降级 / 封顶 / 下限 / `isDue` 边界 / `daysUntil` 取整 / `gradeFromScore` 四档与恰好压在阈值线上的情况（60% 是 2 级、30% 是 1 级）/ 分母为 0 不抛错 / 迁移链的四种坏档 / `stars` 只增不减 / `due()` 只返回到期且学过的内容。

## 10.6 到期复习：入口、评级与「不动星星」

§7.4 曾留过一句「复习测验全部没有生产调用方」：内容里每条 3 道题从来没有展示给玩家，`gradeFromScore` / `recordReview` / `due` 三个函数只有测试在用，`PlayView` 只能拿星星当评级。2026-10-16 这一轮把它做成了**到期复习**，而不是「每局结束考三题」。

### 入口：到期才出现，不到期不打扰

| 位置 | 表现 |
|---|---|
| 图鉴（`AlbumView.vue`） | 每张卡一个「复习」按钮（`data-testid="review-start-<id>"`）；到期时卡上多一枚「该复习了」徽章，顶部一句「有 n 个典故该复习了」 |
| 游戏馆（`HallView.vue`） | **只有真的有到期内容时**才显示一条横幅（`data-testid="hall-review"`），「去复习」直达第一部 |
| 路由 | `#/review/<id>`，与 `#/play/<id>` 共用同一个内容 id 空间 |

「不到期不出现」是刻意的：首页常年挂一句「该复习了」而其实没东西可复习，孩子很快就会学会无视它。

### 评级与间隔：只改「下次什么时候复习」

- 题目来自内容里的 `quiz`（每条 3 道，含 1 道 `transfer`；`content:check` 强制要求有迁移题）；
- 答完最后一题，`gradeFromScore(correct, total)` 把答对率折成 0..3 级，再交给 `nextReview()`：答对升一级、答错降一级，间隔按 **1 / 3 / 7 / 21 / 60 天**递增；
- **评级不动星星**：`ProgressManager.recordReview()` 只写 `review` 与 `lastPlayedAt`，`stars` 一个字节不碰。

为什么这条口径重要？星星是「这一局玩得怎么样」（只增不减，给孩子看），评级是「记得牢不牢」（决定下次什么时候再见）。复习答错就扣星星，等于把复习变成惩罚 —— 而「愿意主动点开复习」恰恰是这个功能唯一的成功指标。`Stars` 这个类型当初就写着「星星与复习评级共用」，这一轮才真的按这个口径用起来。

### 视图：为什么用 DOM，而不是复用 Phaser

`packages/templates/src/quiz.ts` 在这一轮被**删除**了，同一个功能不留两份实现。三条理由：

1. **三道题不值得再下一遍 Phaser**：引擎是 220 KB 的共享 chunk，为 3 个按钮再加载一次，代价与收益完全不成比例；
2. **DOM 能用原生按钮、键盘与读屏**：选项就是 `<button>`，对错反馈挂在 `aria-live="polite"` 上，Tab / 回车直接可用 —— 这些在 canvas 里都得自己重造；
3. 技术选型表里那句「纯 DOM/CSS 只用于图鉴、复习测验等非核心玩法」，到这一轮才真的兑现。

复习页的**纯逻辑**被单独放在 `apps/site/src/review/quiz.ts`，视图只负责画：

```ts
export interface ReviewQuizState {
  index: number;    // 当前第几题（0 起）。等于题数时表示答完了
  picked: number | null;
  correct: number;
}

/** 作答。同一题只认第一次 —— 界面同时会把选项按钮禁掉 */
export function pickOption(state, question, choice): ReviewQuizState {
  if (state.picked !== null) return state;
  return { ...state, picked: choice, correct: state.correct + (isRight(question, choice) ? 1 : 0) };
}

/** 这一题看完了 → 下一题；没作答时不动 */
export function nextQuestion(state, total): ReviewQuizState {
  if (state.picked === null) return state;
  return { ...state, index: Math.min(state.index + 1, total), picked: null };
}

/** 这一局算几级（0..3）—— 决定下次复习间隔 */
export function gradeOf(state, total): 0 | 1 | 2 | 3 {
  return gradeFromScore(state.correct, total);
}
```

`quiz.test.ts` 的 8 项单测覆盖：同一题不重复计分、没作答不翻页、翻不过头、四档评级、按下标而非文字判对、洗牌后判定仍正确、同一条内容顺序确定、答案位置真的被打散。

## 10.7 防猜：选项确定性洗牌

复习题上线后暴露了一个尴尬的数据：**135 道题里 117 道（86.7%）的正确答案是第一个选项**，「最长选项 = 答案」占 106/135（78.5%）。孩子只点第一个就能「通关」复习，评级毫无意义。

修法有两层：

1. **呈现层确定性洗牌**（`apps/site/src/review/quiz.ts`）：

```ts
/** FNV-1a 32 位哈希：把内容 id + 题目 id 变成一个稳定种子 */
function hashSeed(text: string): number { /* … */ }
/** mulberry32：小而稳的确定性随机数 */
function mulberry32(seed: number): () => number { /* … */ }

export function shuffledQuestions(quiz: QuizQuestion[], seedText: string): QuizQuestion[] {
  return quiz.map((question) => {
    const rand = mulberry32(hashSeed(seedText + ':' + question.id));
    const order = question.options.map((_, index) => index);
    for (let i = order.length - 1; i > 0; i -= 1) {
      const j = Math.floor(rand() * (i + 1));
      const a = order[i]!; order[i] = order[j]!; order[j] = a;
    }
    return { ...question, options: order.map((index) => question.options[index]!), answer: order.indexOf(question.answer) };
  });
}
```

**种子 = 内容 id + 题目 id**：同一条内容每次进来顺序一致（便于复现），但不是内容里写的原顺序。改的是呈现顺序，`answer` 下标跟着换算 —— 题干、解释、对错判定都不变。

2. **内容重写**：53 条统一 3 题（共 **159 题**，补了 16 道迁移 / 8 道记忆），重写后答案位置 **53 / 53 / 53（各 33.3%）**、「最长项 = 答案」**0/159**、选项长度差 ≤4。

两条一起做的原因：只洗牌不重写，题库本身仍然是「正确答案长得最像标准答案」；只重写不洗牌，孩子玩到第二次就记住位置了。

## 10.8 存储实现：IndexedDB + 内存降级

`packages/platform/src/web.ts` 里的 `createIdbProgressStore()` 是 `ProgressStore` 的 Web 实现，四件事值得单独说：

```ts
function openDb(): Promise<IDBDatabase | null> {
  return new Promise((resolve) => {
    if (typeof indexedDB === 'undefined') { resolve(null); return; }
    // 隐私模式、存储被禁、旧标签页占着升级（onblocked）都会让 open 永不回调：
    // 超时就退内存档，绝不让启动流程挂在这里等（以前 init 会永远 pending）
    const timer = setTimeout(() => resolve(null), 3000);
    const request = indexedDB.open('chags', 1);
    // onupgradeneeded / onsuccess / onerror / onblocked 四个回调都会把 promise 落定
  });
}
```

1. **打开数据库有 3 秒超时**：隐私模式、存储被禁、旧标签页占着升级（`onblocked`）都会让 `open` 永不回调 —— 以前 `init()` 会永远 pending，大厅一直是 0 星；
2. **拿不到数据库就降级为内存档**：本次会话照常玩，只是刷新后丢 —— 比「打不开」好；
3. **读档本身出错也不卡启动**：`migrate()` 已经对坏数据逐条兜底，这里再兜一层；
4. **写失败必须让调用方知道**：

```ts
async save(data: SaveData): Promise<void> {
  memory = data;
  const db = await dbPromise;
  if (!db) return;
  // ★ 写失败必须让调用方知道（配额满 / 无痕模式 / 存储被清）：
  // 以前 onerror 也 resolve，等于把"进度没存上"静默吞掉
  await new Promise<void>((resolve, reject) => {
    const tx = db.transaction('kv', 'readwrite');
    tx.objectStore('kv').put(data, 'save');
    tx.oncomplete = () => resolve();
    tx.onerror = () => reject(tx.error ?? new Error('存档写入失败'));
    tx.onabort = () => reject(tx.error ?? new Error('存档写入被中止'));
  });
}
```

第 4 条一路传导到界面：`stores/progress.ts` 的 `persist()` 捕获失败 → `unsaved = true` → `HallView` 顶部出现一条「这次进度可能没存上」的提示。以前写失败是静默的，星星白拿。

| `recordReview` | ✅ 复习页答完最后一题时调用，且不动星星 |
| 休息提醒 / 静音 / 家长页 | ✅ 各自有 store 与视图（第 15 章） |

一个仍在的细节：`PlayView.reviewGrade()` 里那个 `total > 0 ? … : result.stars` 的兜底分支是**有意保留**的。纯动手、不记对错的模板（比如整个 `trace` 类）没有 `correct/total` 可算，退回星星是唯一可行的评级来源 —— 不是权宜之计。

## 10.10 替换为云存档

`ProgressManager` 依赖的是 `ProgressStore` 接口（`load` / `save` 两个方法）。要做云存档（阶段 3 的可选项）：

1. 写一个 `createCloudProgressStore()`，在 `load` 时「本地优先 + 远端合并」、`save` 时本地写完后异步上行；
2. 在外壳 `shell/progress.ts` 里把 `platform.storage` 换成它；
3. 游戏包、模板、契约全部零改动。

需要提前想清楚的只有一件事：**合并策略**。星星是「只增不减」的，所以合并可以取 `max`；但 `review.dueAt` 与 `reviews` 是「最近一次生效」的，跨设备会冲突 —— 那时才需要把 `updatedAt` 升级成逐条版本号。这也是为什么 `SaveData.updatedAt` 从第一天就存在。

## 10.11 小结

- 存档结构从第一天带 `schemaVersion`，现在是**迁移链 + 逐条容错**，而不是「版本不等就清空」；
- `ProgressManager` 是唯一入口：单次读档（single-flight）、不可变更新、星星只增不减、复习不动星星；
- 复习调度是简化版 SM-2（1/3/7/21/60 天），评级门槛刻意宽松，`daysUntil()` 让「n 天后再见」能显示出来；
- 到期复习在 2026-10-16 上线：图鉴按钮 + 到期徽章 + 大厅横幅 + 纯 DOM 三题页，评级只改间隔；
- 复习题防猜是「确定性洗牌 + 内容重写」两层一起做，159 道题的答案位置被彻底抹平；
- 存储层把「打不开」「写失败」都变成可见状态，而不是静默吞掉。
