# 第16章 - 踩坑记录与常见问题

## 16.1 踩坑记录总表

CHAGS 的开发过程中积累了大量「现象 → 原因 → 处置」的记录。它们分散在各模块的代码注释与项目文档里，这里按类别集中。**每一条都对应代码里的一处修复或一条 lint / 测试规则**。

### A. Vue × Phaser 集成

| # | 现象 | 原因 | 处置 |
|---|---|---|---|
| A1 | 持有 Phaser 实例后卡顿甚至抛错 | `ref` 会深度代理整个 Phaser 对象图（场景、纹理、WebGL 上下文） | 一律 `shallowRef` / `markRaw`；写进 code review 清单 |
| A2 | 路由切走后后台仍跑着 canvas | 未 `destroy` 或容器被 `<KeepAlive>` / `<Transition>` 保留 | `onBeforeUnmount` 里 `await unmount()`（内部 `game.destroy(true)`）；不放 KeepAlive |
| A3 | 开发热更新后越玩越卡、有多个画面 | HMR 热替换叠加出多个 canvas | 编辑 Phaser 场景时整页刷新；宿主侧 `disposed` 标记防迟到挂载 |
| A4 | 连点「再来一次」后游戏「没反应了」 | 卸载→重新挂载之间有一小段空窗，第二下又挂了一个 Phaser 实例：两块 canvas 叠着、输入只落在最上面那块 | `PlayView.restart()` 加幂等锁 `restarting`：同一时刻只允许一次重开 |

### B. 输入与 Phaser 引擎行为

| # | 现象 | 原因 | 处置 |
|---|---|---|---|
| B1 | **按钮点几次都没反应，有时突然又有反应** | 命中区写成 `Rectangle(-w/2, -h/2, w, h)`，而 Phaser 命中测试会先把局部坐标**加上 `displayOrigin`**（Container 恒为 `width/2, height/2`）：实际可点区整体左上偏半个按钮，只有**左上四分之一**能点中 | 新增 `hitArea.ts`：`containerHitArea(w, h, pad)` 按 `(0,0)` 起算；单测 + e2e 点按钮右下角守着（第 8 章 8.4） |
| B2 | 一根手指按着时，另一根手指点按钮**完全没反应** | Phaser 默认 `input.activePointers: 1`：`InputManager.onTouchStart` 找不到空闲指针就整条丢弃，连 `pointerdown` 都不发 | `input: { activePointers: 3 }`；有状态的连续手势配 `createGestureGuard()` 与 `pointerId`（第 8 章 8.5） |
| B3 | CI 与慢手机上「按住 3.4 秒到不了 45%」 | Phaser 低帧率时钳制 delta，按帧间隔累加的长按进度失真 | 长按改按**墙钟**计时（记起点，`now - holdStartedAt`）；补慢设备用例 |
| B4 | 长按模式（夸父）永远不提示 | 卡住提示只写在连点分支里；孩子只会点不会按，点一下只涨 30，要 60 下才满 | 提示逻辑移出模式分支，两种模式都生效；长按「按住 420ms 才算会了」才收小手，卡住时把小手找回来 |
| B5 | 射出的箭「穿过」了目标没命中 | 箭一帧能飞很远，按点判定会漏 | 按「这一帧扫过的线段」判定（点到线段距离），并取沿弹道最先碰到的目标 |

### G. 测试与门禁的元教训

**「测试全绿」不等于「测试在守正确的东西」。** 2026-10-20 修命中区时，`smoke.spec.ts` 里两条用例同时变红：它们最后一步都是 `clickDesign(page, REWARD.done.x, REWARD.done.y)` 去点「收下」。而典故卡的两个按钮**并排**在 `REWARD.done` 左右各 168（再来一次 207 / 收下 543，宽 288），`REWARD.done.x = 375` 正好落在两个按钮之间的空隙里（视觉空隙 351–387）。旧命中区左上偏半个按钮，收下按钮的可点区实际是 `[255, 543]`，375 恰好落在里面 —— **用例是靠那个 bug 才通过的**。

处置：`smoke.spec.ts`（2 处）、`audit.spec.ts`、`screenshots.spec.ts` 统一改成 `REWARD.done.x + 168`（收下按钮中心），并在 `e2e/input.spec.ts` 里补了「点按钮右下角」的真实点击用例。由此得到三条可复用的规矩：

1. **e2e 点击不要点元素中心**：中心最容易「碰巧通过」，要故意点偏心位置（本案用 `0.42w / 0.42h`）；
2. **修 bug 时先问「为什么之前没红」**：如果旧用例本来就是靠 bug 过的，那它守的不是行为，而是缺陷；
3. **单测守住约定、e2e 守住手感**：命中区的数学在 `hitArea.test.ts`（纯函数、可在 node 跑），「点右下角能进游戏」在 `input.spec.ts`（真浏览器、真触摸）。

## 16.2 常见问题（FAQ）

**Q1：怎么把游戏给孩子玩？**

三种方式：手机浏览器打开在线试玩地址 <https://znlgis.github.io/chags/>（最方便，中英文一键切换）；下载 Windows 便携 exe 或安卓 apk（第 14 章，离线可用）；本地开发用 `pnpm dev`。注意浏览器版目前仍是在线加载静态资源（PWA 离线缓存属阶段 1 未做）。

**Q2：进度会丢吗？存在哪里？**

存在设备的 IndexedDB（本地），无账号、不同步。刷新、重开都在；换设备或清浏览器数据会丢。写失败不会静默：大厅顶部会出现「这次进度可能没存上」的横幅（第 9 章 9.3）。想跨设备要等云存档（换 `ProgressStore` 实现即可，第 10 章）。

**Q3：支持哪些语言？怎么加新语言？**

当前中文 + 英文。加 `zh-TW` 等新语言的完整步骤见第 11 章：注册 locale、补界面文案表、补 53 份内容翻译、跑 `content:check` 与 `audit:i18n`。游戏代码零改动。

**Q4：想换美术 / 配音怎么做？**

美术：改 `games/<id>/src/art.ts` 里的绘制函数（换成贴图调用即可），模板与测试不动；分幕插图走 `story[].illustration` 字段。配音：替换 `AudioBus.speak` 的实现（按 locale 取音频文件），`SpeechHandle` 语义不变，游戏侧一行不改。

**Q5：复习测验在哪？为什么通关后没有答题？**

到期复习已经上线（不再是「未接线」）：图鉴里每张典故卡有「复习」按钮，到期时卡上多一枚「该复习了」徽章，游戏馆顶部出现一条横幅（只有真的有到期内容时才出现）直达第一部。点进去是 **3 道题（含 1 道迁移题）**，53 条内容共 159 题；答对率决定下次什么时候再见：**1 / 3 / 7 / 21 / 60 天**。评级只改「下次什么时候复习」，**不动星星**。页面是纯 DOM，不为三道题去加载 Phaser。顺带说明一个常见疑问：`packages/templates` 里的 `quiz` 场景**已经删除**，复习题只剩内容数据（每典故 3 题含 1 道 `transfer`，由 schema 强制）—— 同一个功能不留两份实现。为什么不在每局结束考三题：那与「少写字、多动手」冲突（第 10 章）。

**Q6：能上微信小游戏吗？**

架构为它留了门（`PlatformServices` 是唯一出口），但项目文档的结论很克制：**微信小游戏不是「换个适配器就能上」** —— 还需处理 WebGL 上下文差异、包体限制、`wx` 全局注入与资源加载器替换。决策规则：如果小游戏是硬性首发要求，应先用 Phaser 3.90 + `weapp-adapter` 做 2–3 天 PoC 验证，或改用 Cocos Creator；如果首发是 H5 / 微信内网页，当前方案最优。

**Q7：可以用它做自己的典故合集吗？**

可以，MIT 许可。16.3 节给了一份 fork 指南。

**Q8：为什么没有排行榜、账号、联机、内购？**

主动不做（Anti-scope，第 15 章）：它们抬高成本与合规风险，对「让孩子记住典故」几乎无贡献。每一项都留了触发条件，需要时按既定出口扩展。

**Q9：测试现在有多少？**

按最近一轮记录（技术方案 §7.22）：单元测试 **1229 项**（含命中区约定 5 条 + 手势守卫 4 条），端到端 **94 条**（§7.21 记录）另加本轮 3 条输入用例；其中发版门禁跑的是带 `@real` 标签的子集（README 记录为 30 条真实指针操作 / 适龄体验用例）。跑法见第 13 章。

**Q10：未成年人隐私怎么保证？**

无广告 SDK、无社交、无外链诱导、不采集个人信息；遥测默认只做本地缓冲且 `flush()` 为空实现；进度只存本机。这些不是配置项，而是代码里没有相反的路径（第 9 章）。

**Q11：为什么游戏里几乎没有文字，家长会不会觉得没教东西？**

设计原话：孩子是「做」出这个办法，而不是被告知（第 15 章三个案例）。教学负载分布在交互、画面、音效、语音里；关卡数据里还有 `keyMoment`、`misconceptions`、`quiz` 三层「记住」的证据链（`quiz` 只是数据，答题界面在复习页，见 Q5）。

**Q12：孩子说「点了没反应」，怎么看是不是 bug？**

先分清三种：**点不中**（命中区，第 8 章 8.4）、**事件不存在**（一根手指按着时的第二根，8.5）、**点中了但被守卫挡下**（8.6 的 `tapAck` 就是为了让它至少响一声）。开发时用 `?autoplay=1&card=hold` 复现典故卡，或用 `window.__chags` 看事件流水 —— 这三类问题在 2026-10-20 之前都存在，现在只剩「模板各自的判定窗口」还记账。

**Q13：家长页在哪？有密码锁吗？**

在游戏馆**长按标题 3 秒**进入（孩子点不进去）。页面里有安全边界声明、本周玩过的典故、静音开关、清除本机存档（长按 3 秒确认）与版本号。**没有 PIN 型密码锁** —— 这是有意留着的：目前的威胁模型是「孩子误触」，长按已经足够；真要防「孩子故意进去」，需要产品先确认（第 15 章）。

**Q14：休息提醒是怎么算的？**

只统计**玩游戏的时间**（游戏页每 30 秒上报一次），当天累计满 20 分钟在大厅出现一次横幅，点「知道啦」当天不再出现；跨天自动清零。它不阻断游戏 —— 提醒是给家长和孩子一个停下来的理由，不是惩罚（第 9 章 9.9）。

**Q15：`pnpm verify` 全绿就可以提交了吗？**

改了玩法或交互还要跑 `pnpm e2e`；改了文案、版面或语言要跑 `pnpm audit:i18n`。原则：**新用例要能失败** —— 写完先故意破坏被测行为，确认变红（16.1 G 就是这么抓到一个「靠 bug 通过」的用例的）。

## 16.3 二次开发指南：做一个自己的合集

假设你不想做典故游戏，而是想做「世界寓言」「科学小实验」之类的合集。可以复用的部分比想象的多：

**保留（几乎不用动）**：

- 工程骨架：pnpm workspace 三层结构、契约、模板机制、平台层、进度层、工具链（verify / content:check / size / e2e / CI）；
- 三个铁律与对应的 lint 规则、测试范式；
- 输入可靠性的三件套（`hitArea` / `gesture` / `tapGuard`）—— 它们与题材无关。

**替换（按顺序做）**：

1. **品牌层**：`apps/site/index.html` 的标题与描述、`messages.ts` 的 `app.title` / `app.subtitle`、`tauri.conf.json` 的 `productName`、`capacitor.config.ts` 的 `appId` / `appName`、图标（`scripts/make-icons.py`）；
2. **内容层**：清空 `packages/content/src/entries/` 与 `i18n/en/`，按第 12 章的流程逐份添加；`groups.ts` 的分组与 `kind` 语义按你的题材调整（如 science / story）；
3. **模板层**：`packages/content/src/schema.ts` 的 `TEMPLATE_IDS` 是模板 id 的唯一事实源（现有 26 个：24 个有独立场景工厂与 chunk，`beacon` / `butcher` 的场景在游戏包内；`story` 是 53 部共用的开场、`chaos` 是盘古专属，二者不在 id 里）；保留 `story` / `place` / `tap` / `sort` / `trace` 等通用骨架，为你的题材新增模板（第 7 章）；
4. **游戏层**：删掉不需要的 `games/*` 目录，同步清 `registry.ts`、`apps/site/package.json` 与 e2e 引用 —— `registry.test.ts` 会立刻告诉你哪里漏了；
5. **术语层**：界面文案里「典故馆 / 典故卡」等词按题材替换（都在 `messages.ts` 一处）。

**三个不要动的纪律**（它们是这套工程的价值所在）：

- `pnpm verify` 必须是「完成」的定义，不要为了赶进度绕过；
- `content:check` 的内容约束（关键抉择、迁移题、出处）不要删 —— 想改规则可以，改成你的题材真正需要的约束，而不是取消约束；
- 一致性测试（registry）、可观测事件（`window.__chags`）、autoplay 直达入口，一个都别省。

## 16.4 路线图与结语

项目自己的路线图（阶段划分）：

| 阶段 | 内容 | 状态 |
|---|---|---|
| 阶段 0 · 技术验证 | 骨架、schema、三模板、曹冲称象、`pnpm verify`、冒烟 | ✅ 已完成 |
| 阶段 1 · MVP | 十七个典故、双语、打包双平台、CI、体积守卫 | ✅ 已完成 |
| 阶段 1 收尾 | 到期复习接线、家长页、20 分钟休息提醒、静音、二周目跳过故事 | ✅ 已完成（2026-10-18 适龄体验轮） |
| 阶段 2 · 扩充 | 三十六计全 36 计、模板扩到 26 个、单局流量压到 ≈226 KB | ✅ 已完成（超出原定「典故扩到 20–30」） |
| 阶段 3 · 平台化 | 云存档、家长报告、（可选）微信小游戏 PoC | 规划 |
| 未做 | PWA 离线、真美术资源、PIN 家长锁、复习间隔封顶、Idle 阈值统一、Android 权限收紧 | 如实记账 |

回看整个项目，它最值得学习的地方不是用了 Phaser 或 Vue，而是把三件事做透了：**把教学要求写进数据结构**（`keyMoment` / refine 规则 / `transfer` 题）、**把工程纪律写进工具链**（`verify` / `content:check` / 体积守卫 / CI 三班岗）、**把没做完的事如实记录**（PWA、真美术、PIN 锁、复习间隔封顶）。这三件事里，最难的其实是第三件 —— 它要求你在「看起来已经完成」的地方继续写「还没做」。

教程到这里结束。如果你也在做给孩子的东西，愿你既有把按钮修到「点一下就中」的耐心，也有把「还没做」写进文档的诚实。
