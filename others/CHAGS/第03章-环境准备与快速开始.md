# 第03章 - 环境准备与快速开始

本章的目标只有一个：**在十分钟内把 CHAGS 跑起来，并知道日常开发最常用的几条命令和调试入口**。如果只想体验游戏，什么都不用装 —— 直接打开 <https://znlgis.github.io/chags/> 即可；如果要参与开发，从 3.1 开始。

## 3.1 环境要求

| 依赖 | 版本 | 说明 |
|---|---|---|
| Node.js | 24.x | Vite 8 需要现代 Node；仓库 CI 统一用 Node 24（`env.NODE_VERSION`） |
| pnpm | 11.22.0 | 根 `package.json` 声明 `"packageManager": "pnpm@11.22.0"` |
| Git | 任意近期版本 | 克隆仓库 |
| 浏览器 | Chromium 系 / 微信内浏览器 | 开发预览与端到端测试 |

桌面壳与安卓壳的额外依赖（Rust、JDK、Android SDK）只在打包时需要，见第 14 章，普通开发不装也能跑。

### 安装 Node 与 pnpm

推荐用 nvm / fnm 管理 Node：

```bash
# 以 fnm 为例
fnm install 24
fnm use 24

# 启用 Corepack 后，pnpm 的版本由 package.json 自动接管
corepack enable
```

Windows 下如果没装过 pnpm，也可以用 `npm i -g pnpm` 作为兜底（核心约束只有一个：**全仓统一使用 pnpm**，不要混用 npm/yarn，否则 `workspace:*` 协议无法解析）。

### 克隆并安装依赖

```bash
git clone https://github.com/znlgis/CHAGS.git
cd CHAGS
pnpm install
```

`pnpm-workspace.yaml` 里已经声明了 `apps/*`、`packages/*`、`games/*` 三个工作区目录，以及需要执行安装脚本的依赖白名单（`esbuild`、`@tailwindcss/oxide`、`sharp`）。安装完成后不会产生任何构建中间产物 —— 所有包都是「exports 直连源码」，直接跑就行。

## 3.2 启动开发服务器

```bash
pnpm dev
```

开发服务器在 `http://127.0.0.1:5183` 启动（`apps/site/vite.config.ts` 里配置了 `strictPort: true`，端口被占用会直接报错而不是静默换端口）。

打开后看到的是**游戏馆**：**53 张卡片分两组** —— 「典故」17 部（组内按年代排）与「三十六计」36 条（组内按计策序号排）。每张卡上有定性徽章（神话 / 传说 / 信史 / 寓言 / 兵法）、拼音、年代、适用年龄、一句话寓意与关键词，右上角是已获得的星星；三十六计的卡上还多一枚「第 n 计」与套名。顶部导航是四个按钮：

- **游戏馆** —— 分组列表，点整张卡或卡上的「开始玩」都能进入游戏（整卡可点是 2026-10-20 才补的，见第 15 章）；
- **我的图鉴** —— 收集到的典故卡，卡上有「复习」按钮与「该复习了」徽章；
- **🔊 / 🔇** —— 全局静音，会记住选择；
- **English / 中文** —— 一键切换语言，界面、内容、语音全部跟随。

游戏馆里还有几条**按状态出现**的横条，第一次跑起来可能看不到，它们是：到期复习横幅（真有内容到期时）、20 分钟休息提醒（当天玩够时长时）、存档异常提示（写不进去时）、「继续上次」（玩过至少一局后）。**家长页**不在导航里：**长按左上角标题 3 秒**进入。

## 3.3 完整玩一遍：曹冲称象

以样板典故「曹冲称象」为例，说明一局的完整闭环（这也是理解整个教程的最小样本）：

1. **看故事**：两幕绘本，每屏一句话，**旁白念完才会出现「继续」小手**。点早了只回一句「先听完这个故事」，不翻页（这是 2026-10-15 的硬规矩，见第 15 章）；
2. **试着直接称**：把大象拖到大秤上 —— 秤被压垮。问题是被玩家自己撞见的，而不是被告知的；
3. **大象上船**：拖大象上船，船身下沉，水面处留下一道待刻的水痕；
4. **刻水痕**：点船身刻一刀，水痕被「记」下来；
5. **换石头**：大象下船，从岸边石堆里一块块拖石头上船，直到水痕重新回到水面 —— 这一步就是等量代换本身。**大象 3300，六块大石只有 3000**，光搬大的凑不出来，得大小搭配（容差 80）；
6. **石头过秤**：石头一块块搬上秤，读数累加，与大象并列成等式；
7. **典故卡**：星星、寓意、关键词、出处与原文（原文默认折叠），两个按钮 ——「再来一次」（原地重开，不回大厅）与「收下」。

每一幕、每一次选择、每一次完成都会通过事件系统上报（`scene:enter`、`beat:enter`、`story:ready`、`choice:made`、`level:complete`、`card:unlocked`……），这是自动化测试的观测基础，第 4 章会详细讲。

## 3.4 自动通关与调试直达

开发和测试时不需要手动玩，URL 上有四个调试开关（`apps/site/src/shell/createGameContext.ts` 的 `readDebugOptions()` 解析）：

| 参数 | 作用 | 例子 |
|---|---|---|
| `?autoplay=1` | 自动走完整个流程（含典故卡），并自动返回大厅 | `/?autoplay=1#/play/caochong-elephant` |
| `?story=instant` | 跳过故事页「听完才能继续」的等待（截图巡检用） | `/?autoplay=1&story=instant#/play/nuwa` |
| `?card=hold` | 自动通关后**停在典故卡上**不自动返回（拍卡面用） | `/?autoplay=1&card=hold#/play/pangu` |
| `?lang=en` | 强制英文（优先级高于上次选择） | `/?lang=en#/play/pangu` |

组合使用：

```
http://127.0.0.1:5183/?autoplay=1&lang=en#/play/dayu
```

**这四个开关在生产环境对普通用户不生效**：`debugAllowed()` 只在 `import.meta.env.DEV` 为真、或者 `navigator.webdriver === true`（Playwright 会置位）时才解析 URL 参数。这条限制是 2026-10-18 补的 —— 否则一个 `?autoplay=1` 的分享链接就能让孩子跳过故事并自动记星。

autoplay 模式下每个模板都实现了自己的「同路径自动操作」：例如 substitution 模板会自动把大象拖上船并搬石头；tap 模板会自动循环点按；place 模板逐个归位。它们**走的是与真实操作完全相同的判定路径**（`runAutoplay()` 调用的是同一批 `pushAlong` / `tapAt` 逻辑），所以 autoplay 过 ≠ 真实操作过，端到端里两者都会跑（第 13 章）。

另外有两个观测窗口：

- **`window.__chags.events`** —— 事件序列（如 `['session:start', 'scene:enter:story', 'beat:enter:b1', ...]`）；
- **`window.__chags.lastError`** —— 最近一次载入失败的技术详情。玩家在界面上看到的是一句人话（「这个典故暂时打不开」）+ 两个出口（再试一次 / 回游戏馆），技术细节留给控制台与这个属性。

在浏览器控制台里随时可以查看：

```js
window.__chags.events   // 事件轨迹
window.__chags.last     // 最近一条事件
```

## 3.5 日常命令

| 命令 | 场景 | 备注 |
|---|---|---|
| `pnpm dev` | 日常开发 | 热更新；改 `packages/*` 与 `games/*` 即时生效 |
| `pnpm typecheck` | 改完类型先跑 | `vue-tsc` 全仓检查，含 `.vue`，带增量缓存 |
| `pnpm lint` | 提交前 | eslint flat config（`--concurrency auto --cache`），`*.logic.ts` 有额外禁令 |
| `pnpm test` | 改逻辑时随写随跑 | Vitest；当前 1229 项（以输出为准） |
| `pnpm content:check` | 改内容 JSON / 译文后 | 53 条 × 中英的 schema、模板、译文完整性校验 |
| `pnpm verify` | **提交前的完整门禁** | 五步并行 + 体积守卫，热跑约 6 秒 |
| `pnpm build` + `pnpm size` | 关心体积时 | size 读 `apps/site/dist`，需先 build |
| `pnpm e2e` | 改玩法交互后 | 首次需 `pnpm exec playwright install chromium` |
| `pnpm e2e:dist` | 打包前 | 针对生产产物验证懒加载与代码分割 |
| `pnpm shots` | 重拍文档截图 | 零断言、不进回归集，产物进 `docs/screenshots/` |
| `pnpm audit:i18n` | 改文案 / 版面 / 加语言后 | 双语版面巡检（每周 + 手动） |
| `pnpm phaser:trim` | 改了 Phaser 导入面之后 | 重新生成裁剪版引擎 |

`pnpm verify` 是「完成」的定义。它全绿之前不要提 PR —— 这不是纪律口号，而是因为其中每一环都对应一类真实故障：类型错、风格坏味道、逻辑回归、内容写错、构建失败、体积超预算。

## 3.6 构建产物与本地预览

```bash
pnpm build     # 产物在 apps/site/dist/
pnpm preview   # 本地服务器预览生产产物
```

构建之后可以看两个东西：

1. **产物结构**：`dist/index.html` 只引用外壳的 JS/CSS；`dist/assets/` 里是 `vendor-phaser-*.js`（裁剪版引擎）、`game-<id>-*.js`（单游戏业务代码）、`content-<id>-*.js` 与 `content-<id>-en-*.js`（本条目内容与英文补丁）；
2. **体积报告**：

```bash
pnpm size
```

输出会列出「首屏必须下载的」与「按需加载的 chunk」两组数字，以及七项预算的对照：

```
首屏必须下载的：
  · index.html 内联脚本/样式  0.1 KB
  · assets/index-xxxx.js  54.0 KB (gzip) / 145.1 KB
  ✓ 首屏 JS+CSS 合计（gzip）：54.1 KB / 预算 60 KB
  ✓ 首屏 JS+CSS 合计（原始）：146.1 KB / 预算 160 KB
按需加载的 chunk：
  · assets/vendor-phaser-xxxx.js  220.6 KB (gzip) / 856.3 KB
  ✓ 最大的懒加载 chunk（assets/vendor-phaser-xxxx.js）：220.6 KB / 预算 260 KB
  ✓ dist 原始大小：1912.0 KB / 预算 2200 KB
体积在预算内 ✅
```

七项预算写在 `scripts/check-size.mjs` 的 `BUDGETS` 里：首屏 60 KB gzip / 160 KB 原始、单 chunk 260 KB / 1000 KB 原始、dist 2200 KB、单资源 200 KB、资源总量 600 KB。超预算会让 `pnpm verify` 失败，处置方式是优化或显式调预算并说明原因 —— 不允许悄悄绕过。

## 3.7 跑端到端测试

首次需要下载浏览器（一次性）：

```bash
pnpm exec playwright install chromium
```

然后：

```bash
pnpm e2e                    # 开发服务器上的回归集（约 98 条，串行 20–25 分钟）
pnpm exec playwright test --grep "@real"   # 只跑真实指针 / 适龄体验用例（发版门禁的子集，约 5–8 分钟）
pnpm e2e:dist               # 先 build 再起 preview，验证生产产物
pnpm shots                  # 重拍文档截图（不是测试）
pnpm audit:i18n             # 双语版面巡检
```

四份 Playwright 配置各有分工（`playwright.config.ts` / `playwright.preview.config.ts` / `playwright.shots.config.ts` / `playwright.audit.config.ts`），共同基线收在 `e2e/playwright.shared.ts`。失败时的产物会自动留在 `test-results/`（截图 + trace），CI 上会作为 artifact 上传。

## 3.8 常见问题

**1）`pnpm install` 报找不到 workspace 依赖 / `workspace:*` 无法解析**

用错包管理器了。删除 `node_modules` 后用 pnpm 重装；不要用 npm 或 yarn 安装这个仓库。

**2）端口 5183 被占用**

`strictPort: true` 会直接报错。要么停掉占用进程，要么临时改 `apps/site/vite.config.ts` 里的端口（改了之后 e2e 的 `baseURL` 也要同步，所以更推荐前者）：

```bash
# Windows
netstat -ano | findstr 5183
# macOS / Linux
lsof -i :5183
```

**3）`vue-tsc` 报 `ERR_PACKAGE_PATH_NOT_EXPORTED: './lib/tsc'`**

TypeScript 被升级到大版本 7 了。仓库刻意锁在 `~5.9.3`（原因见第 2 章），恢复 `pnpm install` 的锁定版本即可；不要单独 `pnpm add typescript@latest`。

**4）`pnpm e2e` 报没找到浏览器**

先执行 `pnpm exec playwright install chromium`。CI 上用的是 `pnpm exec playwright install --with-deps chromium`（含系统依赖）。

**5）`pnpm size` 报 `ENOENT ... apps/site/dist/index.html`**

`size` 读的是构建产物，先 `pnpm build`。`pnpm verify` 里顺序已经排好，不用手跑。

**6）Windows 上 `pnpm dist:apk` 报 Gradle 与 JDK 不兼容**

那是 JDK 25 的问题。装一个 JDK 17–24（如 `C:\Program Files\Eclipse Adoptium`），或者用 `CHAGS_JDK` 环境变量指定，`scripts/build-apk.mjs` 会自动挑。

**7）`?autoplay=1` 在线上不生效**

这是设计如此：调试开关只在开发服务器与自动化浏览器里生效（见 3.4）。要在线上验证，请用 `pnpm preview` 或 `pnpm e2e:dist`。

## 3.9 小结

到这里你已经可以：安装依赖、启动开发服务器、玩通并自动通关任意条目、跑完整质量门禁、构建并检查体积、跑端到端。下一章进入开发部分的第一站 —— 整个架构的心脏：核心契约与游戏生命周期。
