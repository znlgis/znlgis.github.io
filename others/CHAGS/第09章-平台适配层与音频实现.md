# 第09章 - 平台适配层与音频实现

## 9.1 平台层的组成

`packages/platform` 是「游戏不碰环境」这条铁律的落点：它把存储、音频、生命周期、分享、遥测全部实现为 `PlatformServices`（第 4 章的接口），由外壳在创建 `GameContext` 时注入。它只有三个文件：

```
packages/platform/src/
├─ runtime.ts   # 运行环境探测 + 两个原生插件的桥接（67 行，不 import 任何壳 SDK）
├─ web.ts       # Web 实现：IndexedDB / WebAudio / TTS / visibilitychange / share / telemetry
└─ index.ts     # 两行 export *
```

外壳侧只有一个三行的单例（`apps/site/src/shell/platform.ts`）：`export const platform = createWebPlatform()`。它不依赖 Phaser、不依赖 Vue，所以桌面壳、安卓壳、将来的小程序壳都能复用同一份实现（或只替换其中一两个子实现）。

## 9.2 运行环境探测：面向三种壳

同一份站点产物（`apps/site/dist`）会被三种壳加载：浏览器、Tauri 桌面壳、Capacitor 安卓壳。`runtime.ts` 用「运行时桥接对象」探测当前环境：

```ts
export type RuntimeKind = 'web' | 'tauri' | 'capacitor';

export function detectRuntime(): RuntimeKind {
  const w = window as RuntimeWindow;
  if (w.__TAURI_INTERNALS__ !== undefined || w.__TAURI__ !== undefined) return 'tauri';
  if (w.Capacitor?.isNativePlatform?.() === true) return 'capacitor';
  return 'web';
}

export function isNativeRuntime(): boolean {
  return detectRuntime() !== 'web';
}
```

文件头注释写明了设计理由：

> 这里**不 import 任何壳的 SDK**：原生插件全部通过运行时桥接对象取用，好处是 Web 包体积零增长，也不会有插件在浏览器里报错。

两个原生能力都是「有则用、没有则 null」：

```ts
/**
 * 安卓系统 TTS（@capacitor-community/text-to-speech 注册到桥上）。
 * 必须走原生：**Android WebView 没有实现 Web Speech API**，
 * 只靠 speechSynthesis 的话，安卓版会全程没有旁白。
 */
export function nativeTextToSpeech(): NativeTextToSpeech | null {
  const plugin = capacitor()?.Plugins?.['TextToSpeech'];
  return (plugin as NativeTextToSpeech | undefined) ?? null;
}

export function nativeApp(): NativeApp | null {
  const plugin = capacitor()?.Plugins?.['App'];
  return (plugin as NativeApp | undefined) ?? null;   // 安卓返回键
}
```

`nativeApp()` 的消费方是外壳的 `backButton.ts`（第 5 章）——浏览器里返回 `null`，直接跳过，没有分支污染。

## 9.3 存档：IndexedDB + 内存降级 + 写失败可见

`createIdbProgressStore()` 返回一个 `ProgressStore`。打开数据库这一步有两个容易忽略的兜底：

```ts
function openDb(): Promise<IDBDatabase | null> {
  return new Promise((resolve) => {
    if (typeof indexedDB === 'undefined') {
      resolve(null);
      return;
    }
    // 隐私模式、存储被禁、旧标签页占着升级（onblocked）都会让 open 永不回调：
    // 超时就退内存档，绝不让启动流程挂在这里等（以前 init 会永远 pending）
    const timer = setTimeout(() => resolve(null), 3000);
    const request = indexedDB.open(DB_NAME, 1);
    const settle = (db: IDBDatabase | null): void => {
      clearTimeout(timer);
      resolve(db);
    };
    request.onupgradeneeded = () => { /* 建 object store */ };
    request.onsuccess = () => settle(request.result);
    request.onerror = () => settle(null);
    request.onblocked = () => settle(null);
  });
}
```

读路径全线兜底，并且**读到的任何东西都要过 `migrate()`**（第 10 章）：`load()` 里 `request.onsuccess/onerror`、外层 `try/catch` 三条路径最终都 `resolve(emptySave(...))` 或 `resolve(migrate(...))` —— 存档坏了也绝不能让孩子进不去游戏，而 `migrate` 已经对坏数据逐条兜底。

写路径反过来了：**失败必须让调用方知道**。

```ts
async save(data: SaveData): Promise<void> {
  memory = data;
  const db = await dbPromise;
  if (!db) return;
  // ★ 写失败必须让调用方知道（配额满 / 无痕模式 / 存储被清）：
  // 以前 onerror 也 resolve，等于把"进度没存上"静默吞掉
  await new Promise<void>((resolve, reject) => {
    try {
      const tx = db.transaction(STORE_NAME, 'readwrite');
      tx.objectStore(STORE_NAME).put(data, SAVE_KEY);
      tx.oncomplete = () => resolve();
      tx.onerror = () => reject(tx.error ?? new Error('存档写入失败'));
      tx.onabort = () => reject(tx.error ?? new Error('存档写入被中止'));
    } catch (cause) {
      reject(cause instanceof Error ? cause : new Error(String(cause)));
    }
  });
}
```

设计要点：

- **读失败一律返回「空档」而不是抛错**；写失败向上抛，由 `useProgress` 置 `unsaved`，大厅顶部出现「这次进度可能没存上」横幅；
- **写路径先写内存**：隐私模式 / 无 IndexedDB 的环境（自动化测试）里，同一次会话内的行为与正常环境一致；
- `createWebPlatform()` 启动时顺手申请持久存储 `navigator.storage.persist()`（失败不影响功能，只是少一层保险）；
- 数据库结构只有一个 object store（`kv`）、一个键（`save`）—— MVP 无后端，不需要更复杂的设计。

## 9.4 音频总线：接口先于实现

阶段 0 的音频策略是零资源文件：音效用 WebAudio 振荡器**实时合成**，旁白用浏览器 TTS。接口在 `packages/game-kit/src/contract.ts` 里，七个方法就是全部：

```ts
export interface AudioBus {
  /** iOS / 微信必须由用户手势触发解锁 */
  unlock(): Promise<void>;
  play(key: SfxKey): void;
  /** 指定音高的一声，用于"进度听得见"（例如天越撑越高，音调越高） */
  tone(freq: number, durationMs: number): void;
  /** 语音：按当前语言朗读。将来的真人配音也按 locale 取不同音频文件 */
  speak(text: string, locale: Locale): SpeechHandle;
  stopSpeech(): void;
  setMuted(muted: boolean): void;
  isMuted(): boolean;
}
```

六个音效的合成配方（`createWebAudioBus` 里的 `patterns`）：

| SfxKey | 合成方式 | 语义 |
|---|---|---|
| `tap` | 三角波 560Hz / 0.08s | 一般点击（也是 `tapAck` 与所有按下反馈） |
| `correct` | 660Hz / 0.12s → 880Hz / 0.16s（延后 0.1s） | 做对了 |
| `wrong` | 三角波 220Hz / 0.2s | 需要再想想 |
| `splash` | 锯齿波 300Hz / 0.25s | 入水（大象、石头） |
| `unlock` | 523 → 659 → 784Hz（0 / 0.09 / 0.18s） | 里程碑（换代） |
| `complete` | 523 → 659 → 784 → 1046Hz（0 / 0.12 / 0.24 / 0.36s） | 完成 |

底层是标准的三参数包络，音量走 `0.0001 → 0.22 → 0.0001`（避免爆音）：

```ts
function tone(freq: number, duration: number, delay = 0, type: OscillatorType = 'sine'): void {
  const ctx = context();
  if (!ctx || muted) return;
  const start = ctx.currentTime + delay;
  const osc = ctx.createOscillator();
  const gain = ctx.createGain();
  osc.type = type;
  osc.frequency.setValueAtTime(freq, start);
  gain.gain.setValueAtTime(0.0001, start);
  gain.gain.exponentialRampToValueAtTime(0.22, start + 0.02);
  gain.gain.exponentialRampToValueAtTime(0.0001, start + duration);
  osc.connect(gain).connect(ctx.destination);
  osc.start(start);
  osc.stop(start + duration + 0.05);
}
```

除固定音效外还有**可调音高的一声** `tone(freq, durationMs)`：tap 模板用它做「进度听得见」—— 盘古每撑高一丈，音调就高一点。

### 解锁：iOS 与微信的门槛

```ts
async unlock(): Promise<void> {
  const ctx = context();
  if (ctx && ctx.state === 'suspended') await ctx.resume();
  // iOS 上语音合成同样需要一次用户手势内的调用
  if (typeof speechSynthesis !== 'undefined') {
    speechSynthesis.resume();
  }
}
```

外壳在**第一次 `pointerdown`** 时调用它（`App.vue` 的 `window.addEventListener('pointerdown', unlockAudio, { once: true })`），之后游戏内可以自由播音。

## 9.5 TTS 旁白：两条路径与「必须有结局」的句柄

`speak` 是这一层最复杂的实现，因为它同时要满足三件事：安卓走原生、浏览器走 Web Speech、**任何情况下都要给出一个结局**：

```ts
speak(text: string, locale: Locale): SpeechHandle {
  if (muted) return { done: Promise.resolve('unavailable') };

  // ① 原生 TTS（安卓）：WebView 没有 Web Speech API，必须走系统语音
  const native = nativeTextToSpeech();
  if (native) {
    const done = native
      .speak({
        text,
        lang: speechLang(locale),
        rate: locale === 'en' ? 0.95 : 0.9,
        pitch: 1.05,
        // 0.8 而不是 1.0：孩子的设备常在耳边/公交上，满音量容易过响、也容易吓一跳
        volume: 0.8,
      })
      .then((): SpeechOutcome => 'ended')
      // 安卓设备没装语音包时会失败；静默降级，绝不让游戏卡住
      .catch((): SpeechOutcome => 'unavailable');
    return { done };
  }

  // ② Web Speech API（桌面 WebView2 / 浏览器）
  if (typeof speechSynthesis === 'undefined') {
    return { done: Promise.resolve('unavailable') };
  }
  speechSynthesis.cancel();
  const utterance = new SpeechSynthesisUtterance(text);
  utterance.lang = speechLang(locale);
  utterance.rate = locale === 'en' ? 0.95 : 0.9;
  utterance.pitch = 1.05;
  // 与原生 TTS 口径一致：0.8 足够听清，又不会在耳边炸响
  utterance.volume = 0.8;
  // 切语言时优先挑该语言的嗓音，没有就用系统默认
  const voices = speechSynthesis.getVoices();
  const match = voices.find((v) => v.lang.toLowerCase().startsWith(locale === 'en' ? 'en' : 'zh'));
  if (match) utterance.voice = match;
  const done = new Promise<SpeechOutcome>((resolve) => {
    // 只认第一个结果：cancel() 也可能把这一条打成 error
    let settled = false;
    const settle = (outcome: SpeechOutcome): void => {
      if (settled) return;
      settled = true;
      resolve(outcome);
    };
    utterance.onend = () => settle('ended');
    utterance.onerror = () => settle('unavailable');
    speechSynthesis.speak(utterance);
  });
  return { done };
}
```

返回值 `SpeechHandle` 只有一项 `done: Promise<SpeechOutcome>`，`SpeechOutcome` 只有两个值：`'ended'`（真的念完了）与 `'unavailable'`（这台设备念不出来）。契约里写明了为什么两种都必须 resolve：

> 念完、或者确认念不出来时 resolve —— 两种情况都必须 resolve，否则故事页会永远停在「正在听」上。玩法里的旁白可以完全忽略它。

三条规则值得记住：

1. **原生优先**：安卓 WebView 里 `speechSynthesis` 不存在，只靠它在安卓版会全程没旁白（第 14 章的打包方案里因此带了 TTS 插件）；
2. **语速与音量按低龄玩家调**：中文 0.9、英文 0.95，音量 0.8 —— 比默认慢一点、轻一点；
3. **静默降级**：设备没装语音包、API 不存在、被 `cancel()` 打断，都不报错、不卡流程。

## 9.6 「听完才能继续」的放行算法

有了句柄，故事页才能兑现它的硬规矩。`packages/templates/src/story.logic.ts` 是这段逻辑的纯函数部分：

```ts
const CHARS_PER_SECOND: Record<Locale, number> = { 'zh-CN': 5, en: 14 };
/** 再短的一句也要停一下：孩子得有时间把画面和这句话对上 */
export const MIN_NARRATION_MS = 2200;
/** 再长的旁白也有上限：卡住比念不完更糟 */
export const MAX_NARRATION_MS = 24000;

/** 这段话"念一遍"大概要多久；没有语音可用时，它就是这一幕的最低停留时间 */
export function narrationMs(text: string, locale: Locale): number {
  const chars = text.trim().length;
  if (chars === 0) return 0;
  const speed = CHARS_PER_SECOND[locale] ?? CHARS_PER_SECOND['zh-CN'];
  const raw = (chars / speed) * 1000;
  return Math.round(Math.min(MAX_NARRATION_MS, Math.max(MIN_NARRATION_MS, raw)));
}

/** 这一幕还要等多久才能翻页（0 = 现在就可以翻） */
export function remainingGateMs(
  text: string,
  locale: Locale,
  outcome: SpeechOutcome,
  elapsedMs: number,
): number {
  const full = narrationMs(text, locale);
  if (outcome === 'ended' && speechTrusted(elapsedMs, full)) return 0;
  return Math.max(0, full - elapsedMs);
}
```

另外两条纯函数值得一起看：`speechTrusted(elapsedMs, fullMs)` 判「念完了」可不可信 —— 无头浏览器、没装语音包的机器、刚被 `cancel()` 掉的朗读都会**立刻**回报结束，那不是听完了，所以要求 `elapsedMs >= Math.min(Math.max(fullMs * 0.35, 900), 4000)`；`gateWatchdogMs` 是兜底看门狗，等于 `round(narrationMs * 1.8) + 2500` —— 语音引擎一直不回报（部分 WebView 就是这样）也不能把孩子钉在那一幕。

故事页的接线（`packages/templates/src/story.ts` 节选）：

```ts
const settle = (outcome: SpeechOutcome): void => {
  if (ready || this.disposed) return;
  const waited = this.ctx.services.now() - startedAt;
  const rest = remainingGateMs(narration, this.ctx.locale, outcome, waited);
  if (rest <= 0) unlock();
  else this.time.delayedCall(rest, unlock);
};
// 两种结局都要 settle：真的念完 → 立刻放行；念不出来 → 补足读一遍的时间
void handle.done.then(settle, () => settle('unavailable'));
// 兜底：语音引擎一直不回报（部分 WebView 就是这样）也不能把孩子钉在这一幕
this.time.delayedCall(gateWatchdogMs(narration, this.ctx.locale), () => settle('unavailable'));
```

放行时发 `story:ready` 事件并调用 `tapToContinue`（第 8 章），e2e 就靠这个事件确定性地翻页；只有 `?autoplay=1` 与 `?story=instant` 两个调试开关能跳过等待（生产环境拿不到，见 `createGameContext.ts` 的 `debugAllowed()`）。

## 9.7 静音：一个状态，三个入口

声音开关在 `apps/site/src/stores/settings.ts` 里，只有一个布尔值：

```ts
const MUTED_KEY = 'chags.muted';

/**
 * 声音开关。给孩子的产品必须有这个：公交上、睡前、课堂上都需要"静音但还能玩"。
 * 音效与朗读都走 platform.audio，setMuted 会同时停掉正在念的旁白。
 */
export const useSettings = defineStore('settings', () => {
  const muted = ref(false);

  function init(): void {
    let saved: boolean;
    try {
      saved = window.localStorage.getItem(MUTED_KEY) === '1';
    } catch {
      // 隐私模式读不到：按"有声音"处理，本次会话仍可手动关
      saved = false;
    }
    muted.value = saved;
    platform.audio.setMuted(saved);
  }

  function setMuted(next: boolean): void {
    muted.value = next;
    platform.audio.setMuted(next);
    try {
      window.localStorage.setItem(MUTED_KEY, next ? '1' : '0');
    } catch {
      // 写不了也无所谓：本次会话仍然生效
    }
  }
  // …
});
```

三个入口共享同一份状态：顶栏的 `nav-sound`（所有非游戏页）、游戏内右上角的 `play-sound`、家长页的 `parent-sound`。`setMuted(true)` 会连带调 `stopSpeech()` —— 否则「静音」之后还在念上一句旁白（实现是 `web.ts` 里的两行：设 `muted`，再 `if (muted) this.stopSpeech()`）。

## 9.8 生命周期：从「已实现未接线」到真的暂停

`createVisibilityLifecycle()` 本身很短：

```ts
export function createVisibilityLifecycle(): LifecycleBus {
  return {
    onPause(cb: () => void): () => void {
      const handler = () => {
        if (document.visibilityState === 'hidden') cb();
      };
      document.addEventListener('visibilitychange', handler);
      return () => document.removeEventListener('visibilitychange', handler);
    },
    onResume(cb: () => void): () => void {
      const handler = () => {
        if (document.visibilityState === 'visible') cb();
      };
      document.addEventListener('visibilitychange', handler);
      return () => document.removeEventListener('visibilitychange', handler);
    },
  };
}
```

上一版教程在这里写的是「两端尚未接线」。现在接上了 —— 在 `apps/site/src/views/PlayView.vue` 里：

```ts
// 切后台要**真的**暂停：游戏循环睡着才不烧电，顺带把没念完的旁白停掉。
offPause = platform.lifecycle.onPause(() => {
  mod.value?.pause();
  platform.audio.stopSpeech();
});
offResume = platform.lifecycle.onResume(() => {
  mod.value?.resume();
});
```

`GameModule.pause()/resume()` 内部就是 `loop.sleep()/wake()`（第 4 章），所以切后台时 RAF 循环真的停、电省下来；恢复时不会补上一大段 delta。卸载路径也补了同一件事：`onBeforeUnmount` 里先 `stopSpeech()` 再 `unmount()` —— 否则中途退出时还在念的旁白会跟着你回到大厅继续说。`offPause/offResume` 在卸载与「再来一次」时都成对调用，避免监听器越挂越多。

## 9.9 家长页与 20 分钟休息提醒

这两件事不在 `packages/platform` 里，但它们把平台层的能力（本地存储、时间、静音）真正用到了孩子的使用节奏上。

**家长页**（`apps/site/src/views/ParentView.vue`）的入口是游戏馆标题**长按 3 秒**（`App.vue` 里 3000ms 的 `setTimeout`，`pointerup/leave/cancel` 都取消）——孩子不会误入，家长找得到。页面只回答四件事：安全边界（不联网 / 无广告内购 / 存档只在本机）、本周玩过哪些典故（从存档里按 `lastPlayedAt` 取最近 7 天、倒序、最多 6 个）、静音与清档、版本号。清档也是长按 3 秒才真的执行：

```ts
/** 长按 3 秒才真的清档：孩子誤触不会把星星清空 */
function startHold(): void {
  if (holdTimer !== null || cleared.value) return;
  holding.value = true;
  holdTimer = setTimeout(() => {
    holdTimer = null;
    holding.value = false;
    void progress.clear();
    cleared.value = true;
  }, 3000);
}
```

**休息提醒**（`apps/site/src/stores/playtime.ts`）只统计「玩游戏的时间」：

```ts
const KEY = 'chags.playtime';
/** 连续玩到 20 分钟提醒休息一次（docs/技术方案.md §3.7 的承诺） */
export const REST_AFTER_SECONDS = 20 * 60;

interface DayRecord {
  date: string;    // 本地日期 YYYY-MM-DD
  seconds: number;
  rounds: number;
  /** 今天的提醒已经显示过了（点过"知道啦"） */
  reminded: boolean;
}
```

`PlayView` 每 30 秒上报一次 `playtime.addSeconds(30)`（只在游戏页计时），每通关一局 `addRound()`。`restDue` 是纯派生状态 `!reminded && seconds >= REST_AFTER_SECONDS`：大厅顶部出现一次横幅（`data-testid="hall-rest"`），点「知道啦」调 `dismissRest()`，**一天只提醒一次**。跨天自动清零；`localStorage` 不可写时只在本次会话生效。家长页的「本周玩了几个典故」与它是同一份数据的两个视角。

## 9.10 遥测与分享：隐私优先

```ts
/** 默认不采集任何信息，只在本地留一份事件轨迹，方便调试与将来做家长报告 */
export function createLocalTelemetry(): Telemetry {
  const buffer: { type: string; at: number }[] = [];
  return {
    track(type): void {
      buffer.push({ type, at: Date.now() });
      if (buffer.length > 500) buffer.shift();
    },
    async flush(): Promise<void> {
      // 刻意不发送：低龄向产品默认不上报
    },
  };
}
```

遥测只记录**事件类型与时间**，最多 500 条滚动丢弃；`flush()` 是空实现 —— 「什么都不发」是低龄向产品的默认值，不是没做完。分享走 `navigator.share`，有则调、无则静默。

## 9.11 时钟注入：`now()`

`PlatformServices.now` 是 `() => Date.now()` 的一层薄封装，它的意义不在实现而在**约束**：所有模板与逻辑代码取时间一律通过 `services.now()`（或作为参数注入），配合 lint 禁止直接 `Date.now()`，保证单测里可以注入假时钟、慢设备上的长按判定以墙钟为准（夸父的教训）、将来做家长报告时时间源可以统一替换。故事页的过门计时、`tapGuard` 的 350ms、各处 idle 计时都走它。

## 9.12 替换实现：这是留好的门

平台层的全部价值在「将来换实现不改游戏」这一刻兑现。四个替换场景：

| 场景 | 替换点 | 游戏侧改动 |
|---|---|---|
| 云存档 | 换 `ProgressStore` 实现（在 `load/save` 里加远端同步即可） | 无 |
| 真人配音 | 换 `AudioBus.speak` 实现（按 locale 取音频文件而非 TTS），`SpeechHandle` 语义不变 | 无 |
| 微信小游戏 | 新增一个 `wx` 版 `PlatformServices`（存储换 `wx.setStorage`，音频换 `wx.createInnerAudioContext`） | 无 |
| 后台策略 | 换 `LifecycleBus`（例如「切后台就结束本局」而非暂停） | 无 |

项目对第三项有诚实的备注：微信小游戏不是「换个适配器就能上」，还需要处理 WebGL 上下文差异、包体限制、资源加载器替换；如果小游戏是硬性首发要求，应当先做 PoC 再定（技术方案 3.8）。

## 9.13 小结

- `runtime.ts` 做三种壳的环境探测，全部通过运行时桥接，不把任何壳 SDK 打进 Web 包；
- 存档是 IndexedDB + 内存降级 + 迁移兜底：**读失败安全、写失败可见**，启动不会挂在 `open` 上；
- 音频是「振荡器合成音效 + TTS 旁白」的零资源方案，`speak` 返回带结局的 `SpeechHandle`，故事页据此兑现「听完才能继续」，并有三层兜底（可信度判定、补时、看门狗）；
- 静音是一个状态三个入口，`setMuted` 同时停朗读；生命周期已真正接线，切后台会暂停循环并停掉旁白；
- 家长页与 20 分钟休息提醒都建立在本地数据上，没有网络请求；
- 遥测默认不发、分享尽力而为，都是低龄向产品的隐私底线。
