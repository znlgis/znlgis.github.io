# 第11章 - 中英双语实现

## 11.1 双语的覆盖范围与分层做法

CHAGS 要求**界面、内容、语音、文档**全部支持中英切换。分层做法是明确分工的：

| 层 | 做法 | 为什么这么做 |
|---|---|---|
| 界面文案 | `@chags/i18n`：一张扁平的 key→文案表，中英各一份 | 通用标签（「开始玩」）不属于任何条目，不该塞进内容 JSON |
| 内容 | 中文写在 `entries/*.json`（保持可读），英文写在 `i18n/en/*.json`，结构镜像、只写要翻译的字段 | 避免把 JSON 写成双语大杂烩；一条没翻译也能跑（回落中文） |
| 语音 | `AudioBus.speak(text, locale)`，TTS 按 `zh-CN` / `en-US` 选嗓音 | 将来上真人配音时，同样按 locale 取不同音频文件 |
| 文档 | `README.md` / `README.en.md`，`docs/` 与 `docs/en/` | 中英各自成篇，不做机翻拼贴 |

一条容易忽略的现状：**内容的英文是「两半补丁」**。摘要译文（标题 / 寓意 / 关键词 / 出处）与详情译文（故事 / 复习题 / 关卡文案）分属两个注册表、两条加载时机 —— 这是首屏只加载摘要那一半带来的连带设计（11.3）。

## 11.2 界面文案表：编译期完整

`packages/i18n/src/messages.ts` 的核心是一张扁平对照表，中英各一份，键完全对齐：

```ts
/** 界面文案表。典故本身的文字在内容 JSON 里，不在这里。 */
export const messages = {
  'zh-CN': {
    'app.title': '中国历史典故',
    'nav.hall': '游戏馆',
    'nav.album': '我的图鉴',
    'nav.switchTo': 'English',

    // 分组文案：id 与 groups.ts 一一对应（少了 title/note/empty 任意一个，下面就编译报错）
    'group.allusion.title': '典故',
    'group.allusion.note': '一个典故一个游戏：先听完故事，再亲手做一遍。',
    'group.stratagem.title': '三十六计',
    'group.stratagem.note': '三十六条计策，一条一个游戏。',

    // 三十六计：卡上的"第 n 计"与六套的套名（少写一套，下面编译报错）
    'stratagem.card': '第 {n} 计',
    'stratagem.set.1': '胜战计',
    // …set.2–set.6…

    'review.progress': '第 {n} 题 · 共 {m} 题',
    'review.score': '答对 {n} / {m} 题',
    'review.nextDueIn': '{n} 天后再来复习',
    'hall.reviewDue': '有 {n} 个典故该复习了',
    'parent.week': '本周玩了 {n} 局',
    'rest.title': '玩了 20 分钟啦',
    /* …全部界面标签… */
  },
  en: { /* …同结构… */ },
} as const;
```

三类「让编译器帮忙」的设计：

```ts
export type MessageKey = keyof (typeof messages)['zh-CN'];

/** 编译期保证英文表不缺键：缺一个就类型报错 */
const englishCompleteness: Record<MessageKey, string> = messages.en;
void englishCompleteness;

/** 文案里的占位符参数：`'review.score': '答对 {n} / {m} 题'` */
export type MessageParams = Record<string, string | number>;

/**
 * 填占位符。**只认 {名字} 形式**，缺参数时原样保留 ——
 * 少传一个参数会在界面上留下 {n}，比整句消失更容易被发现（单测会盯着这一点）。
 */
export function fillTemplate(template: string, params: MessageParams): string {
  return template.replace(/\{(\w+)\}/g, (whole, name: string) =>
    name in params ? String(params[name]) : whole,
  );
}
```

还有两处是**运行时启动即检查**（不在类型层）：

- `stratagem.set.*` 的条数必须等于 `STRATAGEM_SETS`（= 6），少一条直接抛错 —— 内容数据里 `set` 的取值来自这里，文案缺一套会导致「第 5 套」显示成键名；
- `group.<id>.title/note/empty` 与 `groups.ts` 的分组 id 一一对应。加了一个分组却忘了写文案，大厅会显示键名 —— 所以加分组的三步里第二步就是补文案。

取词器永不抛错、永不空白：

```ts
/**
 * 取词器；缺键时回落到中文，最后回落到键名本身（永不抛错、永不空白）。
 * 带 {参数} 的句子传第二个参数即可：`t('review.score', { n: 2, m: 3 })`。
 */
export function createTranslator(locale: Locale): Translator {
  const table = messages[locale] ?? messages[DEFAULT_LOCALE];
  return (key: MessageKey, params?: MessageParams): string => {
    const text: string = table[key] ?? messages[DEFAULT_LOCALE][key] ?? key;
    return params === undefined ? text : fillTemplate(text, params);
  };
}
```

**带参数取词是 2026-10-16 才补的**。在此之前，`review.score` 这类要填数字的句子只能靠手工拼字符串（`'答对 ' + n + ' / ' + m`），中文语序一变就得改代码；现在句式写在文案表里，中英各自成句。

语言解析打配合：

```ts
/** 从 URL 的 ?lang= 读语言，用于分享与自动化测试 */
export function localeFromSearch(search: string): Locale | null {
  const value = new URLSearchParams(search).get('lang');
  if (!value) return null;
  const lower = value.toLowerCase();
  if (lower === 'en' || lower.startsWith('en-')) return 'en';
  if (lower === 'zh' || lower.startsWith('zh-')) return 'zh-CN';
  return null;
}
```

单测（`messages.test.ts`）把「完整性」从编译期之外再兜一层：每种语言全键无空串、**中英文案不相同**（防复制粘贴漏翻）、占位符缺参数时保留 `{n}`、取词器回落行为、`?lang=` 解析（含 `en-US` → `en`、`zh-TW` → `zh-CN`）。

## 11.3 内容翻译补丁：结构镜像，而且是两半

英文补丁只写需要翻译的字段，结构镜像原文。以盘古的摘要补丁为例（`i18n/en/pangu.json`）：

```jsonc
{
  "title": "Pangu Splits Heaven and Earth",
  "dynasty": "Primordial",
  "era": "Primordial · Myth",
  "source": {
    "book": "San Wu Li Ji",
    "quote": "Heaven and earth were in chaos like a hen's egg, and Pangu was born inside it. ..."
  },
  "moral": "He turned himself into the whole world.",
  "keywords": ["Chaos", "Split", "Become"]
}
```

几条规则：

- **不写 `id`、不写数字、不写坐标** —— 结构性字段不需要翻译；
- **数组按下标对齐**：译文数组必须与原文等长（`story` 两幕就写两项，`quiz` 三道就写三块）；这是 `validatePatch` 强制检查的；
- **`game.stages[].levelScript` 里也有要翻译的文案**（如 `unit: "baskets"`、`hint`），同样写进补丁 —— 这一块的校验有个专门的坑，见 11.5。

合并函数在 `localize.ts` 里，规则简单明确：

```ts
/**
 * 用翻译补丁覆盖基础内容（基础内容用中文写，翻译单独放，避免把 JSON 写成双语大杂烩）。
 * - 对象：递归合并
 * - 数组：按下标逐个合并（翻译文件必须与原文等长，由 content:check 保证）
 * - 其余：补丁优先
 */
export function mergeLocalized<T>(base: T, patch: Json): T { /* … */ }
```

补丁注册表现在有**两个**，因为它们跟着两半内容走：

```ts
// packages/content/src/i18n/index.ts —— 摘要补丁（53 份，约 9 KB gzip，切语言时才加载）
let loaded: Partial<Record<Locale, Record<string, unknown>>> = {};

/** Node 侧同步注册（'@chags/content/full' 专用；浏览器不要调） */
export function registerPatches(patches: Partial<Record<Locale, Record<string, unknown>>>): void {
  loaded = { ...loaded, ...patches };
}

export function patchFor(locale: Locale, id: string): unknown {
  if (locale === DEFAULT_LOCALE) return undefined;
  return loaded[locale]?.[id];
}

/** 切到某个语言之前，先把该语言的摘要补丁加载好 */
export async function ensurePatches(locale: Locale): Promise<void> {
  if (locale === DEFAULT_LOCALE || loaded[locale] !== undefined) return;
  try {
    const mod = await import('./en');
    loaded = { ...loaded, en: mod.patches };
  } catch {
    // 加载失败：patchFor 返回 undefined → 界面回落中文
  }
}
```

```ts
// packages/content/src/i18n/game.ts —— 详情补丁（53 份，随条目 chunk 一起加载）
export const gamePatches: Partial<Record<Locale, Record<string, unknown>>> = {
  en: { 'caochong-elephant': enCaochongGame, pangu: enPanguGame, /* …53 条… */ },
};
export function gamePatchFor(locale: Locale, id: string): unknown {
  return gamePatches[locale]?.[id];
}
```

两份补丁在 `localizedEntry()` 里都合上 —— 这一步曾经漏过一次：拆分时只合了详情那一份，结果英文卡面与顶栏露出中文，而 `content:check`（自己把两半拼起来查）与双语巡检（只截图、不认字）都拦不住。现在 `localize.test.ts` 直接对「运行时取到的英文完整条目」扫中文，堵住这一类。

## 11.4 游戏本身不知道语言的存在

这是整套双语方案里最重要的一条：**外壳把 `loadEntry(id, locale)` 的结果（已经翻译好的内容）交给游戏，游戏只读 `ctx.content`**（第 4 章契约）。因此：

- 游戏代码里没有任何 `if (locale === 'en')`；
- 新增一种语言 = 加一份翻译 JSON，游戏一行不改；
- `ctx.locale` 只用于一件事：语音的嗓音选择（`speechLang(locale)`）。

语言切换的界面行为由外壳负责：`PlayView` 的 `key` 带上 locale（`route.entryId + ':' + i18n.locale`），切语言即**重挂游戏**（卸载 Phaser 再挂载），杜绝出现半中半英的场景。切语言本身也不是瞬间完成的：

```ts
// apps/site/src/stores/locale.ts
async function setLocale(next: Locale): Promise<void> {
  await ensurePatches(next);   // 英文摘要补丁约 9 KB gzip，只在切英文时加载
  apply(next);                 // 写 localStorage + 同步 document.documentElement.lang
}
```

## 11.5 构建期强制：翻译完整性不许等到用户发现

`pnpm content:check` 的第二部分是翻译体检，对 **53 条 × 全语言**逐条检查：

1. **缺译文**：`<id> 缺少 en 摘要译文` / `…详情译文` 直接 fail；
2. **结构不一致**：`validatePatch` 递归检查「字段在原文是否存在」「数组长度是否一致」：

```ts
export function validatePatch(base: Json, patch: Json, path = ''): PatchIssue[] {
  // 数组：长度不一致 → "数组长度不一致：原文 2 项，译文 3 项"
  // 对象：原文里没有这个字段 → "原文里没有这个字段"
  // …
}
```

3. **合并后仍须过内容 schema**：译文太长（`moral` 超过 90 字、`story.text` 超限）同样被挡住；
4. **合并后每一段关卡脚本要重新过一遍模板 schema** —— 这一条是补上来的：

```ts
// 只查内容 schema 是不够的：game.stages[].levelScript 在内容 schema 里是 unknown，
// 英文译文把 unit 写成 "baskets" 就绕过了所有检查，直到玩家打开游戏才报错。
for (const [index, stage] of merged.data.game.stages.entries()) {
  const schema = templateSchemas[stage.template];
  const result = schema.safeParse(stage.levelScript);
  /* 失败即 fail */
}
```

5. **CJK 泄漏扫描**：合并后的英文内容里 **不允许出现中日韩字符**，扫描直接列出可疑路径：

```ts
/** 中日韩字符：英文版里出现它，就说明这个字段漏翻了 */
const CJK = /[\u3400-\u9FFF\uF900-\uFAFF]/;
export function findCjk(value: unknown, path = ''): string[] { /* 返回所有含中文的字段路径 */ }
```

`findCjk` 的判据**只有这一份**：内容体检与 `localize.test.ts` 都调它。以前 26 个游戏测试各抄一份、加上这两处一共 28 份，改规则要改 28 处 —— 漏一处就有一半内容在裸奔。

实际运行输出（节选）：

```
校验 53 个内容条目…
· 曹冲称象 (caochong-elephant)
  · 信史 / 2 幕故事 / 3 道复习题 / 3 段玩法：substitution → place → tap
…
语言 en：
  · Cao Chong Weighs the Elephant
  · Pangu Splits Heaven and Earth
  …
内容校验通过 ✅
```

## 11.6 版面教训：任何文字放进固定容器，必须先量后排

双语上线后暴露的第一类问题不是翻译缺失，而是**版面**：

- **典故卡糊成一团**：英文标题冲出卡片、星星压住寓意、「出处」压在原文上 —— 早期卡片用固定纵坐标排版，中文「曹冲称象」五个字，英文 "Cao Chong Weighs the Elephant" 三十个字母，必然重叠。修复：`reward.ts` 改成**先量后排**的流式版面 —— 每个文字块按卡片内宽换行、量出高度后依次堆叠，卡片高度由内容决定；仍超出就整体等比缩小，**宁可小一点也不重叠**。按钮位置固定不变，自动化用例坐标因此不受影响；
- **故事页小手压住正文**：小手固定在 `H-150`，英文更长的句子排到第四行时被压住。修复：小手按正文实测高度定位，放不下就挪到右下角；
- **提示气泡句号掉行**：换行宽度 `W-260` 太窄，放宽到 `W-180`；
- **计数气泡宽度**：`unit` 字段加 `max(8)` 约束 —— 英文单位（stones / baskets）更长，宽度自适应。

这些修复的共同结论被写进了项目文档：**任何「文字放进固定容器」的地方，都必须先量后排。中英混排会把这类问题一次性照出来。**

三十六计的卡面把这条经验又逼了一步：每计多出 `thinkingTag` 与 `transfer` 两行文字，且英文普遍比中文长 60%–100%，所以卡面排版完全由「量完再排」驱动，没有任何一处写死纵坐标。

## 11.7 双语版面巡检：独立成一条流水线

自动断言的边界之外，还有「看起来是否正常」这一类问题。项目为此保留了一条巡检：把每部游戏在两种语言下的**每个画面**截图，落到 `.scratch/i18n-audit/`（不入库）：

```bash
pnpm audit:i18n     # playwright test --config playwright.audit.config.ts
```

这条流水线在 2026-10-18 被**移出主干 CI**：它是「人眼扫一遍」的巡检，跑一次 50–60 分钟，把主干 CI 堵红了三周。现在它独立成 `.github/workflows/audit.yml`（每周一次 + 手动触发），截图作为 artifact 保留，供人工过目。同一轮里「拍文档截图」也从回归集里拆了出去（`pnpm shots`，零断言、140 处固定等待，混在回归集里只会白跑几分钟）。

端到端里另有一条专门的双语用例（`smoke.spec.ts`），它的清单**从内容目录驱动** —— 三十六计从 0 长到 36，这条用例一行都不用改：

```ts
for (const locale of ['zh-CN', 'en'] as const) {
  for (const id of ids) {
    // 两种语言下每条内容的标题与卡面都在
  }
}
```

## 11.8 新增一种语言（以简繁为例）

假设要加 `zh-TW`，需要动的点：

1. `packages/content/src/locale.ts`：`LOCALES` 加 `'zh-TW'`，`isLocale` / `speechLang` 同步（语音标签 `zh-TW`）；
2. `packages/i18n/src/messages.ts`：加繁体表（`Record<MessageKey, string>` 会强制键完整）；若新增分组或套数，补 `group.*` 与 `stratagem.set.*`；
3. `packages/content/src/i18n/`：加 `zh-TW/` 目录与 **53 份摘要补丁 + 53 份详情补丁**，分别注册到 `i18n/index.ts`（摘要）与 `i18n/game.ts`（详情）；
4. `pnpm content:check`：立刻给出全部缺失项清单，按清单补齐；
5. `pnpm audit:i18n`：跑一遍版面巡检（繁体字形更宽，重点看卡片与按钮）；
6. 界面按钮可以沿用 `nav.switchTo` 的机制（当前是「中文 / English」两态切换，多语言时改为循环切换）；
7. 若该语言的译文需要独立成 chunk，记得 `i18n/en.ts` 与 `entries/loaders.ts` 里的 `import.meta.glob` 路径要跟着扩（当前只 glob 了 `en`）。

因为「游戏不知道语言存在」这条设计，游戏包、模板、工具箱全程零改动。

## 11.9 小结

- 双语三层分工：界面文案表（编译期完整 + 启动期校验）、内容补丁（构建期强制）、语音（按 locale 选嗓音）；
- 内容的英文是**两半补丁**：摘要补丁切语言时懒加载、详情补丁随条目加载，各 53 份；
- 稳定性来自四道强制：`Record<MessageKey, string>` 的编译期检查、`fillTemplate` 的占位符约定、`content:check` 的译文体检（缺键 / 结构 / 超长 / 关卡脚本重校验 / CJK 泄漏）、`localize.test.ts` 对英文完整条目扫中文；
- 版面必须「先量后排」，这是双语给全仓上的最重要一课；
- `audit:i18n` 独立成每周巡检，负责机器断言覆盖不到的部分：人眼过一遍每个画面。
