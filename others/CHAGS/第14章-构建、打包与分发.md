# 第14章 - 构建、打包与分发

## 14.1 Vite 构建：一份站点产物，三种加载方式

```ts
// apps/site/vite.config.ts（节选）
const phaserTrim = fileURLToPath(new URL('../../packages/phaser-kit/vendor/phaser-trim.esm.js', import.meta.url));
const useFullPhaser = process.env.PHASER_FULL === '1';

export default defineConfig({
  base: './',
  plugins: [vue(), tailwindcss()],
  resolve: {
    // 只替换裸 'phaser' 导入；TS 类型仍解析到 phaser 包（typecheck 不受影响）
    alias: useFullPhaser ? [] : [{ find: /^phaser$/, replacement: phaserTrim }],
  },
  server: { host: '127.0.0.1', port: 5183, strictPort: true },
  build: {
    target: 'es2022',
    chunkSizeWarningLimit: 1000,
    rolldownOptions: {
      output: {
        codeSplitting: {
          groups: [{ name: 'vendor-phaser', test: /node_modules[\\/]phaser[\\/]|phaser-kit[\\/]vendor[\\/]phaser-trim/ }],
        },
        chunkFileNames(chunk) { /* 游戏 / 内容 / 英文内容三种前缀 */ },
      },
    },
  },
});
```

五个配置各有明确目的：

- **`base: './'`（相对路径）**：产物不仅部署在域名根目录，还要被 Tauri 与 Capacitor 以本地协议加载 —— 绝对路径 `/assets/...` 在本地壳里会 404；
- **`target: 'es2022'`**：现代语法直出，移动端浏览器与两个壳（WebView2 / Android System WebView）都支持；
- **`chunkSizeWarningLimit: 1000`**：贴着裁剪版 Phaser（约 877 KB 原始）设的告警线 —— 它本来就是共享的大 chunk，而任何**新增**的大 chunk 都该在构建日志里出声；
- **`resolve.alias` 把裸 `phaser` 指到裁剪版产物**：Vite 8 的 Rolldown 内核支持，TypeScript 侧仍解析官方类型；
- **`codeSplitting.groups` 让 Phaser 单独成 chunk**：体积预算、缓存与排障都需要它可辨认。

产物形态（`apps/site/dist`）：

```
dist/
├─ index.html                      # 只引用外壳的 JS/CSS（+ 极少量内联脚本）
└─ assets/
   ├─ index-xxxx.js                # 外壳：大厅 + 路由 + Pinia（游戏/图鉴/复习/家长页是懒加载）
   ├─ index-xxxx.css               # Tailwind 产物
   ├─ vendor-phaser-xxxx.js        # 裁剪版引擎（220.6 KB gzip，首次进游戏才加载）
   ├─ game-caochong-elephant-xxxx.js   # 单游戏业务 chunk
   ├─ game-pangu-xxxx.js
   ├─ content-pangu-xxxx.js        # 本条目内容（1–2 KB）
   ├─ content-pangu-en-xxxx.js     # 英文详情补丁（只在切英文时加载）
   └─ …（共 184 个文件，dist 原始 1912 KB）
```

每个游戏是独立 chunk 是**自动的**：注册表里是 `() => import('@chags/game-xxx')` 动态导入，Vite 按导入图切分；`chunkFileNames` 只是把文件名改成可读的前缀。这也是「外壳首屏不含 Phaser」在构建层面的保证。

## 14.2 体积现状与预算

2026-10-18 实测（跑 `pnpm size` 可得最新数字）：

| 指标 | 数值 | 预算 |
|---|---|---|
| 首屏 JS + CSS（gzip / 原始） | **54.1 / 146.1 KB** | ≤ 60 / 160 KB |
| 裁剪版 Phaser chunk（gzip / 原始） | **220.6 / 856.3 KB** | ≤ 260 / 1000 KB（单 chunk） |
| 单个游戏业务 chunk | 几 KB gzip | — |
| 点开一局的全部新增流量 | **≈226 KB gzip**（第一个游戏；之后每局只再下 3–8 KB） | — |
| 整个 dist（原始 / 文件数） | **1912 KB / 184** | ≤ 2200 KB |
| 非代码资源 | 目前几乎为零（全部几何绘制 + WebAudio 合成） | 单文件 ≤ 200 KB，合计 ≤ 600 KB |

几个数字背后的决策链条：

- **首屏 54.1 KB** 说明 Vue + Pinia + Tailwind 的外壳足够轻；「首屏只留大厅」把家长页 / 图鉴 / 复习 / 游戏的代码全部拆了出去（原始字节 165.6 → 142.7 KB）；
- **Phaser 220.6 KB** 是裁剪的结果：完整版 347.3 KB gzip，剪掉 physics / tilemaps / sound / animations 等 53 个游戏都用不到的系统后省 36%；
- **单局 226 KB** 是「Phaser 220.6 + 本游戏场景几 KB + 本条目内容 1–2 KB」的和 —— 曾经的数字是 448 KB（全部模板场景 + 全部 53 条内容都塞在共享 chunk 里）；
- **dist 1912 KB** 因为每个条目、每个场景都单独成 chunk：文件数从 58 涨到 184，但用户真正下载的字节少了。

## 14.3 Windows：Tauri 便携 exe

### 为什么是 Tauri

| | Tauri 2 | Electron |
|---|---|---|
| 产物 | 几 MB（以产物为准；CI 日志会打印每个文件的 MB 数） | 约 150 MB |
| 渲染 | 系统自带 WebView2 | 内置 Chromium |
| 本地加载 | 默认自定义协议 | `file://` 需要自行处理 |

还有一个具体到本项目的差异：站点 `index.html` 用 `<script type="module" crossorigin>`，在 Electron 的 `file://` 下会被 Chromium 的 CORS 拒绝，必须额外注册自定义协议；Tauri 默认就走自定义协议，这个坑不存在。

### 配置与构建

```jsonc
// apps/desktop/src-tauri/tauri.conf.json（节选）
{
  "productName": "CHAGS",
  "identifier": "com.chags.tales",
  "build": { "frontendDist": "../../site/dist" },   // 直接吃站点产物
  "app": {
    "windows": [{
      "title": "历史典故游戏 · Historical Tales",
      "width": 500, "height": 920,                  // 竖屏窗口，贴近手机比例
      "minWidth": 400, "minHeight": 700,
      "resizable": true, "center": true,
      "backgroundColor": "#3a2f26"
    }],
    "security": { "csp": null }
  }
}
```

```bash
pnpm dist:win    # 站点构建 + tauri build --no-bundle
# → apps/desktop/src-tauri/target/release/chags.exe（双击即玩，不装）
```

`--no-bundle` 表示只出可执行文件，不打安装包 —— 目标是「便携 exe，不写注册表、不用安装」。运行依赖系统 WebView2 运行时（Win10/11 通常已内置）。未签名的 exe 首次运行会有 SmartScreen 提示（「更多信息 → 仍要运行」），要消掉它需要代码签名证书（约 ¥1000–3000/年），属于分发阶段的可选项。

`csp: null` 是一个已知的待办：收紧 Tauri 的 CSP 需要真机回归，被列进了「下一批」清单。

## 14.4 安卓：Capacitor apk

### 配置

```ts
// apps/mobile/capacitor.config.ts
const config: CapacitorConfig = {
  appId: 'com.chags.tales',
  appName: '典故游戏',
  webDir: '../site/dist',
  android: {
    backgroundColor: '#3a2f26',
    allowMixedContent: false,
    captureInput: true,
    webContentsDebuggingEnabled: false,
  },
};
```

关键点在文件头注释里：

> 不配置 `server.url` —— 走 Capacitor 内置的本地服务（`https://localhost`），这样 **ES module、IndexedDB、WebGL 全部按浏览器标准工作**。

如果改成远程 URL 就变成「套壳网页」，离线、IndexedDB 的稳定性都会受影响；本地服务让安卓壳里的运行环境和浏览器保持一致。

### 原生能力对接

- **TTS**：`@capacitor-community/text-to-speech` —— **Android WebView 没有实现 Web Speech API**，必须走系统语音（第 9 章的 `runtime.ts` 通过桥接对象取用）；
- **返回键**：`@capacitor/app` —— 游戏 / 图鉴里按返回回游戏馆，已在游戏馆才退出（第 5 章，且有 5 条单测守着）；
- **竖屏与全屏**：`AndroidManifest.xml` 里 `screenOrientation="portrait"`；`styles.xml` 全屏 + `windowLayoutInDisplayCutoutMode=shortEdges`（刘海屏）；CSS 里 `env(safe-area-inset-*)` 让开手势条。

### 构建与 JDK 选择

```bash
pnpm dist:apk    # 站点构建 + cap sync android + scripts/build-apk.mjs
```

`scripts/build-apk.mjs` 自动挑一个 17–24 的 JDK（原因见第 2 章：Gradle 8.14 不支持 JDK 25）：

```js
// 依序检查：CHAGS_JDK 环境变量 → 常见安装目录（Eclipse Adoptium / Program Files\Java）…
const probe = spawnSync(java, ['-version'], { encoding: 'utf8' });
const major = Number(/version "(\d+)/.exec(text)?.[1] ?? '0');
if (major >= 17 && major <= 24) return { dir, major };
```

找不到时给出可执行的报错（装 Temurin 21 或用 `CHAGS_JDK` 指定），而不是让每个人自己去搜「Unsupported class file major version 69」是什么。

### 签名规则：默认「能装就行」

这是 2026-10-16 定稿的策略（提交 45b7625）：项目不上架应用商店，唯一的真实用法是「自己手机装一个」，所以**没有正式密钥时用 debug 密钥签**。

| 文件 | 是否入库 | 说明 |
|---|---|---|
| `android/keystore.properties` | ❌ | 本地签名配置 |
| `*.keystore` | ❌ | **务必自己备份**；丢了只能让用户先卸载再装新版 |
| `android/local.properties` | ❌ | 本机 SDK 路径 |

三种情形：

| 情形 | 行为 |
|---|---|
| 没有任何签名 Secrets（默认） | 退回 debug 签名，APK 直接能装，日志给 `::warning::`，Release 说明里写明「本次是 debug 签名」 |
| 配了四个 Secrets | 走正式签名，可以覆盖安装旧版本（「存档不丢」） |
| 手动触发并勾选 `require_signed_apk` | 没有 Secrets 时**直接失败**（用于确实要正式包时） |

debug 密钥的代价写在文档里：每次构建可能都不一样，装新版若提示「签名不一致 / 应用未安装」，得先卸载旧版 —— **卸载会清掉本地存档**。想要以后能直接覆盖安装，跑一次 `pnpm keystore` 生成密钥并配成 Secrets。

CI 里还有一步校验，值得抄下来：

```bash
set -euo pipefail
APK=apps/mobile/android/app/build/outputs/apk/release/app-release.apk
APKSIGNER="$ANDROID_SDK_ROOT/build-tools/36.0.0/apksigner"
if ! CERTS="$("$APKSIGNER" verify --print-certs "$APK")"; then
  echo "::error::apksigner 校验失败：$APK"; exit 1
fi
# 签名者是不是 debug 证书，比"有没有签名"更要紧：debug 签名同样能通过 verify
if echo "$CERTS" | grep -q 'CN=Android Debug'; then
  if [ "$SIGN_KIND" = "release" ]; then
    echo "::error::配了正式签名 Secrets，产出的却是 debug 签名"; exit 1
  fi
fi
```

`set -euo pipefail` 与显式判退出码两处都是修出来的：旧版本 `apksigner verify | head -4` 的失败退出码会被 `head` 吃掉，等于没校验。（`$SIGN_KIND` 在真实 workflow 里来自 `steps.sign.outputs.kind`。）

### 首次构建需要

1. JDK 17–21（JDK 25 超出 Gradle 8.14 支持范围）；
2. Android SDK：`platforms;android-36` + `build-tools;36.0.0`（Capacitor 8 要求 compileSdk 36）；
3. Rust 工具链 + MSVC C++ 生成工具（Tauri）；
4. WebView2 运行时（Win10/11 通常已内置）。

## 14.5 图标与「裁剪版引擎」

### 图标

`scripts/make-icons.py` 用 Pillow 几何绘制生成两套壳的图标（与游戏内「几何绘制」的美术策略一致，零设计外包）：

```bash
pnpm icons
```

安卓侧的启动图与自适应图标由 `@capacitor/assets` 生成（`apps/mobile/resources/` 里的源文件 → `android/` 下的各尺寸资源）。

### 裁剪版 Phaser

完整版 Phaser 4.2.1 的 chunk 是 347.3 KB gzip / 1341.9 KB 原始，而 53 个游戏一个都没用到 physics / tilemaps / sound / animations 这些系统。`pnpm phaser:trim` 生成 `packages/phaser-kit/vendor/phaser-trim.esm.js`（220.6 KB gzip，-36%），说明文档在 `packages/phaser-kit/vendor/README.md`。

三个工程细节：

- 裁剪产物**入库**，不依赖每次构建时重建（否则 CI 与本地可能拿到不同版本）；
- `vite.config.ts` 用 alias 只替换裸 `phaser` 导入，TypeScript 仍解析官方类型；
- 想临时回退完整包排查问题：`PHASER_FULL=1 pnpm dev`。

## 14.6 GitHub Actions 自动发布

推一个 tag 就自动构建两个平台并挂到 GitHub Release：

```bash
git tag v0.2.0
git push origin v0.2.0
```

（另有 `workflow_dispatch` 手动入口：只出产物、不发 Release，用于验证流程。）

流水线结构（`.github/workflows/release.yml`）：

```
version   解析 tag → 版本号与 versionCode
web       质量门禁（typecheck/lint/test/content:check）+ 构建站点 + 体积守卫 + 上传 artifact
e2e       真实操作端到端（--grep "@real"）+ 生产构建产物 e2e（与 windows/android 并行）
windows   Tauri 构建便携 exe（windows-latest；收集时体积门禁：> 6MB 失败）
android   Capacitor 构建 apk（ubuntu-latest，JDK 21 + android-36；收集时体积门禁：> 6MB 失败）
release   两个产物挂到 GitHub Release（needs 含 e2e：玩法门禁没过就不发）
```

几个值得学习的工程细节：

**① 站点产物只构建一次**：`windows` 与 `android` 两个 job 都 `download-artifact` 同一份 `web-dist`，保证 exe 与 apk 里的网页代码完全一致，也省掉一次构建。下载后还有一步显式校验 `apps/site/dist/index.html` 存在 —— 产物没就位时要立刻报错，而不是等 Tauri/Gradle 报一个看不懂的错。

**② 版本号自动注入**：

```bash
# tag v1.2.3 → versionName 1.2.3 / versionCode 10203
CODE=$(( MAJOR * 10000 + MINOR * 100 + PATCH ))
# 安卓要求 versionCode >= 1；手动触发（0.0.0-dev）与 v0.0.0 都会算出 0，直接构建会报错
if [ "$CODE" -lt 1 ]; then CODE=1; fi
```

Windows job 会用 node 脚本把版本写进 `tauri.conf.json`；安卓 job 通过 `CHAGS_VERSION_NAME` / `CHAGS_VERSION_CODE` 环境变量传入。带 `-` 的 tag（如 `v1.0.0-beta.1`）自动标为预发布 —— 这一处也有坑：`softprops/action-gh-release` 的 `with` 输入全是字符串，`prerelease: false` 在 JS 里是 truthy，会把正式版也标成预发布，所以改成下一步用 `gh release edit --prerelease=false` 显式纠正。

**③ 不依赖第三方 setup-android**：workflow 里有段注释解释得很清楚 —— `android-actions/setup-android@v3` 会去装早已从 SDK 仓库移除的 `tools` 包，必然报 `Failed to find package 'tools'` 然后整个 job 挂掉；ubuntu runner 本来就预装了 SDK，自己定位 `ANDROID_HOME` 即可（`cmdline-tools` 的目录名带版本号，别写死 `latest`）。

**④ 产物体积门禁**：`ARTIFACT_MAX_BYTES = 6291456`（6 MB），收集时断言 exe / apk 不超过它 —— 历史实测 3.3–3.6 MB，超限多半是误打进了调试符号、多架构产物或未压缩资源。与其发一个几十 MB 的包，不如在收集步骤直接失败。

**⑤ 签名 Secrets（可选）**：`ANDROID_KEYSTORE_BASE64` / `ANDROID_KEYSTORE_PASSWORD` / `ANDROID_KEY_ALIAS` / `ANDROID_KEY_PASSWORD`。不配也能跑（自动退回 debug 签名并给 warning）。手工生成 base64：

```powershell
[Convert]::ToBase64String([IO.File]::ReadAllBytes("apps/mobile/android/chags-release.keystore"))
```

**⑥ 细节兜底**：`chmod +x gradlew`（gradlew 在 Windows 上提交，git 没保留可执行位，直接 `./gradlew` 会 exit 126）；`apksigner verify --print-certs` 校验签名；失败时上传 `test-results`。

## 14.7 分发策略

| 平台 | 方式 | 注意事项 |
|---|---|---|
| Windows | 直接发 exe，双击即用 | 未签名会有 SmartScreen 提示（「更多信息 → 仍要运行」） |
| 安卓 | 直接发 apk，需要允许「安装未知来源的应用」 | 上 Google Play 要 AAB + 隐私政策，**面向未成年人的应用还受 Families 政策约束**，成本高得多 |
| Web | 静态托管（GitHub Pages / CDN / 对象存储） | 面向国内需已备案域名；要上微信生态，备案是硬门槛 |

项目的建议是明确的：**先直接分发文件，跑通体验再考虑上架**。在线试玩就是一个例子：站点产物推到 GitHub Pages（`base: './'` 让它同时适配子路径），孩子点开链接就能玩，连 APK 都不用装。

## 14.8 打包没有改变的东西

打包不是「另做一个版本」，验收清单里明确列了不变项：

- 游戏代码一行没改：两个壳都只加载同一份 `apps/site/dist`；
- 存档仍然是 IndexedDB，在桌面与安卓上都能持久保存；
- 中英切换、`?lang=` 在两端照常工作（调试开关 `?autoplay=1` 等只在开发服务器与自动化浏览器里生效，打包产物里同样如此）；
- `pnpm verify` 与端到端测试完全不受影响（它们针对的是 Web 产物）。

这也解释了为什么「平台适配」在 CHAGS 里是一个薄层（第 9 章的 `runtime.ts` 一百行不到）：壳的差异被压缩到「运行环境探测 + 两个原生插件入口」，其余全部复用。

## 14.9 小结

- 构建产物是一份纯静态站点：游戏、内容、英文补丁各自成 chunk，Phaser 是共享 chunk 且不进首屏；
- 桌面壳选 Tauri（几 MB、系统 WebView2、自定义协议避开 `file://` CORS）；安卓壳选 Capacitor（本地服务保证 ESM / IndexedDB / WebGL 的标准行为），原生能力只接 TTS 与返回键；
- 引擎与模板都按需加载，两个数字值得记住：首屏 54.1 KB gzip、单局新增 226 KB gzip；
- 两个打包入口（`pnpm dist:win` / `dist:apk`）都把「环境差异」写进脚本（JDK 选择、签名回退），而不是写进文档让人记；
- 发布走 tag 驱动的 GitHub Actions：站点构建一次、双平台复用、版本自动注入、签名可选回退、真实操作端到端与产物体积双门禁。
