# 第01章 - CHAGS项目概述与设计理念

## 1.1 CHAGS 是什么

CHAGS（Chinese Historical Anecdotes Game Series，中国历史典故儿童游戏合集）是一个面向 6–12 岁儿童的开源 H5 游戏合集：**一个典故一个小游戏，让小朋友在「做」故事的过程中记住典故**。

项目源码托管在 [https://github.com/znlgis/CHAGS](https://github.com/znlgis/CHAGS)，采用 MIT 许可协议。它不是一个传统意义上的「游戏引擎」，也不是一套课程软件，而是一个把「内容、玩法、壳、工具链」完整拆开的工程样本：

- **五十三部游戏全部实现并可玩通**：十七个典故（曹冲称象 → 庖丁解牛）+ 三十六计全 36 计（胜战 1–6、敌战 7–12、攻战 13–18、混战 19–24、并战 25–30、败战 31–36）；
- 合集有**两层结构**：第一层是分组（present 两组 —— 典故 `allusion` 与三十六计 `stratagem`），第二层才是条目；分组表在 `packages/content/src/groups.ts`，大厅与图鉴都按它分区渲染；
- 十七部典故之外，三十六计**一计一个游戏、一计一个专属动词**；计名与按语保留，冲突抽象成难题 / 赛场 / 工地，不出现流血与死亡；
- 全部游戏、界面、语音、文档支持中英文双语一键切换；
- 手机浏览器即开即玩，同一份站点产物还能打成 Windows 便携 exe 与安卓 apk；
- 无后端、无广告、无账号，进度只存本机；另有「到期复习」把学过的典故按 1 / 3 / 7 / 21 / 60 天的间隔请回来；
- 一条 `pnpm verify` 命令覆盖类型检查、Lint、单测（1229 项）、内容体检、构建与七项体积预算；端到端测试在真实浏览器里把每部游戏玩一遍，其中 31 条是带 `@real` 标签的真实指针 / 儿童体验用例，进发版门禁。

本教程分为「使用」与「开发」两部分。使用部分回答「怎么把它跑起来、玩起来、发出去」；开发部分回答「它的架构为什么这样设计、每个包各管什么、怎么从零加一个新条目、怎么保证质量」。每章相对独立，但建议按顺序阅读。

## 1.2 产品定位决定的技术取向

这个项目的所有技术决策都从一句产品定位出发：**重点不是「玩过」，而是「记住 + 理解寓意」**。

对儿童产品来说，这句话会推导出一系列具体的约束，它们最终都落进了代码：

| # | 产品诉求 | 技术约束 |
|---|---|---|
| 1 | 家长随手就把手机给孩子，不能要求装 App | H5 优先，扫码即玩；不做原生独占 |
| 2 | 小朋友注意力短，单局 3–5 分钟 | 无长连接、无加载等待，随时中断可恢复 |
| 3 | 场景常在车内、老家、弱网 | 静态资源、本地存档；首屏只有 54.1 KB gzip |
| 4 | 家里的旧安卓机、旧 iPad 也要能跑 | 2D、体积预算、按住墙钟计时而不是帧率 |
| 5 | 核心指标是「记住」 | 内容数据结构内建关键抉择、常见误解、迁移练习、复习间隔 |
| 6 | 合集要从 17 部长到 30–100 条 | 分组 + 模块化 + 契约化 + 玩法模板库，新增条目 = 加一个包 + 一份 JSON |
| 7 | 儿童产品，家长会问隐私 | 无广告 SDK、无社交、不采集儿童个人信息，数据默认只存本机；家长页给结论 |
| 8 | 主要由 AI 辅助/主导开发 | 全文本资产（可 diff）、可单测、一条命令验证 |

第 8 条不是附带说明，而是硬约束：它直接否掉了 Cocos / Unity 这类「编辑器里拖拽出场景」的方案 —— 那些工程的场景文件是二进制或巨型 JSON，无法 review、无法 diff、无法被自动化验证。所以 CHAGS 选择了**代码即资产**的路线：游戏画面全部由代码绘制，玩法规则写在纯 TypeScript 模块里，可以用文本工具完成全部开发与审查。

## 1.3 十七部典故一览

十七部典故目前全部跑通。每一部都遵循同一条原则：**每部游戏有一个只属于它的动词**，避免「第 N 部又是换个皮的连点游戏」。

| 典故 | kind | 动词 | 玩法骨架 |
|---|---|---|---|
| 曹冲称象 | history | 称 | 拖大象上秤（压垮）→ 上船 → 刻水痕 → 搬石头等量代换 → 石头过秤 |
| 盘古开天辟地 | myth | 撑 | 连点蛋壳炸开 → 连点撑天一万八千年 → 拖六团光归位 |
| 后羿射日 | myth | 射 | 拉弓瞄准射日，射九留一；把最后一个也射掉会天黑 |
| 女娲补天 | myth | 补 | 按形状（不靠颜色）把五色石拖进五个洞 |
| 精卫填海 | myth | 填 | 连点：衔石投海，海上浮起一小片陆地 |
| 夸父追日 | myth | 追 | 长按奔跑、松手减速；到河渭点一下喝水再追 |
| 愚公移山 | fable | 挖 | 连点挖山；三成智叟出现、六成锄头交给下一代 |
| 神农尝百草 | legend | 尝 | 把草拖到嘴边先尝，再分进对应木牍 |
| 大禹治水 | legend | 疏 | 先连点筑堤直到决口，再手指划出三段河道 |
| 太公钓鱼 | history | 等 | 主线只有「等」；诱惑会把终点后移但永远等得到 |
| 烽火戏诸侯 | history | 点 | 点一次烽火，信任少一格；第四次真有事，没人来 |
| 杞人忧天 | fable | 解 | 把四个「想明白」拖进四个担忧泡泡，逐个破除 |
| 刻舟求剑 | fable | 刻 | 船一直在走、剑一直在水里；刻在船帮与刻在岸上结果不同 |
| 朝三暮四 | fable | 挪 | 七颗橡子串在绳上，只有中间木牌能挪 |
| 狡兔三窟 | fable | 掘 | 挖洞躲天敌；「三窟」是被危险的数目逼出来的 |
| 百步穿杨 | history | 瞄 | 五片柳叶、五档距离，越远越小 |
| 庖丁解牛 | fable | 顺 | 先砍一刀留缺口，再顺着缝一块块推出去 |

> 表中 `kind` 是内容 JSON 的取值（`history` / `myth` / `legend` / `fable` / `strategy`），大厅与图鉴直接读它挂徽章。典故组按 `yearApprox` 排序（公元前为负数）—— 神话排在时间轴最前（如盘古是 -9999），信史落在后面，天然形成「从神话到信史」的时间纵深；三十六计组则按「登记顺序 = 计策序号」排，因为它本来就不是时间序列。

十七部典故背后共享同一套工程结构：分幕故事 + 玩法场景 + 典故卡，由 `defineGame()` 统一组装；玩法骨架来自模板库，各部只提供自己的内容数据、画面绘制与少量定制代码。

## 1.4 三十六计：六套三十六计，一计一个游戏

三十六计是 2026-10-15 一次性补齐的一整组内容（六个提交、六辑），它不是「典故的变体」，而是一组新的内容类型：

- 数据上，它属于 `stratagem` 分组，摘要里多一个 `stratagem: { number, set }` 字段；`number` 是 1–36，`set` 是 1–6，schema 会在构建期校验 `set === ceil(number / 6)`：
  `{ group: 'stratagem', stratagem: { number, set } }`；
- 语义上，它的 `kind` 是 `strategy`（兵法），既不是神话也不是信史 —— 它们不是「故事」，是「招数」；
- 教学口径上，每一计都带两个新字段：`thinkingTag`（2–6 字的思维标签，如「留退路」）与 `transfer`（这一计的思维今天可以怎么用），两者都是内容体检的**必填项**；「防御性的几计」（笑里藏刀 / 反间计 / 美人计 / 苦肉计）只教识别、不教怎么使。

| 套 | 计 | 玩法模板 |
|---|---|---|
| 胜战计 | 1–6 | `ruse` `siege` `borrow` `stillness` `window` |
| 敌战计 | 7–12 | `show` `twoline` `wait` `read` `matchup` `window` |
| 攻战计 | 13–18 | `probe` `borrow` `lure` `chase` |
| 混战计 | 19–24 | `siege` `window` `swap` `matchup` `chain` |
| 并战计 | 25–30 | `swap` `probe` `stillness` `siege` `show` `chain` |
| 败战计 | 31–36 | `lure` `stillness` `twoline` `split` `chain` `trace` |

三十六条计策的实现策略是**「模式扩展优先于新模板」**：第一辑新写 5 个模板，第二辑 4 个、第三辑 3 个、第四辑 2 个，第五、六辑**一个模板都没新增**，全部是给已有模板加模式（`swap.beam` / `probe.hint` / `stillness.feign` / `siege.ladder` / `show.borrow` / `chain.step` / `lure.favor` / `stillness.calm` / `twoline.plant` / `chain.domino`），另有 2 处纯复用（34 苦肉计用 `split`、36 走为上用 `trace`）。

这样做的好处是**老模式一行不动**：第六辑的既有单测删改 0 行，判定文件只动了 1 行 import。代价是模板文件会越长越厚 —— 这一点在第 7 章展开。

## 1.5 记忆工程：五层机制与代码落点

CHAGS 对「让孩子记住」这件事的回答不是策划文档里的一句话，而是数据结构与代码的一部分。项目把记忆拆成五层，每层都有对应的技术落点：

| 层 | 机制 | 技术落点 |
|---|---|---|
| L1 | 情境代入：不是读故事，是「做」故事 | `story` 场景分幕绘本 + 旁白；**旁白没念完不许翻页** |
| L2 | 关键抉择：自己找到那个办法 | 内容里的 `keyMoment` + `misconceptions`；关键动作由交互本身承载 |
| L3 | 多通道编码：看 + 听 + 做 + 说 + 选 | 画面、旁白（TTS）、操作、跟读、复习题 |
| L4 | 收集与结构：典故卡 + 图鉴 | 通关解锁 `card:unlocked`，卡片按分组落位；图鉴可按「原文」折叠 |
| L5 | 间隔重复 + 迁移：1 / 3 / 7 / 21 / 60 天后再见 | `packages/progress/src/review.ts` 的纯调度 + `apps/site/src/review/quiz.ts` 的纯状态机 |

L5 在 2026-10-16 之前只是「数据结构与单测」，界面上没有入口；这一轮把它做成了**到期复习**：图鉴卡上有「复习」按钮与「该复习了」徽章，大厅**只在真的到期时**出现一条横幅，复习页是纯 DOM 的 3 道题（含 1 道迁移题），答对率决定下次间隔，**评级不动星星**。细节见第 10 章。

一个具体例子：曹冲称象的关键抉择不做成文字选择题，而是让玩家亲手走完「直接称 → 秤垮了 → 大象上船 → 刻水痕 → 换石头 → 石头过秤」的过程。孩子是自己撞见「称不动」这个问题的，代换的办法也是自己做出来的 —— `keyMoment` 数据仍然保留，但它提供的是揭晓语与复习题，渲染选择题这件事被有意放弃了。

## 1.6 技术选型速览

| 决策项 | 选型 | 一句话理由 |
|---|---|---|
| 游戏引擎 | Phaser 4.2（裁剪版） | 纯代码、可 diff、可单测；剪掉 physics/tilemaps/sound 等未用系统后 chunk 220.6 KB gzip |
| 应用外壳 | Vue 3.5（SFC + Composition API）+ Pinia + Tailwind 4 | 大厅/图鉴/家长页是 UI 密集型，SFC 写得快 |
| 语言 | TypeScript 5.9.3（strict） | 引擎与游戏之间靠接口契约隔离；版本锁定有实测原因（见第 2 章） |
| 构建 | Vite 8 + pnpm workspace | 原生多入口 + 代码分割，每个游戏自动独立 chunk |
| 内容 | JSON 两半（摘要 / 详情）+ zod schema，构建期校验 | 换内容 = 换 JSON，不用改代码；首屏只加载摘要 |
| 玩法 | 26 个模板 id（24 个共享场景 + 2 个游戏专属场景） | 让「第 54 个条目」的成本远低于「第 1 个」 |
| 存储 | IndexedDB（本地优先）+ 可替换接口 | 无后端、无广告、无个人信息采集 |
| 测试 | Vitest + vue-tsc + Playwright + 内容体检 + 体积守卫 | `pnpm verify` 全绿才算完成 |
| 后端 | 完全不做 | 纯静态站点，部署最便宜、最稳、最合规 |

## 1.7 三条架构铁律

整个仓库的所有设计都服从三条铁律，它们在第 4 章（契约）与后续各章会被反复引用：

1. **逻辑与渲染分离** —— 计分、判定、调度等规则写在纯 TS 模块（`*.logic.ts`）里，不 import Phaser，可以脱离浏览器单测。ESLint 还会禁止这类模块使用 `Math.random` 与 `Date.now`，保证测试可复现（规则名从 `**/logic/**/*.ts` 改成了 `**/*.logic.ts`，因为仓库里并没有 `logic/` 目录 —— 这条规则曾经一年没生效过）。
2. **游戏不得自己碰环境** —— 存档、音频、生命周期、分享一律通过注入的 `GameContext.services`，禁止游戏内部直接 `localStorage` / `fetch` / `wx.*`。这是将来上微信小游戏或云存档的唯一低成本出口。
3. **每个游戏必须能被「无头直达」** —— 支持 `?autoplay=1#/play/<id>` 这类调试入口，否则自动化测试与 AI 协作都做不了。调试开关**只在开发服务器或自动化浏览器（`navigator.webdriver`）里生效**：普通用户拿到分享链接也绕不过「故事必须听完」。

## 1.8 仓库结构总览

```
CHAGS/
├─ apps/
│  ├─ site/            # Vue 3.5 外壳（唯一的产品代码入口）
│  │  └─ src/          #  views/（大厅/游戏/图鉴/复习/家长）
│  │                   #  stores/（进度/设置/玩耍时长/语言）
│  │                   #  shell/（游戏上下文、调试桥、返回键、平台实例）
│  │                   #  review/（复习小测验的纯状态机）
│  ├─ desktop/         # Tauri 2 桌面壳（Windows 便携 exe）
│  └─ mobile/          # Capacitor 8 安卓壳（apk）
├─ packages/
│  ├─ game-kit/        # 契约层：GameModule / GameContext / 事件 / 平台接口（不含 Phaser）
│  ├─ content/         # 内容数据（摘要 <id>.json + 详情 <id>.game.json）+ zod schema + 英文译文补丁
│  ├─ templates/       # 玩法模板库：core + 24 个场景子路径 + 关卡 schema + 内容体检 CLI
│  ├─ phaser-kit/      # Phaser 启动器、主题、基础场景、命中区、手势守卫、拖拽
│  ├─ platform/        # Web 平台实现：IndexedDB / WebAudio / TTS / 生命周期
│  ├─ progress/        # 存档迁移与图鉴、复习调度（纯 TS）
│  └─ i18n/            # 界面文案表与取词器
├─ games/              # 五十三个游戏包，一个条目一个
├─ e2e/                # Playwright：冒烟 / 真实操作 / 复习 / 输入 / 儿童体验 / 产物
├─ scripts/            # verify、体积守卫、APK 构建、Phaser 裁剪、签名密钥、图标
├─ docs/               # 技术方案、各辑方案、打包与分发
└─ package.json        # 根脚本：dev / verify / e2e / size / dist:win / dist:apk ...
```

`packages/game-kit` 与 `packages/content` 不含 Phaser 依赖，所以 Vue 外壳可以安全地 import 它们；Phaser 只出现在 `games/*`、`packages/templates` 与 `packages/phaser-kit` 里，外壳首屏永远不会加载那 220 KB 的引擎。2026-10-18 之后还多了一条**运行时入口纪律**：游戏包只许 import `@chags/templates/core` 与自己的场景子路径，一旦有谁 import 主 barrel，24 个场景就会全部回到共享 chunk 里（第 2 章细讲）。

## 1.9 一个条目的完整生命周期

为了给后面的章节建立一张全局地图，先看一个条目从「打开」到「收下典故卡」的完整流程：

```
大厅（HallView）点整张卡（或卡上的「开始玩」）
  └─ hash 路由 #/play/<id> → PlayView 动态 import 游戏包（独立 chunk）
       ├─ await progress.init()          ← 深链先玩也要先读档，否则写入被旧快照盖掉
       ├─ await loadEntry(id, locale)    ← 摘要已在首屏，详情与关卡脚本这时才下
       └─ defineGame().mount(ctx)
            ├─ createStoryScene     分幕绘本（恰好 2 幕；旁白念完才出现「继续」）
            ├─ 玩法场景（模板或专属场景，一到三段）
            │    期间持续 emit：scene:enter / beat:enter / story:ready / choice:made / level:complete
            └─ createRewardScene    典故卡（星星、「再来一次」、「收下」）+ emit card:unlocked
                 └─ session:exit → requestExit(reason) → 外壳回大厅或原地重开
外壳收到 level:complete → ProgressManager 记星星与复习计划 → IndexedDB 落盘
```

这条链路里的每一步都对应一个明确的模块：

- **外壳**（第 5 章）：路由、注册表、视图、Pinia 状态；
- **契约**（第 4 章）：`GameModule` / `GameContext` / 事件系统；
- **内容**（第 6 章）：摘要 / 详情两层数据模型；
- **模板**（第 7 章）：`createStoryScene` / `createSubstitutionScene` / … 等场景工厂；
- **渲染工具箱**（第 8 章）：`BaseScene`、主题、卡通绘制、命中区与手势守卫；
- **平台层**（第 9 章）：存档、音频、生命周期；
- **进度层**（第 10 章）：星星、存档迁移、复习调度；
- **双语**（第 11 章）：界面文案、内容译文补丁、语音。

复习走的是另一条更短的链路：`#/review/<id>` → 纯 DOM 的 3 道题 → `recordReview` → 只重排下次间隔、不碰星星。

## 1.10 与「使用教程」相关的三条快速通道

如果只是想把项目跑起来体验，可以直接跳到第 3 章；以下是三个最常用的入口：

```bash
pnpm install        # 安装依赖（需要 Node 24 + pnpm 11.22，与 CI 一致）
pnpm dev            # 开发服务器 http://127.0.0.1:5183
pnpm verify         # 提交前必须全绿：类型 / Lint / 单测 / 内容 / 构建 / 体积
```

## 1.12 小结

- CHAGS 的现状是 **53 个游戏 = 17 个典故 + 36 计**，分 `allusion` 与 `stratagem` 两组；分组表是唯一事实来源。
- 它的技术取向由「儿童 + 记住」这两个前提推到极致：纯代码资产、逻辑与渲染分离、游戏不碰环境、每条都能无头直达。
- 五层记忆机制里，L1（听完故事）与 L5（到期复习）在最近一轮从「文档里的设计」变成了「代码里的行为」。
- 后面所有章节讨论的都是这条链路的一个切面：外壳、契约、内容、模板、渲染、平台、进度、双语、质量、交付。
