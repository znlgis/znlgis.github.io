# 第13章 - 测试体系与质量门禁

## 13.1 六层防线总览

CHAGS 的质量保障不是一个测试套件，而是六层互补的防线，每层有明确的分工：

| 层 | 工具 | 覆盖 | 运行方式 |
|---|---|---|---|
| 类型 | `vue-tsc --noEmit` | 全仓 strict，含 `.vue` 单文件组件 | `pnpm typecheck` |
| 风格与禁令 | eslint 10（flat config） | 代码风格 + 逻辑层禁用随机与隐式时钟 + 外壳不许 import 完整内容 | `pnpm lint` |
| 逻辑单测 | Vitest | 模板逻辑、游戏关卡数据、注册表、内容登记、文案表、复习调度 | `pnpm test`（**1229 项**） |
| 内容体检 | 自研 CLI | 内容 schema、模板脚本、双语完整性、漏翻扫描、唯一性 | `pnpm content:check` |
| 体积守卫 | `scripts/check-size.mjs` | 七项预算：首屏 / 单 chunk / dist / 单资源 / 资源总量 | `pnpm size`（verify 内） |
| 端到端 | Playwright ×4 配置 | 真实操作、autoplay、复习、输入可靠性、儿童体验、产物、巡检 | `pnpm e2e` / `e2e:dist` / `shots` / `audit:i18n` |

前五层全部挂在一条命令下（2026-10-18 起是**并行**的）：

```
pnpm verify = [typecheck | lint | test | content:check | build] 并行 → size 串行
```

对 AI 协作来说，这条命令就是「完成」的定义 —— 全绿之前，改动不算做完。并行化本身也是被审查逼出来的：六步串行 65.8 秒，其中类型 13 秒、lint 30 秒、单测 10 秒之间没有任何依赖，纯属浪费；现在热跑约 5.9 秒、冷跑约 12.1 秒。

## 13.2 单元测试：Vitest

根配置只有几行，但**包含范围**是全仓：


`environment: 'node'` 是刻意的：单元测试不碰 DOM、不碰 WebGL、不碰浏览器 —— 能跑单测的地方，说明逻辑真的从渲染里分离出来了（铁律一）。

### 1）模板逻辑（`packages/templates/src/*.logic.test.ts`）

### 2）游戏关卡数据（`games/*/src/logic.test.ts`）

53 个游戏各一组，验证「关卡脚本本身是对的」。女娲的例子（逐字来自源码）：

```ts

    expect(level.orbs.length).toBe(5);
  });

  it('每个洞的形状都不一样 —— 判定靠形状，不靠颜色（色弱的孩子也能玩）', () => {
    const level = placeLevel(raw!);
    const kinds = level.slots.map((s) => s.kind);
    expect(new Set(kinds).size).toBe(kinds.length);
  });

  it('石头与洞的形状一一对应', () => {
    const level = placeLevel(raw!);
    for (const orb of level.orbs) {
      const slot = level.slots.find((s) => s.id === orb.slotId);
      expect(slot, orb.id + ' 找不到对应的洞').toBeTruthy();
      expect(orb.kind).toBe(slot!.kind);
    }
  });

  it('五个洞都开在天上，不会掉到地面', () => {
```

注意这些断言的口吻：它们断言的是**设计意图**（「判定靠形状不靠颜色」「洞在天上」），不是实现细节。设计意图写进测试，改画法时测试不会误报，改规则时会。

## 13.3 ESLint：把纪律写进配置

`eslint.config.js` 是 flat config，除常规规则外有三处关键配置。

### 逻辑层禁令（把铁律写进 lint）

```js
{
  // 纯逻辑层必须可控、可复现：禁止随机与隐式时钟。
  // 注意：纯逻辑文件叫 *.logic.ts（仓库里没有 logic/ 目录）——
  // 这条 glob 以前写成 '**/logic/**/*.ts'，等于从来没生效过。
  files: ['packages/progress/src/**/*.ts', '**/*.logic.ts', '**/logic/**/*.ts'],
  rules: {
    'no-restricted-properties': [
      'error',
      { object: 'Math', property: 'random', message: '纯逻辑层禁止 Math.random，请注入种子随机数，保证测试可复现。' },
      { object: 'Date', property: 'now', message: '纯逻辑层禁止 Date.now，请通过参数注入 now()。' },
    ],
  },
}
```

「这条 glob 以前从来没生效过」值得单独记一笔：规则写得漂亮，但对仓库里实际的文件命名不生效，等于一年没守过。修好之后，模板逻辑里的 `Math.random` 会被直接报错 —— 需要随机的地方改注入（棋盘洗牌就是靠这个改成确定性种子的）。

### 外壳不许 import 完整内容

```js
{
  // 外壳只能吃"摘要"：完整内容（故事 / 复习题 / 关卡脚本）必须走 loadEntry() 的动态 import，
  // 否则首屏会重新变大。这条规则是那次瘦身唯一的长期守卫 ——
  // 一句 import 就能把它作废，而体积门禁只在打包后才发现。
  files: ['apps/site/src/**/*.{ts,vue}'],
  rules: {
    'no-restricted-imports': ['error', { paths: [{
      name: '@chags/content/full',
      message: '外壳不许直接引入完整内容：用 @chags/content 的 loadEntry()（动态 import）。',
    }] }],
  },
}
```

### 三条与引擎无关但很关键的取舍

- `no-undef` 只对 `.ts/.vue` 关闭（TypeScript 已负责），`scripts/*.mjs` 与配置文件保持开启，并显式声明用到的 Node 全局变量（不引 `globals` 包，依赖零增长）；
- 纯排版规则（`vue/max-attributes-per-line` 等）不进 lint 门禁，交给编辑器；
- 忽略清单里每一项都写了原因，例如 `apps/desktop/src-tauri/target/**` —— Tauri 的目标目录里嵌入了压缩后的前端产物，lint 它会让 eslint 报几千条。

## 13.5 体积守卫：`pnpm size`

`scripts/check-size.mjs` 的判定方式很关键：**读构建产物 `index.html` 里实际引用的资源 = 首屏必须下载的**，`assets/` 里其余文件 = 按需加载的：

```js
const BUDGETS = {
  initialKb: 60,        // 首屏 JS + CSS（gzip）：决定用户多久能看到游戏馆（实测 54.1 KB）
  initialRawKb: 160,    // 首屏原始字节：桌面 / 安卓壳是本地加载，省不掉（实测 146.1 KB）
  chunkKb: 260,         // 单个懒加载 js/css（gzip）：目前最大的是 Phaser 裁剪版（220.6 KB）
  chunkRawKb: 1000,     // 同上，原始字节（Phaser 约 856 KB）
  distKb: 2200,         // 整个 dist 原始大小（实测 1912 KB / 184 个文件）
  assetKb: 200,         // 单个图片 / 字体 / 音频
  assetsKb: 600,        // 非代码资源总量
};
```

三处设计细节：

- **内联脚本也算首屏**：防止「把入口改成内联 bootstrap、真入口改成动态 import」这种把首屏偷换成懒加载 chunk 的改法；
- **chunk 只比 js/css**：图片字体已经压缩过，拿 gzip 比会误报；
- **dist 与单 chunk 各有一条原始字节预算**：桌面与安卓是本地文件加载，不过 gzip —— 原始字节才是它们的真实成本。

输出分三组（首屏 / 按需 chunk / 非代码资源），超预算时给出明确出口：**要么优化，要么在脚本里调整预算并说明原因** —— 不允许悄悄绕过。

这个脚本本身也是一次审查补上的：技术方案写了「用 size-limit 守卫体积」，但实际上没有任何东西在守，属于「文档漂移」，修复方式是加脚本并接进 `verify`、`ci.yml` 与 `release.yml`。

## 13.6 端到端：四份配置与一条基线

端到端分四个配置，各管一段；共同基线（testDir / workers / reporter / 截图与轨迹 / retries）收在 `e2e/playwright.shared.ts`：

| 配置 | 起什么服务 | 跑什么 |
|---|---|---|
| `playwright.config.ts` | 开发服务器 `:5183`（复用已有进程） | 冒烟、真实操作、复习、输入、儿童体验、慢设备；**忽略** preview / audit / screenshots |
| `playwright.preview.config.ts` | `vite preview :5199`（不重复 build） | 生产产物上的用例（验证代码分割与懒加载没有被构建改变） |
| `playwright.shots.config.ts` | 开发服务器 | 拍文档截图（`pnpm shots`，零断言，不算测试） |
| `playwright.audit.config.ts` | 开发服务器 | 双语版面巡检（`pnpm audit:i18n`） |

四份配置以前各抄一份基线，漂移得很厉害（shots 与 audit 完全没有截图与轨迹、audit 的 `expect.timeout` 漏了、三份配置都没有 retries）。抽成共享基线之后，「证据策略、超时、单核节奏只改一次」。

默认配置的骨架：


### 坐标换算：设计分辨率 → 屏幕坐标

游戏是 Canvas，Playwright 只能点屏幕像素。`e2e/helpers.ts` 提供整套换算，它是 `Scale.FIT + CENTER_BOTH` 的逆运算：

```ts
export async function toScreen(page: Page, x: number, y: number) {
  const box = await page.locator('canvas').boundingBox();
  if (!box) throw new Error('canvas 还没出现');
  const scale = Math.min(box.width / DESIGN.width, box.height / DESIGN.height);
  const ox = box.x + (box.width - DESIGN.width * scale) / 2;
  const oy = box.y + (box.height - DESIGN.height * scale) / 2;
  return { x: ox + x * scale, y: oy + y * scale };
}
```

基于它的动作原语：`clickDesign` / `dragDesign` / `holdDesign` / `tapDesign`；观测原语：`events(page)` 读 `window.__chags.events`，`lastError(page)` 读最近一次载入失败详情。

### 用例的四种形态

**① 真实操作通关**（17 部典故 + 5 条三十六计真实指针）。曹冲的例子：先拖大象上秤（断言 `choice:made:scale` 且**尚未**进 reward），再上船 → 刻痕 → 搬石头 → `level:complete` / `card:unlocked` → `session:exit`。坐标直接复用 `packages/templates/src/layout.ts` 的常量 —— 布局改了，测试跟着改一处。

**② autoplay 与持久化**：`?autoplay=1` 全流程 → 自动回大厅 → 断言 `collected-count` → **刷新页面仍是 1** → 图鉴里有卡片。这条同时验证了无头直达、进度落盘与 IndexedDB。三十六计的 autoplay 清单从内容目录展开（`entrySummaries('stratagem')`），以前手抄 42 行，新增第 37 计时抄漏了不会有任何测试发现。

**③ 行为语义断言**（最见功力的一组）：

- 后羿：「把最后一个也射了，天黑之后太阳会自己回来（不会卡死）」；
- 夸父：手动操作到河边时**断言尚未通关**，喝水后继续；
- 愚公：三条里程碑**按序各出现一次**；
- 太公：真实等到文王 + 诱惑延后，绝不卡死；
- 大禹：三段河道 + 三次「三过家门」都不卡。

这些断言针对的正是「删掉暂停逻辑测试也会绿」的盲区 —— 所以先把里程碑事件补上，再对事件下断言。

**④ 输入与儿童体验**（本轮新增）：

- `input.spec.ts` 故意点按钮的**右下区域**（旧命中区在正中心靠运气、在右下 100% 没反应），并用 CDP 派发真实双指事件（先按住空白处，再用第二根手指点「再来一次」）—— `activePointers: 1` 必红、`3` 必绿；
- `kid-ux.spec.ts` 六条全部带 `@real`：静音会被记住、退出有确认层、家长页长按可进、20 分钟提醒只出现一次、二周目才出现「跳过故事」、典故卡上「再来一次」原地重开。

### 一个「测试在守护 bug」的例子

命中区修好之后，`smoke.spec.ts` 里有两条用例红了：它们最后一步都是 `clickDesign(page, REWARD.done.x, REWARD.done.y)` 去点「收下」。而典故卡的两个按钮**并排**在 `REWARD.done` 左右各 168（再来一次 207 / 收下 543，宽 288），`REWARD.done.x = 375` 正好落在两个按钮之间的空隙里（视觉空隙 351–387）。旧命中区左上偏半个按钮，收下按钮的可点区实际是 `[255, 543]`，375 恰好落在里面 —— **用例是靠那个 bug 才通过的**。

处置：`smoke.spec.ts` ×2、`audit.spec.ts`、`screenshots.spec.ts` 统一改成 `REWARD.done.x + 168`，并在 `input.spec.ts` 里补了「点按钮右下角」的真实点击用例。这条教训被写进了第 16 章：**通过的旧用例不代表被测行为是对的**。

## 13.7 CI 与发版：三班岗

### `ci.yml`：每次 push / PR

```
check   Node 24 → pnpm install --frozen-lockfile
        → typecheck → lint → test → content:check → build → size

e2e     缓存 chromium → 安装 --with-deps → pnpm e2e（开发服务器）
        → pnpm e2e:dist（生产产物，前一步挂了也跑）
        → 失败时上传 test-results（截图 + trace，保留 7 天）
```

两处细节值得引用原文注释：浏览器下载 40–60 秒/ job，按 `pnpm-lock.yaml` 的哈希缓存；失败时上传的是 `test-results`（以前传的是根本不存在的 `playwright-report`，因为 reporter 是 `list`）。

### `audit.yml`：每周一次的双语巡检

```yaml
on:
  schedule:
    - cron: '17 3 * * 1'     # 每周一 03:17 UTC（北京时间 11:17），避开整点拥堵
  workflow_dispatch:
```

巡检一次 50–60 分钟，**不进每次推送的 CI**：它挂在 ci.yml 里时，每次 push 到 main 都要多烧一小时机器，PR 上又因为太慢被跳过。上传步骤用 `if: always()` —— 巡检挂了，「挂在哪一屏」恰恰是最需要看的东西。

### `release.yml`：发版门禁

打 tag 发布时，除了构建 exe 与 apk，还多两个 job：

- **`e2e`**：跑 `playwright test --grep "@real"` 的真实操作子集 + 生产产物用例，并且 `release` job 的 `needs` 含它 —— 玩法被改坏时，宁可这一次发布失败，也不要把一个有问题的版本挂出去；
- **`web`**：类型 / lint / 单测 / 内容体检 / 构建 / 体积，产物作为 artifact 传给两个平台。

发版链路曾经完全没有端到端门禁：释放一个版本时，判据只有「能构建成功」。「能构建」和「能玩」之间的距离，就是这次补上的距离。

## 13.8 完成定义

一次改动的收尾流程：

```bash
pnpm verify        # 五步并行 + 体积，必须全绿
pnpm e2e           # 交互有改动时
pnpm audit:i18n    # 文案 / 版面 / 语言有改动时
```

三条经验规则：

1. **改玩法必跑 e2e**；只改文案可以只跑 `verify` + 相关单测；
2. **新用例要能失败**：写完先故意破坏被测行为，确认用例变红 —— 本轮三条输入用例都验证过「旧代码必红、新代码必绿」；
3. **报错留证据**：CI 失败自动带截图与 trace；本地失败看 `test-results/` 与 `window.__chags.lastError`。

## 13.9 小结

- 六层防线各司其职：类型、lint 禁令、单测、内容体检、体积守卫、端到端 + 巡检；
- 1229 项单测里最值钱的是「一致性」那几十条：注册表 ↔ 内容 ↔ manifest ↔ 四份登记表，把「漏一行」从线上 404 变成 `pnpm test` 的红；
- lint 禁令有过一次「根本没生效」的历史，提醒我们规则本身也要被检查；
- 端到端的价值在语义断言（里程碑顺序、不能卡死、刷新还在、点得中），而不只是「能跑通」；
- `pnpm verify` 全绿是「完成」的定义；CI 三班岗（每次推送 / 每周巡检 / 发版门禁）保证主干永远可用。
